# Step 002 — The two stylesheets and the Mantine theme

## Goal

Create the only two hand-written stylesheets this project will ever have — `global.css`
holding resets and `shell.css` declared but empty — and the minimal Mantine theme whose
tokens are the answer to everything those two files deliberately do not cover.

## Source files

```
frontend/src/global.css
frontend/src/shell.css
frontend/src/shared/theme.ts
```

## Test files

```
frontend/tests/stylesheets.test.ts
frontend/tests/shared/theme.test.ts
```

## Interface intent

**`frontend/src/global.css`** — **resets only**. Border-box sizing applied to every
element; the document and body stripped of their default margin and given full height;
the mount node given full height so a later shell can fill the viewport; replaced
elements (images, SVG, video) made block-level and prevented from overflowing their
container.

Nothing else. In particular: **no colour, no font, no background, no radius, no
spacing scale, no component selector, no media query, no custom property.** Each of
those is either a theme token (D3) or `008`'s workspace layout — a rule that is neither
a reset nor workspace layout belongs in neither file.

**`frontend/src/shell.css`** — the workspace layout stylesheet, created here **with no
rules at all**: a header comment stating what the file holds, who imports it and which
feature fills it, and nothing else. It exists now so that `008` has a declared home for
the three-column grid, the `1px` gap, the `--navw` custom property, the collapsed-rail
class and the `820px` media query, and so that the import wiring is already correct.

**`frontend/src/shared/theme.ts`** — exports the application's single Mantine theme
object, built with Mantine's theme-creation helper. It carries exactly three tokens:

- the primary colour, set **explicitly** to Mantine's built-in blue rather than left
  implicit;
- a font family — a system font stack, so no font is loaded over the network;
- a default radius.

It carries **no** component `defaultProps`, **no** custom colour tuple, **no** type
scale, **no** spacing or breakpoint override, and **no** geometry. Mantine's built-in
palette supplies the semantic colours the docs reference, notably red for destructive
confirms; the theme does not redefine them.

The module also exports nothing else. The colour-scheme manager and the default scheme
are step `005`'s (`shared/colorScheme.ts`), because they are persistence and provider
configuration rather than design tokens.

## Definition of done

1. `[test]` `src/global.css` sets border-box sizing across all elements, removes the
   document and body default margin, and gives the document, body and the mount node
   full height.
2. `[test]` `src/global.css` contains **no** colour value, **no** font-family
   declaration, **no** background declaration, **no** media query and **no** CSS custom
   property declaration — each of those is a theme token or `008`'s.
3. `[test]` `src/shell.css` exists and contains **no CSS rule at all** — its content is
   comments and whitespace only.
4. `[test]` No third hand-written stylesheet exists: `src/global.css` and
   `src/shell.css` are the only `.css` files anywhere under `frontend/src`.
5. `[test]` The exported theme sets a primary colour, a font family and a default
   radius, and those are the only keys it sets.
6. `[test]` The theme declares no `components` key (no component `defaultProps`) and no
   custom entry in the colour palette.
7. `[test]` The theme's font family names no remotely-hosted font — it is a system font
   stack and there is no `@font-face` or font URL anywhere in this step's files.
8. `[test]` A Mantine component rendered under a provider carrying this theme resolves
   correctly under **both** the dark and the light colour scheme — neither scheme
   produces an unstyled or unresolved result.
9. `[manual/live]` `npm run typecheck` reports no errors against the new module.
