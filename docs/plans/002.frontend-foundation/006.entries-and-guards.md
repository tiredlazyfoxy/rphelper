# Step 006 — The four entry documents, their routers, and the convention guards

## Goal

Create the four `index.html` + `main.tsx` pairs that give the build its four inputs —
each mounting the shared providers, its own `BrowserRouter` and a placeholder route
tree and nothing more — and add the automated scans that make the ids-are-strings rule
and the pure-data-contract rule real criteria rather than review notes.

## Interface intent

**The four `index.html` documents** are identical but for their title and their script
path: a document declaring its language and character set, a viewport meta, a title
naming the entry, a single mount element, and a module script pointing at the sibling
`main.tsx`. Nothing else — no inline style, no inline script, no font link, no
favicon markup, no analytics.

**The four `main.tsx` modules** each export nothing and do one thing on evaluation:
find the mount element, create a React root on it, and render the shared
`AppProviders` wrapping a `BrowserRouter` wrapping a route table.

The route table in each is a **placeholder**: one catch-all route rendering an element
that carries a stable marker identifying which entry mounted — `bootstrap`, `login`,
`admin` or `app` — and no visible page content. Later features replace the route table
wholesale; the marker exists so this step is verifiable and so a deep-link landing on
the wrong document is diagnosable.

The three differences between them, each load-bearing:

- **`admin/main.tsx` sets its router's `basename` to `"/admin"`** — exactly that
  string, with **no trailing slash**, per `frontend-structure.md`. nginx serves the
  document under `/admin/` **with** one; the two strings belong to two different
  mechanisms and neither is derived from the other (`context.md` seam S2).
- **`bootstrap`, `login` and `app` set no `basename` at all.** The `app` entry's routes
  are mounted at the origin root.
- **`app/main.tsx` additionally imports `src/shell.css`**, and is the only module in
  the project that does. `global.css` is not imported here by any entry — it arrives
  through `AppProviders`.

Keep each module as thin as the above: providers, router, placeholder. No store, no
data fetch, no gate, no shell, no `AppShell`, no error boundary.

## Definition of done

1. `[test]` Each of the four entries mounts and renders its own marker, and no entry
   renders another's.
2. `[test]` Each entry renders inside `AppProviders` — a Mantine component rendered
   within it is themed, and the notifications outlet is present.
3. `[test]` The `admin` entry's router `basename` is exactly `"/admin"` — no trailing
   slash — and a location of `/admin/users` resolves against it rather than 404-ing on
   the entry's own route table.
4. `[test]` The `bootstrap`, `login` and `app` entries declare no `basename`.
5. `[test]` `src/app/main.tsx` imports `shell.css`, and it is the **only** module under
   `frontend/src` that does.
6. `[test]` No entry module imports `global.css` directly — it reaches all four through
   `AppProviders`.
7. `[test]` Each `index.html` contains exactly one mount element and exactly one module
   script, and the script's path resolves to the sibling `main.tsx`.
8. `[test]` Each `index.html` declares a language and a character set and contains no
   inline script and no inline style.
9. `[test]` **Ids are strings.** A scan of every `.ts` and `.tsx` file under
   `frontend/src` finds no occurrence of the forbidden patterns listed in
   `006.context.md`, and the failure message of this test names the offending file and
   line number.
10. `[test]` **Pure data contracts.** The same scan finds no `makeAutoObservable`, no
    `*Draft.ts` module and no page-store class anywhere under `frontend/src` — this
    feature ships none, by `context.md` D2, and the convention it records is what later
    features bind to.
11. `[test]` **No forbidden styling mechanism.** The scan finds no Tailwind directive,
    no `.module.css` import and no styled-components import anywhere under
    `frontend/src`.
12. `[test]` **No second notification call site**, restated as a scan rather than left
    to step `005`'s render-level check: Mantine's notification API is imported by
    `shared/notifyFailure.ts` alone.
13. `[manual/live]` `npm run build` succeeds and emits **exactly**
    `dist/bootstrap/index.html`, `dist/login/index.html`, `dist/admin/index.html` and
    `dist/app/index.html`, each referencing its own hashed bundle. This is the seam
    with `fast/001`'s nginx per-entry SPA fallbacks and is invisible until deployment
    if it is wrong.
14. `[manual/live]` The four emitted bundles are distinct: the `app` bundle contains no
    module from `src/admin/`, and the `admin` bundle contains no module from `src/app/`.
15. `[manual/live]` `npm run typecheck` and `npm test` both pass across the whole
    feature.
16. `[manual/live]` All four entries render correctly under **both** the dark and the
    light colour scheme.
