# Step 001 — Frontend scaffold and build configuration

## Goal

Create the `frontend/` package from nothing: the `package.json` that carries every
dependency and the four commands the root `CLAUDE.md` names, the two TypeScript
configurations, and the single `vite.config.ts` that holds the four-entry build (rooted
at `src/`, emitting to `frontend/dist`), the one `/api` dev proxy and the Vitest block.

## Source files

```
frontend/package.json
frontend/package-lock.json
frontend/tsconfig.json
frontend/tsconfig.node.json
frontend/vite.config.ts
frontend/tests/setup.ts
frontend/.gitignore
```

`frontend/package-lock.json` is **generated** by `npm install` and committed; it is
never hand-written or hand-edited, and its size does not count against the step budget.

`frontend/tests/setup.ts` is harness source, not a test — see `context.md` D12.

## Test files

```
frontend/tests/harness.test.ts
frontend/tests/build-config.test.ts
```

## Interface intent

**`frontend/package.json`** — one file holding:

- package metadata, `"type": "module"`, and `"private": true`;
- the runtime and development dependency sets listed in `context.md` D14, and **none**
  of the five deferred packages and **not** `@mantine/form` and **no** linter;
- exactly four scripts, backing the root `CLAUDE.md`'s three commands plus one
  convenience: `build` runs the Vite build only (typechecking is a separate command, so
  the three stay orthogonal); `test` runs Vitest **once and exits**, never in watch
  mode; `typecheck` runs the TypeScript compiler in no-emit mode over **both**
  configurations, so `vite.config.ts` is covered too; `dev` starts the Vite dev server.

**`frontend/tsconfig.json`** — covers `src/` and `tests/`. A modern ES target, ESM
module resolution suited to a bundler, the automatic JSX runtime, DOM libraries,
`noEmit`, `strict`, plus the three lint-shaped compiler flags named in `context.md` D4.
**`allowJs` and `checkJs` are not enabled** — the project is TypeScript only (D4).
`exactOptionalPropertyTypes` and `noUncheckedIndexedAccess` are deliberately absent for
the reason recorded there. **No `paths` aliases** — four entries and one `shared/`
folder do not need them, and nothing in the architecture asks for one.

**`frontend/tsconfig.node.json`** — a second, small configuration covering
`vite.config.ts` itself, with Node types available, the same strictness, and likewise
no `allowJs` or `checkJs`. It exists
because the config file runs in Node while everything under `src/` runs in a browser,
and one `lib` cannot honestly describe both.

**`frontend/vite.config.ts`** — one default-exported configuration, defined through
`vitest/config`'s `defineConfig` so the `test` block is typed without a third config
file. Every filesystem path it declares is an **absolute path resolved from the config
file's own directory** (the `frontend/` directory), per `context.md` D13. It holds:

- the React plugin;
- `root` set to the `frontend/src` directory;
- `build.outDir` set to the `frontend/dist` directory, and `build.emptyOutDir` true —
  needed because the output directory now lies outside `root`;
- `build.rollupOptions.input` with the **four** named entries, keyed exactly as
  `frontend-structure.md` gives them — `bootstrap`, `login`, `admin`, `app` — each
  value the absolute path of `frontend/src/<name>/index.html`. The values deliberately
  deviate from the doc's verbatim `src/<name>/index.html` strings (D13);
- `server.port` 8193, `server.strictPort` true, and exactly **one** proxy rule mapping
  `/api` to `http://localhost:8184`. Both numbers are literals, never environment
  reads;
- a `test` block: its own `root` set to the `frontend/` directory (so Vitest does not
  inherit `src` from the build root), the jsdom environment, globals off, the setup
  file at `./tests/setup.ts`, and an include pattern that picks up `tests/**/*.test.ts`
  and `tests/**/*.test.tsx` and nothing under `src/`. The setup-file and include
  strings are resolved by Vitest against the test block's root, i.e. `frontend/`.

`base` is left at its default, for the reason in `context.md` D13.

**`frontend/tests/setup.ts`** — the Vitest setup module. It registers
`@testing-library/jest-dom`'s matchers against Vitest's `expect` and runs Testing
Library's `cleanup` after each test, so a test never sees the previous test's DOM. No
other global state, no fetch stub, no mock registry — those belong to the tests that
need them.

**`frontend/.gitignore`** — ignores `node_modules/`, `dist/`, `coverage/` and Vite's
local cache. It does **not** ignore `package-lock.json`.

## Definition of done

1. `[test]` The Vite configuration declares exactly four build inputs, named
   `bootstrap`, `login`, `admin` and `app` — no fifth input and no renamed key — and
   each value is an absolute path that resolves to the `index.html` in the
   same-named folder under `frontend/src`: `bootstrap` → `frontend/src/bootstrap/index.html`,
   `login` → `frontend/src/login/index.html`, `admin` → `frontend/src/admin/index.html`,
   `app` → `frontend/src/app/index.html`.
2. `[test]` The dev server port is `8193`, `strictPort` is enabled, and the proxy
   declares **exactly one** rule whose prefix is `/api` and whose target host and port
   are `localhost:8184`. A second proxy prefix fails this item.
3. `[test]` Neither port appears as a read of an environment variable or of
   `import.meta.env` anywhere in the configuration — both are literals.
4. `[test]` The configuration sets no `base`, so it stays at Vite's default; `root`
   resolves to the `frontend/src` directory; `build.outDir` resolves to the
   `frontend/dist` directory (a relative `outDir` counts as resolved against `root`, as
   Vite resolves it); and `build.emptyOutDir` is `true`.
5. `[test]` The Vitest block sets its own `root` to the `frontend` directory, uses the
   `jsdom` environment, and points `setupFiles` at `./tests/setup.ts`, which resolves
   against that root to `frontend/tests/setup.ts`; its include pattern, resolved against
   that root, matches `*.test.ts` and `*.test.tsx` files under `frontend/tests/` and
   matches no path under `frontend/src/`.
6. `[test]` The test harness is live: a test running under this configuration has a
   working DOM (a `document` it can write to and read back) and has
   `@testing-library/jest-dom`'s matchers available on `expect`.
7. `[test]` `package.json` declares exactly the four scripts `build`, `test`,
   `typecheck` and `dev`; `test` invokes Vitest in a single-run mode and its command
   string contains no watch flag.
8. `[test]` `package.json` declares **none** of `@mantine/form`, `eslint`, any package
   whose name begins `eslint-`, `@tiptap/*`, `tiptap-markdown`, `@mantine/tiptap`,
   `react-markdown` or `@dnd-kit/*`, in either dependency set.
9. `[test]` `package.json` declares every package named as installed in `context.md`
   D14, and `@tabler/icons-react` is constrained to `^3.40`.
10. `[test]` `tsconfig.json` enables `strict`, `noUnusedLocals`, `noUnusedParameters`
    and `noFallthroughCasesInSwitch`, sets `noEmit`, declares no `paths` aliases, and
    includes both `src` and `tests`. Neither `tsconfig.json` nor `tsconfig.node.json`
    enables `allowJs` or `checkJs`.
11. `[test]` No file anywhere under `frontend/` — excluding `node_modules/`, `dist/`
    and `coverage/` — has a `.js`, `.jsx`, `.mjs` or `.cjs` extension. A failure names
    each offending path. (TypeScript only — `context.md` D4.)
12. `[manual/live]` From `frontend/`, `npm install` completes and writes a
    `package-lock.json` that is committed, and all four scripts execute.
13. `[manual/live]` `npm run typecheck` reports no errors against both configurations.
14. `[manual/live]` No `.eslintrc*`, `eslint.config.*`, `postcss.config.*` or
    `vitest.config.*` file exists anywhere under `frontend/` — there is one Vite
    configuration and no linter.
