# Step 005 — step-specific context

- **Current page.** `frontend/src/admin/DatabasePage.tsx` renders `Title`
  "Database", then the drift `Alert`, then the drift `Table`, and has no page-level
  action area. Per-row actions sit in an `IconDots` `Menu`. Its store is
  `frontend/src/admin/databasePageState.ts`: `DatabasePageState` has observable
  fields only, and behaviour is free functions such as
  `loadDriftReport(state, signal)`. Errors go to `state.errorMessage` and render as
  an inline red `Alert`.
- **Placement is user-confirmed.** A new page-level action group sits beside the
  Database title, and it is the future home of Import (031) and Rebuild index
  (`fast/002`) (`admin-surfaces.md` ~L605-613). Only Export ships here. Do not
  render placeholders for the other two.
- **The size line is the one permitted report** (`admin-surfaces.md` ~L728: "It
  downloads a file and says how large it was; it never shows what is inside").
  It is inline page text, not a notification, so it does not break the
  no-success-toast rule. Reporting the byte size is the only use the page makes of
  the response.
- **Errors stay inline only.** The admin page already has an in-page error place,
  so an export failure renders there and is **not** also passed to `notifyFailure`
  (`ui-conventions.md` ~L253-261, ~L402-408).
- **Test harness.** Vitest plus Testing Library under `frontend/tests/admin/`.
  Fetch is stubbed per test with `vi.stubGlobal("fetch", ...)`. The page's mount
  also loads the drift report, so the stub must answer `GET
  /api/admin/database/tables` as well. `URL.createObjectURL` and `revokeObjectURL`
  need stubs in jsdom (see `004.context.md`). The notifications outlet comes from
  `shared/AppProviders`; render inside it to observe that no notification appears.
