# Step 004 — shared file-download helper in the API client

## Goal

Add a blob-download call to `shared/api.ts` that GETs a same-origin export route,
saves the body as a file through a temporary object URL, and reports the
downloaded file's name and byte size. It reuses the client's existing error decode
and 401 behaviour.

## Source files

- `frontend/src/shared/api.ts`

## Test files

- `frontend/tests/shared/apiDownload.test.ts`

## Interface intent

- **`apiDownload(path, signal?)`.** Takes a same-origin `/api/...` path and an
  optional `AbortSignal`, and resolves to an object carrying the downloaded file's
  `filename` (string) and `size` (number of bytes).
  - It issues a GET with `credentials: "same-origin"`.
  - On a 2xx it reads the body as a `Blob`, creates an object URL, clicks a
    temporary anchor carrying `download=<filename>`, removes the anchor, and
    revokes the URL.
  - The filename comes from the response's `Content-Disposition` `filename="…"`.
    When the header is absent or unparseable, it falls back to
    `rphelper-export.json`.
  - On a non-2xx it throws the same `ApiError` the JSON calls throw, through the
    client's one existing decode path: a well-formed envelope gives the backend
    code, and a malformed body gives `client_malformed_error`. A 401 performs the
    same `documentNavigation.assign("/login")` before throwing.
  - A rejected `fetch` throws `client_transport_failed`. An abort propagates
    unchanged and is not wrapped.
  - It never parses the body as JSON on success and never exposes the body's
    content to its caller.
- **Content-Disposition filename reader.** A small pure function that takes a
  header value (or null) and returns the filename, or the fallback.

## Definition of done

1. **DoD-1 [test]:** On a 200, `apiDownload` calls `fetch` once with the given
   path, method GET and `credentials: "same-origin"`, and resolves with `size`
   equal to the response body's byte length. (US-077.AC-1)
2. **DoD-2 [test]:** On a 200, an object URL is created from the body, an anchor
   with that URL as its `href` and the header's filename as its `download`
   attribute is clicked exactly once, and the object URL is revoked afterwards.
3. **DoD-3 [test]:** The resolved `filename` equals the quoted filename in
   `Content-Disposition`. With no such header, it is `rphelper-export.json`.
4. **DoD-4 [test]:** No anchor element remains in the document after the download.
5. **DoD-5 [test]:** A non-2xx with a well-formed error envelope rejects with an
   `ApiError` carrying that envelope's `code`, `message` and the real `status`, and
   no object URL is created.
6. **DoD-6 [test]:** A 401 calls `documentNavigation.assign("/login")` and then
   rejects with an `ApiError` of status 401.
7. **DoD-7 [test]:** A non-2xx with a body that is not the envelope rejects with
   code `client_malformed_error`. A `fetch` rejection rejects with
   `client_transport_failed` and status 0.
8. **DoD-8 [test]:** An aborted signal makes the call reject with the original
   abort error, which is not an `ApiError`.
9. **DoD-9 [test]:** The existing JSON calls (`apiGet` / `apiPost`) still behave as
   before. One regression case each, on success and on an error envelope.
10. **DoD-10 [manual/live]:** `npm run typecheck` passes.

## Dependencies

- None. This is frontend-only, and the routes it targets are step 003's but are
  not needed for its tests.
