# Step 001 — transfer core and whole-database export

## Goal

Create `services/transfer.py` with the envelope builder, the column-agnostic row
serializer, the two version constants, the file-naming and encoding helpers, and
the whole-database export (a walk over `schema.metadata.sorted_tables` minus an
explicit exclusion set).

## Source files

- `backend/app/services/transfer.py`

## Test files

- `backend/tests/test_transfer_core.py`

## Interface intent

- **Envelope constants.** The format literal `"rphelper-export"`, the envelope
  `version` (int, `1`) and the `schema_version` (int, `1`), as module-level
  constants (`context.md` §"The envelope").
- **Granularity value set.** A string-valued type naming exactly the four
  granularities `database`, `user`, `character` and `session`.
- **Database exclusion set.** A module-level constant naming the tables the
  whole-database export skips: `auth_sessions` and `translations`.
- **Row serializer.** Takes a `schema` Table and one selected row, and returns a
  JSON-safe mapping of column name to value under `context.md` §"Row serialization
  rules": id columns become decimal strings, booleans stay booleans, enums become
  their string value, nulls stay null, and other values pass through. Id-column
  detection reads the Table's own metadata (primary key, foreign keys, column name)
  and never a hard-coded column list. It optionally drops a given set of column
  names (step 002 uses this for `users`).
- **Table reader.** Takes a connection, a Table and an optional where-clause. It
  selects every column of that Table ordered by primary key and returns the
  serialized rows. This is the one place the exporter issues a `select`, and step
  002 reuses it.
- **Payload ordering helper.** Takes a set of included tables and returns them in
  `schema.metadata.sorted_tables` order. Payload keys follow this order.
- **Envelope builder.** Takes a granularity and an ordered payload (table name to
  rows), and returns the envelope mapping with `created_at` stamped as UTC
  ISO-8601 text.
- **Read-snapshot context.** A private context manager that runs all of one
  export's selects inside a single read transaction and ends it afterwards
  (`backend-structure.md` §"Transactional DDL": an autobegun read must be ended).
- **`export_database(connection)`.** Takes a connection and **no `user_id`**. It
  returns the `database` envelope holding every table in `sorted_tables` that is
  not in the exclusion set, with every row and every column.
- **`encode_envelope(envelope)`.** Returns the envelope as UTF-8 JSON bytes.
- **`export_filename(envelope)`.** Returns
  `rphelper-<granularity>-<compact UTC timestamp>.json`, derived only from the
  envelope's `granularity` and `created_at`.

## Definition of done

1. **DoD-1 [test]:** The envelope from `export_database` has exactly the keys
   `format`, `version`, `granularity`, `created_at`, `schema_version` and
   `payload`. `format` is `"rphelper-export"`, `granularity` is `"database"`,
   `version` and `schema_version` are integers, and `created_at` parses as a UTC
   ISO-8601 timestamp. (US-077.AC-1)
2. **DoD-2 [test]:** The database payload's table names are exactly the names in
   `schema.metadata.sorted_tables` minus `auth_sessions` and `translations`, in
   `sorted_tables` order. (US-077.AC-1)
3. **DoD-3 [test]:** With `auth_sessions` rows present (a logged-in user), the
   database payload has no `auth_sessions` key. With a `translations` row present,
   it has no `translations` key either.
4. **DoD-4 [test]:** No payload key names a table outside
   `schema.metadata.tables`. In particular, none of `memo_fts`, `message_fts`,
   `session_fts`, `memo_vec` or `session_vec` appears, which shows that vectors are
   not exported.
5. **DoD-5 [test]:** Every seeded row of every included table appears, including
   rows owned by two different users, archived characters/setups/sessions, and
   buried messages. Each row object carries every column the Table declares.
   (US-077.AC-1)
6. **DoD-6 [test]:** In every serialized row, the primary key, every
   foreign-key column, `memos.scope_id`, and any non-null `model_server_id` are JSON
   strings of decimal digits that equal the stored integer. A null reference stays
   `null`.
7. **DoD-7 [test]:** Boolean columns serialize as JSON `true`/`false`,
   `memos.scope` serializes as its string value, timestamps are the stored text
   unchanged, and a non-id integer column (e.g. `models.embedding_dim`) stays a JSON
   number.
8. **DoD-8 [test]:** `users.password_hash` is present in the database payload with
   its stored value. `llm_servers.api_key_ref` is present as the stored `"$NAME"`
   pointer. With the named environment variable set to a sentinel value, the
   sentinel appears nowhere in `encode_envelope`'s output.
9. **DoD-9 [test]:** Rows within each table are in ascending primary-key order.
10. **DoD-10 [test]:** `encode_envelope` returns UTF-8 bytes that `json.loads` back
    to the same envelope. Non-ASCII text in a row round-trips unchanged.
11. **DoD-11 [test]:** `export_filename` returns a name that matches
    `rphelper-database-<digits/letters timestamp>.json`, contains the granularity,
    and contains no row content.
12. **DoD-12 [manual/live]:** `mypy app` and `ruff check .` pass.
