# Step 003 — export routes and download response

## Goal

Expose the four exports as GET routes. Each answers with the encoded envelope as a
JSON file attachment. The admin route goes on the existing admin database router,
and the three roleplayer routes go on a new `routers/transfer.py` registered in
`main.py`.

## Source files

- `backend/app/routers/transfer.py`
- `backend/app/routers/admin_db.py`
- `backend/app/main.py`

## Test files

- `backend/tests/test_transfer_router.py`
- `backend/tests/test_admin_db_export.py`

## Interface intent

- **`GET /api/admin/database/export`**, added to `routers/admin_db.py`. It
  inherits that router's router-level admin guard. It calls `export_database` and
  answers with the attachment response below.
- **`routers/transfer.py`** (new). This is an `APIRouter` whose routes each depend
  on `require_user` and on `get_connection`:
  - `GET /api/export` calls `export_user` with the caller's id;
  - `GET /api/characters/{character_id}/export` calls `export_character`;
  - `GET /api/sessions/{session_id}/export` calls `export_session`.

  Path ids are declared with the inbound snowflake alias from `app/models/ids.py`,
  never as a bare `int`.
- **Attachment response.** Both routers build the same response from the
  envelope:
  - status 200;
  - body from `encode_envelope`;
  - media type `application/json`;
  - `Content-Disposition: attachment; filename="<export_filename(envelope)>"`.

  Each router builds it locally (a few lines). Neither router imports the other.
  The route returns this response directly, not a pydantic model; `003.context.md`
  says why.
- **`main.py`.** `create_app()` registers the transfer router, and the factory
  docstring's ordering rationale gains one line for it.

## Definition of done

1. **DoD-1 [test]:** An admin's `GET /api/admin/database/export` answers 200 with
   `application/json`. The body parses to an envelope with `format`
   `"rphelper-export"` and `granularity` `"database"`. (US-077.AC-1)
2. **DoD-2 [test]:** A roleplayer's `GET /api/admin/database/export` answers 403
   with the `insufficient_role` envelope, and an unauthenticated request answers
   401 `not_authenticated`.
3. **DoD-3 [test]:** On every export route the `Content-Disposition` header starts
   with `attachment` and names a file matching
   `rphelper-<granularity>-<timestamp>.json` for that route's granularity. With a
   character and a session seeded under a distinctive name and title, neither the
   name nor the title appears in the header.
4. **DoD-4 [test]:** `GET /api/export` answers 200 with `granularity` `"user"`. Its
   `users` row is the caller's, without `password_hash`, and its `memos` include
   the caller's memos. (US-079.AC-1)
5. **DoD-5 [test]:** `GET /api/characters/{id}/export` for the caller's character
   answers 200 with `granularity` `"character"` and that character's memos.
   (US-080.AC-1)
6. **DoD-6 [test]:** `GET /api/sessions/{id}/export` for the caller's session
   answers 200 with `granularity` `"session"` and only that session's memos.
   (US-081.AC-1)
7. **DoD-7 [test]:** Asking for another user's character, or for a nonexistent
   id, answers 404 `character_not_found`. The same holds for sessions with
   `session_not_found`. Both use the standard error envelope.
8. **DoD-8 [test]:** All three roleplayer export routes answer 401
   `not_authenticated` without a session cookie.
9. **DoD-9 [test]:** Every id in a route's response body is a JSON string. A
   non-numeric path id is refused with 422 and never reaches the service.
10. **DoD-10 [test]:** Existing routes are unaffected. `GET
    /api/characters/{id}`, `GET /api/sessions/{id}` and `GET
    /api/admin/database/tables` still answer as before after the transfer router is
    registered (one smoke request each).
11. **DoD-11 [manual/live]:** Through the dev proxy, each route triggers a browser
    file download, and the downloaded file opens as the JSON envelope.
12. **DoD-12 [manual/live]:** `mypy app` and `ruff check .` pass.
