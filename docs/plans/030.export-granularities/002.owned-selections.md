# Step 002 — user, character and session selections

## Goal

Add the three roleplayer-side exports to `services/transfer.py`: one user's own
data, one character, and one session. Each is selected by owner-scoped queries
and wrapped in the step-001 envelope.

## Source files

- `backend/app/services/transfer.py`

## Test files

- `backend/tests/test_transfer_selections.py`

## Interface intent

- **User-granularity exclusions.**
  - A module-level constant naming the tables that are not user material:
    `auth_sessions` and `translations`.
  - A module-level constant naming the `users` columns dropped from a user export:
    `password_hash`, `role` and `is_enabled`. The reason is in `002.context.md`.
- **`export_user(connection, user_id)`.** Returns the `user` envelope. Its payload
  holds the caller's `users` row (minus the excluded columns) and the caller's
  `characters`, `setups`, `sessions`, `messages` and `memos` (all scopes). Every
  select filters on `user_id`. There are no `llm_servers` or `models` rows.
- **`export_character(connection, user_id, character_id)`.** Returns the
  `character` envelope with the character, its setups, its sessions, those
  sessions' messages, and the memos at the character, its setups and its sessions
  (`context.md` §"Granularity boundaries"). It raises `CharacterNotFoundError` when
  no character with that id is owned by `user_id`.
- **`export_session(connection, user_id, session_id)`.** Returns the `session`
  envelope with the session, all of its messages, and only the `scope='session'`
  memos of that session. It raises `SessionNotFoundError` when no session with that
  id is owned by `user_id`.
- All three run inside the step-001 read snapshot and use the step-001 table reader
  and serializer. Payload keys follow `sorted_tables` order.

## Definition of done

1. **DoD-1 [test]:** `export_user`'s payload keys are exactly `users`,
   `characters`, `setups`, `sessions`, `messages` and `memos`, in `sorted_tables`
   order. There is no `llm_servers`, `models`, `auth_sessions` or `translations`
   key. `granularity` is `"user"`. (UC-062)
2. **DoD-2 [test]:** The user export's single `users` row is the caller's. It has
   no `password_hash`, `role` or `is_enabled` key, and it keeps the other columns
   (e.g. `id`, `username`).
3. **DoD-3 [test]:** The user export includes the caller's memos at all four
   scopes: `user` (with `scope_id` equal to the caller's id), `character`, `setup`
   and `session`. (US-079.AC-1)
4. **DoD-4 [test]:** With a second user seeded with characters, sessions, messages
   and memos, none of that user's rows appear in the first user's export. (UC-062,
   R5)
5. **DoD-5 [test]:** Every metadata table that has a `user_id` column is either in
   the user export's table set or named in the user-granularity exclusion constant.
   This is a guard that fails when a later feature adds unclassified user-owned
   material.
6. **DoD-6 [test]:** `export_character` returns exactly one `characters` row, which
   is the requested character. It also returns all of that character's setups and
   sessions, including archived ones (R6), and all messages of those sessions
   (settled, buried and current-zone). (UC-063)
7. **DoD-7 [test]:** The character export's memos are exactly those scoped to the
   character, to its setups and to its sessions. It includes no `scope='user'` memo
   and none from a sibling character, its setups or its sessions. (US-080.AC-1,
   UC-063)
8. **DoD-8 [test]:** The character export has no `users`, `llm_servers`, `models`,
   `auth_sessions` or `translations` key.
9. **DoD-9 [test]:** `export_character` for another user's character, and for an
   id that does not exist, both raise `CharacterNotFoundError`.
10. **DoD-10 [test]:** `export_session` returns exactly one `sessions` row, which
    is the requested session, even when it is archived (R6). It returns every
    message of that session, whether settled, buried or current-zone, and each
    buried row's `related_to` names a message id present in the payload. (UC-064)
11. **DoD-11 [test]:** The session export's memos are only those with
    `scope='session'` and that session's id. It includes no character, setup or
    user memo, and no memo of a sibling session under the same character.
    (US-081.AC-1)
12. **DoD-12 [test]:** The session export's payload keys are exactly `sessions`,
    `messages` and `memos`.
13. **DoD-13 [test]:** `export_session` for another user's session, and for an id
    that does not exist, both raise `SessionNotFoundError`.
14. **DoD-14 [test]:** In all three exports, id columns are decimal strings, under
    the same rule as step 001.
15. **DoD-15 [manual/live]:** `mypy app` and `ruff check .` pass.

## Dependencies
