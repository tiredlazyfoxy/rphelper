# Step 001 — Frame value types, the encoder, and the shared assistant append

## Goal

Create `services/llm/frames.py` with the seven frame value types and the one encoder that
turns a frame into its wire text, ids as decimal strings (D2). Add
`append_assistant_message` to `services/messages.py` as the one write of a
`role='assistant'` current-zone row (D8).

## Interface intent

**`app/services/llm/frames.py`** (new)

- **Seven frame value types**, immutable, one per event (D2):
  - **accepted**: the roleplayer's committed message id, an int;
  - **token**: text;
  - **tool start**: tool name, call id (opaque string), args (a JSON-serialisable mapping);
  - **tool result**: tool name, call id, summary (a string);
  - **tool fail**: tool name, call id, code;
  - **error**: code, message (string or none), detail (a mapping, default empty);
  - **done**: the assistant row's id, an int.
- **A frame union type** naming all seven, so a source can be typed as "an async iterator
  of frames".
- **The encoder.** Takes any frame and returns its wire text: `data: ` + compact JSON +
  `\n\n`. The JSON:
  - has `event` as the first key, with the field names and order of `001.context.md`;
  - renders both `message_id` fields as decimal **strings**;
  - leaves non-ASCII text unescaped.
- **The error-frame constructor.** Takes a `DomainError` and returns an error frame from
  its **inner** `code`, `message` and `detail`, not from `to_wire()`'s wrapper. `detail`
  is passed through as given; a missing one becomes an empty mapping.

**`app/services/messages.py`** (changed)

- **`append_assistant_message`**: same inputs and result as `append_message`: the
  connection, the id generator, the user id, the session id and the text, returning a
  `StreamMessage`. Inserts one current-zone row with role `"assistant"`, kind NULL,
  `related_to` NULL and `settled_at` NULL, inside one transaction, with the same session
  ownership check (`SessionNotFoundError` for an unknown or foreign session) and the same
  session bump. It does not check for blank text.
- **`append_message`**: behaviour unchanged. The coder may route both through one private
  insert helper parameterised by role.

## Definition of done

1. `[test]` Encoding an accepted frame with id `7250416938275332095` yields exactly
   `data: {"event":"accepted","message_id":"7250416938275332095"}\n\n`. Encoding a done
   frame with id `7250416938275332096` yields exactly
   `data: {"event":"done","message_id":"7250416938275332096"}\n\n`. In both, the id is a
   JSON string, not a number. (D2, `llm-and-streaming.md` ids rule)
2. `[test]` Encoding a token frame with text `"Привет, «мир»\nnext"` yields
   `data: ` + JSON whose parsed form is `{"event":"token","text":"Привет, «мир»\nnext"}`.
   The raw wire text contains the Cyrillic characters unescaped and ends with exactly one
   `\n\n`. A newline inside the text never produces a blank line inside the frame. (D2)
3. `[test]` Encoding a tool-start frame (`memo_search`, call id `"call_9f2"`, args
   `{"query":"x"}`) yields exactly
   `data: {"event":"tool_start","tool":"memo_search","call_id":"call_9f2","args":{"query":"x"}}\n\n`.
   A tool-result frame (`memo_search`, `"call_9f2"`, `"3 memos"`) yields exactly
   `data: {"event":"tool_result","tool":"memo_search","call_id":"call_9f2","summary":"3 memos"}\n\n`.
   A tool-fail frame (`web_search`, `"c2"`, `"tool_failed"`) yields exactly
   `data: {"event":"tool_fail","tool":"web_search","call_id":"c2","code":"tool_failed"}\n\n`.
   (D2)
4. `[test]` The error-frame constructor given `LlmUnreachableError("Provider timed out",
   {"server_id": "7250000000000000007"})` produces a frame that encodes to exactly
   `data: {"event":"error","code":"llm_unreachable","message":"Provider timed out","detail":{"server_id":"7250000000000000007"}}\n\n`.
   It has no `"error"` wrapper key, and the id in `detail` stays a string. Given
   `LlmUnreachableError()` with no arguments, it encodes `"message":null` and
   `"detail":{}`. (D2, error model)
5. `[test]` `append_assistant_message` on an owned session returns a `StreamMessage`
   with role `"assistant"`, kind `None`, `settled_at` `None`, the given text verbatim
   and the given session id. The row is readable afterwards through the `current_zone`
   view. (D8, US-132.AC-1)
6. `[test]` `append_assistant_message` against another user's session, or an unknown
   session id, raises `SessionNotFoundError` and writes no row. (D8)
7. `[test]` After `append_assistant_message`, `GET /api/sessions/{id}/zone` through the
   app answers 200 and lists the row with `"role":"assistant"`, its `id` a decimal
   string, in id order after an earlier `append_message` row. (D8; the `models/stream.py`
   role check)
8. `[test]` `append_message` still writes role `"user"`, unchanged. The existing
   `append_message` tests pass untouched. (D8)
