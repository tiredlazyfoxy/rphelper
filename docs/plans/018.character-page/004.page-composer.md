# Step 004 — The page composer

## Goal

Add the client half of create-and-seed: a `sessionsApi.ts` call that posts the opening
message to the character's sessions route, a small page-local state whose send effect
applies the new session to the workspace store and hands back its id, and
`CharacterComposer`, which renders the shared core alone (no kind switch, no setup
choice) and navigates into the session (D1, D5, US-117).

## Interface intent

**`app/sessionsApi.ts`** (changed; 011 `004`)

- **`StartedSession`** type (new): `Session`'s eight fields plus `opening_message`, which
  is 013's `Message` or null. Ids are strings.
- **Start-with-message call** (new): a character id, the opening text and an optional
  signal. It sends `POST /api/characters/<id>/sessions` with a body of exactly
  `{ "opening_message": <text verbatim> }` and resolves to the `StartedSession`. It rethrows
  the shared client's `ApiError` unchanged.
- **`startSession`**: request unchanged. It now resolves to **exactly the eight `Session`
  keys**, so the `opening_message: null` the route returns never reaches a store (D5).

**`app/characterComposerState.ts`** (new)

- **`CharacterComposerState`**: data class with observable fields only, constructed from a
  character id. It holds the character id, the **draft** (starts empty) and a **sending**
  flag.
- **Can-send derivation** (pure): the draft is not blank and nothing is sending.
- **Send effect**: takes the state, the workspace `SessionsState` and an on-started
  callback receiving the new session id (string). It does nothing unless sending is
  allowed. Otherwise it sets sending, posts the draft through the start-with-message call,
  and then:
  - **on success**: applies the response's eight session keys to the workspace state with
    `applySession`, clears the draft, and calls the callback with the response's `id`
    exactly as received;
  - **on failure**: keeps the draft and calls `notifyFailure` with the thrown error. The
    callback is not called and the workspace state is unchanged.
  
  Either way it clears sending. It takes no signal (a mutation) and never rejects.

**`app/CharacterComposer.tsx`** (new)

- **`CharacterComposer`**: an `observer`. Props: the character id and the workspace
  `SessionsState`. It creates one `CharacterComposerState` with `useState`. It renders a
  region **"Start a session"** headed **"Start a session"** (heading order matching the
  page's sections). Inside is `ComposerCore` (`003`) bound to the state's draft, with Send
  enabled by the can-send derivation and calling the send effect. No paste hook, no slots,
  no send-blocked reason. **No kind switch and no setup control.** The on-started callback
  router-**pushes** to `/sessions/<id>`, unless the component has unmounted by then.

## Definition of done

1. `[test]` The start-with-message call for character `"7250000000000000001"` with text
   `"  Hello\n"` sends exactly one `POST /api/characters/7250000000000000001/sessions` whose
   parsed body equals `{"opening_message": "  Hello\n"}` (no `setup_id` key). It resolves
   to the served nine-key object unchanged, with ids the identical strings. A 404
   `character_not_found` envelope rejects with an `ApiError` carrying that code.
   (US-117.AC-1, US-117.AC-4 — no setup sent; ids are strings)
2. `[test]` `startSession(id, null)` against a served nine-key `StartedSession` with
   `opening_message: null` resolves to an object with exactly the eight `Session` keys. Its
   request body is unchanged from 011. (D5)
3. `[test]` Can-send is false for an empty draft and a whitespace-only draft, true for
   "Hi", and false while sending. (D5)
4. `[test]` The send effect with draft "Hello there", on a 201, calls the callback once
   with the served id string, leaves the draft empty, and the workspace `SessionsState`
   then lists the served session holding exactly its eight keys. No `notifyFailure` call.
   (US-117.AC-1, D5)
5. `[test]` The send effect on a 500 envelope (and on a transport failure) keeps the draft
   "Hello there", calls `notifyFailure` once with the thrown error, does not call the
   callback, leaves the workspace state unchanged, clears sending, and resolves without
   throwing. (R10, D5)
6. `[test]` While a send is pending, a second send effect call sends no second request.
   (D5 — no double create)
7. `[test]` `CharacterComposer` renders a "Start a session" region holding a textbox
   "Composer" and a "Send" button, and **no** "Entry kind" group, no "Partner" / "My turn"
   radio, no "Setup" combobox, no "Settle" and no "Discard empty zone". "Send" is disabled
   until non-blank text is typed. (US-117.AC-4, D1)
8. `[test]` Routed in a `MemoryRouter` at `/characters/<C>`: typing "Hello there" and
   pressing "Send" sends one POST to `/api/characters/<C>/sessions` with exactly
   `{"opening_message": "Hello there"}`. After the 201 the location is `/sessions/<served
   id>`, and Back returns to `/characters/<C>` (a push). (US-117.AC-1, UC-080, D5)
9. `[test]` On a failed POST the location stays `/characters/<C>`, the composer still
   holds "Hello there", and "Send" is enabled again. (R10, D5)
10. `[test]` Pasting a 128,001-character text into the page composer raises the paste
    warning, makes no request, and does not prevent the insertion. (US-035.AC-1 — the core's
    warning on the second host)
11. `[manual/live]` In a browser against a running backend: on a character page, type a
    message and press Send. The workspace opens on a new session under that character,
    the tree shows the session, the zone holds the message as "You", and the record is
    empty. Back returns to the character page. (US-117.AC-1, US-117.AC-2, UC-080)
