# Step 003 — step-specific context

Feature-wide facts are in `context.md`: **D1**, **D4** (probe), **D5**, **D12** (route
shape), the **Wire contract** and the backend **Test conventions**. Only what is narrow to
this step is below.

## Built state at the touch sites (harvest and 021 `006.context.md`)

- Every existing route handler is a sync `def`. **This one is `async def`**, because it
  awaits the service and `request.is_disconnected()`. Do not convert other handlers.
- `require_user` (`app/dependencies.py`) → `CurrentUser` with `.id`. Take it as a
  parameter as well as router-level, because the handler needs the id.
- `get_settings` (`config.py`) is the FastAPI dependency. `get_engine(settings)`
  (`db/engine.py`) is a process-level cache, **not** a dependency. Call it with the injected
  settings, so a test that overrides `get_settings` gets its own engine.
- `get_id_generator` (`routers/bootstrap.py`) reads `app.state`. It is needed only if
  `002`'s frozen `translate_message` takes a generator (`002.context.md` "Ids").
- `SnowflakeIn` parses the path id. A non-numeric id is a 422 from validation.
- The factory dependency is **this module's own** function. It is not imported from
  `routers/stream.py`, which stays untouched (`context.md` "Not touched"). Name it
  distinctly from 021's.
- **`main.py`**: routers are included in order, and the module docstring lists them.
  Append the translation router after the last one present at build time (016–022 may have
  appended their own).

## The probe

A closure over the handler's `request` that returns the awaited value of
`request.is_disconnected()`. Under `TestClient` it reports `False`, so DoD-1's write
happens. The disconnected path is covered at the service level (`002` DoD-12), not here.

## Test shape

- `create_app()` with `dependency_overrides` for `get_settings` (file-local SQLite file)
  and the translation factory dependency (a file-local fake). `_as(user)` logs in through
  the real login route, as `tests/test_stream_router.py` does.
- DoD-5 overrides **only** `get_settings`. Its registry row's `base_url` is something like
  `http://127.0.0.1:9` and the timeout setting is small (e.g. 0.5 s), so the real
  `LlmClient`'s connect error becomes `llm_unreachable` → `translation_failed`.
- DoD-6 inspects `app.routes` for path `/api/messages/{message_id}/translation`.
