# Step 002 — step-specific context

Feature-wide facts are in `context.md`: **D2** (joined `chat_stream`), **D3** (English
fallback), **D4** (probe), **D5** (failure mapping), **D6** (eligibility), **D8** (three
phases), **D9** (stale guard), **D10** (think strip), the **Wire contract** and the backend
**Test conventions**. Only what is narrow to this step is below.

## The eligible-row read

- Select from the **`settled_entries`** selectable (012's view in `db/schema.py`), never
  raw `messages` (R11). Filter on `id = :message_id` and `kind = 'partner'`, with owner
  scope in the same statement. Use the predicate `services/messages.py` already uses for
  `messages` ownership: a join to `sessions` on `sessions.user_id = :caller`, or the row's
  own owner column if `messages` has one.
- Columns needed: `id`, `session_id`, `text`. No row → `MessageNotFoundError()`.
- `get_session_configuration(conn, user_id, session_id)` (017 `003`) gives
  `.preferred_language.value`. It is already trimmed and non-blank, or none. None → the
  fallback constant.

## The write transaction (D8, D9)

One `with connection.begin():` block containing:

1. a re-read of the same eligible row (settled, partner, caller-owned). Continue only if it
   exists **and** its `text` equals the text sent to the model;
2. an insert of `id` (from the app's id generator; see below), `user_id`, `message_id`,
   `target_language`, `text`, `created_at` (fixed-width now), using SQLite's
   insert-or-ignore form (`sqlalchemy.dialects.sqlite.insert(...).on_conflict_do_nothing(
   index_elements=["message_id", "target_language"])` or an equivalent `prefix_with("OR
   IGNORE")`).

**Ids.** Every primary key is a snowflake minted in application code (`app/ids.py`). The
service needs a generator. It takes one as an extra parameter, or uses the module-level
accessor `app/ids.py` exposes. Either way, the skeleton freezes the choice from the code.
If it becomes a parameter, step `003` passes the request's generator (the
`get_id_generator` dependency, as 021 `006` does).

## The model call

- `open_chat_client(conn, enabled_model, timeout_seconds, factory)` → a client. Then
  `client.chat_stream(enabled_model.model_name, messages, [])`. Close it with
  `contextlib.aclosing` or an explicit `aclose()` in a `finally`.
- `messages` is exactly two `ChatMessage`s (021 `002` adds the `system` role):
  - `system`: **`Translate the user's message into {target_language}. Keep its meaning,
    tone, formatting and line breaks. Reply with the translation only — no notes, no
    commentary, no quotation marks.`** with the target language substituted;
  - `user`: the row's stored `text`, verbatim.
- Joined text → 021 D4's strip function (`services/llm/chat.py`) → if `.strip()` is empty →
  failure. The stored and returned text is the stripped result as the strip function
  returns it. No further trimming happens beyond that function's own rule.

## Cause sentences for `TranslationFailedError`

| Cause | Message |
|---|---|
| `LlmUnreachableError` from `chat_stream` | **"Translation failed: the model server could not be reached."** |
| empty result | **"Translation failed: the model returned no text."** |

Raise with `from` the original exception where there is one. Tests assert the code and the
detail, not the sentences.

## Logging (loguru)

- hit: `translate cached=true message=<id> ms=<n>`
- miss written or skipped: `translate cached=false message=<id> ms=<n>`. Append
  ` written=false` when the probe or the D9 guard skipped the write.
- failure: `translate failed message=<id> code=translation_failed ms=<n>`
- Ids as decimal strings. `ms` is integer milliseconds since the call began. Never text.

## Test shape

- The fake chat client and factory are file-local (`context.md` Test conventions). The
  fake's `chat_stream` takes a per-test hook, run on first entry, for DoD-13 / 14 / 18.
- The probe is a file-local async function that appends to a shared order list and returns
  a fixed bool.
- DoD-15 seeds what `assemble_context` needs: a user, a character with a sheet, a session,
  and a settled partner row. No forced memos are required. It compares the two
  `AssembledContext` values for equality.
- DoD-17 adds a loguru sink (`logger.add(list.append, format="{message}")`) and removes it
  afterwards.
