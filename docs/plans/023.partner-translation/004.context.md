# Step 004 — step-specific context

Feature-wide facts are in `context.md`: **D4** (client cancel), **D13** (state shape and
the per-mount cache), **D14** (invalidate), the **Wire contract**, the frontend
cross-cutting constraints and **Test conventions**. Only what is narrow to this step is
below.

## Built state at the touch sites (harvest)

- **`src/shared/api.ts`**: `apiPost(path, body?, signal?)`. It sends JSON when a body is
  given, threads the `AbortSignal` into `fetch`, throws `ApiError` (`code`, `status`,
  `detail`) on non-2xx, and **rethrows an `AbortError` raw**, so it is not wrapped as an
  `ApiError`. To send no body, pass `undefined`.
- **`src/shared/notifyFailure.ts`**: `notifyFailure(error)` shows the error's message
  (for an `ApiError`, the server's message) as a transient red notification. A new caller
  needs no guard change: `tests/conventions.test.ts` restricts only direct
  `@mantine/notifications` imports.
- **`src/app/streamState.ts`** is the pattern to copy, not to import:
  - effects are free functions;
  - they write inside `runInAction` after `await`;
  - they check `signal?.aborted` before writing;
  - they never reject;
  - they use the abort idiom from `context.md`.

## Shape notes

- Observable collections: `observable.map` / `observable.set`, or plain `Map` / `Set`
  fields that `makeAutoObservable` makes observable. The controllers map is annotated
  `false`, which keeps it non-observable, so aborting never triggers a render.
- "Only if the row's controller is still the one this call created" is what keeps an
  invalidate-then-reflick sequence from letting the first call's `finally` clear the second
  call's pending flag.
- A cancel or invalidate aborts the controller. The awaiting flick then sees an abort and
  must write **nothing** except clearing its own pending entry, under the guard above.
  The cached text and shown flag stay untouched.
- The view derivation is the only thing `005` reads. Its exact return shape is frozen by
  the skeleton.

## Test shape

- `fetch` is stubbed with a deferred promise per call, so tests can observe `"pending"` and
  resolve or abort on demand. An aborted fetch stub rejects with a `DOMException` named
  `"AbortError"` when its signal aborts.
- `notifyFailure` is mocked with `vi.mock("../../src/shared/notifyFailure")`.
- These are pure state tests: no rendering, and no `AppProviders` needed.
