Feature-wide facts are in `context.md`: **D5** (new note first), **D8** (opt-in sortable
cards, the keyboard filter, the disabled conditions, jsdom limits, the selection
tension), **D9** (`autoFocus`), the strings table (card name, reorder failure), and Test

## Borrowed interfaces

- `@dnd-kit/sortable`: `SortableContext`, `verticalListSortingStrategy`, `useSortable`
  (its `attributes` option lets the role be set; its return gives `attributes`,
  `listeners`, `setNodeRef`, `transform`, `transition`).
- `@dnd-kit/utilities`: `CSS.Transform.toString` for the inline transform.
- `app/memoLevelState.ts` (`002`): `isReorderInFlight`, `reorderFailure`.
- `shared/MarkdownEditor.tsx`: the TipTap editor built by an earlier feature. Its editor
  setup has an autofocus option, which is the natural carrier for `autoFocus`. The
  skeleton reads the module.

## Keeping 015's list semantics

dnd-kit's `useSortable` attributes default to `role="button"`. Spread on the `li`, that
would turn every note into a button and break 015's `getAllByRole("listitem")`
assertions. Pass the role through the hook's `attributes` option as `"listitem"` (or
override the spread). Then put the position name on the `li` with `aria-label`. The
textbox inside keeps its own name "Note". Testing Library's name matching is exact, so
"Note 1 of 3" never matches a query for "Note".

## The keyboard filter

```
onKeyDown(event):
  if event.target is not event.currentTarget → return (do not forward)
  listeners.onKeyDown(event)
```

That is shape only. The coder writes it. Pointer listeners are forwarded unfiltered (U2:
the whole card is the drag surface). Focus moving into the editor marks the card as
editing and disables it, which covers the selection case once the editor has focus (D8).

## The editing flag

Component-local `useState` in the sortable wrapper, set by `onFocus` and cleared by an
`onBlur` whose `relatedTarget` is outside the editor area (the same "focus leaves the
wrapper" test 015 uses for save). It is view state with no meaning outside the card
(`ui-conventions.md`'s modal-flag precedent), not MobX state. It feeds `useSortable`'s
`disabled`.

## No hook without a context

Hooks cannot be conditional. So the group renders one of two components per saved note:
the sortable wrapper (which calls `useSortable`) when `reorderable`, or the plain card
when not. Both render the same inner card body. This is the "don't fork the card
component" line: one body, two thin outer shells. `SortableContext` is rendered only when
`reorderable`.

## Where the reorder failure sits

Inside the group's region, between the heading and the list (or after the list). It is
dimmed or red `Text`, matching 015's per-note failure style. It is not inside any
listitem, because it belongs to the level (`002.context.md` "Why `reorderFailure` is
level-wide").

## Package installation

The coder installs the three packages with `npm install` from `frontend/`, which updates
`package.json` and `package-lock.json` together. No other dependency moves. If peer
requirements force a version choice, prefer the newest releases that declare React 19
support, and note the versions in `## Files Changed`.

  `sensors={[KeyboardSensor]}` (via `useSensors` / `useSensor` in a tiny wrapper
