## Statements — what the new and changed code carries

| Operation | Statements |
|---|---|
| allocation (changed) | `SELECT COALESCE(MIN(sort_key), 1) - 1 FROM memos WHERE user_id = :user_id AND scope = :scope AND scope_id = :stored_scope_id`, inside create's `begin()`, after the target check, before `next_id()` (015 D12's order is unchanged) |
| reorder — target | the same per-level target check create uses (characters / setups / sessions each with its own `user_id` predicate; none for `"user"`) |
| reorder — set read | `SELECT id FROM memos WHERE user_id = :user_id AND scope = :scope AND scope_id = :stored_scope_id` |
| reorder — check | in Python over the read ids: `len(given) == len(set(given))` and `set(given) == set(read)`. Comparing two id sets that both came from owner-scoped SQL is not "fetch and filter": the owner predicate is in the read |
| reorder — writes | one `UPDATE memos SET sort_key = :index WHERE id = :id AND user_id = :user_id AND scope = :scope AND scope_id = :stored_scope_id` per id, in order. **No `updated_at`** in the `SET` |
| reorder — result | the 015 list select (`… ORDER BY sort_key, id`) inside the same transaction, mapped with 015's row mapper |

All of it happens inside one `with connection.begin():`. A raise before the writes leaves
nothing written and the transaction rolled back.

## Why the set check uses no unique index

015 D4 deliberately declared no unique constraint on `sort_key`. The rewrite passes
through duplicate values mid-transaction (index 0 may already be held by another note),
and no constraint exists to collide. Do not add one.

## The handler and its 422

The reorder request model carries the "non-user scope needs `scope_id`" rule as a
model-level validator, exactly as `CreateMemoRequest` does (015 `001.context.md`
"Non-user scope requires `scope_id`"). So the handler has no manual 422. `memo_ids` items
are 015's inbound snowflake type (non-numeric → 422). If the skeleton finds a list of the
inbound snowflake awkward, it may validate items with the same before-validator form 011
froze for `OptionalSnowflakeIn`. DoD-9 pins the behaviour, not the form.

## Route declaration

`routers/memos.py` declares its handlers with full literal paths (015 D9). Put
`PUT /api/memos/order` above the `/api/memos/{memo_id}` handlers. Starlette matches path
and method together, and only a `PUT` reaches this handler. A `PATCH` or `DELETE` to
`/api/memos/order` falls through to the `{memo_id}` handlers and answers 422 on the
non-numeric id, which is harmless and not tested.

## Logging

If the reorder logs, it logs the scope, the level id and the count. Never a body, and
never the list of ids.
