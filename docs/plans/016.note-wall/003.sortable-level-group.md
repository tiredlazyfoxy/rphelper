# Step 003 — The level group: new note on top with focus, and opt-in sortable cards

## Goal

Add the three `@dnd-kit` packages and an optional `autoFocus` prop on
`shared/MarkdownEditor`. Change `MemoLevelGroup` so that:

- the new note opens at the **top** of its level with focus in its body (D5, D9);
- behind an opt-in `reorderable` prop, every saved note is a **focusable sortable card**
  inside a per-level `SortableContext`. The card is not draggable while its editor has
  focus or while the level's reorder is in flight, and keyboard activation is accepted
  only from the card itself (D8);
- the level's reorder failure renders inline.

The character page, which does not opt in, is unchanged apart from the new note's place
and focus.

## Interface intent

**`package.json` / lockfile**

- Dependencies `@dnd-kit/core`, `@dnd-kit/sortable` and `@dnd-kit/utilities` at current
  versions compatible with React 19, installed so the lockfile records them. No other
  dependency changes.

**`shared/MarkdownEditor.tsx`** (extended)

- **`autoFocus`**: a new optional boolean prop, false by default. When true, the editor
  moves focus into its editable body once it is ready after mounting. Every existing prop
  and behaviour is unchanged. A caller that omits it sees no difference.

**`app/MemoLevelGroup.tsx`** (changed)

- **`MemoLevelGroup`** gains an optional **`reorderable`** prop (boolean, false by
  default). The existing props (`state`, `title`, `headingOrder`, `onRetry`) are
  unchanged.
- **The new note's listitem renders first** in the list, before the saved notes, and its
  `MarkdownEditor` gets `autoFocus`. Saved notes' editors never get `autoFocus`. Nothing
  else about the new note changes: no flags, no reach line, and its failure text under
  it.
- **When `reorderable` is false** the group renders exactly as 015 `007` built it,
  except for the new note's place and focus. No dnd-kit hook runs, and it renders without
  any `DndContext` ancestor.
- **When `reorderable` is true**, the saved notes sit in a `SortableContext` over the
  level's saved note ids in order (vertical list strategy). Each saved note renders
  through a sortable wrapper around the **same** card markup (no second card component)
  whose `listitem`:
  - keeps role `listitem`, is focusable (`tabIndex` 0), and has the accessible name
    **"Note <n> of <total>"** (1-based among the level's saved notes) plus dnd-kit's
    `aria-roledescription` and `aria-describedby`;
  - carries the sortable pointer and keyboard listeners. The keydown listener forwards to
    dnd-kit **only** when the event's target is the `listitem` element itself, so keys
    typed in the editor or pressed on a flag button never start a drag;
  - applies the sortable transform and transition as inline style while dragging;
  - is **disabled** as a sortable while focus is inside its editor area (component-local
    view state, set on focus entering and cleared on focus leaving that area) and while
    `isReorderInFlight(state)` is true.

  The new note's listitem is never sortable: no listeners, no `tabIndex`, no position
  name.
- **The reorder failure**: when `reorderFailure(state)` is non-null, its text renders
  inside the group's region (under the heading, outside the list). There is no
  notification.
