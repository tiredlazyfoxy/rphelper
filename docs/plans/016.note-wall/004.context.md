## Level keys

A level's `scope` is unique within a chain (015 `008.context.md` "Titles and headings"
keys groups by it). Use it as the decision's level key. The decision never needs the
scope id.

## Ids across the dnd-kit boundary

dnd-kit's identifiers are `string | number`. The sortable ids are memo id strings
(`003`). In the drag-end handler, read them with `String(event.active.id)` and
`event.over ? String(event.over.id) : null`. Never parse them, and never annotate an id
as `number` (`tests/ids-are-strings.test.ts` scans `src/`).

## Why the decision is split from the effect

The decision is the one place US-103.AC-2 is enforced, and it must be testable with plain
arrays (`memoReorder.test.ts`, no DOM, no MobX). The effect is what the drag-end handler
calls, and it is testable with level states and a stubbed `fetch`, without a drag
gesture. jsdom cannot produce the gesture (zero-size rects). The handler in
`MemoChainSection` is one line that calls the effect.

## Announcements

Override the default announcements (they interpolate the raw ids). Each message names
the note's 1-based position in its level and the level's group title ("Picked up note 2
of 4 in Character notes.", "Note moved to position 3 of 4.", "Note dropped.",
"Reorder cancelled."). The exact wording is the coder's and is not a test contract.
DoD-9 only asserts that no memo id appears. The titles live privately in this module (015
`008`'s scope-to-title map), so the announcements are built here.
