# Step 004 — The drop decision and the chain's drag context

## Goal

Add `app/memoReorder.ts`: a pure, DOM-free decision that turns (levels, active id, over
id) into one level's new id order, or a refusal when the drop would cross a level
(US-103.AC-2). Add an effect that applies an accepted decision through `002`'s reorder.
Wrap `MemoChainSection`'s groups in one `DndContext` with the pointer (distance) and
keyboard sensors, make every group reorderable, and route drag-end to that effect (D8).

## Interface intent

**`app/memoReorder.ts`** (new)

- **The drop decision** (pure, DOM-free, no MobX): takes the levels as an ordered list,
  each with an identifying key and its saved note ids in order, plus the active id and
  the over id (the over id possibly absent). Returns `null` when:
  - the over id is absent;
  - active and over are the same id;
  - either id is in no level;
  - active and over are in **different** levels.

  Otherwise it returns the key of the one level involved and that level's ids with the
  active id moved to the over id's index (the array-move rule). It may use
  `@dnd-kit/sortable`'s `arrayMove`; it touches no DOM.
- **The drop effect**: takes the chain's level states (`MemoLevelState[]`), the active id
  and the over id. It builds the decision's input from each level's `memos`, and calls
  the decision. On `null` it does nothing at all: no write, no request. Otherwise it calls
  `reorderMemoLevel` on that level's state with the new order. It returns once that
  settles, never rejects, and adds no rule of its own beyond the decision and `002`'s
  guards.

**`app/MemoChainSection.tsx`** (changed)

- In the `"ready"` render the level groups sit inside **one** `DndContext` configured
  with:
  - a `PointerSensor` whose activation constraint is a distance of **6px**;
  - a `KeyboardSensor` using `sortableKeyboardCoordinates`;
  - a drag-end handler that calls the drop effect with `state.levels`, the event's active
    id and its over id (each as a string, or absent);
  - announcements that name a note by its position in its level and its group, never by
    its id.
- Every `MemoLevelGroup` it renders gets `reorderable`. Everything else (region "Notes",
  titles, heading orders, keys, load, retry, the absent setup group) is unchanged.

## Definition of done

1. `[test]` The decision, same level: with levels `user: [u1, u2]`,
   `character: [c1, c2, c3]` and `session: [s1]`, active `c1` over `c3` returns the
   character level with `[c2, c3, c1]`, and active `c3` over `c1` returns
   `[c3, c1, c2]`. (UC-076, US-102)
2. `[test]` The decision refuses a cross-level drop: active `c1` over `u2`, active `u1`
   over `s1` and active `s1` over `c2` each return `null`. (US-103.AC-2)
3. `[test]` The decision returns `null` for an absent over id, for active equal to over,
   and for an active or over id found in no level. Its inputs are not mutated.
4. `[test]` The drop effect, cross-level: given level states for user, character and
   session holding notes, a call with a character note dropped over a user note sends
   **no request**, and every level's `memos` order is unchanged. (US-103.AC-2 — refused
   in the handler, not only in the preview)
5. `[test]` The drop effect, same level: a call with `c1` dropped over `c3` immediately
   orders the character level `c2, c3, c1`. It sends exactly one
   `PUT /api/memos/order` with `{"scope": "character", "scope_id": "<C>", "memo_ids": ["c2", "c3", "c1"]}`
   (string ids), and the other levels are untouched. (UC-076, US-102, D7)
6. `[test]` The drop effect while that level's reorder is in flight sends nothing more.
   A refused (`null`) drop never touches `reorderFailure`. (D7, D8)
7. `[test]` `MemoChainSection` with a four-level chain: every saved note's listitem in all
   four groups is focusable and named "Note <n> of <total>" for its own group. The region,
   the group names and their order (015 `008` DoD-2) still hold. 015 `008`'s other
   assertions in this file (DoD-1 to DoD-6) pass, with one change: a just-created note is
   found **first** in its group rather than last (D5). (D8; R2)
8. `[test]` `MemoChainSection` with a three-level chain (no setup) renders exactly three
   reorderable groups, with no "Setup notes". (US-057.AC-1, R2)
9. `[test]` Inside a rendered `MemoChainSection`, focusing a saved note's listitem and
   pressing Space makes dnd-kit's announcement live region hold a non-empty message. That
   message contains **none** of the chain's memo id strings. (US-102 keyboard path; D8 —
   announcements never read ids)
10. `[manual/live]` In a browser on the wall (after `006`), against a running backend:
    - **keyboard**: focus a card, press Space, ArrowDown, Space. The card moves down one
      place in its level, and the order survives a reload.
    - **pointer**: drag a card within its level and it lands there.
    - **cross-level**: drag a card onto another level's group. It returns to its own
      level, and no request is sent (devtools network).
    - **in flight**: while the server is slow (throttled), a second drag in that level
      does not start.
    - **failure**: with the backend stopped, a drop snaps back and shows "Could not
      reorder the notes.".
    - **announcements**: a screen reader (or the live region's text) reads positions and
      group names, never ids.

    (US-102, US-103.AC-2, U1)
