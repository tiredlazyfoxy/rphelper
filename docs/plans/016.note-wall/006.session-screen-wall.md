# Step 006 — The wall on the session screen

## Goal

Make `SessionScreen`'s ready render the note wall's home. It owns one `NoteWallState` per
mount, reads `narrow` from the 820px query, and renders `NoteWallLayout` with 011's header
and 013's stream in the stream column and 015's `MemoChainSection` **moved** into the
wall. An "Open notes" control sits in the header while the wall is not visible. `storage`
is threaded `App` → `SessionRoute` → `SessionScreen`, re-freezing 011's props. Amend the
011 / 013 / 015 tests whose observations move (D1–D4).

## Interface intent

**`app/SessionScreen.tsx`** (changed; 011-owned, edited by 013 `007` and 015 `008`)

- **`SessionScreenProps`** gains **`storage`** (a `LayoutStorage` or `null`, required):
  `{ sessionId, characters, storage }`. **`SessionRouteProps`** gains the same required
  `storage`: `{ characters, storage }`. `SessionRoute` passes it through unchanged, still
  keyed by the session id. **This re-freezes 011 `009`'s frozen props types**; the
  skeleton records the new freeze.
- **`SessionScreen`** creates its `NoteWallState` once with
  `useState(() => createNoteWallState(storage))`. It reads `narrow` with
  `useMediaQuery(NARROW_VIEWPORT_QUERY, false, { getInitialValueInEffect: false })`.
  - The `"idle"` / `"loading"`, `"not-found"` and `"failed"` renders are unchanged and
    contain **no** wall, no "Open notes" and no `MemoChainSection` (US-095 by
    construction, D1).
  - The `"ready"` render becomes one `NoteWallLayout` (state, `narrow`, `storage`):
    - its **stream** slot holds 011's header (unchanged, plus the open control below) and
      013's `SessionStream`, in that order;
    - its **wall** slot holds `MemoChainSection` for the loaded session's id, removed from
      its former place in the main column (015 `008`).
  - **"Open notes"**: an `IconButton` with `IconNotes`, label "Open notes", running
    `openWall`. It renders in the header only while `isWallVisible(state, narrow)` is
    false.

**`app/App.tsx`** (changed)

- The `/sessions/:id` route passes the `storage` `App` already holds:
  `SessionRoute` with `characters` and `storage`. Nothing else changes. `AppProps`,
  `WorkspaceShell`'s props and every other route are untouched.

## Definition of done

1. `[test]` Ready, with an empty layout storage: the main region shows the session header
   with an "Open notes" button and the stream. No complementary landmark is accessible.
   With `{ hidden: true }` the "Note wall" complementary is found, inside the main
   region, holding the "Notes" region. `GET /api/sessions/<id>/memo-chain` is requested
   exactly once. (D1, D3; US-094)
2. `[test]` Pressing "Open notes" makes the "Note wall" complementary accessible inside
   the main region, holding the region "Notes" with its groups ("Your notes", "Character
   notes", "Setup notes" when the session has a setup, "Session notes") listing the
   chain's notes. "Open notes" is gone. No further memo-chain request is made. The layout
   record is not written. (US-094.AC-1, UC-072 steps 1–2, D3, D4)
3. `[test]` On the open wall, pressing "Pin notes" writes `wallPinned: true` to the
   storage, and the control reads "Unpin notes". Unmounting and rendering the screen
   again with the **same** storage (a reload) shows the "Note wall" accessible without
   pressing anything, and no "Open notes". (US-094.AC-2, UC-072 step 3)
