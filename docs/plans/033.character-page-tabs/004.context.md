## Setup choices source

Today the Sessions section loads its Setup select's choices from
`state.setups` (reloaded in `onDropdownOpen`) via the setups list call in
`setupsApi.ts`. This step gives the composer its own copy of that behaviour,
because the composer store and the sessions store are separate section-owned
stores. The extra setups GET on page open is expected (step 005 may remove the
Sessions section's one); if an existing request-count assertion in
`CharacterScreen.test.tsx` / `App.test.tsx` counts setups GETs, that is why those
files are in this step's Test files.
