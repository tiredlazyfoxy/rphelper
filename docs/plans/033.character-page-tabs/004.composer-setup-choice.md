# Step 004 — composer: optional setup choice on the first message

## Goal

Give the character page's composer a small Setup select ("No setup" default,
working setups as options) and send the chosen setup together with the opening
message in the one create request, so a session with a setup is started by
writing (D8).

## Interface intent

- **`startSessionWithMessage`** (`sessionsApi.ts`) — gains an **optional setup
  id** (string or null) beside the character id and opening text. With a setup id
  the request body carries both `opening_message` and `setup_id`; with none the
  body is exactly `{ opening_message }`, as today. Return value and error
  behaviour unchanged.
- **`CharacterComposerState`** — gains observable fields for the setup choices
  (the character's working setups), their load status / failure, and the
  selected setup id (null = "No setup"). Observable fields only.
- **`loadComposerSetups`** (new free function in `characterComposerState.ts`) —
  loads the character's setups through the existing setups list call in
  `setupsApi.ts`, keeps only **non-archived** ones as choices, records failure
  without throwing, honours an abort signal. If the selected setup is no longer
  among the choices after a reload, the selection falls back to "No setup".
- **`sendCharacterComposer`** — passes the selected setup id through to
  `startSessionWithMessage`. Success and failure handling unchanged (navigate
  push to `/sessions/<id>` with `firstReplyState()`; failure → `notifyFailure`,
  draft kept).
- **`CharacterComposer`** — renders a small Mantine `Select` labelled **"Setup"**
  through one of `ComposerCore`'s existing slots (`underArea` or `besideSend`);
  first option "No setup", then the working setups by name. Loads choices once on
  mount and **reloads them when the dropdown opens** (so a setup created in the
  Setups tab appears without a page reload). Disabled while sending. When the
  load failed, a non-blocking line **"Could not load setups to choose from."**
  renders beside it and sending still works with "No setup". No kind switch.

## Definition of done

1. DoD-1 [test] `startSessionWithMessage` with a setup id posts once to the
   character's sessions route with a body holding the opening message and that
   setup id (as a string); without one the body is exactly the opening message
   alone. (D8)
2. DoD-2 [test] The "New session" composer shows a "Setup" select whose selected
   value is "No setup" on open. (D8)
3. DoD-3 [test] The select offers "No setup" plus the character's non-archived
   setups by name; archived setups are not offered. (D8, UC-021)
4. DoD-4 [test] Sending with "No setup" posts a body carrying no setup id and
   navigates to the new session. (D8, US-117.AC-1, R2)
5. DoD-5 [test] Choosing a setup and sending posts one request carrying both the
   opening message and the chosen setup id, then navigates to `/sessions/<id>`.
   (D8, US-117.AC-1, US-117.AC-2)
6. DoD-6 [test] If loading setups fails, the line "Could not load setups to
   choose from." renders and sending with "No setup" still succeeds. (D8, R2)
7. DoD-7 [test] Opening the dropdown reloads the choices: a setup that appeared
   on the server since page open is offered. (D8)
8. DoD-8 [test] A refused send (e.g. `setup_archived`) raises the failure
   notification, keeps the draft text and does not navigate. (D8)
9. DoD-9 [test] The Setup select is disabled while a send is in flight; the
   composer offers no kind switch. (D8)
10. DoD-10 [manual/live] The select reads as a small control attached to the
    composer box.
