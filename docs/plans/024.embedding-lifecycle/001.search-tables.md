# Step 001 — `db/search_tables.py`: FTS5 and vec0 ensure, triggers, back-fill

## Goal

Add one module that owns all virtual-table DDL (`context.md` D2, D3, D8):

- the idempotent FTS ensure, with triggers and a one-time back-fill;
- the idempotent vec0 ensure at a given dimension, with the mismatch check;
- a dimension read-back.

`create_first_administrator` also ensures the FTS half.

backend/app/db/search_tables.py
backend/app/services/bootstrap.py

## Test files

backend/tests/test_search_tables.py

## Interface intent

**`app/db/search_tables.py`** (new)

- **Table-name constants** for `memo_fts`, `message_fts`, `memo_vec` and `session_vec`. They
  are module-level so later steps never re-type the names.
- **`ensure_fts_tables`**: takes a connection that is already inside a transaction. If
  absent, it creates:
  - `memo_fts` over `memos.body`, as external content keyed on `id`;
  - `message_fts` over `messages.text`, as external content keyed on `id`;
  - the triggers in `001.context.md`.

  When it creates a table, it back-fills that table **once** from existing rows. For
  `message_fts`, that means record rows only. It creates any missing trigger even when its
  table already exists. A second call changes nothing. It returns nothing.
- **`vector_table_dimension`**: takes a connection and one of the two vector-table names.
  It returns the declared dimension of that vec0 table, read back from its stored DDL, or
  none when the table does not exist.
- **`ensure_vector_tables`**: takes a connection inside a transaction and the designated
  dimension (a positive integer).
  - It creates `memo_vec(memo_id …, embedding FLOAT[dim])` and
    `session_vec(session_id …, embedding FLOAT[dim])` when absent.
  - If either table exists with a different dimension, it raises `NoEmbeddingModelError`
    with `detail` `{"reason": "dimension_mismatch"}` and a fixed message, before creating
    anything.
  - A second call with the same dimension changes nothing.

**`app/services/bootstrap.py`**

- **`create_first_administrator`**: after its existing `metadata.create_all` and inside the
  same transaction, it calls `ensure_fts_tables`. It creates no vector table, because
  there is no designated model at bootstrap. Its signature and return are unchanged.

## Definition of done

1. `[test]` On a fresh `create_all` database, `ensure_fts_tables` inside a committed
   transaction leaves `memo_fts` and `message_fts` present. A second call raises nothing,
   and leaves the same set of `sqlite_master` entries (tables and triggers) and the same
   indexed content. (D2)
2. `[test]` **Back-fill.** These rows exist before the first ensure:
   - two memos with distinct body tokens;
   - for one session: a record row (`settled_at` set, `related_to` null), a zone row
     (both null), and a buried row (`related_to` set).

   After the ensure:
   - an FTS `MATCH` on each memo token returns that memo's id as rowid;
   - a `MATCH` on the record row's token returns its id;
   - the zone and buried rows' tokens return nothing;
   - `integrity-check` passes on both tables.

   (US-115, R11)
3. `[test]` **Memo triggers** (with the tables ensured first):
   - a memo inserted afterwards is found by its token;
   - after a `body` update, the old token finds nothing and the new token finds it;
   - an update of only `is_enabled`, `is_forced` or `sort_key` leaves every `MATCH` result
     unchanged;
   - after a delete, its token finds nothing;
   - `integrity-check` passes after the sequence.

   (D5)
4. `[test]` **Message triggers** (tables ensured first). In order, on one row:
   - (a) a zone insert is not found;
   - (b) a zone-row text edit is not found;
   - (c) a settle-shaped single UPDATE that sets `settled_at` and rewrites `text` → the new
     text is found and the pre-settle text is not;
   - (d) a text edit of the record row → the new text is found and the old text is not;
   - (e) a re-open-shaped UPDATE clearing `settled_at` → its text is not found.

   On other rows:
   - (f) a row inserted already settled (partner filing) is found;
   - (g) a zone row whose `related_to` is set (burial) is not found.

   `integrity-check` passes after every step. (US-110.AC-2, US-109.AC-2, US-115)
5. `[test]` `ensure_vector_tables(conn, 8)` creates both tables, and
   `vector_table_dimension` reports 8 for each. A second call with 8 raises nothing and
   preserves a previously inserted row. A call with 16 raises `NoEmbeddingModelError`
   whose `code` is `no_embedding_model` and whose `detail` equals
   `{"reason": "dimension_mismatch"}`, and both tables still report 8. (D8)
6. `[test]` `vector_table_dimension` returns none for each name on a database where the
   vector tables were never created.
7. `[test]` **DDL is transactional.** `ensure_fts_tables` and `ensure_vector_tables` run
   inside a transaction that is then rolled back. Afterwards, none of the four virtual
   tables and none of the triggers exist. (U1, U2)
8. `[test]` `create_first_administrator` on an empty database leaves `memo_fts` and
   `message_fts` present, and `memo_vec` / `session_vec` absent. This test lives in
   `test_bootstrap_service.py`, and its existing tests stay unchanged. (D2)
9. `[test]` **Snowflake keys (U6).** A memo and a message with ids above 2^60 are indexed
   by the triggers, and the FTS rowid returned equals the id. In `memo_vec` and
   `session_vec`, a vector inserted under an id above 2^60 is returned by a point lookup
   on that id, and its deserialised values equal the inserted ones. (D3)
10. `[test]` None of the four virtual-table names, and no FTS5 / vec0 shadow table, is a
    key of `schema.metadata.tables`. (D2)
