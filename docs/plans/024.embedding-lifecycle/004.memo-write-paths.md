# Step 004 — Memo write paths: strict embed on create / body change, none on toggles, delete drops the vector

## Goal

Wire the memo service and router into the embedding lifecycle (`context.md` D5, D7, D8):

- create and a changed body embed **strictly** in the write's transaction;
- flag-only updates, an unchanged body and reorder do **no** vector work and make **no**
  embed call;
- delete removes the memo's vector row;
- every body-touching write and every delete ensures the FTS half.

## Interface intent

**`app/services/memos.py`**

- **`create_memo`**: unchanged positional inputs and result. It gains keyword-only
  `client_factory` and `timeout_seconds` (D9 defaults). Inside its existing transaction,
  after the insert:
  - it ensures FTS;
  - when the body is non-blank (D7), it opens the designated model, ensures the vector
    tables, embeds the body alone, and writes `memo_vec` for the new id.

  A blank body does no vector work. "Unavailable" propagates, and nothing is stored.
- **`update_memo`**: unchanged inputs and result, plus the same two keyword-only
  parameters. **Only when `body` is given and differs from the stored body**, after the
  update and inside the same transaction:
  - it ensures FTS;
  - it either re-embeds strictly and rewrites `memo_vec`, or, when the new body is blank,
    deletes the memo's `memo_vec` row.

  An update carrying only `is_enabled` / `is_forced`, or a body equal to the stored one,
  performs **no** vector or FTS-ensure work and **never calls the factory**, whatever the
  registry state (UC-044, UC-075).
- **`delete_memo`**: unchanged signature. Inside its transaction, it ensures FTS and
  deletes the memo's `memo_vec` row (no model needed).
- **`reorder_memos`** (016): **not modified**.
- A private helper for "embed this memo's body and write its row" may live in this module.

**`app/routers/memos.py`**

- The POST create and PATCH update handlers depend on the shared `get_llm_client_factory`
  (`app.dependencies`) and on `get_settings`. They pass the factory and
  `settings.llm_request_timeout_seconds` to the service.
- Status codes, request bodies and `MemoResponse` are unchanged. The two new failures reach
  the wire through the existing global handler (`context.md` Wire contract).
- DELETE and the reorder route are unchanged.

## Definition of done

1. `[test]` With a designated model (dim 8), `create_memo` with body "The innkeeper is
   Kaelith." returns the memo. Its `memo_vec` row equals the fake's vector for exactly that
   body. The fake recorded one `embed` call with exactly `[body]`. An FTS `MATCH` on
   "Kaelith" returns the memo's id. (UC-042, US-119, D5)
2. `[test]` Each of these makes `create_memo` raise, and afterwards there is no `memos` row
   with that body, no new `memo_vec` row, and no `memo_fts` hit:
   - with **no** designated model → `NoEmbeddingModelError`;
   - with a fake raising → `LlmUnreachableError`.

   (D8, `backend-structure.md` transaction rule)
3. `[test]` `update_memo` with a changed body replaces the memo's `memo_vec` row with the
   fake's vector for the new body. With no designated model, the same call raises
   `NoEmbeddingModelError`, and the stored body and `memo_vec` row are unchanged.
   (UC-043, US-104)
4. `[test]` **No vector work on toggle.** With **no** designated model, `update_memo` with
   only `is_enabled=False`, then only `is_forced=True`, then both, succeeds and persists
   the flags. With a designated model and a recording fake factory, the same calls make
   **zero** factory calls, and the memo's `memo_vec` row is byte-identical before and
   after. (UC-044, UC-075, D5)
5. `[test]` `update_memo` with a body equal to the stored body (plus a flag change)
   succeeds with no model designated and makes zero factory calls. (D5)
6. `[test]` A memo with a vector row is deleted with **no** model designated. The
   `memos` row, its `memo_vec` row and its `memo_fts` hit are all gone. (D5)
7. `[test]` `create_memo` with a whitespace-only body succeeds with no model designated,
   makes zero factory calls and leaves no `memo_vec` row. A later `update_memo` to a blank
   body on a memo that had a vector removes the row. (D7)
8. `[test]` `reorder_memos` (016) with a recording fake factory and a designated model
   makes zero factory calls, and leaves every `memo_vec` row byte-identical. (UC-076, D5)
9. `[test]` **Router**, with `dependency_overrides` for the factory and `get_settings`:
   - `POST /api/memos` with no designated model → 409, `error.code` `no_embedding_model`,
     and the memo list for that level does not contain it;
   - with a designated model and the fake → 201 with the usual `MemoResponse`;
   - `PATCH /api/memos/{id}` with a changed body and a fake raising → 502,
     `llm_unreachable`, and the body unchanged;
   - `PATCH` carrying only `is_enabled` with no model designated → 200.

   (D8, Wire contract)
10. `[test]` **Regression fallout.** Existing tests in `test_memos_service.py` and
    `test_memos_router.py` that create or body-edit memos pass again after being given a
    designated model and the fake (or the overrides). Their assertions about memo
    behaviour are unchanged. (`context.md` Regression fallout)
