# Step 002 — `services/embedding.py`: the designated-model handle, the sync bridge, vector rows

## Goal

Add the shared embedding service. It:

- resolves the designated embedding model into a ready client;
- embeds a batch of texts synchronously through `asyncio.run`, checking each vector's
  length;
- writes and deletes vector rows.

The step also moves `get_llm_client_factory` to the shared dependency module, and adds the
shared provider fake for tests (`context.md` D1, D4, D8, D9).

## Interface intent

**`app/services/embedding.py`** (new)

- **`EmbeddingModelHandle`**: a frozen value holding the constructed client (the
  registry's client protocol type), the designated `model_name` and `embedding_dim`.
- **`open_embedding_model`**: takes a connection, the client factory and the timeout in
  seconds. It returns an `EmbeddingModelHandle`. It:
  - calls `validate_embedding_model(connection)`, whose `NoEmbeddingModelError`
    propagates;
  - re-selects the designated server's `api_key_ref`;
  - resolves it through `resolve_secret`, whose `secret_ref_missing` propagates;
  - constructs the client **once** via the factory with the server's base URL, the
    resolved key and the timeout.

  It makes no network call.
- **`embed_texts`**: takes a handle and a non-empty sequence of texts. It returns one
  vector per text, in input order. It:
  - calls `client.embed(model_name, texts)` **once**, run to completion with
    `asyncio.run`;
  - lets `LlmUnreachableError` propagate unchanged;
  - raises `NoEmbeddingModelError` with `detail` `{"reason": "dimension_mismatch"}` when
    any returned vector's length ≠ `embedding_dim`.
- **`DEFAULT_EMBED_TIMEOUT_SECONDS`** (or an equivalent the skeleton names): the timeout
  default for services, taken from `Settings`' declared field default for
  `llm_request_timeout_seconds` and never re-typed (D9).
- **`write_vector`**: takes a connection, a vector-table name (one of `001`'s two
  constants), an id and a vector. It leaves exactly one row for that id, holding that
  vector (D4: delete-then-insert or update, never `INSERT OR REPLACE`). The table must
  exist.
- **`delete_vector`**: takes a connection, a vector-table name and an id. It removes the
  row for that id. It is a no-op when there is no such row **or when the table does not
  exist**.
- The module imports no `fastapi`.

**`app/dependencies.py`**

- **`get_llm_client_factory`**: moved here unchanged in behaviour. It returns the real
  `LlmClient` class as the registry's client-factory type.

**`app/routers/admin_llm.py`**

- It imports `get_llm_client_factory` from `app.dependencies` instead of defining it. The
  module attribute remains, as the identical object. Its routes and their behaviour are
  unchanged.

**`backend/tests/llm_fakes.py`** (test helper; contract in `context.md` Test conventions)

## Definition of done

1. `[test]` With a designated, enabled model (dim 8) on a server whose `api_key_ref` is
   `"$<VAR>"`, and that variable set (set and restored via the test's environment fixture,
   not monkeypatching the module), `open_embedding_model` returns a handle with the model's
   name and 8. The fake factory was called exactly once, with the server's base URL, the
   variable's value and the passed timeout. (D1, R4)
2. `[test]` Each of these raises `NoEmbeddingModelError` and calls the factory zero times:
   - no model designated;
   - a designated model that is not enabled.

   (R4; `llm-and-streaming.md` no-substitution rule)
3. `[test]` With an `api_key_ref` naming an unset variable, `open_embedding_model` raises
   the `secret_ref_missing` error and does not call the factory.
4. `[test]` `embed_texts` with three texts returns three vectors, in input order, equal to
   the fake's deterministic vectors for those texts. The fake recorded exactly one `embed`
   call, carrying the model name and the three texts in order. (D1)
5. `[test]` A fake returning a vector of length 7 for dim 8 makes `embed_texts` raise
   `NoEmbeddingModelError` with `detail` `{"reason": "dimension_mismatch"}`. (D8)
6. `[test]` A fake raising `LlmUnreachableError` makes `embed_texts` raise that same error
   type, with its code `llm_unreachable`. (D8)
7. `[test]` `embed_texts` works when called from plain synchronous test code, and when
   called from a worker thread (`threading.Thread`) with no event loop. Both return the
   expected vectors. (D1)
8. `[test]` For each of `memo_vec` and `session_vec` (created by `001`'s ensure at dim 8),
   using ids above 2^60:
   - `write_vector` twice for the same id leaves exactly one row, holding the second
     vector;
   - `delete_vector` removes it;
   - `delete_vector` on an absent id raises nothing;
   - `delete_vector` on a database where the table was never created raises nothing.

   (D4)
9. `[test]` `app.dependencies.get_llm_client_factory()` returns the real `LlmClient`
   class. `app.routers.admin_llm.get_llm_client_factory` is the same object as
   `app.dependencies.get_llm_client_factory`. This test lives in `test_dependencies.py`.
   (D9)
10. `[test]` The source of `services/embedding.py` imports no `fastapi`.
11. `[test]` **Regression fallout.** The existing tests in `test_admin_llm_router.py`
    (which override `get_llm_client_factory`) and `test_dependencies.py` pass. Edit them
    only if the move breaks how they import the dependency. Their assertions stay
    unchanged. (`context.md` Regression fallout)
