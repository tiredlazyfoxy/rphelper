`session_fts` is **not** created. `sessions` has no `title` / `partner_label` columns,

EXISTS` so a missing trigger is restored even when its table exists.

## Trigger conditions — exact, because a naive form corrupts the index

**Record row predicate** (the `settled_entries` boundary): `settled_at IS NOT NULL AND
related_to IS NULL`.

**`memo_fts`** — the standard external-content trio:

- AFTER INSERT on `memos` → insert `(rowid, body)`.
- AFTER DELETE → the `'delete'` command with `OLD.id, OLD.body`.
- AFTER UPDATE **OF body** → the `'delete'` command with the OLD values, then insert NEW.
  A plain `AFTER UPDATE` would churn the index on every flag toggle and reorder. Those
  must not touch it.

**`message_fts`** — conditional on the record row predicate:

- AFTER INSERT WHEN NEW is a record row → insert. This covers partner filing, which is born
  settled.
- **One** AFTER UPDATE trigger (on `text`, `settled_at`, `related_to`). Its body runs two
  statements in this order:
  1. `'delete'` with OLD values **only when OLD was a record row**;
  2. insert NEW values **only when NEW is a record row**.

  One trigger with conditional `INSERT … SELECT … WHERE` statements fixes the order. Two
  separate triggers do not guarantee it. This covers all four transitions:
  - zone → record (settle) inserts;
  - record → zone (re-open) deletes;
  - record → record with a text change deletes the old text and inserts the new;
  - zone → zone, and burial, do nothing.
- AFTER DELETE WHEN OLD is a record row → `'delete'`. No message delete exists today, but
  the trigger set is complete.

**Never** use an unconditional update trigger on `message_fts`. It would issue `'delete'`
for rows that were never indexed (zone rows). External-content FTS5 then decrements terms
that are not there and corrupts the index, which `integrity-check` reports.

## Back-fill on creation

- `memo_fts`: `INSERT INTO memo_fts(memo_fts) VALUES('rebuild')`, which is correct because
  every memo is indexed.
- `message_fts`: **not** `'rebuild'`, because that would index zone and buried rows. Use
  `INSERT INTO message_fts(rowid, text) SELECT id, text FROM messages WHERE <record row
  predicate>`.

Back-fill runs only in the call that **created** the table.
