# Step 005 — step-specific context

Feature-wide facts are in `context.md` (**D2** the five outcomes and why the gate is a
component, **D13** the 401 code; "Built state" for `main.tsx`, `api.ts`, `notReady.ts`).
Only what is narrow to this step is below.

## The admin precedent (behaviour mirrored, code not imported)

`admin/main.tsx` runs the same loop for the admin document: nothing while in flight, no
navigation of its own on 401, not-ready screen re-probing every 2000 ms, failure panel with
manual retry. `ADMIN_ACCESS_RETRY_INTERVAL_MS` is `2000`. **Nothing under `src/admin/` may
be imported** — `001`'s DoD-4 scan fails if it is. Mirror the behaviour; write the app's
own small modules.

## Why the state module is `appBootState.ts` and not `appBoot.ts`

`appBoot.ts` beside `AppBoot.tsx` is a pair of module paths differing **only in letter
case**, and the two resolvers in this project disagree about it. TypeScript resolves the
extensionless specifier `./AppBoot` to the `.tsx` file, so `npm run typecheck` is happy;
Vite and Vitest, on this case-insensitive filesystem, resolve the *same* specifier to the
`.ts` sibling, so the component binding is `undefined` at runtime and React reports an
`undefined` element type. Typecheck can never catch the disagreement, and an explicit
`./AppBoot.tsx` specifier is not available — it needs `allowImportingTsExtensions`, which
neither tsconfig sets (`moduleResolution: "bundler"`), and adding it is a build-config
change `context.md`'s "Not touched" list excludes.

So the **state module** is renamed and the **component keeps its name**: `AppBoot.tsx` and
`tests/app/AppBoot.test.tsx` are cited by downstream plans (`009`, `010`), and nothing
downstream cites `appBoot.ts`. The new name follows the precedent step `002` already sets
with `app/shellState.ts` — a MobX data class plus free functions in one module — which is
exactly what this module holds. Lowercased, `appbootstate`, `appboot`, `appbootscreens` and
`main` are all distinct, so the collision is gone rather than relocated.

Symbol names, signatures and responsibilities are untouched by the rename:
`APP_BOOT_RETRY_INTERVAL_MS`, `AppBootOutcome`, `classifyAppBootError`, `AppBootState`,
`probeCurrentUser` and `restartBoot` keep their names verbatim. `AppBoot.tsx` imports them
as **`./appBootState`**, which is unambiguous under both resolvers.

DoD-14's case-collision scan lives in **this step's** test file rather than in step `001`'s
`tests/app/entryIsolation.test.ts` (which already walks `src/app/`), so that no step but
`005` has to be re-bound by this revision. It is a permanent guard over the whole directory,
not a one-off assertion about these two files: any later module that reintroduces a
case-only collision under `src/app/` fails it.

## The 401 path, precisely

`shared/api.ts` calls `documentNavigation.assign("/login")` itself on a 401 and then throws
an `ApiError`. `AppBoot` classifies it as `"unauthenticated"` and renders nothing. It must
**not** call `documentNavigation` — DoD-6 counts exactly one call. The code is
`not_authenticated` — verified (D13): `NotAuthenticatedError` in
`backend/app/errors.py:111-120`, raised by `require_user`, which `GET /api/me` depends on.

## The re-probe timer

Requirement (DoD-7, DoD-10): a re-probe `2000 ms` after **each** not-ready outcome, never
two in flight, all timers cleared on unmount and when the status leaves `"not-ready"`. Note
that a not-ready → not-ready re-probe does **not** change `status`, so an effect keyed only
on `status` will not re-arm by itself. Either re-arm the timer from the probe's completion
or keep a counter — the coder's choice; the behaviour is the contract. The same
`AbortController` that guards the mount probe (or one per probe) must stop a late response
writing after unmount.

## `tests/entries.test.tsx` as built (harvested)

It mounts each of the four entries and has `app` clauses that assume today's placeholder
(no `fetch` at all, `data-entry="app"` rendered). Those clauses are **replaced** (DoD-11):
the `app` entry now fetches `/api/me` on mount, so its clauses stub `fetch` with
`vi.stubGlobal`. The `bootstrap`, `login` and `admin` clauses are not edited. Rendering is
asynchronous now — the shell appears after the stubbed response resolves.

## `main.tsx` keeps its shape

Order outermost-in: `AppProviders` → `BrowserRouter` → `AppBoot`. `AppProviders` already
imports Mantine's stylesheets and `global.css`; `main.tsx` imports `shell.css` and nothing
else stylesheet-wise. `browserLayoutStorage()` (step `002`) is called once at mount and its
result handed down — this is the one point the feature reaches the real `localStorage`.

## No notifications here

Both boot failures are full-page states, so neither calls `notifyFailure`
(`ui-conventions.md`'s "a failure with a full-page state of its own is not also a
notification"). DoD-7 and DoD-9 assert none is raised.
