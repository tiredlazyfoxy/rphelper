# Step 005 — The `app` entry's boot gate and `main.tsx`

## Goal

Make the `app` entry learn who is signed in before it renders anything: a pure
classification of a failed `/api/me`, a small boot-state store with its probe effect, the
not-ready screen and failure panel, the `AppBoot` gate that renders `App` on success, and
`main.tsx` rewritten to mount it (D2, D13).

## Interface intent

**`app/appBootState.ts`** (new)

- **`APP_BOOT_RETRY_INTERVAL_MS`** — `2000`.
- **`AppBootOutcome`** — the classification of a thrown value: `"unauthenticated"`,
  `"not-ready"` or `"failed"`.
- **`classifyAppBootError`** — pure; takes a thrown value; `"unauthenticated"` for an
  `ApiError` whose code is `not_authenticated`; `"not-ready"` when `isNotReady` holds;
  `"failed"` for anything else (a well-formed 403 or 5xx envelope, a non-`ApiError`).
- **`AppBootState`** — data class, observable fields only: `status` — one of `"probing"`,
  `"unauthenticated"`, `"not-ready"`, `"failed"`, `"ready"`, starting `"probing"` — and
  `user`, a `CurrentUser` or `null`.
- **`probeCurrentUser`** — effect; takes the state and an optional signal. Calls
  `fetchCurrentUser`; on success writes `status` `"ready"` and the user; on failure writes
  the classified status. Writes nothing once the signal is aborted. Never rethrows. Does not
  set `"probing"` itself, so a re-probe from the not-ready screen keeps that screen up.
- **`restartBoot`** — effect; takes the state; sets `status` back to `"probing"` (used by the
  failure panel's retry, so the panel disappears while the request is in flight).

**`app/AppBootScreens.tsx`** (new)

- **`AppNotReady`** — props: an `onRetry` callback. A full-page state with the title
  **"RPHelper is not ready yet"**, the line **"The server is not answering yet. Retrying
  automatically."** and a button **"Retry now"**.
- **`AppBootFailed`** — props: an `onRetry` callback. A full-page state with the title
  **"Could not load your account"** and a button **"Retry"**.

**`app/AppBoot.tsx`** (new)

- **`AppBoot`** — `observer` component; props: `storage` (`LayoutStorage` or `null`).
  Creates its `AppBootState` with `useState(() => …)`; probes once on mount with an
  `AbortController` aborted on unmount. Renders by status: `"probing"` and
  `"unauthenticated"` → nothing; `"not-ready"` → `AppNotReady`, and while the status stays
  `"not-ready"` a re-probe fires `APP_BOOT_RETRY_INTERVAL_MS` after each not-ready outcome
  (uncapped, no backoff, never two probes in flight, cancelled on unmount); "Retry now"
  re-probes at once; `"failed"` → `AppBootFailed`, no automatic re-probe, "Retry" calls
  `restartBoot` then re-probes; `"ready"` → `App` with the user and the storage.

**`app/main.tsx`** (rewritten)

- Keeps: the `"../shell.css"` import (the one stylesheet an entry imports itself), the
  `#root` lookup that throws if missing, `AppProviders` outermost, `BrowserRouter` with no
  `basename`.
- Renders `AppBoot` inside the router with `storage` from `browserLayoutStorage()`. The
  placeholder `<div data-entry="app" />` route is gone.

## Preparatory cleanup

An earlier skeleton and test-coder pass already wrote a stub and a test at the **old**
paths `frontend/src/app/appBoot.ts` and `frontend/tests/app/appBoot.test.ts`. Both must be
**deleted** as part of this step, before anything is written at the new paths. Two reasons:
`appBoot.ts` sitting beside `AppBoot.tsx` is the case-collision this revision removes — on
this project's case-insensitive filesystem it keeps shadowing the specifier `./AppBoot`
under Vite and Vitest — and the stale test imports a module that will no longer exist,
which fails `npm run typecheck` because both tsconfigs carry `include: ["src", "tests"]`.

The deletion belongs to the **skeleton pass**: it is the only role in the chain that both
runs before the test-coder and has a shell. The test-coder then re-creates its file at
`frontend/tests/app/appBootState.test.ts`.

## Definition of done

1. `[test]` `classifyAppBootError` returns `"unauthenticated"` for an `ApiError` with code
   `not_authenticated` (status 401); `"not-ready"` for a transport-failure `ApiError` and for
   a malformed-body `ApiError` at status 502; `"failed"` for a well-formed 403 envelope, a
   well-formed 500 envelope and a plain `Error`.
2. `[test]` `probeCurrentUser` over a stubbed `/api/me` returning a user writes `status`
   `"ready"` and that user (id still a string), for role `roleplayer` and role `admin`.
3. `[test]` `probeCurrentUser` writes the classified status on failure, never rethrows, and
   writes nothing when its signal is aborted before the response settles.
4. `[test]` While `/api/me` is pending, `AppBoot` renders nothing: no shell, no not-ready
   screen, no failure panel.
5. `[test]` On success, `AppBoot` renders the shell (the "Workspace navigation" nav and the
   "User menu" trigger showing the username), for a roleplayer and for an administrator —
   neither role is denied. (UC-071)
6. `[test]` On a 401, `AppBoot` renders nothing of its own, and `documentNavigation.assign`
   is called exactly once, with `/login` (by the shared client — `AppBoot` adds no second
   navigation).
7. `[test]` On a not-ready failure, `AppBoot` shows "RPHelper is not ready yet"; after
   2000 ms (fake timers) it requests `/api/me` again; when that succeeds the shell renders.
   No document navigation and no notification occur on this path.
8. `[test]` On the not-ready screen, "Retry now" requests `/api/me` immediately.
9. `[test]` On a well-formed 403, `AppBoot` shows "Could not load your account" and does not
   request `/api/me` again on its own after 2000 ms or more; "Retry" requests it again and on
   success the shell renders. No document navigation and no notification occur on this path.
10. `[test]` Unmounting `AppBoot` while it shows the not-ready screen cancels the re-probe: no
    further request to `/api/me` is made after unmount.
11. `[test]` `tests/entries.test.tsx`'s `app` clauses are updated: mounting the `app` entry
    with `/api/me` stubbed to a user renders the shell into `#root`; with `/api/me` stubbed
    to a 401 it renders nothing into `#root`. The other entries' clauses are untouched.
12. `[test]` `src/app/main.tsx` imports `../shell.css` and no other stylesheet, and contains
    no `basename`.
13. `[manual/live]` Against a running backend: signed in, `/` shows the shell with the
    username; signed out, `/` lands on `/login`; with the backend stopped, `/` shows the
    not-ready screen and recovers on its own once the backend is up.
14. `[test]` No two module paths under `frontend/src/app/` differ only in letter case: a
    recursive filename scan of that directory over its `.ts` and `.tsx` files finds no two
    paths that are equal once lowercased. The scan is shown to be live — it reaches the
    directory's real files, and it flags a constructed colliding pair. Covered in
    `tests/app/appBootState.test.ts`.
