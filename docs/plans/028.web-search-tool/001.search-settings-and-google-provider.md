# Step 001 — Search settings and the Google provider behind the provider seam

## Goal

Add the two environment-read search credentials to `Settings` (D2), and create
`app/services/web_search/`: the web-result value, the provider protocol (D4) and the Google
Custom Search provider (D1). The provider sends only the query (D6), turns every failure
into one cause-free `ToolFailedError` (D5), and logs and caches nothing (D7). Extend the
shared test isolation so that no test sees real credentials (D12).

## Interface intent

**`app/config.py`** (changed)

- **Two `Settings` fields** (D2):
  - the search API key, read from exactly `SEARCH_CSE_KEY`; optional, default none; a
    secret-string type whose `repr` / `str` masks the value;
  - the search engine id, read from exactly `SEARCH_CSE_ID`; optional, default none; a
    plain string.

  No other field changes, and `get_settings` is unchanged.

**`app/services/web_search/__init__.py`** (new): package marker. It may re-export the
public names of `provider.py`.

**`app/services/web_search/provider.py`** (new)

- **Web result** (frozen value): `title`, `url`, `snippet`, each a plain-text string.
- **Web search provider** (protocol): one async operation, search, taking a query string
  and a result limit and returning an ordered list of web results. It raises on failure.
  This is the seam any later provider implements (D1, D4).

**`app/services/web_search/google.py`** (new)

- **A default-timeout constant**: 10 seconds (D9).
- **The Google provider class**. It implements the protocol structurally.
  - Construction takes the API key and the engine id (plain strings, used as given) and
    the optional keywords timeout seconds (default: the constant) and an httpx async
    transport (default none, so the real network is used). It reads no settings and
    resolves no secret.
  - **async search(query, limit)**: one GET per call, on a fresh `httpx.AsyncClient`
    built with that timeout and transport. The request and response rules are in
    `001.context.md`. It returns at most `limit` web results in response order. Any
    failure raises `ToolFailedError` with detail `{"tool": "web_search"}` and no chained
    cause. It emits no log record and keeps no state between calls.

## Definition of done

1. `[test]` With `SEARCH_CSE_KEY=k-123` and `SEARCH_CSE_ID=cx-456` in the environment,
   `Settings` exposes the key's secret value as `k-123` and the engine id as `cx-456`.
   With only `RPHELPER_SEARCH_CSE_KEY` / `RPHELPER_SEARCH_CSE_ID` set, both are none.
   (D2)
2. `[test]` With neither variable in the environment and the env file disabled, both
   fields are none. (D2)
3. `[test]` `repr(settings)` and `str(settings)` for a `Settings` holding key `k-123` do
   not contain `k-123`. (D2, `deployment.md` redaction rule)
4. `[test]` **Shared isolation.** Inside an ordinary test, after changing the working
   directory to a temporary folder whose `.env` sets both variables to non-empty values and
   clearing the settings cache, `get_settings()` reports neither a non-blank key nor a
   non-blank engine id. (D12)
5. `[test]` **Request shape.** A search for `bataille de Valmy` with limit `5`, over a
   recording `MockTransport` answering 200 with three items, sends exactly one request:
   - method `GET`;
   - scheme `https`, host `www.googleapis.com`, path `/customsearch/v1`;
   - query parameters exactly `cx` = the engine id, `q` = `bataille de Valmy`, `num` =
     `5`, and no others;
   - header `X-goog-api-key` = the key;
   - an empty body.

   The key appears nowhere in the request URL. (D1, D6, `001.context.md`)
6. `[test]` **Results.** For that response the provider returns three web results whose
   `title`, `url` and `snippet` equal the items' `title`, `link` and `snippet`, in item
   order. (D1, D4)
7. `[test]` **Parsing edges.**
   - A 200 body with no `items` key returns an empty list.
   - An item that is not an object, or that has no string `link`, is skipped.
   - An item with a missing or non-string `title` or `snippet` gives an empty string for
     that field.
   - A response with more items than `limit` returns only the first `limit`.

   (`001.context.md`)
8. `[test]` **Failures.** Each of these raises `ToolFailedError` with code `tool_failed`
   and detail exactly `{"tool": "web_search"}`:
   - status 403, 429 and 500;
   - the transport raising `httpx.ConnectError`, and raising `httpx.ReadTimeout`;
   - a 200 body that is not JSON;
   - a 200 JSON array;
   - a 200 object whose `items` is not a list.

   In every case the error's `__cause__` is none and its context is suppressed. Its
   `str`, its message and its detail contain none of the query, the key, the engine id or
   `googleapis`. (D5, UC-055 exception flow)
9. `[test]` **Timeout.** The request carries the 10-second timeout by default (the
   recorded `request.extensions["timeout"]` values are all `10.0`). A provider built with
   timeout `2.5` sends `2.5`. (D9)
10. `[test]` **No caching.** Two identical searches on one provider instance make two
    requests. (D7, brief Out)
11. `[test]` **No logs.** With a loguru sink capturing every level, one successful search
    and one failing search (status 500) produce no record containing the query, the key or
    the engine id. (D7, `deployment.md` redaction rule)
12. `[test]` **Conventions.** `provider.py` and `google.py` import nothing from `fastapi`,
    `app.config`, `app.secrets`, `app.db` or `app.services.tools`. `provider.py` imports
    nothing from `httpx`. (D4)
13. `[manual/live]` With the user's real `SEARCH_CSE_KEY` / `SEARCH_CSE_ID`, one search
    from a Python shell in `backend/` returns non-empty results. This confirms that the
    `X-goog-api-key` header is accepted by the live API. If it is rejected, record that
    in `## Notes & Issues`; it is a SPEC fault (see `001.context.md`). (D1)
