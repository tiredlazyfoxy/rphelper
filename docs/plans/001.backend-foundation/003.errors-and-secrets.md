# Step 003 — The typed error hierarchy and the secret-pointer resolver

## Goal

Define the one base error class, its one wire shape and its one handler, plus the first
and only concrete subclass this feature owns — and the `"$ENV_VAR"` resolver that raises
it.

## Source files

```
backend/app/errors.py
backend/app/secrets.py
```

## Test files

```
backend/tests/test_errors.py
backend/tests/test_secrets.py
```

## Interface intent

**`app/errors.py`**

- **A base domain-error exception.** Its shape is declared verbatim in
  `docs/architecture/backend-structure.md` § The error model — a stable
  machine-readable `code`, an `http_status`, and a structured `detail` mapping that is
  never free prose the UI has to parse. `code` and `http_status` are **class
  attributes each subclass sets** (decision D7); `detail` is per-instance. The
  constructor takes an optional human-readable message and an optional detail mapping,
  defaulting the detail to empty. The class exposes a way to render itself as the wire
  body — `{"error": {"code", "message", "detail"}}`, exactly those three keys under
  exactly that one envelope key, and no others.
- **A `secret_ref_missing` subclass**, the only concrete error this feature defines.
  Its `detail` carries the environment variable's name. The remaining eleven codes in
  the architecture's table arrive with the features that raise them; none is
  pre-declared here.
- **A handler function** taking the request and the raised error and returning a JSON
  response whose HTTP status is the error's `http_status` and whose body is the wire
  body above. It logs the `code` and the status and nothing else — no detail values, no
  message text — per the redaction rule.
- **A registration entry point** taking a FastAPI application and installing that
  handler for the base class, so every subclass is covered by the one registration.
  The app factory calls it (step `006`). The registration itself is a planner inference
  from "one base class, one wire shape, one handler"; see `003.context.md`.

**`app/secrets.py`**

- **A `resolve_secret` function**, whose contract is given verbatim as a docstring in
  `docs/architecture/backend-structure.md` § The `"$ENV_VAR"` secret-pointer pattern:
  `None` in gives `None` out; `"$NAME"` gives the process environment's `NAME`;
  anything else raises the typed error. Resolution reads the environment **at call
  time**, never at import, registration or startup — rotating a key is an environment
  change plus a restart. A `"$NAME"` naming an absent variable raises the typed error,
  never returns `None`. Boundary cases are settled in `003.context.md`.
- Write-time validation that a stored reference starts with `$` belongs to feature
  `006` and is **not** in this step.

## Definition of done

1. `[test]` The base class carries `code`, `http_status` and `detail`; a subclass sets
   `code` and `http_status` as class attributes and instances of it report them.
2. `[test]` The rendered wire body is exactly one top-level `error` key holding exactly
   `code`, `message` and `detail` — no extra keys at either level.
3. `[test]` An error raised inside a route of an application the registration entry
   point was applied to becomes a response carrying **that subclass's** `http_status`
   and the wire body from DoD-2.
4. `[test]` The registered handler catches only domain errors: an ordinary exception
   raised in a route is **not** converted into the wire shape.
5. `[test]` The secret-pointer error's `code` is exactly `secret_ref_missing`.
6. `[test]` `resolve_secret(None)` returns `None`.
7. `[test]` `resolve_secret("$NAME")` with `NAME` set returns that value, and resolution
   is at call time — changing the environment between two calls changes the result
   without any re-registration or cache clear.
8. `[test]` `resolve_secret("$NAME")` with `NAME` absent raises the typed error, and its
   `detail` names the variable `NAME`.
9. `[test]` A reference that does not start with `$`, and a bare `"$"` with no name,
   both raise the typed error rather than being returned or treated as absent.
10. `[test]` A variable that is set to the empty string resolves to the empty string —
    present-but-empty is present. (Planner ruling; see `003.context.md`.)
11. `[test]` Neither the raised error's `detail` nor its message ever contains a
    resolved secret value — only the variable name.
