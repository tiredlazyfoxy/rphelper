## The `Settings` field set

The exact declaration — field order, types, `Field(...)` calls and
`SettingsConfigDict` — is given **verbatim** in
`docs/architecture/backend-structure.md` § Configuration. Reproduce it exactly; do not
reorder, rename, retype or add to it. The table below is the same contract in a form
the test-coder can assert against without reading source:

| Field | Type | Default | Validation alias |
|---|---|---|---|
| `data_dir` | `Path` | `Path("data")` | `RPHELPER_DATA_DIR` |
| `db_filename` | `str` | `"rphelper.sqlite"` | `RPHELPER_DB_FILENAME` |
| `node_id` | `int` | `0` | `RPHELPER_NODE_ID` |
| `session_cookie_name` | `str` | `"rphelper_session"` | `RPHELPER_SESSION_COOKIE_NAME` |
| `session_ttl_hours` | `int` | `720` | `RPHELPER_SESSION_TTL_HOURS` |
| `log_console_level` | `str` | `"DEBUG"` | `RPHELPER_LOG_CONSOLE_LEVEL` |
| `log_file_level` | `str` | `"WARNING"` | `RPHELPER_LOG_FILE_LEVEL` |
| `log_file_path` | `Path` | `Path("data/logs/rphelper.log")` | `RPHELPER_LOG_FILE_PATH` |
| `log_file_rotation` | `str` | `"10 MB"` | `RPHELPER_LOG_FILE_ROTATION` |
| `log_file_retention` | `int` | `5` | `RPHELPER_LOG_FILE_RETENTION` |

Model configuration: `env_file=".env"`, `extra="ignore"`.

**Ten fields, exactly.** The architecture block closes with a trailing comment
(`# ... one field per setting, each with an explicit RPHELPER_ alias`) that states the
convention for fields **later** features add; it is not an eleventh field and nothing is
elided behind it. If the block and this table ever disagree on a field, the block wins
and the disagreement is a hand-back to the planner, not a judgement call.

## Two fields that are unused in this feature, deliberately

`session_cookie_name` and `session_ttl_hours` belong to feature `004`. They live on the
one `Settings` model regardless — there is one settings model in this backend, not one
per feature — and nothing in this feature reads them. Their presence is not dead code
to be cleaned up.

## Planner decisions local to this step

- **Minimum Python is 3.12.** The architecture names no version. 3.12 is chosen because
  SQLAlchemy 2.x, pydantic 2 and modern typing syntax are all comfortable there and it
  is what a current `uv python install` gives. Recorded in `outcome.md` so the architect
  can make it a stack fact.
- **`uv.lock` is committed.** It is a generated artifact; the coder produces it by
  running `uv sync`, and never edits it by hand.

## The conftest this step establishes

`backend/tests/conftest.py` is created here with the environment-isolation fixture
described under "Test conventions" in `context.md`: clear every `RPHELPER_*` variable
and clear the settings accessor's cache around each test. **The temp-file database
fixture does not belong here** — it is added to this same file in step `005`, once
`db/engine.py` exists. That sequencing is deliberate, not an oversight.

## Gotchas

- pydantic-settings resolves `env_file` **relative to the process working directory**,
  which for every command in the root `CLAUDE.md` is `backend/`. Do not resolve it
  against the package directory.
- A `validation_alias` replaces the field name as the environment key entirely; that is
  what DoD-3 observes.
