# Step 005 — The SQLAlchemy Core engine and the table registry

## Goal

Create the one SQLite connection factory — PRAGMAs and the `sqlite-vec` load on every
connection, the request-scoped connection dependency — and the empty table-definition
registry that is the schema's single source of truth.

## Source files

```
backend/app/db/__init__.py
backend/app/db/engine.py
backend/app/db/schema.py
```

## Test files

## Interface intent

**`app/db/schema.py`** — decision D2 in `context.md`.

- **One module-level metadata object**, and nothing else in this feature: **zero**
  `Table` objects. Its module docstring states the rule every later feature binds to —
  every table in RPHelper is declared as a `Table(...)` literal **in this same file**,
  there are no per-feature table modules, there is no import-side-effect registration
  and there is no builder callable. Feature `007` walks this object's table collection
  directly, and `db/drift.py` compares it against `PRAGMA table_info` / `index_list`.
- The two SQL views the data model declares, and every table, arrive with the features
  that own them. Nothing is declared here now.

**`app/db/engine.py`** — SQLAlchemy **Core** only. No `DeclarativeBase`, no mapped
classes, no `Session`, no identity map, no lazy loading. Plain `Connection` and explicit
`begin()` blocks.

- **A database-path helper** resolving `data_dir / db_filename` from a settings
  instance, and creating the directory if it is missing.
- **An extension loader** — a module-level function taking a raw DBAPI connection and
  loading `sqlite-vec` into it, enabling extension loading first and disabling it after.
  It is a named module-level function specifically so it is a monkey-patchable seam for
  DoD-4; a failure to load raises the dedicated extension-load exception rather than
  returning a connection without the extension (decision D8).
- **A dedicated extension-load exception.** Like the backwards-clock exception it is an
  operational fault and is **not** a domain error.
- **An engine factory** taking a settings instance and returning a SQLAlchemy `Engine`
  for that database path, cached so one path yields one engine per process (decision
  D9), configured with the pysqlite dialect's default pool for a file database and with
  the same-thread assertion disabled. It registers a single `connect` event listener
  that runs on **every** new connection and, in this order: loads the `sqlite-vec`
  extension, sets `PRAGMA foreign_keys = ON`, sets `PRAGMA journal_mode = WAL`
  (decision D5).
- **A disposal entry point** that disposes and forgets every cached engine, for test
  teardown.
- **A `get_connection` FastAPI dependency** (decision D6) resolving settings through
  the settings dependency, acquiring a `Connection` from that engine, yielding it for
  the life of the request and closing it afterwards. It is the only way a router obtains
  a connection. It opens no transaction of its own — transaction boundaries are
  `with conn.begin():` blocks at the service's own level.

**`app/db/__init__.py`** — package marker, no logic.

## Definition of done

1. `[test]` `PRAGMA foreign_keys` reports enabled on a freshly acquired connection, and
   again on a second, separately acquired connection — it is re-set every time, not once.
2. `[test]` `PRAGMA journal_mode` reports WAL on a connection to a file database.
3. `[test]` The `sqlite-vec` extension is available on **every** connection: the
   extension's version function answers, and a `vec0` virtual table can be created and
   queried, on a connection acquired after the first one.
4. `[test]` When the extension loader fails, acquiring a connection raises the dedicated
   extension-load exception and yields no usable connection — the failure is loud, never
   a silent degrade. That exception is **not** a subclass of the domain-error base class.
5. `[test]` The database file is created at `data_dir / db_filename` from the supplied
   settings, and a missing `data_dir` is created rather than raising.
6. `[test]` The connection dependency yields a working Core `Connection` and the
   connection is closed after the dependent request completes.
7. `[test]` `db.schema` exposes a module-level metadata object whose table collection is
   **empty** in this feature and is enumerable by name — which is the shape feature
   `007` will walk.
8. `[test]` The engine factory returns the same engine for the same database path and a
   different engine for a different path; disposal clears the cache so a later call
   builds a fresh engine.
9. `[test]` Connections acquired from two different threads both work — the same-thread
   assertion does not fire under uvicorn's threading model.
10. `[manual/live]` No ORM construct appears anywhere under `app/db/`: no
    `DeclarativeBase`, no mapped class, no `Session`, no `sqlalchemy.orm` import.
    Verifier confirms by reading the two modules.
11. `[manual/live]` `sqlite-vec` is version-pinned in `pyproject.toml` and the pinned
    version is the one the tests ran against.

## Dependencies

Step `001` — settings supply `data_dir` and `db_filename`, and `pyproject.toml` carries
the SQLAlchemy and `sqlite-vec` dependencies.
