# Step 001 — Project scaffold and configuration

## Goal

Create the `backend/` package from nothing: the PEP 621 `pyproject.toml` that carries
every dependency and every tool's configuration, the `app` package skeleton, and the
`pydantic-settings` `Settings` model with its cached accessor.

## Source files

```
backend/pyproject.toml
backend/uv.lock
backend/.gitignore
backend/app/__init__.py
backend/app/config.py
backend/app/routers/__init__.py
backend/app/services/__init__.py
```

`backend/uv.lock` is **generated** by `uv sync` and committed; it is never hand-written
or hand-edited, and its size does not count against the step budget.

## Test files


## Interface intent

**`backend/pyproject.toml`** — a single PEP 621 file holding:

- project metadata and the minimum Python version;
- runtime dependencies: FastAPI, uvicorn (with its standard extras), pydantic,
  pydantic-settings, loguru, SQLAlchemy 2.x, and a **version-pinned** `sqlite-vec`
  (decision D8). **Not Alembic** — it is `007`'s dependency, not this feature's;
- development dependencies: pytest, mypy, ruff, and the HTTP client FastAPI's
  `TestClient` requires;
- `[tool.ruff]`, `[tool.mypy]` and `[tool.pytest.ini_options]` sections. mypy is
  configured to type-check the `app` package strictly enough that an unannotated
  function definition is an error — the root `CLAUDE.md` calls `mypy app` a gate.
  pytest's test path is `tests`.

No `requirements.txt`, no `ruff.toml`, no `mypy.ini`, no `pytest.ini`, no `setup.cfg`.

**`backend/.gitignore`** — ignores `.venv/`, `__pycache__/`, `.mypy_cache/`,
`.pytest_cache/`, `.ruff_cache/` and the local `.env`. It does **not** ignore
`uv.lock`.

**`app/config.py`**

- A settings model, subclassing pydantic-settings' `BaseSettings`, carrying exactly the
  ten fields declared verbatim in `docs/architecture/backend-structure.md`
  § Configuration — five instance fields and five logging fields — each with an
  **explicit `RPHELPER_<FIELD>` validation alias**, never an `env_prefix`. Its model
  configuration reads a `.env` file (resolved relative to the backend working
  directory) and ignores extra keys. The field/alias/default table is in
  `001.context.md`; the exact declaration is the architecture doc's and the skeleton
  reproduces it.
- A module-level accessor that returns the settings instance and is memoised so the
  environment is parsed once per process. Routers depend on it through FastAPI's
  dependency injection, so a test overrides the cache rather than patching a global.
  Its cache must be clearable — that is how the test fixtures isolate environments.

**`app/__init__.py`** — package marker, no logic.

**`app/routers/__init__.py`** and **`app/services/__init__.py`** — package markers whose
module docstrings state the enforced convention in one paragraph each: a router owns
HTTP and issues no SQL and holds no business rule; a service owns domain rules and data
access, takes plain arguments, and never imports `fastapi`, never sees a `Request` and
never knows a status code. Dependency direction is `routers → services → db`, one way.
No code beyond the docstring.

## Definition of done

1. `[test]` The settings model exposes exactly the ten fields named in
   `001.context.md`, each with the default recorded there, and nothing else.
2. `[test]` Each field is populated from its `RPHELPER_`-prefixed environment variable —
   setting the variable changes the field.
3. `[test]` A variable named after the field **without** the `RPHELPER_` prefix does
   **not** populate it. (The aliases are explicit, not an `env_prefix`; this is the
   observable difference.)
4. `[test]` An unrelated environment variable does not cause construction to fail —
   extra keys are ignored.
5. `[test]` There is **no** `port` field and no port-shaped setting. Ports are topology,
   hardcoded elsewhere.
6. `[test]` The accessor returns the identical object on repeated calls, and after its
   cache is cleared it re-reads the environment and returns a different object
   reflecting the new values.
7. `[test]` `app`, `app.routers` and `app.services` import cleanly, and `app.services`
   defines no module-level names beyond its docstring (the package is empty in this
   feature).
8. `[manual/live]` From `backend/`, `uv venv` followed by `uv sync` creates `.venv` and
   writes a `uv.lock` that is committed; the three commands in the root `CLAUDE.md`
   (`pytest`, `mypy app`, `ruff check .`) all execute.
9. `[manual/live]` `mypy app` and `ruff check .` report no findings against the files
   this step creates.
10. `[manual/live]` `alembic` appears in no dependency list, and no `alembic.ini`,
    `env.py` or `versions/` directory exists anywhere under `backend/`.
