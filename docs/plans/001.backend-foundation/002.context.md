# Step 002 — step-specific context

Feature-wide facts — the redaction rule, the layout, the commands — are in `context.md`.

## Why the bridge is the load-bearing part

`docs/architecture/deployment.md` states it as a prohibition rather than advice: a plan
that adds loguru **without** installing the `InterceptHandler`, and **without a test
that asserts a record emitted through stdlib `logging` lands in loguru's sinks**, has
not finished the work. That is why DoD-1 exists and why it is `[test]` rather than
`[manual/live]`.

It is also the part that fails **silently**. If the handler is missing, nothing raises;
uvicorn's records simply go to uvicorn's own formatter and the file sink quietly never
sees them. Nobody notices until an incident.

## Sink table

| Sink | Level setting | Default level | Destination |
|---|---|---|---|
| Console | `log_console_level` | `DEBUG` | stderr |
| Rotating file | `log_file_level` | `WARNING` | `log_file_path`, default `data/logs/rphelper.log` |

The file sink additionally takes `log_file_rotation` (default `"10 MB"`),
`log_file_retention` (default `5`) and **`diagnose=False`**.

`log_file_path` defaults under `data/` because that is the one writable volume in
production.

## The module-name gotcha

This module is `app/logging.py` and it must import the standard library's `logging`.
Under Python 3's absolute imports that works — `import logging` inside
`app/logging.py` resolves to the stdlib module, not to itself — but it reads wrongly at
a glance and invites a "fix". It is correct as written; do not rename the module, since
`docs/architecture/backend-structure.md` § Layout fixes the filename.

## Call-site rule this step establishes

No other module in this backend adds, removes or reconfigures a sink. Every other module
imports loguru's logger and logs **ids, codes and counts, never text**. Steps `003`–`006`
are bound by that and it is not restated in their files.

## Testing seams

`configure_logging` takes a settings instance as its argument rather than calling the
settings accessor, so a test constructs a settings object pointed at a `tmp_path` log
file and passes it in. That is the only seam the test-coder needs; there is no global to
patch.
