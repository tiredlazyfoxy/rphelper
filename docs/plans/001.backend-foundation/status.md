### Step 004 — frozen interface (2026-09-28)

- `backend/app/ids.py` — module — **new**. Imports `threading`,
  `from collections.abc import Callable`, `from app.config import Settings`. It does
  **not** import `app.errors` — the backwards-clock exception is deliberately unrelated
  to `DomainError` (DoD-6), and an unused import fails ruff F401.
- `backend/app/ids.py` — three public layout constants — **new**. Module-level, annotated,
  literal values; never read from configuration:
  - `EPOCH_MS: int = 1767225600000` — milliseconds since the Unix epoch at
    `2026-01-01T00:00:00Z`. This exact number is what a test decodes against.
  - `NODE_ID_BITS: int = 10`
  - `SEQUENCE_BITS: int = 12`
  - Layout, high to low: 41 bits `(clock_ms - EPOCH_MS)`, then `NODE_ID_BITS` of node id,
    then `SEQUENCE_BITS` of sequence. Decoding shifts follow from the two widths; no
    shift/mask constant is frozen, and none may be added by the coder.
- `backend/app/ids.py` — `class BackwardsClockError(Exception)` — **new**. Base class is
  the built-in `Exception`, **deliberately not `app.errors.DomainError`** (DoD-6 asserts
  the non-relationship): a backwards clock step is an operational fault — a 500 — not a
  domain failure the SPA renders. Docstring only; no `__init__`, no `code`, no
  `http_status`, no constructor arguments beyond `Exception`'s. Do not "tidy" it into the
  error hierarchy.
- `backend/app/ids.py` — `def _system_clock_ms() -> int:` — **new**. Module-level, private,
  no parameters; the default clock. Stub body `raise NotImplementedError` — the coder
  fills in the millisecond wall-clock read. Not part of the tested surface; frozen only
  because it is the default argument below.
- `backend/app/ids.py` — `class SnowflakeGenerator` — **new**. Plain class, no base.
  Attribute annotations (declarations only — nothing is assigned until the coder fills
  `__init__`): public `node_id: int`; private `_clock: Callable[[], int]`,
  `_lock: threading.Lock`, `_last_ms: int`, `_sequence: int` (the "two values behind a
  lock").
  - `def __init__(self, node_id: int, clock: Callable[[], int] = _system_clock_ms) -> None:`
    — two positional-or-keyword parameters in that order; `clock` defaults to the module's
    system clock and is the **only** seam by which DoD-5 and DoD-6 are testable. The node
    id is read once here; one outside the range `NODE_ID_BITS` allows is refused at
    construction. Stub body `raise NotImplementedError`.
  - `def next_id(self) -> int:` — the mint operation. No parameters beyond `self`; returns
    `int`. Blocks into the next millisecond on sequence exhaustion (never raises, never
    wraps); raises `BackwardsClockError` when the clock reads earlier than the last issued
    millisecond. Stub body `raise NotImplementedError`.
  - `Callable` is `collections.abc.Callable`; the clock returns **milliseconds**.
- `backend/app/ids.py` — `def build_id_generator(settings: Settings) -> SnowflakeGenerator:`
  — **new**. Module-level, one positional parameter, the settings **instance** (never
  `get_settings()` called from inside — same seam as `configure_logging`). Reads
  `settings.node_id` and nothing else. Stub body `raise NotImplementedError`. Step `006`'s
  app factory is its one call site (DoD-10).
- `backend/app/models/ids.py` — the two aliases — **new**. Reproduced verbatim from

  - `SnowflakeIn = Annotated[int, BeforeValidator(lambda v: int(v))]`

  - The doc block aligns `SnowflakeIn  =` with two spaces; the single space here is the
    only deviation (formatting, not declaration). The `lambda v: int(v)` is kept exactly —

- `backend/app/models/__init__.py` — package marker — **new**. Module docstring states the

## Notes & Issues

- Step 003: for the two *malformed* reference cases (a bare `"$"`, and a string not starting with
  `$`) the raised `SecretRefError` carries an empty `detail` and a message that does **not** echo
  the reference — there is no variable to name, and a non-pointer reference may itself be a pasted
  raw credential. Only the absent-variable case populates `detail["variable"]`, which is the case
  the frozen `detail` shape and DoD-8 describe.
- Step 005: the `connect` listener wraps *any* exception out of `load_sqlite_vec` — not just an
  `ExtensionLoadError` — into `ExtensionLoadError`, so the D8 invariant ("a failed load is loud,
  and never a connection without the extension") holds however the seam fails, including when it
  is patched.
- Step 005 (out of scope, observed while verifying by hand): `Settings` declares
  `validation_alias="RPHELPER_*"` without `populate_by_name`, so `Settings(data_dir=...)` is
  silently ignored and the default is used — a settings instance must be built as
  `Settings(RPHELPER_DATA_DIR=...)` or from the environment. Step `001`'s file, not touched here.
- Step 006: the probe's administrator test uses the literal role value `'admin'` on a `users`
  table (`data-model.md` § `users` defines `role` as `'roleplayer' | 'admin'`); the step file
  states it only in prose as "a row whose role is administrator". Feature `003`, which creates the
  table, must use the same literal or the `configured` branch silently stays false.
- Step 006: `sqlite_master` is read with `type IN ('table', 'view')` so a registry entry that is
  later declared as a view is not reported `"missing"`; in this feature the registry is empty and
  the distinction has no effect.
