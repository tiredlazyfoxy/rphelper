# Step 005 — The current zone's messages, each editable in place

## Goal

Add `app/ZoneList.tsx`: the zone's messages in served order, each with its author label,
its body painted (D5), and an in-place editor that commits on blur through `003`'s
`editZoneMessage` and keeps the typed text open on failure (D10, US-115).

## Source files

frontend/src/app/ZoneList.tsx

## Test files

frontend/tests/app/ZoneList.test.tsx

## Interface intent

**`app/ZoneList.tsx`** (new)

- **`ZoneList`**: `observer` component. Props: `state` (`StreamState`) and an optional
  `signal` (`AbortSignal`) passed on to the effect it calls. Renders a list labelled
  **"Zone messages"**, one list item per row of `state.zone` in order. Renders nothing at
  all (no list) when the zone is empty.
- **`ZoneMessage`** (may be module-private): `observer` component for one row. Shows the
  author label — **"You"** for `user`, **"Assistant"** for `assistant`, **"Tool"** for
  `tool` — an `IconButton` (`IconEdit`) labelled **"Edit message"**, and the body as
  `MessageBody` `"painted"` (`004`).
  - Pressing "Edit message" replaces the body with an autosizing Mantine `Textarea`
    labelled **"Edit message text"**, holding the row's current text and focused. The
    editing flag and the edit draft are component-local `useState` (view state, D10).
  - **Blur** calls `editZoneMessage` with the row's id and the edit draft. When it
    resolves true the editor closes and the body shows the row as it now is in
    `state.zone`; when false the editor **stays open with the typed text**.
  - Any role is editable, the assistant's included (US-115.AC-1).
  - No Settle, Send or discard control lives here; no copy control.

## Definition of done

1. `[test]` With zone rows `[user "Hi", assistant "Hello there", tool "lookup"]`, the
   "Zone messages" list renders three items in that order labelled "You", "Assistant",
   "Tool", each with an "Edit message" control. With an empty zone no "Zone messages"
   list is rendered. (US-125.AC-1, US-115.AC-1)
2. `[test]` A zone row `"((just a note))"` renders the out-of-character card
   (`data-paren="ooc"`); a row `"Text ((hint)) more"` renders one fragment chip with text
   `((hint))`. (D5)
3. `[test]` Pressing "Edit message" on the **assistant** row shows a textbox "Edit
   message text" holding "Hello there"; changing it to "Hello, friend" and blurring sends
   exactly `PATCH /api/messages/<that id>` with `{"text":"Hello, friend"}`; after the
   response the editor is gone and the item shows the served text. No GET is made.
   (US-115.AC-1, D10)
4. `[test]` Blurring the editor with the text unchanged, or with only whitespace, makes no
   request; the editor closes and the original text is shown. (D10)
5. `[test]` A PATCH answered with 409 `message_not_editable` calls `notifyFailure` with
   that code, re-reads `GET /api/sessions/<id>/zone`, and — if the row is still served —
   leaves the editor open holding the typed text. (D10, R10)
6. `[test]` If the zone re-read after a failed PATCH no longer contains the row, its item
   and editor are gone. (D10)
7. `[test]` Editing one row leaves every other row's text and the row order unchanged.
   (D10, "Never optimistic")
