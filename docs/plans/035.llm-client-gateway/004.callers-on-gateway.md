# Step 004 — Compose and translation run on the gateway

## Goal

This step switches the chat path to the gateway:

- the chat-client factory takes `kind` first;
- `open_chat_client` passes the server's `kind`;
- translation calls `complete`;
- the compose source drains `compose`, with the runner holding every RPHelper
  rule about a tool call.

Frames, rows, replay and the stop stay as they were.

## Interface intent

- **`ChatClientLike`** (in `llm_registry.py`) is now `complete(model, messages)`
  plus `compose(model, messages, tools)`, as DEC-035-6 defines them. It no
  longer has `chat_stream`.
- **`ChatClientFactory`** is called `(kind, base_url, api_key, timeout_seconds)`
  (DEC-035-1).
- **`open_chat_client(connection, enabled_model, timeout_seconds, client_factory)`**
  keeps its signature. It passes `enabled_model.server.kind` first to the
  factory.
- **`compose_stream(...)`** keeps its signature and its setup phase. Its body
  does the following:
  1. Drains the gateway's `compose` inside `aclosing`.
  2. Turns each text piece into a token frame and accumulates it.
  3. Passes each runner-emitted frame through.
  4. On success, writes the joined token text as the assistant row on a fresh
     connection.
  5. Yields `done`.

  It no longer assembles rounds, tool-call fragments or `<think>` tags
  (DEC-035-7, `DEC-arch-llm-client-library-8`).
- **The compose runner** is private to `compose.py`: the compose half of the
  wrapper (DEC-035-6, `DEC-arch-llm-client-library-7`). Given a `ToolCall` and
  `emit`, it does the following:
  1. Emits the `tool_start` frame.
  2. Awaits the seam's `dispatch`.
  3. Emits the result's frame.
  4. Returns the result message's content.

  On any `Exception`, it emits a `tool_fail` frame (`tool_failed`) for that call
  and returns the seam's fixed "tool failed" text. Cancellation propagates.
- **`translate_message(...)`** keeps its signature. It obtains its text from the
  client's `complete` rather than by joining stream deltas, and the
  `_join_content` helper goes away. The strip, the cache, the failure mapping and
  the disconnect check are unchanged.
- **`get_chat_client_factory`** (`routers/stream.py`) and
  **`get_translation_chat_client_factory`** (`routers/translation.py`) return the
  gateway class.

## Definition of done

1. DoD-1 `[test]` — `open_chat_client` calls the injected factory with the
   enabled model's server `kind`, `base_url`, resolved key and timeout, in that
   order. `secret_ref_missing` is still raised before the factory is called.
2. DoD-2 `[test]` — A compose exchange whose client streams text pieces emits
   one token frame per piece, in order, with `<think>` tags verbatim. The
   assistant row persisted before `done` holds exactly the joined token text.
   `done` carries that row's id as a string. (UC-034, US-114, US-146)
3. DoD-3 `[test]` — When the client invokes an offered tool, the exchange does
   the following:
   - emits `tool_start` and then `tool_result`, both carrying that call's
     `call_id` (`call_1` for the first call);
   - persists the tool row through the seam;
   - continues to the final text and `done`.

   (UC-051, UC-053)
4. DoD-4 `[test]` — A tool whose `run` fails produces a `tool_fail` frame with
   code `tool_failed`. The model-facing output is the fixed failed text, and the
   exchange still reaches `done`. (US-066.AC-1, UC-051, UC-053)
5. DoD-5 `[test]` — If `dispatch` itself raises a non-cancellation exception,
   the runner emits a `tool_fail` frame for that call and returns the fixed
   failed text, and the exchange still reaches `done`.
   (`DEC-arch-llm-client-library-7`)
6. DoD-6 `[test]` — The client's `compose` receives only the offered
   declarations, in the fixed order `memo_search`, `session_search`,
   `web_search`. With no tool offered, it receives an empty declaration list.
   (FEAT-014, FEAT-015, FEAT-016)
7. DoD-7 `[test]` — If the client's stream raises `llm_unreachable` after some
   text, the route emits an `error` frame (`llm_unreachable`) and no `done`. The
   streamed text is persisted as the assistant row. (US-044)
8. DoD-8 `[test]` — Closing the compose source while a tool is running ends the
   exchange: the client's compose stream is closed, and no tool row is written
   for that call. Text streamed before the stop is persisted as an ordinary
   zone row. (US-132.AC-1, US-133.AC-1)
9. DoD-9 `[test]` — Model-resolution refusals (`no_model_enabled`,
   `model_not_chosen`, `model_not_enabled`) still arrive as `error` frames after
   `accepted`. (US-107, US-144)
10. DoD-10 `[test]` — A translation miss calls `complete` with the two
    translation messages (system instruction, then the stored text verbatim).
    The result is `<think>`-stripped, cached and returned. (UC-039, UC-041,
    US-045)
11. DoD-11 `[test]` — Translation failures map as follows:
    - `llm_unreachable` from `complete` becomes `translation_failed`, and
      nothing is cached;
    - a result that is empty after the strip becomes `translation_failed`;
    - model-resolution errors and `secret_ref_missing` propagate under their own
      codes.

    (US-048, UC-039)
12. DoD-12 `[test]` — If the client has disconnected by the time the result
    arrives, nothing is cached. This is the best-effort check, and it is
    unchanged. (US-133.AC-2)
13. DoD-13 `[test]` — `get_chat_client_factory()` and
    `get_translation_chat_client_factory()` return the gateway class.
14. DoD-14 `[test]` — The privacy-audit modules pass unchanged on the moved
    chat fakes. (FEAT-019, US-085)
