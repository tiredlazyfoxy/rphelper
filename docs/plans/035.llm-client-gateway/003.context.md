# Step 003 — step-specific context

## Library calls this step makes

- `chat(messages, *, system=None, options=None, stream=False, on_delta=None) -> str`.
  The Responses client turns each message into an input item, which is why a
  leading system message works without `system=` (DEC-035-4).
- `chat_with_tools(messages, *, tools_definitions, tools, system=None, max_loops=5, options=None, stream=False, on_delta=None, response_format=None) -> str`.
  In 0.2.0 it works like this:
  - Before any request, every advertised name in `tools_definitions` must have
    a callable in `tools`, or `ValueError` is raised.
  - Nested definitions (`{"type":"function","function":{…}}`) are flattened.
  - Per call, it checks the name was offered and parses the arguments, raising
    `LLMError` otherwise. It then checks that every kwarg name is in
    `inspect.signature(func).parameters` (`ValueError` otherwise), and calls
    `func(**kwargs)`, awaiting the result if it is awaitable.
  - Any `Exception` from the callable becomes `RuntimeError`.
    `CancelledError` (a `BaseException`) passes through untouched.
  - A `str` result is sent as-is. A `dict` or `list` result is JSON-dumped.
  - `on_delta(piece)` gets reasoning pieces (with `<think>` prefixed on the
    first piece of a run) and text pieces (with `</think>` prefixed on the first
    text after reasoning, or as its own piece at round end). It is awaited if
    awaitable. Nothing about tool calls reaches `on_delta`.
  - The history accepts chat-completions assistant turns with
    `tool_calls: [{"id","type":"function","function":{"name","arguments"}}]` and
    `{"role":"tool","tool_call_id","content"}` turns.

## RPHelper values used

- `ChatMessage` and `ToolCall(call_id, name, arguments)` come from
  `services/llm/chat.py`. `to_wire_message` is at `chat.py:73`, and the gateway
  calls it unchanged (DEC-035-4).
- Tool declarations are `Mapping[str, object]` (`services/tools/definitions.py:13`),
  nested `{"type": "function", "function": {"name", "description",
  "parameters": {…, "properties": {…}}}}`. All three current declarations have
  exactly one property, `query`. The gateway must not import
  `services/tools/`: type the declarations structurally, as `Mapping[str, object]`.
- The wrapper reads `function.name` and `function.parameters.properties` from
  each declaration. DEC-035-6 gives the signature rule: keyword-only parameters
  defaulting to a private absent-marker, with absent values left out of the
  arguments JSON.

## Queue and termination

DEC-035-7 is the whole mechanism. Three points matter for this step:

- `on_delta` and `emit` must not block, because the library awaits `on_delta`
  inline on its read path.
- The task's exception is read from the task when the end marker is reached.
  The library's own exception types are mapped there, per DEC-035-8.
- The `finally` runs on normal end, on error, on `aclose()`/`GeneratorExit` and
  on cancellation of the consumer. After it, no library client is open.

## Test notes (for the test-coder, from the spec)

The fake library class needs an async `chat_with_tools` that imitates the
library's tool-call contract: it calls `on_delta` with scripted pieces, checks
kwarg names against `inspect.signature` exactly as above, and calls the given
callables with scripted kwargs. That is what makes DoD-6..8 and DoD-12
observable. DoD-12 needs a fake that blocks on an event the test controls, and
records whether it was cancelled and whether its context manager exited.
