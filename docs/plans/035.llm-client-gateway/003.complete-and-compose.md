# Step 003 — Gateway complete and compose

## Goal

This step adds the gateway's two chat operations over the library:
`complete`, which is non-streamed, and `compose`. `compose` runs the library's
streaming tool loop as one task that feeds one ordered queue, and presents each
offered tool to the library through a minted, signature-bearing wrapper. Nothing
calls either operation yet; step 004 switches the callers.

## Interface intent

- **`LlmGateway.complete(model, messages)`** is async. It takes a model name and
  a sequence of `ChatMessage` values, and returns the model's whole answer text.
  It is built on the library's non-streamed `chat` (DEC-035-4, DEC-035-8).
- **`ComposeText`** is an immutable value carrying one streamed text piece,
  verbatim.
- **`ComposeTools`** is an immutable value that bundles two things:
  - the offered tool declarations: mappings in the shape
    `services/tools/definitions.py` declares them, in offered order;
  - the **runner**: an async callable that receives a `ToolCall` and an `emit`
    callback for the caller's own events, and returns the tool's output text.

  See DEC-035-6.
- **`LlmGateway.compose(model, messages, tools)`** is an async iterator. It takes
  a model name, a sequence of `ChatMessage` values and a `ComposeTools`. It
  yields, in the order things happened, `ComposeText` pieces and whatever the
  runner emitted (generic in that event type). It ends when the library's tool
  loop ends, and raises `llm_unreachable` on a library failure. Closing it
  cancels the library task (DEC-035-6, DEC-035-7, DEC-035-10,
  `DEC-arch-llm-client-library-4`, `-5`, `-6`, `-8`).
- **The per-declaration library callable** is internal: the gateway half of the
  wrapper (DEC-035-6).

## Definition of done

1. DoD-1 `[test]` — `complete` builds one library client with the model and
   calls its `chat` non-streamed, with no system keyword and no options. The
   library receives the messages as their `to_wire_message` forms, in order,
   with the leading system message as the first item. `complete` returns the
   library's text unchanged. (UC-039)
2. DoD-2 `[test]` — `complete` maps failures as follows (DEC-035-8):
   - an `LLMError` whose message contains `status 401` or `status 403` raises
     `llm_unreachable` with `detail` `{"reason": "auth_failed"}`;
   - any other `LLMError` (another status, a transport message, an
     `Invalid response …` or `Unreadable reply …` message), or a `ValueError`
     from the library, raises `llm_unreachable` with `detail`
     `{"reason": "unreachable"}`;
   - for `kind` `'openai'` with no api key, it raises `llm_unreachable` with
     `{"reason": "auth_failed"}` and calls nothing.

   No provider text appears in the error's message, its `detail` or the log.
   The error has no `__cause__`, and its `__suppress_context__` is true.
   (UC-039, US-048)
3. DoD-3 `[test]` — `compose` builds one library client with the model and calls
   `chat_with_tools` with all of the following:
   - `stream=True`;
   - `max_loops=sys.maxsize`;
   - no system keyword and no options;
   - `tools_definitions` equal to the declarations as given, in order;
   - one callable per declaration name.

   (`DEC-arch-llm-client-library-4`, `-12`)
4. DoD-4 `[test]` — Replayed history reaches the library intact: an assistant
   `ChatMessage` carrying a tool call, followed by its `tool` message, arrives in
   the library's `messages` with `tool_calls` and `tool_call_id` preserved.
   (UC-034)
5. DoD-5 `[test]` — Each piece the library passes to `on_delta` yields exactly
   one `ComposeText` with identical text, in order. `<think>` and `</think>`
   pass through verbatim, with nothing added or removed. (US-114, US-146)
6. DoD-6 `[test]` — When the library invokes a tool callable with keyword
   arguments, the runner receives a `ToolCall` with:
   - `call_id` equal to `call_1`, `call_2`, … in invocation order within one
     `compose` call, restarting at `call_1` for the next call;
   - the declaration's name;
   - `arguments` equal to `json.dumps` of the given keyword arguments, with
     non-ASCII kept unescaped.

   The runner's returned text is what the callable returns to the library.
   (`DEC-arch-llm-client-library-5`)
7. DoD-7 `[test]` — Each tool callable's `inspect.signature` lists exactly the
   declaration's `properties` names, as keyword-only parameters that have
   defaults. A declared argument the library does not pass is absent from the
   `ToolCall`'s `arguments` JSON. (`DEC-arch-llm-client-library-6`)
8. DoD-8 `[test]` — Events the runner emits appear in the stream in emit order.
   Text the library streamed before a tool call precedes that call's events, and
   text streamed after the call follows them. (UC-051, UC-053)
9. DoD-9 `[test]` — When the library's call returns, the stream ends after the
   last queued event. The library's returned text is not yielded.
   (`DEC-arch-llm-client-library-8`)
10. DoD-10 `[test]` — When the library fails, every event queued before the
    failure is yielded first. The stream then raises `llm_unreachable` with no
    `__cause__` and no provider text, and with this `detail`:
    - `{"reason": "auth_failed"}` for an `LLMError` whose message contains
      `status 401` or `status 403`;
    - `{"reason": "unreachable"}` for any other `LLMError`, and for a
      `RuntimeError` or `ValueError` (which includes the temporary-limitation
      cases: an unoffered tool name, unparseable arguments, unknown argument
      names).

    (US-044)
11. DoD-11 `[test]` — For `kind` `'openai'` with no api key, `compose` raises
    `llm_unreachable` with `{"reason": "auth_failed"}` before yielding any
    event.
12. DoD-12 `[test]` — Closing the stream (`aclose`) while the library call is
    still running has these effects:
    - the library call observes cancellation;
    - the library client is exited;
    - `aclose` returns without raising.

    A runner awaiting inside a tool at that moment observes cancellation, and no
    later event is yielded. (UC-085, US-133.AC-1)
13. DoD-13 `[test]` — With an empty declarations list, `compose` still calls
    `chat_with_tools`, with an empty `tools_definitions` and an empty callables
    map. (DEC-035-10)
14. DoD-14 `[test]` — Each `compose` call enters and exits exactly one library
    client, whether it completes, fails or is closed.
