## Goal

## Interface intent

**`app/SearchScreen.tsx`** (new)

- **`SearchScreen`** — `observer` component, no props. Creates one `SearchState` with
  `useState`. Reads `q` from the URL's search parameters.
  - **Search box**: Mantine `TextInput`, accessible name `Search query`, value
    component-local, set from `q` whenever `q` changes. Enter navigates (in-entry, push) to
    `searchHref(value)` (`004`). It is **focused on every arrival at `/search`** — keyed on
    the location's identity, so a second navigation to `/search` focuses it again (D9).
  - **Load**: whenever `q` changes, runs `loadSearch(state, q, signal)` with a fresh
    `AbortController`; the previous one, and the one alive at unmount, are aborted.
  - **States**: `"idle"` → only the box; `"loading"` → the text `Searching…`; `"failed"` →
    `Search failed`, the failure message, and a `Retry` button that re-runs the load for the
    current `q`; `"ready"` with `hasNoHits` → `Nothing found.`; `"ready"` otherwise → the
    groups.
  - **Groups**: in the order Characters, Setups, Sessions, Entries, Notes; **a group with no
    hits is not rendered**. Each rendered group is a region whose accessible name is its
    heading, holding a list of rows. Each row is a **link** (`href` = the hit's target from
    `004`); activating it navigates in-entry.
  - **Row content** (Mantine props only):
    - character — the name; archived → `Archived` badge + dimmed text;
    - setup — the setup name and, secondary, the character name; archived → as above;
    - session — the formatted start (`formatSessionStart(created_at)`) and, secondary, the
      character name followed by ` · ` and the setup name when there is one; archived → as
      above;
    - entry — the snippet as plain text and, secondary, the character name ` · ` the
      formatted session start;
    - memo — the snippet as plain text and, secondary, the level label (`User note`,
      `Character note`, `Setup note`, `Session note`); `is_enabled` false → snippet
      `c="dimmed"` + `td="line-through"` and a gray `Disabled` badge.
  - No title for any memo row. No markdown rendering. No `notifyFailure`.

**`app/App.tsx`** (changed)

- The `/search` route renders `SearchScreen` instead of the empty centre. Nothing else in
  the route table changes.

## Definition of done

1. `[test]` **All five groups, in order.** `/search?q=mira` with a stub answering one hit
   per kind: five regions named `Characters`, `Setups`, `Sessions`, `Entries`, `Notes`, in
   that document order, each holding its hit's primary text. The request carried
   `q=mira`. (US-074.AC-1, US-075.AC-1, UC-059)
2. `[test]` **Empty groups hidden.** A stub with hits only in Sessions and Notes renders
   exactly those two regions, Sessions before Notes. Five empty groups render `Nothing
   found.` and no region. (US-075.AC-1, `context.md` literals)
3. `[test]` **Disabled memo marked.** Two memo hits, one `is_enabled` false and one true:
   only the disabled row shows a `Disabled` badge, and its snippet is struck through; the
   enabled row has no badge. Each memo row shows its level label (`Setup note` for a setup
   memo, `User note` for a user memo). (US-137.AC-2, D7, US-119)
4. `[test]` **Archived marked.** An archived character, setup and session each show an
   `Archived` badge; their non-archived siblings show none. (U3, D7)
5. `[test]` **Row labels.** The setup row shows its character's name; the session row shows
   `formatSessionStart(created_at)` and "<character> · <setup>" (only "<character>" when
   `setup_name` is null); the entry row shows its snippet and "<character> · <formatted
   session start>". Snippets containing markdown (`**bold**`) render literally. (D4, D7)
6. `[test]` **Navigation per kind.** Clicking each row moves the in-entry router (probe) to
   exactly that hit's target from `004.context.md` "Targets" — including
   `/sessions/<session_id>?entry=<id>` for an entry and `/sessions/<scope_id>?notes=open`
   for a session memo, `/settings` for a user memo, and `/characters/<character_id>` for a
   setup and a setup memo. (UC-060, U4)
7. `[test]` **Blank query makes no request.** `/search` and `/search?q=%20` render the box
   (empty / holding the spaces), no region, no `Nothing found.`, and `fetch` is never
   called for `/api/search`. (D1, U4)
8. `[test]` **Box follows and submits the URL.** At `/search?q=mira` the box holds `mira`.
   Typing `kael` in place and pressing Enter navigates to `/search?q=kael`, which requests
   `q=kael` and shows its results; the box then holds `kael`. (U4)
9. `[test]` **Failure inline, whole page.** A 409 `no_embedding_model` envelope renders
   `Search failed` with the envelope's message and no region; `notifyFailure` is not
   called (no notification appears). `Retry` re-requests the same `q`, and a 200 then shows
   the groups. (U1, `context.md` constraints)
10. `[test]` **Focus on arrival.** Rendering at `/search` puts focus in the `Search query`
    box; after focus moves elsewhere, a fresh navigation to `/search` (same path) focuses it
    again. (D9)
11. `[test]` **Rail trigger reaches it (App).** In `App` with the tree collapsed to the
    rail, pressing the rail's `Search` button lands on `/search` with the `Search query`
    box focused. With the tree expanded, `/search` renders the box in the centre. (US-118.AC-2,
    D9)
12. `[test]` **App amendments.** In `tests/app/App.test.tsx`, `/search` leaves
    `EMPTY_CENTRE_ROUTES` (it now renders the `Search query` box) and stays in
    `NO_SESSION_ROUTES` (no note wall on `/search`). No other existing assertion is dropped.
    (`005.context.md`)
13. `[manual/live]` Against a running backend with an embedding model designated and data
    in every kind: search a half-remembered word, scan the groups, open an entry hit and a
    session-memo hit. Unset the designation: the page shows `Search failed` with the
    no-embedding-model message. (US-074.AC-1, U1)
