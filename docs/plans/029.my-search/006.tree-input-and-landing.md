# Step 006 — The tree's search input, and landing on an entry or an opened wall

## Goal

Replace the tree header's `Search` button with a text input that submits to
`/search?q=<text>` (US-118.AC-1), and make the two landing params work on a session: `entry`
scrolls the stream to that settled entry and highlights it briefly; `notes=open` opens the
note wall on arrival (`context.md` U4, D8). Both ends of navigation outside the results
page; merged into one step because the tree half alone is under the size floor.

## Interface intent

**`app/CharacterTree.tsx`** (changed)

- The header's `Search` `IconButton` is replaced by a Mantine `TextInput`, accessible name
  `Search`, value component-local. Enter navigates (in-entry, push) to `searchHref(value)`
  (`004`) — `/search` when blank. The `New character` button and the `Show archived`
  switch are unchanged. The local `SEARCH_PATH` constant goes if nothing else uses it.

**`app/SessionScreen.tsx`** (changed)

- Reads the URL's search parameters. `notes=open` → the note wall is open on arrival
  (through `noteWallState`'s existing open function), in place of the closed-on-mount
  default. Any other value or absence → unchanged behaviour.
- Passes `entry`'s value (or none) to `SessionStream` as the **focus entry id**.

**`app/SessionStream.tsx`** (changed)

- Props gain an optional focus entry id (string or none, default none), passed unchanged to
  `StreamRecord`. Nothing else changes.

**`app/StreamRecord.tsx`** (changed)

- Props gain the same optional focus entry id, passed to each `StreamEntry` as a boolean
  "is the focus entry".
- `StreamEntry`'s `<li>` always carries `data-entry-id` = its message id. When it is the
  focus entry, on mount (or when it becomes the focus entry) it scrolls itself into view
  (centred) **once** and is highlighted — `data-highlighted="true"` plus a Mantine
  background prop — for **2000 ms**, after which both are removed. The `<li>`'s existing
  ref, key and content are unchanged.

## Definition of done

1. `[test]` **Input reachable in the expanded tree.** The ready tree's header holds a
   textbox named `Search`. Typing `mira` and pressing Enter moves the in-entry router to
   `/search?q=mira` (the probe's `q` decodes to `mira`). Typing `a&b c` submits a `q` that
   decodes to `a&b c`. Enter on an empty box moves it to `/search`. (US-118.AC-1, U4)
2. `[test]` **Tree amendments.** The former "Search moves the in-entry router to /search"
   case (~L594) is replaced by DoD-1; the "ready tree's only buttons" case (~L744-753) now
   expects exactly one button, `New character`, plus the `Search` textbox and the `Show
   archived` switch. No other existing assertion is dropped. (`006.context.md`)
3. `[test]` **Entry anchor.** At `/sessions/<s>?entry=<m>` with a loaded record of several
   entries, the entry whose `data-entry-id` is `<m>` has `scrollIntoView` called on it
   exactly once and carries `data-highlighted="true"`; no other entry does. Every entry
   carries `data-entry-id` equal to its id. (UC-060, D8)
4. `[test]` **Highlight is brief.** With fake timers, the highlight is present at 1999 ms
   and gone at 2000 ms; `scrollIntoView` is not called again afterwards, including after a
   re-render of the record. (D8, literals)
5. `[test]` **Unknown entry does nothing.** `?entry=<id not in the record>` renders the
   session normally: no `scrollIntoView` call, no highlighted entry, no error text.
   Without `entry`, no entry is highlighted. (D8)
6. `[test]` **Wall opened on arrival.** `/sessions/<s>?notes=open` renders the note wall
   open on arrival (its notes region is visible without pressing "Open notes");
   `/sessions/<s>` without the param renders it closed, as before. (UC-060, U4, D8)
7. `[manual/live]` From a real search, open an entry hit deep in a long session: the stream
   scrolls to it and it flashes, then settles. Open a session-memo hit: the wall is open.
   (UC-060)
