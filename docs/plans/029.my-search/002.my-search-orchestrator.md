# Step 002 — `search/my_search.py`: hydration and the `run_my_search` orchestrator

## Goal

Add the session, entry and memo hit values, their owner-scoped hydration reads (D4), the
grouped result value, and `run_my_search`: three 025 port calls (no extra predicate), the
two LIKE searches from `001`, hydration, and fail-whole propagation (`context.md` U1–U3,
D1, D2, D4, D5).

## Source files

backend/app/services/search/my_search.py

## Test files

backend/tests/test_my_search_service.py

## Interface intent

**`app/services/search/my_search.py`** (extended)

- **`SessionHit`** — frozen value: session id, character name, setup name (or none),
  session `created_at`, archived (bool, the session's own `archived_at`).
- **`EntryHit`** — frozen value: message id, its session id, snippet (text, from the port),
  the session's character name, the session's `created_at`.
- **`MemoHit`** — frozen value: memo id, scope (one of the four memo scope literals), scope
  id (**none when scope is user**), the character id the memo routes to (character level →
  its scope id; setup level → that setup's character id; otherwise none), snippet (from the
  port), `is_enabled` (bool, read from `memos`).
- **`MySearchResults`** — frozen value with five ordered lists, in UC-059 order: characters
  (`CharacterHit`), setups (`SetupHit`), sessions, entries, memos.
- **Hydration helpers** — private; one owner-scoped read per kind (D4) taking the user id
  and the port's hits, returning the hit values **in the port's order**, dropping any id the
  read does not return.
- **`run_my_search`** — inputs: a connection, the user id, the raw query text; keyword-only
  `client_factory` and `timeout_seconds` defaulting to the port's defaults. Behaviour:
  1. blank query (after stripping) → a `MySearchResults` with five empty lists; no port
     call, no factory call, no SQL;
  2. otherwise, in D5's order: the port's session scope, then memo scope, then entry scope
     — each built from the user id alone with **no extra predicate**, each with the cap as
     `limit`, each passed the query and the two keyword arguments; then `search_characters`
     and `search_setups` (`001`); then hydration;
  3. returns the five groups. Any exception propagates unchanged (U1); nothing partial is
     returned. Reads only; leaves no transaction open on return or raise (D6).

## Definition of done

1. `[test]` **Every kind reachable.** User A owns a character, a setup, a session with
   settled entries, and memos at all four levels, each containing a distinctive token (and,
   for the vector-armed kinds, a vector equal to the fake's vector of the query text). One
   `run_my_search` call returns a hit in each of the five groups, each naming the seeded id.
   (US-074.AC-1, UC-058)
2. `[test]` **Groups in order.** The result exposes the five groups in the order
   characters, setups, sessions, entries, memos, and each group holds only its own kind's
   ids. (US-075.AC-1, UC-059)
3. `[test]` **Memo state never filters.** Four of A's memos match equally: enabled +
   forced, enabled + not forced, disabled + forced, disabled + not forced. All four are
   returned; each hit's `is_enabled` equals its stored value. (US-137.AC-1, US-137.AC-2
   data, R3)
4. `[test]` **Memo levels and routing ids.** A user-level memo's hit has scope `user`,
   scope id none, character id none; a character-level memo's has the character's id as
   both scope id and character id; a setup-level memo's has the setup's id as scope id and
   the setup's character's id as character id; a session-level memo's has the session id as
   scope id and character id none. No hit carries a title. (U4, D4, US-119)
5. `[test]` **Session hydration.** A matched session with a setup carries its character's
   name, the setup's name, its `created_at` and `archived` false; a matched session with no
   setup carries setup name none; an archived matched session is returned with `archived`
   true. (D4, U3, US-068 shape)
6. `[test]` **Entry hydration and corpus boundary.** A settled entry containing the token
   is returned with its message id, its session id, a snippet containing the token, the
   session's character name and the session's `created_at`. A current-zone message and a
   buried message containing the same token are absent. (D4, R11, UC-038, US-115)
7. `[test]` **Owner isolation (absence), every kind.** User B owns a character, setup,
   session (with an identical `session_vec` vector), settled entry and memo, each matching
   A's query on every arm its kind runs. None of B's ids appears in any of A's five
   groups. (US-076.AC-1, UC-065, R5)
8. `[test]` **Port order kept; cap.** With 25 matching memos whose vector ranking is known
   from the fake's pure function, the memo group holds exactly 20 hits, in the port's order
   (the test derives the expected order from D1 of 025 applied to rankings it computes
   itself, or asserts membership plus the vector-derived prefix). Characters over the cap
   are capped at 20 likewise. (D2)
9. `[test]` **Blank query.** `""` and `"   "` return five empty groups, and the fake
   factory records **zero** constructions and zero embed calls. (D1)
10. `[test]` **No model → whole search fails.** With the vector tables present, a matching
    character present, and no designated embedding model, `run_my_search` raises
    `NoEmbeddingModelError` (no result is returned). With the vector tables declared at a
    dimension different from the designated model's, it raises `NoEmbeddingModelError` whose
    detail is `{"reason": "dimension_mismatch"}`. With the fake scripted to raise, it raises
    `LlmUnreachableError`. (U1, D5)
11. `[test]` **No transaction left open** after a successful call, after a blank call, and
    after each raise in DoD-10. (D6)
12. `[test]` `my_search.py` still imports no `fastapi`, and contains no reference to
    `is_forced`. (`context.md` constraints)
