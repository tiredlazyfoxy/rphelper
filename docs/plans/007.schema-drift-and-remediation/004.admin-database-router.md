# Step 004 — The admin database router and its pydantic models, behind one router-level `require_role(Role.admin)`

## Goal

Expose the report and the two apply operations as the three routes `context.md` D9 fixes,
owning HTTP and nothing else, guarded once at the router so a route added later cannot
forget it, and register it in the app factory.

## Source files

```
backend/app/models/admin_db.py
backend/app/routers/admin_db.py
backend/app/main.py
```

## Test files

```
backend/tests/test_admin_db_router.py
```

## Interface intent

**`backend/app/models/admin_db.py`** — the pydantic response models for this router and
nothing else. Models live in `app/models/` beside `ids.py` and `health.py`; there is no
`schemas/` directory. **There is no request model at all** — both apply routes take an
empty body.

- **A column-shape model** — a column's name, its normalised SQLite type text and its NOT
  NULL flag.
- **An index-shape model** — an index's column list and its uniqueness flag.
- **A changed-column model** — the column name with its **expected** and its **actual**
  shape, so the page renders "expected → actual" without deriving anything.
- **A per-table report model** — the table name; the status as the closed **three-value**
  set (`context.md` D2); the missing column names; the extra column names; the changed
  columns; the missing indexes; the extra indexes. It carries **no row count, no byte size
  and no timestamp**, and **no field relating to a user, character, setup, session, message
  or memo** (R5, UC-066).
- **A whole-report model** wrapping the per-table reports under one field, in registry
  declaration order. A route returns a pydantic model, never a bare list and never a
  `JSONResponse`.
- **No id field anywhere** — this router's wire carries no snowflake, so `models/ids.py`'s
  two aliases are not imported (`context.md`, "This feature's wire carries no id").

**`backend/app/routers/admin_db.py`** — the router, owning HTTP and nothing else: no
business rule, no SQL, no registry lookup, no transaction.

- It declares its own prefix **`/api/admin/database`** and a tag, following
  `routers/health.py`'s and `005`/`006`'s admin-router precedent, and carries
  **`require_role(Role.admin)` as a router-level dependency** — on the router, never per
  handler.
- Exactly the three routes of `context.md` D9's table: `GET /tables`,
  `POST /tables/{table_name}/create` and `POST /tables/{table_name}/sync`, each answering
  **200**. Every handler takes the connection dependency and, like `routers/health.py`,
  **imports `metadata` from `app.db.schema` and passes it down** as a plain argument.
- Each handler calls **exactly one** operation — the report builder in `db/drift.py` for
  the read, one of `db/sync.py`'s two operations for an apply — and maps its plain result
  onto a model. Each apply route answers with the **re-derived** per-table report the
  operation returns, which is what gives **US-018.AC-2** a server-side witness.
- **No handler translates a domain error by hand**: the handler `001` registered renders
  `unknown_table` as 404 and `schema_apply_failed` as 500 on its own. The router contains
  no `try` / `except` and builds no `HTTPException`.
- **`{table_name}` is passed down as a plain string and is never used to build SQL here**;
  `db/sync.py` validates it against the registry (`context.md` D9).
- **No query parameter exists anywhere on this router** — no filter, no page, no sort. **No
  route is keyed on anything but a table name**, and there is no route returning a count
  of anything.
- **No rebuild route, no export route and no import route** is declared — UC-016 belongs to
  `fast/002` and export/import to `030`/`031`.

**`backend/app/main.py`** — include the router with one appended `app.include_router(...)`
line, beside health, bootstrap, auth, admin-users and admin-llm. Nothing else changes: the
factory's ordering stands, collaborators stay imported as **bare names**, and the
**lifespan still runs no DDL**.

## Definition of done

1. `[test]` `GET /api/admin/database/tables` with a live administrator session answers 200
   with **one entry per registry table, in declaration order**, each carrying its status
   from the closed three-value set. (US-017.AC-1, UC-014)
2. `[test]` The response distinguishes an **in sync**, a **missing** and a **drifted**
   table against a real database in each of those states, and a drifted entry carries its
   missing columns, its extra columns, its changed columns with expected and actual type
   and nullability, and its missing and extra indexes. (US-017.AC-1, UC-014;
   `context.md` D1)
3. `[test]` No response on this router carries a **row count, a byte size or a timestamp**,
   nor any field or count relating to a user, character, setup, session, message or memo;
   the router declares **no route** that could return one and **no query parameter** at
   all. (R5, UC-066)
4. `[test]` **Every** route on this router answers **403** with the `insufficient_role`
   envelope for a live roleplayer session and **401** with the `not_authenticated`
   envelope when there is no session — in that order of precedence.
   (`admin-surfaces.md`, "Backend gating is independent and authoritative" — **no product
   id**)
5. `[test]` The guard is **router-level**: a route registered on this router that declares
   no dependency of its own is still refused for a roleplayer.
   (`backend-structure.md`, "Authorization as router dependencies"; the pattern `005/003`
   DoD-4 set — **no product id**)
6. `[test]` `POST /api/admin/database/tables/{table_name}/create` on a **missing** table
   answers 200, the answer reports that table **in sync**, and a subsequent
   `GET /api/admin/database/tables` reports it in sync too. (US-018.AC-1, US-018.AC-2,
   UC-015)
7. `[test]` The same route on a table that **already exists** answers 200 and changes
   nothing — no column added, no column dropped, no row touched. (`context.md` D4 — **no
   product id**)
8. `[test]` `POST /api/admin/database/tables/{table_name}/sync` on a **drifted** table
   answers 200 with that table reported **in sync**, and a subsequent report read agrees.
   (US-018.AC-1, US-018.AC-2, UC-015)
9. `[test]` The same route on a table carrying a column the registry no longer declares
   drops it and preserves the data in every surviving column, observable through a read of
   those columns afterwards. (US-018.AC-1; `context.md` D5)
10. `[test]` Both apply routes accept **no request body and no query parameter**, and a
    supplied body changes nothing about what they do. (`context.md` D9 — **no product
    id**)
11. `[test]` Either apply route against a table name the registry does not declare answers
    **404** with `{"error": {"code": "unknown_table", …}}` carrying the name, and emits no
    DDL — including for a name carrying SQL punctuation. (`context.md` D9 — **no product
    id**)
12. `[test]` An apply that cannot complete answers **500** with
    `{"error": {"code": "schema_apply_failed", …}}` whose `detail` carries the table name
    and the operation and **no driver message**, and the table is left exactly as it was.
    (`context.md` D5, D9 — **no product id**)
13. `[test]` The router issues no SQL, holds no rule and performs no registry lookup: its
    only database contact is through the connection dependency, the registry is imported
    at module level and passed down as an argument, and the unknown-table refusal comes
    from the service rather than from a handler check. (`backend-structure.md`, routers
    versus services — **no product id**)
14. `[test]` The router declares **no rebuild route, no export route and no import route**,
    and nothing in this feature's route surface mentions a vector index.
    (`brief.md`'s Scope Out — **no product id**)
15. `[manual/live]` The router declares exactly the three routes at the paths
    `context.md` D9 fixes, carries `require_role(Role.admin)` **once, on the router**, and
    no handler declares an authorization dependency of its own. Verifier confirms by
    reading the module.
16. `[manual/live]` `main.py`'s lifespan still runs no DDL, the router registration is the
    only change to the factory, and feature `001`'s assertion that `sqlite_master` holds no
    application table after startup still passes. Verifier confirms by reading it and by
    running `001`'s test.
17. `[manual/live]` `uvicorn app.main:app` on port 8184 starts; against a bootstrapped
    database an administrator's cookie can read the report, create a hand-dropped table and
    sync a hand-drifted one through `curl`, and a roleplayer's cookie is refused on all
    three routes.
18. `[manual/live]` `mypy app`, `ruff check .` and `pytest` all pass from `backend/`.
