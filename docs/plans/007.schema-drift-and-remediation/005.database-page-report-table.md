# Step 005 — The Database page: its store, the drift report table and its status badge

## Goal

Replace the `/database` route's 404 element with the real page — a plain Mantine table of
per-table drift rows with a coloured, word-bearing status badge and a differences summary
— driven by a MobX page store with no methods.

## Source files

```
frontend/src/admin/databasePageState.ts
frontend/src/admin/DatabasePage.tsx
frontend/src/admin/AdminApp.tsx
```

## Test files

```
frontend/tests/admin/databasePage.test.tsx
```

## Interface intent

**`frontend/src/admin/databasePageState.ts`** — the page store, its row types and its load
effect, in one module (`context.md` D13).

- **Row types mirroring step `004`'s models** — a column shape (name, type text, not-null
  flag), an index shape (columns, unique flag), a changed column (name, expected shape,
  actual shape), and a per-table row: the table name, the status as the **closed
  three-value union** (not widened to `string`), the missing and extra column names, the
  changed columns, and the missing and extra indexes. **No id field of any kind** — the
  row key is the table name — and **no row count, no size, no timestamp**.
- **A page-state class** holding observable fields only: the rows, an explicit
  `"idle" | "loading" | "ready"` status, and a nullable page-level error message. **No
  methods, no computed getters**, `makeAutoObservable(this, {}, { autoBind: true })` in the
  constructor.
- **A load effect** — `GET`s the report, `runInAction`s its writes, **early-returns on an
  aborted signal before writing**, moves the status through idle → loading → ready, and
  puts a failure's message into the page error field rather than raising.
- **A pure badge helper** deriving a row's badge **label and colour** from its status, so
  `context.md` D11's mapping lives in exactly one testable place: in sync → `green`,
  drifted → `yellow`, missing → `red`. The label is the **status word**, so colour is
  redundant to it and never the only signal.
- **A pure differences-summary helper** turning a row's five difference lists into the
  short administrator-facing text the table cell renders — naming the columns and index
  column-lists involved, and a changed column's expected and actual values. It **names no
  count of rows** and derives nothing from content (R5).

**`frontend/src/admin/DatabasePage.tsx`** — an `observer` component taking the store as a
prop and rendering it.

- A page-level `useEffect` with an `AbortController` that loads on mount and aborts on
  unmount. The store is created by the component that mounts the page with
  `useState(() => new …)`, **never `useMemo`**.
- A **plain Mantine `Table striped highlightOnHover`**, no data-table library, no card
  list, **no sorting, no filtering, no pagination**. Columns: **Table** (the name);
  **Status** (the `Badge`); **Columns** (the missing / extra / changed summary);
  **Indexes** (the missing / extra summary); and a trailing **`w={60}`** action column,
  empty in this step — step `006` fills it.
- A short page heading and the page's own `Container size="lg" py="md"`, since the shell
  omits `padding` deliberately (`admin-surfaces.md`).
- **Loading** is a centered Mantine `Loader` gated on the explicit status field, never on
  "rows are empty". **Errors** are an inline `Alert` **above** the table and **never** also
  a notification. A report with no rows renders an empty table body under its headers.
- **Nothing else on the page** — no Export control, no Import control, no Rebuild index
  control, no header action bar, and no disabled placeholder for any of them
  (`brief.md`'s Scope Out).

**`frontend/src/admin/AdminApp.tsx`** — replace the one `<Route path="/database">` element
that renders `NotFoundPage` with this page. Nothing else in the file changes: the
`<Routes>` stays flat and four elements long, with no nested layout route and no
`<Outlet/>`. **`navItems.ts` is not touched** — `005/005` already declares the `Database`
row.

## Definition of done

1. `[test]` On mount the page requests the drift report **once** and renders **one row per
   table** in the order the response gives, showing each table's name and its status.
   (US-017.AC-1, UC-014)
2. `[test]` A table reported **in sync**, one reported **missing** and one reported
   **drifted** each render a distinct status badge whose **text is the status word**, so
   the status is legible without colour. (US-017.AC-1; `ui-conventions.md`'s accessibility
   floor)
3. `[test]` The badge colours are the pure helper's: in sync → `green`, drifted → `yellow`,
   missing → `red`, derived in one place and mapped nowhere in the component.
   (`context.md` D11 — **no product id**)
4. `[test]` A drifted row renders its **missing columns, extra columns, changed columns
   with expected and actual type and nullability, missing indexes and extra indexes** from
   the pure summary helper. (US-017.AC-1, UC-014; `context.md` D1)
5. `[test]` The page renders **no row count, no byte size, no timestamp** and nothing
   derived from another user's data; no string it renders contains a digit-bearing claim
   about rows, sessions, characters, setups, messages, memos or users. (R5, UC-065,
   UC-066)
6. `[test]` While the report request is in flight a centered `Loader` renders and no table
   body does; the gate is the explicit status field, so an **empty** ready report renders
   the table's headers with no rows and **no** `Loader`. (`ui-conventions.md`, loading and
   empty states — **no product id**)
7. `[test]` A failed report load renders its message in an inline `Alert` **above** the
   table and **raises no notification** — `notifyFailure` and Mantine's notification API
   are not reached from this feature at all. (`ui-conventions.md`, errors and async
   feedback — **no product id**)
8. `[test]` The page declares **no id type, prop, store field or call argument** and calls
   no `parseInt`; the row key is the **table name**. (`context.md`, "This feature's wire
   carries no id" — **no product id**)
9. `[test]` The table has no sort control, no filter input and no pagination control, and
   the page sends **no query parameter** on any request. (`ui-conventions.md`, "No sorting,
   filtering or pagination" — **no product id**)
10. `[test]` The page renders **no Export control, no Import control and no Rebuild index
    control**, enabled or disabled. (`brief.md`'s Scope Out — **no product id**)
11. `[test]` The store class declares **no methods and no computed getters**; the load
    effect is a free function taking the state first, `runInAction`s its writes and
    early-returns on an aborted signal before writing, and the store is instantiated with
    `useState(() => …)` rather than `useMemo`. (`context.md` D13 — **no product id**)
12. `[test]` Unmounting mid-request aborts it and writes nothing into the store afterwards.
    (`context.md` D13 — **no product id**)
13. `[test]` `/database` renders this page and no longer the 404 element, while `/`,
    `/llm-servers` and an unmatched path are unchanged; the `<Routes>` is still flat and
    four elements long. (`admin-surfaces.md`, "Flat `<Routes>`" — **no product id**)
14. `[test]` No file under `frontend/src/admin/` imports a stylesheet or declares a `.css`
    of its own, and this page renders through Mantine props alone.
    (`frontend-structure.md`; root `CLAUDE.md` — **no product id**)
15. `[manual/live]` `frontend/src/admin/navItems.ts` is unchanged and the existing
    `Database` nav item highlights on this route. Verifier confirms by reading the file and
    by navigating.
16. `[manual/live]` Signed in as an administrator against a running backend, the page lists
    the real registry's tables with correct statuses, including for a hand-dropped and a
    hand-drifted table.
17. `[manual/live]` `npm run typecheck`, `npm test` and `npm run build` all pass from
    `frontend/`.
