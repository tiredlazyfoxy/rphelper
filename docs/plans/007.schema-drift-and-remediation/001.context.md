# Step 001 — step-specific context

Feature-wide facts are in `context.md` (**D1** for the compared and uncompared set and the
two normalisation rules, **D2** for the three statuses and the declined `seed-missing`,
**D3** for the `metadata.tables`-only walk). Only what is narrow to this step is below.

## The one table the registry declares today

`backend/app/db/schema.py` declares **`users` only** — 9 columns — plus whatever `004`,
`005` and `006` add before this feature is built. Its properties that this step's tests
will be written against:

- `id` is `BigInteger().with_variant(Integer(), "sqlite")` with `primary_key=True,
  autoincrement=False` — the reason DoD-4 exists, because the un-varianted compile would
  yield `BIGINT` and `PRAGMA table_info` reports `INTEGER`;
- `username` is `Text` with `unique=True` — the reason DoD-6 exists, because SQLite makes
  an implicit `u`-origin index for it and the registry declares no `Index(...)`;
- `role` is a **non-native** `Enum`, which compiles to a `VARCHAR(n)`;
- **the module declares no explicit `Index(...)` object anywhere.**

**This step does not edit `db/schema.py`** and must not add a table to it to have something
to test against. A test builds its own `MetaData` with purpose-made `Table` objects; that
is exactly why the readers take a `Table` rather than reaching for the real registry.

## Borrowed interfaces, by module path and role

- **`backend/app/db/engine.py`** (`001`) — `get_engine` / `resolve_db_path` behind the
  `db_engine` fixture. The connection this step's reader takes is an ordinary SQLAlchemy
  Core `Connection`; the dependency `get_connection` opens **no** transaction and neither
  does this module.
- **`backend/tests/conftest.py`** (`001`) — `db_settings` and `db_engine`, which give a
  real `.sqlite` **file** under `tmp_path`. **Never `:memory:`**, and never a mock: what is
  under test here is what SQLite's own pragmas report.

## The PRAGMA surface, precisely

Three pragmas and nothing more:

- `PRAGMA table_info(<table>)` — one row per column, carrying the name, the declared type
  text as SQLite stored it, and a not-null flag. **An empty result means the table does not
  exist** — that is how DoD-8's absent case is detected; there is no exception to catch.
- `PRAGMA index_list(<table>)` — one row per index, carrying the index name, a unique flag
  and an **origin** discriminator. Only explicitly created indexes count (DoD-6).
- `PRAGMA index_info(<index>)` — the indexed columns **in order** for one index.

The pragma's argument is a table name. It is always a name the caller resolved from a
`Table` object or is about to compare against one; **it is never a string that arrived from
an HTTP request** — that constraint lives one layer up, in `db/sync.py` (`context.md` D9),
and this module has no HTTP-facing caller at all in this step.

## What is deliberately absent from the value types

`PRAGMA table_info` also reports a column's **default value** and its **primary-key
position**, and `sqlite_master` holds the full `CREATE TABLE` text including `CHECK` and
foreign-key clauses. **None of them is read into a shape value.** `context.md` D1 records
why: they do not round-trip against a SQLAlchemy declaration, and a false `drifted` row
invites a destructive rebuild that fixes nothing. Reading them "just to have them" is how
the comparison in step `002` grows a branch that uses them.

## Gotchas

- **Compile the declared type through the SQLite dialect, not through `str(column.type)`.**
  The latter ignores the variant and yields `BIGINT`, which will never match a live
  `INTEGER` and makes `users.id` permanently drifted on a correct database.
- **A `unique=True` column is a constraint, not an index, on both sides.** The declared
  reader reads `Table.indexes`, not `Table.constraints`; the live reader filters on origin.
  They agree because both exclude the same thing, not because either compensates for the
  other.
- **`PRAGMA index_info` returns columns in indexed order and the order is part of the
  shape** — an index on `(a, b)` is not an index on `(b, a)`.
- **The per-table and whole-report value types are declared in this step but populated in
  step `002`.** Declaring them here is deliberate: two steps write this module, and the
  shape the router and the frontend bind to must be frozen once.
- **The frozen dataclass style is `services/health.py`'s `HealthProbeResult`** — plain
  frozen dataclasses, not pydantic. Pydantic appears only at the router boundary, in step
  `004`'s `models/admin_db.py`.
