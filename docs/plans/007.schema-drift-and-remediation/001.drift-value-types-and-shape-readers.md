# Step 001 — The drift report's value types, and the two readers that produce a table's shape

## Goal

Create `db/drift.py` with the closed status set, the frozen report value types, and the two
readers that answer "what shape does this table have" — one from the live SQLite file via
`PRAGMA`, one from the registry's `Table` object — in the **same** value types, so that
step `002`'s comparison is a pure function over two shapes.

## Interface intent

**`backend/app/db/drift.py`** — diagnosis only. This module issues `PRAGMA` reads and
`SELECT`s, opens **no** transaction, emits **no** DDL, and **never imports `db/sync.py`**
(`backend-structure.md`: "the code path that only reports cannot write"). It also **never
imports `app.db.schema`** — the registry and the `Table` objects arrive as arguments.

- **A table-status value** with exactly three members — in sync, missing, drifted
  (`context.md` D2). A closed set declared **once, here**, and reused by step `002`'s
  comparison, step `004`'s router model and step `005`'s frontend row type. There is **no
  fourth member and no `seed-missing`**.
- **A column-shape value** — the column's name, its **normalised SQLite type text**, and
  whether it is **NOT NULL**. Nothing else: no server default, no `CHECK` text, no
  foreign-key clause (`context.md` D1 says why each is excluded).
- **An index-shape value** — the index's **column list in declaration order** and whether
  it is **unique**. The index's *name* is not part of its identity, because
  SQLAlchemy-generated names and SQLite's own do not correspond.
- **A table-shape value** — a table's column shapes and index shapes together, as produced
  by either reader.
- **A column-difference value** — a column name present on both sides, carrying the
  **expected** shape and the **actual** shape, so the page can render "expected → actual"
  without re-deriving anything.
- **A per-table report value**, frozen — the table name, the status, the missing column
  names, the extra column names, the changed columns, the missing indexes and the extra
  indexes. **No row count, no size, no timestamp** (R5). Step `002` is what populates it;
  this step declares it so both steps bind to one shape.
- **A whole-report value**, frozen — the per-table reports and nothing beside them.
- **A live-shape reader** — takes a connection and a table name and answers with that
  table's shape, or reports that **the table is absent**. It issues `PRAGMA table_info`
  for the columns and `PRAGMA index_list` plus `PRAGMA index_info` for the indexes, and
  writes nothing. Two rules it must hold:
  - indexes whose `PRAGMA index_list` **origin is not an explicitly created index** (the
    ones SQLite makes for a `UNIQUE` constraint or a `PRIMARY KEY`) are **not reported** —
    otherwise `users`, whose `username` is `unique=True` and which declares no explicit
    `Index(...)` at all, reports an extra index forever on a correct database
    (`context.md` D1);
  - the type text it reports is put through the same normalisation the declared reader
    uses, so neither side needs to know about the other.
- **A declared-shape reader** — takes a registry `Table` object and answers with the same
  shape value. It **touches no database**. Each column's type is compiled **through the
  SQLite dialect** (so `BigInteger().with_variant(Integer(), "sqlite")` yields `INTEGER`
  and the non-native `Enum` yields its `VARCHAR(n)` form), and nullability comes from the
  column's own declaration. Indexes come from the `Table`'s declared `Index` objects only —
  a `unique=True` column is a constraint, not an index, matching what the live reader
  reports.
- **The normalisation the two share** — upper-case and collapse whitespace before a type
  text is stored in a shape value, so `text` / `TEXT` and `VARCHAR(50)` / `VARCHAR (50)`
  are never differences.

## Definition of done

1. `[test]` The status value set has **exactly three** members — in sync, missing, drifted
   — and no member named or meaning `seed-missing`. (US-017.AC-1; `context.md` D2)
2. `[test]` The live reader returns a table's columns with their name, normalised type text
   and NOT NULL flag, for a table created from a registry `Table` on a real SQLite file.
   (UC-014; `context.md` D1)
3. `[test]` The declared reader returns the **same** column shapes for the **same**
   `Table` object, with no database involved — so a table freshly created from the registry
   compares identical on both sides, field for field. (UC-014; `context.md` D1)
4. `[test]` A column declared `BigInteger().with_variant(Integer(), "sqlite")` reports the
   same normalised type text from both readers, and so does a non-native `Enum` column and
   a `Text` column. (`context.md` D1 — **no product id**)
5. `[test]` Type text differing only in case or in internal whitespace is **not** a
   difference: both readers normalise before reporting. (`context.md` D1 — **no product
   id**)
6. `[test]` The live reader reports **no index** for a table whose only uniqueness comes
   from a `unique=True` column or a primary key, while reporting an explicitly declared
   `Index(...)`; the declared reader agrees on both counts. (`context.md` D1 — **no product
   id**)
7. `[test]` An index shape's identity is its **column list and uniqueness**, not its name:
   two indexes over the same columns with the same uniqueness and different names are the
   same shape. (`context.md` D1 — **no product id**)
8. `[test]` The live reader reports a table that does not exist as **absent** and raises
   nothing. (US-017.AC-1, UC-014)
9. `[test]` The live reader **writes nothing and opens no transaction**: running it against
   a populated database leaves `sqlite_master` and every row untouched, and it can be
   called on a connection with no `begin()` around it. (`backend-structure.md`, the
   drift/sync split — **no product id**)
10. `[test]` The per-table report value carries **no row count, no byte size and no
    timestamp**, and the module issues **no `COUNT(*)` of any kind**. (R5, UC-066)
11. `[test]` `db/drift.py` imports neither `app.db.sync` nor `app.db.schema`: the registry
    and every `Table` reach it as arguments. (`backend-structure.md`, "the code path that
    only reports cannot write"; `context.md`'s cross-cutting constraints — **no product
    id**)
12. `[manual/live]` The module declares no `kind` discriminator for views or virtual tables
    and contains no branch for either — `context.md` D3. Verifier confirms by reading it.
13. `[manual/live]` `mypy app`, `ruff check .` and `pytest` all pass from `backend/`.
