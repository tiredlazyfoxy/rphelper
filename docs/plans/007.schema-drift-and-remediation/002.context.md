# Step 002 — step-specific context

Feature-wide facts are in `context.md` (**D1** the compared set, **D2** the three statuses,
**D3** the `metadata.tables`-only walk and the recorded view / virtual-table gap, **D10**
the health roll-up's mapping, precedence and cost). Only what is narrow to this step is
below.

## What `probe_health` does today, and the shape of the change

`backend/app/services/health.py` holds a frozen `HealthProbeResult` (`status`,
`configured`, `schema`) and `probe_health(connection, registry)`. Today `schema` is
computed as a **pure presence test** — in effect `"ok" if declared <= present else
"missing"`, where `present` comes from a cheap `sqlite_master` read — and there is **no
`"drift"` branch at all**, even though `backend/app/models/health.py`'s `SchemaState`
already declares `"drift"` as a legal value.

The module's own docstring says feature `007` adds that branch and that this is **a
widening of this function, not a rewrite of it**. Take it literally:

- the signature does not change;
- the parameters do not change — in particular **the registry keeps arriving as a
  parameter** and `app.db.schema` is imported nowhere in this module;
- `HealthProbeResult`'s fields do not change;
- the `status` precedence does not change;
- `backend/app/routers/health.py` is **not in this step's Source files** and is not edited:
  it already imports `metadata` and passes it in.

The presence test is **replaced by**, not layered on top of, the report's answer — the
report already reports a declared table as *missing*, so keeping the old `sqlite_master`
read alongside it would be two sources of truth for the same word.

## Borrowed interfaces, by module path and role

- **`backend/app/db/drift.py`** (step `001`) — the two shape readers and every value type.
  This step adds to the same module; it does not create a second one.
- **`backend/app/models/health.py`** (`001`) — `SchemaState`, which already carries
  `"drift"`. **Not edited.**
- **`backend/app/routers/health.py`** (`001`) — the caller. **Not edited**, and the source
  of the convention that a router imports the registry and passes it down.
- **`backend/tests/conftest.py`** (`001`) — `db_settings` / `db_engine`, real `.sqlite`
  files. Router-level health tests build their own `TestClient(create_app())` **not as a
  context manager** and override `get_settings` through `app.dependency_overrides`.

## `backend/tests/test_health.py` already exists

It is feature `001`'s and it holds the existing presence-test coverage. This step's test
work **extends** it rather than replacing it: DoD-11 exists precisely to pin that the
`missing` behaviour for an existing input is unchanged by the widening. A test that was
passing before this step and fails after it is a regression, not an update.

## Comparison rules that are easy to get subtly wrong

- **`missing` and `extra` are set differences over names; `changed` is over the
  intersection.** A column that is in neither side's set cannot be changed, and a column
  in exactly one side is missing or extra, never changed. Getting this wrong produces a
  report that names the same column twice.
- **An absent live shape short-circuits everything.** A *missing* table reports status
  missing with **empty** difference lists — not "every declared column is missing". The
  page renders a missing row as one fact, and filling the lists would make it read as nine.
- **Status is derived from the difference lists, never set independently.** A table with
  empty lists is in sync by construction; there is no path that reports *drifted* with
  nothing to show for it, and that invariant is what makes the frontend's
  "offer Sync only when drifted" rule safe.
- **Declaration order, not alphabetical.** `metadata.tables` preserves declaration order in
  `metadata.sorted_tables`/insertion order; the report follows the registry so the page's
  rows match the file a reader is comparing against. Do not sort.

## The health cost, already weighed

The probe now runs the PRAGMA walk rather than one `sqlite_master` read, on an endpoint
that is **also the container healthcheck target** and is therefore called on a timer
(`deployment.md`, `backend-structure.md`). `context.md` D10 records that this is accepted
over a handful of tables on a WAL file, and records the flip condition. **Do not add a
cache, a TTL or a module-level memo to "fix" it** — a cached health probe is a health probe
that cannot fail, which is the thing `backend-structure.md` says the endpoint exists not to
be.

## Gotchas

- **`/api/health` is unauthenticated.** DoD-16 is not decoration: the roll-up must stay one
  word. A future "which tables are drifted" field on this endpoint would put the schema of
  a private instance on an open route, and the detailed report is admin-only by design.
- **The walk must not open a transaction**, because `get_connection` gives callers a
  connection with none and the health path is a pure read. A stray `with conn.begin():`
  here would also silently swallow the pragma behaviour step `003` depends on.
- **Do not let the comparison reach for the real registry** for a default. It takes what it
  is given; every test in this step builds its own `MetaData`.
