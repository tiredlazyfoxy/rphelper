# Step 004 — step-specific context

Feature-wide facts are in `context.md`: the **Wire contract**, **D4** (switch not
persisted), **D10** (server order), **D11** (section-owned state; the upsert rule is 009
D11's), **D12** (the two row-action sentences), the **No context, no methods** and **Ids
are strings** constraints, and frontend **Test conventions**. 009's `004.context.md`
holds the shared-client facts (`apiGet` / `apiPost` / `apiPatch`, path must start
`/api/`, query string is part of the path, `ApiError` branch on `.code`, abort rejects
unwrapped, no reviver), the MobX precedent (`src/admin/usersPageState.ts`) and **"The
insert position, concretely"** (string comparison of fixed-width `created_at`; insert
before the first row whose `created_at` is less than the new one's, else at the end).
They apply here unchanged and are not restated. Only what is narrow to this step is below.

## Why a separate apply rule, not a reuse of `applyCharacter`

`charactersState.ts`'s `applyCharacter` is typed to `CharactersState` and `Character`.
Generalising it would edit a 009 file (out of scope). The rule is a few lines, and two
copies typed to their own subjects are cheaper than a shared generic module that neither
feature owns. A later refactor may merge them.

## Why `pendingId` and not a per-row map

Only one row action can be in flight from one menu at a time in practice, and the
section's UI disables just that row's menu trigger while it runs (`006`). A single field
is enough and keeps the class flat. A second action started on another row while one is
pending overwrites `pendingId`; the first one's completion then resets it to `null`. That
is accepted for an interim section, since both mutations still apply the server's rows.

## Why the row actions live here and the create/edit submit does not

Archive and restore are list mutations with no form: their only state is the in-flight
row and the error, both of which belong to the list. Create and edit belong to the modal's
draft (`005`), which hands the returned row back to the section through a callback.

## Placement

Both modules live under `src/app/` (single-entry state: `frontend-structure.md` "Where a
store's file lives"). `setupsApi.ts` is separate from the state because `005`'s draft
uses the create/update calls without the list.
