# Step 006 — step-specific context

Feature-wide facts are in `context.md`: **D1** (placement; absent in new mode and
non-ready states), **D2** (labelled "New setup", modal flags in `useState`, apply then
close), **D4** (the switch's label and reload), **D5** (archived character allowed),
**D11** (section-owned state, keyed by character id), **D12** (inline feedback, no
notification), **D13** (table, overflow menu, empty line), the **Build prerequisite**
table, and frontend **Test conventions** (the `vi.mock` editor stub, Mantine portals,
scoping to the "Setups" region). Only what is narrow to this step is below.

## Borrowed interfaces

- `app/setupsSectionState.ts` (`004`): `SetupsSectionState`, `loadSetups`,
  `setShowArchived`, `applySetup`, `archiveRow`, `restoreRow`. The component holds **no**
  business logic beyond calling these and rendering their fields.
- `app/setupsApi.ts` (`004`): `Setup`, `isSetupArchived`.
- `app/SetupModal.tsx` (`005`): props `characterId`, `setup`, `onClose`, `onSaved`.
- `shared/IconButton.tsx`: the `IconDots` trigger (`sizeVariant` "inline" suits a table
  row). It is the row's only icon-only control (`ui-conventions.md` "Tables").
- Mantine: `Title`, `Group`, `Stack`, `Button` (`leftSection`), `Switch`, `Table`,
  `Menu` / `Menu.Target` / `Menu.Dropdown` / `Menu.Item` (`leftSection` icons, "inline"
  size `size={16} stroke={1.5}`), `Badge`, `Alert`, `Loader`, `Text` (`c="dimmed"`).

## The region and its heading

A `section` element with `aria-labelledby` pointing at the heading's id gives role
`region` with the name "Setups". 009's screen renders "Sessions" as a heading. Use the
same `Title` order for "Setups" so the two read as siblings.

## The reload effect

Same pattern as 009 `008.context.md` "The reload effect": depend on `showArchived` read
during render, abort the previous controller in the cleanup, and do **not** also call
`loadSetups` from the switch's handler, or the toggle would issue two requests.

## The menu trigger inside `Menu.Target`

`Menu.Target` needs a child that forwards its ref and click props. If the shared
`IconButton` does not forward refs, wrap it in an element that does (a `span` or `div`)
inside `Menu.Target`. Do not replace it with a bare `ActionIcon` (`ui-conventions.md`
forbids it). The trigger's accessible name stays "Actions for <name>".

## The hook in `CharacterScreen.tsx`

One element added in the existing-mode "ready" branch:
`SetupsSection` with `characterId` set to the loaded character's id and `key` set to the
same id. `CharacterRoute` already keys the whole screen by id (009 `007`), so the explicit
key is belt-and-braces. It keeps D11's reset true if `CharacterScreen` is ever rendered
unkeyed. `characterScreenState.ts` is read, not edited.

## 009 test amendments this step owns

- `tests/app/CharacterScreen.test.tsx`: every existing-mode test whose character load
  succeeds now also triggers `GET /api/characters/<id>/setups`. A `fetch` stub that
  answers every URL with the character body would hand the section a payload with no
  `setups` key, so route the stub by URL. A 009 assertion that checks "exactly one
  request" or the last request's URL must exclude the setups listing. A query for the
  screen's own "Archived" badge must not also match a setup row's badge. With an empty
  setups listing there is none, so the simplest fix is to answer `{ "setups": [] }` in
  009's tests. DoD-10..12 are added here.
- `tests/app/App.test.tsx`: 009 `008` DoD-8..10 render the character screen through
  `App`. Their stubs answer `GET /api/characters` (the tree) and the character. They must
  also answer the setups listing. 009 `008` DoD-8 asserts no second `GET /api/characters`
  after a create. The setups listing is a different URL and does not violate it, but a
  stub or counter keyed on the prefix `/api/characters` would count it, so key on the exact
  path.
- `tests/app/AppBoot.test.tsx` and `tests/entries.test.tsx` render `App` at `/`, where no
  character screen mounts. They are unaffected and are not in this step's scope.

## What is deliberately absent

No setup route, no setup in the tree, no description preview in the row, no confirm, no
"create your first setup" prompt, no session picker (`011`).
