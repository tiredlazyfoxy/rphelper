# Step 005 — step-specific context

Feature-wide facts are in `context.md`: **D2** (the modal's fields, labels, titles,
conditional mount, edit sends both fields, Save needs a change), **D8** (name stripped by
the server; description never stripped), **D12** (the two modal sentences, no
notification), the **Never optimistic** and **No context, no methods** constraints, and
frontend **Test conventions** (the `vi.mock` `MarkdownEditor` stub; Mantine portals).
Only what is narrow to this step is below.

## Precedent

`src/admin/createUserDraft.ts` + `src/admin/CreateUserModal.tsx`: a draft data class with
free `canSubmit` / `submitX(draft, …, onSaved, signal?)`, and a modal component mounted
only while open that builds its draft with `useState`. Follow their shape.

**Deviation from the full draft convention, deliberately small.** `ui-conventions.md`'s
draft carries `serverErrors` keyed by field plus `clientErrors` / `errors`. Here one
`error` string and `canSubmit` suffice, for the reasons 009 gives for its screen state
(009 `006.context.md`, "Why the error is a fixed text per action"): the only field that
can fail validation is the name, the client already guards it, and a 422 carries no useful
prose. The general-key rule ("anything unmappable renders above the form") is what the
`Alert` is.

## The setters

`setDraftName` / `setDraftDescription` exist so `SetupModal` writes through MobX actions
without `runInAction` in the component. They are part of this step's module, so no
cross-step workaround is needed (contrast 009 `007.context.md`, "Draft binding").

## `onSaved` and closing

The modal does **not** close itself on success. `submitSetup` calls `onSaved(row)`, and
the parent (`006`) applies the row and unmounts the modal. That keeps "close" in one place
(the parent's `useState`) and lets the parent decide ordering: apply, then close.

## Mantine specifics

- `Modal` with `opened` true for the component's whole lifetime. The parent mounts and
  unmounts it, so there is no closed-but-mounted state. Its `title` gives the dialog its
  accessible name ("New setup" / "Edit setup").
- The submit button's left-section icon is the "main" size (`size={18} stroke={1.5}`).
  It is labelled, so `IconButton` does not apply.
- In jsdom, Mantine's modal transition can delay content. Use `findByRole("dialog", {
  name: … })` for the first assertion. `tests/setup.ts` already polyfills what Mantine
  needs.

## Tests and the editor

Both tests may `vi.mock("…/shared/MarkdownEditor")` with 009's sanctioned textarea stub,
so typing into "Description" is a plain `user-event` type. The draft test needs no render.
