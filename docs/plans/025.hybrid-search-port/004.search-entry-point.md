# Step 004 — `search/hybrid.py`: the `search` entry point

## Goal

Add the port's single entry point: dispatch on the scope variant to its fixed arms, fuse
the rankings by RRF, cut to the caller's limit, and hydrate each hit into the D3 shape
(`context.md` U1–U3, D1–D7).

## Source files

backend/app/services/search/hybrid.py

## Test files

backend/tests/test_search_hybrid.py

## Interface intent

**`app/services/search/hybrid.py`**

- **`search`** — takes a connection, a `SearchScope` (step `001`), the raw query text and a
  limit; keyword-only `client_factory` and `timeout_seconds` (defaults as in step `003`).
  Returns a list of at most `limit` `SearchHit` values, highest fused score first, ties by
  ascending id. Behaviour:
  1. D2 early exits (`limit <= 0`, blank query → `[]`, nothing opened or queried);
  2. builds the scope's candidate select once (step `002`);
  3. runs the variant's arms (U1 table): memo → vector over `memo_vec` and lexical over
     `memo_fts`; session → vector over `session_vec` only; entry → lexical over
     `message_fts` only. The lexical arm uses `build_fts_query`'s expression (none →
     that arm contributes nothing). The vector arm's errors propagate (U2);
  4. fuses the arms' id rankings with `rrf_fuse` and keeps the first `limit`;
  5. hydrates the kept ids with **one owner-scoped read per kind** (D6): memo → `scope`,
     `scope_id`, and `body` for vector-only hits; entry → `session_id` from
     `settled_entries`; session → nothing;
  6. builds each `SearchHit` per D3 / D4: memo snippet is the lexical snippet when the
     lexical arm found it, else the leading extract of its body.
  Reads follow D7's posture.
- Private helpers (per-kind hydration, arm dispatch) are the coder's choice.

## Definition of done

1. `[test]` **Memo hybrid.** Several of one user's memos with vectors and FTS rows: the
   result's ids, order and scores equal `rrf_fuse` (computed by the test from the
   expected vector ranking — fake vectors — and the expected lexical membership) cut to
   `limit`; every hit has kind `"memo"`, its `scope` / `scope_id`, `session_id` none, and a
   non-empty snippet. (D1, D3)
2. `[test]` **Lexical rescues the exact token.** With more memos than `ARM_DEPTH`, one memo
   whose body holds a rare token but whose vector is not among the vector arm's top
   `ARM_DEPTH` is present in the results for a query of that token, with score `1/(60+1)`.
   (`search-and-retrieval.md` "Why hybrid")
3. `[test]` **Memo snippet shape.** A hit found lexically carries a snippet containing the
   matched token; a hit found only by the vector arm carries exactly `leading_extract` of
   its body (computed by the test from D4's rule). No hit carries a title or any field
   beyond D3's. (D4, US-119)
4. `[test]` **Memo level is scope only.** Hits for a user-level and a session-level memo
   carry `scope` `"user"` / `"session"` and the stored `scope_id`, with no level name. (U3)
5. `[test]` **Session vector-only.** A session-scope search returns kind `"session"` hits
   ordered by the expected vector ranking with scores `1/(60+rank)`, snippet none, memo
   level none, `session_id` none; no FTS table is queried — it succeeds with neither FTS
   table present. (U1, D3)
6. `[test]` **Entry lexical-only.** An entry-scope search returns kind `"entry"` hits for
   the record rows containing the token, each with its message id, its `session_id` and a
   snippet containing the token; with **no designated model**, the fake factory is called
   zero times and the search still succeeds. (U1, U2)
7. `[test]` **Owner isolation (absence).** For each variant, another user's row that
   matches the query on every arm the variant runs never appears. (D6, UC-065, US-085)
8. `[test]` **Extra predicate honoured.** A memo-scope predicate selecting enabled,
   not-forced memos excludes a disabled memo and a forced memo that both match on both
   arms; a session-scope predicate on `character_id` and `id != current` excludes the other
   character's session and the current one. (U1)
9. `[test]` **Entry corpus boundary (absence).** A zone row and a buried row whose text
   contains the token never appear in entry results. (R11, US-115, UC-038)
10. `[test]` **No model, no degrade.** With no designated model, memo- and session-scope
    searches raise `NoEmbeddingModelError` — the memo search raises even though `memo_fts`
    holds a match. A fake scripted to raise `LlmUnreachableError` makes a memo search raise
    that error. (U2, R4)
11. `[test]` **Early exits.** `limit` 0, a negative limit, `""` and a whitespace-only query
    each return `[]` for every variant, with the fake factory called zero times. (D2)
12. `[test]` **Unusable lexical text.** A memo search whose query is only punctuation (e.g.
    `"""`) returns the vector arm's results alone (scores `1/(60+rank)`) and raises
    nothing. (`001.context.md`, D1)
13. `[test]` **Absent tables.** Memo search with a designated model and neither `memo_fts`
    nor `memo_vec` present returns `[]`; with only `memo_fts` present it returns the lexical
    matches alone, snippets from FTS. Entry search with `message_fts` absent returns `[]`.
    (U2)
14. `[test]` `limit` larger than the fused set returns the whole fused set; a smaller
    `limit` returns its prefix. (D1)
15. `[test]` No module under `app/services/search/` imports `fastapi`, and no module
    other than `vector.py` imports `sqlite_vec`. (`context.md` constraints)
