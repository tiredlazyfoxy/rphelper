## FTS query sanitising — exact rules

User text must never raise an FTS5 syntax error, whatever it contains.

1. Split the raw text on whitespace runs (Python `str.split()` semantics).
2. In each token, remove every `"` character.
3. Drop tokens that are empty after step 2.
4. Wrap each remaining token in double quotes, making it an FTS5 string (phrase). Inside a
   string FTS5 treats `AND`, `OR`, `NOT`, `NEAR`, `*`, `^`, `:`, `(`, `)`, `-` as plain
   text, which is why quoting is sufficient once `"` is removed.
5. Join the phrases with ` OR ` (one space either side).
6. No tokens left → return none. The caller (step `004` via the lexical arm) then skips the
   lexical arm.

A phrase whose text tokenises to nothing under `unicode61` (e.g. `"---"`) is legal FTS5 and
matches nothing; it is kept, not filtered. Token case is preserved; the default tokenizer
case-folds at match time.

OR-join is a deliberate recall choice: BM25 ranks rows matching more tokens higher.
