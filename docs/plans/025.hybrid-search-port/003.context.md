# Step 003 — step-specific context

Feature-wide facts are in `context.md`: the 024 prerequisite names, U2 (error propagation,
absent tables), D5 (filters first), D6 (owner scope), and the Test conventions. Only what
is narrow to this step is below.

## The one permitted query form — form (a), exact scan

Per vec table `V` with id column `C` (`memo_id` for `memo_vec`, `session_id` for
`session_vec`):

```
SELECT C
FROM V
WHERE C IN (<candidate_ids subquery>)
ORDER BY vec_distance_l2(embedding, :query_vector), C
LIMIT :depth
```

- `:query_vector` is the embedded query serialised with `sqlite_vec.serialize_float32`
  (024 D4). Importing `sqlite_vec` in `vector.py` is allowed; the extension is already
  loaded on every connection by `db/engine.py`.
- **Forbidden** (024 D3): any `embedding MATCH ? AND k = ? AND C IN (...)` — vec0 KNN with
  a pushed-down id constraint silently drops true candidates for ids above ~2^50. The scan
  above uses no `MATCH`, so the KNN path is never entered. The alternative 024 also
  permits (over-fetching KNN, then a JOIN or `+C IN`) is **not** used in 025: candidate sets
  are hundreds of rows, the scan is exact, and it has no recall parameter.
- L2 rather than cosine follows 024's recorded form; only the **rank** reaches fusion, so
  the metric's scale is irrelevant to RRF. Recorded as conventional in `outcome.md`.
- The vec table is outside `schema.metadata`; build the statement with `text()` or a
  lightweight `table()` / `column()` construct, naming it through 024's constant.

## Dimension handling

- 024's `vector_table_dimension(connection, name)` returns the declared `FLOAT[n]` or none.
- `embed_texts` already raises `dimension_mismatch` when the **returned** vector length ≠
  `embedding_dim`; this step adds the **table vs designation** check before embedding, so
  `vec_distance_l2` is never called on vectors of different lengths (it would raise a raw
  SQLite error otherwise).
- `NoEmbeddingModelError` has no default message (024 `001.context.md`); pass a fixed one,
  e.g. "The embedding index was built for a different dimension; an administrator must
  rebuild it." `errors.py` is not edited.

## Ordering rationale

Model first, table second: with no designated model the vector arm **always** raises, even
on an instance whose vec tables do not exist yet. A search that silently returned
lexical-only results there would be the degrade U2 rules out. With a model but no table,
there is nothing to compare against, so no provider call is spent.

## Test shape

- DoD-1's and DoD-2's expected orders are computed in the test from the fake's pure
  `(text, dim)` function and a plain-Python L2 distance — float32-exact by 024's fake
  contract — with ties broken by ascending id.
- For DoD-2, use enough rows (≥ 200 candidates, ≥ 200 non-candidates) with ids above 2^60;
  024 measured the defect in 18–36 % of queries at realistic ids, so run several distinct
  query texts in the same test.
