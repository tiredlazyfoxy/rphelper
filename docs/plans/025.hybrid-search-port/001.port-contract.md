# Step 001 — `search/ports.py`: the port's types and its pure helpers

## Goal

Create the `services/search` package and its contract module: the three scope variants,
the hit value, the fusion function, the FTS query sanitiser, the leading extract and the
constants (`context.md` U1, U3, D1, D3, D4). Pure Python — no connection, no SQL execution.

## Source files

backend/app/services/search/__init__.py
backend/app/services/search/ports.py

## Test files

backend/tests/test_search_ports.py

## Interface intent

**`app/services/search/__init__.py`** — empty package marker. Re-exports nothing.

**`app/services/search/ports.py`**

- **Constants** `RRF_K` (60), `ARM_DEPTH` (50), `SNIPPET_CHARS` (160) — D1.
- **Hit kind** — a closed set of the three values `"memo"`, `"session"`, `"entry"`.
- **Extra-predicate builder type** — a callable taking the base relation (a SQLAlchemy
  FROM object) and returning a boolean SQL clause over its columns (U1).
- **`MemoSearchScope`**, **`SessionSearchScope`**, **`EntrySearchScope`** — frozen values.
  Each holds a required `user_id` (no default) and an optional extra-predicate builder
  (default none). Names are suggestions; the skeleton freezes them, avoiding a clash with
  `models/memos.py`'s `MemoScope`.
- **`SearchScope`** — the union of the three variants; the type `search` accepts.
- **`SearchHit`** — a frozen value with the fields of `context.md` D3: kind, id, fused
  score (float), snippet (text or none), memo level scope (one of the memo scope literals,
  or none), memo level scope id (or none), session id (or none).
- **`rrf_fuse`** — takes a sequence of rankings (each an ordered sequence of distinct
  integer ids, best first) and `k` (default `RRF_K`). Returns a list of `(id, score)`
  pairs covering every id that appears in any ranking, ordered by score descending, then
  id ascending. Score per D1. An empty input, or only empty rankings, returns an empty list.
- **`build_fts_query`** — takes the user's raw query text. Returns an FTS5 MATCH
  expression that can never raise an FTS5 syntax error, or none when the text has no
  usable token (rules in `001.context.md`).
- **`leading_extract`** — takes a body text. Returns the D4 leading extract.

## Definition of done

1. `[test]` Each scope variant constructed without `user_id` raises `TypeError`; each
   constructed with only `user_id` has no extra predicate; each is immutable (assigning a
   field raises). (U1)
2. `[test]` `rrf_fuse` over two rankings `[a, b, c]` and `[c, d]` returns exactly
   `a: 1/61`, `b: 1/62`, `c: 1/63 + 1/61`, `d: 1/62`, ordered `c, a, then b and d` with
   `b` / `d` tie-broken by ascending id. Scores compare equal to the formula within float
   tolerance. (D1)
3. `[test]` `rrf_fuse` over a single ranking returns its ids in the same order with
   scores `1/(60 + rank)`; with an explicit `k`, the formula uses that `k`; with no
   rankings or only empty rankings it returns `[]`. (D1)
4. `[test]` `rrf_fuse` breaks equal scores by ascending id regardless of input order. (D1)
5. `[test]` `build_fts_query` returns none for `""`, whitespace-only text, and text made
   only of `"` characters and whitespace. (`001.context.md`)
6. `[test]` `build_fts_query("Kaelith inn")` returns `"Kaelith" OR "inn"` exactly; a token
   containing `"` has every `"` removed before quoting; runs of whitespace (including
   newlines and tabs) separate tokens and produce no empty phrase. (`001.context.md`)
7. `[test]` For each hostile input — `AND`, `OR (`, `NEAR(a b)`, `col:term`, `a*`, `-x`,
   `^start`, `"unbalanced`, `)(`, `*`, `---` — `build_fts_query`'s result (when not none)
   used as `MATCH` against a real `fts5` table on a SQLite connection raises no error. The
   test creates its own throwaway FTS5 table; the port does not. (`001.context.md`)
8. `[test]` `leading_extract`: a body of `SNIPPET_CHARS` characters or fewer is returned
   with whitespace runs collapsed to one space and ends stripped; a longer body returns its
   first `SNIPPET_CHARS` collapsed characters followed by `…`, total length
   `SNIPPET_CHARS + 1`. (D4)
9. `[test]` `RRF_K == 60`, `ARM_DEPTH == 50`, `SNIPPET_CHARS == 160`. (D1)
10. `[test]` `ports.py` imports no `fastapi` and no `sqlite_vec`, and has no import of
    `app.db.engine`. (Pure module.)
