# Step 004 — step-specific context

Feature-wide facts are in `context.md`: U1 (variant → arms table), U2 (propagation),
U3 / D3 / D4 (hit shape and snippets), D1 (fusion), D2 (early exits), D6 (owner scope),
D7 (read posture), and the Test conventions. Only what is narrow to this step is below.

## Where `search` lives

`search` is in `hybrid.py`, not `ports.py`. `ports.py` is the contract (types, pure
helpers) that `candidates.py`, `lexical.py`, `vector.py` and `hybrid.py` all import;
putting `search` there would make the contract import its own implementation and create
an import cycle. Callers (`026`–`029`) import the types from `ports.py` and `search` from
`hybrid.py`. Swapping the backing store touches `hybrid.py` and the two arm modules, never
a caller. `outcome.md` records this for `backend-structure.md`.

## Hydration reads

- Memo: `SELECT id, scope, scope_id, body FROM memos WHERE user_id = :u AND id IN (:kept)`.
  `body` is only needed for vector-only hits; reading it for all kept ids in one statement
  is fine.
- Entry: `SELECT id, session_id FROM <settled_entries subquery> WHERE user_id = :u AND id
  IN (:kept)` (R11).
- Session: no read; a session hit is its id and score.
- A kept id missing from its hydration read (a row deleted between the arm read and the
  hydration read, impossible inside one read window) is dropped, not raised.
- Snippets for lexical hits come from the lexical arm's `LexicalMatch` values (step
  `002`); keep them by id rather than re-querying FTS.

## Arm order inside a memo search

Run the vector arm first, so a missing model raises before any FTS work. Either order
yields the same result; this one makes DoD-10's "raises even though `memo_fts` holds a
match" the cheapest path.

## Test shape

- `test_search_hybrid.py` is the end-to-end file: real `metadata.create_all`, 024's ensure
  functions and `write_vector`, the fake factory, raw-inserted rows with ids above 2^60 and
  two users.
- Expected fused orders and scores come from D1's formula applied by the test to rankings
  the test derives itself (vector order from the fake's pure function and plain-Python L2;
  lexical membership from which bodies contain the token; for exact lexical order use
  bodies where BM25's order is unambiguous, or assert on membership and the vector-derived
  part only).
- DoD-2 needs more than 50 memos; give the target memo a body whose fake vector is far from
  the query's, verified in the test by computing its rank from the fake's pure function.
- DoD-15 inspects module sources / imports for the six files of `context.md`
  "Files this feature touches".
