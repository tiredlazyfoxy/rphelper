# Step 002 — rename-route

## Goal

Add `PATCH /api/sessions/{session_id}`. It renames an owned session and accepts `name` as its only key. Register the route and the `sessions.name` content carrier with the privacy audit.

## Interface intent

- **Rename request model** (`models/sessions.py`) — has exactly one field, `name`. The field is required, and its value is a string or null. It is whitespace-trimmed, and blank becomes null (DEC-034-1). Unknown keys are refused (DEC-034-2). There is no length cap (DEC-034-3).
- **`rename_session`** (`services/sessions.py`) — takes the connection, the owner's `user_id`, the session id and the new name (string or None). In one transaction it:
  - requires the owned session (archived sessions are allowed);
  - writes the normalised name and a fresh `updated_at`, and never `last_used_at`;
  - returns the re-read `RpSession`.

  If the session is missing or foreign, it raises the existing `session_not_found`. It applies the same trim / blank-to-None normalisation itself (DEC-034-1). It performs no embedding and touches no search table (DEC-034-5).
- **Rename handler** (`routers/sessions.py`) — `PATCH /api/sessions/{session_id}`, status 200. It takes the path id as the existing snowflake input type, plus `current_user` and `connection`. It answers with `SessionResponse`. The module docstring's "No PATCH" sentence is replaced with a sentence describing the narrow `PATCH`.
- **Privacy audit support** (test-side) — `ENUMERATED_ROUTES` gains `PATCH /api/sessions/{}` as owner / `session_not_found`. `_CARRIER_ROWS` gains a `sessions.name` sentinel carrier, and the world builder seeds it (DEC-034-4).

## Definition of done

1. DoD-1 [test] — `PATCH` with `{"name": "  The Docks  "}` answers 200 with the session shape and `name` `"The Docks"`, and later reads return that name. (US-150.AC-2)
2. DoD-2 [test] — `PATCH` with `name` as `""`, as whitespace only, or as `null` answers 200 with `name` null, and later reads return null. (US-150.AC-3)
3. DoD-3 [test] — A rename advances `updated_at`. It leaves `last_used_at` byte-identical, and it does not change the session's position in `GET /api/sessions` or `GET /api/characters/{id}/sessions`. (US-150.AC-4; DEC-arch-session-names-6)
4. DoD-4 [test] — A body carrying any key other than `name` answers 422 and leaves the row unchanged. This holds whether the key comes alone or together with `name`, for example `model`, `system_prompt` or `archived_at`. (DEC-arch-session-names-2; DEC-034-2)
5. DoD-5 [test] — A body without `name` (`{}`), a non-object body, and a non-string, non-null `name` (a number, a list or a boolean) each answer 422. (DEC-034-1)
6. DoD-6 [test] — Renaming another user's session, or a nonexistent id, answers 404 `session_not_found`, and the foreign row is unchanged. A malformed id answers 422. (US-029.AC-1; R5 refusal identity)
7. DoD-7 [test] — An archived session can be renamed (200), and it stays archived.
8. DoD-8 [test] — Two sessions can hold the same name. (UC-089 exception flows)
9. DoD-9 [test] — A rename succeeds with no embedding model designated, and it makes no embedding call. (DEC-034-5)
10. DoD-10 [test] — `rename_session` called directly stores NULL for a whitespace-only name and stores a trimmed value otherwise. (DEC-034-1)
11. DoD-11 [test] — The privacy route enumeration lists `PATCH /api/sessions/{}` as an owner route refusing with `session_not_found`. The two-way equality with the app's routes holds, and an anonymous call answers 401.
12. DoD-12 [test] — The `sessions.name` sentinel never reaches another user's read surfaces, exports or the log sinks. This includes the rename request's own log records. (deployment.md § Logging; DEC-034-4)
