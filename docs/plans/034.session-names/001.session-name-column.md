# Step 001 — session-name-column

## Goal

Add the nullable `sessions.name` column. Carry `name` on every session read. Move the transfer schema version to 2 and add the one named version-1 upgrade, so existing exports still import. The version bump ships with the column because `transfer.md` ties every bump to a registry shape change.

## Interface intent

- **`sessions` table (registry)** — gains `name`: nullable text, no server default, no index. The table's doc comment changes from "no title" to explain `name`, where NULL means never renamed.
- **`RpSession` (service dataclass)** — gains `name`, the stored value or None. Every service read that returns a session (list, character list, get, archive, restore, start, start-seeded) fills it.
- **The session select** — selects `sessions.name` next to the joined setup name, which must stay distinguishable from it.
- **`SessionResponse`** — gains `name` (string or null). The "eight keys" docstrings become nine. `StartedSessionResponse` inherits it. The router's response mapping copies it.
- **`SCHEMA_VERSION`** — becomes 2.
- **Envelope validation** — accepts `schema_version` 1 or 2. It refuses everything else as `schema_mismatch` and exposes the file's version to the payload deserializer (DEC-034-7).
- **Payload deserialization** — for a version-1 file only, a `sessions` row may lack `name` and is imported with `name` NULL. Every other column-set rule is unchanged (DEC-034-7).
- **`errors.py`** — the schema-mismatch comment ("newer and older both refuse") is reworded to say that version 1 is upgraded.

## Definition of done

1. DoD-1 [test] — The registry's `sessions` table declares `name` as nullable text with no default. The schema tests' expected session column sets include it. (data-model.md § sessions; DEC-arch-session-names-1)
2. DoD-2 [test] — Every session payload carries `name` as null for a newly created session: `GET /api/sessions`, `GET /api/characters/{id}/sessions`, `GET /api/sessions/{id}`, archive, restore, `POST /api/characters/{id}/sessions` and the create-and-seed answer. (US-150.AC-1)
3. DoD-3 [test] — Starting a session either way needs no name. A `name` key sent in a start body is ignored, and the session is created with `name` null. (US-150.AC-6)
4. DoD-4 [test] — A session whose `name` is stored (written directly in test setup) returns that exact value on every read in DoD-2 and in `RpSession`.
5. DoD-5 [test] — `SCHEMA_VERSION` is 2. Every export granularity (session, character, user, database) emits `schema_version` 2, and every exported session row carries a `name` key holding the stored value or null.
6. DoD-6 [test] — A renamed session that is exported and re-imported keeps its name: session, character and user granularities through the roleplayer import, and the database replace. (US-150.AC-5)
7. DoD-7 [test] — A version-1 file whose session rows lack `name` imports successfully, and every imported session has `name` NULL. This holds for the session, user/character and database imports, and for the bootstrap import path. (DEC-arch-session-names-7)
8. DoD-8 [test] — In a version-1 file, a missing or extra column on any other table is still `malformed_payload`, and so is a session row that carries `name`. The `users`-row allowance is unchanged. (DEC-034-7)
9. DoD-9 [test] — In a version-2 file, a session row without `name` is `malformed_payload`.
10. DoD-10 [test] — `schema_version` 0, 3, a string, or a boolean is `schema_mismatch`.
