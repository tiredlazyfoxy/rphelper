# Step 003 — step-specific context

Feature-wide facts are in `context.md`; the decisions this step implements are D2 (409),
D6 (the guard is router-level and lives here), D9 (no cookie) and D16 (the `422`
backstop). None of that is repeated here.

## The route path is this plan's choice

`backend-structure.md` names `routers/bootstrap.py` and its `require_unconfigured`
dependency but **fixes no path**. The plan chooses the prefix `/api/bootstrap` and the one
route `POST /api/bootstrap/create`, so that `fast/003.bootstrap-from-export` has the
obvious sibling `POST /api/bootstrap/import` available under the same guarded router.
`outcome.md` asks the architect to record it.

The API client on the frontend requires every path to begin `/api/` (`002/004`), which this
satisfies without special-casing.

## Getting the generator out of application state

`001/006:33-35` has the app factory construct the snowflake generator and hold **that
single instance on application state**; `backend-structure.md`'s `app/ids.py` section makes
one instance per process a guarantee, not a convenience. `001` freezes no named dependency
for retrieving it, so:

- if the delivered `001` code exposes a dependency or accessor for it, use that;
- otherwise the router reads it from the application state reachable on the request, which
  is HTTP plumbing and therefore the router's business, and passes it into the service.

Either way the **service takes it as an argument** (step `002`, DoD-8) and nothing reaches
for a module global. The skeleton agent resolves which form the delivered code supports.

## Why the guard is a dependency on the router and not a line in the handler

`backend-structure.md:209-213`, verbatim on the reason: *"The check is a dependency rather
than a check inside each handler so that adding a bootstrap route cannot forget it."*
DoD-4 is the test that turns that sentence into a criterion — a second route registered on
the same router in the test, declaring nothing, must still be refused on a configured
instance. That test route is the test-coder's, lives only in the test, and is the reason
this step can claim the property for `fast/003` without building `fast/003`.

## The error needs no translation in the router

`001` registers **one** handler for the domain-error base class, so `already_configured`
reaches the client in the one wire shape with its own `409` without the router catching
anything. A `try`/`except` here, or an `HTTPException` raised by hand, would be a second
error path and is the defect to avoid.

## The `422` backstop, and what it is not

The request model's non-empty constraints produce FastAPI's own validation response, whose
body is **not** the `{"error": {...}}` envelope. That is accepted (`context.md` D16): the
form cannot submit an empty field, so this path is defensive. Consequence for the
frontend, held by step `005`: such a response decodes to `002`'s synthetic
`client_malformed_error` with status `422`, which is **not** the not-ready-yet condition
(that requires status ≥ 500) and therefore renders as an ordinary in-place form error.

**Do not invent a domain error code for empty credentials.** The error table in
`backend-structure.md` is the architect's, and this feature adds exactly one code to it.

## Gotcha — the response model and the id boundary

`app/models/ids.py` (`001/004`) provides the two annotated aliases, re-exported from
`app/models/__init__.py`. The response's id field uses the **outbound** one, so the
`int` in Python leaves as a decimal string. This is the single most forgettable rule in
the doc set (`backend-structure.md`'s own words), and this response is the feature's only
id on the wire.

## Gotcha — 201 and the absent `Location` header

The route answers **201** because it creates a resource. It deliberately adds **no
`Location` header**: there is no `GET /api/users/{id}` in existence, and FEAT-003 owns
account routes. Pointing at a route that does not exist is worse than omitting the header.

## Gotcha — the frontend does not read this response's body

Step `005` hands off to `/login` on success and reads nothing out of the response except
that it succeeded. The response model exists because `backend-structure.md` requires
routes to return pydantic models rather than bare dicts, and because a created resource
that reports nothing about itself is a poorer contract for `fast/003` and for manual
verification. Do not remove it on the grounds that no client reads it.
