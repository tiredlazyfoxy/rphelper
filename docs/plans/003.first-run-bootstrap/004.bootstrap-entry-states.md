# Step 004 — The `bootstrap` entry: the probe, the not-ready classification, and the rendered states

## Goal

Replace the `bootstrap` entry's placeholder route table with a real page that probes
`GET /api/health` and renders one of its states — the offer, the already-configured
refusal, or the not-ready-yet state that retries while the backend is still coming up.

## Interface intent

**`frontend/src/shared/notReady.ts`** — one exported **pure predicate** taking a thrown
value and answering whether it is the not-ready-yet condition (`context.md` D10): an
`ApiError` whose code is the transport-failure synthetic code, or whose code is the
malformed-body synthetic code **with a status of 500 or above**. Both code constants come
from `shared/apiError.ts` — this module defines no code string of its own. Anything else,
including a well-formed backend error envelope and an abort, is **not** the condition. It
navigates nothing, renders nothing and logs nothing.

**`frontend/src/bootstrap/bootstrapState.ts`** — the entry's store and its free functions,
following `002`'s D2 exactly (`context.md` D13).

- **A data class** holding observable fields only, `makeAutoObservable(this, {}, {
  autoBind: true })` in the constructor and **no methods and no computed getters**. Its
  fields carry: which phase the entry is in, and the message of a failure that is neither
  a refusal nor the not-ready condition. The five phases are **probing**, **offer**,
  **refusal**, **not-ready** and **failed**.
- **A pure derivation** taking the data object and answering which phase to render, so the
  component branches on one value rather than on a combination of flags.
- **An effectful probe function** taking the data object and an optional `AbortSignal`:
  it requests `GET /api/health` through `shared/api.ts`, reads **`configured` alone** out
  of the body (`context.md` D5 — never `status`, never `schema`), and `runInAction`s the
  resulting phase: offer when `configured` is false, refusal when it is true, not-ready
  when the thrown value satisfies the predicate above, failed otherwise with the error's
  message kept for rendering. It **early-returns on an aborted signal before writing**,
  and an abort rejection is never rendered as a failure.
- **A retry starter and its stopper** (`context.md` D11): while the phase is not-ready the
  probe re-runs on a **fixed 2000 ms interval**, uncapped, with no backoff; the stopper
  cancels the pending timer and any in-flight request and is what the component calls on
  unmount.

The module reads no id, parses nothing numeric, and holds **no draft and no credential** —
those are step `005`'s.

**`frontend/src/bootstrap/BootstrapPage.tsx`** — an `observer` component taking the store
**explicitly as a prop**, instantiated by nobody but `main.tsx`. It renders exactly one of:

- **probing** — a quiet in-place progress indication, and **neither** the offer nor the
  refusal;
- **the offer** — the unconfigured screen: a heading naming the instance as unconfigured,
  and the create-a-new-database option, presented as **one option of a list that will grow
  by one** (`fast/003`'s import). No import control, no disabled import control and no
  "coming soon" copy — room, not a stub. The create form itself arrives in step `005`;
- **the refusal** — UC-003: a statement that the instance is already configured and that
  bootstrap will not act, with **no create control rendered at all**, plus a **real anchor
  to `/login`** directing the person to sign in (US-003.AC-2). A cross-entry navigation is
  a document navigation, never a router `Link` (`frontend-structure.md`);
- **not-ready-yet** — a statement that the instance is still starting, worded as a wait
  rather than a fault (`deployment.md`: this is a deployment fact, not a bug), plus the
  visible manual retry control;
- **failed** — an in-place failure panel carrying the kept message and the same manual
  retry control, with **no automatic re-probe**.

It also carries the entry's **stable marker** so `002/006`'s per-entry test keeps holding
unchanged, calls the probe once on mount and the stopper on unmount, and **calls
`notifyFailure` nowhere** (`context.md` D12). It imports no stylesheet.

**`frontend/src/bootstrap/main.tsx`** — the placeholder route table is **replaced
wholesale**, as `002/006:43-47` anticipated. It keeps everything else about the module
exactly as `002` built it: it finds the mount element, creates the React root, renders
`shared/AppProviders` wrapping a `BrowserRouter` with **no `basename`**, and imports no
stylesheet. The route table becomes a catch-all rendering the page above with a store
created through `useState(() => new …State())` — never `useMemo` — in whatever component
owns it.

## Definition of done

1. `[test]` On mount the entry issues exactly **one** `GET /api/health` request and no
   other request — in particular **no `/api/me`** and no bootstrap POST.
2. `[test]` While that first probe is in flight the page renders **neither** the offer nor
   the refusal.
3. `[test]` `configured: false` renders the offer, and the offer names the create-a-new
   option. (UC-001)
4. `[test]` `configured: true` renders the refusal, and **no create control is rendered at
   all** in that state. (US-003.AC-1)
5. `[test]` The refusal renders a link to `/login` that is a real document navigation
   target — an anchor with that href, not a router link. (US-003.AC-2)
6. `[test]` The entry branches on `configured` alone: a body reporting
   `configured: false` with `status: "degraded"` and `schema: "missing"` — which is what a
   pre-bootstrap instance really answers (`context.md` D5) — still renders the **offer**,
   and a body reporting `configured: true` still renders the **refusal** whatever `status`
   says.
7. `[test]` The not-ready predicate answers **true** for the transport-failure code and
   for the malformed-body code at statuses 500, 502, 503 and 504; and **false** for the
   malformed-body code at 4xx statuses, for a well-formed backend error envelope such as
   `already_configured`, for an abort, and for a non-`ApiError` value.
8. `[test]` A probe failure satisfying the predicate renders the not-ready-yet state, and
   the entry **re-probes on a fixed 2000 ms interval** — a second request after one
   interval, a third after two — until a probe succeeds, after which the interval stops
   and the resolved state renders.
9. `[test]` The visible manual retry control re-probes immediately, in both the not-ready
   and the failed states.
10. `[test]` A probe failure **not** satisfying the predicate renders the failed state with
    the failure's own message, and **does not** start the interval.
11. `[test]` `notifyFailure` is called in **no** state of this entry, and Mantine's
    notification API is still imported by `shared/notifyFailure.ts` alone. Also, **the
    pure-data-contract scan clause is deleted**: `002/006` DoD-10's assertion that no
    `makeAutoObservable` and no page-store class exists under `frontend/src` is removed and
    **not replaced**, because this step creates the project's first store
    (`context.md` D14). **Every other clause of that scan is left intact** — the forbidden
    styling mechanisms and the single notification call site still assert.
12. `[test]` Unmounting cancels the pending timer and the in-flight request: no request is
    issued after unmount, and no store write happens after it either.
13. `[test]` The store is a data class with observable fields only — no method, no computed
    getter — and every derivation and effect used by the page is a free function taking it
    (`002`'s D2, `context.md` D13).
14. `[test]` The `bootstrap` entry still carries its stable entry marker and still declares
    **no router `basename`**, so `002/006`'s DoD-1 and DoD-4 hold unchanged.
15. `[test]` No module under `frontend/src/bootstrap/` imports a stylesheet, and
    `src/app/main.tsx` is still the only module importing `shell.css`.
16. `[manual/live]` With the backend stopped and the dev server running, opening the
    bootstrap entry shows the not-ready-yet state and **resolves to the offer on its own**
    once the backend is started — no reload.
17. `[manual/live]` Both colour schemes are correct in all five states.
18. `[manual/live]` `npm run typecheck`, `npm test` and `npm run build` all pass from
    `frontend/`, and the build still emits exactly the four entry documents.

## Dependencies

None within this feature — it binds to the route contract, not to the service internals,
and reads only `GET /api/health`, which `001.backend-foundation` already delivers. Steps
`001`–`003` are what make `configured` ever become true.
