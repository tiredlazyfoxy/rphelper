# Step 004 — step-specific context

Feature-wide facts are in `context.md`; the decisions this step implements are D11 (the
widening, and why the session is opened inside the creation transaction), D12 (`/` is where
everyone lands) and D15 (the four invalidated `003` assertions and who owns each). None of
that is repeated here.

## This step is a widening of `brief.md`, authorized by the user

`brief.md`'s Scope In does not name bootstrap. `context.md` D11 records the user decision
that adds it, and this step exists as its own step **so the widening is visible and
reviewable in one place** rather than smeared across the login steps. Nothing else about
FEAT-001 is reopened here: the offer, the refusal, the not-ready state, the probe, the
validation and the created row's contents are all `003`'s and stay as built.

## What `003` built that this step extends, by role

Exact names are `003`'s to freeze; the skeleton resolves them against the delivered code.

- **`services/bootstrap.py`** (`003/002`) — a configured-instance predicate and a
  create-first-administrator operation. The latter already runs **entirely inside one
  `with conn.begin():`**: re-check the predicate and raise `already_configured`, apply the
  registry with SQLAlchemy's create-if-missing creation, mint the id from the generator
  passed in, hash through `services/passwords.py`, insert the one `users` row. This step
  appends one insert to that block and widens the returned result.
- **`routers/bootstrap.py`** (`003/003`) — `POST /api/bootstrap/create`, 201, behind a
  **router-level** `require_unconfigured`. This step adds the settings dependency, the
  response object and the cookie write. The guard, the prefix and the absence of an import
  route are untouched.
- **`CreateAdminForm.tsx`** (`003/005`) — an `observer` component taking the bootstrap
  store and the draft as props, **plus an optional hand-off function defaulting to the
  document navigation to `/login`**. That default is the whole of this step's frontend
  change.

## Why the session is opened in the service's transaction and not by the router

Two properties are at stake and both are `003`'s own:

- **`003`'s D8 property.** Schema plus first administrator commit together so that "tables
  but no admin" is never observable. Once the create route also signs the operator in, the
  same argument covers the session: an administrator who exists while the response that was
  supposed to sign them in failed leaves the operator at `/` and immediately bounced back
  to `/login`, with no way to tell whether the account was created.
- **The routers-versus-services split.** A router that called two services in sequence
  would be making an ordering decision — a rule — in the layer that is supposed to hold
  none. The service composes; the router transports.

The service still knows nothing about HTTP: it returns a token and an expiry, and the
router is what turns them into a `Set-Cookie`.

## The TTL arrives as an argument

`services/bootstrap.py` reads no settings today and must not start: `001`'s convention is
that settings reach services as plain arguments resolved by the router's dependency, which
is what lets a test drive the operation with a two-hour TTL and no environment at all. The
router resolves `Settings.session_ttl_hours` and passes it down, exactly as it already
resolves the generator from application state.

## Gotcha — the response body does not change

The token goes in the cookie. `app/models/bootstrap.py` is **not** in this step's Source
files, and adding a token, expiry or session field to the create response would put the
session token in a place JavaScript can read — which is the whole reason the cookie is
`HttpOnly` (`frontend-structure.md`: "there is no token JavaScript can read"). DoD-4 is the
assertion that keeps it out.

## Gotcha — the four edits to other features' tests, kept narrow

Each of the three test files in scope is edited for exactly the clauses DoD-4, DoD-7,
DoD-9 and DoD-10 name. Everything else in all three stays. In particular:

- `003/002` DoD-7's atomicity test and DoD-8's generator test stay and still pass — DoD-5
  here widens the first rather than replacing it;
- `003/003` DoD-3's refusal test, DoD-5's no-credentials test and DoD-7's
  "a request naming a role or an id creates nothing with it" test are untouched;
- `003/005`'s validation, submittability, single-submit, request-body, refusal-flip,
  in-place-failure, masked-password and abort tests are untouched — only the hand-off's
  expected target moves.

If a clause named here turns out not to exist in the delivered test file, or to live in a
different file of the same feature, that is a **test-coder hand-back to the orchestrator**,
not a licence to edit outside the listed scope.

## Gotcha — `/` in stage 001

The hand-off lands on `002`'s placeholder `app` document, which renders a marker and
nothing else. That is expected (`context.md` D12). The root document's deployment seam —
the build emits `dist/app/index.html` while nginx's catch-all resolves `dist/index.html` —
is recorded in `002/outcome.md` and is `fast/001`'s to bridge. DoD-13 is run against the
**dev server**, where the same seam means the entries may be reached at their own paths;
the observable claim is that the hand-off navigates to `/` and that the session cookie
survives it, not that `/` renders a workspace.
