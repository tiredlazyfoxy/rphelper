# Step 002 — The role ladder, `CurrentUser`, `require_user`, `require_role`, and the cookie writers

## Goal

Turn the two-rung ladder into code and give every router one way to demand an
authenticated caller and one way to demand a rung, plus the single place that knows the
session cookie's name and flags.

## Source files

```
backend/app/roles.py
backend/app/errors.py
backend/app/dependencies.py
```

## Test files

```
backend/tests/test_dependencies.py
backend/tests/test_errors.py
backend/tests/test_db_schema.py
```

`backend/tests/test_errors.py` is extended. `backend/tests/test_db_schema.py` is edited for
exactly one reason: it carries `003/001` DoD-4's now-false purity clause about the role
enum (DoD-3 below, `context.md` D15, and `002.context.md` for the hand-back rule if the
clause turns out to live in the other file).

## Interface intent

**`backend/app/roles.py`** — extend `003`'s leaf module with **the ladder and one pure
comparison**, and nothing else:

- **`ROLE_LADDER`** — the mapping `domain-rules.md` states, `{roleplayer: 0, admin: 1}`,
  keyed by the existing enum's members. It covers **every** member of the enum, so a rung
  added later without a ladder entry is a failure rather than a silent zero.
- **one pure predicate** answering whether a role is **at least** another role on the
  ladder. It takes two roles and returns a boolean; it reads no settings, opens no
  connection and imports no `fastapi` symbol.

The module stays importable by `db/schema.py`, which is the whole reason the dependency
factory is **not** here (`context.md` D8). It gains no `CurrentUser`, no dependency and no
`Request`.

**`backend/app/errors.py`** — add **two subclasses** of the existing domain-error base,
following the same pattern as everything already in the file (`code` and `http_status` as
class attributes the subclass sets, per-instance message/detail, the inherited render
method, no new handler):

- **`not_authenticated`**, HTTP **401**, empty `detail` — raised when a request carries no
  session cookie, or one that does not resolve to a live session (`context.md` D3, D7).
- **`insufficient_role`**, HTTP **403**, empty `detail` — raised when an authenticated,
  enabled caller's role is below the required rung. Its `detail` carries **nothing**: it
  names neither the caller's role nor the required one, because a refusal that reports the
  policy is a refusal that teaches it.

**`backend/app/dependencies.py`** — a new top-level leaf module, the HTTP-side
authentication seam. It imports `fastapi`; nothing under `db/` or `services/` imports it.
Five things and nothing else:

- **`CurrentUser`** — the small immutable value a guarded route receives: the caller's id,
  username and role. It is a plain value object, not a pydantic response model and not an
  ORM row; a route that wants to *return* an identity uses step `003`'s model.
- **`require_user`** — the dependency `backend-structure.md` specifies. It resolves the
  settings and the connection through `001`'s existing dependencies, reads the cookie **by
  the name in `Settings.session_cookie_name`** off the request, asks step `001`'s
  resolve-session operation, and **yields a `CurrentUser`**. A missing cookie, an empty
  cookie and a cookie that does not resolve to a live session all raise
  `not_authenticated` — one branch, one error.
- **`require_role(min_role)`** — a dependency **factory**, not a fixed dependency
  (`backend-structure.md`'s snippet): it takes a minimum role and returns a dependency
  callable that resolves the caller exactly as `require_user` does and then compares
  through `roles.py`'s pure predicate, raising `insufficient_role` when the caller is below
  the rung and yielding the same `CurrentUser` when they are not. It resolves through the
  same path as `require_user` rather than duplicating it, so there is one definition of
  "who is calling".
- **a cookie writer** — takes FastAPI's response object, a token, an expiry-relevant
  lifetime and the settings, and sets the session cookie with the flags `context.md` D6
  fixes: the configured name, `HttpOnly`, `SameSite=Lax`, `Path=/`, **`Secure` off**, and a
  `Max-Age` matching the TTL.
- **a cookie clearer** — takes the response and the settings and clears that same cookie,
  using the **same name and path** so the browser actually drops it.

The two writers live here rather than in a router because they and the two dependencies
share one fact — the cookie's name and flags — and are used by two different routers
(`auth.py`, and `bootstrap.py` from step `004`). No route path, no status code literal and
no business rule appears in this module.

## Definition of done

1. `[test]` `ROLE_LADDER` maps **every** member of the role enum to a rung, with
   `roleplayer` below `admin`, exactly as `domain-rules.md` states.
2. `[test]` The pure comparison answers true for equal roles and for a higher role against
   a lower minimum, and false for a lower role against a higher minimum.
3. `[test]` `app/roles.py` exposes the ladder and the comparison and **still** exposes no
   dependency, no `Request` and no `fastapi` import — and it is importable without
   importing `fastapi` at all, which is what keeps `db/schema.py` free of it
   (`context.md` D8). The `003/001` assertion that the module exposes **no ladder mapping
   and no comparison helper** is **deleted** as part of this step, deliberately and not
   incidentally (`context.md` D15); the rest of that assertion — two members, and their
   values — is left intact.
4. `[test]` `not_authenticated` carries code `not_authenticated`, HTTP status **401** and
   an empty `detail`; `insufficient_role` carries code `insufficient_role`, HTTP status
   **403** and an empty `detail`; both render in the one wire shape through the handler
   `001` already registered, and no second handler is added.
5. `[test]` A route guarded by `require_user`, called with **no** cookie, answers **401**
   with the `not_authenticated` envelope and never reaches the handler.
6. `[test]` The same route called with a cookie holding an unissued token, a **revoked**
   token, an **expired** token, or a token whose user is **disabled** answers the same
   **401** in every case. (US-007.AC-2)
7. `[test]` The same route called with a cookie holding a live session's token reaches the
   handler and receives a `CurrentUser` carrying that user's id, username and role — the
   role read live from `users`, so changing it changes the next call's `CurrentUser`
   without a new session. (`context.md` D7)
8. `[test]` The cookie is read by the name in `Settings.session_cookie_name`: overriding
   that setting changes which cookie is honoured, and a cookie under the default name is
   ignored when the setting says otherwise.
9. `[test]` A route guarded by `require_role` at the administrator rung answers **403**
   with the `insufficient_role` envelope for a live roleplayer session, reaches the
   handler for a live administrator session, and answers **401** — not 403 — when there is
   no live session at all.
10. `[test]` The `insufficient_role` response body names neither the caller's role nor the
    required one.
11. `[test]` The cookie writer sets the cookie under the configured name with `HttpOnly`,
    `SameSite=Lax`, `Path=/`, **no `Secure` flag**, and a `Max-Age` matching the TTL it was
    given; the cookie clearer clears that same name at that same path.
    (`context.md` D6)
12. `[test]` The guards attach at **router level** as well as at handler level: a route
    registered on a router carrying the dependency is guarded without declaring anything of
    its own — which is the property every `admin_*.py` router will depend on
    (`backend-structure.md`).
13. `[manual/live]` `app/dependencies.py` contains no SQL, no route path and no business
    rule: its only database contact is through `001`'s connection dependency and its only
    rule is the ladder comparison it delegates to `roles.py`. Verifier confirms by reading
    the module.
14. `[manual/live]` `mypy app`, `ruff check .` and `pytest` all pass from `backend/`.
