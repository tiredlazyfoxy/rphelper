# Step 007 — app entry points: user menu "Import…" and Sessions section "Import session"

## Goal

Add the roleplayer's two import controls, both with `IconUpload`:
- **"Import…"** in the user menu, for every role. It takes a `user` or `character`
  export.
- **"Import session"** in the character page's Sessions section. It imports a
  `session` export into that character.

`CharactersState` and `SessionsState` are threaded to these controls so that an
import can reload them.

## Interface intent

- **`UserMenu`** gains two required props: `charactersState` and `sessionsState`
  (the single `CharactersState` / `SessionsState` that `App` creates).
  - It renders a `Menu.Item` labelled **"Import…"** with `leftSection`
    `IconUpload` (`size={16} stroke={1.5}`). The item is shown to every role, next
    to 030's "Export my data" and above Log out.
  - Choosing the item opens the browser file picker through a hidden file input
    that accepts `.json` / `application/json`. The input is rendered **outside** the
    menu dropdown (see the gotcha in `007.context.md`) and carries an accessible
    label.
  - A chosen file runs `runOwnedImport` with both states and the router's
    `navigate`.
  - The input is reset after each choice, so the same file can be chosen again
    (US-136.AC-2: a second import is allowed).
- **`SessionsSection`** gains a required `sessionsState` prop.
  - It adds a section-level **"Import session"** `Button` (`variant="default"`,
    `leftSection` `IconUpload`), placed in the section header beside the existing
    section-level control(s).
  - The button is wrapped in a Mantine `FileButton` that accepts `.json` /
    `application/json`.
  - A chosen file runs `runSessionImport` for the section's character id, passing
    `sessionsState`. Its `reloadSection` callback re-runs the section's existing
    list loader (`loadSectionSessions`) on the section's state.
  - While the import is in flight the button shows a loading state, held in
    component-local `useState`.
  - The `FileButton` is reset after each choice.
- **Threading.** `App` already creates both states. They are passed:
  - through `WorkspaceShell` to `UserMenu`;
  - through `CharacterScreen` to `SessionsSection`.

  If the skeleton finds a component rendered somewhere else, or a state already
  threaded, it records the real path in `## Skeleton`. Each edit stays the minimum
  needed to deliver the prop, and any file in this list that turns out to be
  unneeded is left untouched.
- **Neither control opens a confirm dialog** (`context.md` §"Frontend shared
  facts").

## Definition of done

1. **DoD-1 [test]:** The user menu shows an "Import…" item for a roleplayer and for
   an admin alike. Choosing a file containing a `character` export:
   - posts it to `POST /api/import`;
   - then requests both the characters list and the sessions list again;
   - lands on `/characters/<returned id>`.

   (US-080.AC-2)
2. **DoD-2 [test]:** Choosing a `user` export in the user menu posts to
   `POST /api/import`, requests both the characters list and the sessions list
   again, and stays on the current route. (US-079.AC-2)
3. **DoD-3 [test]:** A successful user-menu import raises exactly one
   notification, carrying the pinned coverage sentence (`006.context.md`). No other
   notification is raised.
4. **DoD-4 [test]:** Choosing a file whose text is not JSON raises one
   notification carrying "The chosen file is not a readable export." and makes no
   `POST`. A server answer of 400 `export_invalid` raises one notification with the
   server's message. Neither case reloads any list.
5. **DoD-5 [test]:** Choosing the same file twice in a row posts twice, because the
   input accepts a repeat choice. (US-136.AC-2)
6. **DoD-6 [test]:** The character page's Sessions section shows an "Import
   session" button. Choosing a `session` export:
   - posts to `POST /api/characters/<that character's id>/import`;
   - after success, requests the section's session list again and shows the new
     session in it;
   - also requests the `SessionsState` sessions list again.

   (US-082.AC-1, UC-064)
7. **DoD-7 [test]:** A failed session import (404 `character_not_found` or 400
   `export_invalid`) raises one notification with the server's message. Neither the
   section list nor the sessions list is reloaded.
8. **DoD-8 [test]:** Neither control opens a dialog. Choosing a file goes straight
   to the request, and no element with role `dialog` exists before the `POST`.
9. **DoD-9 [test]:** Each import control has the accessible name "Import…" or
   "Import session" respectively, and renders the Tabler upload icon
   (`.tabler-icon-upload`).
10. **DoD-10 [test]:** With the new props supplied, these existing tests pass:
    - the `UserMenu` tests (`UserMenu.test.tsx` and 030's
      `UserMenu.export.test.tsx`). Settings, Admin area (admin only), Export my
      data and Log out behave as before;
    - 030's `SessionsSection.export.test.tsx` and `CharacterScreen.export.test.tsx`.
      The row Export items and the character Export button behave as before.
11. **DoD-11 [manual/live]:** In a browser:
    - export a character, then import it through the user menu. The page opens on
      the new copy, and the tree shows its sessions;
    - export a session, then import it from another character's Sessions section.
      It is listed both in that section and under that character in the tree.
12. **DoD-12 [manual/live]:** `npm run typecheck` passes.
