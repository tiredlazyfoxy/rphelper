# Step 006 — step-specific context

## Pinned warning sentence (U3; tests bind to it)

> Imported material won't appear in semantic search until an administrator rebuilds the search index.

- **When it appears.** Raised **once per successful roleplayer import**, through
  `shared/notifyWarning.ts`. Never raised on failure.
- **Why it is allowed.** It is a caveat about search coverage, not a success
  message, so it does not break "a notification whose message is a success is a
  defect".
- **Why it is unconditional.** The response carries no
  `search_coverage_incomplete` field. An import never embeds anything, so coverage
  is always incomplete for the material it brought in.

## Existing names

- **`shared/api.ts`.**
  - `apiPost(path, body?, signal?)` JSON-stringifies the body and decodes the
    envelope.
  - `ApiError(code, message, status, detail)` is the error type.
  - `CLIENT_MALFORMED_ERROR` and `CLIENT_TRANSPORT_FAILED` are existing code
    constants.
  - A 401 calls `documentNavigation.assign("/login")`.

  The new code constant lives in `shared/importFile.ts`, not in `api.ts`, because
  `api.ts` is not in this step's scope. It follows the same `client_*` naming.
- **Notifications.**
  - `shared/notifyFailure.ts` exports `notifyFailure(error)`.
  - `shared/notifyWarning.ts` exists. The skeleton records its exact parameter
    shape; the call passes the pinned sentence.
  - A conventions test restricts `@mantine/notifications` imports to these two
    files, so this step never imports Mantine notifications directly.
- **`app/charactersState.ts`** has `CharactersState` and `loadCharacters(state,
  signal?)`.
- **`app/sessionsState.ts`** has `SessionsState` and `loadSessions`.
  - `SessionsState` drives the session level of the character tree, which is why
    every roleplayer import reloads it.
  - The skeleton records `loadSessions`' exact parameters and the sessions-list path
    it requests. Tests key their `fetch` stub on that path.
- **Error routing** follows `app/logout.ts`: `notifyFailure` unless aborted, and
  never rethrow.
- **Module shape** follows `app/exportDownloads.ts` (030): free functions only. It
  has no MobX class, because no control owns domain state about an import.
- **`navigate`** is the function `useNavigate()` returns. It is passed in so the
  effect stays a free function that can be tested without a router.

## Gotchas

- **`File.text()` in jsdom.** `readExportFile` depends only on the argument's
  `text()`. If the repo's jsdom lacks `Blob.prototype.text`, tests may pass any
  object with an async `text()` instead of a `File`.
- **Abort detection** matches `logout.ts` and `exportDownloads.ts`: a
  `DOMException` named `AbortError`, or the signal's aborted state.
- **Reload order** on success:
  1. the section or characters reload;
  2. then `loadSessions`;
  3. then the warning.

  Run the reloads sequentially, not in parallel, so that a test can observe a
  deterministic request order.
