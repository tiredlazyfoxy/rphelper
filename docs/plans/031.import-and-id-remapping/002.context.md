# Step 002 — step-specific context

## Registry facts (references the engine must rewrite)

| Table | FK / reference columns | Target |
|---|---|---|
| `characters` | `user_id` | users → caller |
| `characters` | `model_server_id` (**no FK**) + `model_name` | kept only if the pair is in `models` (`server_id`, `model_name`) |
| `setups` | `user_id`, `character_id` | caller; `characters` map |
| `sessions` | `user_id`, `character_id` (NOT NULL), `setup_id` (nullable) | caller; `characters` map; `setups` map |
| `sessions` | `model_server_id` + `model_name` | as for characters |
| `messages` | `user_id`, `session_id`, `related_to` (self-FK, nullable) | caller; `sessions` map; `messages` map (second pass) |
| `memos` | `user_id`, `scope` + `scope_id` (**no FK**) | caller; by scope: `user` → caller, `character`/`setup`/`session` → that table's map |

- **`model_server_id` is not an FK.** It is caught as an id column by 030's name
  rule, and the engine handles it explicitly. It is never "unresolved", only kept
  or nulled.
- **The CHECK `ck_characters_model_both_or_neither`** (and the sessions
  counterpart) means the two columns are nulled together, never one alone.
- **CHECK `related_to IS NULL OR settled_at IS NULL`.** The first-pass insert has
  `related_to` null, and the second pass sets it only on buried rows, whose
  `settled_at` is null.
- **FKs are immediate.** `PRAGMA foreign_keys=ON` is set on every connection, and
  nothing is deferrable. That is why the self-reference is two-pass, and why insert
  order is `sorted_tables`. Do **not** toggle `PRAGMA foreign_keys`: it is a no-op
  inside a transaction (`backend-structure.md` §"The FK posture of a rebuild").

## Existing names

- **Generator.** `app/ids.py` `SnowflakeGenerator.next_id() -> int`. Services take
  it as a parameter after the connection.
- **Read convention.** The services' private `_reading(connection)` context
  manager is used for reads outside a write. Here the model-pair lookup happens
  **inside** the import's `with connection.begin():`, so no separate read
  transaction is opened.
- **024 FTS.** `ensure_fts_tables(connection)` is in `app/db/search_tables.py`.
  Call it only inside the transaction. When it creates a table it back-fills once,
  and afterwards the triggers index each insert.

## Test guidance

- Build the source envelope as user A with 030's exporters, import as user B with a
  fresh `SnowflakeGenerator`, then compare B's rows to the seeded A rows through
  the id correspondence. The correspondence can be recovered by pairing rows
  ordered by id per table: DoD-6 guarantees that the order is preserved. **Do not
  call the remap engine directly**; it is private.
- **Buried rows.** Seed a settled group with `services/settle.py`, or with Core
  inserts that satisfy the CHECK.
- **"Stores nothing"** = count rows in every `schema.metadata.sorted_tables` table
  before and after.
- **FTS observation.** Query `memo_fts` / `message_fts` with `MATCH` directly; tests
  may do so (024 convention).
