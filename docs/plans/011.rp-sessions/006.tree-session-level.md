# Step 006 — The tree's session level, chevron and character order

## Goal

Extend 009's `CharacterTree` with the session level: characters ordered by newest session
use (D6), a persisted per-character chevron (D7), and under each expanded character its
working sessions as links labelled with the start time and the setup label (D16). `App`
creates the one workspace `SessionsState` and `WorkspaceShell` hands it, with the layout
storage, to the tree.

## Interface intent

**`app/CharacterTree.tsx`** (edited; 009-owned file)

- **`CharacterTree`** gains two **required** props: `sessions` (the workspace
  `SessionsState`) and `storage` (`LayoutStorage` or `null`). Everything 009 renders
  (header, "Show archived" switch, character load/failed/ready states, row links, active
  character mark, archived dimming) stays. In addition it:
  - loads the sessions (`loadSessions`) **once on mount**, with an `AbortController`
    aborted on unmount; the "Show archived" switch does **not** reload sessions;
  - renders the character rows in `orderCharactersByUse(characters, sessions)` order;
  - holds the collapsed set as component-local `useState`, initialised from
    `readCollapsedCharacters(storage)`;
  - on each character row that has at least one session in the workspace state, renders
    before the link an `IconButton` with `sizeVariant` "chevron": label **"Collapse
    <name>"** and the `IconChevronDown` glyph while expanded; label **"Expand <name>"** and
    the same glyph rotated `-90°` while collapsed. Pressing it computes the next set with
    `toggleCollapsedCharacter`, sets it, and writes it with `writeCollapsedCharacters`. A
    character with no sessions renders no chevron;
  - under each **expanded** character that has sessions, renders a nested list with
    accessible name **"Sessions of <name>"**, one row per session from
    `sessionsOfCharacter` in state order. Each row is a router link to `/sessions/<id>`
    (id verbatim) whose content is the start-time label (`formatSessionStart` of
    `created_at`) and, when `setup_name` is non-null, the setup name as dimmed small text;
    with no setup, nothing else. The row whose id equals the current `/sessions/:id` has
    `aria-current="page"`; no other session row does;
  - when the sessions load has `"failed"`, renders in the tree the text **"Could not load
    sessions"** and a button **"Retry"** that re-runs `loadSessions`. The character level
    still renders (without session rows or chevrons). No notification;
  - renders no session loader (characters show at once; session rows appear when loaded).

**`app/WorkspaceShell.tsx`** (edited; 008-owned file)

- Gains one **required** prop, `sessions` (`SessionsState`), and passes it, with its
  existing `storage` prop, to `CharacterTree`. Nothing else changes.

**`app/App.tsx`** (edited)

- Creates one `SessionsState` with `useState(() => new SessionsState())` and passes it to
  `WorkspaceShell` as `sessions`. Routes and screens are unchanged in this step.

## Definition of done

1. `[test]` `CharacterTree` mounted with characters `[A, B, C]` (the characters payload's
   order) and a sessions payload where a session of C has the most recent `last_used_at`, a
   session of A an older one, and B none, shows the "Characters" list's character links in
   the order C, A, B. (D6)
2. `[test]` Under an expanded character, the "Sessions of <name>" list holds exactly that
   character's sessions as links in the sessions payload's (last-use) order, each `href`
   `/sessions/<id>` with the id verbatim; no session of another character appears under it.
   (US-089.AC-1, UC-069)
3. `[test]` A session with `setup_name` "Tavern" shows "Tavern" in its row; a session with
   `setup_id` null shows only a start-time label of the fixed shape and no other text.
   (US-088.AC-1, US-088.AC-2)
4. `[test]` Clicking a session row navigates in-entry to `/sessions/<id>`, with no document
   navigation. Rendered at `/sessions/<id>`, that session row has `aria-current="page"`
   and no other session row or character row does. (UC-069, UC-024)
5. `[test]` With an empty storage every character with sessions is expanded and carries a
   "Collapse <name>" button; a character with no sessions carries no chevron. Pressing
   "Collapse A" hides A's session rows, the button becomes "Expand A", and the storage
   holds, under `rphelper.tree-collapsed`, a JSON array containing A's id. (D7)
6. `[test]` A tree mounted over a storage whose `rphelper.tree-collapsed` array holds A's
   id starts with A collapsed ("Expand A", no A session rows) and B expanded. Pressing
   "Expand A" shows A's rows and removes A's id from the stored array. 008's
   `rphelper.workspace-layout` record is never written by these toggles. (D7)
7. `[test]` On mount the tree requests `GET /api/sessions` exactly once, never with
   `include_archived`. Turning "Show archived" on requests the characters listing again
   but not the sessions listing; an archived character's sessions then appear under it,
   and turning the switch off hides that character and its sessions. (D5, D16)
8. `[test]` A failed sessions load shows "Could not load sessions" and "Retry" in the
   tree, the character links still render, and no notification is shown. "Retry"
   requests `GET /api/sessions` again, and on success the session rows render. (D18)
9. `[test]` Applying a new working session to the passed `SessionsState` with
   `applySession` after mount (no fetch) shows its row first under its character and moves
   that character to the top; applying the archived version of a listed session removes
   its row. No sessions request follows either. (D15, US-027.AC-1)
10. `[test]` `WorkspaceShell` (amending 008's and 009's tests for the new required prop):
    expanded, the nav contains "Collapse tree", the "Show archived" switch, the
    "Characters" list and the "User menu" trigger, and session rows from the stubbed
    sessions payload; collapsed, the rail shows no session rows. 008's and 009's other
    shell assertions still hold.
11. `[test]` `App` at `/` with stubbed characters and sessions shows the session rows under
    their characters in the tree. 009's and 010's existing `App.test.tsx` assertions keep
    passing with their `fetch` stubs extended to answer `GET /api/sessions` (for example
    with `{ "sessions": [] }`). No 009 or 010 assertion is dropped.
12. `[test]` `tests/app/AppBoot.test.tsx` and `tests/entries.test.tsx` keep passing their
    008 / 009 assertions with their `fetch` stubs extended to answer `GET /api/sessions`.
    No assertion about the boot outcomes changes.
13. `[test]` 009's `tests/app/CharacterTree.test.tsx` assertions keep passing when the
    sessions payload is empty (the payload order of characters; "Search" and "New
    character" as the only header buttons and no chevron on any row). Clauses that this
    step's behaviour contradicts when sessions exist are replaced by DoD-1..9, not deleted
    silently (`006.context.md`).
14. `[manual/live]` In a browser: the collapsed chevron reads as rotated `-90°`; the setup
    label reads as secondary text at 252px; below 820px choosing a session row in the
    overlay navigates and closes the overlay (008 D11).
