# Step 007 — The Sessions section's state

## Goal

Add `app/sessionsSectionState.ts`: the section's data class (one character's sessions,
the archived switch, the setup choices and selection, start and row-action status and
errors) with its load effects, the section's apply-a-row rule, and the start / archive /
restore effects that apply the server's row to **both** the section and the workspace
`SessionsState` (D1, D5, D15, D18, D19).

## Source files

frontend/src/app/sessionsSectionState.ts

## Test files

frontend/tests/app/sessionsSectionState.test.ts

## Interface intent

**`app/sessionsSectionState.ts`** (new)

- **`SessionsSectionState`**: data class, observable fields only, constructed from a
  `characterId` (string):
  - `characterId`: as constructed;
  - `sessions`: array of `Session`, starts empty; `status`: `"idle"`, `"loading"`,
    `"ready"` or `"failed"`, starts `"idle"`;
  - `showArchived`: boolean, starts false, never persisted;
  - `setups`: array of 010's `Setup` (the working choices), starts empty; `setupsStatus`:
    `"idle"`, `"loading"`, `"ready"` or `"failed"`, starts `"idle"`;
  - `selectedSetupId`: a setup id string or `null` ("No setup"), starts `null`;
  - `startStatus`: `"idle"` or `"submitting"`, starts `"idle"`; `startError`: text or
    `null`;
  - `error`: the row-action failure text or `null`; `pendingId`: the id of the row whose
    archive/restore is in flight, or `null`.
- **`loadSectionSessions`**: effect. Takes the state and an optional signal. Sets
  `"loading"`, requests the character's sessions with `includeArchived` equal to
  `showArchived`, and on success writes the rows in the order received with `"ready"`. On
  failure writes `"failed"` and keeps the rows. Writes nothing once aborted; never rejects.
- **`setShowArchived`**: effect. Takes the state and a boolean; sets the flag; does not
  load (the section reloads in response, `008`).
- **`loadSetupChoices`**: effect. Takes the state and an optional signal. Sets
  `setupsStatus` `"loading"`, requests the character's **working** setups (010's
  `fetchSetups` with `includeArchived` false), and on success writes them in the order
  received with `"ready"`; if `selectedSetupId` is no longer among them, it is reset to
  `null` in the same action. On failure writes `"failed"`, keeps the previous choices and
  the selection. Writes nothing once aborted; never rejects.
- **`selectSetup`**: effect. Takes the state and a setup id string or `null`; sets
  `selectedSetupId`.
- **`applySectionSession`**: takes the state and one server-returned `Session` and upserts
  it: archived while `showArchived` is false → removed if present, not inserted; otherwise
  removed if present and inserted at its `last_used_at`-descending position (`004`'s
  insert rule).
- **`startSessionFromSection`**: effect. Takes the state, the workspace `SessionsState`,
  an `onStarted` callback receiving the new session's id string, and an optional signal.
  Clears `startError`, sets `startStatus` `"submitting"`, POSTs a start for `characterId`
  with `selectedSetupId` (`null` for "No setup"). On success applies the returned row with
  `applySectionSession` **and** the workspace `applySession`, then calls `onStarted` with
  the id exactly as received. On failure sets `startError` to **"Could not start the
  session."** and changes neither list. Either way `startStatus` returns to `"idle"`.
  Writes nothing once aborted; never rejects.
- **`archiveSectionRow`** / **`restoreSectionRow`**: effects. Take the state, the
  workspace `SessionsState`, a session id and an optional signal. Clear `error`, set
  `pendingId`, POST the action, and on success apply the returned row to the section
  (`applySectionSession`) and the workspace (`applySession`). On failure set `error` to
  **"Could not archive the session."** / **"Could not restore the session."** and change
  neither list. Either way `pendingId` returns to `null`. Write nothing once aborted;
  never reject.

## Definition of done

1. `[test]` A fresh `SessionsSectionState("c1")` has `characterId` "c1", no sessions,
   `status` `"idle"`, `showArchived` false, no setups, `setupsStatus` `"idle"`,
   `selectedSetupId` `null`, `startStatus` `"idle"`, and `startError`, `error`,
   `pendingId` all `null`. (D1, R2)
2. `[test]` `loadSectionSessions` sets `"loading"` while pending, requests exactly
   `GET /api/characters/c1/sessions` (with `?include_archived=true` only when
   `showArchived` is true), then `"ready"` with the server's rows in the server's order. A
   failed request sets `"failed"`, keeps the rows and resolves without throwing; an
   aborted signal writes nothing. (US-028.AC-1)
3. `[test]` `loadSetupChoices` requests exactly `GET /api/characters/c1/setups` (no
   `include_archived`), then `setupsStatus` `"ready"` with the server's setups in order. A
   failure sets `"failed"`, keeps the previous setups and the selection, and resolves
   without throwing; an aborted signal writes nothing. (US-023.AC-2, D19)
4. `[test]` With "s1" selected, a successful `loadSetupChoices` whose payload still holds
   s1 keeps the selection; one whose payload lacks s1 resets `selectedSetupId` to `null`.
   (D19, R2)
5. `[test]` `selectSetup(state, "s1")` sets `selectedSetupId` "s1"; `selectSetup(state,
   null)` sets it back to `null`. (UC-021)
6. `[test]` `startSessionFromSection` with `selectedSetupId` `null` POSTs
   `/api/characters/c1/sessions` with the body `{"setup_id": null}`; with "s1" selected,
   with `{"setup_id": "s1"}`. While pending, `startStatus` is `"submitting"` and neither
   the section nor the workspace state holds the new row (never optimistic). After the 201
   the row is in the section state (first, being newest) and in the workspace
   `SessionsState`, `onStarted` was called once with the response's id string, and
   `startStatus` is `"idle"`. (US-026.AC-1, US-024.AC-1, US-025.AC-1, D15)
7. `[test]` A failed start sets `startError` to "Could not start the session.", leaves
   both states' rows unchanged, does not call `onStarted`, returns `startStatus` to
   `"idle"` and resolves without throwing. A start after a failure clears `startError`
   before its request. (D18)
8. `[test]` `applySectionSession`: an absent working row is inserted by `last_used_at`
   descending; a present row with unchanged `last_used_at` keeps its index with the new
   values; an archived row is removed while `showArchived` is false (no-op if absent) and
   kept in place while it is true. (US-027.AC-1, US-028.AC-1)
9. `[test]` `archiveSectionRow` POSTs `/api/sessions/<id>/archive`. While pending,
   `pendingId` is that id and the row is still listed. After the response, with
   `showArchived` false, the row is gone from the section and from the workspace
   `SessionsState`; with `showArchived` true it stays in the section with the response's
   `archived_at`, and is still gone from the workspace state. `pendingId` ends `null`.
   (US-027.AC-1, D5, D15)
10. `[test]` `restoreSectionRow` POSTs `/api/sessions/<id>/restore`. After the response the
    section row has `archived_at` null, and the workspace `SessionsState` holds it at its
    `last_used_at` position. (US-027.AC-2, D15)
11. `[test]` `archiveSectionRow` / `restoreSectionRow` failures set "Could not archive the
    session." / "Could not restore the session.", leave both states unchanged, reset
    `pendingId` to `null` and resolve without throwing; a later row action clears the
    previous `error` before its request. (D18)
12. `[test]` `setShowArchived` sets the flag and issues no request. An `autorun` reading
    `sessions` re-runs after `applySectionSession`, and one reading `selectedSetupId`
    re-runs after `selectSetup`.
