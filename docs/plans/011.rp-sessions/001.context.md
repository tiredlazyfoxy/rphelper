Feature-wide facts are in `context.md`: **D8** (columns, FKs, index, deferred columns),
**D12** (the two codes and why 409), **D2** (body semantics), the **Wire contract** (the
`Session` shape), **Test landmines**, and backend **Test conventions**. 009's

"The delta pattern") and 010's `001.context.md` ("Applying 009's patterns here", "The

narrow to this step is below.

## Applying the patterns here

- `character_id` and `setup_id` use the same column type as `user_id` (`BigInteger` with
  the SQLite `Integer` variant, matching the referenced PK). `setup_id` is
  `nullable=True` with **no** `server_default` and no Python-side `default` other than
  `None`: R2's "no default" is a column property here, not only a service habit.
- `sessions` goes **after** `setups` in `schema.py`, because its FKs name both
  `characters` and `setups`. Both registry-literal guard tests
  (`test_every_registry_table_is_a_literal_in_the_schema_module`,
  `test_no_other_app_module_defines_its_own_table`) must keep passing unchanged.
- The composite index is declared like 010's: column list exactly
  `("user_id", "character_id")`, non-unique; the drift report keys on (column list,
  uniqueness), so the name is free.
- `SessionResponse` uses `SnowflakeOut` for `id` and `character_id`, and a nullable form
  of it for `setup_id`. A bare `int` anywhere would leak a JS-unsafe number
  (`data-model.md` Identifiers).

## Gotcha — the nullable inbound snowflake

`StartSessionRequest.setup_id` is the first **nullable** inbound id in the codebase.
`backend-structure.md` shows `SnowflakeIn` as an `int` with a `BeforeValidator` calling
`int(v)`. Wrapped naively in an optional union, a JSON `null` can reach that validator and
raise something other than a validation error (pydantic v2 does not convert a `TypeError`
from a validator into a 422). The skeleton chooses the form; whatever it is, DoD-8 pins the
behaviour: `null` and absent → `None`, a decimal string → int, a non-numeric string → a
validation error. `models/ids.py` itself is not in scope; the nullable handling lives in
`models/sessions.py`.

## Names

`SessionResponse` / `SessionListResponse` / `StartSessionRequest` must not collide with any
model name the auth router already uses (it models the identity, not a login session row,
per `backend-structure.md`). If the skeleton finds a collision inside `models/`, it
prefixes these with `Rp` and records it in `## Skeleton`; the wire shape is unchanged.

## The delta (DoD-1, DoD-9)

Same two-shape rule as 010 `001.context.md` "The delta": if the file asserts membership
plus absence, assert `"sessions"` membership and that nothing beyond the tables declared
through 011 could be 011's; if it subtracts a "declared by later features" set, add
`"sessions"` to that set for 006's, 009's and 010's deltas and write 011's own delta against
a later-features set that starts empty. The test-coder reads the file to see which.

## Gotcha — `/api/health` on existing databases

As 009 / 010: registering `sessions` makes an existing database report `schema:
"missing"` until an administrator presses Create. Designed behaviour; tests build schema
with `create_all`.
