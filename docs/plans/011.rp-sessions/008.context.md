## The "No setup" option value

Mantine's `Select` speaks strings, and its `null` value means "nothing selected", which
would let the field be emptied. Give "No setup" a fixed option value that can never equal
a decimal id (for example `"none"`), set `allowDeselect={false}`, and map that value to
`null` before calling `selectSetup` (and `null` back to it for the displayed value). This
value lives **only inside this component**: it never reaches the state, the API client or
the wire (R2, "no sentinel"). The setup options' values are the setup id strings verbatim.

## Reloading choices on open

Use the `Select`'s dropdown-open callback (`onDropdownOpen`) to start `loadSetupChoices`
with a fresh controller (aborting any in-flight one). Do not also call it from a render
effect keyed on anything else, beyond the one mount load. While a reload runs, the current
options stay rendered.

## Row labels and the menu trigger

The trigger's accessible name embeds the start-time label, so two sessions started in the
same minute share a name. Tests therefore locate a row by its link `href` and query the
trigger **within that table row**. Do not add an id or the setup name to the label: names
are the contract, and the label must stay readable.

## The hook in `CharacterScreen.tsx`

One element replaces 009's heading-only "Sessions" section in the existing-mode "ready"
branch: `SessionsSection` with `characterId` and `key` set to the loaded character's id
and `sessions` set to the prop. The region's own "Sessions" heading takes the old
heading's place, so 010's DoD-10 ("Setups region precedes the 'Sessions' heading") stays
true. `characterScreenState.ts` is read, not edited.

## What is deliberately absent

No modal, no session title field, no confirm, no "start your first session" prompt (the
empty line is neutral like 010's), no archive controls anywhere but the row menu, no
opening-message composer (`018`).
