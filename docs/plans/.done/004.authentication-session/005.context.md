# Step 005 — step-specific context

Feature-wide facts are in `context.md`; the decisions this step implements are D1 (one
message for all three refusals), D12 (everyone lands on `/`, no role branch), D13 (no
normalization), D14 (one screen, failures in place) and D16 (a draft and no page store).
None of that is repeated here.

## What `002` already built under this entry, and what it left for this step

`002/006.entries-and-guards.md` creates **both** `frontend/src/login/index.html` and
`frontend/src/login/main.tsx`.

- `index.html` is a document with lang and charset, a viewport meta, a title naming the
  entry, one mount element and a module script pointing at the sibling `main.tsx`. **This
  step changes none of it**, which is why it is in no Source files list.
- `main.tsx` finds the mount element, creates the React root and renders `AppProviders`
  wrapping a `BrowserRouter` wrapping a route table, with **no `basename`** for this entry.
  Its route table is an explicit **placeholder** — one catch-all rendering a stable entry
  marker and no visible content — and `002/006` says *"Later features replace the route
  table wholesale."* So this step **extends** the module; it does not re-create it.
- `002/006` is explicit that the placeholder carries *"No store, no data fetch, no gate, no
  shell, no `AppShell`, no error boundary"*.

The entry marker is kept rather than dropped, for the same reason `003/004` kept the
bootstrap one: it costs one attribute, it keeps `002`'s per-entry test passing untouched,
and it keeps a deep link landing on the wrong document diagnosable.

- `002/006` DoD-10's pure-data-contract clause was already **deleted** by `003/004`

## The shared modules this step calls, by role

Exact names are `002`'s to freeze; the skeleton resolves them against the delivered code.

- **`shared/api.ts`** — one request function taking path, method, optional JSON body and
  optional `AbortSignal`, plus four thin verb helpers. It **requires the path to begin
  `/api/`**, sends credentials, sets no `Authorization` header, resolves `204`/empty to
  nothing, and **throws** on non-2xx. A `401` performs a document navigation to `/login`
  and still throws; a `403` does **not** navigate. An abort rejection propagates
  **unchanged and unwrapped**.
- **`shared/apiError.ts`** — `ApiError` carrying `code`, `message`, `detail` and `status`,
  plus a type guard, plus the two named synthetic code constants
  (`client_malformed_error`, preserving the real status; `client_transport_failed` at
  status `0`). Import the constants; do not re-type the strings.
- **`shared/AppProviders.tsx`** — Mantine's provider with the theme and colour-scheme
  manager, the notifications outlet, and the stylesheet imports in one place. It creates no
  context and provides no store: **stores are passed explicitly as props everywhere in this
  project.**
- **`shared/notReady.ts`** (`003/004`) — exists, and this entry **does not use it**
  (`context.md` D14).
- **`shared/notifyFailure.ts`** — exists, and this entry calls it nowhere.

## The route this form posts to

`POST /api/auth/login`, from step `003`. Its request body is a username and a plaintext
password and nothing else; its success is **200** with an identity body the form does not
read; its refusal is **400** with code `invalid_credentials`; an empty field is refused
with FastAPI's own **422**, whose body is not the error envelope and therefore decodes to
`002`'s `client_malformed_error` at status 422. All three of those failures land in the
same general alert.

**The refusal is recognised by `code`, never by status `409`/`400` and never by the
message string** — `002`'s D7 is explicit that call sites branch on `.code`.

## Why the refusal never becomes a field error

`context.md` D1 is the reason, and it is worth seeing concretely: the only per-field
message the form could write for a refusal would be "we do not know this username" or "that
password is wrong", and the backend deliberately does not tell the client which applies.
A field-shaped message would therefore be **invented**, and it would be wrong half the
time. One general message is the honest rendering of the one fact the server actually
returned.

## Why there is no page store

`003`'s D13 puts a page's state and draft modules under the entry folder beside
`main.tsx`. This entry has one screen whose entire state is the form, so a `loginState.ts`
would hold no field the draft does not already hold (`context.md` D16). The draft is
created with `useState(() => new …Draft())` at the mount that renders the form —
`ui-conventions.md`'s fresh-instance-per-open rule, applied to a page rather than a modal.

## Gotcha — do not trim what is sent

The client validates on trimmed values to decide whether a field is *filled*, and sends the
raw ones (`context.md` D13). Trimming the password would change the credential; trimming
the username would make an account created with surrounding whitespace unreachable. DoD-4
is the assertion that catches either.

## Gotcha — the hand-off is a document navigation, and it is injectable

`frontend-structure.md`, "Navigation between entries": within an entry `react-router-dom`;
**between** entries a plain document navigation (`window.location.assign`), because the
entries are separate documents with no shared router. `login` → the `app` area is a
cross-entry move, so it is a document navigation — never a router navigation and never a
`<Link>`. The default is the real navigation; the prop exists so a component test can
observe the hand-off without fighting jsdom's location object.

That the session cookie survives the navigation is the whole reason the four-entry split is
safe: it is same-origin and `SameSite=Lax`, so the browser carries it automatically and no
entry contains auth-token plumbing (`frontend-structure.md`, `deployment.md`).

## Gotcha — this entry never asks who the user is

No `/api/me` on mount, no "you are already signed in, go to `/`" redirect, no role read.
`frontend-structure.md` makes `login` the one surface reachable unauthenticated on a
configured instance, and every request it can make is a request an unauthenticated caller
can make. A probe on mount would also put this entry inside `deployment.md`'s
not-ready-yet window, which is exactly the problem the `bootstrap` entry and the `admin`
gate had to solve and this one does not have.
