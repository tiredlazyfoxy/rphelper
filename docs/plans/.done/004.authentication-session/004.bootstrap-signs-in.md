# Step 004 — Bootstrap signs the operator in

## Goal

Close US-001.AC-2: the first-run create operation opens a session in the same transaction
that creates the administrator, the route sets the session cookie on its 201, and the
`bootstrap` entry hands off to `/` instead of `/login`.

## Source files

```
backend/app/services/bootstrap.py
backend/app/routers/bootstrap.py
frontend/src/bootstrap/CreateAdminForm.tsx
```

## Test files

```
backend/tests/test_bootstrap_service.py
backend/tests/test_bootstrap_router.py
frontend/tests/bootstrap/CreateAdminForm.test.tsx
```

All three are `003.first-run-bootstrap`'s files. Each is **edited**, and each edit is an
explicit Definition-of-done item below (`context.md` D15) so that nothing in them changes
incidentally.

## Interface intent

**`backend/app/services/bootstrap.py`** — the create-first-administrator operation is
**widened by one insert and one returned value**. Inside the **same** `with conn.begin():`
block it already opens (`003/context.md` D8 — apply the registry, mint the id, hash the
password, insert the `users` row) it now also opens a session for the administrator it just
created, through step `001`'s open-session operation on the **same connection**, and its
plain result grows to carry the **token** and the **expiry** beside the id, username and
role it already returned. It therefore takes the **session TTL in hours** as an additional
plain argument.

Everything else about the module is unchanged: the configured predicate, the
`already_configured` re-check at the top of the block, the values written into `users`, and
the properties that it **never imports `fastapi`, never sees a `Request` and never knows a
status code**. It still sets **no cookie** — it returns a token, and the router is what
makes that a cookie (`context.md`'s routers-versus-services constraint).

One transaction rather than a second service call from the router, because `003`'s D8
property is the one being extended: schema, administrator and session commit together or
nothing happened, so there is no instance where the administrator exists and the operator
who created them is not signed in.

**`backend/app/routers/bootstrap.py`** — `POST /api/bootstrap/create` gains the settings
dependency and FastAPI's response object, passes `Settings.session_ttl_hours` into the
service, and sets the session cookie through step `002`'s cookie writer before answering
its **201**. Its status code, its request and response models, and its router-level
`require_unconfigured` guard are all unchanged, and **`app/models/bootstrap.py` is not
touched**: the token travels in the cookie, so the response body's shape is exactly what
`003` shipped.

**`frontend/src/bootstrap/CreateAdminForm.tsx`** — the hand-off's **default target becomes
`/`** instead of `/login`. It remains a plain document navigation
(`window.location.assign`) and remains injectable so a test can observe it. Nothing else in
the component changes: the three fields, the client validation, the disabled submit, the
field/general error mapping, the refusal-flips-the-page behaviour and the absence of any
`notifyFailure` call are all `003/005`'s and stay exactly as they are.

## Definition of done

1. `[test]` `POST /api/bootstrap/create` on an unconfigured instance answers **201** and
   sets a `Set-Cookie` for the configured session cookie name, with the flags
   `context.md` D6 fixes — `HttpOnly`, `SameSite=Lax`, `Path=/`, no `Secure`, and a
   `Max-Age` matching `Settings.session_ttl_hours`. (US-001.AC-2)
2. `[test]` The cookie that response sets is a live session: `GET /api/me` with it answers
   **200** and reports the newly created administrator's id, username and role — with no
   login in between. (US-001.AC-2)
3. `[test]` Afterwards the database holds exactly **one** `auth_sessions` row, belonging to
   the new administrator, not revoked, with an `expires_at` of its creation instant plus
   the configured TTL. (US-001.AC-2)
4. `[test]` The response **body** still carries no token, session or expiry field — only
   the administrator's id (as a decimal string), username and role. This is the surviving
   half of `003/003` DoD-2; **its `Set-Cookie` half is deleted as part of this step** and
   replaced by DoD-1 above, deliberately and not incidentally (`context.md` D15).
5. `[test]` The creation remains **atomic across all three writes**: when the operation
   cannot complete, the connection is left with **neither** an administrator row **nor** an
   `auth_sessions` row, so no instance is reachable in which one exists without the other.
   The test provokes the failure through the operation's own inputs, not by patching its
   internals.
6. `[test]` The refusal path is untouched: the same request against a **configured**
   instance still answers **409** with the `already_configured` envelope, creates **no**
   `auth_sessions` row, and sets **no** cookie. (US-003.AC-1)
7. `[test]` The creation operation's `003`-era guarantees all still hold — the registry is
   applied, exactly one `users` row exists with the administrator role, `is_enabled` true,
   a `password_hash` that is not the plaintext and NULL language columns, and the id is
   minted from the generator it was **given**. `003/002` DoD-13's clause that the step
   "mints no token" is **deleted** here; its "declares no `auth_sessions` table", "sets no
   cookie" (the service still sets none) and "adds no setting" clauses stay true and stay
   asserted. (US-001.AC-1, `context.md` D15)
8. `[test]` `services/bootstrap.py` still imports no `fastapi` symbol, references no HTTP
   status code and takes no `Request`, and still sets no cookie — it returns a token and a
   plain result.
9. `[test]` On a successful create the `bootstrap` form's hand-off runs **once** and targets
   **`/`**, not `/login`. This **corrects** `003/005` DoD-5's target; the rest of that item
   — that the hand-off runs, and runs once — is unchanged, and every other assertion in
   that test file stays intact. (US-001.AC-2)
10. `[test]` Nothing else in the `bootstrap` form changes: an invalid draft still cannot
    submit, a second activation while one submit is in flight still issues no second
    request, the request body still carries the username and password and nothing else,
    an `already_configured` answer still flips the page to the refusal, and every other
    failure still renders in place.
11. `[manual/live]` The widened creation is still **one** `with conn.begin():` block,
    now covering the registry application, the administrator insert **and** the session
    insert. Verifier confirms by reading the module — DoD-5 asserts the behaviour, but the
    single-block shape is the thing later features must not split.
12. `[manual/live]` `app/models/bootstrap.py` is unchanged, and no new setting was added:
    `session_cookie_name` and `session_ttl_hours` already exist. Verifier confirms by
    reading the two files.
13. `[manual/live]` Against a running backend with no database: filling the bootstrap form
    and submitting creates the administrator, lands on **`/`** already signed in — `GET
    /api/me` in the browser's devtools answers 200 without a login — and re-opening the
    bootstrap entry afterwards shows the refusal. This is UC-001 including US-001.AC-2,
    followed by UC-003. `003/005` DoD-11's `/login` target is **corrected** to `/` by this
    item.
14. `[manual/live]` `mypy app`, `ruff check .` and `pytest` pass from `backend/`, and
    `npm run typecheck`, `npm test` and `npm run build` pass from `frontend/`.

## Dependencies

Steps `001` (the open-session operation) and `002` (the cookie writer). Step `003` is not
required by this step's code, but its `GET /api/me` route is what DoD-2 and DoD-13 observe
the cookie through.
