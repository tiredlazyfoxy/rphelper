# Step 005 — The `login` entry: the form, its submit, and the hand-off to `/`

## Goal

Replace the `login` entry's placeholder route table with the sign-in screen: a credential
draft with pure validators, a submit that posts once, one message for every refusal, and a
hand-off to `/` on success.

## Source files

```
frontend/src/login/loginDraft.ts
frontend/src/login/LoginPage.tsx
frontend/src/login/main.tsx
```

## Test files

```
frontend/tests/login/loginDraft.test.ts
frontend/tests/login/LoginPage.test.tsx
```

No test file of an earlier feature is edited here — `002/006`'s entry, ids and conventions
scans all stay true unchanged (see `005.context.md`).

## Interface intent

**`frontend/src/login/loginDraft.ts`** — the draft and its free functions, following
`002`'s D2 and `003`'s D13 (`context.md`'s store constraint).

- **A draft data class** holding observable fields only — the username, the password, a
  server-error map with a general key, and whether a submit is in flight — with
  `makeAutoObservable(this, {}, { autoBind: true })` in the constructor and **no methods
  and no computed getters**. A fresh instance per mount.
- **A pure client-validation function** taking the draft and returning the field-keyed
  client errors: username required and non-empty **after trimming**, password required and
  non-empty. It validates on trimmed values but **changes nothing that is sent**
  (`context.md` D13). No length floor, no character classes, no strength meter —
  `docs/product/` states no password policy and none is invented.
- **A pure submittability function** taking the draft and answering whether it may be
  submitted: no client errors and no submit in flight.
- **An effectful submit function** taking the draft and an optional `AbortSignal`. It
  posts the username and password **exactly as typed** to `POST /api/auth/login` through
  the request function in `frontend/src/shared/api.ts`, `runInAction`s the in-flight flag
  around the call, early-returns on an aborted signal before writing, and resolves to a
  **plain outcome value** the caller acts on: *signed in* or *failed*. On failure it maps
  the thrown `ApiError` onto the draft's server-error map **by code or status, never by
  parsing prose** (`002`'s D6): the code `invalid_credentials` maps to **one fixed message
  on the general key**, and everything else lands on the general key too. It performs
  **no navigation of its own**, reads **no field of a successful response**, and calls
  `notifyFailure` nowhere (`context.md`'s failures-render-in-place constraint).

  **There is no per-field mapping for a refusal.** A message on the username field would
  say "this username is the part that is wrong", which is exactly the distinction
  `context.md` D1 refuses to make.

**`frontend/src/login/LoginPage.tsx`** — an `observer` component taking the draft
**explicitly as a prop**, plus an optional hand-off function defaulting to the **document
navigation to `/`** (`window.location.assign`) so a test can supply its own. It renders two
Mantine text inputs — username, and password **masked** — the client and server errors on
their fields, the general server error as an inline `Alert`, and one submit control that is
disabled while a submit is in flight or while the draft is not submittable. On the *signed
in* outcome it calls the hand-off, **unconditionally and with no role branch**
(`context.md` D12). On *failed* it renders and stays put.

It also carries the entry's **stable marker** so `002/006`'s per-entry test keeps holding
unchanged, issues **no request on mount**, imports no stylesheet, and has **no icon-only
action** — so `shared/IconButton` does not appear; if one is ever added it goes through
`IconButton` (`ui-conventions.md`).

**`frontend/src/login/main.tsx`** — the placeholder route table is **replaced wholesale**,
as `002/006` anticipated. Everything else about the module stays exactly as `002` built it:
it finds the mount element, creates the React root, renders `shared/AppProviders` wrapping
a `BrowserRouter` with **no `basename`**, and imports no stylesheet. The route table
becomes a catch-all rendering the page above, with the draft created through
`useState(() => new …Draft())` — never `useMemo` — in whatever component owns it.

## Definition of done

1. `[test]` The client-validation function reports an error for an empty or
   whitespace-only username and for an empty password, and reports none for a filled
   draft.
2. `[test]` The submittability function is false whenever any client error exists and
   false while a submit is in flight, and true only for a valid draft with no submit in
   flight.
3. `[test]` The submit control is disabled for an invalid draft and while a submit is in
   flight, and a second activation while one is in flight issues **no** second request.
4. `[test]` A successful submit issues exactly **one** `POST /api/auth/login` carrying the
   username and password **byte-for-byte as typed** — whitespace and case preserved, no
   normalization — and nothing else in the body. (US-004.AC-1, `context.md` D13)
5. `[test]` On success the hand-off runs **once** and targets **`/`**. (US-004.AC-2)
6. `[test]` The entry performs **no role branch** and reads no field of the response: the
   same hand-off to `/` happens whatever role the body reports, and it happens for a body
   the page never inspects at all. (US-004.AC-2, `context.md` D12)
7. `[test]` A submit answered with the `invalid_credentials` refusal renders **one fixed
   message in the general alert**, leaves the form mounted and usable with the entered
   username preserved, runs **no** hand-off, and places **no** message on the username or
   password field. (US-005.AC-2)
8. `[test]` A refusal caused by a **disabled account** is indistinguishable from a wrong
   password in what the page renders — same message, same place, same remaining form —
   because the client cannot tell them apart and must not try. (US-006.AC-2,
   `context.md` D1)
9. `[test]` Any other failure renders **in place** in the general alert and navigates
   nowhere: a transport failure, a malformed-body error at a 5xx status, and a 422 all
   land there, and **no not-ready-yet screen is rendered** (`context.md` D14).
10. `[test]` The password is never rendered in readable form, and no value of either field
    appears in the general message the form shows.
11. `[test]` An aborted submit writes nothing onto the draft and renders no failure.
12. `[test]` The entry issues **no request on mount** — in particular **no `/api/me`** —
    and issues its only request in response to a submit.
13. `[test]` `notifyFailure` is called nowhere in this entry, and the draft is a data class
    with observable fields only — no method, no computed getter — with every derivation and
    effect a free function taking it.
14. `[test]` The `login` entry still carries its stable entry marker and still declares
    **no router `basename`**, so `002/006`'s DoD-1 and DoD-4 hold unchanged; and no module
    under `frontend/src/login/` imports a stylesheet.
15. `[manual/live]` Against a bootstrapped backend: signing in with correct credentials
    lands on `/` with the session cookie set, and `GET /api/me` in devtools answers 200
    afterwards. Signing in with a wrong password shows the one message and **stays on the
    login screen** — the page does not reload. (US-004.AC-1, US-005.AC-2)
16. `[manual/live]` US-007.AC-2 end to end: with a session that has been revoked or has
    expired, an authenticated call from a loaded document returns the person to the login
    screen. The mechanism is **inherited, not rebuilt** — the shared API client's 401 →
    document navigation to `/login` is `002/004` DoD-10, and the 401 itself is step `003`
    DoD-9.
17. `[manual/live]` Navigating the browser to **`/login`** (no trailing slash) serves the
    login document — the path the API client's 401 rule and `003`'s bootstrap refusal link
    both target. If it does not, that is the nginx/root-fallback seam `002/outcome.md`
    records and `fast/001` owns; report it rather than working around it here.
18. `[manual/live]` Both colour schemes are correct for the form, its field errors and its
    general alert.
19. `[manual/live]` `npm run typecheck`, `npm test` and `npm run build` all pass from
    `frontend/`, and the build still emits exactly the four entry documents.

## Dependencies

Step `003` — the login route's contract. It binds to that contract, not to the service
