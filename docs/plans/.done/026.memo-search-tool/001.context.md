# Step 001 — step-specific context

Feature-wide facts — D1, D2, the (A)/(B) interface list, the binding rule for `## Skeleton`
records, the test conventions — are in `context.md`. Only what is narrow to this step is
below.

## Touch site — `services/memo_chain.py` (A, built)

- `resolve_chain` builds its OR-terms inline as `and_(memos.c.scope == X, memos.c.scope_id
  == stored_id)`, one per existing level, omitting setup when the session's `setup_id` is
  None. It does an owner-scoped session read first and raises `SessionNotFoundError`.
  `MemoChainLevel.scope_id` is None for the user level **in its return value**, but the
  stored `memos.scope_id` for a user-level note is the user id — the builder uses the user
  id.
- The builder takes the relation as a parameter (not the module-level `memos` table)
  because 025's extra-predicate builder receives "the base relation the port uses as its
  FROM object", which may be an alias. Build the terms from that relation's `.c.scope` and
  `.c.scope_id`.
- Re-routing `resolve_chain` is optional (D2). If the coder does it, the resulting rows and
  order must be identical; the existing memo-chain tests are the regression guard, and the
  verifier's full-suite run is what checks them.

## Port binding — 025 (B, pending)

- The memo scope variant name (`MemoSearchScope` in 025's step prose) and its builder
  parameter name come from 025's `## Skeleton`. It must not be confused with
  `models/memos.py`'s `MemoScope` literal.
- 025 D7: `search` rolls back its own autobegun read transaction. `search_memos` still
  guarantees "no transaction open" itself on both exits (a `finally` that rolls back when
  `connection.in_transaction()`), because the guarantee is 026's contract to 021's seam and
  must not depend on the port's error path.
- 025's `search` hydrates memo hits with an owner-scoped read and fills `scope` /
  `scope_id`; nothing here re-reads memos.

## Test seeding notes

- Every note in DoD-6..11 shares one distinctive token (e.g. `Kaelith`) in its body, so the
  lexical arm would match it, and has a `memo_vec` row (written with `write_vector` from the
  fake's vector for its body), so the vector arm would rank it. An absence therefore means
  the predicate excluded it.
- `memo_fts` must exist **before** the memos are raw-inserted (its insert trigger indexes
  them), or be created after — 024's ensure back-fills on creation. Either order works.
- The B collision notes of DoD-9 are constructible because `scope_id` has no FK: insert
  `(user_id=B, scope='session', scope_id=<A's session id>)` etc.
- DoD-1 and DoD-4 compile against SQLite's dialect with `literal_binds` and inspect the
  text; DoD-4 compares the positions of `is_enabled` and `is_forced` in that text.
- DoD-13 reads the module source as text (as earlier plans' import tests do).
