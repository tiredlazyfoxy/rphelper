# Step 002 — The `memo_search` Tool adapter and its registration

## Goal

Implement 021's `Tool` protocol for `memo_search` in `services/tools/memo_search.py`: run
step `001`'s sync search off the event loop on the seam's connection, using only
`ToolScope` ids, and format hits into the model content and the summary (D3–D6). Register it
in the production registry in `services/tools/seam.py`, and amend the 021 tests that pinned
that registry as empty.

## Interface intent

**`app/services/tools/memo_search.py`** (new)

- **The adapter class** — implements 021's `Tool` protocol structurally.
  - `name` is `memo_search`.
  - Construction takes optional keyword `client_factory` and `timeout_seconds`. When they
    are omitted, `search_memos`'s own defaults apply. Tests inject the 024 fake factory here.
  - **async `run(scope, connection, arguments)`** → `ToolOutcome`:
    1. Reads `query` from `arguments`. If it is missing or not a string, it raises
       `ToolFailedError` (detail: the tool name). No other key is read (D6).
    2. Awaits `asyncio.to_thread` of step `001`'s `search_memos`. It passes the given
       connection, the `ToolScope`'s user id, character id, setup id (or none) and session
       id, the query, and the injected factory and timeout when set (D3).
    3. Returns `ToolOutcome(content, summary)` built by the formatter below.
    Errors from the search propagate unchanged (D5). No transaction is left open (step
    `001` guarantees this for the search, and `run` issues nothing else).
- **Formatter** (module-level, pure): takes the ordered hits and returns the content and the
  summary per D4.
  - **Content.** Each line is `[<scope>] <snippet>`, with the snippet's whitespace runs
    collapsed to one space and its ends stripped. Lines are joined by `\n` and keep the hit
    order. With no hits, the content is exactly `No matching notes.`
  - **Summary.** Exactly `<N> memos`.
- **Import shape.** The seam imports this module to register it, so this module must not
  import `services/tools/seam.py` at import time. Types are imported for type-checking only,
  and `ToolOutcome` is imported where it is constructed (`002.context.md`).

**`app/services/tools/seam.py`** (021-owned, changed)

- **Production registry** — now maps exactly `memo_search` to a default-constructed adapter
  instance. It stays a read-only mapping. Nothing else in the seam changes.

## Definition of done

1. `[test]` **Content and order.** With a designated model and the fake factory, `run` for
   a with-setup scope whose chain holds searchable notes at all four levels carrying the
   token returns content whose lines are `[<level>] <snippet>`. There is one line per
   expected note. Each level literal matches the note's level. The line order equals
   `search_memos`'s hit order for the same query. (D4, UC-051, US-063.AC-1)
2. `[test]` **Summary.** For that call, the summary is exactly `4 memos`. For a chain with
   one matching note it is `1 memos`. No summary contains any note body's text, including
   the distinctive token. (D4, 021 D6)
3. `[test]` **One line per hit.** A searchable note whose body has the token next to
   newlines and tabs produces a single content line with no newline or tab inside it. (D4)
4. `[test]` **Zero hits is success.** A query matching nothing in the chain returns content
   exactly `No matching notes.` and summary exactly `0 memos`. It raises nothing. (D4)
5. `[test]` **Exclusions hold through the tool.** A forced note, a disabled-not-forced note,
   a disabled-forced note, B's note colliding on A's session `(scope, scope_id)`, and A's
   note on another session all carry the token. None of their body text appears in the
   content. The searchable note's line does appear. (UC-052, US-100.AC-2, US-064.AC-1)
6. `[test]` **No setup.** `run` with a `ToolScope` whose setup id is none returns one line
   each for the user-, character- and session-level notes, and raises nothing.
   (US-065.AC-1)
7. `[test]` **Ids only from the scope.** `run` with arguments that also carry B's
   `user_id`, B's `session_id`, a `character_id`, a `setup_id` and a `scope` returns the
   same content as with `{"query": …}` alone, and nothing of B's appears. (D6, R5, US-064.AC-1)
8. `[test]` **Bad arguments.** `run` with `{}`, and with a non-string `query`, raises
   `ToolFailedError`. (D5)
9. `[test]` **Off the loop.** `run`, awaited inside a running event loop (`asyncio.run` of a
   coroutine that awaits it) with a designated model and the fake factory, returns hits and
   raises no "event loop is running" error. (D3)
10. `[test]` **No transaction left open.** After a successful `run`, and after a `run` that
    raised `NoEmbeddingModelError`, the connection it was given reports no transaction in
    progress. (D5, 021 D6)
11. `[test]` **Registration.** The production registry holds exactly one entry, under
    `memo_search`. Its value has `name` `memo_search`. With all three switches on,
    `offered_tools` over the production registry returns exactly the `memo_search`
    declaration, unchanged from `definitions.py`, with the single parameter `query`.
    (D3, 021 D5)
12. `[test]` **Failure through the real seam.** 021's `dispatch` is given a registry
    holding the real adapter, `memo_search` among the offered names, a `ToolScope` for A's
    session, arguments `{"query":"<token>"}`, and **no designated embedding model**. It
    raises nothing. Its frame is tool-fail with tool `memo_search` and code `tool_failed`.
    Its tool message content is exactly `The tool failed. Continue without its result.`
    One failed tool row is written. (US-066.AC-1, UC-051 exception flow, R9)
13. `[test]` **Success through the real seam.** The same `dispatch` with a designated model
    and an adapter built with the fake factory returns a tool-result frame whose summary is
    `<N> memos`, for N the expected hit count. Its tool message content equals the
    formatter's content for those hits. (UC-051, 021 D6)
14. `[test]` **Import shape.** In a fresh interpreter, importing
    `app.services.tools.memo_search` alone succeeds, and importing
    `app.services.tools.seam` alone succeeds (no import cycle). Neither module imports
    `fastapi`. (D3)
15. `[test]` **021 assertions amended.** The amendments to `test_tool_seam.py`
    (021 `004` DoD-2, DoD-10) and to `test_compose_route.py` (021 `006` DoD-10) are made as
    `002.context.md` states. Every other test in both files passes unchanged. (D3)
16. `[manual/live]` With a real chat model and a designated embedding model, the session's
    memo-search switch on and searchable notes in the chain: the assistant calls
    `memo_search` and its answer reflects a searchable note. With the embedding designation
    removed, the same exchange shows a `tool_fail` frame and **still produces a final
    answer** (`done`). (US-066.AC-1, UC-051, `llm-and-streaming.md` "The tool-calling loop")
