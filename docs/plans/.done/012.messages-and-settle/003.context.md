## The parser, as spec (D8)

Line breaks are `\n`; `\r` has no special meaning. "Whitespace" is Python's
`str.isspace` set; "trimming" removes leading and trailing whitespace in that sense.

**`classify(text)`** → `"decision"` **iff** the text, after trimming, **starts with `((`
and ends with `))`**. Otherwise `"turn"`. (User decision.) Nothing between the outer
`((` and `))` is inspected, so:

- `"((x))"`, `"  ((x))  \n"`, `"((first line\nsecond line))"`, `"((one)) ((two))"`,
  `"((a)) prose ((b))"`, `"(((x)))"` and `"(())"` are all decisions;
- `"((hint)) She walks."` (does not end with `))`), `"She walks. ((x))"` (does not start
  with `((`), `"(( never closed"`, `"a single (paren) pair"` and `""` are turns.

A three-character text cannot both start with `((` and end with `))`, so no overlap case
exists. A **decision's text is filed verbatim**: never stripped, never trimmed. The user
accepts that a message like `"((a)) prose ((b))"` is filed as a decision with its prose and
both instructions intact.

**Fragment** (used only by stripping). Scanning left to right, a fragment starts at a `((`
and ends at the **first** `))` that begins after it (the shortest span; it may cross line
breaks). Fragments do not overlap; scanning resumes after the `))`. A `((` with no later
`))` is not a fragment and is plain text. (Equivalent to the non-greedy,
dot-matches-newline pattern `\(\(.*?\)\)` applied left to right.)

**`strip_fragments(text)`** — applied by settle to turns only:

1. If the text contains no fragment, return it **unchanged** (byte-for-byte).
2. Remove every fragment **together with the run of spaces and tabs immediately before
   it** (not line breaks).
3. Replace every run of line breaks that contains **three or more** `\n`, where the only
   characters between them are spaces and tabs, with exactly `\n\n` (one blank line).
   Markdown renders any number of blank lines as one, so this changes no rendering.
4. Trim the whole result.

`strip_fragments` is a pure function and does not consult `classify`; settle decides which
of the two applies.

**The empty-turn edge case — it cannot occur, including for malformed input.** For a turn
to strip to empty (or to whitespace only), every non-whitespace character of its text must
lie inside some fragment. Fragments begin with `((` and end with `))`, so the trimmed text
would then begin with the first fragment's `((` and end with the last fragment's `))`:
that text classifies as a **decision**, which is never stripped. Malformed input does not
change this:

- an unbalanced `((` with no later `))` is not a fragment, so it survives stripping and the
  turn is non-empty (`"((a)) (("` → `"(("`);
- a stray `)` or `(` outside every fragment survives (`"((a)))"` is a decision anyway;
  `"x ((a))"` → `"x"`);
- a `))` with no `((` before it is plain text and survives.

So settle never needs an "empty turn" refusal, and none is specified.

**Known oddities, recorded, not designed for:** nested or tripled parentheses inside a
**turn** split oddly under the shortest-span rule (`"x (((y))) z"` → `"x) z"`). US-130's
Constraint states double parentheses never occur in the roleplayer's RP prose (R12's
recorded assumption), so no case is designed for them and no test pins them.

## Settle — the statement sequence (one `begin()`)

1. Session check: `SELECT sessions.id FROM sessions WHERE id = :session_id AND user_id =
   :user_id` → none → `SessionNotFoundError`.
2. Zone: `current_zone` narrowed by `session_id` and `user_id`, ordered by id ascending
   (id and text are what is needed). Empty → `ZoneEmptyError`.
3. Head = last row. `kind = classify(head.text)`; settled text = `head.text` for a
   decision, `strip_fragments(head.text)` for a turn.
4. If there are other zone rows: `UPDATE messages SET related_to = :head_id, updated_at =
   :now WHERE id IN (:other_ids) AND user_id = :user_id`. Burying by the id list read in
   step 2 keeps the burial set exactly the zone the transaction saw.
5. `UPDATE messages SET settled_at = :now, kind = :kind, text = :text, updated_at = :now
   WHERE id = :head_id AND user_id = :user_id`.
6. Bump: `UPDATE sessions SET last_used_at = :now, updated_at = :now WHERE id = … AND
   user_id = …`.

**Step 4 precedes step 5 and the order is load-bearing** (`backend-structure.md`): once
the head carries `settled_at` it has left the zone. With the CHECK in place, stamping the
head first and then burying by a zone predicate would bury nothing.

## Re-open — the statement sequence (one `begin()`)

1. Session check (as above).
2. Zone non-empty (`current_zone` narrowed by session and owner, any row) →
   `ZoneNotEmptyError`.
3. Last settled: `settled_entries` narrowed by session and owner, ordered by id
   **descending**, limit 1. None → `NothingToReopenError`.
4. Group: `SELECT messages.id FROM messages WHERE related_to = :head_id AND user_id =
   :user_id ORDER BY id`. This is the one raw `select()` on `messages` outside the
   selectables, and it is allowed **here only** (settle / re-open, R11). Empty →
   `NothingToReopenError`.
5. `UPDATE messages SET related_to = NULL, updated_at = :now WHERE id IN (:group_ids) AND
   user_id = :user_id`, then `UPDATE messages SET settled_at = NULL, kind = NULL,
   updated_at = :now WHERE id = :head_id AND user_id = :user_id`. Either order satisfies
   the CHECK (no row ever has both set).
6. Bump the session.

## Test seeding

Users A and B, a character and a session each, raw-inserted. **All `messages` rows in this
step's tests are raw inserts** (zone rows with `role` `'user'` or `'assistant'`, settled
rows, born-settled partner rows with `kind='partner'`, buried rows) with explicitly chosen
ascending ids, so the test file does not depend on step `002`. A "lone decision" (DoD-18)
is a single zone row with a wholly-parenthesised text settled through `settle`. DoD-22 sets
`sessions.archived_at` with a raw update. DoD-6 and DoD-23 read the modules' source text
from disk.
