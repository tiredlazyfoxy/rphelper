# Step 002 — The messages service

## Goal

Add `services/messages.py`: a frozen `StreamMessage` value and five owner-scoped
operations — read the record, read the zone, append a roleplayer message to the zone, file
a born-settled partner block, and edit the text of a current-zone message — each reading
only through the schema layer's selectables (D1, D7), bumping the session on every write
(D3), and never touching the burial / settle columns of an existing row (D16).

## Source files

backend/app/services/messages.py

## Test files

backend/tests/test_messages_service.py

## Interface intent

Every operation takes the Core `Connection` first and the owner's `user_id` (int) as a
**required positional** argument after it (after the id generator, for the two inserts).
Each returns `StreamMessage` values or raises a domain error, and imports nothing
HTTP-shaped and nothing from any `app.services.` module.

- **`StreamMessage`**: frozen dataclass value with `id` (int), `session_id` (int), `role`,
  `kind` (string or `None`), `text`, `settled_at` (string or `None`), `created_at`,
  `updated_at`. No `user_id`, no `related_to`, no tool columns.
- **`list_entries`**: takes the connection, `user_id` and a session id. Raises
  `SessionNotFoundError` when the session is missing or not the caller's; otherwise
  returns the session's settled rows (through `settled_entries`) in ascending id order. A
  read: writes nothing, leaves no transaction open on either exit.
- **`list_zone`**: same inputs and errors; returns the session's current-zone rows
  (through `current_zone`) in ascending id order. A read, as above.
- **`append_message`**: takes the connection, the id generator, `user_id`, a session id
  and the text. In one write transaction: session check; mint the id; insert one row with
  `role` `'user'`, `kind` / `related_to` / `settled_at` NULL, the text verbatim,
  `created_at` = `updated_at` = the operation's instant; bump the session. Returns the new
  row's value. Makes no model call.
- **`file_partner_entry`**: takes the connection, the id generator, `user_id`, a session id
  and the text. In one write transaction: session check; mint the id; insert one row with
  `role` `'user'`, `kind` `'partner'`, `related_to` NULL, `settled_at` = `created_at` =
  `updated_at` = the operation's instant, the text verbatim (no parsing, R12); bump the
  session. Returns the new row's value. No zone precondition (D14).
- **`edit_message_text`**: takes the connection, `user_id`, a message id and the new text.
  In one write transaction: classify the target through `message_states` (owner-scoped by
  id) — no row → `MessageNotFoundError`; buried or settled → `MessageNotEditableError`
  (D2); otherwise update that row's `text` (verbatim, no parsing) and `updated_at`, bump
  its session, and return the row as read back through `current_zone`.

There is no delete, no discard and no settle-state operation in this module.

## Definition of done

1. `[test]` `append_message` on the caller's session returns a `StreamMessage` whose `id`
   is the value the supplied generator minted, with that `session_id`, `role` `'user'`,
   `kind` `None`, `settled_at` `None`, the text exactly as given, and `created_at ==
   updated_at` in the fixed-width form. `list_zone` then contains it and `list_entries`
   does not. The stored row has `related_to` NULL. (UC-083 step 2, R11)
2. `[test]` Three `append_message` calls on one session leave all three in `list_zone`, in
   ascending id order equal to the order of the calls; nothing refuses a second or third
   zone message. (US-125.AC-1 — the zone is a set, needs no constraint)
3. `[test]` `file_partner_entry` returns a value with `role` `'user'`, `kind` `'partner'`,
   `settled_at` set and equal to `created_at` and `updated_at`, and the text exactly as
   given. `list_entries` contains it and `list_zone` does not; the stored row has
   `related_to` NULL. (US-121.AC-1, R11 single exception)
4. `[test]` `file_partner_entry` with text `"She smiles. ((ooc: brb)) Then leaves."` and
   with text `"((whole thing))"` stores and returns each text **byte-for-byte unchanged**,
   with `kind` `'partner'` in both cases (never `'decision'`). (US-121.AC-2, R12)
5. `[test]` Several `file_partner_entry` calls in a row, and a `file_partner_entry` while
   the zone holds an appended message, all succeed; `list_entries` returns the partner
   rows in ascending id order and the zone row is untouched. (UC-031 several partner blocks
   in sequence, D14)
6. `[test]` `list_entries` and `list_zone` each return exactly their own state from a
   session raw-seeded with one zone row, one settled row and one buried row: the buried
   row appears in **neither**. (R11, R7 "a buried group never reaches a reader")
7. `[test]` Each of the five operations called with another user's session (or a message of
   another user's session, for `edit_message_text`) raises `SessionNotFoundError` (or
   `MessageNotFoundError`), the same as for an id that exists for nobody; afterwards the
   other user's rows and session are unchanged and no `messages` row was inserted. (R5)
8. `[test]` `edit_message_text` on a current-zone row stores the new text verbatim — a text
   containing `((fragment))` keeps it — moves the row's `updated_at` forward (not
   backward) while `created_at` is unchanged, leaves `kind`, `settled_at` and `related_to`
   NULL, and returns the edited value. The row stays in `list_zone` at the same position.
   An assistant-role zone row (raw-inserted) is editable the same way. (US-115.AC-1, D2,
   R12)
9. `[test]` `edit_message_text` on a raw-seeded **buried** row raises
   `MessageNotEditableError`; on a **settled** row (a filed partner block, and a
   raw-seeded settled turn) raises `MessageNotEditableError`; in each case the row's text
   and `updated_at` are unchanged and the session is not bumped. (US-116.AC-1, D2)
10. `[test]` Bump: after each of `append_message`, `file_partner_entry` and
    `edit_message_text`, the session's `last_used_at` and `updated_at` both equal the
    written row's `updated_at`. After `list_entries` and `list_zone` the session's
    `last_used_at` and `updated_at` are unchanged. A refused operation (DoD-7, DoD-9)
    leaves them unchanged. (D3, 011 D3)
11. `[test]` On an **archived** session (raw `archived_at` set), all five operations
    succeed exactly as on a working one, and the session stays archived. (R6)
12. `[test]` After `list_entries` and `list_zone` (including when they raised
    `SessionNotFoundError`), the connection is not in a transaction, so a following
    `connection.begin()` succeeds.
13. `[test]` Source check of `app/services/messages.py`: no `select(...)` call takes the
    `messages` Table or any of its columns as an argument (it reads only through
    `settled_entries`, `current_zone`, `message_states`); it contains no `delete(` call
    and no `DELETE` SQL keyword; it imports nothing from `fastapi`, from any `app.services.`
    module, or named `parens`; and it never assigns the `related_to` column in an insert
    or update. (D1, D7, D11, D16, R12)
