## Which re-read follows which mutation

| Effect | Success re-reads | Failure re-reads |
|---|---|---|
| send on *my turn* (append) | zone | zone |
| send on *partner* (file) | entries | entries |
| file pasted partner | entries | entries |
| settle (with or without append) | entries + zone | append failed: zone only; settle failed: entries + zone |
| re-open | entries + zone | entries + zone |
| zone edit | none (the PATCH response replaces the row) | zone |

The settle / re-open results' ids are **not** used to patch the lists (012 D11); the
re-read is the reconciliation.

## Draft clearing under concurrency

The composer stays editable while a request is in flight. If the roleplayer typed after
pressing Send, the draft no longer equals the text sent, and the draft is left alone after
success — the sent text is now in the zone and the newly typed text stays in the composer.
A test for this is not required; the rule is stated so the coder does not write an
unconditional clear.

## Abort posture

An effect checks the signal after every `await` and returns before writing anything —
including `busy`, the draft and any `notifyFailure` call — once it is aborted. The signal
comes from `SessionStream`'s unmount controller (`007`); an aborted request rejects with
the original abort error, which is not an `ApiError` and must not be notified.
