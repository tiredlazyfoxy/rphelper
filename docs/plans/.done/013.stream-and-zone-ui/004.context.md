## Rendering fragments inline

`react-markdown` wraps prose in block elements (`p`). A chip that must sit between two
prose segments of the same paragraph needs the prose segments rendered without forcing a
block break between them — for example by mapping `p` to an inline-flowing element for
segments that sit inside a paragraph. The exact mechanism is the coder's; the contract is
DoD-3 (DOM order) plus the `[manual/live]` look in `007`. Multi-paragraph prose must still
render its paragraphs.

## Why `data-paren`

The chip and the card have no natural ARIA role; a data attribute is the stable, visible
contract the tests and later features (`014`, `022`) can find, without an `aria-label`
that would override the element's text.

its default icon is not wanted (pass none).
