# Step 001 — `search/my_search.py`: cap, read posture and the two LIKE corpora

## Goal

Create `services/search/my_search.py` with the per-kind cap (D2), the local read-posture
helper (D6), and the character and setup searches: escaped, case-insensitive substring
`LIKE` over two columns each, owner-scoped, archived rows included and flagged (`context.md`
U2, U3, D2, D3).

## Source files

backend/app/services/search/my_search.py

## Test files

## Interface intent

**`app/services/search/my_search.py`** (new)

- **Per-kind cap constant** — the value `20` (D2). Name frozen by the skeleton.
- **Local read-posture helper** — private; replicates `services/memos.py`'s `_reading`
  (D6): runs reads and rolls back the autobegun transaction on return and on raise. Steps
  `001` and `002` both use it.
- **`CharacterHit`** — a frozen value: character id, name, archived (bool).
- **`SetupHit`** — a frozen value: setup id, name, the setup's character id, that
  character's name, archived (bool — the **setup's own** `archived_at`).
- **`search_characters`** — inputs: a connection, the user id, the raw query text, and a
  limit (defaults to the cap). Strips the query; blank → `[]` with no SQL issued. Otherwise
  returns the user's characters whose `name` **or** `sheet` contains the stripped text as a
  case-insensitive substring (D3), each once, ordered by `name` then `id` ascending, at most
  `limit`. Archived characters are included. User input never acts as a wildcard. Reads
  only; leaves no transaction open.
- **`search_setups`** — same contract over the user's setups, matching `name` **or**
  `description`, hydrating the owning character's name through an owner-scoped join (both
  tables carry the `user_id` predicate). Archived setups are included; a setup under an
  archived character is included too.

## Definition of done

1. `[test]` The cap constant equals `20`. (D2)
2. `[test]` **Characters by name and by persona.** User A has characters "Mira" (sheet
   about a lighthouse), "Corvin" (sheet mentioning "Mira's brother") and "Tess" (unrelated
   sheet). Query `mira` returns Corvin and Mira — matched on sheet and on name, case folded
   — once each, in name order (Corvin, Mira), with their ids, names and `archived` false.
   Tess is absent. (US-074.AC-1, U2, D2, D3)
3. `[test]` **Setups by name and by description.** Query matching one setup's name and
   another setup's description (different case) returns both, in name order, each carrying
   its own id, name, its character's id and its character's name. A non-matching setup is
   absent. (US-074.AC-1, U2)
4. `[test]` **Owner isolation (absence).** User B owns a character and a setup whose names
   and texts equal A's matching ones. A's results contain none of B's ids, for both kinds;
   B's own search returns only B's rows. (US-076.AC-1, UC-065, R5)
5. `[test]` **Archived included and flagged.** An archived character and an archived setup
   that match are returned with `archived` true; their unarchived siblings with `archived`
   false. A non-archived setup whose character is archived is returned with `archived`
   false. (U3)
6. `[test]` **Wildcards are literal.** With characters named "100% sure", "100 sure",
   "a_b" and "axb": query `%` returns only "100% sure"; query `_` returns only "a_b";
   query `100%` returns only "100% sure"; query `a_b` returns only "a_b". A name containing
   a backslash is found by a query containing that backslash, and a query containing a
   backslash matches nothing else. The same holds for setups (one representative case).
   (D3)
7. `[test]` **Blank and stripping.** `""`, `"   "` and `"\n\t"` return `[]` for both kinds.
   Query `"  Mira  "` returns the same rows as `"Mira"`. A query of two words matches only
   rows containing both words **adjacent, as typed** (one substring, not split). (D3)
8. `[test]` **Limit.** With 25 matching characters, `search_characters` returns 20 by
   default and exactly 3 with `limit=3` — the first 3 in name order. (D2)
9. `[test]` **No transaction left open.** After each call — a hit, a blank query, and a
   call made while the connection is mid-read — the connection reports no transaction in
   progress. (D6)
10. `[test]` `my_search.py` imports no `fastapi`. (`context.md` constraints)
