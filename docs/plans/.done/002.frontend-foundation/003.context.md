# Step 003 — step-specific context

Feature-wide facts are in `context.md`; the constraint this step holds is the
every-icon-only-action-goes-through-`IconButton` rule, which is stated there and not
repeated.

## The verbatim declaration this step reproduces

`docs/architecture/ui-conventions.md` § "Every icon-only action goes through a shared
`IconButton`" gives the props type verbatim, and § "Sizing convention" gives the
three-row table verbatim. The skeleton agent reproduces both from the doc.

## The one thing the docs leave open, and the choice made

The sizing table gives an explicit stroke only for the `"main"` row; the other two rows
list a size and nothing else. **All three variants use stroke 1.5.**

The reason: `ui-conventions.md` opens the Icons section with *"One family, for one
visual weight."* A stroke that changed between variants would be a second visual weight
in the same family, which is the thing that sentence forbids. The table omits the
stroke on the smaller rows because it does not change, not because it differs. Recorded
in `outcome.md` so the omission is closed rather than re-guessed.

## The boundary this component does not cross

`ui-conventions.md` resolves the tension between `IconButton` and the table overflow
menu **by scope**, and the resolution lives at the call site, not in this component:

| Place | Pattern |
|---|---|
| Toolbars, headers, the composer, inline controls | `IconButton` |
| Table rows | one overflow `Menu` behind a single `IconDots` trigger — which itself is an `IconButton` — and no other icon-only control in the row |

This component enforces nothing about that; it is the admin and workspace features'
rule. Noted here only so nobody adds a `rowAction` variant to the props type.

## Why the props type is not widened

Four things a reader may expect and which are deliberately absent: no `children`, no
`variant` prop, no `size` escape hatch beside `sizeVariant`, and no `aria-label`
override. Each would reintroduce exactly the divergence the `label`-feeds-both rule
exists to prevent, or would let a call site opt out of the sizing table. If a later
feature genuinely needs one, it is an architecture change, not a prop.

## Gotcha — asserting the tooltip

Mantine's `Tooltip` renders its content only once the control is hovered or focused,
and it uses a floating layer outside the button's own subtree. DoD-2 therefore needs
the tooltip triggered before its text can be read. `@testing-library/user-event`'s
hover, or a focus, is the trigger; the assertion is that the text found equals the
accessible name found on the button.

## Gotcha — asserting the icon's size and stroke

The `icon` prop is a **component type**, not an element. The cleanest way to observe
what it received is to pass a test double in place of a Tabler icon — an ordinary
function component that renders something inspectable from the props it was given. The
test-coder does not need a real Tabler icon for any of DoD-5, DoD-6 or DoD-7.

## Gotcha — disabled and the tab order

Mantine's `ActionIcon` renders a native `button`. A disabled native button is not in
the tab order and does not fire click handlers, which is what DoD-4 and DoD-8 assert.
Do not substitute an `aria-disabled` styling approach — that would satisfy neither.
