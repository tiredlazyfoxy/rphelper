# Step 003 — The shared `IconButton` and the icon sizing convention

## Goal

Create the one component every icon-only action in the product goes through, folding
`ui-conventions.md`'s three-row sizing table into a single `sizeVariant` prop and making
one `label` prop the source of both the tooltip text and the accessible name.

## Interface intent

**`frontend/src/shared/IconButton.tsx`** exports:

- **the props type**, exactly as `ui-conventions.md` declares it verbatim: an `icon`
  that is a component accepting a size and a stroke; a required `label`; a required
  `onClick` taking no arguments and returning nothing; an optional `disabled`; an
  optional semantic `color` that is a Mantine colour; and an optional `sizeVariant`
  that is one of `"main"`, `"inline"` or `"chevron"`.
- **the component**. It renders a Mantine `Tooltip` whose label is the `label` prop,
  wrapping a Mantine `ActionIcon` whose accessible name is that **same** `label` prop,
  which in turn renders the `icon` component with the size and stroke the `sizeVariant`
  resolves to. The `color` prop is passed to the `ActionIcon` and **never** to the icon
  — colour is decided in one place, by the element that also decides hover and disabled
  states, and the icon itself stays `currentColor`. `disabled` is passed through to the
  `ActionIcon`.

The size map is `ui-conventions.md`'s table: `"main"` (main, header and composer
actions) resolves to size 18, `"inline"` to 16, `"chevron"` to 14. All three carry the
**same** stroke weight, 1.5 — see `003.context.md` for why. `"main"` is the default
when `sizeVariant` is omitted, because it is the table's first and most common row.

The `ActionIcon` variant is `"subtle"`: an icon-only action is secondary chrome, and
Mantine's default filled variant would render roughly thirty solid coloured boxes
across the product. The docs specify no variant; this is recorded in `outcome.md`.

The module exports nothing else — no per-call-site convenience wrappers and no icon
re-exports.

## Definition of done

1. `[test]` The rendered control is a button with an accessible name equal to the
   `label` prop.
2. `[test]` The `label` prop feeds **both** the accessible name and the tooltip text —
   the tooltip's content, once shown, is the same string as the accessible name. There
   is no second prop that can make the two disagree.
3. `[test]` `onClick` is invoked when the control is activated.
4. `[test]` When `disabled` is set, the control is disabled and activating it does not
   invoke `onClick`.
5. `[test]` `sizeVariant="main"` renders the icon at size 18, `"inline"` at 16 and
   `"chevron"` at 14, each with stroke 1.5.
6. `[test]` Omitting `sizeVariant` is equivalent to `"main"`.
7. `[test]` A `color` passed to `IconButton` is applied to the button and **not** to
   the icon — the icon receives no colour prop and no colour is set on the icon
   element itself.
8. `[test]` The control is keyboard-activable: it is reachable by tab order when
   enabled, and removed from it when disabled.
9. `[manual/live]` The control renders correctly under **both** the dark and the light
   colour scheme.
10. `[manual/live]` `npm run typecheck` passes, and the exported props type matches
    `ui-conventions.md`'s declaration field for field.
