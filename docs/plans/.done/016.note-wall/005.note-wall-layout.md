# Step 005 — The wall's state, its layout component and its stylesheet rules

## Goal

Add `app/noteWallState.ts`: the wall's data class (`pinned` from the layout record,
`open` not persisted) with the mode, visibility and class derivations and the open /
pin-toggle / dismiss actions (D2). Add `app/NoteWallLayout.tsx`, which renders the
session screen's two-part layout: a stream column and the wall `aside` with its pin and
close controls. The wall is mounted always, and is inert and hidden from assistive
technology while closed (D3). Add the colourless layout rules to `shell.css` and amend
the stylesheet guard's allowed selectors (D11).

## Interface intent

**`app/noteWallState.ts`** (new; React-free, DOM-free)

- **`NoteWallState`**: data class, observable fields only: `pinned` (boolean) and `open`
  (boolean, starts false). It is constructed from the initial `pinned` value.
- **`createNoteWallState`**: takes a `LayoutStorage` or `null`. Returns a state whose
  `pinned` is `readWorkspaceLayout(storage).wallPinned` and whose `open` is false.
- **`wallMode`**: pure. Takes the state and `narrow`. Returns `"pinned"` when `pinned`
  and not narrow, `"floating"` otherwise.
- **`isWallVisible`**: pure. Takes the state and `narrow`. True when the mode is pinned,
  or when `open`.
- **`sessionLayoutClassName`**: pure. Takes the state and `narrow`. Returns
  `"app-session"`, plus `" wall-pinned"` when the mode is pinned.
- **`wallClassName`**: pure. Takes the state and `narrow`. Returns `"app-wall"`, plus
  `" wall-open"` when the mode is floating and the wall is visible.
- **`openWall`**: action. Takes the state. Sets `open` true. Writes nothing.
- **`toggleWallPin`**: action. Takes the state and the storage. When unpinned, sets
  `pinned` true and writes `{ wallPinned: true }` through `writeWorkspaceLayout`. When
  pinned, sets `pinned` false and `open` true, and writes `{ wallPinned: false }`.
- **`dismissWall`**: action. Takes the state, the storage and `narrow`. Sets `open`
  false. When the mode was pinned (pinned and not narrow), it also sets `pinned` false and
  writes `{ wallPinned: false }`. In floating mode, a narrow pinned wall included, it
  writes nothing.

**`app/NoteWallLayout.tsx`** (new)

- **`NoteWallLayout`**: `observer` component. Props: `state` (a `NoteWallState`),
  `narrow` (boolean), `storage` (a `LayoutStorage` or `null`), `stream` (the stream
  column's content) and `wall` (the wall's content). It renders one root element with
  `sessionLayoutClassName`, holding, in this order:
  - a stream column element (class `app-stream`) with `stream` in it;
  - the wall: a Mantine `Paper` rendered as an `aside` named **"Note wall"**, with
    `wallClassName`, a Mantine `shadow` only while floating and visible, and no radius.
    It holds a header row with the pin toggle (`IconButton`, `IconPin`, **"Pin notes"**
    / **"Unpin notes"**, given a `color` while `pinned`, running `toggleWallPin`) and
    the dismiss control (`IconButton`, `IconX`, **"Close notes"**, running
    `dismissWall`), then `wall`.
  - While not visible, the `aside` carries `inert` and `aria-hidden="true"`.
- The `aside` is always rendered, at the same place in the tree, in every mode, so
  `wall` never remounts when the mode or visibility changes. There is no notification.
  The "Open notes" control is **not** here; it belongs to the session header (`006`).

**`shell.css`** (extended)

- Appends the six rules of D11 (`.app-session`, `.app-session.wall-pinned`,
  `.app-stream`, `.app-wall`, `.app-wall.wall-open`,
  `.app-session.wall-pinned .app-wall`). They declare layout, positioning, sizing,
  overflow, transform and transition only, with no colour and no typography. No new media
  query. `.app-main` may gain a height or display declaration if the session root needs
  it to fill the column. No other existing rule changes.

## Definition of done

1. `[test]` `createNoteWallState` with a storage whose record has `wallPinned` true gives
   `pinned` true and `open` false. With `null` storage, an absent key, or unparseable
   JSON it gives `pinned` false and `open` false. (US-094.AC-2; `workspace-shell.md`
   "open does not survive")
2. `[test]` `wallMode` / `isWallVisible` over the full table: pinned, not narrow →
   `"pinned"`, visible whether or not `open`. Pinned, narrow → `"floating"`, visible only
   when `open`. Not pinned, either width → `"floating"`, visible only when `open`. (D2;
   `workspace-shell.md` "below 820px a pinned wall reverts to floating")
3. `[test]` `sessionLayoutClassName` is exactly `"app-session wall-pinned"` in pinned mode
   and `"app-session"` otherwise. `wallClassName` is exactly `"app-wall wall-open"` when
   floating and visible, and `"app-wall"` otherwise (pinned, or closed). (D11)
4. `[test]` `openWall` sets `open` and leaves the stored record untouched (no `setItem`
   call). (US-094.AC-1; open is not persisted)
5. `[test]` `toggleWallPin` from unpinned sets `pinned` and stores `wallPinned: true`
   under `"rphelper.workspace-layout"`. A stored `navCollapsed: true` stays true in the
   same record. From pinned, it sets `pinned` false and `open` true and stores
   `wallPinned: false`. (US-094.AC-2; D2 — unpinning leaves the wall floating and open;
   write merges)
6. `[test]` `dismissWall` with a pinned state at wide width sets `open` and `pinned` false
   and stores `wallPinned: false`. With a pinned state at narrow width and `open` true it
   sets `open` false and leaves `pinned` true, with no write. With an unpinned open state
   it sets `open` false, with no write. (UC-072 steps 4–5; D2's narrow interpretation)
7. `[test]` `NoteWallLayout` with a closed floating state: the stream content is
   accessible. No complementary landmark is found by role without `{ hidden: true }`. With
   `{ hidden: true }` the "Note wall" aside is found, carries `inert` and
   `aria-hidden="true"`, and contains the `wall` content. (US-095 partner; D3 — mounted
   while closed)
8. `[test]` After `openWall`: the complementary "Note wall" is accessible, shows "Pin
   notes" and "Close notes", has neither `inert` nor `aria-hidden`, and carries class
   `wall-open`. The root lacks `wall-pinned`. (US-094.AC-1 — over the stream)
9. `[test]` With a pinned state at wide width: the root carries `wall-pinned`, the wall is
   accessible with "Unpin notes", and it has no `wall-open` class. With the same state and
   `narrow` true, the root lacks `wall-pinned` and the wall is not accessible until
   `openWall`. (D2, D11)
10. `[test]` Pressing "Pin notes" stores `wallPinned: true` and relabels the control
    "Unpin notes". Pressing "Unpin notes" stores `wallPinned: false` and leaves the wall
    accessible. Pressing "Close notes" makes the wall not accessible. (UC-072, US-094.AC-2)
11. `[test]` A `wall` child that counts its mounts mounts **once** across open, close,
    pin, unpin and a `narrow` flip. A `wall` child holding typed text in an uncontrolled
    input keeps it across close and reopen. (D3)
12. `[test]` `tests/stylesheets.test.ts`: `ALLOWED_SELECTORS` is the five existing
    selectors plus exactly `.app-session`, `.app-session.wall-pinned`, `.app-stream`,
    `.app-wall`, `.app-wall.wall-open`, `.app-session.wall-pinned .app-wall`. Every
    existing guard still passes against the extended `shell.css`: exactly two
    stylesheets, every selector allowed, no colour, no font or typography, no import, no
    `@font-face`, and the media query byte-identical with `NARROW_VIEWPORT_QUERY`. (D11)
13. `[manual/live]` In a browser at a wide window: the floating wall slides in from the
    stream's right edge, about 320px wide, with a shadow, over the stream. Pinned, it is
    a 320px column beside the stream with no shadow, and the switch does not animate. A
    closed wall adds no horizontal scrollbar. Below 820px the floating wall is at most
    84vw wide and a sliver of stream stays visible. Both colour schemes read correctly.
    (`workspace-shell.md` geometry, US-094.AC-1)
