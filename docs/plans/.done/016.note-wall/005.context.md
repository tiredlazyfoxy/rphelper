# Step 005 — step-specific context

Feature-wide facts are in `context.md`: **D1** (geometry and why the wall is the session
screen's), **D2** (state, modes, actions, the narrow-dismiss interpretation), **D3**
(mounted while closed, `inert` + `aria-hidden`), **D10** (icons and labels), **D11** (the
six selectors, shadow via Mantine, the revert decided in TypeScript), the strings table,
and Test conventions (the storage fake, the closed-wall query). Only what is narrow to
this step is below.

## Borrowed interfaces

- `app/workspaceLayout.ts` (built, not edited): `LayoutStorage`, `readWorkspaceLayout`,
  `writeWorkspaceLayout`, `WORKSPACE_LAYOUT_KEY`. The write already merges over a fresh
  total read and swallows errors. Do not re-implement either.
- `app/shellState.ts` (built, not edited): the precedent. `createShellState(storage)`,
  `shellClassName(...)` and its pure class derivation are the shape to mirror. This
  module does **not** import `shellState.ts`. `NARROW_VIEWPORT_QUERY` is imported only
  where `narrow` is computed (`006`).
- `shared/IconButton.tsx`: `icon`, `label`, `onClick`, `color?`.
- `@tabler/icons-react`: `IconPin`, `IconX` (both in the installed ^3.40).
- Mantine `Paper` (`component="aside"`, `shadow`, `radius`), `Group`, `Box`.

## File names

`noteWallState.ts` and `NoteWallLayout.tsx` differ in more than letter case, so the
case-insensitive filesystem concern does not arise. Do not add a `noteWall.ts` or
`NoteWall.tsx` beside them.

## Actions are synchronous

The three actions write two booleans and (sometimes) one localStorage record. There is no
request, no `await` and no signal. They are MobX actions (`runInAction` or
`makeAutoObservable`-bound free functions writing inside an action). They still do not
reject or throw: `writeWorkspaceLayout` swallows storage errors.

## `inert` and `aria-hidden`

React 19 accepts `inert` as a boolean attribute. Render it as present or absent, never as
the string `"false"`. `aria-hidden="true"` sits on the same `aside` element. When the
wall is visible, both are absent.

## The `aside`'s name

`aria-label="Note wall"` on the `aside`. Do not label it by the inner "Notes" heading:
that would give the complementary landmark and the region inside it the same name (D4).

## CSS notes for the coder

- `.app-session` must establish the positioning context (`position: relative`) and clip
  overflow so the closed wall (translated by 100%) adds no scrollbar. It must fill the
  available height so `.app-stream` scrolls on its own. If `.app-main` needs a height or
  display tweak for that, it is the one existing rule that may change. Say so in
  `## Files Changed`.
- The `.app-wall` transition is on `transform` only, and is short (around 150–200ms). The
  pinned override removes it, so the pinned column does not animate.
- No colour, shadow, border colour or font in `shell.css`. The `Paper` supplies the
  background and, while floating, the shadow.
- Do not add a `@media` block. The existing one's string must stay byte-identical.

## The stylesheet guard

`tests/stylesheets.test.ts` holds `ALLOWED_SELECTORS` as a literal list. DoD-12 extends
that literal with the six selectors, in any order the file's shape allows. Every other
assertion in the file is left as it is and must pass.

## Test notes

- `noteWallState.test.ts` needs no DOM. Build states with `new NoteWallState(…)` or
  `createNoteWallState(fake)`.
- `NoteWallLayout.test.tsx` renders inside `AppProviders`, with no router. `stream` and
  `wall` are small test elements. A mount counter is a `useEffect` with an empty
  dependency list incrementing a test variable.
- Narrow is a prop here, so no `matchMedia` stub is needed in this step.
- Class assertions read `className` on the root (the stream column's parent) and on the
  `aside`. The classes are the CSS contract (D11), which is why they are asserted.
