## Interface intent

**`app/setupDraft.ts`** (new)

- **`SetupDraft`**: data class, observable fields only, constructed from a `characterId`
  (string) and the setup being edited (a `Setup`, or `null` for create):
  - `characterId`, `original` (the `Setup` or `null`): as constructed;
  - `name`, `description`: start as the original's values in edit mode, empty in create
    mode;
  - `submitStatus`: `"idle"` or `"submitting"`;
  - `error`: the inline failure text, or `null`.
- **`isEditing`**: pure. True when `original` is non-null.
- **`isDirty`**: pure. In edit mode, true when `name` or `description` differs from the
  original's. In create mode, true.
- **`canSubmit`**: pure. True when the trimmed `name` is non-empty, nothing is
  submitting, and the draft is dirty.
- **`submitSetup`**: effect. Takes the draft, an `onSaved` callback receiving the
  server-returned `Setup`, and an optional signal. Clears `error`, sets `"submitting"`,
  then in create mode POSTs `name` and `description` to the draft's character, or in edit
  mode PATCHes both to the original's id. On success it calls `onSaved` with the returned
  row. On failure it sets `error` to **"Could not create the setup."** /
  **"Could not save the setup."** and keeps the typed values. Either way it returns to
  `"idle"`. Writes nothing once aborted, never rejects. The name is sent as typed (009
  `006.context.md`, "Name sent as typed").
- Two small setters, **`setDraftName`** and **`setDraftDescription`**, each taking the
  draft and a string and writing the field as a MobX action.

**`app/SetupModal.tsx`** (new)

- **`SetupModal`**: `observer` component, mounted only while the modal is open. Props:
  `characterId` (string), `setup` (a `Setup` to edit, or `null` to create), `onClose`, and
  `onSaved` (receives the returned `Setup`). Creates its `SetupDraft` once with `useState`
  (fresh per mount, `ui-conventions.md` "Draft lifetime") and an `AbortController`
  aborted on unmount. Renders a Mantine `Modal`, open, with:
  - title **"New setup"** (create) or **"Edit setup"** (edit);
  - an inline `Alert` with the draft's `error` when non-null, above the fields;
  - a text input labelled **"Name"** bound to the draft name;
  - `MarkdownEditor` labelled **"Description"** bound to the draft description,
    `readOnly` while submitting;
  - a **"Cancel"** button calling `onClose`, and a labelled submit **"Create"** (create;
    `IconPlus` left section) or **"Save"** (edit; `IconDeviceFloppy` left section),
    disabled unless `canSubmit`. Pressing it `void`s `submitSetup` with an `onSaved` that
    calls the prop `onSaved` (the parent applies the row and closes the modal).
  - The modal's own close (the X / Escape / overlay) calls `onClose`.
- No notification is raised anywhere.

## Definition of done

1. `[test]` A create-mode draft has empty `name` / `description`, `isEditing` false, and
   `canSubmit` false for an empty or whitespace-only name and true once the name has a
   non-space character. An edit-mode draft built from a setup starts with that setup's
   `name` / `description`, `isDirty` and `canSubmit` false, and both become true when
   either field changes. While `submitStatus` is `"submitting"`, `canSubmit` is false. (D2)
2. `[test]` Create-mode `submitSetup` POSTs `/api/characters/<characterId>/setups` with the
   draft's `name` and `description`. On the 201 it calls `onSaved` exactly once with the
   returned setup, and `submitStatus` is back to `"idle"`. (US-023.AC-1)
3. `[test]` Edit-mode `submitSetup` PATCHes `/api/setups/<original id>` with both `name`
   and `description`, and calls `onSaved` with the response's setup (for example a
   server-trimmed name). (D2)
4. `[test]` A failed `submitSetup` sets "Could not create the setup." (create) or "Could
   not save the setup." (edit), does not call `onSaved`, keeps the typed values, returns
   to `"idle"` and resolves without throwing. A submit after a failure clears the previous
   `error` before its request. With its signal aborted before the response settles, it
   writes nothing and does not call `onSaved`. (D12)
5. `[test]` `SetupModal` with `setup` null renders a dialog titled "New setup" with an
   empty "Name" textbox, a "Description" textbox, a "Cancel" button and a disabled
   "Create" button. Typing a name enables "Create" and sends no request. (D2)
6. `[test]` `SetupModal` in create mode: entering a name and a description and pressing
   "Create" POSTs once with them. On the 201 `onSaved` is called once with the response's
   setup, and no notification is shown. (US-023.AC-1)
7. `[test]` `SetupModal` with a setup renders a dialog titled "Edit setup" whose "Name"
   and "Description" hold that setup's values and whose "Save" is disabled. Changing the
   description enables "Save". Pressing it PATCHes `/api/setups/<id>` with both fields and
   calls `onSaved` with the response. (D2)
8. `[test]` A failed submit shows the failure sentence inside the dialog, the dialog stays
   open, `onSaved` is not called, the typed values are still in the fields, and no
   notification is shown. (D12)
9. `[test]` Pressing "Cancel" calls `onClose` and sends no request. While a submit is in
   flight the submit button is disabled and the Description editor is read-only.
10. `[manual/live]` In a browser, the modal opens over the character screen, the
    Description editor's toolbar works inside it, and Escape closes it.
