# Step 002 — The setups service

## Goal

Add `services/setups.py`, the one layer that issues SQL against `setups`. It holds a
frozen `Setup` value and six owner-scoped operations (list under a character, create under
a character, get, update, archive, restore). It verifies the parent character with its own
scoped select (D6), follows archive semantics per D9 and order per D10, and has no delete
operation (R5, R6) and no path that creates a setup implicitly (R2).

backend/app/services/setups.py

backend/tests/test_setups_service.py

## Interface intent

Every operation takes the Core `Connection` first and the owner's `user_id` (int) as a
**required positional** argument after it. Each returns `Setup` values or raises a domain
error. Each never imports or raises anything HTTP-shaped.

- **`Setup`**: frozen dataclass value: `id` (int), `character_id` (int), `name`,
  `description`, `archived_at` (string or `None`), `created_at`, `updated_at`. No
  `user_id`.
- **`list_setups`**: takes the connection, `user_id`, a `character_id` and an
  `include_archived` flag. Raises `CharacterNotFoundError` when the character does not
  exist **for that user** (an archived character is fine). Otherwise returns that
  character's setups, working only unless the flag is true, ordered newest created first
  (D10). A read: leaves no transaction open.
- **`create_setup`**: takes the connection, the id generator, `user_id`, a
  `character_id`, `name` and `description`. In one write transaction it verifies the
  parent (raising `CharacterNotFoundError` when it is missing or foreign, inserting
  nothing), mints the id, stamps `created_at` = `updated_at` with one instant, leaves
  `archived_at` NULL, writes `user_id` from the argument, and returns the created value.
  Stores `name` and `description` as given (validation is the request model's, `001`).
- **`get_setup`**: takes the connection, `user_id` and a setup id. Returns the setup,
  archived or not, or raises `SetupNotFoundError`. A read: leaves no transaction open.
- **`update_setup`**: takes the connection, `user_id`, a setup id, an optional `name` and
  an optional `description` (`None` = not supplied). Writes only supplied fields and bumps
  `updated_at`. With neither supplied it writes nothing and returns the current row. It
  never changes `character_id` or `archived_at`. Raises `SetupNotFoundError`.
- **`archive_setup`**: takes the connection, `user_id` and a setup id. Sets `archived_at`
  and bumps `updated_at` when the setup is working; on an archived one it writes nothing
  and returns it with its original `archived_at`. Touches no table but `setups` (D3).
  Raises `SetupNotFoundError`.
- **`restore_setup`**: same inputs. Sets `archived_at` to NULL and bumps `updated_at`
  when archived; on a working one it writes nothing. Raises `SetupNotFoundError`.

There is **no** delete operation.

## Definition of done

1. `[test]` `create_setup` under the user's character returns a `Setup` whose `id` is the
   value the supplied generator minted, with that `character_id`, the given `name` and
   `description`, `archived_at` `None`, `created_at == updated_at`, and both timestamps in
   the fixed-width form `YYYY-MM-DDTHH:MM:SS.ffffff+00:00`. `get_setup` then returns an
   equal value, and `list_setups` for that character contains it. (US-023.AC-1)
2. `[test]` `create_setup` and `list_setups` with **another user's** character id, or a
   character id that exists for nobody, raise `CharacterNotFoundError`. After the refused
   create the `setups` table holds no new row. (R5, D6, D8)
3. `[test]` `create_setup` and `list_setups` under the user's **archived** character
   succeed. (D5)
4. `[test]` With two users each owning a character with setups, `list_setups` returns only
   the addressed character's setups, both with and without `include_archived`. Setups of
   the user's other character are not included. (R5)
5. `[test]` `list_setups` without the flag excludes archived setups. With the flag it
   returns working and archived together. In both cases three setups created in sequence
   come back newest → oldest. (US-087.AC-1, R6, D10)
6. `[test]` `get_setup`, `update_setup`, `archive_setup` and `restore_setup` called with
   **another user's** setup id raise `SetupNotFoundError`, and the owner's row is
   unchanged afterwards (same name, description, `archived_at`, `updated_at`). The same
   four called with an id that exists for nobody raise the same error. (R5, D8)
7. `[test]` `update_setup` with only `name` changes the name and keeps the description;
   with only `description` the reverse; with both, both. Each leaves `created_at` and
   `character_id` unchanged and `updated_at` not earlier than before. With neither it
   returns the current row with `updated_at` unchanged. The change is visible through a
   subsequent `get_setup`. (D5, as 009 D7)
8. `[test]` `archive_setup` on a working setup returns it with `archived_at` set in the
   fixed-width form. It is then absent from the default listing, present in the
   include-archived listing, and still returned by `get_setup`. Archiving it again returns
   the same `archived_at` and the same `updated_at`. (US-087.AC-1, R6, D9)
9. `[test]` `restore_setup` on an archived setup returns it with `archived_at` `None`, and
   it is back in the default listing. Restoring a working setup returns it unchanged (same
   `updated_at`). `update_setup` on an archived setup succeeds and leaves `archived_at`
   unchanged. (US-087.AC-2, D9)
10. `[test]` After a character row is inserted for a user (with no `create_setup` call),
    `list_setups` with `include_archived=True` for it returns an empty list. No operation
    of this module inserts a row other than `create_setup`. (R2)
11. `[test]` After `list_setups` and after `get_setup`, the connection is not in a
    transaction, so a following `connection.begin()` succeeds. This also holds after
    `list_setups` raised `CharacterNotFoundError`.
12. `[test]` The source text of `app/services/setups.py` contains no `delete(` call, no
    `DELETE` SQL keyword, no `fastapi` import, and no import from
    `app.services.characters`. (R6, D6, `backend-structure.md` "Routers versus services")
