# Step 008 — Frontend: authoring writes say why they were refused when embedding is unavailable

## Goal

When a memo create or save, a character save, or a setup create or save fails with
`no_embedding_model` or `llm_unreachable`, the UI shows a distinct sentence naming the
cause instead of the generic failure sentence. A small shared helper maps the code to a
sentence (`context.md` D8, Wire contract).

## Interface intent

**`src/shared/embeddingFailure.ts`** (new)

- **`embeddingFailureSentence`**: a pure function taking an unknown caught value. It
  returns the fixed sentence for an `ApiError` whose `code` is `no_embedding_model`, the
  fixed sentence for one whose `code` is `llm_unreachable`, and nothing (null) for anything
  else. The two sentences are module constants, exported so tests and callers do not
  re-type them (exact text in `008.context.md`).

**`src/app/memoLevelState.ts`**

- `saveNote` (~L160) and `saveNewNote` (~L231): in their existing catch, they surface the
  helper's sentence when it returns one, and otherwise the existing fixed sentence exactly
  as today. They surface it through the same channel they use today. Their signatures and
  every other behaviour are unchanged.

**`src/app/characterScreenState.ts`**

- `submitSave` (~L185): the same rule, through its existing failure field or notification.

**`src/app/setupDraft.ts`**

- `submitSetup` (~L85): the same rule, for both create and save.

## Definition of done

1. `[test]` `embeddingFailureSentence` returns the `no_embedding_model` sentence for an
   `ApiError` with that code and status 409, and the `llm_unreachable` sentence for one
   with that code and 502. It returns null for `ApiError` codes `memo_not_found` and
   `not_authenticated`, for a plain `Error`, and for `undefined`. The two exported
   constants equal `008.context.md`'s texts exactly.
2. `[test]` `saveNote` against a stubbed `PATCH /api/memos/{id}` answering 409
   `{error:{code:"no_embedding_model",…}}` surfaces the `no_embedding_model` sentence. A
   stubbed 502 `llm_unreachable` surfaces the other sentence. A stubbed 500 with another
   code surfaces the pre-existing generic sentence, unchanged. (D8)
3. `[test]` `saveNewNote` against a stubbed `POST /api/memos` follows the same three cases.
   (D8)
4. `[test]` `submitSave` on the character screen against a stubbed
   `PATCH /api/characters/{id}` follows the same three cases. (D8)
5. `[test]` `submitSetup` against the stubbed setup create and save routes follows the
   same three cases for each. (D8)
6. `[manual/live]` On a live instance with no embedding model designated:
   - creating a note shows the `no_embedding_model` sentence and creates nothing;
   - editing the persona of a character that has sessions shows the same sentence and
     keeps the old persona.
