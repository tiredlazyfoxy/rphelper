## Sync-bridge notes

- `asyncio.run` creates and closes a fresh loop per call. That is why the handle's client
  is built per write operation and used for **one** `embed` call (D1). Reusing one client
  across two `asyncio.run` calls risks an httpx pool bound to a closed loop.
- Routes calling into this are sync `def`, so they run on a threadpool thread with no
  running loop. Calling `embed_texts` from inside a running loop would raise. No 024 caller
  does that.

## The fake (`tests/llm_fakes.py`) — what it must offer

- **A fake client** satisfying the registry's client protocol (only `embed` is exercised
  by 024). It needs:
  - a configured dimension;
  - an optional scripted error;
  - an optional wrong-length override;
  - a list of recorded calls `(model, tuple(texts))`.
- **A public pure function** mapping `(text, dim)` to a deterministic list of floats.
  Different texts should give different vectors, for example from a hash of the text. It
  must be exactly representable as float32, so a round-trip through
  `serialize_float32` compares equal.
- **A fake factory**: a callable matching the factory type. It returns one fake client,
  and records `(base_url, api_key, timeout)` per call plus a call count.
