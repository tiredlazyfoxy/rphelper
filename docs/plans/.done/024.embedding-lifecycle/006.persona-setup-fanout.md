# Step 006 — Persona and setup-text fan-out: strict re-embed of every affected session

## Goal

When `update_character` changes `sheet`, or `update_setup` changes `description`, every
session that text feeds (archived included) is refreshed **strictly** inside the same
transaction. This applies only when there is at least one such session. Creates, name-only
edits, unchanged text and archive / restore do no vector work (`context.md` D5, D8, U4).

## Interface intent

**`app/services/characters.py`**

- **`update_character`**: positional inputs and result unchanged. It gains keyword-only
  `client_factory` and `timeout_seconds` (D9 defaults).
  - **Only when `sheet` is given and differs from the stored sheet**, after the update and
    inside the same transaction, it lists `003`'s `session_ids_for_character` and passes
    them to `003`'s strict `refresh_session_vectors`.
  - With zero sessions this needs no model (U4).
  - "Unavailable" propagates, and the persona edit is not stored.
- `create_character`, archive and restore are unchanged.

**`app/services/setups.py`**

- **`update_setup`**: the same shape. When `description` is given and differs from the
  stored one, it fans out over `session_ids_for_setup`.
- `create_setup`, archive and restore are unchanged.

**`app/routers/characters.py`, `app/routers/setups.py`**

- Each PATCH handler depends on the shared `get_llm_client_factory` and `get_settings`, and
  passes the factory and the timeout through. Nothing else changes.

## Definition of done

1. `[test]` **Persona fan-out.** Character C has three sessions:
   - S1, active, with setup X;
   - S2, archived;
   - S3, active, with no setup.

   Each has a settled entry. With a designated model, `update_character` changes the sheet
   to "Tall, scarred, soft-spoken.". Afterwards:
   - each of S1, S2 and S3 has a `session_vec` row equal to the fake's vector for its
     composed text;
   - each recorded text begins with the new sheet;
   - the factory was called **once**, and one `embed` call carried all three texts.

   (US-021.AC-1, US-138.AC-1, U4)
2. `[test]` **Persona edit, unavailable, N > 0.** With **no** designated model,
   `update_character` changing the sheet raises `NoEmbeddingModelError`. With a fake
   raising, it raises `LlmUnreachableError`. In both cases the stored sheet is the old
   one, and every `session_vec` row is byte-identical to before. (D8, authoring fail-hard)
3. `[test]` **N = 0.** A character with no sessions has its sheet changed with no model
   designated. The change succeeds, is stored, and makes zero factory calls. (U4)
4. `[test]` **No vector work.** For a character with sessions and **no** model designated,
   these succeed with zero factory calls and leave the `session_vec` rows unchanged:
   - a name-only update;
   - an update whose sheet equals the stored sheet, with a new name.

   `create_character` with no model designated also succeeds with zero factory calls.
   (D5)
5. `[test]` **Setup fan-out.** Character C has these sessions:
   - S1, active, setup X;
   - S2, archived, setup X;
   - S3, setup Y;
   - S4, no setup.

   With a model, changing X's description refreshes exactly S1 and S2: the fake's single
   `embed` call carried two texts, each containing the new description. S3's and S4's rows
   are byte-identical. (US-138.AC-1, U4)
6. `[test]` **Setup edit, unavailable / N = 0 / no-op.** These mirror DoD-2 to DoD-4 for
   setups:
   - no model, or unreachable, with sessions on the setup → the error propagates, and the
     description and rows are unchanged;
   - a setup with no sessions → the change succeeds with no model;
   - a name-only edit, an unchanged description, and `create_setup` → zero factory calls.

   (D5, D8)
7. `[test]` **Routers**, with the factory and settings overrides:
   - `PATCH /api/characters/{id}` changing the sheet of a character with sessions, with no
     model → 409 `no_embedding_model`, and a following GET shows the old sheet;
   - with the fake → 200 with the new sheet;
   - `PATCH /api/setups/{id}` changing the description with a fake raising → 502
     `llm_unreachable`;
   - the same setup PATCH with no sessions on the setup and no model → 200.

   (Wire contract)
8. `[test]` **Regression fallout.** Existing tests in `test_characters_service.py`,
   `test_setups_service.py`, `test_characters_router.py` and `test_setups_router.py` that
   change a sheet or description on a character / setup **with sessions** pass again once
   they are given a designated model and the fake (or the overrides). Their assertions
   about character and setup behaviour are unchanged. (`context.md` Regression fallout)
