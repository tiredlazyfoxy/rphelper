# Step 007 — Frontend: the coverage flag in the stream state and the banner above the stream

## Goal

Read `search_coverage_incomplete` from the record-keeping responses into an observable flag
on `StreamState`. Render a non-blocking warning banner above the stream record while the
flag is set (`context.md` D10, D11; US-112.AC-2).

## Source files

frontend/src/app/streamApi.ts
frontend/src/app/streamState.ts
frontend/src/app/SessionStream.tsx

## Test files

frontend/tests/app/streamCoverage.test.ts

## Interface intent

**`src/app/streamApi.ts`**

- `SettleResult`, `ReopenResult` and `Message` each gain an **optional** boolean
  `search_coverage_incomplete` (D10). The API functions are unchanged. They already return
  the parsed body.

**`src/app/streamState.ts`**

- **`StreamState`** gains one observable boolean field, the coverage flag. It is `false` on
  construction. The class keeps holding data only.
- **The effects that already receive a record-keeping response** set the flag from it,
  inside `runInAction`, with an absent field read as false. Their other behaviour,
  signatures and failure handling are unchanged. The effects are:
  - settle (`settleComposer`);
  - re-open (`reopenLast`);
  - entry edit (`editEntry`), only when the returned message's `settled_at` is non-null;
  - partner filing (the partner branch of `sendComposer`, and `filePastedPartner`), only
    when the returned message's `settled_at` is non-null.
- Responses whose message has a null `settled_at` (zone rows) leave the flag as it is. A
  failed request leaves it as it is.

**`src/app/SessionStream.tsx`**

- In the ready branch, directly above the stream record, a Mantine `Alert` in the warning
  colour is rendered **only while the flag is set**. Its text is the sentence in
  `007.context.md`. It has no close button, and it disables nothing (the record, the editors
  and the composer stay usable). It is an observer of the existing state instance, and no
  new props are added.

## Definition of done

1. `[test]` After a successful settle whose stubbed response carries
   `search_coverage_incomplete: true`, the state's flag is true. A following successful
   settle whose response carries `false` makes it false. (US-112.AC-2, D11)
2. `[test]` A re-open response carrying `true` sets the flag. One with the field
   **absent** sets it false. (D10, D11)
3. `[test]` An `editEntry` whose response is a message with non-null `settled_at` and the
   flag `true` sets the flag. An edit response for a message with `settled_at: null` and the
   flag absent leaves a previously true flag true. (D11)
4. `[test]` Filing a pasted partner block whose response message is settled with the flag
   `true` sets it. A zone append's response (`settled_at: null`) does not change it. (D11)
5. `[test]` A failed settle (stubbed 409 `zone_empty`) leaves the flag unchanged.
6. `[test]` Rendered with the flag true, `SessionStream`'s ready view shows an alert
   (`role="alert"`) whose text is exactly `007.context.md`'s sentence. It is placed before
   the first record entry in document order, and the entry's edit affordance is still
   present and enabled. With the flag false, no such alert is rendered. (US-112.AC-2,
   `workspace-shell.md` banner)
7. `[test]` On a fresh mount, before any write, no banner is rendered, even when the
   initial stream load succeeds. (D11, U5)
8. `[manual/live]` On a live instance with no embedding model designated, settling a reply
   shows the banner, the entry appears in the record, and the composer remains usable.
   After an administrator designates a model, the next settle clears the banner.
