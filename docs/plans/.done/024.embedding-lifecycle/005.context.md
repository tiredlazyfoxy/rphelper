Feature-wide facts are in `context.md`: **D5**, **D8**, **D9**, **U5**, the **Wire

## Built state at the touch sites (harvest)

- `services/settle.py`:
  - `settle(connection, user_id, session_id) -> SettleResult(entry_id, kind, buried_ids)`.
    The head's text is rewritten (`strip_fragments`) **in the same UPDATE that sets
    `settled_at`**, and the zone rows are buried by setting `related_to`.
  - `reopen(connection, user_id, session_id) -> ReopenResult(reopened_id, restored_ids)`
    clears `settled_at` / `kind` on the head (the text is not restored) and restores the
    buried rows to the zone.
  - Both run inside `with connection.begin():`. `settle.py` imports `parens`. It will now
    also import `services/session_index.py`, which is a deliberate addition recorded in
    `outcome.md`.
- `services/messages.py`:
  - `append_message(...)` writes to the zone;
  - `file_partner_entry(connection, generator, user_id, session_id, text) -> StreamMessage`
    creates a row born settled, kind partner;
  - `edit_message_text(connection, user_id, message_id, text) -> StreamMessage` handles
    zone or settled rows, and raises for buried rows.
  - `StreamMessage(id, session_id, role, kind, text, settled_at, created_at, updated_at)`.
  - The edit classifies the row through `message_states` before writing. Use that
    classification to decide record row vs zone row.
- `models/stream.py`: `MessageResponse`, `SettleResponse(entry_id, kind, buried_ids)`,
  `ReopenResponse(reopened_id, restored_ids)`. Ids are `SnowflakeOut`.
- `routers/stream.py`: sync `def` handlers, mapping results with
  `model_validate(..., from_attributes=True)`.

## Placement

- **Settle / re-open:** the refresh is the last statement inside the existing `with`
  block, after every relational write. The composed text must observe the new state.
- **Edit:** right after the `messages` update, inside the same block. If 023 `001` has
  landed by build time, its `translations` delete sits there too, and the order between
  them is immaterial.
- **Partner filing:** after the insert, inside its block.

## Router note

`MessageResponse` may be the response model of other routes, such as the stream list. They
pick up the field from `StreamMessage`'s default (false). Do not change those handlers.
