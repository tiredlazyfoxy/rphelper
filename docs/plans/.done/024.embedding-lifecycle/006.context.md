# Step 006 — step-specific context

Feature-wide facts are in `context.md`: **D5** ("changed" means differs from stored;
archived included; N > 0), **D6** (persona and setup lead the text), **D8**, **D9**, the
**Wire contract** and **Regression fallout**. Only what is narrow to this step is below.

## Built state at the touch sites (harvest)

- `services/characters.py`:
  - `update_character(connection, user_id, character_id, name=None, sheet=None) ->
    Character` (PATCH `/api/characters/{id}`);
  - plus `create_character`, archive and restore, each in `with connection.begin():`.
- `services/setups.py`:
  - `update_setup(connection, user_id, setup_id, name=None, description=None) -> Setup`
    (PATCH `/api/setups/{id}`);
  - plus `create_setup`, archive and restore.
- Services do not import each other today. Both will now import
  `services/session_index.py`, which is a deliberate addition recorded in `outcome.md`.
- Neither service has a delete. The fan-out never has to handle a removed character or
  setup.

## Placement

- Read the stored sheet / description **inside the transaction, before the update**, to
  decide "changed". The service already reads the row to authorise the update.
- Run the fan-out after the update, as the last thing in the `with` block, so the composed
  texts read the new value.
- With N = 0, `refresh_session_vectors` is called with an empty collection, or the call is
  skipped. Either way, no model is resolved.

## Cost note (not a DoD)

A persona edit on a character with many sessions holds the write lock for the whole embed
round trip (D1), and sends every composed session text in one request. Its size grows with
the history. This is the accepted price recorded in `search-and-retrieval.md`, and the
progress-surface `_TBD:` stays open.
