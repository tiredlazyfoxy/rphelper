## Ordering inside the transaction

1. relational write;
2. FTS ensure;
3. if embedding: open the model, ensure the vector tables, embed `[body]`, write the row.

A raise anywhere rolls back the lot, including any DDL the ensure created. The FTS ensure
may equally run before the relational write, because back-fill and triggers give the same
end state. The order above is the default.

"Body changed" compares against the row as stored **before** the update. Read it inside the
same transaction, since the service already reads the row to authorise the update.
