# Step 006 — The compose route

## Goal

Mount `POST /api/sessions/{id}/zone/compose`: commit the roleplayer's text (or, textless,
check there is something to retry) on the handler's connection, then return 019's SSE
response over `005`'s source with the own-connection persister (D1, D2). Add the request model
and two overridable dependencies for the chat-client factory and the tool registry (D14).

## Interface intent

**`app/services/compose.py`** (changed)

- **`begin_compose`**: the synchronous, handler-side half. Inputs: the handler's connection,
  the id generator, the user id, the session id, the text or none. With text: appends it with
  012's `append_message` (committed in its own transaction; ownership → `SessionNotFoundError`)
  and returns the new row's id. Without: reads the zone with `list_zone` (ownership as above)
  and raises `ZoneEmptyError` when it has no row whose role is not `"tool"`; returns none.
  Never calls a model.

**`app/models/stream.py`** (changed)

- **A compose request model**: `text` optional (absent or JSON null = textless); when present
  it is refused as blank exactly as the existing zone-append request model refuses it (422).

**`app/routers/stream.py`** (changed)

- **Two dependencies**: one returning the chat-client factory (the real `LlmClient` class) and
  one returning the production tool registry (004). Tests override both.
- **`POST /api/sessions/{session_id}/zone/compose`**: `require_user`, `get_connection`,
  `get_id_generator`, settings, the two dependencies, the request. Calls `begin_compose`
  (its domain errors answer as JSON through the normal handler, before any stream), then
  returns `sse_response(request, compose_stream(engine=get_engine(settings), generator,
  user id, session id, accepted id, settings.llm_request_timeout_seconds, factory, registry),
  own_connection_persister(get_engine(settings), generator, user id, session id))`.
- The module docstring's "no compose route" statement is replaced by a description of the
  route.

## Definition of done

1. `[test]` `POST …/zone/compose` `{"text":"Write me a reply"}` with a fake client yielding
   `"Hi"` answers 200, `content-type` starting `text/event-stream`, header
   `X-Accel-Buffering: no`; the frames are `accepted` (`message_id` a decimal **string**),
   token `"Hi"`, `done` (`message_id` a decimal string, different from accepted's). A
   following `GET …/zone` lists the user row (that text, the accepted id) then the assistant
   row (`Hi`, the done id). (UC-034, UC-032, D1)
2. `[test]` When the fake client's `chat_stream` is first entered, a fresh connection already
   sees the user row in the zone: the text is committed before any model call. (R10, D1)
3. `[test]` A fake that raises `LlmUnreachableError` before yielding anything: frames are
   `accepted` then `error` with `code` `llm_unreachable` and a `message`, and no `done`; the
   zone holds the user row only; `GET …/entries` is unchanged. (US-044.AC-1, US-044.AC-2)
4. `[test]` A fake that yields `"Par"` then raises `LlmUnreachableError`: frames `accepted`,
   token `"Par"`, `error`; the zone then holds the user row and an assistant row with text
   `Par` (019 D4, end to end). (US-044.AC-1, US-132.AC-1)
5. `[test]` A session whose captured model is disabled → `accepted` then `error` code
   `model_not_enabled` with `detail.level` `"session"` and `detail.server_id` a string; with
   no enabled model on the instance → `no_model_enabled`; with no captured model →
   `model_not_chosen`. In each case the user row is in the zone and the factory was never
   called. (US-044.AC-2, US-107, R4, D3)
6. `[test]` Retry: after DoD-3's failure, `POST …/zone/compose` with `{}` (and, separately,
   with `{"text": null}`) answers a stream with **no** `accepted` frame, then tokens and
   `done`; the zone holds exactly one user row (no duplicate) followed by the assistant row;
   the messages the fake received equal those of the failed attempt. (US-044.AC-3, D2)
7. `[test]` The model is read at use time: between a failed compose and a textless retry the
   session's `model_server_id` / `model_name` are raw-updated to a second enabled server's
   model; the retry's factory call gets the second server's base URL and its client call gets
   the new model name. (R4, D2)
8. `[test]` Textless compose on an empty zone, and on a zone holding only a tool row, answers
   409 JSON `zone_empty` (not a stream); nothing is written and the factory is never called.
   (D2, D8)
9. `[test]` `{"text":"   "}` answers 422; another user's session and an unknown id answer 404
   `session_not_found` as JSON with no row written; no cookie answers 401. In all three the
   factory is never called. (R5, D1)
10. `[test]` With the real production registry dependency (not overridden) and all switches
    on, the fake client receives an empty tools list. (D5, U3)
11. `[test]` A server whose `api_key_ref` names an unset variable → `accepted` then `error`
    code `secret_ref_missing`; the user row is kept. (D14, R10)
12. `[test]` Any pre-existing assertion that the compose route is absent is updated; every
    other existing stream-router test passes unchanged. (D1)
13. `[manual/live]` With a real model and the 019 frontend: Send streams a reply; Stop
    mid-reply leaves the partial as an editable candidate after the reload with no failure
    notice; Settle mid-reply behaves per 019 D16/D17 (019 `005` DoD-12 becomes runnable).
    (US-132.AC-1, US-132.AC-2)
14. `[manual/live]` Stopping the provider mid-reply: the reason appears as a ~5 s
    notification, the typed text and any partial survive, and a textless compose (e.g. via a
    raw request until 022's control exists) after restarting the provider produces an answer.
    (US-044.AC-1..AC-4)
