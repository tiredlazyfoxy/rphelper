# Step 003 — `LlmClient.chat_stream` and chat-client construction

## Goal

Add the streaming chat-completions call to the one OpenAI-compatible client (D10), with the
provider-delta values it yields, and the registry-side helper that builds a chat client for a
validated model from its server's base URL and resolved credential (D14).

## Source files

backend/app/services/llm/client.py
backend/app/services/llm_registry.py

## Test files

backend/tests/test_llm_chat_stream.py
backend/tests/test_open_chat_client.py

`test_llm_client.py` is touched only to remove the two `chat_stream`-absence tests
(`003.context.md`).

## Interface intent

**`app/services/llm/client.py`** (changed)

- **Delta values** (frozen):
  - **`ToolCallDelta`**: `index` (int), `call_id` (string or none), `name` (string or none),
    `arguments` (an argument fragment string, or none) — exactly what one provider chunk
    carried for one call, unaccumulated.
  - **`ChatDelta`**: `content` (string or none), `reasoning` (string or none, from the
    delta's `reasoning_content` or else `reasoning`), `tool_calls` (immutable sequence of
    `ToolCallDelta`, possibly empty).
- **`chat_stream`**: an async-iterator method taking the model name, a sequence of 020/021
  `ChatMessage`s and a sequence of tool definition objects (JSON-ready mappings). It POSTs to
  the composed `…/v1/chat/completions` URL (same composition as `embed`) with JSON
  `{"model", "messages": [to_wire_message(m)…], "stream": true}` plus `"tools"` only when the
  sequence is non-empty, the bearer header when an API key is set, over an httpx **streaming**
  request on the client's own `AsyncClient` (timeout and `transport` as today). It reads the
  body line by line: a `data:` line's payload (one leading space dropped) is either `[DONE]`
  (stop) or JSON whose `choices[0].delta` becomes one `ChatDelta` (a chunk with no choices,
  or a delta carrying nothing, yields nothing); other lines are ignored; a clean end of body
  ends iteration. Failures raise `LlmUnreachableError` through the existing unreachable
  helper: a non-2xx status (before any delta), a transport error or timeout, an unparseable
  `data:` payload. Closing the iterator early (`aclose`) exits the httpx stream and client
  contexts.
- The module docstring's "chat_stream deliberately absent" statement is replaced by a
  description of `chat_stream`. No `fastapi`, `app.secrets` or `app.db` import is added.

**`app/services/llm_registry.py`** (changed)

- **A chat-capable client protocol** (exposes `chat_stream` as above) and **a chat-client
  factory type** (base URL, API key or none, timeout → that protocol). `LlmClient` satisfies
  both; the existing probe/embed `LlmClientLike` and `LlmClientFactory` are unchanged.
- **`open_chat_client`**: inputs: a connection, an `EnabledChatModel`, the timeout in seconds,
  the chat-client factory. Re-reads that server's `api_key_ref`, resolves it with
  `resolve_secret` (missing variable → `secret_ref_missing`, before any network call), and
  returns the factory's client for the server's `base_url`, the key and the timeout. Writes
  nothing and leaves no transaction open.

## Definition of done

1. `[test]` Against a `MockTransport` recorder, `chat_stream("m1", [system "S", user "U"],
   [])` makes one POST to `<base>/v1/chat/completions` (for a base URL with and without a
   trailing `/v1`), whose JSON body is exactly
   `{"model":"m1","messages":[{"role":"system","content":"S"},{"role":"user","content":"U"}],"stream":true}`
   (no `tools` key); with one tool definition the body also has `"tools"` equal to that list.
   The `Authorization: Bearer <key>` header is sent when the client has a key and absent
   otherwise. (D10)
2. `[test]` A streamed body of `data:` lines with content `"Hel"`, `"lo"`, then `[DONE]`,
   then a further content line, yields exactly two deltas with content `"Hel"` and `"lo"`
   (nothing after `[DONE]`). Blank lines, `:` comment lines and `event:` lines are ignored; a
   chunk with an empty `choices` list yields nothing. Cyrillic content arrives intact. (D10)
3. `[test]` A delta carrying `reasoning_content` `"r1"` yields `reasoning` `"r1"`; one carrying
   `reasoning` `"r2"` yields `reasoning` `"r2"`; content and reasoning in one delta are both
   kept. (D4, D10)
4. `[test]` Tool-call chunks — first `{index 0, id "call_a", function {name "memo_search",
   arguments ""}}`, then `{index 0, function {arguments "{\"query\":"}}`, then `{index 0,
   function {arguments "\"inn\"}"}}` — yield three deltas whose `ToolCallDelta`s carry exactly
   those per-chunk values (index 0; id and name only on the first; the fragments as given).
   (D10, D11)
5. `[test]` A body that ends cleanly without `[DONE]` ends iteration normally after its
   deltas. (D10)
6. `[test]` Each raises `LlmUnreachableError` (code `llm_unreachable`): a 500 response (no
   delta yielded); a 401 response; a transport `ConnectError`; a `ReadTimeout`; a `data:` line
   whose payload is not JSON, after the deltas before it were yielded. (D10, US-044.AC-2)
7. `[test]` Closing the iterator after the first delta (with more body still pending) closes
   the response stream: the transport's byte stream records that it was closed, and no further
   chunk is read. (US-132.AC-2, 019 D6)
8. `[test]` The two `…_S006_002_DoD15` tests asserting `chat_stream` is absent are removed;
   `client.py` still imports no `fastapi`, no `app.secrets` and nothing from `app.db` (the
   existing structural tests pass unchanged). (D10)
9. `[test]` `open_chat_client` for a server whose `api_key_ref` is `"$RPH_TEST_KEY"` (set in
   the environment) calls the factory once with `(base_url, <the variable's value>,
   timeout)` and returns its result; with a NULL ref the key is `None`; with `"$RPH_MISSING"`
   (unset) it raises `secret_ref_missing` and never calls the factory. Afterwards the
   connection is not in a transaction. (D14, `backend-structure.md` secret pointers)
