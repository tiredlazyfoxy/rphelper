# Step 007 — Send on *my turn* composes; `composeZone` text becomes optional

## Goal

Switch Send on the *my turn* position from the non-streaming append to 019's compose effect,
so the assistant answers and a failed compose shows its server reason through the existing
transient notification; make `composeZone`'s text optional so a textless compose (the retry,
D2) can be sent by `022`'s control (D12). Under 50 lines: it is the only frontend change and
cannot merge with a backend step.

## Interface intent

**`app/streamApi.ts`** (changed)

- **`composeZone`** (019 `004`): its text becomes optional. With text, the body is
  `{"text": <text>}` exactly as before; with no text, the body is exactly `{}`. Path, frame
  callback, signal and outcome are unchanged.

**`app/streamState.ts`** (changed)

- **`sendComposer`**: on the *my turn* position it delegates to 019's `composeMessage(state,
  signal)` and resolves when that has wound down. This branch does **not** set or clear
  `busy` (019 D13), makes no `…/zone/messages` request, and adds no notification of its own
  (019 D14's outcome handling applies). The *partner* branch is unchanged.
- Nothing else changes; `composeMessage`, `canSend`, `canSettle`, `showsDiscard` stay as 019
  built them.

## Definition of done

1. `[test]` `composeZone("7250000000000000042", "Hi", cb, signal)` POSTs
   `/api/sessions/7250000000000000042/zone/compose` with body exactly `{"text":"Hi"}`;
   `composeZone` called with no text POSTs the same path with body exactly `{}`. (D2, D12,
   019 forward note "binding point")
2. `[test]` With draft `"Write me a reply"` on *my turn*, `sendComposer` issues exactly one
   POST, to `/api/sessions/s1/zone/compose` with `{"text":"Write me a reply"}`, and **no**
   request to `/api/sessions/s1/zone/messages`. (D12)
3. `[test]` While that compose is streaming (a token received, body held open), `busy` is
   false, `isStreaming` is true, and with a zone row on *my turn* `canSettle` is true.
   (019 D13)
4. `[test]` For each of `llm_unreachable`, `no_model_enabled`, `model_not_chosen`,
   `model_not_enabled` arriving as an `error` frame after `accepted`: `notifyFailure` is called
   once with an `ApiError` carrying that code (and the frame's message); the zone is re-read;
   `entries` is untouched; nothing is written into `zone` that the server did not serve.
   (US-044.AC-2, US-044.AC-4, R10)
5. `[test]` On `done`, `notifyFailure` is not called and the zone equals the final served list.
   (D12, never optimistic)
6. `[test]` On *partner*, Send still POSTs `/api/sessions/s1/entries` with
   `{"kind":"partner","text":…}` and never `…/zone/compose`. (D12)
7. `[test]` 013's assertions that Send on *my turn* POSTs `…/zone/messages` are rewritten to
   expect `…/zone/compose`; every other 013 test passes unchanged. (D12)
8. `[manual/live]` With `006` mounted: a failed compose's reason appears as a notification
   that disappears after about five seconds, and the typed text remains in the zone.
   (US-044.AC-4, US-044.AC-1)
