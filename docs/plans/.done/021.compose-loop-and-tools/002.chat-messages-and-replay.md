# Step 002 — Tool-capable chat messages, their wire form, and tool-row replay

## Goal

Extend 020's chat-message value so it can carry a system prompt, tool calls and tool results,
give it the OpenAI chat-completions wire form, and make 020's mapper replay zone tool rows
(D9) and strip think blocks from current-zone assistant replies (D4) instead of skipping tool
rows (020 D3).

## Interface intent

**`app/services/llm/chat.py`** (changed)

- **`ChatRole`** widens to `"system"`, `"user"`, `"assistant"`, `"tool"`.
- **`ToolCall`** (new, frozen): `call_id` (opaque string), `name`, `arguments` (the raw JSON
  arguments **string**, verbatim).
- **`ChatMessage`** gains `tool_calls` (an immutable sequence of `ToolCall`, default empty)
  and `tool_call_id` (string or none, default none). Existing two-field construction stays
  valid.
- **`to_wire_message`** (new, pure): one `ChatMessage` → the OpenAI chat-completions message
  object:
  - system / user: `{"role", "content"}`;
  - assistant: `{"role": "assistant", "content"}` plus `"tool_calls"` only when non-empty,
    each `{"id": call_id, "type": "function", "function": {"name", "arguments"}}` in order;
  - tool: `{"role": "tool", "tool_call_id", "content"}`.
- Still imports nothing from `app.services`.

**`app/services/context.py`** (changed; 020's module)

- **`to_chat_messages`**: same inputs and ordering as 020 (union by id). Changes:
  - a current-zone row with role `"assistant"` maps with its text passed through
    `strip_think` (D4); user rows and settled rows of any role are unchanged from 020;
  - a row with role `"tool"` is **replayed** per D9 at its id position: an assistant
    `ChatMessage` with content `""` and exactly one `ToolCall` (payload `call_id`, the row's
    `tool_name`, payload `arguments`), followed by a tool `ChatMessage` with that
    `tool_call_id` and content = payload `content` when status is `ok`, else the failed
    literal (`context.md` Literals). A tool row that cannot be replayed (D9) is skipped;
  - any other role is still skipped.
- **`assemble_context`**: unchanged; it returns the new mapping through `to_chat_messages`.
  Its imports from `app.services` are unchanged (020 `002` DoD-16 holds).
