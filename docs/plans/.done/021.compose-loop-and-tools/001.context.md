# Step 001 — step-specific context

Feature-wide facts (D4's strip rule and worked examples, D7's payload, D8's invariants, the
literals) are in `context.md`. Only what this step alone needs is here.

## Built state at the touch sites

- **`db/schema.py` `messages`**: `role` is Text NOT NULL with **no CHECK** (so `'tool'` needs
  no schema change); `text` is **NOT NULL**; `tool_name`, `tool_payload` are nullable Text
  that exist today with no writer. The `current_zone` / `settled_entries` views are Core
  selects with **no role filter**, so tool rows already appear in `list_zone`.
- **`services/messages.py`**: `StreamMessage` (eight fields: `id`, `session_id`, `role`,
  `kind`, `text`, `settled_at`, `created_at`, `updated_at`; frozen); `append_message(conn,
  generator, user_id, session_id, text)` hardcodes role `user`; `list_zone`, `list_entries`;
  `edit_message_text(conn, user_id, message_id, text)` refuses only buried rows today. 019
  `001` adds `append_assistant_message` and (coder's choice) a private insert parameterised by
  role — extend that helper rather than writing a third insert body.
- **`services/settle.py`**: `settle()` takes `zone_rows[-1]` as head with no role filter,
  classifies with `parens.classify`, strips fragments for a turn, buries the rest (bury
  **before** flagging the head — load-bearing, `backend-structure.md`). `reopen()` has no role
  filter and stays untouched.
- **`app/models/stream.py` `MessageResponse`** exposes exactly 8 keys via
  `model_validate(..., from_attributes=True)`; the two new `StreamMessage` attributes are
  ignored by it. Do not touch `models/stream.py` in this step.
- **`app/errors.py`**: `DomainError(code, http_status, message, detail)`; subclasses set a
  default message in `__init__` (017 convention). `MessageNotEditableError` (409) and
  `ZoneEmptyError` (409) exist.

## Gotchas local to this step

- **Ordering inside settle:** think-strip the head text first, then classify and strip `(( ))`
  on the result. A head whose think-stripped text is empty still settles (no new refusal is
  invented); `outcome.md` notes it for 022.
- **Pre-existing structural tests.** 012 may have source-convention tests pinning
  `settle.py`'s or `messages.py`'s imports. `settle.py` gains one import (`app.services.llm.chat`).
  If such a test exists and fails only because of that import, the verifier reports it as a
  plan gap (Fault: SPEC) rather than the coder routing around it; nothing else in existing
  tests should change.
- `strip_think` is pure and imported by `settle.py` (here) and `context.py` (`002`); `chat.py`
  must still import nothing from `app.services` (020 `001` DoD-17).
- `test_settle_tool_rows_and_think.py` raw-inserts tool rows (role `'tool'`) where it needs
  them; it must not depend on `append_tool_message` for setup of DoD-6..8, so a failure there
  isolates cleanly.
