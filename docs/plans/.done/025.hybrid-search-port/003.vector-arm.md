# Step 003 — The vector arm

## Goal

Rank a candidate set by vector distance to the embedded query: open the designated model
through 024's embedding service, embed the query once, and run the exact scan over
`memo_vec` / `session_vec` restricted to the candidates — never the forbidden pushed-down
KNN form (`context.md` U2, D5; 024 D3).

## Source files

backend/app/services/search/vector.py

## Test files

backend/tests/test_search_vector.py

## Interface intent

**`app/services/search/vector.py`**

- **`vector_ranking`** — takes a connection, the vec table name (024's `memo_vec` or
  `session_vec` constant), a candidate select (from step `002`'s `candidate_ids`), the raw
  query text and a depth (default `ARM_DEPTH`); keyword-only `client_factory` and
  `timeout_seconds` (defaults: the real client factory and 024's
  `DEFAULT_EMBED_TIMEOUT_SECONDS`). Returns a ranking: at most `depth` distinct ids, nearest
  first, ties by ascending id, restricted to ids in the candidate set. Behaviour, in order:
  1. opens the designated model via `open_embedding_model` — its errors propagate;
  2. reads the table's declared dimension via 024's `vector_table_dimension`; absent table
     → returns `[]` **without** embedding;
  3. declared dimension ≠ the handle's `embedding_dim` → raises `NoEmbeddingModelError`
     with `detail {"reason": "dimension_mismatch"}` and a fixed message, without embedding;
  4. embeds the query text with **one** `embed_texts` call (its errors propagate);
  5. runs the exact scan (`003.context.md`) and returns the ids.
- The module never creates or writes a vec table, and its source never contains the
  pushed-down KNN form.

## Definition of done

1. `[test]` With a designated model (dim 8), `memo_vec` ensured at 8, and vectors written
   for four of one user's memos from the fake's pure function, `vector_ranking` returns the
   ids ordered by ascending L2 distance between each memo's vector and the fake vector of
   the query text, as computed by the test from the fake's pure function. (D5)
2. `[test]` **Snowflake correctness (024 D3).** With at least 200 candidates whose ids are
   above 2^60 (spread, non-contiguous) plus vectors for non-candidates, and `depth` smaller
   than the candidate count, the returned ranking equals the brute-force expected top-`depth`
   computed by the test over the candidates only — no true candidate is missing.
3. `[test]` Ids outside the candidate set never appear even when nearer: another user's
   memo whose vector equals the query vector exactly is absent; so is one excluded by an
   extra predicate. (D5, D6, UC-065)
4. `[test]` The same holds for `session_vec` with a session-scope candidate set (another
   character's session excluded by an extra predicate; another user's session excluded by
   the owner predicate). (U1, US-085)
5. `[test]` `depth` caps the ranking; a candidate with no vector row is simply not ranked
   (no error); an empty but present vec table returns `[]`. (U2)
6. `[test]` With no designated model, `vector_ranking` raises `NoEmbeddingModelError` and
   the fake factory is called zero times — also when the vec table is absent. (U2, R4)
7. `[test]` A fake scripted to raise `LlmUnreachableError` makes `vector_ranking` raise
   that same error type. (U2)
8. `[test]` With the vec table absent and a designated model, `vector_ranking` returns `[]`
   and the fake recorded **no** `embed` call. (U2)
9. `[test]` A vec table declared at 8 with a model designated at 16 raises
   `NoEmbeddingModelError` with `detail` equal to `{"reason": "dimension_mismatch"}`, and the
   fake recorded no `embed` call. (024 D8)
10. `[test]` On success the fake recorded exactly one `embed` call, carrying the designated
    model name and exactly the one query text. (024 D1)
11. `[test]` The source of `vector.py` does not contain the substring `MATCH` (the vec0 KNN
    operator) and imports no `fastapi`. (024 D3)
