## Lexical query shape

Per FTS table `T` (024 constant), with `rowid` = base id:

```
SELECT rowid, snippet(T, 0, '', '', '…', 16)
FROM T
WHERE T MATCH :fts_expr
  AND rowid IN (<candidate_ids subquery>)
ORDER BY bm25(T), rowid
LIMIT :depth
```

- `bm25()` is lower-is-better; ascending order is best first.
- Snippet parameters are fixed: column 0, **empty** start / end markers (plain text, no
  highlight markup), ellipsis `…` (U+2026), 16 tokens (a module constant). The 16 is
  conventional, like D1's numbers.
- `MATCH` must use the table name on the left (`T MATCH …`), not a column, so the
  expression's quoted phrases search the indexed column.
- The FTS tables are outside `schema.metadata`; build the statement with `text()` or a
  lightweight `table()` / `column()` construct, naming the table through 024's constant.

## Absent-table check

`SELECT 1 FROM sqlite_master WHERE type='table' AND name=:name`. 024 exposes no public FTS
existence helper (only `vector_table_dimension` for vec tables), so `fts_table_exists` is
025's own.

## Test shape

- `test_search_lexical.py` ensures FTS tables with 024's `ensure_fts_tables` inside a
  committed transaction **after** or **before** inserting rows (the back-fill and the
  triggers both index them); DoD-10 never ensures.
- DoD-4's BM25 expectation comes from BM25's definition (term frequency in a shorter
  document scores better), not from running the code first.
