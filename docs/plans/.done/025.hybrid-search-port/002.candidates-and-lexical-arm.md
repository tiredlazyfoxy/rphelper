# Step 002 — Candidate sets and the lexical arm

## Goal

Build the filters-first candidate select for each scope variant (owner predicate plus the
caller's extra predicate) and the lexical arm: BM25 ranking with a plain-text snippet over
`memo_fts` / `message_fts`, constrained to a candidate set, tolerant of an absent FTS table
(`context.md` U1, U2, D5, D6).

## Source files

backend/app/services/search/candidates.py
backend/app/services/search/lexical.py

## Test files

backend/tests/test_search_lexical.py

## Interface intent

**`app/services/search/candidates.py`**

- **`base_relation`** — takes a scope variant; returns the FROM object its candidates come
  from: the `memos` table, the `sessions` table, or a subquery over the `settled_entries`
  selectable (R11 — never raw `messages`). The same object is what the extra-predicate
  builder receives.
- **`candidate_ids`** — takes a scope variant; returns a Core select of a single id column
  from that variant's base relation, filtered by `user_id = scope.user_id` AND (when
  present) the clause the scope's extra-predicate builder returns for that base relation.
  It executes nothing. Both arms consume it as a subquery.

**`app/services/search/lexical.py`**

- **`LexicalMatch`** — a frozen value: an id and its snippet text.
- **`fts_table_exists`** — takes a connection and an FTS table name (one of 024's
  constants); true iff `sqlite_master` holds a table of that name.
- **`lexical_ranking`** — takes a connection, the FTS table name (`memo_fts` for memo,
  `message_fts` for entry), a candidate select (from `candidate_ids`), the sanitised FTS
  expression (from `build_fts_query`, step `001`) and a depth (default `ARM_DEPTH`).
  Returns at most `depth` `LexicalMatch` values, best BM25 first, ties by ascending id,
  restricted to ids in the candidate set. Returns `[]` without querying the FTS table when
  the FTS expression is none or the table does not exist.

## Definition of done

1. `[test]` For each variant, `candidate_ids` executed on a database holding rows for two
   users returns exactly the scope user's ids; the other user's ids never appear. (D6,
   UC-065, US-085)
2. `[test]` For each variant, an extra-predicate builder is honoured: e.g. memo
   `is_enabled` true excludes a disabled memo of the same user; session
   `character_id = X` excludes the same user's session under another character; entry
   `session_id = S` excludes the same user's record row in another session. The owner
   predicate still applies alongside it. (U1)
3. `[test]` The entry candidate set contains a record row and excludes, for the same user
   and session, a zone row (`settled_at` null) and a buried row (`related_to` set). (R11,
   US-115, UC-038)
4. `[test]` With `memo_fts` ensured and three of one user's memos — one containing the
   token twice in a short body, one containing it once in a long body, one without it —
   `lexical_ranking` returns the two matching ids, the stronger BM25 match first, and not
   the third. (BM25 ranking)
5. `[test]` `lexical_ranking` returns only ids in the candidate set: another user's memo
   (or one excluded by an extra predicate) containing the token is absent even though
   `memo_fts` indexes it. (D5, D6)
6. `[test]` Each `LexicalMatch` snippet is plain text that contains the matched token and
   contains none of `<`, `>`, `[`, `]` markup; for a body longer than the snippet window it
   contains `…`. (`002.context.md`, D4)
7. `[test]` Over `message_fts`, an entry-scope candidate set yields the record row whose
   text contains the token, with its message id and a snippet containing the token. (U1)
8. `[test]` `depth` caps the result: with more matching candidates than `depth`, exactly
   `depth` matches are returned. (D1)
9. `[test]` Snowflake ids above 2^60 round-trip: the returned id equals the inserted row
   id exactly. (024 D3)
10. `[test]` With the FTS table absent (never ensured), `lexical_ranking` returns `[]` and
    raises nothing; `fts_table_exists` is false before the ensure and true after. (U2)
11. `[test]` With a none FTS expression, `lexical_ranking` returns `[]`. (`001.context.md`)
