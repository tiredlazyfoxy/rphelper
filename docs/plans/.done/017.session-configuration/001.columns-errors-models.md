# Step 001 — Configuration columns, the two use-time errors, and the wire models

## Goal

Add the assistant-chain columns to `characters` and the assistant-chain plus language
columns to `sessions` (D4, D5, D6). Add `no_model_enabled` and `model_not_chosen` (D2).
Add `models/configuration.py`, the request and response models of the seven routes,
including D6's normalisation. Amend the schema tests that pinned the old column sets.

## Source files

backend/app/db/schema.py
backend/app/errors.py
backend/app/models/configuration.py

## Test files

backend/tests/test_db_schema.py

## Interface intent

**`db/schema.py`** (extended)

- **`characters`** gains six nullable columns, no defaults: `model_server_id` (the
  registry's id column type, **no foreign key**), `model_name` (Text), `system_prompt`
  (Text), `tool_memo_search`, `tool_session_search`, `tool_web_search` (Boolean). It also
  gains a named table CHECK requiring `model_server_id` and `model_name` to be both NULL
  or both non-NULL. The comment block that defers configuration to 017 is replaced by one
  citing R1 (no language columns here), R4 and D4 / D5.
- **`sessions`** gains the same six columns and the same kind of named CHECK (its own
  name), plus `rp_language` and `preferred_language` (Text, nullable). The deferral
  comment is replaced by one citing R1, R4 (captured model, D1) and D4–D6.
- **`users`** is unchanged.

**`errors.py`** (extended)

- **`NoModelEnabledError`**: `DomainError` subclass, code `no_model_enabled`, HTTP 409,
  empty `detail`, a fixed non-empty default message.
- **`ModelNotChosenError`**: code `model_not_chosen`, HTTP 409, empty `detail`, a fixed
  non-empty default message.

**`models/configuration.py`** (new)

- **Level literal**: a type naming exactly `"session"`, `"character"`, `"user"`,
  `"default"`.
- **`ModelRefIn`**: request sub-model. `server_id` (inbound snowflake), `model_name`
  (required, non-blank, kept verbatim).
- **`ModelRefOut`**: response sub-model. `server_id` (outbound snowflake → decimal
  string), `model_name`.
- **`EnabledModelResponse`**: `server_id` (outbound snowflake), `server_name`,
  `model_name`. **`EnabledModelListResponse`** wraps a list under `models`.
- **`UserSettingsResponse`**: `rp_language`, `preferred_language` (string or null).
- **`CharacterConfigurationResponse`**: `model` (`ModelRefOut` or null),
  `system_prompt`, `tool_memo_search`, `tool_session_search`, `tool_web_search`.
- **Setting responses**: one for text settings (`session`, `inherited`, `value`: string
  or null) and one for boolean settings (`session`, `inherited`: boolean or null;
  `value`: boolean). Both carry `inherited_level` and `level` (the level literal or
  null).
- **`SessionConfigurationResponse`**: `model` (`ModelRefOut` or null), `system_prompt`,
  the three `tool_*`, `rp_language`, `preferred_language`, each the matching setting
  response. All response models are buildable from service values by attribute,
  including the nested ones.
- **`UpdateUserSettingsRequest`**: unknown keys ignored. `rp_language`,
  `preferred_language`, each optional and nullable. A supplied string is trimmed, and
  blank becomes null (D6). Which keys were sent is recoverable (explicit null ≠ absent).
- **`UpdateSessionConfigurationRequest`**: unknown keys ignored. `model` (optional
  `ModelRefIn`; an explicit null **fails validation**), `system_prompt` (optional,
  nullable; blank → null, otherwise verbatim), the three `tool_*` (optional, nullable
  booleans), `rp_language`, `preferred_language` (as the user request). Which keys were
  sent is recoverable.
- **`UpdateCharacterConfigurationRequest`**: unknown keys ignored (so `rp_language` /
  `preferred_language` are dropped, US-061.AC-3). `model` (optional, **nullable**:
  explicit null = clear), `system_prompt`, the three `tool_*`, with the same rules.

## Definition of done

1. `[test]` `characters` has exactly its seven existing columns plus `model_server_id`,
   `model_name`, `system_prompt`, `tool_memo_search`, `tool_session_search`,
   `tool_web_search`. The six new columns are nullable, and none declares a default or a
   foreign key. `rp_language` and `preferred_language` are still absent, and so are the
   literal names `model_ref` and `tools`. (R1, US-061.AC-3, D4, D5)
2. `[test]` `sessions` has exactly its eight existing columns plus `model_server_id`,
   `model_name`, `system_prompt`, the three `tool_*`, `rp_language` and
   `preferred_language`, all nullable, with no default and no new foreign key. `title`,
   `partner_label`, `status`, `state`, `model_ref` and `tools` are still absent. (R1, D4,
   D5, D6)
3. `[test]` `users` has no column named `model_server_id`, `model_name`, `model_ref`,
   `system_prompt`, `tools` or `tool_*`, and still has `rp_language` and
   `preferred_language`. (R1 — the user level carries the two languages only; UC-047)
4. `[test]` After `metadata.create_all` on a fresh engine, on both tables: a row with
   `model_server_id` set and `model_name` NULL fails to insert, and so does the reverse; a
   row with both set inserts, and so does a row with both NULL; a `model_server_id` that
   names no `llm_servers` row inserts (no FK). (D4)
5. `[test]` The 009 / 011 schema assertions this step's columns change are amended in
   place, and every other existing assertion in `tests/test_db_schema.py` still passes
   (`001.context.md` "Amending the schema tests").
6. `[test]` `NoModelEnabledError` and `ModelNotChosenError` are `DomainError`s with codes
   `no_model_enabled` / `model_not_chosen`, both 409. Raised from a route on an
   application with the handlers registered, each answers 409 with `{ "error": { "code":
   <code>, "message": <non-empty string>, "detail": {} } }`. (D2)
7. `[test]` `UpdateUserSettingsRequest`: `{"rp_language": "  Japanese "}` parses to
   `"Japanese"`; `{"rp_language": "   "}` parses to null with the key marked as sent;
   `{"preferred_language": null}` marks that key sent and null; `{}` marks nothing sent;
   unknown keys (`model`, `system_prompt`) are ignored. (D6, US-058.AC-1)
8. `[test]` `UpdateSessionConfigurationRequest`: `{"model": {"server_id":
   "7250000000000000301", "model_name": "llama-3"}}` parses with `server_id` the int;
   `{"model": null}` fails; a `model` with `model_name` `""` or `"  "`, or with a
   non-numeric `server_id`, fails; `{"system_prompt": "  Be terse.\n"}` keeps those exact
   characters; `{"system_prompt": " \n"}` parses to null, marked as sent;
   `{"tool_web_search": false}` sets only that key; `{"tool_memo_search": null}` marks it
   sent and null; `{"tool_memo_search": "yes"}` fails; languages trim as in DoD-7. (D6,
   D10)
9. `[test]` `UpdateCharacterConfigurationRequest`: `{"model": null}` parses as sent and
   null; `{"rp_language": "French", "preferred_language": "English"}` parses with
   nothing sent and no language attribute on the model. The other fields follow DoD-8.
   (D10, US-061.AC-3)
10. `[test]` `SessionConfigurationResponse` built from values carrying an int `server_id`
    serialises `model.server_id` as its decimal string. `model` null serialises as JSON
    `null`. Each setting serialises exactly the keys `session`, `inherited`,
    `inherited_level`, `value`, `level`, and the top level has exactly the seven keys of
    the Wire contract. `EnabledModelListResponse` serialises `{ "models": [...] }` with
    each item exactly `server_id` (string), `server_name`, `model_name`.
    `CharacterConfigurationResponse` has exactly its five keys. (Wire contract)
11. `[manual/live]` Against a database from before 017: the admin Database page reports
    `characters` and `sessions` as drifted; **Sync** on each brings it in sync with
    existing rows intact and the new columns NULL. Opening an existing session afterwards
    works. (FEAT-005, D1)
