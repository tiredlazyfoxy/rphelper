# Step 004 — Session, character and user configuration writes

## Goal

Extend `services/configuration.py` with the write paths. A session configuration update
validates a new model at set time (D10). The character configuration has a read and an
update, also with a set-time check, and never touches a session. The user settings have a
read and an update. Each update writes only the supplied fields (D11).

## Source files

backend/app/services/configuration.py

## Test files

backend/tests/test_configuration_writes.py

## Interface intent

**`services/configuration.py`** (extended)

- **`CharacterConfiguration`**: frozen value with `model` (`ModelRef` or none),
  `system_prompt`, `tool_memo_search`, `tool_session_search`, `tool_web_search` (each a
  stored value or none).
- **`UserSettings`**: frozen value with `rp_language`, `preferred_language`.
- **`update_session_configuration`**: takes a connection, the caller's user id, a session
  id, and keyword arguments `model`, `system_prompt`, `tool_memo_search`,
  `tool_session_search`, `tool_web_search`, `rp_language`, `preferred_language`, each
  defaulting to `UNSET` (absent). `model` is a `ModelRef` when supplied (never none).
  The others accept none to clear. In one transaction: the owner-scoped session check
  (`SessionNotFoundError`); if `model` is supplied, `validate_chat_model` with level
  `session`. A `ModelNotEnabledError` leaves the row untouched. Then the supplied
  columns are written with `updated_at` (fixed-width now). `last_used_at` is never
  touched. With nothing supplied it writes nothing. Returns `get_session_configuration`'s
  result for the session after the write.
- **`get_character_configuration`**: takes a connection, the caller's user id, a
  character id. Owner-scoped read (`CharacterNotFoundError` for missing or foreign;
  archived reads). Returns a `CharacterConfiguration`.
- **`update_character_configuration`**: same caller and character arguments, keyword
  arguments `model` (a `ModelRef`, none to clear, or `UNSET`), `system_prompt` and the
  three `tool_*`, each defaulting to `UNSET`. In one transaction: owner-scoped character
  check; if `model` is a `ModelRef`, `validate_chat_model` with level `character`
  (failure writes nothing). Then the supplied columns plus `characters.updated_at`.
  Never touches `sheet`, `name`, `archived_at` or any `sessions` row. With nothing
  supplied it writes nothing. Returns the `CharacterConfiguration` after the write.
- **`get_user_settings`**: takes a connection and the caller's user id; returns
  `UserSettings`.
- **`update_user_settings`**: caller's user id plus keyword `rp_language`,
  `preferred_language`, each `UNSET` by default, none to clear. One transaction writing
  the supplied columns plus `users.updated_at` (fixed-width). Nothing supplied → no
  write. Returns `UserSettings` after the write. Never touches any other `users` column.

## Definition of done

1. `[test]` `update_session_configuration` with an enabled `model` writes that pair.
   `get_session_configuration` afterwards reports it, and a fresh connection still does
   (persisted). (US-105.AC-1, US-105.AC-2)
2. `[test]` With a `model` that is disabled, or on no existing server, it raises
   `ModelNotEnabledError` with `detail.level` `"session"` and the decimal-string
   `server_id`. When the same call also carried `system_prompt`, neither the model nor the
   prompt nor `updated_at` changed. (D10)
3. `[test]` Supplying only `system_prompt="S"` writes it and leaves the captured model,
   tools and languages unchanged. Then `system_prompt=None` clears it, and the resolved
   prompt falls back to the character's. Tools and languages behave the same way:
   supplying a value overrides, `None` restores inheritance. (US-060.AC-1, US-061.AC-2,
   US-062.AC-2, R1 — clearing restores inheritance)
4. `[test]` An update bumps `updated_at` to a later fixed-width value and leaves
   `last_used_at` unchanged. An update with nothing supplied leaves the whole row
   unchanged and still returns the configuration. (D11)
5. `[test]` An archived session updates normally. Another user's session or a missing id
   raises `SessionNotFoundError` and writes nothing. (R6, R5)
6. `[test]` `update_character_configuration` with an enabled model, a prompt and
   `tool_web_search=False` writes them. `get_character_configuration` reports them. A
   **new** session's resolved configuration then shows the character's prompt and web
   search off at level `character` (US-059.AC-2, US-062.AC-1).
7. `[test]` `update_character_configuration` changing the character's model leaves every
   existing session row of that character unchanged, its captured model included, and
   touches no session's `updated_at` (US-139.AC-1). `model=None` clears the character's
   pair (both columns NULL). (D10)
8. `[test]` `update_character_configuration` with a disabled model raises
   `ModelNotEnabledError` with `detail.level` `"character"` and writes nothing. It never
   reports `"user"`. (D10, `backend-structure.md` error table)
9. `[test]` `update_character_configuration` leaves `name`, `sheet` and `archived_at`
   unchanged and bumps `characters.updated_at`. Another user's character or a missing id
   raises `CharacterNotFoundError`. An archived character updates normally. (R5, R6, D9)
10. `[test]` `update_user_settings(rp_language="Japanese", preferred_language="English")`
    persists both. `get_user_settings` returns them. A session with no language override
    then resolves both at level `user`. Later `preferred_language=None` clears only that
    one. Another user's settings are unchanged throughout. (US-058.AC-1, US-061.AC-1, R5)
11. `[test]` `update_user_settings` leaves `username`, `password_hash`, `role`,
    `is_enabled` and `last_login_at` unchanged, and bumps `updated_at` to a fixed-width
    value. Nothing supplied → no write. (D11, D14)
