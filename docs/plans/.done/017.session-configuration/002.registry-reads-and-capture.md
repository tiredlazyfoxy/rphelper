# Step 002 — Enabled-model reads, and capturing the model at session creation

## Goal

Add two registry reads, the enabled set in first-enabled order and its first row (D7).
Make them, and `validate_chat_model`, safe inside a caller's open transaction (D12). Then
have `start_session` capture the model in its creation transaction by D1's three cases.

## Source files

backend/app/services/llm_registry.py
backend/app/services/sessions.py

## Test files

backend/tests/test_llm_registry_enabled.py
backend/tests/test_sessions_capture.py
backend/tests/test_sessions_service.py

## Interface intent

**`services/llm_registry.py`** (extended)

- **`list_enabled_chat_models`**: takes a connection. Returns the enabled set (D7):
  every `models` row with `is_enabled` true whose server exists, as `EnabledChatModel`
  values (server + model name), ordered by server id then model row id, ascending. An
  embedding-designated model that is enabled is included. Empty when none.
- **`first_enabled_chat_model`**: takes a connection. Returns the first item of that
  list, or none.
- **Transaction posture** (D12): these two and the existing `validate_chat_model` can
  each be called **inside a caller's open `with connection.begin():` block** without
  opening, committing or rolling back anything, and **standalone** without leaving a
  read transaction open. `validate_chat_model`'s signature, error and detail are
  unchanged.

**`services/sessions.py`** (changed; 011-owned)

- **`start_session`**: signature and return value (`RpSession`, eight fields)
  unchanged. Inside its existing single transaction, after the character and setup
  checks and before the insert, it determines the captured model by D1. The character's
  own pair, read by the owner-scoped character check, is taken **as-is without
  consulting the registry**. Otherwise it takes `first_enabled_chat_model`. Otherwise
  NULL. It writes the pair into the new row's `model_server_id` / `model_name`. The
  other new `sessions` columns are left NULL (nothing is copied from the character:
  prompt and tools resolve live, D1 / R4).
- The module docstring's "model ref stays 017's" / "no update" lines are replaced by
  D1's statement and a pointer to `services/configuration.py` for configuration writes
  (`004`).

## Definition of done

1. `[test]` `list_enabled_chat_models` with two servers and models whose server-id order
   and model-id order disagree returns exactly the enabled models, ordered by server id
   then model id. A disabled model is absent. A model on a deleted server is absent. An
   enabled embedding-designated model is present. With no enabled model it returns an
   empty list. (D7)
2. `[test]` `first_enabled_chat_model` returns the first item of DoD-1's order, and none
   when nothing is enabled. Disabling that model makes the next one first. (D7,
   US-106.AC-1)
3. `[test]` `list_enabled_chat_models`, `first_enabled_chat_model` and
   `validate_chat_model` (for both an enabled and a disabled reference) each run inside
   an open `with connection.begin():` block that then inserts a row and commits; the row
   is persisted and no transaction error occurs. Called standalone, each leaves the
   connection with no transaction in progress. (D12)
4. `[test]` Character with no model, no enabled model on the instance: `start_session`
   creates the session with `model_server_id` and `model_name` NULL. The returned
   `RpSession` is unchanged in shape. (D1 case 3, user decision 1)
5. `[test]` Character with no model, two enabled models (D7 order chosen to disagree with
   `models.id` order): the new row holds the **first enabled** model's server id and name.
   (US-106.AC-1, US-108.AC-1, D7)
6. `[test]` Character configured with a model (raw-written pair) that is enabled: the new
   row holds the character's pair, not the first enabled one. (US-139.AC-2,
   US-059.AC-2, US-108.AC-1)
7. `[test]` Character configured with a model that is **disabled**, or names a server
   that does not exist, with or without other models enabled: the new row holds the
   character's pair unchanged and creation succeeds. (R4 — captured unvalidated; D1)
8. `[test]` A session is created while its character has no model (one model enabled).
   The character is then given a different model, and another model becomes first
   enabled. The first session's row still holds its captured pair. A second session
   created afterwards holds the character's new pair. (US-139.AC-1, US-139.AC-2,
   US-059.AC-1)
9. `[test]` The character's `system_prompt` and tool switches set (raw) before creation
   are **not** copied: the new session's `system_prompt` and three `tool_*` are NULL, and
   so are `rp_language` / `preferred_language`. (D1, R4 — prompt and tools stay live)
10. `[test]` A creation refused by the character check (another user's character) or the
    setup checks inserts nothing and reads no registry state that changes the outcome.
    011's error codes are unchanged. `tests/test_sessions_service.py` passes with only
    the DoD-11 amendment, and `tests/test_sessions_router.py` passes unmodified.
    (011 D12)
11. `[test]` 011's DoD-16 import guard in `tests/test_sessions_service.py` is amended in
    place to D12's exception: `services/sessions.py` may import from `app.services` only
    the module `app.services.llm_registry`, and from it only names in D12's list
    (`list_enabled_chat_models`, `first_enabled_chat_model`, `validate_chat_model`,
    `ModelRefLevel`, `EnabledChatModel`, `UNSET`, `Unset`). Any other `app.services.*`
    import, or any other name from `llm_registry`, still fails the guard. The test is
    renamed by appending `__S017_002_DoD11` to its 011 name. Nothing else in that file
    changes. (D12; 011 D11)
