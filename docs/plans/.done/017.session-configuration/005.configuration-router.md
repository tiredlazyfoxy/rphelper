# Step 005 — The configuration router

## Goal

Add `routers/configuration.py` with the seven routes of the Wire contract over `002`–`004`.
Register it in `main.py` after every existing router. Amend `routers/sessions.py`'s
docstring, which says nothing is editable (D13).

## Interface intent

**`routers/configuration.py`** (new)

Router-level `require_user`, full literal paths, path ids parsed through the
`models/ids.py` inbound alias. No SQL. Each handler maps its request model's sent fields
to service keyword arguments, mapping fields **not** sent to `UNSET` and passing `None`
where `null` was sent. It answers with `001`'s response models from the service values.

- **`GET /api/models`** → `EnabledModelListResponse` from `list_enabled_chat_models`: each
  item's server id, server name and model name, in service order.
- **`GET /api/me/settings`** → `UserSettingsResponse` from `get_user_settings`.
- **`PATCH /api/me/settings`** (`UpdateUserSettingsRequest`) → `UserSettingsResponse`
  from `update_user_settings`.
- **`GET /api/sessions/{session_id}/configuration`** → `SessionConfigurationResponse`
  from `get_session_configuration`.
- **`PATCH /api/sessions/{session_id}/configuration`**
  (`UpdateSessionConfigurationRequest`) → `SessionConfigurationResponse` from
  `update_session_configuration`. The `model` sub-object becomes a service `ModelRef`.
- **`GET /api/characters/{character_id}/configuration`** →
  `CharacterConfigurationResponse` from `get_character_configuration`.
- **`PATCH /api/characters/{character_id}/configuration`**
  (`UpdateCharacterConfigurationRequest`) → `CharacterConfigurationResponse` from
  `update_character_configuration`. An explicit `model: null` is passed as `None` (clear).

**`main.py`** (changed): the configuration router is included **last**, after every
router already present. Nothing else changes.

**`routers/sessions.py`** (docstring only): the "nothing is editable / no PATCH" note
says configuration is edited through `routers/configuration.py`'s
`/api/sessions/{id}/configuration`, and that `PATCH /api/sessions/{id}` still does not
exist. No route or code changes.

## Definition of done

1. `[test]` `GET /api/models` with two servers and models whose id orders disagree answers
   200 `{ "models": [...] }` in D7 order: each item exactly `server_id` (decimal string),
   `server_name`, `model_name`, with no `base_url`, `kind`, `api_key_ref` or test field.
   With none enabled it answers `{ "models": [] }`. A roleplayer (non-admin) gets the
   same answer. Without a login cookie it answers 401. (D7, D13, R5)
2. `[test]` `PATCH /api/me/settings` with `{"rp_language": " Japanese ", "preferred_language":
   "English"}` answers `{ "rp_language": "Japanese", "preferred_language": "English" }`,
   and a later `GET /api/me/settings` answers the same. A second user's `GET` is
   unaffected. `{"rp_language": ""}` answers it null. `GET /api/me` still answers exactly
   `id`, `username`, `role`. (US-058.AC-1, D6, D14)
3. `[test]` End to end, with two models enabled and a character with no model: `POST
   /api/characters/{id}/sessions` (011's route, unchanged) answers its 8-key `Session`.
   `GET …/configuration` for it answers `model` = the first enabled model in D7 order,
   every tool `{value: true, level: "default"}`, `system_prompt` value null, and both
   languages at level `user` once the user's settings are set. (US-106.AC-1, US-108.AC-1,
   US-108.AC-2, D5)
4. `[test]` `PATCH /api/characters/{id}/configuration` with an enabled model, `"system_prompt":
   "Stay in character."` and `"tool_memo_search": false` answers those values. A session
   created **before** it keeps its captured model in `GET …/configuration`, but shows the
   new prompt (level `character`) and memo search off (level `character`). A session
   created **after** it captures the character's model. (US-139.AC-1, US-139.AC-2,
   US-059.AC-1, US-059.AC-2, US-062.AC-1)
5. `[test]` `PATCH /api/sessions/{id}/configuration` with `{"model": {"server_id": "<enabled
   server>", "model_name": "<enabled name>"}}` answers 200 with that `model`. A later `GET`
   (new request) answers the same. With a model that is not enabled it answers 409
   `model_not_enabled` with `detail` `{ server_id: "<decimal>", model_name, level:
   "session" }`, and a later `GET` shows the previous model. `{"model": null}` answers 422.
   (US-105.AC-1, US-105.AC-2, D10)
6. `[test]` `PATCH /api/sessions/{id}/configuration` with `{"system_prompt": "S",
   "tool_web_search": false, "rp_language": "French"}` answers those at level `session`,
   with `inherited` still showing the character / user values. A second PATCH with
   `{"system_prompt": null, "rp_language": null}` restores level `character` / `user` for
   those two and leaves web search off. (US-060.AC-1, US-061.AC-2, US-062.AC-2, R1)
7. `[test]` `PATCH /api/characters/{id}/configuration` with `{"rp_language": "French",
   "preferred_language": "English"}` answers 200 with nothing changed, and a session under
   it still resolves its languages from the user. `PATCH` with a disabled model answers
   409 `model_not_enabled` with `detail.level` `"character"`. `{"model": null}` clears
   the character's model. (US-061.AC-3, D10)
8. `[test]` Session and character routes on another user's or a missing id answer 404
   `session_not_found` / `character_not_found` for both GET and PATCH, and the PATCH
   writes nothing. An archived session and an archived character are readable and
   writable. (R5, R6)
9. `[test]` 011's routes are unchanged: `GET /api/sessions/{id}` still answers exactly the
   eight `Session` keys, and `PATCH /api/sessions/{id}` still answers 405. The
   configuration router is the last router included by the app factory. (D9, D13)
10. `[test]` A session `PATCH …/configuration` leaves the session's `last_used_at`
    unchanged in `GET /api/sessions/{id}`, and its `updated_at` advances. (D11)
11. `[manual/live]` With a running backend and two LLM servers registered by an
    administrator: a roleplayer reads `GET /api/models` in the order the LLM Servers page
    shows the enabled models, and `GET /api/sessions/{id}/configuration` for an existing
    session created before 017 answers `model: null`. (D1, D7)
