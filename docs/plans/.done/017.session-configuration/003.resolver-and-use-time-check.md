# Step 003 — The two resolvers, the session configuration read, and the use-time model check

## Goal

Add `services/configuration.py` with the per-level input values, the two pure resolver
functions (D8, R1), `get_session_configuration` (one owner-scoped read applying both),
and `resolve_model_for_use` (D2's check order; no call site until `021`).

## Source files

backend/app/services/configuration.py

## Test files

backend/tests/test_configuration_resolver.py

## Interface intent

**`services/configuration.py`** (new)

- **`ConfigLevel`**: a string enum with `session`, `character`, `user`, `default`.
- **`ModelRef`**: frozen value, `server_id` (int) and `model_name`.
- **`ResolvedSetting`**: frozen value with `session`, `inherited`, `inherited_level`,
  `value`, `level`, generic over the setting's value type (text or boolean). It follows
  the Wire contract's level rules.
- **Per-level inputs**, frozen values, each carrying only what its level may hold:
  - **`CharacterAssistantLevel`**: `system_prompt` and the three tool switches. **No
    model** and no language field;
  - **`SessionAssistantLevel`**: `model` (`ModelRef` or none, the captured reference),
    `system_prompt` and the three tool switches;
  - **`UserLanguageLevel`**: `rp_language`, `preferred_language`. Nothing else;
  - **`SessionLanguageLevel`**: `rp_language`, `preferred_language`.
- **`AssistantConfiguration`**: `model` (passed through), `system_prompt`, and the three
  `tool_*` as `ResolvedSetting`s.
- **`LanguageConfiguration`**: `rp_language`, `preferred_language` as `ResolvedSetting`s.
- **`SessionConfiguration`**: the Wire contract's seven fields (`model`,
  `system_prompt`, the three `tool_*`, `rp_language`, `preferred_language`), assembled
  from the two results.
- **`resolve_assistant_chain`**: pure; takes exactly a character-level input and a
  session-level assistant input; returns an `AssistantConfiguration`. Lowest non-null
  wins (session, then character). A tool that no level sets is enabled with level
  `default`. The model is the session's captured reference **unchanged**. It never reads
  the registry and never substitutes (R4).
- **`resolve_language_chain`**: pure; takes exactly a user-level input and a session-level
  language input; returns a `LanguageConfiguration`. Session wins, then user. Nothing set
  → value and level null.
- **`get_session_configuration`**: takes a connection, the caller's user id and a session
  id. One owner-scoped read of the session, its character (scoped by the caller) and the
  caller's user row, then both resolvers. Returns a `SessionConfiguration`. A missing or
  another user's session raises `SessionNotFoundError`. Archived session or character →
  read normally. Writes nothing and leaves no transaction open.
- **`resolve_model_for_use`**: takes a connection, the caller's user id and a session id.
  Raises `SessionNotFoundError` as above. Otherwise, in D2's order: no enabled model on
  the instance → `NoModelEnabledError`; captured model none → `ModelNotChosenError`;
  else `validate_chat_model` with level `session` (raising `ModelNotEnabledError` when not
  enabled). Returns the `EnabledChatModel`. Writes nothing. A module comment states that
  it has no call site until `021`.

## Definition of done

1. `[test]` `resolve_assistant_chain`: character prompt "C", session prompt none →
   value "C", level `character`, inherited "C", inherited_level `character`, session none
   (US-059.AC-2, US-108.AC-1). Session prompt "S" → value "S", level `session`, inherited
   still "C" (US-060.AC-1). Neither → value, level, inherited and inherited_level all null
   (US-059.AC-1).
2. `[test]` Tools resolve independently: character sets memo search off and nothing else,
   session sets web search off and session search on. The result is memo search off
   (`character`), session search on (`session`), web search off (`session`). A tool set
   by neither is on with level `default`, inherited true, inherited_level `default`. A
   session override beats a contrary character override for the same tool. (US-062.AC-1,
   US-062.AC-2, D5)
3. `[test]` `resolve_assistant_chain`'s model output equals the session input's model
   (same server id and name), including none. The character input type has no `model`,
   `rp_language` or `preferred_language` field, so a differing character model cannot
   influence the result. (R4, D8, US-139.AC-1)
4. `[test]` `resolve_language_chain`: user "Japanese" / "English", session none / none →
   values "Japanese" / "English" with level `user` (US-061.AC-1, US-108.AC-2). Session RP
   language "French" → RP "French" level `session`, preferred still "English" level
   `user` (US-061.AC-2). Neither set → value and level null for each.
5. `[test]` The two resolvers are distinct functions. `resolve_assistant_chain`'s
   parameters are exactly a character input and a session input (no user parameter), and
   `resolve_language_chain`'s are exactly a user input and a session input (no character
   parameter). The user-level input type has exactly the fields `rp_language` and
   `preferred_language`. (R1 — two functions, shapes enforce the chains)
6. `[test]` `get_session_configuration` on a raw-inserted user (languages set), character
   (prompt, one tool off) and session (one language override, captured model) returns
   the combined result per DoD-1..4. After the character's prompt is changed, a second
   call returns the new prompt for the **same, existing** session (live), while the
   captured model is unchanged even after the character's model columns are set.
   (US-059.AC-1, US-059.AC-2, US-139.AC-1, R4)
7. `[test]` `get_session_configuration` for another user's session and for a missing id
   raises `SessionNotFoundError`. An archived session (and a session under an archived
   character) reads normally. (R5, R6)
8. `[test]` `resolve_model_for_use`: no enabled model on the instance → `NoModelEnabledError`
   **both** when the session's model is NULL and when it holds a pair (US-107.AC-1,
   US-107.AC-2, D2). Models enabled, session model NULL → `ModelNotChosenError`. Session
   model set and not enabled while another model is → `ModelNotEnabledError` whose detail
   is `{ "server_id": "<decimal string>", "model_name": …, "level": "session" }` (D3).
   Session model enabled → returns it. Another user's session → `SessionNotFoundError`.
9. `[test]` `resolve_model_for_use` never writes. The session row is byte-identical
   before and after each DoD-8 case, and it never returns a model other than the
   session's captured one (no fallback to the first enabled model). (R4)
10. `[test]` The module imports from `app.services` only `llm_registry`, and only the
    names D12 lists. It imports no `fastapi`. (D12)
