## Request models — "which keys were sent"

`model_fields_set` on a pydantic v2 model distinguishes an explicit `null` from an
absent key. Services take `llm_registry.UNSET` for "absent" (D12, `004`), so the router
(`005`) maps fields not in `model_fields_set` to `UNSET`. DoD-7..9 assert "marked as
sent" through `model_fields_set` or an equivalent the skeleton exposes; the skeleton
records which.

Normalisation is a field validator that runs only on a supplied string:

- languages: strip, then `""` → `None`;
- system prompt: if `value.strip()` is empty → `None`, else return `value` unchanged;
- `model_name`: reject blank (`value.strip()` empty), keep verbatim.

`UpdateSessionConfigurationRequest.model` must reject an explicit `null` while allowing
absence. A non-nullable optional field (default sentinel or `None`-rejecting validator)
gives FastAPI's 422. 011 `001.context.md` "Gotcha — the nullable inbound snowflake"
covers the nullable `SnowflakeIn` form `ModelRefIn` does **not** need (its `server_id` is
required inside the object).

## Response models — nested from attributes

Services return frozen dataclasses (`003`, `004`): `ModelRef(server_id, model_name)`, a
resolved setting value with `session` / `inherited` / `inherited_level` / `value` /
`level`, and configuration values with the field names of the Wire contract. Response
models set `from_attributes=True` on every nested model so
`SessionConfigurationResponse.model_validate(value, from_attributes=True)` works. Level
values reach the response as the service's `StrEnum` members, which equal the literal
strings. `005` pins the round trip.

## Gotcha — `/api/health` on existing databases

Changing two declared tables makes an existing database report `schema: "drift"` until an
administrator presses Sync on each (DoD-11). This is designed behaviour, as for every
feature before. Tests build the schema with `create_all`.
