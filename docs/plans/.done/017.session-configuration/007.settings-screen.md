## Interface intent

**`app/settingsState.ts`** (new)

- **`SettingsState`**: data class, observable fields only: `status` (`"idle"`,
  `"loading"`, `"ready"`, `"failed"`; starts `"idle"`); `saved` (`UserSettings` or null,
  the server's last answer); `rpLanguage`, `preferredLanguage` (editor text, start `""`);
  `saveStatus` (`"idle"` or `"saving"`); `saveFailure` (string or null).
- **`loadSettings`**: state and optional signal. Sets `"loading"`, fetches the user's
  settings, and on success writes `saved` and fills both editor texts from it (null →
  `""`), then `"ready"`. On failure `"failed"`. Writes nothing once aborted; never
  rejects.
- **`setRpLanguage`**, **`setPreferredLanguage`**: write the editor text.
- **`isDirty`**: pure; true when either editor text, trimmed with blank as null, differs
  from `saved`.
- **`canSave`**: pure; `"ready"`, dirty, and not saving.
- **`saveSettings`**: state only (no signal: a save that started reaches the server).
  Sends a patch with **only the changed keys** (trimmed, blank → null). On success writes
  `saved` and both editor texts from the response, and clears `saveFailure`. On any
  failure sets `saveFailure` to **"Could not save your settings."** and keeps the typed
  text. Never rejects.

**`app/SettingsScreen.tsx`** (new)

- **`SettingsScreen`**: `observer` component, no props. Creates a `SettingsState` and a
  `MemoLevelState` for scope `"user"` with no scope id, each once with `useState`. On
  mount it runs `loadSettings` and `loadMemoLevel`, each with its own `AbortController`
  aborted on unmount. Renders, in order:
  - a heading **"Settings"**;
  - a region **"Languages"** headed **"Languages"** (one level below "Settings"). By
    status: a `Loader`; or **"Could not load your settings"** with **"Retry"** (re-runs
    the load with a fresh controller); or, when ready, text inputs **"RP language"** and
    **"Preferred language"** bound to the editor texts, each with the description **"Used
    by every session that does not set its own."**, a button **"Save"** enabled iff
    `canSave`, and, when `saveFailure` is set, that sentence in an inline `Alert`;
  - `MemoLevelGroup` with the user-level state, title **"Your notes"**, the same heading
    level as "Languages", and an `onRetry` that reloads the level with a fresh controller.
    **Not** `reorderable` (D15).
  - No notification anywhere.

**`app/App.tsx`** (changed)

- The `/settings` route renders `SettingsScreen` instead of `null`. Nothing else changes.

## Definition of done

1. `[test]` A fresh `SettingsState` is `"idle"` with `saved` null and empty texts.
   `loadSettings` requests exactly `GET /api/me/settings`, and on `{rp_language:
   "Japanese", preferred_language: null}` it becomes `"ready"` with texts `"Japanese"` and
   `""`. A failure writes `"failed"` and resolves. An aborted signal writes nothing.
2. `[test]` `isDirty` / `canSave`: unchanged texts → false. Text `" Japanese "` against
   saved `"Japanese"` → not dirty. `""` against saved `"Japanese"` → dirty. While
   `saveStatus` is `"saving"` → `canSave` false.
3. `[test]` Changing only the RP language to `"French"` and calling `saveSettings` sends
   `PATCH /api/me/settings` with exactly `{"rp_language":"French"}`. Clearing the
   preferred language sends exactly `{"preferred_language":null}`. After the response the
   texts equal the served values and `isDirty` is false. A failed PATCH sets "Could not
   save your settings." and keeps the typed text. (US-058.AC-1, D6)
4. `[test]` `SettingsScreen` with both loads answered renders the "Settings" heading, a
   "Languages" region holding textboxes "RP language" and "Preferred language" with the
   served values, and a "Your notes" region listing the user's notes from
   `GET /api/memos?scope=user`, in that document order. (US-092.AC-1)
5. `[test]` Typing "Japanese" into "RP language" and "English" into "Preferred language",
   then pressing "Save", sends both keys. The inputs then show the served values and
   "Save" is disabled. (US-058.AC-1, US-092.AC-1)
6. `[test]` A failed settings load shows "Could not load your settings" and "Retry" inside
   "Languages", while "Your notes" still renders. "Retry" re-requests
   `GET /api/me/settings`. A failed save shows "Could not save your settings." in the
   region. `notifyFailure` is never called. (D19)
7. `[test]` In "Your notes", "New note", typing and blurring POSTs `/api/memos` with
   `{"scope":"user","scope_id":null,"body":…}`. No note in the group exposes a reorder
   position name ("Note 1 of …"). (US-092.AC-1, D15)
8. `[test]` `App` at `/settings` renders the settings screen inside the workspace's main
   region, with the tree still present. The amended App, WorkspaceShell and entries test
   clauses that pinned `/settings` as an empty centre now stub `/api/me/settings` and
   `/api/memos?scope=user` and expect the "Settings" heading. Every other assertion in
   those files keeps passing. (`007.context.md`)
9. `[test]` The user menu's "Settings" item navigates in-entry to `/settings`, and the
   settings screen renders. (US-092.AC-1, UC-071)
10. `[manual/live]` Against a running backend: open Settings from the user menu, set both
    languages, Save, reload — the values persist. Add a note under "Your notes" and find
    it under "Your notes" on a session's note wall. Open a session's configuration (after
    `011`) and see the languages shown as inherited from your settings. (US-058.AC-1,
    US-092.AC-1, US-061.AC-1)
