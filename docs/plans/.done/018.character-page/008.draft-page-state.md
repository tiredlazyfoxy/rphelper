# Step 008 — The character screen's state: draft page and blur-save

## Goal

Rework `characterScreenState.ts` for the draft page and blur-save. A draft becomes a
character when its first non-blank name is committed (posting the persona too). On an
existing character, name and persona each save on commit, and a blank name is refused
client-side. A flush saves pending edits when the screen goes away. Archive and Restore
are unchanged (D6, D7).

## Source files

frontend/src/app/characterScreenState.ts

## Test files

frontend/tests/app/characterScreenState.test.ts

## Interface intent

**`app/characterScreenState.ts`** (changed; 009 `006`)

- **`CharacterScreenState`** keeps its fields and constructor (`characterId` string or
  null, `status`, `character`, `name`, `sheet`, `submitStatus`, `error`). It gains a
  **name error** (the client-side sentence, or null) and per-field **in-flight** markers
  for the name save and the persona save. Observable fields only.
- **`isNewCharacter`**, **`loadCharacter`**, **`submitArchive`**, **`submitRestore`**:
  unchanged. **`isDirty`**: unchanged in meaning.
- **Is-draft derivation** (new, pure): true while the mode is new **and** no character has
  been created yet.
- **`submitCreate`** (changed; same parameters: state, workspace `CharactersState`,
  `onCreated(id)`, optional signal): **sends nothing** unless the state is a draft, the
  trimmed name is non-blank, and no create is in flight. Otherwise it sets `"submitting"`,
  clears `error`, and POSTs the draft's name (as typed) **and sheet**. On success it holds
  the returned row as `character` (so the draft is over), adopts its name and sheet, applies
  it to the workspace state, and calls `onCreated` with its id. On failure it sets "Could
  not create the character.", keeps the draft and calls nothing. It returns to `"idle"` and
  never rejects.
- **Name commit** (new effect; state, workspace state): existing character only. Trimmed
  blank → sets the name error **"A character needs a name."** and sends nothing.
  Otherwise it clears the name error. If the name equals the held character's, or a name
  save is in flight, it sends nothing. Otherwise it PATCHes `{ name }` (D7).
- **Persona commit** (new effect; state, workspace state): existing character only. Sheet
  unchanged or a persona save in flight → nothing. Otherwise PATCH `{ sheet }`.
- Both commits, on success: they apply the returned row to the workspace state. They
  replace `character` only if the returned `updated_at` is **not older** than the held
  one's. They replace the field's draft with the returned value only if the draft still
  equals what was sent. The other field's draft is never touched. On failure: "Could not
  save the character.", the typed text kept, `character` unchanged. Neither takes a signal
  or rejects.
- **Flush** (new effect; state, workspace state): in a draft, runs `submitCreate` with a
  no-op `onCreated` when the name is non-blank. On an existing character, runs the name
  commit (unless the name is blank) and the persona commit. Used on unmount (D7).
- **`canSubmit`** and **`submitSave`** are **removed**: there is no Create or Save button
  left to drive them (D6, D7).

## Definition of done

1. `[test]` A state constructed with `null` is a draft, `"ready"`, with no character.
   `submitCreate` with an empty or whitespace-only name sends **no request** and does not
   call `onCreated`. With a persona typed and the name blank, it still sends nothing.
   (US-097.AC-1, UC-074 alternate flow)
2. `[test]` With name "Aria" and sheet "# Aria", `submitCreate` POSTs `/api/characters`
   with exactly `{"name": "Aria", "sheet": "# Aria"}`. On the 201 it calls `onCreated`
   once with the served id string, the workspace `CharactersState` contains the row, and
   the state is no longer a draft. (US-097.AC-2, UC-074, D6)
3. `[test]` A second `submitCreate` while the first is pending sends no second request. A
   `submitCreate` after success sends nothing. (D6 — no double create)
4. `[test]` A failed create sets "Could not create the character.", keeps name and sheet,
   leaves the state a draft, does not call `onCreated`, and leaves the workspace state
   unchanged. (R10, D6)
5. `[test]` On a loaded character "Aria": the name commit with "Aria" sends nothing. With
   "Aria Vale" it PATCHes exactly `{"name": "Aria Vale"}`, then `character` and the
   workspace state hold the served row. With "   " it sends nothing, sets "A character
   needs a name.", keeps the typed "   " in the draft, and `character.name` stays "Aria".
   A later commit with a non-blank name clears the error. (D7, US-021.AC-1)
6. `[test]` The persona commit with an unchanged sheet sends nothing. With a changed sheet
   it PATCHes exactly `{"sheet": <sheet>}`, and the name draft is untouched even when it
   holds an unsaved edit. (D7)
7. `[test]` While a persona PATCH is pending, editing the sheet further keeps the newer
   text after the response, and `isDirty` stays true. A second persona commit during the
   pending save sends nothing. (D7, R10)
8. `[test]` A save response whose `updated_at` is older than the held character's (an
   archive answered first) does not replace `character`. A newer one does. (D7)
9. `[test]` A failed name or persona save sets "Could not save the character.", keeps the
   typed text and keeps `character` unchanged. (R10, 009 D12)
10. `[test]` Flush on a loaded character with a changed name and a changed sheet sends one
    name PATCH and one sheet PATCH. On a draft with name "Aria" it POSTs the create once.
    With nothing changed it sends nothing. (D7, R10)
11. `[test]` 009 `006`'s load, archive and restore assertions in
    `tests/app/characterScreenState.test.ts` keep passing. Its `canSubmit` / `submitSave`
    / Create-button-era assertions are replaced by DoD-1 to DoD-10, and each replaced item
    is named in `## Tests`. (D6, D7)
