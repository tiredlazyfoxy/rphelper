# Step 009 — The character page, assembled

## Goal

Rebuild `CharacterScreen` into the finished page. `/characters/new` becomes the draft page
(a marker, Name and Persona only, create on the first committed non-blank name, replace
navigation). `/characters/:id` saves name and persona on focus loss, with Create and Save
gone. The body runs in the agreed order: notes grid → setups → configuration → sessions →
the page composer last. Pending edits are flushed on leaving. The page is two columns, with
no wall (D6, D7, D10; US-096, US-097, US-117).

## Interface intent

**`app/CharacterScreen.tsx`** (changed; 009 `007`, edited by 010, 011 `008`, 015 `009`)

- **`CharacterScreen`**: props unchanged from the built screen (the workspace
  `CharactersState`, `characterId`, and the workspace `SessionsState` 011 already threads
  for `SessionsSection`). `CharacterRoute` is unchanged (keyed by id).
- **Draft mode** (new mode while a draft): heading "New character" with a `Badge`
  **"Draft"** beside it, the dimmed line **"Nothing is saved until you enter a name."**,
  the inline error `Alert` when set, the **Name** input, and the **Persona** editor.
  - Name losing focus runs `submitCreate`. Its `onCreated` navigates **with `replace`** to
    `/characters/<id>` (id verbatim), unless the screen has unmounted.
  - Persona losing focus does nothing in a draft. Its text rides along with the create.
  - While the create is in flight, Name is read-only and the Persona editor is `readOnly`.
  - **Nothing else renders**: no Create, no Save, no Archive, no notes, setups,
    configuration, sessions or composer. No request is made on mount.
- **Existing mode, ready**, in document order:
  1. header: the saved name as heading and the "Archived" badge (as built);
  2. the inline error `Alert` when set; **Name** (losing focus runs the name commit; the
     name error renders as the input's error); **Persona** in a wrapper whose focus-leave
     (focus moving outside the wrapper, not into the editor's own toolbar) runs the persona
     commit; **Archive** / **Restore** (as built). **No Save button**;
  3. `CharacterNotesSection` (keyed by id), **moved** here from after Sessions;
  4. `SetupsSection` (as built);
  5. `CharacterConfigSection` (`007`) for the character, with the page's heading order;
  6. `SessionsSection` (as built);
  7. `CharacterComposer` (`004`) for the character with the workspace `SessionsState`,
     **last**.
- Loading, "Character not found" and "Could not load the character" + "Retry" render as
  built, with none of the sections.
- **On unmount**, in either mode, it runs the flush (`008`) with the workspace state.
- No `.css`, no `shell.css` change, no note wall, no notification of its own.

## Definition of done

1. `[test]` At `/characters/new` the main region shows "New character", a "Draft" badge and
   "Nothing is saved until you enter a name.", a "Name" textbox and a "Persona" textbox,
   and **no** "Create", "Save", "Archive" or "Send" button and no "Notes", "Setups",
   "Configuration", "Sessions" or "Start a session" region. No request is made.
   (US-097.AC-1, UC-074, D6)
2. `[test]` On the draft page, typing a persona and blurring it sends nothing. Blurring an
   empty Name sends nothing. Unmounting the page with only a persona typed sends nothing.
   (US-097.AC-1, UC-074 alternate flow)
3. `[test]` In `App` at `/characters/new`: typing "Aria" into Name, a persona "# Aria", then
   blurring Name sends one `POST /api/characters` with exactly
   `{"name": "Aria", "sheet": "# Aria"}`. After the 201 the tree's "Characters" list shows
   "Aria", the location is `/characters/<served id>`, and Back does not return to
   `/characters/new` (replace). (US-097.AC-2, UC-074, UC-017, D6)
4. `[test]` While that POST is pending, Name is read-only and blurring it again sends no
   second POST. A failed POST shows "Could not create the character.", keeps "Aria" and
   the persona, stays at `/characters/new`, and still shows "Draft". (D6, R10)
5. `[test]` At `/characters/<id>` once loaded: there is no "Save" button. Changing Name to
   "Aria Vale" and blurring sends exactly `PATCH {"name": "Aria Vale"}`, and the heading and
   the tree row then read "Aria Vale". Clearing Name and blurring sends nothing and shows "A
   character needs a name." on the Name field, while the heading still reads the saved
   name. Changing the persona and blurring its editor sends exactly `PATCH {"sheet": …}`.

6. `[test]` At `/characters/<id>` once loaded, the regions appear in exactly this document

7. `[test]` The character page renders **no note wall**: no complementary landmark "Note
