# Step 007 — step-specific context

Feature-wide facts are in `context.md`: **D9**, the UI strings table (Configuration rows),
"Test conventions". The state and its derivations are `006`'s. This step only renders and
binds them.

## Heading order

The page's section headings (`SetupsSection` "Setups", `SessionsSection` "Sessions",
`CharacterNotesSection` "Notes") share one heading order. `009` passes the same order to
this section. The prop exists so this component does not hard-code a level that the page
might change.

## Mantine specifics

- `Select` options render in a portal. Tests open the combobox labelled "Model" and choose
  with `screen.getByRole("option", { name })`. A disabled option is a Mantine option with
  `disabled`.
- `Select`'s value is a string. Map each choice to a string key the component owns (for
  example the unset key and `server_id` + `model_name` joined), never by parsing an id.
  The key is opaque, and the choice list from `006` is the source of truth.
- `SegmentedControl` renders radios. Tests choose with `getByRole("radio", { name })`
  scoped to the control's group (017 conventions). Because three controls share the option
  names "Default" / "On" / "Off", every query is scoped to its group's name.
- The system prompt is plain text, not markdown, so it uses a `Textarea`, not
  `MarkdownEditor`. The session modal's prompt field (017 `010`) is the precedent.
