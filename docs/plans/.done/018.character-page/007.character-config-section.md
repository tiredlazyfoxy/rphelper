# Step 007 — The configuration block

## Goal

Add `CharacterConfigSection`, the character page's "Configuration" region. It shows the
model, the system prompt and the three tool switches, each with its resolved value and
whether it is set on this character, and lets each be edited in place (D9; UC-048, US-059,
US-096).

frontend/src/app/CharacterConfigSection.tsx

## Test files

frontend/tests/app/CharacterConfigSection.test.tsx

## Interface intent

**`app/CharacterConfigSection.tsx`** (new)

- **`CharacterConfigSection`**: an `observer`. Props: the character id and the heading
  order the page uses for its sections. It creates one `CharacterConfigState` with
  `useState`. On mount it runs the load effect with an `AbortController` aborted on
  unmount. It renders a region **"Configuration"** headed **"Configuration"** that holds:
  - while either load is idle or loading: a small `Loader`;
  - when either load failed: **"Could not load the configuration"** and **"Retry"**, which
    re-runs the load with a fresh controller (aborting any in-flight one);
  - when both are ready:
    - a Mantine `Select` **"Model"** over `006`'s model choices (the disabled "(not
      enabled)" choice included), with the description sentence from the strings table and
      the model line under it. Choosing "First enabled model" saves `{ model: null }`.
      Choosing a model saves `{ model: { server_id, model_name } }`. It is disabled while
      the model save is in flight;
    - a Mantine `Textarea` **"Character system prompt"** (`autosize`) bound to the prompt
      draft, which runs the prompt commit when it loses focus. The prompt line is under it;
    - three Mantine `SegmentedControl`s **"Memo search"**, **"Session search"**,
      **"Web search"** with options **"Default"** / **"On"** / **"Off"**, showing the
      held value. Choosing saves that one tool key, and the control is disabled while its
      save is in flight. The tool's line is under it;
    - the failure sentence, when set, as text in the region.
  - No language field, no notification, no modal, no request on render beyond the load.
- Every effect is `void`ed from its handler.

## Definition of done

1. `[test]` Over stubs answering a configuration (model A on S1, prompt "Be terse.", memo
   search null, session search false, web search true) and models `[A, B]`: the region
   "Configuration" shows the "Model" combobox with "A (S1)" and "Set on this character.",
   the "Character system prompt" textbox holding "Be terse." with "Set on this
   character.", "Memo search" on "Default" with "On (default)", "Session search" on "Off"
   with "Off (set on this character)", and "Web search" on "On" with "On (set on this
   character)". It holds no "RP language" and no "Preferred language" control.
   (US-096.AC-1, UC-048, US-059.AC-2, US-061.AC-3)
2. `[test]` The "Model" combobox's description reads "Applies to sessions started from now
   on. Existing sessions keep their model.". With model null it shows "First enabled model"
   and "Not set: new sessions take the first enabled model.". (US-106.AC-1, US-139.AC-1)
3. `[test]` Choosing "B (S2)" sends `PATCH /api/characters/<id>/configuration` with
   exactly `{"model": {"server_id": "<S2>", "model_name": "B"}}`. While it is pending the
   combobox is disabled and still shows "A (S1)". After the 200 it shows "B (S2)". Choosing
   "First enabled model" sends exactly `{"model": null}`. (US-059.AC-2, D9)
4. `[test]` With a configured model absent from the served list, the combobox shows
   "A (not enabled)", and that option is disabled when the list is opened. (D9)
5. `[test]` Choosing "Off" on "Memo search" sends exactly `{"tool_memo_search": false}`.
   Choosing "Default" on "Session search" sends exactly `{"tool_session_search": null}`.
   After each 200 the control and its line follow the served configuration.
   (US-062.AC-1, D9)
6. `[test]` Typing "Stay in character." into "Character system prompt" and blurring sends
   exactly `{"system_prompt": "Stay in character."}`. Blurring with no change sends
   nothing. Clearing it and blurring sends exactly `{"system_prompt": null}`, after which the
   line reads "Not set: no system prompt.". (017 D6, D9)
7. `[test]` A 409 `model_not_enabled` on choosing a model shows "That model is no longer
   enabled." in the region, keeps the previous selection, and requests `GET /api/models`
   again. A 500 on a tool save shows "Could not save the configuration.". `notifyFailure`
   is never called. (D9; 017 D19's posture)
8. `[test]` A failed configuration load shows "Could not load the configuration" and
   "Retry". "Retry" requests both `GET …/configuration` and `GET /api/models` again and,
   on success, the controls render. (D9)
9. `[manual/live]` Against a running backend with two enabled models: set the character's
   model and web search off on its page. Start a new session from the page composer and
   see that model in the session header and "Web search: off". An older session of the
   same character keeps its model (US-139.AC-1). Clearing the model back to "First enabled
   model" makes the next session take the first enabled model (US-106.AC-1).
