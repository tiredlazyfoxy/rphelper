## Declared interfaces (B — re-verify at build time)

- 015 `007` / 016 `003` `MemoLevelGroup`: props `state`, `title`, `headingOrder`,
  `onRetry`, `reorderable?`. The card markup is **inline in the group** (no separate card
  component). A thin sortable wrapper around it applies only when `reorderable`. The per-level
  `SortableContext` uses the **vertical list strategy** over the saved note ids. Sortable
  cards keep role `listitem`, `tabIndex` 0, the name "Note <n> of <total>", and keyboard
  activation only from the card itself. They are disabled while their editor has focus and
  while `isReorderInFlight(state)`. `reorderFailure(state)` renders inline.
- 016 `004` `app/memoReorder.ts`: a pure drop decision over (levels with keys and ordered
  ids, active id, over id), and a **drop effect** taking `MemoLevelState[]`, the active id
  and the over id. The effect calls `reorderMemoLevel` on the one level involved, or does
  nothing. Pass `[state]` for the character page.
- 016 `004` `MemoChainSection`: one `DndContext` in its ready render with `PointerSensor`
  (distance 6px), `KeyboardSensor` + `sortableKeyboardCoordinates`, a drag-end that calls
  the drop effect with `state.levels`, and announcements by position and group. Every group
  is `reorderable`. These sensors and announcements are what moves into `memoDnd.ts`.
- 015 `009` `CharacterNotesSection`: props `{ characterId }`. It creates
  `MemoLevelState("character", id)` with `useState`, loads it on mount with an
  `AbortController` aborted on unmount, renders `MemoLevelGroup` titled "Notes" with the
  page's heading order, and retries with a fresh controller.

## Grid without a stylesheet

The list stays the element that carries role `list`. Its children stay listitems. Grid is
a Mantine layout prop (for example `SimpleGrid` rendered as the list element) or an inline
`display: grid` with `gridTemplateColumns: repeat(auto-fill, minmax(<card min>, 1fr))`. No
`.css` file and no new selector, because `tests/stylesheets.test.ts` pins both. The card
minimum width is the coder's call. jsdom does not lay out, so the visual grid is
`[manual/live]`.

## The rect strategy

`@dnd-kit/sortable` exports `rectSortingStrategy` beside `verticalListSortingStrategy`.
Grid + `reorderable` picks rect. List + `reorderable` keeps vertical, which leaves the wall
unchanged. `sortableKeyboardCoordinates` works with both.
