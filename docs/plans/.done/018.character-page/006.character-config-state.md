## Interface intent

**`app/configurationApi.ts`** (changed; 017 `006`)

- **`CharacterConfiguration`** type: `model` (017's `ModelRef` or null), `system_prompt`
  (string or null) and the three `tool_*` (boolean or null), mirroring the wire exactly.
- **`CharacterConfigurationPatch`** type: any subset of those five keys, each value or
  null. It has **no language key**. A patch is sent with exactly the keys it holds.
- **Fetch call**: a character id and an optional signal. It requests
  `GET /api/characters/<id>/configuration` and resolves to the configuration.
- **Update call**: a character id, a patch and an optional signal. It sends
  `PATCH /api/characters/<id>/configuration` and resolves to the configuration. Both calls
  rethrow `ApiError` unchanged.

**`app/characterConfigState.ts`** (new)

- **`CharacterConfigState`**: data class with observable fields only, constructed from a
  character id. It holds the configuration and its load status, the enabled models and
  their load status, the **system prompt draft** (the prompt text being edited), which
  key's save is **in flight** (if any), and the **failure** sentence (or null).
- **Load effect**: takes the state and an optional signal. It requests the configuration
  and the enabled models (017's `fetchEnabledModels`), writes each with its own status
  (ready or failed), and seeds the prompt draft from the configuration (`""` for null).
  It sets loading first, so a retry shows loading. Aborted → writes nothing. Never rejects.
- **Save effect**: takes the state and one patch. It does nothing while another save is in
  flight. It clears the failure, marks the patch's key in flight, and PATCHes. On 200 the
  returned configuration replaces the held one, and the prompt draft follows the returned
  prompt. On 409 `model_not_enabled` the failure becomes **"That model is no longer
  enabled."** and the enabled models are re-requested. On any other failure the failure
  becomes **"Could not save the configuration."** On failure the held configuration is
  unchanged. Either way it clears the in-flight key. No signal; never rejects; no
  notification.
- **Prompt commit effect**: takes the state. When the draft equals the held prompt (null
  read as `""`), it sends nothing. Otherwise it saves `system_prompt` as the draft
  **verbatim**, or as **null** when the draft is blank.
- **Derivations** (pure):
  - **model choices**: "First enabled model" (the unset value) first, then each enabled
    model labelled "<model_name> (<server_name>)" in served order. When the configured
    model is not among them, it is added as a **disabled** "<model_name> (not enabled)"
    choice. The selected choice is the configured model, or the unset value when null. Two
    models are the same when both `server_id` and `model_name` are equal as strings.
  - **resolved-value lines**, exactly the UI strings table's sentences: the model line
    (not set / set here), the prompt line (not set / set here), and each tool's line
    ("On (default)" when null; "On (set on this character)" / "Off (set on this character)"
    otherwise).
  - **tool choice** for a tool: Default / On / Off from null / true / false; and the
    patch value for a choice (Default → null, On → true, Off → false).

## Definition of done

1. `[test]` `fetchCharacterConfiguration("7250000000000000001")` (or the frozen name)
   requests exactly `GET /api/characters/7250000000000000001/configuration` and resolves
   to the served five-key object unchanged. (Wire contract)
2. `[test]` The update call with `{ model: { server_id: "7250000000000000301", model_name:
   "llama-3" } }` sends `PATCH /api/characters/<id>/configuration` with exactly that one
   key. `{ model: null }` sends exactly `{"model": null}`. `{ tool_web_search: false }`
   sends exactly that key. A 409 `model_not_enabled` envelope rejects with an `ApiError`
   carrying that code. (US-059.AC-2, 017 D10)
3. `[test]` Amends 017 `006` DoD-6: the module exports exactly the two character calls
   (fetch, update) and no other character-addressed call, and `CharacterConfigurationPatch`
   admits no `rp_language` / `preferred_language` key (a type-level check, compiled by
   `npm run typecheck`). (D9, US-061.AC-3)
4. `[test]` The load effect over a configuration (model A on server S1, prompt null, memo
   search null, session search false, web search true) and models `[A, B]` sets both
   statuses ready. The model choices are, in order, "First enabled model", "A (S1)",
   "B (S2)", with "A (S1)" selected. The lines read "Set on this character.", "Not set: no
   system prompt.", "On (default)", "Off (set on this character)", "On (set on this
   character)". (UC-048, US-059.AC-2, US-106.AC-1, D9)
5. `[test]` A configuration whose model is null selects "First enabled model" with the
   line "Not set: new sessions take the first enabled model.". A configured model absent
   from `[B]` adds a disabled "A (not enabled)" choice, which is selected. (US-106.AC-1,
   D9)
6. `[test]` The save effect with `{ tool_memo_search: false }` sends exactly that key.
   While it is pending, that key is in flight, the held configuration is still the old
   one, and a second save sends nothing. After the 200 the held configuration is the
   served one. (US-062.AC-1, D9 — never optimistic)
7. `[test]` The save effect on a 409 `model_not_enabled` sets "That model is no longer
   enabled.", keeps the held configuration, and requests `GET /api/models` again. On a
   500 it sets "Could not save the configuration.". Neither calls `notifyFailure`, and
   both resolve without throwing. (017 D10, D9)
8. `[test]` The prompt commit: unchanged draft → no request; draft `"  Be terse.\n"` →
   PATCH exactly `{"system_prompt": "  Be terse.\n"}`; a whitespace-only draft over a set
   prompt → PATCH exactly `{"system_prompt": null}`. (017 D6, D9)
9. `[test]` A failed configuration load sets its status failed and leaves the models
   result independent (and the reverse). An aborted load writes nothing. (D9)
