# Step 001 — step-specific context

- **Registry facts this step reads.** `backend/app/db/schema.py` has one
  module-level `metadata`, and every table is a `Table(...)` literal there. All ids
  are snowflake `BigInteger` (Integer on SQLite), and all timestamps are `Text`.
  The relevant tables are `users` (with `password_hash`), `auth_sessions`
  (`user_id`, `token_hash`), `llm_servers` (global; `api_key_ref` holds a
  `"$ENV_VAR"` pointer), `models` (global; FK `server_id`), `characters`, `setups`,
  `sessions`, `messages` (with self-FK `related_to`) and `memos` (`scope` enum and
  FK-less `scope_id`), plus 017's columns and 023's `translations`.
- **What is not a table.** `settled_entries`, `current_zone` and `message_states`
  are Core selectables, not Tables in `metadata`, so a walk over `sorted_tables`
  never meets them. 024's FTS/vec tables live in `backend/app/db/search_tables.py`,
  outside `metadata`. **Do not import `search_tables.py`.**
- **Why the id-column rule is name-based as well as metadata-based.** Two
  references carry no FK: `memos.scope_id` (the polymorphic scope pair,
  `data-model.md` ~L643-658) and 017's `model_server_id` (deliberately no FK). The
  `_id` suffix rule catches both without a column list. Note that
  `models.embedding_dim` is an integer and is not an id.
- **Enum columns.** Depending on how `schema.py` declares `memos.scope`, a selected
  value may arrive as a plain `str` or as a Python `enum.Enum` member. The
  serializer emits the string value in both cases.
- **Timestamp helper.** There is no shared helper. Each service has a private
  `_now_text()` returning `datetime.now(UTC).isoformat(timespec="microseconds")`,
  and this module gets its own in the same shape. The compact filename timestamp is
  derived from that value (e.g. `20261003T142530Z`); the exact compact form is the
  coder's choice within DoD-11.
- **Read snapshot.** Services read through a private `_reading(connection)` context
  manager, and this module keeps that convention. A whole export is one read
  transaction, so the file is a consistent snapshot under WAL.
- **Test seeding.** `backend/tests/conftest.py` provides `db_settings` and
  `db_engine`. Seed rows with Core inserts against the `schema` Tables, or with the
  existing services (`services.messages.append_message` / `file_partner_entry`,
  and `services/settle.py` for buried rows). To produce an `auth_sessions` row, log
  in or insert one directly.
