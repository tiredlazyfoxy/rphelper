# Step 006 — app entry points: own data, character, session

## Goal

Add the roleplayer's three export controls, all using `IconDownload`, with failures
going through `notifyFailure` and success silent:
- "Export my data" in the user menu;
- an Export button beside Archive/Restore on the character screen;
- an "Export" item in each session row's overflow menu.

## Interface intent

- **`exportDownloads.ts`** (new, `app` entry). This module holds:
  - **Three path builders.** The own-data path (`/api/export`) takes no input. The
    character export path takes a character id string. The session export path
    takes a session id string. Ids are used exactly as given.
  - **`runExport(path)`.** A free function that awaits `apiDownload(path)`. On any
    thrown value other than an abort, it calls `notifyFailure` with that value. It
    resolves on success and on handled failure, and never rethrows. It raises
    nothing on success.
- **`UserMenu`.** It gains a `Menu.Item` labelled "Export my data" with
  `leftSection` `IconDownload` (`size={16} stroke={1.5}`), shown to every role.
  Clicking it runs the own-data export.
- **`CharacterScreen`.** Its action `Group` gains a `Button variant="default"`
  labelled "Export" with `leftSection` `IconDownload`. It is placed next to
  Archive/Restore and is rendered under exactly the same condition as that button
  (a persisted character). It is in a loading state while the download is in flight;
  the flag is component-local `useState`. Clicking it runs the character export for
  the screen's character id.
- **`SessionsSection`.** Each session row's `IconDots` menu (`Actions for <label>`)
  gains a `Menu.Item` labelled "Export" with `leftSection` `IconDownload`. It is
  present for both active and archived rows. Clicking it runs the session export for
  that row's id.

## Definition of done

1. **DoD-1 [test]:** The path builders return `/api/export`,
   `/api/characters/<id>/export` and `/api/sessions/<id>/export`, with the id
   string inserted verbatim (including a 19-digit id beyond
   `Number.MAX_SAFE_INTEGER`).
2. **DoD-2 [test]:** `runExport` calls `notifyFailure` exactly once with the thrown
   `ApiError` when the download fails. It does not call it on success, and it does
   not call it when the download rejects with an abort error.
3. **DoD-3 [test]:** The user menu shows an "Export my data" item, for a
   roleplayer and for an admin alike. Choosing it requests `GET /api/export`.
   (US-079.AC-1)
4. **DoD-4 [test]:** The character screen for a persisted character shows an
   "Export" button in the same action group as Archive (or Restore). Clicking it
   requests `GET /api/characters/<that id>/export`. (US-080.AC-1)
5. **DoD-5 [test]:** The character draft page (no persisted character) renders no
   Export button.
6. **DoD-6 [test]:** Each session row's `Actions for <label>` menu contains an
   "Export" item, for active and for archived rows alike. Choosing it requests `GET
   /api/sessions/<that row's id>/export`. (US-081.AC-1)
7. **DoD-7 [test]:** On each of the three controls, a failed export (an error
   envelope, e.g. 404 `character_not_found`) raises one notification carrying the
   error's message. A successful export raises no notification and renders no
   success text.
8. **DoD-8 [test]:** No export control opens a confirm dialog. One click goes
   straight to the request.
9. **DoD-9 [manual/live]:** In a browser, each of the three controls downloads a
   `rphelper-<granularity>-….json` file.
10. **DoD-10 [manual/live]:** `npm run typecheck` passes.
