# Step 006 — step-specific context

- **Current components** (as harvested; all under `frontend/src/app/`):
  - **`UserMenu.tsx`.** A Mantine `Menu` with items Settings, Admin area
    (admin-only, a real `<a href="/admin">`) and Log out. Each item uses
    `Menu.Item leftSection={<IconX size={16} stroke={1.5}/>}`. "Export my data" is
    shown to every role. Its position among the items is the coder's choice, but it
    stays above Log out.
  - **`CharacterScreen.tsx`.** Assembled by 018. It has an action `Group` holding
    the Save `Button` and an Archive/Restore `Button variant="default"`. The draft
    page (`/characters/new`, UC-074) has no persisted id. The Export button follows
    Archive/Restore's render condition exactly, so no export is offered for an
    unsaved draft.
  - **`SessionsSection.tsx`.** From 011. It has a per-row `IconDots` `Menu`
    labelled `Actions for <label>`, with Archive/Restore items. These are labelled
    text items, so no `IconButton` is needed inside the menu (`ui-conventions.md`
    ~L90-98).

  If the skeleton finds that 011/018 placed `SessionsSection.tsx` elsewhere, it
  records the real path in `## Skeleton`. The scope is still that one component.
- **Why `runExport` lives in `exportDownloads.ts`.** Three components share one
  effect (download, then notify on failure). One free function keeps the failure
  routing in one place. It is a module of free functions with no MobX class: none
  of the three controls owns domain state about the export.
- **`notifyFailure`** comes from `shared/notifyFailure.ts`. It takes a thrown
  value and has no success path (`ui-conventions.md` ~L425-439). Success is
  silent, because the browser's download is the signal.
- **Test harness.** Vitest plus Testing Library under `frontend/tests/app/`. Fetch
  is stubbed per test with `vi.stubGlobal("fetch", ...)`. Menus are driven with
  `userEvent.setup({ pointerEventsCheck: 0 })` and accessible names; see
  `tests/app/UserMenu.test.tsx` for the existing pattern. `URL.createObjectURL`
  and `revokeObjectURL` need stubs in jsdom (`004.context.md`). Observe
  notifications by rendering inside `shared/AppProviders`, or by spying on
  `notifyFailure`.
