# Step 003 — step-specific context

- **Why the admin export goes in `admin_db.py`, not `transfer.py`.** That router
  has prefix `/api/admin/database` and holds `require_admin = require_role(Role.ADMIN)`
  (`routers/admin_db.py:41`) attached at router level. Placing the route there means
  it cannot forget the guard (`backend-structure.md` §"Authorization as router
  dependencies"). The route takes no body and no query, and has no path id, like
  the existing three.
- **Why the roleplayer routes go in `routers/transfer.py`.** That module is
  pre-named in `backend-structure.md` §Layout for FEAT-018. Routers group by
  feature, not by path prefix, which is the precedent `stream.py` set by owning
  `PATCH /api/messages/{id}`. So `/api/characters/{id}/export` and
  `/api/sessions/{id}/export` live here and not in `characters.py` or
  `sessions.py`. The paths have one more segment than those routers' item routes,
  so they cannot collide.
- **Why the routes return a raw `Response`, not a pydantic model.** This is a
  deliberate exception to "routes return pydantic models". The envelope is
  column-agnostic, so no static model can describe it. The JSON id boundary is still
  held, because `services/transfer.py`'s serializer stringifies ids before the
  router sees the envelope (step 001). The exception is recorded in `outcome.md`.
- **Existing facts.**
  - `require_user` lives in `app/dependencies.py` and yields
    `CurrentUser(id, username, role)`.
  - `get_connection` is in `app/db/engine.py`.
  - `SnowflakeIn` is in `app/models/ids.py`.
  - Router registration is `app/main.py` `create_app()` (~L126-140), and its
    docstring records why the routers are in the order they are. Keep that
    rationale intact and add the transfer router's line.
  - No route in the codebase returns a file download yet, so this step introduces
    the first `Content-Disposition`.
- **Test harness.** Router tests declare their own `_seed`, `_insert_user`,
  `_as(application, settings, user, pw) -> TestClient` and `_assert_envelope`
  helpers. See `tests/test_characters_router.py:96-200`,
  `tests/test_sessions_router.py` and `tests/test_memos_router.py` for the pattern.
  Messages can be created through `POST /api/sessions/{id}/zone/messages`.
