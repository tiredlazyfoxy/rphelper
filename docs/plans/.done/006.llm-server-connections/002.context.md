# Step 002 — step-specific context

Feature-wide facts are in `context.md` (D2 for why `embed` exists at all, D3 for the
`httpx` promotion and the async choice, D5 for one primitive with no `kind` branch, D6 for
the outcome taxonomy and its mapping, D7 for `llm_unreachable`'s 502). Only what is narrow
to this step is below.

## The authority for this module

`docs/architecture/llm-and-streaming.md`, "One OpenAI-compatible client" (lines 13–41). It
sketches the shape:

```
LlmClient(base_url, api_key)
  chat_stream(model, messages, tools) -> async iterator of provider deltas
  embed(model, texts)                -> list[vector]
  probe()                            -> reachability result   # UC-011
```

Two of the three land here. `chat_stream` is `019`/`021`'s and is deliberately absent, not
stubbed. The doc is also explicit that **the credential arrives through
`resolve_secret(api_key_ref)` at call time** and that a missing variable is
`secret_ref_missing` **raised before any network call** — which is why resolution happens
in the caller (step `003`) and not in this module.

## The taxonomy is declared here and nowhere else

`context.md` D6 fixes the four values and their conditions. This module is where the closed
set of values is **declared**; the registry service, the router's response model and the
frontend's row type all reuse it rather than re-spelling the strings. A second literal
list of those four values anywhere in the codebase is a defect.

## Why the probe never raises and `embed` always does

They answer different questions and are consumed differently.

- The probe answers "what is the state of this connection", and **every** state including
  total failure is a legitimate answer that UC-011 requires to be reported — so it returns
  a value. A probe that raised would force its two callers to catch in order to render a
  badge.
- `embed` answers "give me these vectors". There is no useful partial answer, so failure
  is an exception, and `context.md` D2 needs the *typed* failure to block a designation.

## Base-URL composition, which is the quiet source of field reports

An administrator supplies the base URL by hand (UC-010 step 2: "supplies its details").
The three forms that will actually be pasted are `http://host:8080`,
`http://host:8080/` and `http://host:8080/v1`. All three must reach the same models
endpoint. This is worth a `[test]` item (DoD-4) because getting it wrong produces a
`404` that the probe classifies as `unreachable`, sending the administrator to check a
host that is perfectly fine.

## The async decision, restated where it bites

`httpx.AsyncClient` means both operations are `async def`, which makes step `003`'s three
outbound registry functions `async` and step `005`'s three routes `async def`. The
SQLAlchemy `Connection` those functions hold stays **sync**. `context.md` D3 records why
that mix is accepted and what would flip it; this step should not try to hide it behind a
sync wrapper.

## Redaction

`deployment.md`'s rule binds this module hard, because it is the one place a credential
exists in memory in plaintext. No log line, no exception message and no `detail` may carry
the resolved credential, the authorization header, or a provider response body.
`backend-structure.md`'s error table says `llm_unreachable`'s `detail` carries a
provider-side message and **no request body**; this feature narrows that to a **structured
reason** (`context.md` D6), which is strictly safer.

## Gotchas

- **`httpx` is currently a dev-only dependency used as `TestClient`'s transport.** Moving
  it must not remove it from the dev environment — it is the same package, now declared at
  runtime, and the dev group should stop naming it rather than the runtime list duplicating
  it.
- **The models-listing response shape differs slightly between providers** (an envelope
  with a `data` array of objects carrying an `id`). Read defensively and classify an
  unreadable 2xx as `unreachable` (DoD-8) rather than raising — that is the difference
  between a badge and a stack trace.
- **A 2xx embeddings response with an empty `data` array is a failure, not an empty
  result** (DoD-12). This is precisely the "you designated a chat model" case.
- **No module-level client instance.** The timeout and the credential vary per server, and
  a shared client would leak one server's authorization header into another's request.
