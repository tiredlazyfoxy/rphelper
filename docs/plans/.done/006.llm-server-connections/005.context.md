## The route table

`context.md` D17 is the authority and is not restated here. Read it before writing a line
of this router; it also carries the four decisions embedded in it — `PATCH` rather than
named action routes, `POST` rather than `PUT` for the enabled set, no separate
`GET .../models` route, and a server-scoped clear-designation path.

## The one status decision a reader will question

`secret_ref_missing` answers **500** from an administrator-facing route (DoD-13). That is
the status `001` already froze for the code and this feature does not re-map it:
`context.md` D14 records the reasoning — the failure is a configuration fault of the
instance rather than a property of the connection, and the typed envelope carries the
variable name the administrator needs. `outcome.md` asks the architect whether the code's
status should be revisited now that it has an admin-facing call site. **Do not "fix" it in
this step.**

## The `PATCH` model and the three states

This is the single easiest thing in the feature to get wrong, and the route is where it
becomes visible. The model must make "the caller did not send `api_key_ref`" and "the
caller sent `api_key_ref` as `\"\"`" two different inputs to the service. A model with
`api_key_ref: str | None = None` collapses them and silently deletes a credential on every
save that did not retype it. The mechanism — pydantic's supplied-fields set, a sentinel
default, or an explicit wrapper — is the skeleton agent's to freeze; the *contract* is
DoD-8, and step `003`'s DoD-7 already requires the same distinction one layer down.

## What the response model does **not** carry

Fixed by `admin-surfaces.md` and R5, and asserted by DoD-2 and DoD-3:

- **no `api_key_ref` text**, ever, on any route — the boolean means "a pointer is
  recorded", not that it resolves; a pointer naming an absent variable fails later as
  `secret_ref_missing`, by design;
- **no session count, no user count, no character/setup/memo anything**, and no route that
  could power one;
- **no `active` field** — `context.md` D1.

## Status codes, gathered in one place

201 create · 204 delete and clear-designation · 200 everything else · 422 for every field-
shape refusal · 404 `llm_server_not_found` · 502 `llm_unreachable` · 500
`secret_ref_missing` · 409 `model_not_enabled` / `no_embedding_model` (no route raises
these two — they are use-time and have no call site here, `context.md` D12).

## Gotchas

- **The test route answers 200 for a failed test.** The *test* succeeded; the connection
  did not. Answering 502 there would make UC-011's alternate flow indistinguishable from a
  broken route and would push the UI into treating a normal outcome as an error.
- **Available-models answers 502 for a failed probe**, which is the opposite posture, and
  deliberately so: there is no useful partial answer to "what can it run".
- **The three `async def` handlers still hold a sync `Connection`.** Do not wrap the
  registry call in a thread executor and do not make the other six `async` for symmetry.
- **`DELETE` answers 204, so the shared frontend client returns `undefined`** for it — that
  is expected and step `006` relies on it.
- **One `include_router` line in `main.py` and nothing else.** The factory's ordering and
  the empty lifespan are frozen by `001` and asserted by DoD-24.
