# Step 007 — The server form modal: register and edit, and the three-state API-key rule

## Goal

Add the one modal that registers a connection and edits one, with a hand-rolled MobX draft
and a submit that keeps "untouched", "explicitly cleared" and "replaced" three distinct
things in the request payload.

## Source files

```
frontend/src/admin/serverFormDraft.ts
frontend/src/admin/ServerFormModal.tsx
frontend/src/admin/LlmServersPage.tsx
```

## Test files

```
frontend/tests/admin/serverFormModal.test.tsx
```

## Interface intent

**`frontend/src/admin/serverFormDraft.ts`** — the draft class, its pure derivations and its
one effect, in one module (`context.md` D16). `@mantine/form` is **not** used.

- **A draft class** holding observable fields only: the name, the kind, the base URL, the
  API-key pointer text, a **boolean recording whether the pointer field has been touched**,
  a server-errors map keyed by field name plus a general key, and an idle/submitting/done
  status. Constructed from an optional existing row — absent means register, present means
  edit — with the pointer field **always starting empty** even when the row records one,
  because the server never returns it. `makeAutoObservable(this, {}, { autoBind: true })`;
  **no methods and no computed getters**.
- **Pure derivation functions** taking the draft: a client-errors map (name non-empty, base
  URL non-empty and shaped like an absolute `http`/`https` URL, and the pointer either
  empty or `$` followed by at least one character — the client-side twin of step `001`'s
  rule, so the administrator is told before the round-trip); a merged errors map over
  client and server errors; and a can-submit predicate (no client errors and not currently
  submitting).
- **A submit free function** taking the draft, the target row's id or nothing, a re-load
  callback and an optional `AbortSignal`. It builds the payload, calls `POST` for a
  register and `PATCH` for an edit, maps failures onto field keys **by status or code,
  never by parsing prose**, and on success invokes the callback. It `runInAction`s its
  writes and early-returns on an aborted signal before writing.

  **The payload rule, which is the point of this step** (`context.md` D9):

  | Case | What the payload does with the pointer key |
  |---|---|
  | register, field left empty | the key is **omitted** |
  | register, field filled | the key carries the value |
  | edit, field never touched | the key is **omitted** — the stored pointer survives |
  | edit, field touched and left empty | the key is present as `""` — the stored pointer is cleared |
  | edit, field touched and filled | the key carries the new value |

  The other three fields are sent on a register always, and on an edit only when they
  differ from the row the draft was built from, so a `PATCH` says what actually changed.

**`frontend/src/admin/ServerFormModal.tsx`** — an `observer` Mantine `Modal` taking the
draft and the callbacks as props. Name and base URL as `TextInput`s; the kind as a
two-option `Select` (`llamaswap`, `OpenAI`) matching `llm_servers.kind`; the pointer as a
**`PasswordInput`** whose description says the field expects a pointer such as
`$OPENAI_API_KEY` and **not a key**, and, in edit mode, that leaving it untouched keeps the
stored pointer while clearing it removes one. Field errors render under their fields; the
general key renders **above** the form. The submit button is disabled while the can-submit
predicate is false. No confirm step — it is a form (`context.md` D18).

**`frontend/src/admin/LlmServersPage.tsx`** — two additions and nothing else: a page-header
button that opens the modal in register mode, and an **Edit** item in the existing row
menu that opens it in edit mode for that row. Both the open flag and the target row are
component-local `useState`; the modal body is **conditionally mounted** so a fresh draft is
constructed per open and discarded on close. On success the modal closes and the page
**re-loads** — no success toast.

## Definition of done

1. `[test]` Choosing the header button opens the modal with empty fields; filling name,
   kind and base URL and submitting `POST`s the registration, closes the modal, and the new
   row is visible after the page re-loads. (US-012.AC-1, US-012.AC-2, UC-010)
2. `[test]` Both kinds — llamaswap and OpenAI — can be chosen and are sent as the value the
   backend's two-member literal accepts; the `Select` offers exactly those two and no
   third. (US-012.AC-1; `context.md` D5)
3. `[test]` **D9, register.** Submitting with the pointer field left empty omits the key
   from the payload; submitting with it filled sends the value. (`admin-surfaces.md`'s
   API-key round-trip rule — **no product id**)
4. `[test]` **D9, edit, untouched.** Opening Edit on a row that records a pointer shows the
   field **empty**, and submitting without touching it sends a payload with **no pointer
   key at all** — the stored pointer survives, and the row still reports an API key after
   the re-load. (`admin-surfaces.md`'s API-key round-trip rule — **no product id**)
5. `[test]` **D9, edit, explicitly cleared.** Typing into the pointer field and then
   clearing it sends the key present as an **empty string**, after which the row reports no
   API key. (`admin-surfaces.md`'s API-key round-trip rule — **no product id**)
6. `[test]` **D9, edit, replaced.** Typing a new pointer sends it and the row still reports
   an API key. (UC-010)
7. `[test]` An edit that changes only the name sends only the changed field, leaving kind,
   base URL and pointer out of the payload. (UC-010; `context.md` D9)
8. `[test]` A pointer that does not start with `$` and is not empty is refused **in the
   client**, with the message on the pointer field and **no request issued** — the
   client-side twin of the server's 422. (`backend-structure.md`'s secret-pointer pattern;
   `admin-surfaces.md`'s "a value not starting with `$` is rejected on write")
9. `[test]` An empty name and an empty or non-absolute base URL are refused in the client
   with the message on the offending field and no request issued. (UC-010)
10. `[test]` A server refusal is mapped onto a field key **by status or code**, never by
    parsing the message text, and anything unmappable renders on the **general key above
    the form** rather than being swallowed. (`ui-conventions.md`'s draft convention, rule 3
    — **no product id**)
11. `[test]` The draft class declares **no methods and no computed getters**; the
    derivations are pure free functions over a constructed draft, testable with no render
    and no network; the submit is a free function that `runInAction`s its writes and
    early-returns on an aborted signal. (`context.md` D16 — **no product id**)
12. `[test]` A **fresh draft per open**: opening, typing, closing without saving and
    reopening shows empty fields — the modal body is conditionally mounted and no draft is
    reset-and-reused. (`ui-conventions.md`, draft lifetime — **no product id**)
13. `[test]` The modal's open flag and its target row live in component-local `useState`,
    not in the page store — the store's fields are unchanged by opening or closing it.
    (`ui-conventions.md`; `context.md` D16 — **no product id**)
14. `[test]` On success the modal closes and the **list re-loads**; **no success
    notification is raised** and nothing is written into the store in anticipation.
    (`ui-conventions.md`, no success toasts and never optimistic — **no product id**)
15. `[test]` The pointer control is a masked `PasswordInput` whose description tells the
    administrator the field expects a `$`-prefixed pointer rather than a key.
    (`admin-surfaces.md`'s reasoning for masking a non-secret — **no product id**)
16. `[test]` The modal renders **no active switch and no active field**. (`context.md` D1
    — **no product id**)
17. `[test]` Every id the modal handles is a `string`, and the modal imports no stylesheet.
    (`frontend-structure.md` — **no product id**)
18. `[manual/live]` Against a running backend, registering a real llamaswap connection and
    a real OpenAI connection both succeed; editing one without touching the key field keeps
    the key working on a subsequent Test connection, and clearing it makes the same test
    report `auth_failed` where the provider requires one.
19. `[manual/live]` `npm run typecheck`, `npm test` and `npm run build` all pass from
    `frontend/`.
