# Step 003 — Server registrations, and the probe primitive the two routes share

## Goal

Create `services/llm_registry.py` with the four registration operations and the one piece
of code in this backend that talks to an OpenAI-compatible server, plus the two operations
the router will expose over it — test-a-connection, which records its typed result on the
row, and list-available-models.

```
backend/app/services/llm_registry.py
```

## Test files

## Interface intent

Plain functions taking a Core `Connection` first, returning frozen dataclasses or raising
a typed error. The module **never imports `fastapi`**, never sees a `Request` and never
names a status code. `Settings`, the snowflake generator and the acting administrator's id
arrive as **plain arguments**, never as module globals and never as a `CurrentUser` the
service unpacks.

**A frozen server-row value** — everything the list and the single-server responses are
built from: the id, the name, the kind, the base URL, a **boolean "has a pointer"** (never
the pointer itself), the enabled model names for that server, the designated model name
and its dimension when the designation lives on this server, the three last-test values,
and the two timestamps. The pointer text is not a field on this value at all, so no route
can leak it by accident.

**A registration-listing operation** — every registered server, each with its enabled model
names and its designation, read in one pass. No parameters beyond the connection: no
filter, no page, no sort (`ui-conventions.md`). Ordering is stable and by id, which is
chronological (`data-model.md`'s Identifiers).

**A single-registration read** — the same value for one id, raising `llm_server_not_found`
when there is no such row. Used by every id-addressed operation below rather than each one
re-reading.

**A create-registration operation** — takes the name, the kind, the base URL and an
optional pointer, mints an id from the generator it was handed, stamps both `*_at`
columns, and returns the new server row value. One `with conn.begin():` block. The pointer
is stored exactly as received; an empty string is stored as **no pointer**, not as an
empty string, so the "has a pointer" boolean is honest.

**An update-registration operation** — takes the id plus **only the fields the caller
actually supplied**, expressed so that "not supplied" and "supplied as empty" are
different things (`context.md` D9). Fields not supplied are not written. A supplied empty
pointer clears the stored pointer; a supplied non-empty pointer replaces it; an unsupplied
pointer leaves it exactly as it was. Bumps `updated_at`, raises `llm_server_not_found` for
an unknown id, and returns the updated row value. One transaction.

**A delete-registration operation** — removes the server's `models` rows and then the
server row, **in one transaction** (`context.md` D10), raising `llm_server_not_found` for
an unknown id. The child delete is explicit rather than left to the cascade so the
behaviour does not depend on a connection pragma. It returns nothing. It refuses nothing:
there is no dependency check of any kind, and there is no query anywhere near it that
could count what uses this server (R5).

**The probe primitive** — the one function that talks to a server. Given the connection,
the server id and `Settings`, it reads the row, resolves the stored pointer through the
existing `resolve_secret` (so a missing environment variable raises `secret_ref_missing`
**before** any network object exists), builds a client through an injectable **client
factory** whose default is the real one, and returns step `002`'s typed outcome. It
**writes nothing** and raises only `llm_server_not_found` and `secret_ref_missing`. It is
`async`.

**A test-connection operation** — calls the probe primitive, then in its own transaction
writes `last_test_at`, `last_test_ok` (true only for `reachable`) and `last_test_error`
(the **outcome value itself**, and `NULL` when reachable), and returns the outcome
alongside the refreshed row value. A failing outcome **never blocks or removes the
registration** (UC-011). `secret_ref_missing` propagates and records nothing
(`context.md` D14). It is `async`.

**A list-available-models operation** — calls the same primitive and returns the model
names for a `reachable` outcome and an empty list for `model_list_empty`; for `unreachable`
and `auth_failed` it raises `llm_unreachable` with `detail` carrying the typed outcome
value and nothing else. It **records nothing on the row** — recording is the test route's
job, and a modal opening must not overwrite the administrator's last deliberate test
result. It is `async`.

## Definition of done

1. `[test]` Creating a registration with a name, a kind, a base URL and a pointer stores
   the row with an id minted from the generator passed in, both timestamps set, and
   returns it. (US-012.AC-1)
2. `[test]` A created registration appears in the listing operation's result.
   (US-012.AC-2)
3. `[test]` **No returned value carries the pointer text** — the server-row value exposes a
   boolean only, and the pointer is absent from the value's fields entirely. A registration
   created with no pointer, and one created with an empty-string pointer, both report the
   boolean false; one created with `$NAME` reports true. (UC-010;
   `backend-structure.md`'s secret-pointer pattern)
4. `[test]` The listing carries, per server, its **enabled model names** and the designated
   model name with its dimension when the designation is on that server — and nothing
   about any user, session, character or memo, and no count of any of them. (UC-012,
   UC-013, UC-066, R5)
5. `[test]` The listing takes no filter, page or sort parameter and returns every
   registration in a stable id order. (`ui-conventions.md`, "No sorting, filtering or
   pagination" — **no product id**)
6. `[test]` Updating with only a name supplied changes the name and leaves the kind, the
   base URL and the pointer exactly as they were; `updated_at` moves and `created_at` does
   not. (UC-010)
7. `[test]` **D9's three states.** An update that does not supply the pointer leaves the
   stored pointer unchanged; one that supplies an empty pointer clears it so the boolean
   turns false; one that supplies a new pointer replaces it. The three are distinguishable
   at the service's own boundary, not only at the route's. (`context.md` D9;
   `admin-surfaces.md`'s API-key round-trip rule — **no product id**)
8. `[test]` Every id-addressed operation raises `llm_server_not_found` for an id no row
   has, and writes nothing. (UC-010 — **no product id for the code itself**)
9. `[test]` Deleting a registration removes it and **all of its `models` rows**, in one
   transaction, leaving every other server's rows untouched — and removes nothing when the
   id is unknown. (`context.md` D10)
10. `[test]` Deleting a registration **consults nothing about sessions or users**: the
    operation issues no query against any table but `llm_servers` and `models`, and there is
    no parameter, return value or error by which a dependency could be reported. (R5,
    UC-012, UC-066)
11. `[test]` The probe primitive resolves the pointer through `resolve_secret` and raises
    `secret_ref_missing` **before constructing any client** when the variable is absent —
    observable as the injected factory never being called. (`backend-structure.md`'s
    secret-pointer pattern; `llm-and-streaming.md`)
12. `[test]` The probe primitive passes the configured timeout from `Settings` down to the
    client it builds, and takes `Settings` as a plain argument rather than calling
    `get_settings` itself. (`context.md` D13; `backend-structure.md`'s routers-versus-services
    split — **no product id**)
13. `[test]` Test-connection against a `reachable` outcome answers reachable and records
    `last_test_at`, `last_test_ok` true and `last_test_error` `NULL`. (US-013.AC-1)
14. `[test]` Test-connection against each failing outcome records `last_test_ok` false and
    `last_test_error` set to **the typed outcome value**, never a provider message or free
    prose — **and the registration still exists and is unchanged in every other respect
    afterwards**. (US-013.AC-2; UC-011's postcondition)
15. `[test]` `model_list_empty` records `ok = false`, per `context.md` D6's mapping.
    (`admin-surfaces.md`'s result taxonomy — **no product id**)
16. `[test]` Test-connection lets `secret_ref_missing` propagate and records **nothing** on
    the row — no timestamp, no flag, no error value. (`context.md` D14 — **no product id**)
17. `[test]` List-available-models returns the names for `reachable`, an empty list for
    `model_list_empty`, and raises `llm_unreachable` for `unreachable` and `auth_failed`
    with the typed outcome in `detail`. (UC-012; `context.md` D6, D7)
18. `[test]` List-available-models **writes nothing** — a server whose last test succeeded
    still reports that last test after a failing model listing. (`backend-structure.md`,
    "one primitive, two routes" — **no product id**)
19. `[test]` Both routes' behaviour comes from **one** probe implementation: a single
    injected factory serves test-connection and list-available-models, and there is no
    second code path that issues a request to a server. (`backend-structure.md`, "The
    connection probe — one primitive, two routes" — **no product id**)
20. `[test]` Nothing in the module branches on `kind`. (`context.md` D5;
    `llm-and-streaming.md` — **no product id**)
21. `[test]` The module imports no `fastapi` symbol and names no HTTP status code; every
    transaction is an explicit `with conn.begin():` in this module, and the connection it
    receives arrives with none open. (`backend-structure.md`, Database access — **no
    product id**)
22. `[manual/live]` `mypy app`, `ruff check .` and `pytest` all pass from `backend/`.
