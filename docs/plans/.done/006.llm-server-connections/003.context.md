# Step 003 — step-specific context

Feature-wide facts are in `context.md` (D5 for one primitive and no `kind` branch, D6 for
the outcome mapping, D9 for the three pointer states, D10 for `models` rows, D13 for the
timeout, D14 for `secret_ref_missing` from the test path, D17 for the route surface these
operations back). Only what is narrow to this step is below.

## The authority for the two-route split

`docs/architecture/backend-structure.md`, "The connection probe — one primitive, two
routes" (~lines 681–710). It is explicit that the primitive lives in
`services/llm_registry.py`, that it resolves the pointer, issues the request and returns a
typed outcome or raises a typed error, and that **the second route is a deliberate
deviation from the sibling project** — FEAT-004 treats testing a connection as its own
capability and overloading the model listing conflates "can I reach and authenticate" with
"what can it run". Reusing the *primitive* while splitting the *route* is the whole point;
DoD-19 is what keeps it honest.

## Borrowed interfaces, by module path and role

- **`backend/app/db/engine.py`** (`001`) — the connection dependency opens **no**
  transaction. Every atomic operation here opens its own `with conn.begin():`.
- **`backend/app/ids.py`** (`001`) — the generator reaches create as a **plain argument**
  handed down by the route from application state.
- **`backend/app/secrets.py`** (`001`) — `resolve_secret` used **unchanged**: `'$NAME'` to
  the environment variable, `None` to `None`, anything else to `secret_ref_missing`.
  Resolution is at call time, never at registration and never at startup, so rotating a key
  is an environment change plus a restart.
- **`backend/app/services/users.py`** (`005/002`) — the precedent for the shape of every
  function here: a Core `Connection` first, plain arguments, a frozen dataclass out or a
  `DomainError` subclass raised.
- **step `002`'s client** — constructed through the injectable factory, never imported and
  instantiated directly inside an operation, so the test-coder has a seam that needs no
  network.

## The client-factory seam

Every operation that reaches the network takes an **optional client-factory argument whose
default is the real one**. This mirrors "the hashing seam in `services/passwords.py`"
(`003/001`) and exists for the same reason: the pipeline's test-coder writes from the spec
alone and cannot stand up a provider. The factory receives what the client needs — the
base URL, the resolved credential and the timeout — and returns something with step `002`'s
probe and embed operations on it.

Step `004` reuses the same seam for the designation's embedding call, so it is declared
here in a form both steps can share.

## `last_test_error` holds a typed value, not a message

The column is named "error" but `context.md` D6 fixes its contents as **the outcome value
itself** — `unreachable`, `auth_failed` or `model_list_empty` — and `NULL` when reachable.
`admin-surfaces.md` requires "a typed value, never a free-text message the UI has to
parse", and a column that sometimes holds prose is exactly how a UI ends up parsing it. The
frontend maps the value to a badge label.

## The three states, at the service's own boundary

DoD-7 asks for the omitted / empty / present distinction to be observable **in the service
signature**, not only in the route's pydantic model. That is deliberate: if the service
takes a nullable pointer and treats `None` as "unchanged", then the route's "clear it"
state has nowhere to go and the bug is one layer down where no route test will find it.
The mechanism is the skeleton agent's to freeze — a sentinel, a supplied-fields set, or a
three-valued wrapper are all acceptable — but "supplied as empty" and "not supplied" must
be different inputs.

## What this step deliberately does not build

- **No enable/disable of models, no designation, no use-time validator** — all step `004`,
  in this same module.
- **No `chat_stream`, no streaming, no compose** — `019`/`021`.
- **No dependency check, no usage count, no "is this server in use" query** — R5, and
  DoD-10 asserts the absence rather than trusting it.

## Gotchas

- **The listing's per-server enabled names and designation are a read of `models`**, which
  this step does not otherwise touch. Reading it is correct; writing it here is not.
- **An empty-string pointer on create is stored as `NULL`**, not as `""`. Otherwise the
  "has a pointer" boolean says true for a server with nothing to resolve, and the
  administrator learns only at call time.
- **`resolve_secret` raises for a value that is neither `None` nor `$`-prefixed.** Step
  `001`'s write-time validation makes that state unreachable through the API, but a row
  written before `006` shipped, or by hand, can still hit it — let it raise; do not
  defensively swallow it into an outcome.
- **List-available-models must not record a test result** (DoD-18). It is tempting because
  the information is right there; it would silently overwrite the administrator's last
  deliberate test with a side effect of opening a modal.
- **The two service test modules split by step, not by concern**:
  `test_llm_registry_servers.py` here, `test_llm_registry_models.py` in step `004`. The
  one-file-per-module convention bends here because two steps write one module; neither
  file may contain the other step's clauses.
