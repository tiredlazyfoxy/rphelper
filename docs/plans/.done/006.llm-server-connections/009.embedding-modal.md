# Step 009 — The embedding designation modal and the confirmed Clear Embedding action

## Goal

Add the single-select sibling of step `008`'s modal — designating the one embedding model,
which the backend blocks unless a real embeddings call succeeds — and the conditional
Clear Embedding action behind the shared confirm.

## Source files

```
frontend/src/admin/embeddingDraft.ts
frontend/src/admin/EmbeddingModal.tsx
frontend/src/admin/LlmServersPage.tsx
```

## Test files

```
frontend/tests/admin/embeddingModal.test.tsx
```

## Interface intent

**`frontend/src/admin/embeddingDraft.ts`** — the single-select half. Step `008`'s picker is
reused unchanged for the probe, the union and the failed-probe behaviour; nothing about it
is re-declared here.

- **A draft class** holding observable fields only: the selected model name or none, the
  currently designated name for that server (from the page's list payload, so it survives a
  failed probe), a server-errors map with a general key, and an idle/submitting/done
  status. `makeAutoObservable(this, {}, { autoBind: true })`; no methods, no computed
  getters.
- **Pure derivations** taking the draft: a can-submit predicate that requires a selection
  and no submission in flight.
- **A submit free function** taking the draft, the server id, a re-load callback and an
  optional `AbortSignal`. It `POST`s the chosen model name to the designation route, maps a
  failure onto the general key **by status or code** — the `llm_unreachable` 502 that a
  chat-only model produces is the case that matters — and on success invokes the callback.
  It `runInAction`s its writes and early-returns on an aborted signal before writing.
- **A clear free function** taking the page state and a server id: `DELETE`s the
  designation route and **re-loads the list**. Its failure lands in the page-level error
  field, not in a draft, because it is invoked from the row menu rather than from a form.

**`frontend/src/admin/EmbeddingModal.tsx`** — an `observer` Mantine `Modal` taking the
picker, the draft and the callbacks as props. It renders a `Loader` while the probe is in
flight, an inline `Alert` when the probe failed with the option list still rendered from
the union, and a **single-select** control (a `Radio.Group` or an equivalent single-choice
list — **not** a checkbox list) over the union, with the currently designated model
preselected and any option the server no longer offers marked. Copy states that designating
**measures the model's embedding dimension with one real call** and that a model which
cannot embed will be refused. A general-key error renders above the list — this is where a
"this is not an embedding model" refusal appears. No confirm on save.

**`frontend/src/admin/LlmServersPage.tsx`** — two additions to the existing row menu: **Set
Embedding**, opening the modal for that row, and **Clear Embedding**, rendered **only on
the row that currently holds the designation** and routed through `shared/ConfirmModal`
(`context.md` D18). The confirm's consequence sentence says that with no designation every
semantic feature stops working until one is designated again, and **names no count of
anything**. Open flags and target rows are component-local `useState`; the modal body is
conditionally mounted; on success the modal closes and the page **re-loads** — no success
toast.

## Definition of done

1. `[test]` Opening the modal probes the server's models once and renders a **single-select**
   control over the `available ∪ already-enabled` union — choosing one option deselects any
   other, and there is no way to select two. (UC-013; `admin-surfaces.md`'s Embedding modal)
2. `[test]` The server's currently designated model is preselected on open, sourced from
   the page's list payload. (UC-013)
3. `[test]` Choosing a model and saving `POST`s that name to the designation route; after
   the page re-loads the row shows that model as designated together with its recorded
   dimension. (US-015.AC-1, UC-013)
4. `[test]` Designating on a second server moves the designation: the re-loaded list shows
   exactly **one** designation across every row. (UC-013; `data-model.md`'s `models`)
5. `[test]` A refusal from the designation route — the 502 a model that cannot embed
   produces — renders on the **general key** above the list, mapped by status or code and
   never by parsing prose, and **the previously designated model is still shown as
   designated** after the modal is closed and the page re-loaded. (`context.md` D2 — **no
   product id**)
6. `[test]` **Failed-probe resilience.** When the probe fails, the modal shows an error and
   the option list still renders the already-enabled models with the current designation
   preselected — it does not present an empty list. (`admin-surfaces.md`'s failed-probe
   rule; `context.md` D11 — **no product id**)
7. `[test]` **Clear Embedding is offered only on the row that holds the designation** and
   is absent from every other row's menu. (`admin-surfaces.md`'s "Clear Embedding
   (conditional)" — **no product id**)
8. `[test]` **Clear Embedding is confirmed**: choosing it opens the shared confirm and
   issues no request; cancelling issues none; confirming issues the `DELETE` and then
   **re-loads the list**, after which no row shows a designation. (`context.md` D18;
   `ui-conventions.md`'s confirm convention — **no product id**)
9. `[test]` The confirm's text names **no count and nothing derived from another user's
   data** — it describes the action and its consequence for the instance only. (R5,
   UC-012, UC-065, UC-066)
10. `[test]` Nothing in this step warns about, prompts for, or offers a rebuild when the
    designation changes — UC-013's postcondition is that changing it neither forces nor
    prompts one. (UC-013)
11. `[test]` Designating a model that is **not enabled** is possible and the modal neither
    blocks it nor enables the model as a side effect — designation is independent of
    `is_enabled`. (`context.md` D4 — the brief's first open question, **no product id**)
12. `[test]` A clear failure renders in the **page-level** `Alert` above the table, and no
    notification is raised for it. (`ui-conventions.md`, errors render in place — **no
    product id**)
13. `[test]` On success the modal closes and the list **re-loads**; **no success
    notification is raised** anywhere in this step. (`ui-conventions.md`, no success toasts
    — **no product id**)
14. `[test]` The draft class declares no method and no computed getter; both free functions
    `runInAction` their writes and early-return on an aborted signal; a fresh picker and a
    fresh draft are constructed per open. (`context.md` D16 — **no product id**)
15. `[test]` The row menu still holds **one** icon-only trigger routed through
    `shared/IconButton` in its trailing `w={60}` column, now with its full item set — Test
    connection, Edit, Select Models, Set Embedding, Clear Embedding (conditional) and
    Delete — and no second icon-only control appears in a row. (`ui-conventions.md`, tables
    and the icon boundary; `admin-surfaces.md`'s row menu — **no product id**)
16. `[test]` Every id handled here is a `string`, and no file added in this step imports a
    stylesheet. (`frontend-structure.md` — **no product id**)
17. `[manual/live]` Against a real embeddings-capable server, designating a model succeeds
    and the row shows a plausible dimension; designating a chat-only model is refused with
    the message rendered above the list and the previous designation intact; Clear
    Embedding removes it after the confirm.
18. `[manual/live]` `npm run typecheck`, `npm test` and `npm run build` all pass from
    `frontend/`.
