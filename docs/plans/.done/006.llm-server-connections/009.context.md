# Step 009 — step-specific context

Feature-wide facts are in `context.md` (D2 for the measured dimension and the refusal it
can produce, D4 for designation being independent of `is_enabled`, D11 for failed-probe
resilience, D16 for the MobX rules, D17 for the two routes, D18 for the confirm). Only what
is narrow to this step is below.

## The spec sentence this modal implements

`admin-surfaces.md`, Embedding modal (~lines 389–395): "The same probe-on-open shape, but
**single** select: at most one model is designated across the whole table
(`models.is_embedding_designated`). Plus a page-level **Clear embedding** action. Clearing
is not a no-op: with no designation, every semantic path fails as `no_embedding_model`
rather than substituting a model (R4), because vectors from a different model are not
comparable with the stored ones."

Two readings fixed here so they are not re-decided:

- **"At most one across the whole table" is enforced server-side** (step `004`'s DoD-9).
  The modal is per-server and does **not** try to clear another server's designation
  itself; DoD-4 verifies the server did it.
- **Clear Embedding is offered in the row menu, conditionally**, which is the shape the
  doc's own row-menu list gives ("Clear Embedding (conditional)"). No separate page-header
  duplicate of the same action is built — one affordance, on the row that owns the state,
  is enough and two would drift.

## Why this is the modal that can be refused

Step `008`'s save cannot fail on the provider's account: enabling a model writes flags and
touches no server. Designating **does** reach the provider (`context.md` D2) and returns
**502 `llm_unreachable`** when the chosen model cannot embed — which is the entire point of
measuring at pick time rather than at first search. DoD-5 is therefore the important item
in this step, and it has two halves: the message renders, **and** the previous designation
is untouched.

## Borrowed interfaces, by module path and role

- **`frontend/src/admin/modelPicker.ts`** (step `008`) — the picker class, the loader and
  the pure union function, used **unchanged**. Re-declaring any of the three here is a
  defect; see `008.context.md` for why the module exists.
- **`frontend/src/shared/ConfirmModal.tsx`** (`005/006`) — reused for Clear Embedding,
  exactly as step `006` reuses it for Delete. Cancel sits left of confirm; the component
  holds no state and makes no request.
- **`frontend/src/shared/api.ts`** (`002/004`) — `apiPost` for the designation,
  `apiDelete` for the clear (which answers **204**, so the helper returns `undefined`).
- **step `006`'s page store** — the clear free function writes into the page's error field
  and calls its re-load, because the action is invoked from the row menu, not from a form.

## Routes this step calls

`GET /api/admin/llm-servers/{id}/available-models` (shared with step `008`),
`POST /api/admin/llm-servers/{id}/embedding-model` and
`DELETE /api/admin/llm-servers/{id}/embedding-model` (`context.md` D17).

## What must not appear

- **No rebuild prompt, no "your existing vectors were produced by a different model"
  warning, no dimension comparison.** UC-013's postcondition is explicit that changing the
  designation neither forces nor prompts a rebuild and that **nothing indicates this**; the
  remedy is UC-016, which is feature `007`'s Database page. DoD-10 asserts the absence.
- **No count of anything** in the confirm or anywhere else (R5). The consequence sentence
  is about the instance's own capability, not about whose work depends on it.
- **No enabling as a side effect** of designating (DoD-11) — `context.md` D4.

## Gotchas

- **Single-select, not a checkbox list with a one-item rule.** A checkbox list that merely
  refuses a second tick is a different affordance and reads as a bug.
- **The preselection comes from the list payload**, so it survives a failed probe (DoD-6) —
  the same structural reason step `008` seeds its selection from the row rather than from
  the probe.
- **Clearing leaves `embedding_dim` on the row** (step `004`'s DoD-14). Nothing in the UI
  reads it for a non-designated model, so nothing renders it there.
- **The clear's failure goes to the page `Alert`, not to a draft**, because the action has
  no form; a general-key error with no form above it has nowhere to render.
- **The row menu is now complete.** DoD-15 checks the full item set in one place, which is
  the last chance to catch a second icon-only control having crept into a row across four
  frontend steps.
