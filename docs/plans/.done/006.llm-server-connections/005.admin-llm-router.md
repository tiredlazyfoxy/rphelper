# Step 005 — The admin LLM router and its pydantic models, behind one router-level `require_role(Role.admin)`

## Goal

Expose the registry as the nine routes `context.md` D17 fixes, owning HTTP and nothing
else, guarded once at the router so a route added later cannot forget it, and register it
in the app factory. The step sits at the top of the size budget because a route and its
request/response model are not independently verifiable; the models are deliberately terse.

## Interface intent

**`backend/app/models/admin_llm.py`** — the pydantic request and response models for this
router and nothing else. Models live in `app/models/` beside `ids.py`, `secret_ref.py`,
`health.py` and `005`'s admin-users models; there is no `schemas/` directory.

- **A server model** — the response shape the list, create, update and designate routes
  answer with: the **id** (using the outbound snowflake alias, so it serialises as a
  decimal string — a bare `int` is the defect), the name, the kind, the base URL, the
  **boolean** has-API-key, the enabled model names, the designated model name and its
  dimension (both nullable), the three last-test fields, and the two timestamps. It carries
  **no pointer text**, and **no count or field relating to a user, session, character,
  setup or memo** (R5, UC-066).
- **A list model** wrapping the servers under one field. A route returns a pydantic model,
  never a bare list and never a `JSONResponse`.
- **A create-request model** — name, kind, base URL and an optional API-key pointer. Name
  and base URL are constrained **non-empty** by field constraints; the kind is a
  **two-member literal** (`context.md` D5); the pointer uses step `001`'s annotated
  secret-ref alias. Every one of those refusals is FastAPI's own **422** and adds no domain
  error code.
- **An update-request model** — the same four fields, **all optional**, shaped so that the
  set of fields the caller actually supplied is recoverable (`context.md` D9). Absent
  means "leave unchanged"; an explicitly supplied empty pointer means "clear".
- **A connection-test result model** — the typed outcome (step `002`'s closed four-value
  set), the boolean ok, and the instant tested. No free-text field the UI could be tempted
  to parse (`admin-surfaces.md`).
- **An available-models model** — the model names the probe returned, under one field.
- **An enabled-models request model** — the **complete** set of names to enable, as a list
  of strings, with the empty list a legal value meaning "none".
- **An embedding-designation request model** — one non-empty model name.

**`backend/app/routers/admin_llm.py`** — the router, owning HTTP and nothing else: no
business rule, no SQL, no secret resolution, no transaction.

- It declares its own prefix `/api/admin/llm-servers` and a tag, following
  `routers/health.py`'s and `005`'s `routers/admin_users.py`'s precedent, and carries
  **`require_role(Role.admin)` as a router-level dependency** — on the router, never per
  handler.
- The nine routes of `context.md` D17's table, at those paths, with those status codes.
  Every handler takes the connection dependency; create additionally takes the snowflake
  generator resolved from **application state**, never a module global; the three outbound
  routes additionally take `Settings` from the existing settings dependency and pass it
  down as a plain argument. Those three — test, available-models and designate — are
  `async def` (`context.md` D3); the rest are not.
- Each handler calls **exactly one** registry operation and maps its plain result onto a
  model. **No handler translates a domain error by hand** — the base-class handler `001`
  registered renders `llm_server_not_found` as 404, `llm_unreachable` as 502,
  `secret_ref_missing` as 500 and the two 409s on its own.
- The `{server_id}` path parameter is declared with `001`'s **inbound** snowflake alias
  (`005`'s D9): it arrives as a decimal string and reaches the service as an `int`, with no
  `int()` call in the handler and no bare `int` path type.
- **No query parameter exists anywhere on this router** — no filter, no page, no sort. **No
  route is keyed on anything but a server id**, and there is no route returning a session,
  a user, or a count of either (R5).

**`backend/app/main.py`** — include the router with one appended `app.include_router(...)`
line, beside health, bootstrap, auth and admin-users. Nothing else changes: the factory's
ordering stands and the **lifespan still runs no DDL**.

## Definition of done

1. `[test]` `GET /api/admin/llm-servers` with a live administrator session answers 200 with
   every registration, each carrying its id as a **decimal string** (never a JSON number),
   name, kind, base URL, the has-API-key boolean, its enabled model names, its designation
   and dimension where it holds one, and its three last-test fields. (US-012.AC-2, UC-010)
2. `[test]` **No response on this router carries the API-key pointer text**, in any field,
   on any route, for any of create, update, list, test or designate. (UC-010;
   `admin-surfaces.md`'s API-key round-trip rule)
3. `[test]` No response on this router carries a field or count relating to a user,
   session, character, setup or memo, and the router declares **no route** that could
   return one and **no query parameter** at all. (UC-012, UC-066, R5)
4. `[test]` **Every** route on this router answers **403** with the `insufficient_role`
   envelope for a live roleplayer session and **401** with the `not_authenticated` envelope
   when there is no session — in that order of precedence. (`admin-surfaces.md`, "Backend
   gating is independent and authoritative" — **no product id**)
5. `[test]` The guard is **router-level**: a route registered on this router that declares
   no dependency of its own is still refused for a roleplayer. (`backend-structure.md`,
   "Authorization as router dependencies"; the pattern `005/003` DoD-4 set — **no product
   id**)
6. `[test]` `POST /api/admin/llm-servers` answers **201** with the created registration,
   which then appears in a subsequent `GET`. (US-012.AC-1, US-012.AC-2)
7. `[test]` A kind outside the two-member literal, an empty name, an empty base URL, and a
   pointer that neither is empty nor starts with `$` are each refused with FastAPI's **422**
   before anything is written, and none of those responses is the domain-error envelope.
   (`context.md` D5, D8 — **no product id**)
8. `[test]` **D9's three states, over HTTP.** A `PATCH` body that **omits** the pointer key
   leaves the stored pointer in place (has-API-key stays true); one that sends it as an
   **empty string** clears it (has-API-key turns false); one that sends a new pointer
   replaces it. A `PATCH` that supplies only the name changes only the name.
   (`admin-surfaces.md`'s API-key round-trip rule; `context.md` D9 — **no product id**)
9. `[test]` `DELETE /api/admin/llm-servers/{id}` answers **204**, after which the
   registration is absent from the list and its models are gone with it. (`context.md` D10;
   `ui-conventions.md`'s per-entity delete choice)
10. `[test]` `POST /api/admin/llm-servers/{id}/test` answers **200** with the typed outcome
    and the ok flag for a reachable server, and the registration is unchanged apart from
    its three last-test fields. (US-013.AC-1)
11. `[test]` The same route answers **200** — not an error status — for each failing
    outcome, reporting it, and **the registration still exists afterwards and can be listed
    and re-tested**. (US-013.AC-2, UC-011's postcondition)
12. `[test]` The test route's result is a **typed value from the closed four-value set**,
    with no free-text field for the UI to parse. (`admin-surfaces.md`'s result taxonomy;
    `context.md` D6 — **no product id**)
13. `[test]` A pointer naming an absent environment variable makes the test route answer
    **500** with `{"error": {"code": "secret_ref_missing", …}}` carrying the variable name,
    and records nothing on the row. (`context.md` D14;
    `backend-structure.md`'s secret-pointer pattern — **no product id**)
14. `[test]` `GET /api/admin/llm-servers/{id}/available-models` answers 200 with the names
    for a reachable server and an empty list for an empty listing, and **502** with
    `{"error": {"code": "llm_unreachable", …}}` for an unreachable or auth-failed one —
    and in every case leaves the row's last-test fields untouched. (UC-012;
    `context.md` D6, D7)
15. `[test]` `POST /api/admin/llm-servers/{id}/models` with the full set answers 200 with
    the enabled names as stored; submitting a set that omits a previously enabled model
    reports it gone from the enabled names while the registration and its rows survive.
    (US-014.AC-1, US-014.AC-2)
16. `[test]` That route **never refuses** a disable and offers no mechanism to report a
    dependency: no status, no error code and no response field by which "N sessions use
    this" could be expressed. (US-016.AC-1, UC-012, R5)
17. `[test]` `POST /api/admin/llm-servers/{id}/embedding-model` answers 200 with the
    designation and its measured dimension visible on the subsequent list, and designating
    on a second server moves it — the list then shows exactly one designation across every
    server. (US-015.AC-1, UC-013)
18. `[test]` A designation whose embeddings call fails answers **502** with
    `llm_unreachable` and leaves any previous designation exactly as it was.
    (`context.md` D2, D7 — **no product id**)
19. `[test]` `DELETE /api/admin/llm-servers/{id}/embedding-model` answers **204** and the
    subsequent list shows no designation anywhere. (UC-013;
    `admin-surfaces.md`'s Clear-embedding action)
20. `[test]` Every id-addressed route answers **404** with
    `{"error": {"code": "llm_server_not_found", …}}` for an id no registration has.
    (`context.md` D7 — **no product id**)
21. `[test]` A `{server_id}` sent as a decimal string beyond `Number.MAX_SAFE_INTEGER`
    round-trips correctly — it addresses that registration and comes back as the same
    string. (`backend-structure.md`'s JSON id boundary; `005`'s D9 — **no product id**)
22. `[test]` The router issues no SQL and holds no rule: its only database contact is
    through the connection dependency, every stored value comes from a registry operation,
    the generator comes from application state, and `Settings` reaches the service as a
    plain argument. (`backend-structure.md`, routers versus services — **no product id**)
23. `[manual/live]` The router declares exactly the nine routes at the paths
    `context.md` D17 fixes, carries `require_role(Role.admin)` **once, on the router**, and
    no handler declares an authorization dependency of its own. Verifier confirms by
    reading the module.
24. `[manual/live]` `main.py`'s lifespan still runs no DDL and the router registration is
    the only change to the factory. Verifier confirms by reading it.
25. `[manual/live]` `uvicorn app.main:app` on port 8184 starts; against a bootstrapped
    database an administrator's cookie can register, test, list models, enable a set,
    designate, clear and delete through `curl`, and a roleplayer's cookie is refused on all
    nine routes.
26. `[manual/live]` `mypy app`, `ruff check .` and `pytest` all pass from `backend/`.
