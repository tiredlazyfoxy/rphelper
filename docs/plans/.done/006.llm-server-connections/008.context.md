# Step 008 — step-specific context

Feature-wide facts are in `context.md` (D10 for rows persisting, **D11 for failed-probe
resilience**, D16 for the MobX rules, D17 for why the enabled set rides on the list
payload, D18 for what is confirmed, plus R5 and the never-optimistic rule). Only what is
narrow to this step is below.

## The two rules from `admin-surfaces.md` this step implements literally

From "LLM Servers page — FEAT-004" (~lines 378–388):

- **The union.** The modal renders a checkbox list over **`available ∪ already-enabled`**.
  "The union matters: a model that was enabled but is no longer offered by the server must
  still be visible and still be un-checkable, otherwise the administrator cannot see, let
  alone clear, a stale enablement."
- **Failed-probe resilience.** "A probe failure surfaces an error and **clears the
  available list**, but **must not disturb the existing selection**. Stated as a
  requirement because the naive implementation — set `available = []` and derive the
  checkboxes from it — silently presents 'nothing enabled' and saves that."

The architecture of this step is chosen to make the second one *structural* rather than
careful: **the already-enabled names come from the page's list payload**, which involves no
outbound call and therefore cannot fail with the probe, and the probe's loader writes only
the `available` field. There is no code path in which a probe failure can reach the
selection. DoD-8 still asserts it, because the structure can be undone by someone deriving
the draft from the picker later.

## Why the picker is its own module

Step `009` builds the embedding modal, which has "the same probe-on-open shape, but
**single** select" (`admin-surfaces.md`). Sharing the picker means one loader, one union
function and one failed-probe behaviour for both modals rather than two that must be kept
identical. The **differing** half — a set versus one name, and what a save posts — stays in
each modal's own `*Draft.ts`, per the draft convention.

The picker is not a draft: it holds no user input and submits nothing. It is a small
observable data object with one loader, and it follows the same no-methods rule.

## Borrowed interfaces, by module path and role

- **`frontend/src/shared/api.ts`** (`002/004`) — `apiGet` for the probe route, `apiPost`
  for the save.
- **`frontend/src/shared/apiError.ts`** (`002/004`) — the probe's failure arrives as an
  `ApiError` with code `llm_unreachable` (502) for an unreachable or auth-failed server,
  or as the transport-failure code. Render `.message`; branch on `.code` only if a step
  needs to, and this one does not.
- **step `006`'s page store and row type** — the row's enabled names seed the draft; the
  page's re-load effect is the submit's success callback.
- **`frontend/src/admin/createUserDraft.ts`** (`005/007`) — the draft shape precedent.

## Routes this step calls

`GET /api/admin/llm-servers/{id}/available-models` (may answer **502** `llm_unreachable`)
and `POST /api/admin/llm-servers/{id}/models` with the complete set
(`context.md` D17). There is deliberately **no** route that returns the enabled names on
their own — see `context.md` D17's third note.

## R5, in the place it is most tempting

This modal disables models. The sentence the architecture names as forbidden — "Are you
sure? N sessions use this model" and every variant — would be written **here**, in good
faith, as a warning before saving. `domain-rules.md` R5 forbids it, there is no endpoint to
power it, and none may be added. **Saving is not confirmed at all** (`context.md` D18): the
action is fully reversible and the only sentence that would make a confirm informative is
the forbidden one. DoD-10 asserts the absence of the whole shape, not just of the string.

## Gotchas

- **The order of the union must be stable**, or checkboxes reshuffle under the pointer
  between a probe and a re-probe. Sort it in the pure function; do not rely on the
  provider's order for the enabled half.
- **"No longer offered" is a mark on an option, not a separate section.** A second list
  would make the union invisible again.
- **An empty save is legal** (DoD-7) and must not be confused with the failed-probe case
  (DoD-8). The difference is the *selection*, not the availability.
- **The draft's baseline is the row's enabled names as loaded**, so "has anything changed"
  is comparable and a save after no change still sends the full set (DoD-6) rather than
  nothing.
- **Fresh picker and fresh draft per open**, inside a conditionally mounted modal body —
  reopening must re-probe, because a model list is exactly the thing that changes between
  two opens.
