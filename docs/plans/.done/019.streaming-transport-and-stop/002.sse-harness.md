# Step 002 — The SSE harness and the own-connection persister

## Goal

Add the harness to `services/llm/frames.py`. It drains an async source of frames into an
SSE `StreamingResponse` carrying `X-Accel-Buffering: no`, and it guarantees two things:

- every stream the server ends ends with exactly one `error` or `done`;
- whenever no `done` was sent, including on a client disconnect, the streamed assistant
  text is persisted as an ordinary current-zone row and the source is closed.

All of this is done on a connection the harness owns (D3–D7).

## Interface intent

All in `app/services/llm/frames.py`, beside `001`'s frame types.

- **`frame_stream`**: an async generator of wire strings. Inputs:
  - **request**: only its async `is_disconnected()` is used;
  - **source**: an async iterator of frame values;
  - **`on_partial`**: a synchronous callable taking the partial text.

  Behaviour:
  - For each frame the source yields, it first checks `is_disconnected()`. If the client
    is gone, it stops.
  - Otherwise it encodes the frame (`001`'s encoder) and yields it. A `token` frame's text
    is appended to the partial text.
  - After a terminal frame it yields nothing more.
  - End-of-stream behaviour is exactly the D4 table, with D5 for a non-domain exception
    and for exhaustion without a terminal frame.
  - Cleanup runs in a `finally` per D6: a synchronous persist when no `done` passed and
    the partial text is not blank; a shielded `aclose()` of the source with its
    exceptions suppressed; `CancelledError` and `GeneratorExit` re-raised.
- **`sse_response`**: same inputs. Returns a `StreamingResponse` over `frame_stream`
  with media type `text/event-stream` and the header `X-Accel-Buffering: no`.
- **`own_connection_persister`**: inputs are an `Engine`, the id generator, the user id
  and the session id. Returns the synchronous `on_partial` callable. When called, it
  opens one connection from the engine, runs `001`'s `append_assistant_message`, and
  closes the connection. Any exception is logged (session id and exception class only,
  never text) and swallowed (D7).

## Definition of done

1. `[test]` Through a throwaway FastAPI route that returns `sse_response(...)` over a
   source yielding accepted `7250000000000000001`, token `"Hel"`, token `"lo"`, then
   done `7250000000000000002` (with a recording `on_partial`):
   - a `TestClient` POST answers 200;
   - the `content-type` starts with `text/event-stream`;
   - the header `x-accel-buffering` is exactly `no`;
   - the body is exactly the four frames' wire texts concatenated (bytes per `001`'s
     examples). (D3, `deployment.md`)
2. `[test]` On the success path above, `on_partial` is **never** called. (D4)
3. `[test]` A source that yields token `"Partial "`, token `"answer"`, then raises
   `LlmUnreachableError("down")`, produces the two token frames followed by exactly one
   `error` frame with code `llm_unreachable` and message `"down"`, and nothing after it.
   `on_partial` is called once with `"Partial answer"`, **before** the error frame is
   yielded. (D4, `llm-and-streaming.md` termination table)
4. `[test]` A source that raises a plain `RuntimeError("secret provider text")` after
   one token produces a final `error` frame with code `llm_unreachable`, message exactly
   "The reply could not be completed." and detail `{}`. The text "secret provider text"
   appears in no frame. `on_partial` gets the token's text. (D5)
5. `[test]` A source that yields two tokens and then simply ends produces a final `error`
   frame with code `llm_unreachable`, message exactly "The reply ended before it was
   complete.", detail `{}`, and calls `on_partial` with the joined token text. (D5)
6. `[test]` A source that yields its own error frame (code `model_not_enabled`) after one
   token produces that frame verbatim as the last frame, never pulls another item from
   the source, and calls `on_partial` with the token text. A source that yields `done`
   followed by a further token produces nothing after `done`. (D4)
7. `[test]` **Disconnect by poll.** Drive `frame_stream` directly under `asyncio.run`
   with a fake request whose `is_disconnected()` turns true after two tokens have been
   yielded. The stream yields no further frame and **no terminal frame**. `on_partial` is
   called once with the two tokens' text. The source's `aclose()` ran, observed through
   the fake source generator's `finally`. (D6, US-132.AC-1, US-132.AC-2)
8. `[test]` **Disconnect by close.** Drive `frame_stream` for two tokens, then `aclose()`
   the stream itself, as a server closing the body iterator does. `on_partial` is called
   once with the two tokens' text, and the source's `finally` ran. (D6, US-132.AC-1,
   US-132.AC-2)
9. `[test]` **Disconnect by cancellation.** Run the consumption of `frame_stream` as an
   asyncio task. The source blocks forever after one token, standing in for a model still
   generating. Cancel the task. `on_partial` is called once with that token's text, the
   source's `finally` ran, and the task ends cancelled: the `CancelledError` is not
   swallowed. (D6, US-132.AC-1, US-132.AC-2)
10. `[test]` On a disconnect (any of 7–9) with no token, or with tokens whose joined text
    is whitespace only, `on_partial` is **not** called. (D4, `llm-and-streaming.md`
    consequence 4)
11. `[test]` `own_connection_persister(db_engine, generator, user_id, session_id)` called
    with `"kept text"` leaves one current-zone row with role `"assistant"`, kind NULL and
    text `"kept text"` for that session, with no connection supplied by the caller.
    Called for a session that does not exist, it returns normally and writes nothing.
    (D7, US-132.AC-1)
12. `[test]` End to end: a disconnect-by-poll stream (as in 7) wired to
    `own_connection_persister` for a real seeded session leaves exactly one new
    current-zone row with role `"assistant"` holding the streamed text. (D4, D7,
    US-132.AC-1)
13. `[manual/live]` With 021's route mounted, behind nginx: pressing Stop mid-reply
    leaves the partial text in the zone after a reload, and the provider-side request is
    seen to end (llama-swap / provider log shows the connection closed). (US-132.AC-1,
    US-132.AC-2)
