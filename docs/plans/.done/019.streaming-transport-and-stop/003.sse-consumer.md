# Step 003 — The SSE consumer and the shared failure decode

## Goal

Add `shared/sse.ts`, the browser's only SSE consumer. It is a `fetch()` POST read through
`body.getReader()` and a streaming `TextDecoder`, splits frames on the blank line, keeps
every id a string, and reports exactly one of the four terminations (D9). It reuses the
non-2xx and transport-failure decoding that `shared/api.ts` now exports (D10), so a
failed request is decoded once in one place.

## Interface intent

**`src/shared/api.ts`** (changed)

- **A non-2xx decode helper**, exported. Input: a non-2xx `Response`. Output: a promise of
  the `ApiError` that `apiRequest` would throw for it. When the status is 401 it first
  calls `documentNavigation.assign("/login")`. A well-formed envelope gives its own code,
  message, detail and the real status; anything else gives the `client_malformed_error`
  fallback with the real status.
- **A rejection-mapping helper**, exported. Input: whatever `fetch` (or a body read)
  rejected with, plus the signal. Output: the original value unchanged when it is an abort
  (signal aborted); otherwise
  `ApiError(client_transport_failed, "The server could not be reached.", 0)`.
- **`apiRequest`** uses both helpers. Its observable behaviour is unchanged.

**`src/shared/sse.ts`** (new)

- **Frame types.** A discriminated union on `event` for the seven frames, every id field
  typed `string`:
  - `accepted {message_id}`, `token {text}`;
  - `tool_start {tool, call_id, args}`, `tool_result {tool, call_id, summary}`,
    `tool_fail {tool, call_id, code}`;
  - `error {code, message, detail}`, `done {message_id}`.
- **The outcome type.** A discriminated union of four:
  - **done**, with `messageId` (string);
  - **error**, with an `ApiError`;
  - **stopped**;
  - **unexpected end**.
- **The consumer function.** Inputs: an `/api/...` path, a JSON-serialisable body, a frame
  callback for non-terminal frames, and an `AbortSignal`. It POSTs with JSON
  content-type, `credentials: "same-origin"` and the signal, then reads and splits frames
  per D9. It resolves to exactly one outcome and **never rejects**:
  - **Non-2xx** gives error, through the `api.ts` decode helper (401 navigation
    included).
  - **A fetch or read rejection** gives stopped if `signal.aborted` at that moment;
    otherwise error via the rejection mapper.
  - **An `error` frame** gives error, with an `ApiError` of the frame's code, message
    (`""` if not a string), detail (`{}` if absent) and the response's HTTP status.
  - **A `done` frame** gives done.
  - **The body ending without either** gives stopped if `signal.aborted`, otherwise
    unexpected end.
  - **A malformed frame** (bad JSON, or no string `event`) gives an error with
    `client_malformed_error`.
  - **An unknown `event`** is skipped.

  After a terminal frame or a malformed frame it cancels the reader and resolves at once.

## Definition of done

1. `[test]` The consumer POSTs to exactly the given path with method `POST`, header
   `Content-Type: application/json`, body `JSON.stringify` of the given object,
   `credentials: "same-origin"`, and the given signal. (D9)
2. `[test]` A body of accepted (`message_id` `"7250416938275332095"`), token `"Hel"`,
   token `"lo"`, done (`"7250416938275332096"`) delivers to the callback, in order:
   accepted with `message_id` **the string** `"7250416938275332095"` (`typeof` is
   `"string"`, value unchanged), token `"Hel"`, token `"lo"`. It resolves to done with
   messageId `"7250416938275332096"`. The callback never receives the `done`. (D9, ids
   rule)
3. `[test]` The same frames split arbitrarily across chunks still give the same callback
   sequence and outcome. The cases:
   - a chunk boundary inside `data:`;
   - a boundary between the two `\n` of a terminator;
   - all frames in one chunk;
   - a boundary **inside a multi-byte UTF-8 character** of token text `"Привет 🙂"`.

   In the last case, the token arrives intact as `"Привет 🙂"`. (D9,
   `frontend-structure.md` load-bearing details)
4. `[test]` A body with token `"x"` then an `error` frame
   (`{"event":"error","code":"llm_unreachable","message":"down","detail":{"server_id":"7250000000000000007"}}`)
   resolves to error with an `ApiError` whose code is `"llm_unreachable"`, message
   `"down"`, detail `{server_id: "7250000000000000007"}` and status 200. It is not
   rejected. (D9)
5. `[test]` A body that ends after two tokens with no `done` or `error`, signal not
   aborted, resolves to **unexpected end**. Nothing is notified and nothing is thrown.
   (D9, `llm-and-streaming.md` termination table)
6. `[test]` **Stop.** While the body is open, after one token, the test aborts the
   signal. The consumer resolves to **stopped**, not error and not unexpected end, and it
   neither rejects nor wraps anything in an `ApiError`. The same holds when the abort
   lands before `fetch` resolves. (D9, UC-085)
7. `[test]` A 409 response with envelope
   `{"error":{"code":"model_not_enabled","message":"m","detail":{"level":"session"}}}`
   resolves to error with that code, message, detail and status 409. A 502 with an HTML
   body resolves to error with `client_malformed_error`, status 502. The frame callback
   is never called. (D10)
8. `[test]` A 401 response calls `documentNavigation.assign` once with exactly `"/login"`
   and resolves to error with the envelope's code. (D10)
9. `[test]` A `fetch` that rejects with a `TypeError` (signal not aborted) resolves to
   error with code `client_transport_failed` and status 0. (D10)
10. `[test]` A frame whose `data` is not JSON resolves to error with code
    `client_malformed_error`. A frame with event `"thinking"` (unknown) between two
    tokens is skipped: both tokens are delivered and a following `done` is the outcome.
    A comment line `: keepalive` is ignored. (D9)
11. `[test]` Bytes after a `done` frame (a further token) are never delivered to the
    callback. (D9)
12. `[test]` `apiRequest`'s behaviour is unchanged by the refactor. For a 401, a
    well-formed 409, a malformed 500, a transport rejection and an abort, `apiGet`
    rejects with, respectively: the envelope code after navigating to `/login`; the
    envelope code and status; `client_malformed_error`; `client_transport_failed` with
    status 0; and the raw abort rejection. (D10)
