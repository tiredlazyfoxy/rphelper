# Step 001 — step-specific context

Feature-wide facts are in `context.md`; the decisions this step implements are D1
(Argon2id via `argon2-cffi`, library defaults, one seam module), D7 (the enum, not the
ladder), D14 (the deleted emptiness sub-clause) and D15 (the whole table declared). None
of that is repeated here.

## The registry file's own rule, which this step is the first to exercise

`db/schema.py` ships from `001.backend-foundation/005` with **one `MetaData` and zero
`Table` objects**, and its module docstring states the rule this step binds to: *every
table in RPHelper is declared as a `Table(...)` literal in this same file; there are no
per-feature table modules, no import-side-effect registration and no builder callable*
(`001/005.db-engine-and-registry.md:31-40`). So the `users` table is a literal added to
that file — not a new module, not a registration call.

The exact name of the metadata object is `001`'s to freeze; the skeleton agent reads it
from the delivered file rather than assuming one.

## The column list is `data-model.md`'s, verbatim

`docs/architecture/data-model.md`, section `users`. Read it rather than trusting a
paraphrase: it is the authoritative list, and it also records two prohibitions this step
must hold — `role` is a single enum column and **never** an `is_admin` boolean, and the
three configuration-default columns that once appeared there (`default_model_ref`,
`default_system_prompt`, `default_tools`) are **removed and must not come back**.

`data-model.md`'s Identifiers section carries the storage rule for the key: `id INTEGER
PRIMARY KEY` in SQLite — the rowid alias, which holds a signed int64 natively — and the
big-integer type in SQLAlchemy Core, with **no `AUTOINCREMENT` anywhere** because the id
is minted before the INSERT.

## SQLite and enums — why the constraint is spelled out

SQLite has no native enum type. A Core `Enum` bound to the role enum with native types
disabled produces a text column plus a check constraint, which is what makes DoD-3
observable: a third value is refused by the database rather than merely discouraged by a
type annotation the database never sees. The precise construction is the skeleton's to
freeze; the requirement is that the refusal is real against a live database.

## Gotcha — the enum's values are what is stored

The column stores the strings `data-model.md` names. If the enum is declared such that
SQLAlchemy persists member *names* rather than member *values*, the stored text can
diverge from the documented column domain, and `services/bootstrap.py` (step `002`) plus
every later `role` comparison would be reading a different alphabet from the one the
architecture documents. Whatever construction the skeleton chooses, the bytes in the
column are the documented strings.

## `argon2-cffi`'s defaults are the parameters

The library exposes a hasher whose constructor defaults are the maintained baseline. Use
it with no argument overrides. The module must not restate those numbers as its own
constants "for documentation" — a copied default is a silent pin that goes stale, and
DoD-9 is written to catch exactly that.

The encoded string the hash operation returns carries the algorithm, the version and the
parameters inside it, which is why `password_hash` is a plain text column and why a
future parameter change is a rehash-on-verify concern rather than a schema change.
`003` builds no rehash-on-verify: it writes one hash and has no login path.

## Nothing else consumes these yet

`services/passwords.py`'s hash operation gets its first caller in step `002` and its
verification operation gets its first caller in **feature `004`'s login path** — that
symmetry is the point of the seam (`context.md` D1). This step therefore leaves both
operations exported and unused by application code, which is expected and is not dead
code to prune.

## The two edits to another feature's test file, kept narrow

`backend/tests/test_db_schema.py` is `001.backend-foundation/005`'s file. In this step the
test-coder deletes **only** the sub-clause asserting the registry's table collection is
empty, and adds the `users` assertions this step's DoD asks for. The enumerability
sub-clause stays — it is still true and it is still the shape `007` walks. No other
assertion in that file, and no other file of `001`'s, is touched here.
