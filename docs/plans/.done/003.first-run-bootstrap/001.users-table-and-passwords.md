# Step 001 — The `users` table, the role enum, and the password-hashing seam

## Goal

Declare the project's first table in the registry, give the `role` column its two-value
domain, and put password hashing behind one swappable module backed by `argon2-cffi`.

## Source files

```
backend/pyproject.toml
backend/app/roles.py
backend/app/db/schema.py
backend/app/services/passwords.py
```

## Test files

```
backend/tests/test_passwords.py
backend/tests/test_db_schema.py
```

`backend/tests/test_db_schema.py` exists from `001.backend-foundation/005` and is
**edited** here: its registry-emptiness assertion is now false (see DoD-7 and
`context.md` D14).

## Interface intent

**`backend/pyproject.toml`** — add **`argon2-cffi`** to the runtime dependencies, pinned
in the same style the existing dependencies use, and refresh the committed lock. Nothing
else in the file changes: no new tool configuration, no new dev dependency, and
**Alembic is still not a dependency**.

**`backend/app/roles.py`** — a new leaf module holding **one string enum of the two
roles**, `roleplayer` and `admin`, whose values are exactly the strings
`data-model.md` stores in the column. Its two members are the whole of the module:
**no ladder mapping, no comparison helper, no dependency factory** — those are `004`'s
(`context.md` D7). The member whose value is the administrator role is the one the
first-run account is created with (UC-001).

**`backend/app/db/schema.py`** — add the **`users` `Table(...)` literal** to the single
`MetaData` already in that file, per the file's own documented rule: every table in
RPHelper is declared as a literal in this same file, with no per-feature table module and
no builder callable. Columns are `data-model.md`'s authoritative list and **all of them
are declared**, even where this feature writes only some:

- the snowflake primary key, stored as SQLite's integer rowid alias and declared as
  SQLAlchemy Core's big-integer type, **not** auto-incrementing — ids are minted in
  application code before the INSERT;
- `username`, **unique** and not nullable;
- `password_hash`, not nullable, wide enough for an Argon2 encoded string;
- `role`, not nullable, constrained to the two values of the enum above, declared so the
  constraint is part of the table rather than a convention (a non-native enum backed by a
  text column with a check is the shape SQLite supports);
- `is_enabled`, boolean, not nullable;
- `rp_language` and `preferred_language`, **nullable** text (`context.md` D15);
- `created_at` and `updated_at`, UTC ISO-8601 text per `data-model.md`'s convention.

No index beyond the primary key and the uniqueness of `username`. **No view, no second
table, no `auth_sessions`.**

**`backend/app/services/passwords.py`** — the hashing seam, and a service by
construction rather than by domain classification (the same reasoning `001` records for
`services/health.py`). Two operations and nothing else:

- **a hash operation** taking a plaintext password and returning `argon2-cffi`'s own
  **self-describing encoded string** (`$argon2id$v=19$m=...`), using **Argon2id with the
  library's own current default parameters** — the module names no cost, memory or
  parallelism literal of its own (`context.md` D1);
- **a verification operation** taking an encoded hash and a candidate plaintext and
  returning whether they match, answering **false rather than raising** for a wrong
  password and for a value that is not a valid encoded hash, so a caller has one branch
  instead of two.

The module imports no `fastapi` symbol, opens no connection, reads no settings, logs
nothing, and exposes **no rehash-on-verify affordance** — a parameter change is a future
concern and `003` has no login path to rehash from.

## Definition of done

1. `[test]` The registry exposes a `users` table carrying exactly the columns
   `data-model.md` names — `id`, `username`, `password_hash`, `role`, `is_enabled`,
   `rp_language`, `preferred_language`, `created_at`, `updated_at` — and no others.
2. `[test]` `username` is unique, and `id` is the primary key and does **not**
   autoincrement; `rp_language` and `preferred_language` are nullable while
   `username`, `password_hash`, `role` and `is_enabled` are not.
3. `[test]` The `role` column accepts each of the two enum values and **rejects** a third
   value against a real database, so the value domain is enforced by the table and not by
   convention.
4. `[test]` The role enum has exactly two members, and their values are the two strings
   the column stores. It exposes **no** ladder mapping and **no** role-comparison or
   dependency helper (`context.md` D7).
5. `[test]` The hash operation returns an Argon2**id** encoded string — recognisable from
   its own self-describing prefix — and two calls on the same password return
   **different** strings, which is the observable proof that a per-hash salt is in use.
6. `[test]` The verification operation returns true for the password that produced a hash,
   **false** for any other password, and **false rather than raising** for a value that is
   not a valid encoded hash.
7. `[test]` The registry's table collection is enumerable by name and contains `users` —
   which is the shape feature `007` walks. The `001`-era assertion that the collection is
   **empty** is **deleted** as part of this step, deliberately and not incidentally
   (`context.md` D14); every other assertion in that file is left alone.
8. `[test]` `services/passwords.py` imports no `fastapi` symbol, takes no connection and
   reads no settings — it is callable with two plain strings and nothing else.
9. `[manual/live]` `argon2-cffi` appears in `backend/pyproject.toml`'s runtime
   dependencies and in the committed lock, and **no parameter literal for Argon2's cost,
   memory or parallelism appears anywhere in `app/`**. Verifier confirms by reading the
   two files.
10. `[manual/live]` Alembic is still absent from the dependency list, and `db/drift.py`,
    `db/sync.py`, `alembic.ini` and any `versions/` directory still do not exist.
11. `[manual/live]` `mypy app`, `ruff check .` and `pytest` all pass from `backend/`.
