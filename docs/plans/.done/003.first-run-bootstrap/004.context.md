# Step 004 — step-specific context

Feature-wide facts are in `context.md`; the decisions this step implements are D5 (branch
on `configured`, never `status`), D10 (the not-ready classification and where it lives),
D11 (the retry posture), D12 (no `notifyFailure`), D13 (store placement and the MobX
contract) and D14 (the deleted scan clause). None of that is repeated here.

## What `002` already built under this entry, and what it left for this step

`002/006.entries-and-guards.md:12-21` creates **both** `frontend/src/bootstrap/index.html`
and `frontend/src/bootstrap/main.tsx`.

- `index.html` is a document with lang and charset, a viewport meta, a title naming the
  entry, one mount element and a module script pointing at the sibling `main.tsx`. **This
  step changes none of it**, which is why it is in no Source files list.
- `main.tsx` finds the mount element, creates the React root and renders `AppProviders`
  wrapping a `BrowserRouter` wrapping a route table, with **no `basename`** for this entry.
  Its route table is an explicit **placeholder** — one catch-all rendering a stable entry
  marker and no visible content — and `002/006:43-47` says *"Later features replace the
  route table wholesale."* So this step **extends** the module; it does not re-create it.
- `002/006:61-62` is explicit that the placeholder carries *"No store, no data fetch, no
  gate, no shell, no `AppShell`, no error boundary"*. Every one of those for `bootstrap` is
  this feature's, and `002` defines **nothing** bootstrap-specific.

The entry marker is kept (DoD-14) rather than dropped, even though `002/006.context.md`
says later features owe it nothing: keeping one attribute costs nothing, keeps `002`'s
per-entry test passing untouched, and keeps a deep link landing on the wrong document
diagnosable.

## The shared modules this step calls, by role

Exact names are `002`'s to freeze; the skeleton resolves them against the delivered code.

- **`shared/api.ts`** — one request function taking path, method, optional JSON body and
  optional `AbortSignal`, plus four thin verb helpers. It **requires the path to begin
  `/api/`**, sends credentials, sets no `Authorization` header, resolves `204`/empty to
  nothing, and **throws** on non-2xx. A `401` performs a document navigation to `/login`
  and still throws; a `403` does **not** navigate. An abort rejection propagates
  **unchanged and unwrapped**.
- **`shared/apiError.ts`** — `ApiError extends Error` carrying `code`, `message`, `detail`
  and `status`, recognisable with `instanceof`, plus a type guard, plus the **two named
  synthetic code constants**: `client_malformed_error` (the real status is preserved — a
  raw nginx 502 HTML page decodes to this with `status === 502`) and
  `client_transport_failed` (`status === 0`). Import the constants; do not re-type the
  strings.
- **`shared/AppProviders.tsx`** — Mantine's provider with the theme and colour-scheme
  manager, the notifications outlet at 5000 ms, and **the stylesheet imports in one place**
  (Mantine core, notifications, then `global.css` last). It creates no context and provides
  no store: **stores are passed explicitly as props everywhere in this project.**
- **`shared/notifyFailure.ts`** — exists, and this entry calls it nowhere
  (`context.md` D12).

## The health body, and the one field this entry reads

`GET /api/health` answers `{"status": ..., "configured": ..., "schema": ...}` and is
unauthenticated (`backend-structure.md`'s `/api/health` section). `backend-structure.md:629-631`
is the sentence this step implements: *"`configured` is FEAT-001's signal … The bootstrap
entry uses it to decide whether to offer bootstrap at all; UC-003's refusal is the
server-side enforcement of the same fact."*

So: **there is no second probe endpoint, and none may be invented.** The narrow response
type the entry needs — one boolean — is declared in `bootstrapState.ts` and not in
`shared/`, because no other entry reads this body yet and a shared type would be a contract
invented against one caller.

DoD-6 exists because a pre-bootstrap instance genuinely answers `status: "degraded"`
(`context.md` D5); an entry that branched on `status` would refuse to offer bootstrap on
precisely the instance that needs it.

## Why the not-ready state exists at all

`deployment.md:145-152`: `supervisord` has **no wait-for ordering**, so nginx serves the
bootstrap bundle while uvicorn is not yet accepting connections — and the freshly loaded
bundle's very first request is the one that cannot succeed yet. `/api/health` is the
readiness signal, and *"the bootstrap entry is built to render a not-ready-yet state"*.
The same passage records that this is reported as a bug when it is not one, which is why
DoD-8's wording is a wait and not a fault, and why the retry is automatic.

`deployment.md:165-170` is the sibling rule for the `admin` gate — *"a 502 or a network
failure on `/api/me` is not a deny"* — which is why the predicate lives in `shared/` rather
than inside this entry (`context.md` D10) even though `005` is the feature that will use it
second.

## Gotcha — testing a fixed interval

`002`'s D10 fixes Vitest, and `frontend/tests/setup.ts` holds **no fetch stub**: `fetch` is
stubbed per test with no network-mocking library. A fixed 2000 ms interval is assertable
with fake timers and a counted stub; that is exactly why `context.md` D11 chose a fixed
interval over a jittered backoff. Whether the interval is a repeating timer or a
self-rescheduling one is the skeleton's call — what DoD-8 fixes is the observable request
cadence.

## Gotcha — an abort is not a failure

`002`'s D8: an abort rejection propagates **unchanged and unwrapped**, so it is neither
synthetic code and therefore not the not-ready condition (DoD-7 asserts that directly). The
probe's early-return-on-aborted-signal rule (`002`'s D2) is what keeps a late response from
writing into a store whose component is gone — which is the whole of DoD-12.

## Gotcha — the offer leaves room, and room is not a control

`fast/003.bootstrap-from-export` is sequenced after `031.import-and-id-remapping`, so the
import option is a long way off. Render the create option as **one option among a list that
will grow**, not as the only thing on the page and not as a pair with a disabled sibling: a
disabled control promises a capability that does not exist, and "coming soon" copy is a
requirement nobody wrote.

## Gotcha — `useState`, not `useMemo`

`frontend-structure.md` is explicit: one store per page instantiated via
`useState(() => new XState())`, because *"`useMemo` is a cache with no guarantee of
identity, and a store whose identity can change silently is a source of lost in-flight
state"* — and this store holds an in-flight probe and a live timer, which is exactly the
state that would be lost.

## The single clause deleted from `002`'s scan

`002/006.entries-and-guards.md`'s Test files are `entries.test.tsx`,
`ids-are-strings.test.ts` and `conventions.test.ts`. DoD-9's ids scan is
`ids-are-strings.test.ts`; DoD-10 (pure data contracts), DoD-11 (styling mechanisms) and
DoD-12 (the single notification call site) are the conventions scan, so
**`frontend/tests/conventions.test.ts`** is the file that carries the now-false clause and
is the file in this step's scope.

If the delivered `002` tests placed DoD-10's clause in `ids-are-strings.test.ts` instead,
the deletion applies there and this step's Test files are wrong by one path — that is a
**test-coder hand-back to the orchestrator**, not a licence to edit a file outside the
listed scope. Delete only the `makeAutoObservable` / page-store-class clause; the ids scan,
the styling scan and the notification scan all stay.
