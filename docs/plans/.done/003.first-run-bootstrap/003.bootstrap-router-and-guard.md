# Step 003 — The bootstrap router, its models, and `require_unconfigured`

## Goal

Expose the creation operation as one HTTP route behind a **router-level**
`require_unconfigured` dependency, so that UC-003's refusal is enforced for every
bootstrap route that exists now or is added later.

## Source files

```
backend/app/models/bootstrap.py
backend/app/routers/bootstrap.py
backend/app/main.py
```

## Test files

```
backend/tests/test_bootstrap_router.py
```

## Interface intent

**`backend/app/models/bootstrap.py`** — two pydantic models and nothing else.

- **A create-request model** carrying a username and a plaintext password, both
  constrained to be non-empty (`context.md` D16 — the defensive backstop, answered by
  FastAPI's own `422`; **no new domain error code**). It carries no role field: the
  first-run account is always the administrator (UC-001), and accepting a role here would
  let a caller ask for something else.
- **A create-response model** carrying the new administrator's **id**, username and role.
  The id field uses `001`'s outbound snowflake alias from `app/models/ids.py`, so it
  serialises as a **decimal string** — a bare `int` id field is the defect. It carries
  **no token and no session field** (`context.md` D9).

**`backend/app/routers/bootstrap.py`** — the router, owning HTTP and nothing else: no
business rule, no SQL.

- **`require_unconfigured`** — the dependency `backend-structure.md:209-213` specifies,
  declared here (`context.md` D6). It resolves a connection through `001`'s connection
  dependency, asks step `002`'s predicate, and **raises the `already_configured` error**
  when the instance is configured; on an unconfigured instance it yields nothing of
  interest and lets the request proceed. It is attached **to the router**, not to the
  handler, so a bootstrap route added later — `fast/003.bootstrap-from-export`'s import
  route — inherits the guard without anyone remembering to.
- **`POST /api/bootstrap/create`** — the one route. It takes the create-request model,
  the connection dependency, and the process's snowflake generator resolved from
  **application state**; calls step `002`'s creation operation; and returns the
  create-response model with status **201**. It sets **no cookie**. It performs no
  validation of its own beyond the request model and translates no error by hand — the
  base-class handler `001` registered renders `already_configured` on its own.
- The router is mounted under the `/api/bootstrap` prefix, and **`/api/bootstrap/import`
  is deliberately absent** — room is left for it, nothing is built.

**`backend/app/main.py`** — include the bootstrap router in the app factory, beside the
health router. Nothing else changes: the **lifespan still runs no DDL**, no schema
creation, no upgrade and no schema check.

## Definition of done

1. `[test]` `POST /api/bootstrap/create` on an unconfigured instance answers **201** with
   a body carrying the new administrator's id, username and role — the id as a **decimal
   string**, never a JSON number — and afterwards the database holds that administrator.
   (US-001.AC-1)
2. `[test]` The response body carries **no** token, session or cookie field, and the
   response sets **no** `Set-Cookie` header. (`context.md` D9 — US-001.AC-2 is `004`'s)
3. `[test]` The same request against a **configured** instance answers **409** with the
   wire shape `{"error": {"code": "already_configured", "message": ..., "detail": {}}}`,
   and the existing database is untouched. (US-003.AC-1)
4. `[test]` The guard is **router-level**: a second route registered on the same router in
   the test answers the same refusal on a configured instance without declaring any
   dependency of its own — which is the property `fast/003`'s import route depends on.
   (US-003.AC-1)
5. `[test]` The route is reachable with no credentials at all — no cookie, no
   `Authorization` header — on an unconfigured instance, because there is no account to
   authenticate as yet.
6. `[test]` An empty username or an empty password is refused before anything is written,
   and the database still holds no administrator afterwards.
7. `[test]` A request naming a role, an id, or any field the request model does not
   declare does not create an account with that role or that id — the first-run account is
   always the administrator, with a server-minted id. (UC-001)
8. `[test]` The administrator created through the route can be found by the predicate from
   step `002`, so `/api/health` reports `configured: true` immediately afterwards without
   a restart. (US-001.AC-1)
9. `[test]` The router issues no SQL and holds no rule: its only database contact is
   through `001`'s connection dependency, and the created row's every value comes from the
   service.
10. `[manual/live]` `routers/bootstrap.py` declares exactly one route today, the guard is
    attached to the router rather than to that handler, and no import route exists.
    Verifier confirms by reading the module.
11. `[manual/live]` `main.py`'s lifespan still runs no DDL. Verifier confirms by reading
    the factory.
12. `[manual/live]` `uvicorn app.main:app` on port 8184 starts; against a data directory
    with no database, `POST /api/bootstrap/create` creates one and a second identical
    request answers 409.
13. `[manual/live]` `mypy app`, `ruff check .` and `pytest` all pass from `backend/`.
