# Step 005 — The create-administrator form, its submit path, and the hand-off to `/login`

## Goal

Give the offer state its form: a draft with pure validators, a submit that posts the first
administrator once, and a hand-off to `/login` when it succeeds.

## Source files

```
frontend/src/bootstrap/createAdminDraft.ts
frontend/src/bootstrap/CreateAdminForm.tsx
frontend/src/bootstrap/BootstrapPage.tsx
```

`BootstrapPage.tsx` is step `004`'s file and the **only** change to it here is mounting the
form inside the offer state.

## Test files

```
frontend/tests/bootstrap/createAdminDraft.test.ts
frontend/tests/bootstrap/CreateAdminForm.test.tsx
```

## Interface intent

**`frontend/src/bootstrap/createAdminDraft.ts`** — the draft and its free functions,
following `002`'s D2 and `context.md` D13.

- **A draft data class** holding observable fields only — the username, the password, the
  confirmation, a per-field server-error map with a general key, and whether a submit is in
  flight — with `makeAutoObservable(this, {}, { autoBind: true })` in the constructor and
  **no methods and no computed getters**. A fresh instance per mount.
- **A pure client-validation function** taking the draft and returning the field-keyed
  client errors: username required and non-empty after trimming, password required and
  non-empty after trimming, confirmation must equal the password (`context.md` D16 — no
  length floor, no character classes, no strength meter, because
  `docs/product/` states no password policy).
- **A pure submittability function** taking the draft and answering whether it may be
  submitted: no client errors and no submit in flight.
- **An effectful submit function** taking the draft and an optional `AbortSignal`. It posts
  the username and password to `POST /api/bootstrap/create` through `shared/api.ts`,
  `runInAction`s the in-flight flag around the call, early-returns on an aborted signal
  before writing, and resolves to a **plain outcome value** the caller acts on: *created*,
  *refused because the instance is already configured*, or *failed*. On failure it maps the
  `ApiError` onto the draft's server-error map **by code or status, never by parsing
  prose**, with anything unmappable landing on the general key (`002`'s D6). It performs
  **no navigation of its own** and calls `notifyFailure` nowhere (`context.md` D12).
  A refusal is recognised by the backend code `already_configured` and is **not** written
  onto the draft as a field error — it is the page's state change.

**`frontend/src/bootstrap/CreateAdminForm.tsx`** — an `observer` component taking the
bootstrap store and the draft **explicitly as props**, plus an optional hand-off function
defaulting to the **document navigation to `/login`** (`window.location.assign`) so a test
can supply its own. It renders three Mantine text inputs — username, password and
confirmation, the two latter masked — client errors and server errors on their fields, the
general server error as an inline `Alert`, and one submit control that is disabled while a
submit is in flight or while the draft is not submittable. On the *created* outcome it calls
the hand-off; on the *refused* outcome it flips the bootstrap store to its refusal phase, so
the whole page becomes the refusal (UC-003) rather than the form showing an error beside a
still-live submit control. It has **no icon-only action**, so `shared/IconButton` does not
appear — if one is ever added it must go through `IconButton`.

**`frontend/src/bootstrap/BootstrapPage.tsx`** — the offer state now mounts this form,
creating the draft with `useState(() => new …Draft())` — never `useMemo`. Nothing else in
the page changes: the other four states, the probe lifecycle, the entry marker and the
absence of `notifyFailure` are step `004`'s and stay as they are.

## Definition of done

1. `[test]` The client-validation function reports an error for an empty or
   whitespace-only username, for an empty or whitespace-only password, and for a
   confirmation that does not equal the password; and reports none for a filled, matching
   draft.
2. `[test]` The submittability function is false whenever any client error exists and false
   while a submit is in flight, and true only for a valid draft with no submit in flight.
3. `[test]` The submit control is disabled for an invalid draft and while a submit is in
   flight, and a second activation while one is in flight issues **no** second request —
   the first administrator is created once.
4. `[test]` A successful submit issues exactly one `POST /api/bootstrap/create` carrying the
   username and password and **nothing else** — no role, no id, no confirmation field.
   (US-001.AC-1)
5. `[test]` On success the hand-off runs, targeting `/login`, and it runs **once**.
   (`context.md` D9 — the operator signs in there; US-001.AC-2 is `004`'s)
6. `[test]` A submit answered with `already_configured` flips the page to the refusal state:
   the refusal and its sign-in link render, and the form is **gone** rather than showing an
   error beside a live submit control. (US-003.AC-1, US-003.AC-2)
7. `[test]` A submit answered with any other failure renders **in place**: a field-shaped
   failure on its field and anything else in the general inline alert, with the form still
   usable and the entered username preserved.
8. `[test]` The password and the confirmation are never rendered in readable form, and no
   value of either appears in the general error message the form shows.
9. `[test]` An aborted submit writes nothing onto the draft and renders no failure.
10. `[test]` `notifyFailure` is called nowhere in this step either, so the entry as a whole
    raises no notification (`context.md` D12), and the draft is a data class with
    observable fields only — no method, no computed getter.
11. `[manual/live]` Against a running backend with no database: filling the form and
    submitting creates the administrator, lands on `/login`, and re-opening the bootstrap
    entry afterwards shows the refusal. This is the end-to-end reading of UC-001 followed by
    UC-003.
12. `[manual/live]` Both colour schemes are correct for the form, its field errors and its
    general alert.
13. `[manual/live]` `npm run typecheck`, `npm test` and `npm run build` all pass from
    `frontend/`.

## Dependencies

Step `004` (the entry's store, its phases and the offer state it mounts into). It binds to
step `003`'s route contract, which must be deployed for DoD-11.
