## The insert position, concretely

`last_used_at` values are fixed-width UTC text, so plain string comparison orders them
chronologically. "Insert by `last_used_at` descending" means: before the first existing
row whose `last_used_at` is **less than** the new one's, else at the end. Equal values
insert after the equal rows. **Never** compare or tie-break on `id` (`tests/ids-are-strings.test.ts`
cannot catch a lexicographic id sort; this sentence is the guard).

The rule removes a present row before inserting, rather than replacing in place, because
from `012` on a content write moves `last_used_at` and the row must move with it. In 011
nothing changes `last_used_at` after creation (D3), so a re-applied row lands where it was
(DoD-5).

## `orderCharactersByUse` without importing 009

The function reads only `id` from each character, so it is typed over "anything with an
`id` string" (a generic over that shape) and returns the same element type. That keeps
this module free of `charactersApi.ts` and buildable before 009. The tree (`006`) passes
009's `Character` rows. The "greatest `last_used_at`" is a text max over that character's
sessions; the sort must be **stable** (a decorate-sort or a stable `Array.prototype.sort`
with a comparator that returns 0 for ties both preserve the given order).

## Why `startSession` always sends a body

The backend also accepts no body (`003.context.md`), but the client sends
`{ setup_id: null }` explicitly so the request states "no setup" rather than implying it,
and so a later field (`018`'s opening message) is added to an existing body rather than
introducing one.

## Placement

Both modules under `src/app/` (single-entry state). `sessionsApi.ts` is separate from the
state because the section state (`007`) and the session screen (`009`) use the calls
without the workspace list.
