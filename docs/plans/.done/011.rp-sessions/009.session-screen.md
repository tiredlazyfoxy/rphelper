# Step 009 — The session's own screen at `/sessions/:id`

## Goal

Add `app/sessionScreenState.ts` (the screen's data class and its load) and
`app/SessionScreen.tsx` (the session's own empty screen with its header, plus a route

## Interface intent

**`app/sessionScreenState.ts`** (new)

- **`SessionScreenState`**: data class, observable fields only, constructed from a
  `sessionId` (string): `sessionId`; `session` (a `Session` or `null`, starts `null`);
  `status`: `"idle"`, `"loading"`, `"ready"`, `"not-found"` or `"failed"`, starts
  `"idle"`.
- **`loadSessionScreen`**: effect. Takes the state and an optional signal. Sets
  `"loading"`, requests the one session, and on success writes it with `"ready"`. An
  `ApiError` with code `session_not_found` writes `"not-found"`; any other failure writes
  `"failed"`. Writes nothing once aborted; never rejects. Reads only (D3).

**`app/SessionScreen.tsx`** (new)

- **`SessionScreen`**: `observer` component. Props: `sessionId` (string) and
  `characters` (the workspace `CharactersState`). Creates its `SessionScreenState` once
  with `useState`; loads on mount with an `AbortController` aborted on unmount. Renders by
  status:
  - `"idle"` / `"loading"`: a centred `Loader`;
  - `"not-found"`: the text **"Session not found"**, with no retry;
  - `"failed"`: the text **"Could not load the session"** and a button **"Retry"** that
    re-runs the load;
  - `"ready"`: a header holding a router link to `/characters/<character_id>` whose text
    is the character's name when `characters.characters` holds that id, else
    **"Character"**; a heading whose text is the start-time label; the setup name when
    `setup_name` is non-null, else nothing; an **"Archived"** badge when archived; then
    the line **"No entries yet."**. No archive or restore control, no textbox, no stream,
    ruler, composer or wall.
  - No notification anywhere.
- **`SessionRoute`**: component. Props: `characters`. Reads the `:id` route parameter (a
  string, used verbatim) and renders `SessionScreen` for it, **keyed by the id**.

**`app/App.tsx`** (edited)

- `/sessions/:id` renders `SessionRoute` with the `CharactersState`. Every other route
  is unchanged.

## Definition of done

   `status` `"idle"`. `loadSessionScreen` sets `"loading"` while pending, requests exactly
   `GET /api/sessions/s1`, then `"ready"` with the session (ids still the payload's
   strings). A 404 `session_not_found` writes `"not-found"`; a 500 or transport failure
   writes `"failed"`; neither throws; an aborted signal writes nothing. (UC-024)
2. `[test]` At `/sessions/<id>` the screen shows a loader while the GET is pending.
   (UC-024)
3. `[test]` Ready, with the workspace `CharactersState` holding the session's character
   "Aria": the main region shows a link "Aria" with `href` `/characters/<character_id>`,
   a heading whose text has the start-time label's fixed shape, and "No entries yet.".
   (US-026.AC-1, UC-023, UC-024)
4. `[test]` A session with `setup_name` "Tavern" shows "Tavern" in the header; one with
   `setup_id` null shows no setup text. (US-088.AC-1, US-088.AC-2)
5. `[test]` With an empty `CharactersState`, the character link reads "Character" and
   still has `href` `/characters/<character_id>`; no extra request is made for the
   character. (D17)
6. `[test]` An archived session opened directly shows an "Archived" badge in the main
   region and no "Archive", "Restore" or "Actions for …" control. (D5, R6, US-027.AC-3 —
   reopens by id)
7. `[test]` A 404 `session_not_found` renders "Session not found" in the main region, with
   no "Retry" and no notification.
8. `[test]` A 500 or transport failure renders "Could not load the session" and "Retry";
   pressing "Retry" requests the session again, and on success it renders.
9. `[test]` Navigating in-entry from `/sessions/<a>` to `/sessions/<b>` requests `b` and
   shows only `b`'s header.
10. `[test]` The ready screen's main region contains no textbox and no button. (D17)
11. `[test]` `App` (amending 008's and 009's route tests): `/sessions/1` with
    `GET /api/sessions/1` stubbed renders the session screen in the main region; `/`,
    `/settings` and `/search` still render an empty main region; an undeclared path still
    renders "Page not found". From `/`, clicking a session row in the tree opens that
    session's screen. (UC-024, UC-069)
12. `[test]` `tests/entries.test.tsx` keeps passing its 008 / 009 assertions: if it mounts
    the `app` entry at a `/sessions/…` path, its stub also answers that
    `GET /api/sessions/<id>` (by exact path); no assertion about the boot outcomes
    changes.
13. `[manual/live]` Against a running backend: start a session from a character page, land
    on its screen with the character link, start time and setup label; reload the URL and
