# Step 008 — The Sessions section and its place on the character screen

## Goal

Add `app/SessionsSection.tsx`: the "Sessions" region with its inline start (the "Setup"
select and "Start session"), the "Show archived sessions" switch, the table of sessions
with a per-row overflow menu (Archive / Restore), and its loading / failed / empty states.
Render it on the character screen in place of 009's empty "Sessions" heading, keyed by the
character id, and pass the workspace `SessionsState` from `App` down to it (D1, D5, D15,
D18, D19).

## Interface intent

**`app/SessionsSection.tsx`** (new)

- **`SessionsSection`**: `observer` component. Props: `characterId` (string) and
  `sessions` (the workspace `SessionsState`). Creates its `SessionsSectionState` once with
  `useState`. It:
  - loads `loadSectionSessions` on mount and again whenever `showArchived` changes, and
    `loadSetupChoices` on mount and again **each time the Select's dropdown opens**; each
    load kind with its own `AbortController`, aborted when its next run starts or on
    unmount;
  - renders a **region** named **"Sessions"**, headed by a heading **"Sessions"** at the
    same level as 010's "Setups" heading;
  - in its header: a Mantine `Switch` labelled **"Show archived sessions"** reflecting
    `showArchived` and calling `setShowArchived`;
  - the inline start: a Mantine `Select` labelled **"Setup"** whose options are **"No
    setup"** first, then the working setups' names in state order, its value reflecting
    `selectedSetupId` ("No setup" when `null`) and calling `selectSetup`; under it, when
    `setupsStatus` is `"failed"`, the dimmed line **"Could not load setups to choose
    from."**; and a labelled button **"Start session"** (`IconPlus` left section),
    disabled only while `startStatus` is `"submitting"`, which runs
    `startSessionFromSection` with an `onStarted` that navigates in-entry (push) to
    `/sessions/<id>`. `startError`, when non-null, renders in an inline `Alert` in the
    region;
  - the list, by `status`: `"idle"` / `"loading"` → a small `Loader`; `"failed"` → the
    text **"Could not load sessions"** and a button **"Retry"** re-running
    `loadSectionSessions`; `"ready"` and empty → the text **"No sessions yet."** and
    nothing else; `"ready"` with rows → a Mantine `Table`, one row per session in state
    order. Each row: a router link to `/sessions/<id>` whose text is the start-time label;
    the setup name, or nothing; dimmed with an **"Archived"** badge when archived; and a
    trailing `IconButton` (`IconDots`) labelled **"Actions for <start-time label>"**,
    disabled while that row is `pendingId`, opening a `Menu` with **"Archive"**
    (`IconArchive`, `archiveSectionRow`) for a working row or **"Restore"**
    (`IconArchiveOff`, `restoreSectionRow`) for an archived one. No confirm;
  - renders `error`, when non-null, in an inline `Alert` in the region;
  - `void`s every effect from its handlers. No notification anywhere.

**`app/CharacterScreen.tsx`** (edited; 009-owned file, edited by 010 `006`)

- `CharacterScreen` and `CharacterRoute` each gain one **required** prop, `sessions` (the
  workspace `SessionsState`); `CharacterRoute` passes it through.
- In existing mode with status `"ready"`, 009's empty "Sessions" heading section is
  **replaced** by `SessionsSection` for the loaded character, keyed by the character id,
  in the same position (after 010's `SetupsSection`). New mode, loading, not-found and
  failed render no section.

**`app/App.tsx`** (edited)

- Passes its `SessionsState` (created in `006`) to the `/characters/new` `CharacterScreen`
  and to `CharacterRoute` as `sessions`. Nothing else changes.

## Definition of done

1. `[test]` `SessionsSection` mounted for character C with `fetch` answering two sessions
   (one with a setup name, one without) requests exactly `GET /api/characters/<C>/sessions`
   and `GET /api/characters/<C>/setups`, then shows a "Sessions" region with a "Sessions"
   heading, an off "Show archived sessions" switch, a "Setup" select showing "No setup",
   an enabled "Start session" button, and a table with one row per session in the
   payload's order: each a link to `/sessions/<id>` with a start-time label of the fixed
   shape, the first showing its setup name and the second no other text. (US-028.AC-1,
   US-088.AC-1, US-088.AC-2)
2. `[test]` With an empty sessions listing the region shows "No sessions yet." and no
   table. (D18)
3. `[test]` A failed sessions load shows "Could not load sessions" and "Retry" in the
   region, with no notification; "Retry" requests the listing again, and on success the
   rows render. (D18)
4. `[test]` Pressing "Start session" with "No setup" selected POSTs
   `/api/characters/<C>/sessions` with `{"setup_id": null}`; after the 201 the router
   location is `/sessions/<the response's id string>`, and the passed `SessionsState`
   holds the new row. (US-026.AC-1, US-024.AC-1, UC-023, D1, D15)

   names in the setups payload's order; the setups request carries no `include_archived`.
