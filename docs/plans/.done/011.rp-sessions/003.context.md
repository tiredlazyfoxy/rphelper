## The optional body

The start route must accept three request shapes as "no setup": no body at all, `{}`, and
`{"setup_id": null}` (DoD-2). Declare the body parameter as optional with a `None`
default (FastAPI's `Body(default=None)` or an equivalent optional model parameter) and
treat a `None` model as `setup_id` `None`. The frontend always sends a JSON object
(`004`); the no-body form exists so a hand-made client cannot trip on it. `018` later adds
an optional opening-message field to this same model and route.

## Path coexistence

- `/api/characters/{character_id}/sessions` sits beside 010's
  `/api/characters/{character_id}/setups` and 009's `/api/characters/{character_id}`
  `…/archive` / `…/restore`: the third segment is a different literal, so nothing
  overlaps. Registering after setups keeps 009's and 010's routes matched first (DoD-17).
- `/api/sessions` and `/api/sessions/{session_id}` have no other owner yet. `012`'s
  `routers/stream.py` will add `/api/sessions/{id}/entries`, `…/zone…`, `…/settle`,
  `…/reopen`: different literal segments, no conflict with `…/archive` / `…/restore`.

## 405 for PATCH and DELETE

No handler is declared for either method. Starlette answers 405 when a path matches under
another method: `/api/sessions/{session_id}` (GET), `/api/sessions` (GET) and
`/api/characters/{character_id}/sessions` (GET/POST) all match. DoD-13 asserts the status
only.

## Test seeding

Users A and B (role `roleplayer`) through the file-local `_insert_user`, each logged in on
its own client. Characters through `POST /api/characters`, setups through
`POST /api/characters/{id}/setups`, a setup archived through `POST /api/setups/{id}/archive`,
a character archived through `POST /api/characters/{id}/archive`, all as their owner.
"Nobody's" ids are large decimal strings no row holds. DoD-11 relies on D3: with no
content writes yet, last use equals start order.
