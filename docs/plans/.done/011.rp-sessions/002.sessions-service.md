# Step 002 — The sessions service

## Goal

Add `services/sessions.py`, the one layer that issues SQL against `sessions`: a frozen
`RpSession` value and six owner-scoped operations (start under a character, list all, list
for a character, get, archive, restore). It checks the parent character and the chosen
setup with its own scoped selects in the same transaction (D11, D12), joins the setup
label at read time (D10), follows D3 / D13 / D14, and has no delete operation (R6), no
default setup (R2) and no model capture (R4 deferred).

## Interface intent

Every operation takes the Core `Connection` first and the owner's `user_id` (int) as a
**required positional** argument after it (after the generator, for the create). Each
returns `RpSession` values or raises a domain error, and never imports or raises anything
HTTP-shaped.

- **`RpSession`**: frozen dataclass value: `id` (int), `character_id` (int), `setup_id`
  (int or `None`), `setup_name` (string or `None`), `archived_at` (string or `None`),
  `last_used_at`, `created_at`, `updated_at`. No `user_id`.
- **`start_session`**: takes the connection, the id generator, `user_id`, a
  `character_id` and a `setup_id` (int or `None`). In **one** write transaction: verifies
  the character is the caller's (archived or not; else `CharacterNotFoundError`); when a
  `setup_id` is given, verifies it is the caller's setup **under that character** (else
  `SetupNotFoundError`) and not archived (else `SetupArchivedError`); mints the id; stamps
  `created_at` = `updated_at` = `last_used_at` with one instant; leaves `archived_at`
  NULL; writes `user_id` from the argument; returns the created value with `setup_name`
  set from the checked setup (or `None`). A refusal inserts nothing.
- **`list_sessions`**: takes the connection, `user_id` and an `include_archived` flag.
  Returns the caller's sessions across all characters, working only unless the flag is
  true, ordered by D14, each with its `setup_name`. A read: leaves no transaction open.
- **`list_character_sessions`**: takes the connection, `user_id`, a `character_id` and
  `include_archived`. Raises `CharacterNotFoundError` when the character is not the
  caller's (an archived character is fine); otherwise returns that character's sessions
  as `list_sessions` does. A read: leaves no transaction open on either exit.
- **`get_session`**: takes the connection, `user_id` and a session id. Returns the
  session, archived or not, or raises `SessionNotFoundError`. Writes nothing (D3). A read.
- **`archive_session`**: takes the connection, `user_id` and a session id. Sets
  `archived_at` and bumps `updated_at` when working; on an archived one writes nothing and
  returns it with its original `archived_at`. Never changes `last_used_at`. Touches no
  table but `sessions`. Raises `SessionNotFoundError`.
- **`restore_session`**: same inputs. Sets `archived_at` NULL and bumps `updated_at` when
  archived; on a working one writes nothing. Never changes `last_used_at`. Raises
  `SessionNotFoundError`.

There is **no** delete operation, no update operation and no "touch" operation.

## Definition of done

1. `[test]` `start_session` under the user's character with `setup_id` `None` returns an
   `RpSession` whose `id` is the value the supplied generator minted, with that
   `character_id`, `setup_id` `None`, `setup_name` `None`, `archived_at` `None`, and
   `created_at == updated_at == last_used_at` in the fixed-width form
   `YYYY-MM-DDTHH:MM:SS.ffffff+00:00`. `get_session` then returns an equal value, and both
   `list_sessions` and `list_character_sessions` contain it. (US-026.AC-1, US-024.AC-1, D3)
2. `[test]` `start_session` with a setup of the caller under the same character returns
   that `setup_id` and `setup_name` equal to the setup's name. Starting a second session
   with the same setup succeeds, and both sessions list with that `setup_id` and
   `setup_name`. (US-025.AC-1, UC-022, D10)
3. `[test]` `start_session` and `list_character_sessions` with another user's character id,
   or a character id that exists for nobody, raise `CharacterNotFoundError`; after the
   refused start the `sessions` table holds no new row. Both succeed under the caller's
   **archived** character. (R5, D2, D12)
4. `[test]` `start_session` with a `setup_id` that is another user's setup, one that exists
   for nobody, or the caller's setup under **another of the caller's characters** raises
   `SetupNotFoundError`, and no `sessions` row is inserted. (D12, R5)
5. `[test]` `start_session` with the caller's **archived** setup under that character
   raises `SetupArchivedError`, and no `sessions` row is inserted. (D2, D12)
6. `[test]` With two users each owning characters with sessions, `list_sessions` returns
   only the caller's sessions, and `list_character_sessions` only the addressed character's,
   with and without `include_archived`. (US-029.AC-1, R5)
7. `[test]` Ordering: sessions raw-inserted for one character with `last_used_at` values
   **out of creation order** come back from both lists by `last_used_at` descending, not by
   `created_at`. Three sessions started in sequence through `start_session` come back newest
   first. (US-028.AC-1, D14)
8. `[test]` Both lists exclude archived sessions without the flag and return working and
   archived together with it. (US-027.AC-1, R6)
9. `[test]` `get_session`, `archive_session` and `restore_session` called with another
   user's session id raise `SessionNotFoundError`, and the owner's row is unchanged
   afterwards (`archived_at`, `updated_at`, `last_used_at`). The same three called with an
   id that exists for nobody raise the same error. (US-029.AC-1, R5, D12)
10. `[test]` `archive_session` on a working session returns it with `archived_at` set in
    the fixed-width form; it is then absent from both default lists, present in both
    include-archived lists, and still returned by `get_session`. Archiving it again returns
    the same `archived_at` and `updated_at`. `last_used_at` is unchanged throughout.
    (US-027.AC-1, D13, D3)
11. `[test]` `restore_session` on that archived session returns it with `archived_at`
    `None`, and it is back in both default lists. Its `id`, `character_id`, `setup_id`,
    `setup_name`, `created_at` and `last_used_at` equal the values from before the archive.
    Restoring a working session returns it unchanged (same `updated_at`). (US-027.AC-2,
    US-027.AC-3 — the row half, D13)
12. `[test]` Calling `get_session` (and either list) leaves the session's `last_used_at`
    and `updated_at` exactly as they were. (D3)
13. `[test]` After the referenced setup is archived (a raw update of `setups.archived_at`),
    `get_session` and both lists still return the session with its `setup_id` and
    `setup_name`. (D10, 010 D3)
14. `[test]` After `list_sessions`, `list_character_sessions` (including when it raised
    `CharacterNotFoundError`) and `get_session` (including when it raised
    `SessionNotFoundError`), the connection is not in a transaction, so a following
    `connection.begin()` succeeds.
15. `[test]` After `start_session` with `setup_id` `None`, the `setups` table holds no new
    row: no operation of this module inserts into any table but `sessions`. (R2)
16. `[test]` The source text of `app/services/sessions.py` contains no `delete(` call, no
    `DELETE` SQL keyword, no `fastapi` import, no import from any `app.services.` module,
    and no reference to `model_ref`. (R6, D11, R4 deferral)
