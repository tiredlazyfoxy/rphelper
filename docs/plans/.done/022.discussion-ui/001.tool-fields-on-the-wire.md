# Step 001 — Tool name, status and arguments on the wire

## Goal

Derive the tool view (`tool_name`, `tool_status`, `tool_args`) from a tool row's
`tool_payload` in the messages service and expose it on `MessageResponse`. Raw payload,
`call_id` and `content` stay server-side (D3, U2).

## Source files

backend/app/services/messages.py
backend/app/models/stream.py

## Test files

backend/tests/test_tool_wire_fields.py
backend/tests/test_tool_rows.py
backend/tests/test_stream_router.py

`test_tool_rows.py` is 021 `001`'s. Only its DoD-4 test is amended. `test_stream_router.py`
is 012's. It is amended only where an assertion pins a message object to exactly the eight
original keys (`001.context.md`).

## Interface intent

**`app/services/messages.py`** (changed)

- **Tool view derivation** (new; may be public or module-private, name final at skeleton).
  - Input: a row's role, `tool_name` and `tool_payload`.
  - Output: the three values `tool_name`, `tool_status` and `tool_args`, per `context.md` D3's
    table.
  - It is pure: no I/O, and it never raises on any payload string, including invalid JSON.
- **`StreamMessage`** gains `tool_status` (`"ok"`, `"failed"` or none) and `tool_args` (a
  mapping or none).
  - Both are appended **after** 021's `tool_name` / `tool_payload`, **with a default of
    none**, so every existing constructor call stays valid.
  - Every `StreamMessage` the module returns for a `role='tool'` row carries the derived
    values, whatever path builds it: the shared row mapper, `append_tool_message`, and edit
    results.
  - Every non-tool row carries none for both.
- No other behaviour changes. The S012_002_DoD13 guard (no `select` naming `messages`, no
  fastapi, no `app.services` import) stays green.

**`app/models/stream.py`** (changed)

- **`MessageResponse`** gains `tool_name` (string or null), `tool_status` (`"ok"` /
  `"failed"` / null) and `tool_args` (a JSON object or null). That makes **eleven** keys:
  the original eight plus these three.
- `tool_payload` is **not** a field, so the attribute-based mapping
  (`from_attributes=True`) never copies it out.
- The ids stay `SnowflakeOut`.

## Definition of done

1. `[test]` The derivation maps every row of `001.context.md`'s payload table to its expected
   `(tool_name, tool_status, tool_args)` exactly, including the unreadable-payload rows, and
   never raises. (D3)
2. `[test]` `list_zone` over a zone `[user, assistant, tool(ok), tool(failed)]` returns:
   - the user and assistant rows with `tool_name`, `tool_status` and `tool_args` all `None`;
   - the ok tool row with `tool_status` `"ok"` and `tool_args` `{"query": "lighthouse"}`;
   - the failed tool row with `tool_status` `"failed"` and `tool_args` `{"query": "x"}`.

   (D3, 021 D7)
3. `[test]` `GET /api/sessions/{id}/zone` with those four rows answers 200:
   - every message object has **exactly** the eleven keys (the eight originals plus
     `tool_name`, `tool_status`, `tool_args`);
   - the ok tool row has `"tool_name":"memo_search"`, `"tool_status":"ok"` and
     `"tool_args":{"query":"lighthouse"}`;
   - no response body anywhere contains the strings `tool_payload`, `call_id`, `call_1` or
     the payload's `content` value.

   This test replaces 021 `001` DoD-4's no-tool-keys assertion, which is amended in place
   with a chained suffix. (D3, U2)
4. `[test]` `GET /api/sessions/{id}/entries` messages also carry the eleven keys, with all
   three tool fields `null` on settled partner / turn / decision rows. Any existing 012
   assertion that pins a message to exactly eight keys is amended to the eleven keys with a
   chained suffix. Every other existing stream-router test passes unchanged. (D3)
5. `[test]` `PATCH /api/messages/{id}` on a zone assistant row answers the edited message with
   the eleven keys and all tool fields `null`. 021's refusal of a tool row
   (`message_not_editable`) is unchanged. (D3, 021 D8)
6. `[test]` `append_tool_message` (021 `001`) returns a `StreamMessage` whose `tool_status`
   and `tool_args` are derived from the payload it was given: `"ok"` and
   `{"query": "lighthouse"}` for the ok payload of `001.context.md`. (D3)
