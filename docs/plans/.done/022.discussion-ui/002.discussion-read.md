# Step 002 — The buried-group read: `buried_messages`, `list_discussion`, `GET …/discussion`

## Goal

Add the lazy, owner-scoped read of a settled entry's buried group (D1, U1). It needs a fourth
named selectable in the schema (D2), a service function in `services/messages.py`, and the
message-addressed route `GET /api/messages/{message_id}/discussion` with its response model.

## Source files

backend/app/db/schema.py
backend/app/services/messages.py
backend/app/models/stream.py
backend/app/routers/stream.py

## Test files

backend/tests/test_discussion_read.py
backend/tests/test_db_schema.py

`test_db_schema.py` is amended only where an existing assertion enumerates the module's
selectables, or the set of names that must not collide. New tests in that file follow the
existing selectable tests' style (`002.context.md`).

## Interface intent

**`app/db/schema.py`** (changed)

- **`buried_messages`**: a module-level Core selectable, defined beside `settled_entries`,
  `current_zone` and `message_states`. It returns **every** `messages` column for rows with
  `related_to IS NOT NULL`. It has no owner or session filter. Its name collides with no
  registry table. No table, column, index or constraint changes.

**`app/services/messages.py`** (changed)

- **`list_discussion`** (new).
  - Inputs: connection, user id, entry id.
  - Output: the list of `StreamMessage`s whose `related_to` is the entry id and whose
    `user_id` is the caller, ascending by id, each carrying `001`'s tool view.
  - It first confirms that the entry id names a **settled** row owned by the caller, read
    through `settled_entries`. If it does not (unknown, foreign, a zone row or a buried row),
    it raises **`MessageNotFoundError`** and reads nothing further. A confirmed entry with
    nothing buried returns an empty list.
  - Reads only. It goes through the named selectables only; no `select` names `messages`, so
    the S012_002_DoD13 guard stays green. It opens no write transaction.

**`app/models/stream.py`** (changed)

- **`DiscussionResponse`**: a single field `messages`, a list of `MessageResponse` (`001`'s
  eleven keys).

**`app/routers/stream.py`** (changed)

- **`GET /api/messages/{message_id}/discussion`** (new).
  - The path id is `SnowflakeIn`, and the route is authenticated like its siblings.
  - It calls `list_discussion` with the authenticated user's id and maps each message through
    the existing `_message_to_response`.
  - It answers 200 `DiscussionResponse`.
  - `MessageNotFoundError` reaches the existing error handler as 404 `message_not_found`.
  - The router does no SQL and imports no `app.db.schema`; the AST guard stays green.

## Definition of done

1. `[test]` `buried_messages` is a module-level Core selectable whose result columns are
   exactly `messages`' columns. Over a seeded table holding one zone row, one settled row and
   two rows buried under it, it returns exactly the two buried rows, text included. Its name
   is not a table name in the metadata. Existing schema tests pass. Any assertion that
   enumerated the selectables is amended with a chained suffix to include it. (D2)
2. `[test]` `list_discussion` on player A's settled turn with three buried rows
   `[user, tool, assistant]` (by id) returns those three, ascending by id, with role, text
   and `related_to` as stored. The tool row carries `001`'s derived `tool_status` /
   `tool_args`. (D1, US-040.AC-1)
3. `[test]` `list_discussion` on a settled partner row, and on a settled turn with nothing
   buried, returns an empty list. (D1)
4. `[test]` `list_discussion` raises `MessageNotFoundError` for each of the following, and in
   every case returns none of the rows buried under player A's entry:
   - an unknown id;
   - player B's settled entry, called as player A;
   - player A's entry, called as player B;
   - a zone row id;
   - a buried row id.

   (D1, R5)
5. `[test]` Rows buried under a **different** settled entry in the same session are not
   returned for this entry. (D1)
6. `[test]` `GET /api/messages/{entry_id}/discussion` as the owner answers 200
   `{"messages":[…]}`:
   - each message has `001`'s eleven keys;
   - ids are JSON strings;
   - order is ascending by id;
   - every message has `related_to` = the entry, which is checked on the seeded rows, because
     `related_to` is not a wire key.

   (D1, D3, US-040.AC-1)
7. `[test]` The route answers 404 with envelope code `message_not_found` for an unknown id, a
   foreign entry, a zone row id and a buried row id. It answers 200 `{"messages":[]}` for an
   owned settled partner block. It answers 401 unauthenticated. (D1, R5)
8. `[test]` Reading a discussion changes nothing. After the GET, every seeded row's
   `related_to`, `settled_at`, `text` and `updated_at` are unchanged. (R11)
9. `[manual/live]` With the app running, settling a zone of `[user, assistant]` and then
   calling the route for the new entry returns the user row as the one buried message.
   (US-039.AC-1, US-040.AC-1)
