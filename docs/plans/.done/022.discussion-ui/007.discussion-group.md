# Step 007 — The collapsed, read-only Discussion group under settled entries

## Goal

Add `DiscussionGroup` and mount it in every settled non-partner entry in `StreamRecord`. It is
collapsed by default and lazily loads its buried rows through `fetchDiscussion` on first
expand. It renders those rows read-only through `ZoneMessage` with editing off, with an
explicit empty line and an inline failure line (D11, D12, U1).

## Interface intent

**`app/DiscussionGroup.tsx`** (new)

- **`DiscussionGroup`**: a function component. Props:
  - the settled entry's id (string);
  - the `StreamState`, passed through to the row component.
- **Collapsed (initial).** It renders a header and no body, and makes **no request**. The
  header holds:
  - an `IconButton` chevron labelled **"Show discussion"**;
  - the text **"Discussion"**, or **"Discussion (N)"** once rows have loaded;
  - the marker **"Read-only"**.
- **First expand.** It calls `fetchDiscussion(id, signal)`, using its own `AbortController`
  that is aborted on unmount, and shows a Mantine `Loader` until the answer arrives. Then it
  renders exactly one of:
  - for a non-empty list, a list labelled **"Discussion messages"** with one
    `ZoneMessage` per row in served order, `editable` **false**;
  - for an empty list, the text **"No discussion behind this entry."**;
  - on any failure, the text **"The discussion could not be loaded."** It does **not** call
    `notifyFailure`.
- **While open**, the toggle is labelled **"Hide discussion"**. Collapsing hides the body.
- **Re-expanding:**
  - after a **success**, it shows the kept rows with no new request;
  - after a **failure**, it requests again (the failure is forgotten on collapse).
- The open flag, the load status and the rows are component-local `useState`. Nothing is
  written after unmount.

**`app/StreamRecord.tsx`** (changed)

- **`StreamEntry`** renders `DiscussionGroup` below the entry body for every entry whose kind
  is **not** `"partner"`, keyed by the entry id.
- The kind label, body, 014's action group and 013's re-open control are unchanged. Re-open
  presence keeps 013 D4's rule.

     "Discussion";
   - the partner entry carries none;
   - no `fetch` to any `/discussion` path has been made;
   - no "Discussion messages" list exists.

   (D11, US-039.AC-1, US-113.AC-2)
2. `[test]` Pressing "Show discussion" on the turn entry issues exactly one `GET
   /api/messages/<turn id>/discussion`.
   - It is answered with `[user "Write me a reply", tool "Found 2 memos." (memo_search, ok,
     {"query":"lighthouse"}), assistant "<think>plan</think>\n\nI wave back."]`.
   - A "Discussion messages" list then shows three items labelled "You", "Tool" and
     "Assistant", in that order, with their texts readable.
   - The header reads "Discussion (3)", and the toggle is "Hide discussion".

   (D11, US-040.AC-1)

   - there is **no** "Edit message" control on any item;
   - the assistant's thinking is collapsed ("Show thinking" present, `plan` absent);
   - the tool block is collapsed;

     arguments.

   (US-116.AC-1, US-114.AC-2, US-114.AC-3)

   shows the same three items, and **no** second GET is made. (D11)
5. `[test]` An expand answered `{"messages":[]}` shows "No discussion behind this entry.",

   - shows "The discussion could not be loaded.";
