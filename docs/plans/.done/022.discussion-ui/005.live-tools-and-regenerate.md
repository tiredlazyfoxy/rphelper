# Step 005 — Live tool calls, `regenerate`, and the non-tool zone derivations

## Goal

Extend `streamState.ts` with four things:

- **Live tool calls.** An observable list of live tool calls, fed by the compose run's
  `tool_*` frames and cleared together with the streaming text (D7, superseding 019 D18).
- **`regenerate`.** The textless-compose effect, sharing `composeMessage`'s run machinery
  (D8, U3).
- **`showsRegenerate`.** Its derivation.
- **The non-tool rule** for `canSettle` and the settle target (D9).

## Interface intent

**`app/streamState.ts`** (changed)

- **Live tool call** (new exported type; name final at skeleton). It holds:
  - call id (string);
  - tool name (string);
  - arguments (plain object);
  - status: `"running"`, `"ok"` or `"failed"`;
  - summary (string or null).
- **`StreamState`** gains one **observable** field, the live tool calls list, initially empty.
  019's non-observable compose handle stays the only non-observable field.
- **The compose run** (019 `005`'s `composeMessage` body).
  - Its frame handler now applies `context.md` D7's table to the live tool list, inside the
    same `runInAction` discipline: nothing is written after the mount signal aborts.
  - It empties the list when a run starts. It empties it **in the same action** that writes
    the terminal re-read result and clears the streaming text and handle.
  - Every other part of 019 D11–D16 is unchanged. The coder may factor the run into a private
    helper parameterised by "with text" vs "textless"; `composeMessage`'s observable behaviour
    must not change.
- **`showsRegenerate`** (new derivation). True iff all of the following hold:
  - not `isStreaming`;
  - not `busy`;
  - `zone` holds at least one row whose role is not `"tool"`.

  (D8)
- **`regenerate`** (new effect). Inputs: the state and the optional mount signal. It never
  rejects. It does nothing when `showsRegenerate` is false. Otherwise it runs the compose
  machinery with **no text**:
  - it calls `composeZone` without text, so the body is `{}` (021 `007`);
  - it sets the streaming text to `""` and the compose handle (019 D12), so `stopCompose` and
    019 D16's settle prefix apply to it unchanged;
  - it handles `token` and tool frames as above;
  - it applies 019 D14's outcome table, with notification, terminal zone re-read and clearing.

  It **never reads or writes `draft`**. If an `accepted` frame arrives, it only triggers 019
  D15's zone re-read. It never sets or clears `busy`, and never touches `entries` or
  `kindOverride`.
- **`canSettle`** (changed). It is true iff all of the following hold:
  - *my turn*;
  - not `busy`;
  - a zone row whose role is not `"tool"` exists, **or** the draft is non-blank.

  Streaming is still not consulted (019 D13). (D9)
- **The settle target** (013's `settleTargetText`, read by `settlePreviewOf`) (changed). With
  a blank draft, it is the text of the **last zone row whose role is not `"tool"`**. If there
  is none, it is the same "nothing to settle" value the derivation returns today for an empty
  zone. (D9, 021 D8)
- **`showsDiscard`**, `canSend`, `showsReopen` and `isStreaming` are unchanged.

## Definition of done

1. `[test]` A fresh `StreamState` has an empty live tool list. (D7)
2. `[test]` During a `composeMessage` with draft `"Find it"`, a body of `accepted`, then
   `tool_start{tool:"memo_search", call_id:"c1", args:{"query":"lighthouse"}}` (held open)
   gives the live list exactly one entry: `c1`, `memo_search`, `{"query":"lighthouse"}`,
   `running`, summary null. `zone` contains no row the server did not serve. (D7,
   US-114.AC-1)
3. `[test]` Continuing that body with `tool_result{tool:"memo_search", call_id:"c1",
   summary:"Found 2 memos."}` gives `c1` status `ok` and summary `Found 2 memos.`. A further
   `tool_start` for `c2`, then `tool_fail{call_id:"c2", code:"tool_failed"}`, gives `c2`
   status `failed` and summary `The tool failed.`. Order is `[c1, c2]`. A `tool_result` for
   unknown `c9` changes nothing. (D7)
4. `[test]` When that compose ends with `done`, the live list is empty in the **same** state
   where `zone` equals the final served list and the streaming text is `null`: no
   intermediate render sees the served tool rows and the live list together.
   `notifyFailure` is not called. (D7, 019 D14, US-114.AC-2)
5. `[test]` With a mid-body user stop (`stopCompose`) after a `tool_start`, the live list is
   emptied with the streaming text and `notifyFailure` is not called. With a mid-body
   **mount** abort, the list is not written after the abort. (D7, 019 D12, D14)
6. `[test]` `showsRegenerate` is true for each of these zones when not streaming and not
   busy:
   - `[user]`;
   - `[user, assistant]`;
   - `[user, tool, assistant]`.

   It is false for:
   - an empty zone;
   - a zone of `[tool]` only;
   - while streaming (streaming text `""`);
   - while `busy`.

   (D8, 021 D2 / D8)
7. `[test]` `regenerate` on session `s1` with zone `[user]` and draft `"half typed"`:
   - issues exactly one POST to `/api/sessions/s1/zone/compose` with body exactly `{}`;
   - sets `isStreaming` true before the body completes;
   - appends `token` text to the streaming text;
   - on `done`, re-reads the zone and clears the streaming text;
   - leaves the draft `"half typed"` throughout and afterwards.

   No request to `/zone/messages` is made. (D8, US-044.AC-3, R10)
8. `[test]` `regenerate` whose compose ends in an `error` frame `llm_unreachable` calls
   `notifyFailure` once with that code, re-reads the zone, leaves `entries` and the draft
   untouched, and clears the streaming text. A non-2xx 409 `zone_empty` answer calls
   `notifyFailure` with `zone_empty` and re-reads the zone. Afterwards, with a non-tool zone
   row, `showsRegenerate` is true again: the retry persists. (D8, D13, US-044.AC-2,
   US-044.AC-3, US-044.AC-4)
9. `[test]` `regenerate` is a no-op (no request) when the zone is empty, holds only tool rows,
   while streaming, or while busy. (D8)
10. `[test]` `stopCompose` during a `regenerate` aborts its request and ends with no
    notification and a zone re-read. `settleComposer` during a `regenerate` stops it first
    and then settles, in 019 D16's request order. (D8, 019 D16)
11. `[test]` `canSettle` on *my turn*, not busy, blank draft:
    - true for zone `[user]`;
    - true for `[user, tool]`;
    - **false** for `[tool]`.

    With draft `"x"` and zone `[tool]` it is true. (D9, US-135.AC-1)
12. `[test]` With a blank draft, the settle target over zone
    `[user "Mine", assistant "Theirs", tool "lookup"]` is `Theirs`, and the preview reads
    "Settles as a turn.". Over `[user "((ooc))", tool "lookup"]` the preview reads
    "Settles as a decision (out of character).". (D9, US-126.AC-1, 013 D1)
13. `[test]` 019's and 021's compose tests and 013's state tests pass unchanged, except any
    assertion amended per `005.context.md`. (019 D11–D16)
