# Step 004 — The collapsible thinking and tool blocks, and the assistant body

## Goal

Add the three presentational components every later step renders through:

- `ThinkingBlock`;
- `ToolBlock`;
- `AssistantBody`, which parses assistant text with `003`'s `splitThinking` and renders
  think segments as thinking blocks and answer segments through 013's painted `MessageBody`.

Each block starts open or collapsed on a single flag (D5).

## Interface intent

**`app/ThinkingBlock.tsx`** (new)

- **`ThinkingBlock`**: a plain function component.
- Props:
  - the think text (string);
  - whether the block **starts open** (boolean);
  - optionally, whether the thought is still unterminated. The component may show this
    subtly; it is not a test contract.
- It renders a header:
  - an `IconButton`, `IconChevronDown`, `sizeVariant "chevron"`, rotated `-90°` when
    collapsed, labelled **"Hide thinking"** when open and **"Show thinking"** when collapsed;
  - a decorative `IconBulb`;
  - the text **"Thinking"**.
- When open, it renders the think text verbatim as plain, pre-wrapped, dimmed text. There is
  no markdown and no `(( ))` painting.
- When collapsed, the text is **not rendered** (D5).
- The open flag is component-local state, initialised from the prop once. Pressing the toggle
  flips it.

**`app/ToolBlock.tsx`** (new)

- **`ToolBlock`**: a plain function component.
- Props:
  - the tool name (string, null or absent);
  - the status: `"running"`, `"ok"` or `"failed"`;
  - the arguments (a plain object);
  - the summary (string or null);
  - whether it **starts open**.
- It renders a header:
  - the chevron `IconButton` labelled **"Hide tool call"** / **"Show tool call"**;
  - a decorative `IconTool`;
  - the tool name, or **"Unknown tool"** when it is null or absent;
  - a status word: **"Running"**, **"Done"** (for `ok`) or **"Failed"**.
- When open, the body holds:
  - the label **"Arguments"**;
  - the arguments as `JSON.stringify(args, null, 2)` in a Mantine code block, or
    **"No arguments."** when the object has no keys;
  - then the summary as plain text, when non-null.
- When collapsed, the body is not rendered.
- The open flag is component-local, initialised once. A **status change while mounted** (a
  live call finishing) does not change the open flag.

**`app/AssistantBody.tsx`** (new)

- **`AssistantBody`**: a plain function component.
- Props: the assistant text and a **`live`** boolean.
- It renders `splitThinking(text)`'s segments in order:
  - each think segment as a `ThinkingBlock` starting open iff `live`;
  - each answer segment as `MessageBody` variant `"painted"`.
- Text with no think block renders exactly as `MessageBody` painted rendered it before this
  feature (D4 row 1: one untrimmed answer segment).
- It never parses or renders anything for non-assistant text. Callers only use it for
  `role: "assistant"`.

## Definition of done

1. `[test]` `ThinkingBlock` with text `plan` and **starts open = false**:
   - a button "Show thinking" and the text "Thinking" are present;
   - `plan` is **not** in the document.

   Pressing "Show thinking" shows `plan`, and the button is now "Hide thinking". Pressing it
   again removes `plan`. (US-114.AC-2, US-114.AC-3, D5)
2. `[test]` `ThinkingBlock` with **starts open = true** shows its text and a "Hide thinking"
   button on first render. (US-114.AC-1, D5)
3. `[test]` `ThinkingBlock` renders its text verbatim, with no markdown and no painting. Text
   `**bold** ((x))` appears as that literal string, with no `strong` element and no fragment
   chip. (D5)
4. `[test]` `ToolBlock` named `memo_search`, status `ok`, args `{"query":"lighthouse"}`,
   summary `Found 2 memos.`, starts open = false:
   - the header shows `memo_search` and `Done`, with a "Show tool call" button;
   - neither `"query": "lighthouse"` nor `Found 2 memos.` is in the document.

   After pressing it, the document shows "Arguments", the pretty-printed text containing
   `"query": "lighthouse"`, and `Found 2 memos.`. (US-114.AC-2, US-114.AC-3, D5)
5. `[test]` `ToolBlock` with starts open = true and status `running` shows "Running", the
   arguments and a "Hide tool call" button on first render. Re-rendered with status `ok` and
   a summary, it stays open, shows "Done" and shows the summary. (US-114.AC-1, D5, D7)
6. `[test]` `ToolBlock` with status `failed`, name null, args `{}` and summary
   `The tool failed.`, opened, shows "Failed", "Unknown tool", "No arguments." and
   `The tool failed.`. (D3, D7)
7. `[test]` `AssistantBody` with `live` false and text `<think>plan</think>\n\nHello` renders
   `Hello`, with "Show thinking" present and `plan` absent. With `live` true and the same
   text, `plan` and `Hello` are both visible, and "Hide thinking" is present.
   (US-114.AC-1, US-114.AC-2, D4 row 3)
8. `[test]` `AssistantBody` with text `<think>a</think>One<think>b</think> two` (`live` false)
   renders two "Show thinking" buttons and the answers `One` and `two`, in that document
   order. (D4 row 4)
9. `[test]` `AssistantBody` with text `<think>x\ny</think>\n((ooc))` renders the
   out-of-character card for `((ooc))`: 013's `data-paren="ooc"`, with "Out of character".
   (D4 row 8, 013 D5)
10. `[test]` `AssistantBody` with text `Hello` and with `a </think> b` renders no thinking
    toggle, and shows the text. (D4 rows 1, 7)
11. `[manual/live]` In a browser:
    - the chevron sits at the smallest size (14 / stroke 1.5);
    - it is rotated `-90°` when collapsed and points down when open;
    - `IconBulb` and `IconTool` render beside their labels.
