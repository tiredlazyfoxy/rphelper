# Step 005 — step-specific context

## Touch sites

The state module is built (013) plus pending (019 `004` / `005`, 021 `007`).

- **`StreamState`** (built) has these fields: `sessionId`, `entries`, `zone`, `status`,
  `draft`, `kindOverride` and `busy`. It uses `makeAutoObservable` with `autoBind`.
  - 019 `004` adds the streaming text (observable, `null` = not streaming) and the compose
    handle (annotation `false`).
  - This step adds the live tool list. It is observable by default, so it needs no
    annotation.
- **`composeMessage`** (019 `005`) handles frames in `runInAction`.
  - It treats `accepted` per 019 D15 and appends `token` text.
  - It currently **ignores** `tool_start` / `tool_result` / `tool_fail` (019 D18). This step
    makes it handle them.
  - It is a no-op when already streaming or when the draft is blank. That is why `regenerate`
    cannot simply call it: a regenerate has no draft by definition.
- **Frame shapes** (019 `003`):
  - `tool_start{tool, call_id, args}`, where `args` is the parsed object, or `{}` per 021 D6;
  - `tool_result{tool, call_id, summary}`;
  - `tool_fail{tool, call_id, code}`.

  `call_id` is an opaque string.
- **`composeZone(sessionId, text?, onFrame, signal)`** (019 `004`, 021 `007`): no text gives
  body `{}`. The exact parameter order is fixed in 019's skeleton record. Bind to it.
- **`settleTargetText` / `settlePreviewOf`** (013 `002`, D1) read "the last zone message"
  when the draft is blank. This step changes them to the last non-tool row. The preview
  strings are 013's ("Settles as a turn." etc.).

## Fixture rows

Zone rows are `Message` objects with `kind: null`, `settled_at: null` and string ids. A tool
row has `role: "tool"`, the text `lookup`, and optionally `tool_name: "memo_search"`,
`tool_status: "ok"` and `tool_args: {}`.

## Amendment rule for `streamState.test.ts`

If a 013 test seeds a zone whose rows include `role: "tool"` **and** asserts `canSettle` true,
or a settle target taken from a tool row, rewrite only that expectation per DoD-11 / DoD-12.
Keep its title and append ` — DoD-11 (022 005)` or ` — DoD-12 (022 005)`. If no such
assertion exists, the file is not touched.

## The atomic clear (DoD-4)

019 D14 already requires the streaming text and handle to be cleared in the same action as
the re-read result is written. The live list joins that same action. A test can observe this
with a MobX `reaction` or `autorun` that records every combination of
(`zone` contains a tool row, live list non-empty) seen during the run, and asserts that the
combination (true, true) never occurs after the terminal re-read starts.
