# Step 004 — step-specific context

Feature-wide facts are in `context.md` (**D1** what a difference is, **D2** the three
statuses, **D4** the two operations' postconditions, **D9** the two error codes **and the
whole route table**, **D5** what a Sync preserves). Only what is narrow to this step is
below.

## The route table

`context.md` D9 is the authority and is not restated here. Read it before writing a line of
this router; it also carries the decisions embedded in it — why each apply route answers
with the **re-derived** row, why `{table_name}` is validated in `db/sync.py` and not here,
why there are two routes rather than one `apply`, and why no route takes a body.

## Borrowed interfaces, by module path and role

- **`backend/app/dependencies.py`** (`004/002`) — `require_role(min_role)`, the dependency
  **factory**. Attached **once, to the router**, as `require_role(Role.admin)`, exactly as
  `005/003` and `006/005` attached it. No handler declares one of its own.
- **`backend/app/roles.py`** (`003/001`, `004/002`) — the `Role` enum.
- **`backend/app/routers/admin_users.py`** (`005/003`) and
  **`backend/app/routers/admin_llm.py`** (`006/005`) — the precedent this router copies:
  its own `APIRouter(prefix=…, tags=…)` with the whole path prefix on the router, the
  router-level guard, one service call per handler, a pydantic model out, no query
  parameters, no hand-mapped errors.
- **`backend/app/routers/health.py`** (`001`) — the precedent for **the router importing
  `metadata` from `app.db.schema` and passing it into the callee**. This router does the
  same; `db/drift.py` and `db/sync.py` import the registry nowhere.
- **`backend/app/db/engine.py`** (`001`) — `get_connection`, which opens **no** transaction.
  This router opens none either; `db/sync.py` owns the transaction boundary.
- **`backend/app/db/drift.py`** (steps `001`, `002`) — the report builder, called by the
  read route.
- **`backend/app/db/sync.py`** (step `003`) — the two apply operations, one per apply
  route, each already answering with the re-derived report row.

## What this router does **not** import

- **`backend/app/models/ids.py`** — this feature's wire carries no snowflake at all. The
  report is keyed on **table names**, so neither alias is used and there is no `int`/`str`
  id boundary to hold on this router. Stated because every other admin surface in the
  project is id-addressed and a reader will look for it.
- **`backend/app/config.py`'s `get_settings`** — no setting reaches these handlers. This
  feature adds none.
- **`backend/app/ids.py`** / `app.state.id_generator` — nothing is inserted.

## Status codes, gathered in one place

200 for all three routes · 404 `unknown_table` · 500 `schema_apply_failed` · 403
`insufficient_role` and 401 `not_authenticated` from the router-level guard, always in that
precedence. **No 201 and no 204**: neither apply route creates an addressable resource, and
both have something worth returning.

## Why the apply routes answer with a report row

US-018.AC-2 is "when the administrator views the drift report again, then it reflects the
corrected state". The frontend satisfies it by re-loading (step `006`), but a router test
should be able to witness it without a second call, and `db/sync.py` already re-derives the
row after committing. So the route answers with it. **This does not make the frontend
re-load optional** — `ui-conventions.md`'s never-optimistic rule still binds step `006`,
and DoD items exist on both sides.

## Gotchas

- **The handler must not check whether the table exists in the registry.** That is
  `db/sync.py`'s job and it raises `unknown_table`. A handler that looks it up first is a
  rule in a router, and it also duplicates the one place the raw name is made safe.
- **The handler must not branch on the table's status** to pick an operation. D4 made both
  operations total over every state precisely so the router has nothing to decide.
- **No `try` / `except` anywhere.** Both new codes reach the client through the handler
  `register_exception_handlers` already installed; `006/005` DoD-22 set the same bar.
- **One `include_router` line in `main.py` and nothing else.** The factory's ordering and
  the empty lifespan are frozen by `001` and asserted by DoD-16; the bare-name imports are
  patchable test seams — do not qualify them.
- **`TestClient(create_app())` is built locally and not as a context manager** (the
  lifespan is deliberately bypassed), with settings overridden through
  `app.dependency_overrides[get_settings]`. There is no shared `client` fixture.
- **A drifted state has to be manufactured for a test**, since `db/schema.py` is correct by
  construction. The way to do it is to create the schema and then hand-drift the file with
  raw DDL on the test connection — not by editing the registry, which this feature must
  not touch.
