# Step 002 — The pure comparison, the registry walk, and `/api/health`'s `"drift"` branch

## Goal

Turn two shapes into a per-table report with a pure function, walk `metadata.tables` to
produce the whole report, and widen `probe_health` so its coarse `schema` roll-up finally
reports `"drift"` — the value `models/health.py` has declared since feature `001` and
nothing has ever produced.

## Interface intent

**`backend/app/db/drift.py`** — the comparison and the walk, added beside step `001`'s
value types and readers. Still diagnosis only: no transaction, no DDL, no import of
`db/sync.py` and no import of `app.db.schema`.

- **A pure comparison function** — takes a **declared** shape and an **optional live**
  shape (absent meaning the table does not exist) plus the table's name, and returns the
  per-table report. It performs **no I/O whatsoever**, which is the property that makes it
  testable with no database at all. Its rules:
  - **missing columns** — declared names the live shape does not have;
  - **extra columns** — live names the registry no longer declares;
  - **changed columns** — a name on both sides whose normalised type text or NOT NULL flag
    differs, reported with both the expected and the actual shape;
  - **missing / extra indexes** — the same set difference over index shapes, compared by
    **(column list, uniqueness)**;
  - **status** — *missing* when the live shape is absent; *in sync* when every difference
    list is empty; *drifted* otherwise. Nothing else can produce a status
    (`context.md` D2).
- **A report builder** — takes a connection and a registry (`MetaData`), iterates
  **`metadata.tables` and nothing else** in **declaration order**, calls step `001`'s two
  readers per table, runs the comparison, and returns the whole-report value. Views and
  `vec0` / FTS5 virtual tables are **out of the report** and there is **no `kind`
  discriminator** (`context.md` D3). A table the live database has but the registry does
  not declare is **not reported either** — the registry is the source of truth and an
  unknown table is not drift the registry can describe.
- **A roll-up predicate pair** the health service consumes — whether the whole report
  contains any *missing* table and whether it contains any *drifted* one — so the coarse
  roll-up reads the report instead of re-implementing the precedence.

**`backend/app/services/health.py`** — **a widening of `probe_health`, not a rewrite of
it**, exactly as the module's own docstring says.

- `probe_health` keeps its parameters — the connection **and the registry as a parameter**;
  nothing is imported inside the service module and `routers/health.py` is **not edited**.
- Its `schema` computation replaces today's presence-only expression with the report's
  answer: **`missing`** when at least one declared table is absent, **`drift`** when every
  declared table is present and at least one differs, **`ok`** otherwise
  (`context.md` D10).
- The existing **`status` precedence is unchanged** — `schema != "ok"` → `"degraded"`,
  elif not configured → `"unconfigured"`, else `"ok"` — and so are `HealthProbeResult`'s
  fields and the response's shape. The roll-up is **one word and names no table**, which is
  what keeps the endpoint safe unauthenticated.
- The probe stays a **read**: it opens no transaction and writes nothing.

## Definition of done

1. `[test]` The report lists **one entry per registry table, in declaration order**, each
   carrying that table's status. (US-017.AC-1, UC-014)
2. `[test]` A table the registry declares and the database does not have is reported
   **missing**. (US-017.AC-1, UC-014)
3. `[test]` A table whose live shape matches its declaration exactly is reported **in
   sync**, including for a table whose only uniqueness is a `unique=True` column and which
   declares no explicit index. (US-017.AC-1, UC-014)
4. `[test]` A table missing a declared column, a table carrying a column the registry no
   longer declares, and a table whose column changed **type** or changed **nullability**
   are each reported **drifted**, with that column named in the right one of the missing /
   extra / changed lists and, for a changed column, with both the expected and the actual
   type and nullability. (US-017.AC-1, UC-014; `context.md` D1)
5. `[test]` A declared index absent from the live table and a live index the registry no
   longer declares each make the table **drifted** and land in the missing / extra index
   lists respectively; index identity is **(columns, uniqueness)**, so a name difference
   alone is not drift. (US-017.AC-1; `context.md` D1)
6. `[test]` A **server default**, a **`CHECK` constraint** and a **foreign-key clause**
   present in the live table but not in the declaration — or the reverse — leave the table
   **in sync**. These are deliberately outside the compared set and a `drifted` row for one
   of them is the defect. (`context.md` D1 — **no product id**)
7. `[test]` The comparison function performs **no I/O**: it is called with two shape values
   and no connection at all and returns a full report. (`backend-structure.md`, the
   drift/sync split — **no product id**)
8. `[test]` A table present in the live database that the registry does not declare
   appears **nowhere** in the report, and the walk visits `metadata.tables` only.
   (`context.md` D3 — **no product id**)
9. `[test]` No report entry carries a row count, a byte size or a timestamp, and building
   the whole report issues **no `COUNT(*)`**. (R5, UC-066)
10. `[test]` Building the report **writes nothing**: `sqlite_master` and every row are
    unchanged afterwards, and no transaction is opened. (`backend-structure.md`, "the code
    path that only reports cannot write" — **no product id**)
11. `[test]` `probe_health` reports `schema` as **`"missing"`** when a declared table is
    absent — unchanged from feature `001`'s behaviour for the same input. (`context.md`
    D10 — **no product id**)
12. `[test]` `probe_health` reports `schema` as **`"drift"`** when every declared table is
    present and at least one differs — the first time anything in the backend produces that
    value. (UC-014; `context.md` D10)
13. `[test]` `probe_health` reports `schema` as **`"ok"`** for a database created from the
    registry. (`context.md` D10 — **no product id**)
14. `[test]` **Missing outranks drift**: a database that is both short a table and drifted
    on another reports `"missing"`. (`context.md` D10 — **no product id**)
15. `[test]` The existing `status` precedence is unchanged — a non-`ok` `schema` yields
    `"degraded"` whatever `configured` says; an `ok` schema on an unconfigured instance
    yields `"unconfigured"`; otherwise `"ok"`. (FEAT-001; `context.md` D10)
16. `[test]` `GET /api/health`'s body **names no table, no column and no count** in any
    state, and the `schema` field is one of the three declared values. (UC-066, R5;
    `backend-structure.md`'s `/api/health`)
17. `[test]` `probe_health` still receives the registry **as a parameter** and
    `services/health.py` imports `app.db.schema` nowhere; `routers/health.py` is unchanged.
    (`backend-structure.md`, routers versus services; `context.md` D10 — **no product id**)
18. `[manual/live]` `db/drift.py` still imports neither `app.db.sync` nor `app.db.schema`,
    and `services/health.py` reaches `db/drift.py` and nothing else. Verifier confirms by
    reading both modules.
19. `[manual/live]` `mypy app`, `ruff check .` and `pytest` all pass from `backend/`.
