# Step 006 — The per-row Create and Sync actions, and the confirm a lossy Sync earns

## Goal

Fill the report table's trailing action column with UC-015's remediation — Create on a
missing row, Sync on a drifted one — re-loading the whole report after each, and routing a
Sync that would drop a column through the shared `ConfirmModal` naming those columns.

## Source files

```
frontend/src/admin/databasePageState.ts
frontend/src/admin/DatabasePage.tsx
```

## Test files

```
frontend/tests/admin/databaseActions.test.tsx
```

## Interface intent

**`frontend/src/admin/databasePageState.ts`** — two effects and one pure predicate added
beside step `005`'s store and load effect. The class gains at most one observable field —
a nullable "which table is currently being applied" name, so a row can show progress — and
still declares **no methods and no computed getters**.

- **A create effect** — takes the state and a table name, `POST`s the create route, and on
  success **re-loads the whole report** (`ui-conventions.md`: mutations are never
  optimistic; this is also how **US-018.AC-2** is satisfied). A failure lands in the page
  error field and clears the in-progress marker. `runInAction`s its writes, early-returns
  on an aborted signal.
- **A sync effect** — the same shape against the sync route. **It does not itself confirm
  anything**; the confirm is the component's, and the effect is what the confirm's
  callback invokes.
- **A pure "is this Sync lossy" predicate** over a row — true when the row lists **at
  least one extra column** (`context.md` D7). It is the single place that decision is
  made, so the confirm's trigger condition and its sentence cannot disagree.
- **A pure consequence-sentence helper** producing the confirm's one-sentence copy from a
  row: it names the **table** and the **columns that will be dropped**, and states that
  the data in every other column is preserved (`context.md` D5). It names **no count of
  rows** and nothing derived from content (R5).

**`frontend/src/admin/DatabasePage.tsx`** — the trailing `w={60}` column gains the row
menu, and the page gains the confirm.

- The action column holds **one** icon-only control — an `IconDots` trigger routed through
  `shared/IconButton` — opening a Mantine `Menu` whose items are **text-labelled**, never
  icons (`ui-conventions.md`'s icon boundary).
- **Menu items are conditional on the row's status, and absent rather than disabled**
  (the `IconArrowBackUp` / US-093.AC-2 precedent): **Create** on a **missing** row,
  **Sync** on a **drifted** row. An **in-sync** row has no action at all and therefore
  renders **no trigger** — an empty cell, not a menu with nothing in it.
- **Create is not confirmed** and fires its effect directly (`context.md` D4, D7).
- **Sync consults the lossy predicate.** Not lossy → fire the effect directly. Lossy →
  open `shared/ConfirmModal` with the consequence helper's sentence, a `Sync` confirm label
  and `color="red"`; confirming fires the effect, cancelling issues no request and leaves
  the row untouched. The modal's **open flag and its target row are component-local
  `useState`**, never store fields, and `ConfirmModal` is **reused as-is, never
  hand-rolled**.
- Row-level progress is shown from the store's in-progress name; failures render in the
  existing inline `Alert` above the table and **never** also as a notification. **No
  success toast** — success is the report re-loading and the row's badge turning green.

## Definition of done

1. `[test]` A **missing** row's menu offers **Create** and does not offer Sync; a
   **drifted** row's menu offers **Sync** and does not offer Create; an **in-sync** row
   renders **no action trigger at all**. Unavailable actions are **absent, not disabled**.
   (UC-015; `context.md` D4)
2. `[test]` Choosing **Create** posts to that row's create route **with no confirm and no
   intermediate dialog**, and issues exactly one request for the action.
   (US-018.AC-1, UC-015; `context.md` D7)
3. `[test]` After a successful Create the page **re-loads the whole report** and the row
   renders its corrected status — nothing is written into the store in anticipation.
   (US-018.AC-2; `ui-conventions.md`, mutations are never optimistic)
4. `[test]` Choosing **Sync** on a drifted row whose report lists **no extra column**
   posts to that row's sync route directly, with **no confirm**. (US-018.AC-1;
   `context.md` D7)
5. `[test]` Choosing **Sync** on a row that lists **at least one extra column** opens the
   shared confirm and issues **no** request; the dialog **names the table and every column
   that will be dropped**. (`context.md` D7 — **no product id**)
6. `[test]` **Cancelling that confirm issues no request and leaves the row exactly as it
   was**; **confirming issues the sync and then re-loads the whole report**, after which
   the row renders its corrected status. (US-018.AC-1, US-018.AC-2; `context.md` D7)
7. `[test]` The confirm is the **shared `ConfirmModal`**, not a hand-rolled dialog, and its
   open flag and target row are **component-local state** rather than fields on the page
   store. (`ui-conventions.md`'s confirm convention; `context.md` D13 — **no product id**)
8. `[test]` **The confirm's text names no count and nothing derived from another user's
   data**: the rendered dialog contains no digit-bearing claim about rows, sessions,
   characters, setups, messages, memos or users, and neither does any other string this
   page renders. (R5, UC-065, UC-066)
9. `[test]` The confirm's sentence states that the data in every **surviving** column is
   preserved, so what the administrator is agreeing to is the named columns and nothing
   wider. (`context.md` D5 — **no product id**)
10. `[test]` A failed Create and a failed Sync each render their message in the inline
    `Alert` above the table, clear the in-progress marker, leave the table usable, and
    **raise no notification**. (`ui-conventions.md`, errors and async feedback — **no
    product id**)
11. `[test]` A failed apply performs **no** local mutation of the row: the row still shows
    its pre-apply status until a successful re-load replaces it.
    (`ui-conventions.md`, mutations are never optimistic — **no product id**)
12. `[test]` **No success notification and no success toast is raised anywhere on this
    page**; success is the report refreshing. (`ui-conventions.md`, "A notification whose
    message is a success is a defect" — **no product id**)
13. `[test]` Row actions live in **one** overflow `Menu` behind a single `IconDots` trigger
    routed through `shared/IconButton`, in the trailing `w={60}` column, with
    **text-labelled** items — there is no second icon-only control in a row.
    (`ui-conventions.md`, tables and the icon boundary — **no product id**)
14. `[test]` The menu offers **no Rebuild index item, no Export item and no Import item**,
    enabled or disabled. (`brief.md`'s Scope Out — **no product id**)
15. `[test]` Both effects are free functions taking the state first, `runInAction` their
    writes, early-return on an aborted signal before writing, and the store still declares
    **no methods and no computed getters**; the lossy predicate and the consequence-
    sentence helper are **pure** and testable without a render. (`context.md` D13 — **no
    product id**)
16. `[test]` Unmounting mid-apply aborts the request and writes nothing into the store
    afterwards. (`context.md` D13 — **no product id**)
17. `[manual/live]` Signed in as an administrator against a running backend: Create on a
    hand-dropped table creates it and the row turns in sync; Sync on a hand-drifted table
    with an extra column shows the confirm naming that column, and on confirm rebuilds the
    table with the other columns' data intact.
18. `[manual/live]` `npm run typecheck`, `npm test` and `npm run build` all pass from
    `frontend/`.
