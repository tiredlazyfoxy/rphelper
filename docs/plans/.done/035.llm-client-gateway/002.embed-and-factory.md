# Step 002 — Gateway embed, and the kind-aware probe/embed factory

## Goal

This step adds `LlmGateway.embed`. It switches the probe/embed factory seam to
`(kind, base_url, api_key, timeout_seconds)`, with the gateway class as the
production factory, and wires `kind` into the probe, the designation and the
embedding use. Afterwards, every probe and embedding goes through the library.
The chat path is still on `client.py`.

## Interface intent

- **`LlmGateway.embed(model, texts)`** is async. It takes a model name and a
  sequence of texts, and returns one vector per text, in the texts' order. It
  raises `llm_unreachable` with the `detail.reason` that DEC-035-8 gives for
  embed. It is built on the library's `embed_batch`, using one library client
  built with that model.
- **`LlmClientFactory`** in `llm_registry.py` is now called
  `(kind, base_url, api_key, timeout_seconds)` (DEC-035-1). `LlmClientLike`
  keeps `probe()` and `embed(model, texts)`, and its import of the probe types
  moves to the gateway.
- **`probe_server`** reads the server's `kind` alongside `base_url` and
  `api_key_ref`, and passes `kind` first to the factory. Its behaviour is
  otherwise unchanged.
- **`designate_embedding_model`** does the same as `probe_server`.
- **`open_embedding_model`** (in `embedding.py`) passes the designated server's
  `kind` first.
- **`get_llm_client_factory`** returns the gateway class.
- **Every factory default** that named `LlmClient` in the listed modules names
  the gateway class instead. The parameter names and positions are unchanged.

## Definition of done

1. DoD-1 `[test]` — `embed(model, texts)` builds one library client with that
   model and calls `embed_batch` with the texts. It returns the library's vectors
   in order. (UC-013)
2. DoD-2 `[test]` — Failures map to `llm_unreachable` as follows:
   - an `LLMError` whose message contains `status 401` or `status 403` gives
     `detail` `{"reason": "auth_failed"}`;
   - an `LLMError` whose message starts with `Invalid response` gives
     `{"reason": EMBED_NO_VECTOR_REASON}` (`no_usable_vector`);
   - any other status, a transport message or an `Unreadable reply …` message
     gives `{"reason": "unreachable"}`.
3. DoD-3 `[test]` — For `kind` `'openai'` with no api key, embed raises
   `llm_unreachable` with reason `auth_failed` and calls no library method. An
   unrecognised `kind` raises `llm_unreachable` with reason `unreachable`.
4. DoD-4 `[test]` — Put a sentinel in a library error's message and its
   `description`. The sentinel appears in none of these: the raised error's
   message, its `detail`, or the log records of the call. The raised error has
   no `__cause__`, and its `__suppress_context__` is true.
5. DoD-5 `[test]` — Each `embed` call enters and exits exactly one library
   client, on success and on failure.
6. DoD-6 `[test]` — `probe_server` calls the injected factory with the server's
   `kind`, its `base_url`, the resolved key and the timeout, in that order. Its
   recorded outcomes and route postures are unchanged:
   - the test route answers 200 even for a failing outcome, and writes
     `last_test_*`;
   - the available-models route answers 502 `llm_unreachable` for an
     unreachable or auth-failed server.

   (UC-011, US-013)
7. DoD-7 `[test]` — `designate_embedding_model` calls the factory with the
   server's `kind` first, and measures the dimension as before. (UC-013, US-015)
8. DoD-8 `[test]` — `open_embedding_model` calls the factory with the designated
   server's `kind` first. Embedding writes and searches through the shared fakes
   behave as before, including the no-vector and wrong-length cases. (UC-013,
   US-112)
9. DoD-9 `[test]` — An `api_key_ref` naming an absent variable still raises
   `secret_ref_missing` before the factory is called. (UC-011)
10. DoD-10 `[test]` — `get_llm_client_factory()` returns the gateway class
    `LlmGateway`.
