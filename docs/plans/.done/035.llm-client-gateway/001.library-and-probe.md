# Step 001 — Library dependency, infrastructure, and the gateway's probe

## Goal

This step brings in `llm-client` 0.2.0 by changing:

- the dependency pin;
- the image build (adding `git`);
- the `aiohttp` log silencing;
- the 600 s timeout default.

It also creates `services/llm/gateway.py` with the re-homed probe value types,
the `kind`-selected library client and `probe()`. Nothing calls the gateway yet.

## Interface intent

- **The runtime dependency**: `llm-client` is pinned to the `v0.2.0` git tag in
  `backend/pyproject.toml`, and `backend/uv.lock` is refreshed
  (`DEC-arch-llm-client-library-1`). `httpx` stays.
- **`Dockerfile`**: the stage that runs `uv sync` installs `git`.
- **`Settings.llm_request_timeout_seconds`**: the default becomes 600.0, and the
  alias is unchanged (`DEC-arch-llm-client-library-2`).
- **`_SILENCED_LOGGERS`** in `app/logging.py` gains the `aiohttp` logger tree
  beside `httpx` (`DEC-arch-llm-client-library-10`).
- **`ProbeOutcome`, `ProbeResult` and `EMBED_NO_VECTOR_REASON`** are re-homed
  into `gateway.py` with identical names, members, values, fields and defaults.
  `client.py` imports them from the gateway instead of defining them
  (DEC-035-2).
- **`LlmGateway`**: a class constructed with `kind`, `base_url`, `api_key`
  (optional) and `timeout_seconds`, positionally in that order. It also takes the
  keyword-only `library_clients` seam (DEC-035-3). Construction builds no library
  client and performs no I/O.
- **`LlmGateway.probe()`**: async. It takes no arguments, returns a
  `ProbeResult`, and never raises (DEC-035-8, DEC-035-9,
  `DEC-arch-llm-client-library-3`, `-9`).
- **The base-URL normaliser**: it is internal to the gateway and observable
  only through the `base_url` handed to the library client (DEC-035-11).

## Definition of done

1. DoD-1 `[test]` — `Settings().llm_request_timeout_seconds` defaults to 600.0.
   `RPHELPER_LLM_REQUEST_TIMEOUT_SECONDS` still overrides it.
2. DoD-2 `[test]` — Records logged to the `aiohttp` logger, and to a child of it
   (for example `aiohttp.client`), reach neither the console sink nor the file
   sink. This is the same treatment `httpx` records get, which is unchanged.
3. DoD-3 `[test]` — `backend/pyproject.toml` declares the runtime dependency
   `llm-client @ git+https://github.com/Iezious/PythonLLMClient.git@v0.2.0` and
   still declares `httpx`. The root `Dockerfile` installs `git` in the stage that
   runs `uv sync`.
4. DoD-4 `[test]` — `kind` `'openai'` builds the `openai` entry of
   `library_clients`, and `kind` `'llamaswap'` builds the `llamaswap` entry. Each
   is built with:
   - the configured timeout as `timeout`;
   - the api key as `bearer_token`;
   - the normalised URL as `base_url`.
5. DoD-5 `[test]` — Base-URL normalisation: `http://h:1`, `http://h:1/`,
   `http://h:1/v1` and `http://h:1/v1/` all reach the library client as
   `http://h:1/v1`. `http://h:1/api` reaches it as `http://h:1/api/v1`.
6. DoD-6 `[test]` — A listing of names gives outcome `reachable`, with
   `model_names` equal to those names in the order the library returned them.
   (UC-011, US-013)
7. DoD-7 `[test]` — An empty listing gives `model_list_empty`. (UC-011, US-013)
8. DoD-8 `[test]` — An `LLMError` whose message contains `status 401` or
   `status 403` gives `auth_failed`. An `LLMError` with `status 500`, a transport
   message (`failed: timeout`, `failed: connection failure`) or an
   `Invalid response …` message gives `unreachable`. (UC-011, US-013)
9. DoD-9 `[test]` — For `kind` `'openai'` with no api key (`None` or `""`), probe
   gives `auth_failed` without calling `list_models`. For `kind` `'llamaswap'` with
   no api key, the library client is built with no bearer token, and the probe
   proceeds. (UC-011)
10. DoD-10 `[test]` — An unrecognised `kind` gives `unreachable`, and no library
    client is built.
11. DoD-11 `[test]` — `probe()` never raises: any exception out of the library
    client (including a non-`LLMError` one) gives `unreachable`. (UC-011)
12. DoD-12 `[test]` — Each `probe()` call enters and exits exactly one library
    client, on success and on failure.
13. DoD-13 `[test]` — Put a sentinel string in a library error's message and in
    its `description`. The sentinel must not appear in the returned
    `ProbeResult` (its `note` is `None` in every outcome), and must not appear in
    any log record emitted during the probe.
14. DoD-14 `[test]` — `ProbeOutcome` imported from `app.services.llm.gateway` and
    from `app.services.llm.client` is the same object, and its four values are
    unchanged.
15. DoD-15 `[manual/live]` — `uv sync` against the refreshed lock installs
    `llm-client` 0.2.0, and the container image builds with `git` present.
