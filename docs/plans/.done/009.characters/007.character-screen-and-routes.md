# Step 007 — The character screen and its two routes

## Goal

## Interface intent

**`app/CharacterScreen.tsx`** (new)

- **`CharacterScreen`**: `observer` component. Props: `characters` (the workspace
  `CharactersState`) and `characterId` (string, or `null` for new mode). Creates its
  `CharacterScreenState` once with `useState`. In existing mode it loads on mount with an
  `AbortController` aborted on unmount. Renders by mode and status:
  - **new mode**: a heading **"New character"**; a text input labelled **"Name"** bound to
    the draft name; `MarkdownEditor` labelled **"Persona"** bound to the draft sheet; a
    labelled button **"Create"** (`IconPlus` as its left section), disabled unless
    `canSubmit`. Pressing it runs `submitCreate` with an `onCreated` that navigates
    in-entry to `/characters/<id>` with `replace`. No Archive, no Sessions heading;
  - **existing, `"loading"`**: a centred Mantine `Loader`;
  - **existing, `"not-found"`**: the text **"Character not found"**, with no retry;
  - **existing, `"failed"`**: the text **"Could not load the character"** and a button
    **"Retry"** that re-runs the load;
  - **existing, `"ready"`**: a heading showing the **saved** name (`character.name`); an
    **"Archived"** badge beside it when archived; the "Name" input and "Persona" editor
    bound to the draft; a labelled **"Save"** button (`IconDeviceFloppy`), disabled unless
    `canSubmit`, running `submitSave`; a labelled **"Archive"** button (`IconArchive`)
    when working, or **"Restore"** (`IconArchiveOff`) when archived, running
    `submitArchive` / `submitRestore`; then a section headed **"Sessions"** with no
    content;
  - in both modes, while `submitStatus` is `"submitting"` the editor is `readOnly` and the
    action buttons are disabled. A non-null `error` renders in an inline `Alert` above the
    form. No notification is raised anywhere.
  - Every submit is `void`-ed from its click handler (the effects never reject).
- **`CharacterRoute`**: component. Props: `characters`. Reads the `:id` route parameter
  (a string, used verbatim) and renders `CharacterScreen` for it, **keyed by the id**, so
  moving between characters builds a fresh screen state.

**`app/App.tsx`** (edited; 008-owned file)

- Creates one `CharactersState` with `useState(() => new CharactersState())`.
- `/characters/new` renders `CharacterScreen` with that state and a `null` id.
- `/characters/:id` renders `CharacterRoute` with that state.
- Every other route, the shell around `<Routes>`, and the `*` "Page not found" are
  unchanged. Props (`user`, `storage`) are unchanged.

## Definition of done

1. `[test]` At `/characters/new`: a heading "New character", a textbox "Name", a textbox
   "Persona", and a button "Create" that is disabled. No "Archive" button and no
   "Sessions" heading are present. (D1)
2. `[test]` At `/characters/new`, typing a name enables "Create", and typing alone sends no
   request (no `fetch` call). (D1)
3. `[test]` At `/characters/new`, entering a name and persona then pressing "Create" POSTs
   `/api/characters` once with that name and sheet. On the 201 the router location
   becomes `/characters/<the response's id string>`, and no document navigation occurs.
   (US-020.AC-1)
4. `[test]` A failed Create shows "Could not create the character." in the screen, the
   location stays `/characters/new`, the typed name is still in the field, and no
   notification is shown. (D12)
5. `[test]` At `/characters/<id>`, while the GET is pending a loader is shown. On success
   the screen shows a heading with the character's name, the "Name" field holding it, the
   "Persona" editor holding its sheet, a disabled "Save", an "Archive" button, no
   "Archived" text, and a "Sessions" heading.
6. `[test]` Editing the name and the persona enables "Save". Pressing it PATCHes
   `/api/characters/<id>` with both `name` and `sheet`. After the response the heading
   shows the server's name and "Save" is disabled again. (US-021.AC-1)
7. `[test]` Pressing "Archive" POSTs `…/archive`. After the response the screen shows
   "Archived" and a "Restore" button, and no "Archive" button. Pressing "Restore" POSTs
   `…/restore`, and after the response "Archived" is gone and "Archive" is back.
   (US-086.AC-1, US-086.AC-2)
8. `[test]` Opening `/characters/<id>` for a character whose `archived_at` is set shows
   "Archived" and "Restore", and its name and persona remain editable. (D4, D9)
9. `[test]` A 404 `character_not_found` renders "Character not found" in the main region,
   with no "Retry" and no notification.
10. `[test]` A 500 or transport failure on load renders "Could not load the character"
    and "Retry". Pressing "Retry" requests the character again, and on success the
    character renders.
11. `[test]` A failed Save shows "Could not save the character." and the edited values stay
    in the fields.
12. `[test]` Navigating in-entry from `/characters/<a>` to `/characters/<b>` requests `b`
    and shows `b`'s name and persona, with nothing of `a`'s draft carried over.
13. `[test]` `App` (amending 008's route tests): at `/characters/new` the shell's
    "Workspace navigation" is present and the main region shows the "New character"
    screen. At `/characters/<id>` (with the GET stubbed) it shows that character. `/`,
    `/sessions/1`, `/settings` and `/search` still render an empty main region, and an
    undeclared path still renders "Page not found".
14. `[manual/live]` Against a running backend: create a character, give it a formatted
    persona with the toolbar, Save, reload `/characters/<id>`, and the persona shows the
    same formatting. Archive and Restore round-trip, and an archived character's URL opens.
