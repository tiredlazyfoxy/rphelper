# Step 005 — The shared markdown editor and its dependencies

## Goal

Add `shared/MarkdownEditor.tsx`, the one TipTap wrapper (`@mantine/tiptap` +
`tiptap-markdown`) with a plain label / markdown `value` / `onChange(markdown)` /
`readOnly` interface. Add the six npm dependencies it needs to `frontend/package.json`
and the lockfile (D3).

## Interface intent

**`shared/MarkdownEditor.tsx`** (new)

- **`MarkdownEditor`**: component. Props:
  - `label`: the accessible name of the editable surface;
  - `value`: the markdown the editor shows;
  - `onChange`: called with the editor's content **serialised as markdown** after each
    user edit;
  - `readOnly` (optional, default false).

  It:
  - renders Mantine's `RichTextEditor` over a TipTap editor configured with the starter
    kit, the link extension and the markdown extension, so `value` is parsed as markdown
    and the content serialises back to markdown;
  - gives the editable surface the textbox role, the `label` as its accessible name and
    multi-line semantics;
  - when editable, shows a small formatting toolbar (bold, italic, two heading levels,
    bullet list, ordered list, link / unlink). When `readOnly`, it shows **no toolbar**
    and the surface is not editable;
  - **never echoes**: `onChange` fires for user edits only. It does not fire on mount or
    when a new `value` arrives from the parent;
  - when the parent passes a `value` different from the editor's current markdown (a
    load or a save response), replaces the content with it;
  - reacts to `readOnly` changing after mount;
  - imports `@mantine/tiptap`'s stylesheet itself.

**`frontend/package.json`** / **`package-lock.json`**: adds `@mantine/tiptap`,
`@tiptap/react`, `@tiptap/pm`, `@tiptap/starter-kit`, `@tiptap/extension-link`,
`tiptap-markdown` to `dependencies` within the version constraints in `005.context.md`.
The lockfile is regenerated by `npm install`, never hand-edited.

## Definition of done

1. `[test]` Rendered with `label` "Persona", the component exposes a textbox whose
   accessible name is "Persona".
2. `[test]` Rendered with a `value` of a level-2 heading "Voice", a paragraph containing
   `**bold**` and a two-item bullet list, the editor shows a heading "Voice", a `strong`
   element "bold", and two list items.
3. `[test]` `onChange` is not called on mount, and it is not called when the component is
   re-rendered with a different `value`. After such a re-render the editor shows the new
   content (e.g. its new heading text), and the old content is gone.
4. `[test]` With `readOnly` true the component renders no button (no formatting toolbar),
   and the textbox is not editable (`contenteditable="false"`). With `readOnly` false it
   renders formatting buttons and the textbox is editable. Re-rendering from false to true
   removes the buttons.
5. `[test]` `frontend/package.json` lists all six packages under `dependencies`.
   `@mantine/tiptap`'s major version equals `@mantine/core`'s, and every `@tiptap/*`
   range is on major 2. No `.js` / `.mjs` / `.cjs` file is added under `frontend/` outside
   `node_modules/` and `dist/`.
6. `[manual/live]` In a browser, typing in the editor and using each toolbar control
   calls `onChange` with markdown (e.g. bold text arrives as `**text**`, a heading as `## …`).
   Text round-trips through save and reload unchanged in meaning.
7. `[manual/live]` `npm run build` succeeds with the new dependencies, and the editor's
   toolbar is styled (the stylesheet import took effect).
