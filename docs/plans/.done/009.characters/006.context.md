# Step 006 — step-specific context

Feature-wide facts are in `context.md`: **D1** (nothing persisted before Create), **D2**
(name + sheet saved together), **D9** (archived stays editable), **D11** (apply the
server's row), **D12** (inline errors, no notification), and the **No context, no
methods** / **Never optimistic** constraints. Only what is narrow to this step is below.

## Precedent

`src/admin/createUserDraft.ts`: a draft data class plus the free functions
`clientErrors` / `canSubmit` / `submitX(draft, …, onSaved, signal?)`. This module is the
same idea, widened to a page whose state is mostly its form. It is one module, not a
separate draft plus page store, because every field here belongs to the one screen
(`frontend-structure.md` "Where a store's file lives": one subject, one module). The
modal-draft rule "fresh instance per open" maps to "fresh instance per character id"
(`007` keys the component by id).

## Why the error is a fixed text per action

The screen renders `error` as given. A fixed sentence per action keeps the UI from
depending on the backend's `message` prose, and on a 422 (native FastAPI body, which the
shared client classifies as `client_malformed_error`) there is no useful prose anyway.
Client-side `canSubmit` already prevents the blank-name 422 in normal use. No field-level
`serverErrors` map is needed: there is one field that can fail validation, and the
client already guards it.

## Navigation is the caller's

`submitCreate` takes an `onCreated(id)` callback rather than a router function, so the
module stays React-free and testable with no router. `007` passes a callback that
performs the in-entry `replace` navigation (D1).

## Draft vs character after archive / restore

Archive and restore change only `archived_at` on the server. Replacing the draft with the
response would silently discard unsaved name/sheet edits, so only `character` is
replaced. `isDirty` then still reports the unsaved edits correctly against the new
`character`.

## Name sent as typed

The draft name is sent untrimmed. The request model strips it (`001`), and the response
carries the stored, stripped value, which `submitSave` / `submitCreate` adopt. `canSubmit`
trims only to decide whether the name is blank.
