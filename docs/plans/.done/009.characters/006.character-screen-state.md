# Step 006 — The character screen's state

## Goal

Add `app/characterScreenState.ts`: the character screen's data class (mode, load status,
the loaded character, the name/sheet draft, submit status, inline error) and its free
functions. Those are the load, the Create / Save / Archive / Restore submits (each
applying the server's row to the workspace characters state), and the pure dirty /
can-submit derivations (D1, D2, D9, D11, D12).

frontend/src/app/characterScreenState.ts

## Test files

## Interface intent

**`app/characterScreenState.ts`** (new)

- **`CharacterScreenState`**: data class, observable fields only, constructed from a
  `characterId` (string, or `null` for new mode):
  - `characterId`: as constructed;
  - `status`: `"loading"`, `"ready"`, `"not-found"` or `"failed"`. Starts `"ready"` in
    new mode and `"loading"` otherwise;
  - `character`: the last server-returned `Character`, or `null`;
  - `name`, `sheet`: the draft, both starting empty;
  - `submitStatus`: `"idle"` or `"submitting"`;
  - `error`: the inline failure text, or `null`.
- **`isNewCharacter`**: pure. True when `characterId` is null.
- **`isDirty`**: pure. True when a character is loaded and the draft `name` or `sheet`
  differs from it.
- **`canSubmit`**: pure. True when the trimmed draft name is non-empty, nothing is
  submitting, and either the mode is new or the draft is dirty.
- **`loadCharacter`**: effect. Takes the state and an optional signal, and fetches the
  character by `characterId`. On success it writes `character`, copies its `name` / `sheet`
  into the draft and sets `"ready"`. An `ApiError` with code `character_not_found` sets
  `"not-found"`, and any other failure sets `"failed"`. It sets `"loading"` first (so a
  retry shows loading), writes nothing once aborted, and never rejects.
- **`submitCreate`**: effect. Takes the state, the workspace `CharactersState`, an
  `onCreated` callback receiving the new id (string), and an optional signal. Clears
  `error` and sets `"submitting"`, then posts the draft's `name` and `sheet`. On success it
  applies the returned row to the workspace state and calls `onCreated` with its id. On
  failure it sets `error` to **"Could not create the character."**. Either way it returns
  to `"idle"`, and it never rejects.
- **`submitSave`**: effect. Takes the state, the workspace state and an optional signal.
  Clears `error`, then PATCHes `name` and `sheet`. On success it replaces `character`
  **and** the draft with the response's values and applies the row. On failure it sets
  **"Could not save the character."** and leaves the draft and `character` as they were.
- **`submitArchive`** / **`submitRestore`**: effects with the same inputs as `submitSave`.
  Each POSTs its action. On success it replaces `character` with the response and applies
  the row, but **leaves the draft untouched** (unsaved edits survive an archive). On
  failure it sets **"Could not archive the character."** / **"Could not restore the
  character."**.

## Definition of done

1. `[test]` A state constructed with `null` is in new mode, with status `"ready"`, no
   character, and an empty draft. `canSubmit` is false with an empty or whitespace-only
   name and true once the name has a non-space character. (D1)
2. `[test]` `submitCreate` POSTs `/api/characters` with the draft's `name` and `sheet`. On a
   201 it calls `onCreated` exactly once with the response's id string, the workspace
   `CharactersState` now contains that row, and `submitStatus` is back to `"idle"`.
   (US-020.AC-1, US-020.AC-2)
3. `[test]` `submitCreate` on a failure sets `error` to "Could not create the character.",
   does not call `onCreated`, leaves the workspace state unchanged, and resolves without
   throwing. (D12)
4. `[test]` `loadCharacter` on success sets `"ready"`, `character` to the response, and the
   draft `name` / `sheet` to the response's values. A 404 `character_not_found` sets
   `"not-found"`. A transport failure or a 500 envelope sets `"failed"`. With its signal
   aborted before the response settles it writes nothing.
5. `[test]` Right after a successful load, `isDirty` and `canSubmit` are false. Changing
   the draft `name` or `sheet` makes both true. A whitespace-only draft name makes
   `canSubmit` false. While `submitStatus` is `"submitting"`, `canSubmit` is false.
6. `[test]` `submitSave` PATCHes `/api/characters/<id>` with both `name` and `sheet`.
   Before the response arrives, `character` is still the previously loaded value (never
   optimistic). After it, `character` and the draft equal the response (e.g. a
   server-trimmed name replaces the typed one), `isDirty` is false, and the workspace
   state holds the updated row. (US-021.AC-1)
7. `[test]` `submitSave` on a failure sets `error` to "Could not save the character.",
   keeps the edited draft, and keeps `character` unchanged.
8. `[test]` `submitArchive` POSTs `/api/characters/<id>/archive`. After it, `character`'s
   `archived_at` is the response's, the draft's unsaved edits are unchanged, and the
   workspace state no longer lists the row (its `showArchived` being false).
   (US-086.AC-1)
9. `[test]` `submitRestore` POSTs `/api/characters/<id>/restore`. After it, `character`'s
   `archived_at` is null and the workspace state lists the row. (US-086.AC-2)
10. `[test]` `submitArchive` / `submitRestore` failures set "Could not archive the
    character." / "Could not restore the character." and leave `character` unchanged.
11. `[test]` A submit that starts after a failure clears the previous `error` before its
    request.
