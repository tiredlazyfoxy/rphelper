# Step 003 — The `/api/characters` router

## Goal

Add `routers/characters.py`, the six routes of the wire contract behind a router-level
`require_user` (D6, D7). Each route converts the service's `Character` into the response
models, and no delete route exists. Register the router in `main.py` after the existing
routers.

## Interface intent

**`routers/characters.py`** (new)

- **`router`**: an `APIRouter` with prefix `/api/characters` and `require_user` as a
  router-level dependency.
- **List handler**: `GET ""`. Takes the boolean query parameter `include_archived`
  (default false), the current user and the connection. Calls `list_characters` and
  answers a `CharacterListResponse`.
- **Create handler**: `POST ""`, status 201. Takes a `CreateCharacterRequest`, the current
  user, the connection and the id generator. Calls `create_character` and answers a
  `CharacterResponse`.
- **Get handler**: `GET "/{character_id}"`. The path id is declared with the inbound
  snowflake alias. Calls `get_character`, answers a `CharacterResponse`.
- **Update handler**: `PATCH "/{character_id}"`. Takes an `UpdateCharacterRequest`. Calls
  `update_character` with the supplied fields (`None` for unsupplied), answers a
  `CharacterResponse`.
- **Archive handler**: `POST "/{character_id}/archive"`. **Restore handler**:
  `POST "/{character_id}/restore"`. Each calls its service operation and answers a
  `CharacterResponse` with status 200.
- A private conversion from the service's `Character` to `CharacterResponse`.
- `CharacterNotFoundError` propagates to the already-registered domain handler (404). The
  router catches nothing.
- **No `DELETE` handler.**

**`main.py`** (extended)

- Includes the characters router after the routers already registered.

## Definition of done

1. `[test]` With no session cookie, each of the six routes answers 401 with code
   `not_authenticated`.
2. `[test]` A signed-in roleplayer's `POST /api/characters` with `{ "name": "Aria",
   "sheet": "# Aria" }` answers 201 with `name` "Aria", `sheet` "# Aria", `archived_at`
   null, both timestamps present, and `id` a JSON **string** of decimal digits. A
   following `GET /api/characters` contains a row with that id. (US-020.AC-1, US-020.AC-2)
3. `[test]` `POST /api/characters` with `name` `""`, `"   "` or no `name` answers 422, and
   the user's listing is unchanged afterwards. A `name` of `"  Aria "` is stored and
   answered as `"Aria"`. (D8)
4. `[test]` With users A and B each having created characters, A's `GET /api/characters`
   (with and without `include_archived=true`) contains only A's characters and B's
   contains only B's. (US-022.AC-1, R5)
5. `[test]` As user B, `GET`, `PATCH`, `POST …/archive` and `POST …/restore` on A's
   character id each answer 404 with code `character_not_found` and an empty `detail`. A's
   character is unchanged when read back as A. The response body for B's request equals
   the body for an id that exists for nobody. (R5, D8)
6. `[test]` `PATCH /api/characters/{id}` with `{ "name": "Bo" }`, then with
   `{ "sheet": "new body" }`, each answers the updated character. A following
   `GET /api/characters/{id}` returns name "Bo" and sheet "new body". (US-021.AC-1, D7)
7. `[test]` `POST /api/characters/{id}/archive` answers 200 with `archived_at` a string.
   The default `GET /api/characters` then omits the character,
   `GET /api/characters?include_archived=true` includes it, and
   `GET /api/characters/{id}` still answers 200 with it. (US-086.AC-1, US-086.AC-3, R6)
8. `[test]` `POST /api/characters/{id}/restore` on that archived character answers 200
   with `archived_at` null, and the default listing contains it again. (US-086.AC-2)
9. `[test]` `DELETE /api/characters/{id}` and `DELETE /api/characters` answer 405, and the
   character is still returned by `GET /api/characters/{id}` afterwards. (R6, US-086.AC-3)
10. `[test]` Archiving an already-archived character answers 200 with the same
    `archived_at` as the first archive. (D9)
11. `[test]` A signed-in **administrator** can create a character and sees it, and only
    its own characters, in its listing. (D6)
12. `[test]` A non-numeric path id (e.g. `/api/characters/abc`) answers 422.
13. `[test]` A create or patch body carrying `user_id` (another user's id) or
    `archived_at` is accepted with those keys ignored: the character belongs to the
    caller, and a PATCH does not archive it. (D8)
14. `[manual/live]` Against a running dev backend whose database pre-dates 009: after the
    administrator presses Create for `characters` on the Database page, `curl`-ing the
    list with a roleplayer's cookie answers `{ "characters": [] }`.
