# Step 001 — Settled rows become editable through the existing `PATCH`

## Goal

Widen 012's `edit_message_text` so a settled row of any kind is edited (text verbatim,
`kind` / `settled_at` untouched, session bumped) and read back through `settled_entries`,
while a buried row stays `message_not_editable` (D1, D2); amend 012's service and router
tests that pinned the interim settled-row refusal. Below the 50-line floor on purpose: it is
the feature's only backend change (D11).

## Source files

backend/app/services/messages.py

## Test files

backend/tests/test_messages_service.py
backend/tests/test_stream_router.py

## Interface intent

**`services/messages.py`** (edited — 012 `002`)

- **`edit_message_text`** — same inputs (connection, owner's `user_id`, message id, new
  text), same return (`StreamMessage`), same errors. Behaviour in its one write
  transaction:
  - classify the target through `message_states`, owner-scoped by id: no row →
    `MessageNotFoundError`; buried (`related_to` set) → `MessageNotEditableError`;
    **settled (`settled_at` set) → proceed**; zone → proceed (unchanged);
  - update that row's `text` (verbatim — no trimming, no `(( ))` parsing) and
    `updated_at`; never write `kind`, `settled_at` or `related_to`;
  - bump the row's session (`last_used_at` and `updated_at`, the same instant);
  - read the row back through the selectable matching the classified state —
    `current_zone` for a zone row, `settled_entries` for a settled row — narrowed by id
    and `user_id`, and return it.
- Nothing else in the module changes. No router, model, schema or error change: the
  `PATCH` route already calls this function and converts its value.

## Definition of done

1. `[test]` A raw-seeded settled `turn` whose `created_at` / `settled_at` / `updated_at`
   are weeks old (e.g. `2026-08-01T…`) is edited to `"Fixed the typo."`: the returned
   value has that text, `kind` `'turn'`, `settled_at` and `created_at` equal to the seeded
   values, and `updated_at` strictly later than the seeded one; the stored row's
   `related_to` is NULL; `list_entries` holds the new text at the same position and
   `list_zone` does not contain the row. (US-032.AC-1, US-110.AC-1, D1)
2. `[test]` A partner block filed through `file_partner_entry` is edited to
   `"She waves. ((ooc: brb))"`: stored and returned byte-for-byte, `kind` `'partner'`
   unchanged. (US-109.AC-1, US-121.AC-2, R12)
3. `[test]` Literal edits keep the kind: a settled `decision` (raw-seeded `"((x))"`)
   edited to `"plain words"` stays `'decision'`; a settled `turn` edited to
   `"((whole thing))"` stays `'turn'` with that text verbatim; `settled_at` is unchanged
   in both. (R12, D1)
4. `[test]` Bump: after a settled edit the session's `last_used_at` and `updated_at` both
   equal the edited row's returned `updated_at`. (D2, 012 D3)
5. `[test]` (amends 012 `002` DoD-9) A raw-seeded **buried** row still raises
   `MessageNotEditableError`, its text and `updated_at` unchanged and the session not
   bumped; the former settled-row refusal cases (a filed partner block, a raw-seeded
   settled turn) are removed from that test, now covered by DoD-1 / DoD-2. (US-116.AC-1)
6. `[test]` Another user's settled row raises `MessageNotFoundError`, the same as an id
   that exists for nobody; the row and that user's session are unchanged. (R5)
7. `[test]` On an archived session (raw `archived_at` set) a settled edit succeeds and the
   session stays archived. (R6)
8. `[test]` 012's source check of `app/services/messages.py` (012 `002` DoD-13) still
   passes, extended: no `update(...)` statement in the module assigns `kind`,
   `settled_at` or `related_to`. (D1, 012 D16)
9. `[test]` Router: on a session created through 011's routes, append and settle a message
   (a `turn`), read its `settled_at` from `GET …/entries`, then `PATCH
   /api/messages/<entry id>` with `{"text": "Edited turn."}` answers 200 with that exact
   text, `kind` `"turn"` and the same `settled_at`; `GET …/entries` shows the new text at
   the same position and `GET …/zone` is unchanged. (US-110.AC-1, US-032.AC-1)
10. `[test]` Router (amends 012 `004` DoD-13): `PATCH` on a filed partner block answers
    200 with `kind` `"partner"`; on a settled decision (append `"((skip ahead))"`, settle)
    with `{"text": "Skip to morning."}` answers 200 with `kind` `"decision"`; on a
    **buried** message it still answers 409 `message_not_editable` with the text
    unchanged. The zone-message case of 012 DoD-13 is unchanged. (US-109.AC-1,
    US-110.AC-1, US-116.AC-1)
11. `[test]` Router: `PATCH` on a settled entry with text `""`, `"   "` or missing answers
    422 and the entry is unchanged; a text of 500 000 characters answers 200. (012 D9,
    R10)
12. `[test]` Router: after a settled `PATCH`, `GET /api/sessions/<id>` shows `last_used_at`
    not earlier than before; a refused (buried) `PATCH` leaves it unchanged. As user B,
    `PATCH` on A's settled entry answers 404 `message_not_found`. (D2, R5)
13. `[manual/live]` Against a running dev backend with 012 delivered: `curl -X PATCH` a
    settled entry's text with a roleplayer's cookie; `GET …/entries` returns the new text
    with the kind unchanged.
