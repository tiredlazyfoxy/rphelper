## Re-reads per outcome

| `editEntry` outcome | Writes | Re-reads |
|---|---|---|
| blank / unchanged | nothing | none |
| success, served row settled | that one row in `entries` | none |
| success, served row not settled | — | entries (via `applyEntries`) + zone |
| failure | — | entries (via `applyEntries`) |

The "replace one row" write may go straight to `entries` or through `applyEntries` with
the patched list — either keeps `kindOverride` because the id sequence does not change
(DoD-5 pins the outcome, not the route).

## Why copy lives in its own module

Copy reads no state and writes none (UC-030 postcondition), so it is not a
`StreamState` effect; and it touches `navigator` / `document`, so it cannot live in the
pure `plainText.ts`. `copyOut.ts` is the one place in `src/` that touches the clipboard.

## The fallback, concretely (D9)

A `textarea` created for the call, `value` = the plain text, `readOnly`, positioned off
screen with inline style (e.g. `position: fixed`, far negative `top`/`left`) — inline
style on a transient element is not a stylesheet and does not touch
`tests/stylesheets.test.ts`. Remember `document.activeElement` first; append to
`document.body`; `select()`; `execCommand("copy")`; in a `finally`, remove the element and
re-focus the remembered element if it is still in the document. jsdom does not implement
`execCommand`; tests stub it.
