# Step 001 — `translations` table, `TranslationFailedError`, response model, edit invalidation

## Goal

Add the `translations` table (D7), the `translation_failed` error class (D5), the
translate route's response model, and the server-side discard of a message's cached
translations inside `edit_message_text`'s transaction (D11, US-111.AC-1).

## Interface intent

**`app/db/schema.py`** (changed)

- **`translations`**: a table on the one `metadata` with D7's columns, FKs and named unique
  constraint. The `message_id` FK has no `ondelete`. There is no `updated_at` and no state
  column.

**`app/errors.py`** (changed)

- **`TranslationFailedError`**: a `DomainError` subclass with class-level `code`
  `"translation_failed"` and `http_status` 502. Its constructor takes the message id (int)
  and an optional message. It sets `detail` to `{"message_id": <the id as a decimal
  string>}` and uses a fixed default message when none is given.

**`app/models/translation.py`** (new)

- **`TranslationResponse`**: a pydantic response model with `message_id` (`SnowflakeOut`,
  so a decimal string on the wire), `target_language` (string), `text` (string) and
  `cached` (boolean). It can be built from attributes. It imports neither routers nor
  services.

**`app/services/messages.py`** (changed)

- **`edit_message_text`**: after its `messages` update, inside the same transaction, it
  deletes every `translations` row whose `message_id` is the edited id. The signature and
  return value are unchanged, and so is every refusal path: a refused edit deletes nothing.
- The module docstring's "no delete" statement is amended to say that the one delete is the
  edited message's cached translations.

## Definition of done

1. `[test]` After `create_all`, `translations` has exactly the columns `id`, `user_id`,
   `message_id`, `target_language`, `text`, `created_at`, all NOT NULL. `user_id`
   references `users.id`. `message_id` references `messages.id` with no `ON DELETE`
   action. A unique constraint named `uq_translations_message_id_target_language` covers
   `(message_id, target_language)`. (D7)
2. `[test]` Inserting two rows with the same `message_id` and `target_language` raises an
   integrity error. The same `message_id` with two different target languages is accepted.
   (D7, UC-041)
3. `[test]` The table-set constants and assertions that pin the full table list include
   `translations`, and every other existing assertion in the three amended files still
   passes. (D7)
4. `[test]` `TranslationFailedError(7250000000000000101)` has `code` `"translation_failed"`,
   `http_status` 502, `detail` `{"message_id": "7250000000000000101"}` (a string), and a
   non-empty default message. A given message replaces the default. It is a `DomainError`.
   (D5, US-048.AC-1)
5. `[test]` `TranslationResponse` built from an object with `message_id`
   7250000000000000101, `target_language` "Russian", `text` "Привет", `cached` true
   serialises to exactly
   `{"message_id":"7250000000000000101","target_language":"Russian","text":"Привет","cached":true}`.
   (wire contract)
6. `[test]` A settled partner row with two cached `translations` rows (two languages) is
   edited through `edit_message_text`. Afterwards both rows are gone. A `translations` row
   belonging to a **different** message is untouched. (US-111.AC-1, D11)
7. `[test]` Edits that are refused delete nothing: a buried row (`message_not_editable`)
   and another user's row (`message_not_found`), each with a raw-inserted `translations`
   row, keep that row. (D11, R5)
8. `[test]` Atomicity: a SQLite `BEFORE DELETE` trigger on `translations` that raises
   (`SELECT RAISE(ABORT, …)`) makes the edit of a partner row with a cached translation
   fail. Afterwards the message text is unchanged and the cached row is still present.
   (D11)
9. `[test]` Editing a settled turn row and a zone row (neither with cached rows) still
   succeeds and returns the edited row as before this step. (D11, 014 D1)
