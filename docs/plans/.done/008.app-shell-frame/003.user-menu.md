# Step 003 — The user menu and logout

## Goal

Add the user menu that sits at the foot of the left column — an upward-opening Mantine
`Menu` whose trigger shows avatar plus username (or the avatar alone on the rail) — with
Settings, the administrator-only real `<a href="/admin">`, and Log out, plus the logout
effect that posts, then navigates to `/login`, or notifies and stays on failure (D6, D7).

## Interface intent

**`app/logout.ts`** (new)

- **`logOut`** — effect; takes an optional `AbortSignal`; resolves to nothing. Calls
  `apiPost` on `/api/auth/logout` with no body; on success calls
  `documentNavigation.assign("/login")`. On any thrown failure it calls
  `notifyFailure(error)` and does **not** navigate; it never rethrows (it is invoked from a
  click handler). An abort neither navigates nor notifies.

**`app/UserMenu.tsx`** (new)

- **`UserMenu`** — component; props: the signed-in `user` (`CurrentUser` from
  `shared/currentUser.ts`) and `compact` (boolean — true on the rail). Renders:
  - a **trigger** button whose accessible name is **"User menu"** in both modes; expanded,
    it shows an avatar derived from the username (its initial) and the username as text;
    compact, the avatar only;
  - a Mantine `Menu` with a `top-*` position (opens upward), whose dropdown holds, in order:
    - **"Settings"** with `IconSettings` — an in-entry router navigation to `/settings`;
    - **"Admin area"** with `IconShield` — rendered **only** when `user.role === "admin"`, as
      a real anchor with `href="/admin"` (a `Menu.Item` rendered as `a`), never a router
      `Link` and with no click handler of its own;
    - **"Log out"** with `IconLogout` — invokes `logOut`, `void`-ed.
  Holds no MobX state; the menu's open flag is Mantine's own.

## Definition of done

1. `[test]` Opening the user menu (clicking the "User menu" trigger) shows the items
   "Settings" and "Log out" for a roleplayer and for an administrator. (UC-071)
2. `[test]` For a user with role `admin`, the open menu shows an "Admin area" item.
   (US-093.AC-1)
3. `[test]` For a user with role `roleplayer`, the open menu shows **no** "Admin area" item —
   absent from the document, not disabled — and the rendered output contains no element
   with `href="/admin"`. (US-093.AC-2)
4. `[test]` The "Admin area" item is an anchor element with `href` exactly `/admin`, and
   activating it does not change the in-entry router's location (it is not a router link).
   (US-093.AC-1)
5. `[test]` Choosing "Settings" changes the in-entry router location to `/settings` and
   performs no document navigation. (UC-071)
6. `[test]` Choosing "Log out" posts to `/api/auth/logout` and, on a 204, calls
   `documentNavigation.assign` with exactly `/login`. (US-091.AC-1)
7. `[test]` `logOut` on a transport failure and on a well-formed 5xx envelope calls
   `notifyFailure` with the thrown error, performs no document navigation, and resolves
   without throwing. (US-091.AC-1)
8. `[test]` `logOut` with an already-aborted signal neither navigates nor notifies.
9. `[test]` Expanded (`compact` false) the trigger shows the username as visible text;
   compact it does not show the username text, and the trigger is still found by the
   accessible name "User menu" and still opens the same menu. (US-090.AC-1)
10. `[manual/live]` The menu opens upward from the bottom-left of the left column in both
    expanded and rail states.
11. `[manual/live]` Middle-clicking "Admin area" opens `/admin` in a new tab with the session
    intact; a normal click loads the admin document.
12. `[manual/live]` Against a running backend, "Log out" lands on the sign-in form and a
    subsequent visit to `/` is redirected to `/login`.
