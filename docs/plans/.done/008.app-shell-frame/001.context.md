# Step 001 — step-specific context

Feature-wide facts are in `context.md` (**D1** the identity move, **D8** the record's
rules, "Built state" for `shared/api.ts` and `admin/adminAccess.ts`). Only what is narrow
to this step is below.

## The admin gate as built (harvested)

- `admin/adminAccess.ts` today exports: the `CurrentUser` type; `resolveAdminAccess`
  (pure, takes a current user or null); `classifyAdminAccessError` (returns
  `"not-ready"` or `"failed"`); `enforceAdminAccess` (optional signal; calls
  `apiGet<CurrentUser>("/api/me")`, never re-navigates on 401, navigates to `/` when the
  user is not an admin); `ADMIN_ACCESS_RETRY_INTERVAL_MS = 2000`.
- `admin/main.tsx` runs the retry loop and renders `AdminApp` / `AdminNotReady`; it is **not**
  in this step's scope and must not need editing — that is why the type is re-exported.
- Existing tests: `tests/admin/adminAccess.test.ts`, `AdminNotReady.test.tsx` and others
  under `tests/admin/`. They stub `fetch` globally, so moving the `apiGet` call into
  `fetchCurrentUser` is invisible to them. The test-coder may **add** DoD-3 clauses to
  `adminAccess.test.ts`; existing clauses are not deleted or loosened.

## The entry-isolation scan (DoD-4)

`tests/ids-are-strings.test.ts` and `tests/conventions.test.ts` are the precedent: a test
under `frontend/tests` reading every `.ts` / `.tsx` file beneath a `frontend/src` subfolder
and failing with the file path. `src/app/` holds `main.tsx` and `index.html` today and gains
`workspaceLayout.ts` in this step; later steps' files fall under the same scan automatically.
The import forms to catch are relative paths reaching `admin/` (e.g. `../admin/…`).

## Gotchas

- **`JSON.parse("null")` is `null`, and `typeof null === "object"`.** DoD-6 lists `null` on
  purpose; an array is also `typeof "object"`.
- **A stored `"true"` string is not a boolean.** Wrong type → that field's default.
- **The fresh read inside a write uses the same storage** it is about to write to — never a
  cached value — so a write of one field cannot clobber the other.
- **`localStorage` is not referenced in this module at all**, not even in a type position
  that would pull DOM lib typing into the reasoning; the `LayoutStorage` interface is the
  module's own. The caller (step `002`) supplies the real storage.
