**D5** the routes, **D10** the collapse glyph, **D11** overlay dismissal; the **Vocabulary**

  `shellClassName`, `expandTree`, `collapseTree`, `closeOverlay`, `NARROW_VIEWPORT_QUERY`.

  navigation; `Routes` / `Route` in `App`.

## Testing narrow width

`tests/setup.ts` polyfills `window.matchMedia`; the polyfill reports no match by default
(expected — the test-coder confirms). Narrow tests replace `window.matchMedia` with a stub
that reports `matches: true` for exactly `"(width < 820px)"`. jsdom does not apply
`shell.css` — the tests assert **classes and rendered content**, never computed widths;
widths are `[manual/live]`.

## Testing the record

Tests pass a fake `LayoutStorage` (a small in-memory object with spy-able `getItem` /
`setItem`) rather than jsdom's `localStorage`, so "no write happened" is assertable
(DoD-6, DoD-7). `WorkspaceShell` never reaches for `window.localStorage` itself — the
storage arrives as a prop (`005` supplies `browserLayoutStorage()`).

## Route notes

- `useParams()` values are strings and are not read in 008 at all — the centre columns are
  empty. Nothing here parses an id.
- `App` is rendered inside a router by its caller (`005`'s `main.tsx` uses `BrowserRouter`;
  tests use `MemoryRouter` with `initialEntries`). `App` must not create a router.
- The empty route element may be `null` or an empty fragment — "no text content" is the
  contract (DoD-10), not a particular element.

## What the expanded column does not carry

No search, no new-character and no tree rows in the expanded column: those are the tree's
header and body, `011`'s and `029`'s. The expanded column in 008 is the collapse control,
an empty body and the user menu. It will look sparse; that is the brief's "empty frame".
