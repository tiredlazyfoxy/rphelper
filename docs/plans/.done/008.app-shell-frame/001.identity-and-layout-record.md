# Step 001 — Shared identity and the persisted layout record

## Goal

Move the `CurrentUser` type and the `/api/me` fetch into `shared/currentUser.ts` and
re-point the admin gate at it with no behaviour change (D1), and add the pure, DOM-free
`app/workspaceLayout.ts` record with total reads and best-effort writes (D8). Two
independent foundation modules in one step because the identity move alone is below the
size floor (D14).

## Interface intent

**`shared/currentUser.ts`** (new)

- **`CurrentUser`** — the type of `GET /api/me`'s body: an `id` (string), a `username`
  (string) and a `role` that is either `"roleplayer"` or `"admin"`. Moved here verbatim from
  `admin/adminAccess.ts`; this module is now its one definition.
- **`fetchCurrentUser`** — takes an optional `AbortSignal`; performs `GET /api/me` through
  the shared client's `apiGet` and resolves to a `CurrentUser`. Adds no error handling of its
  own: every failure propagates as the client threw it (including the client's own 401
  navigation to `/login`). Names no `/admin` route.

**`admin/adminAccess.ts`** (changed)

- Its own `CurrentUser` declaration is removed; it **re-exports** the type from
  `shared/currentUser.ts` so existing importers compile unchanged.
- **`enforceAdminAccess`** obtains the user through `fetchCurrentUser` instead of calling
  `apiGet` itself. Nothing else changes — `resolveAdminAccess`,
  `classifyAdminAccessError`, `ADMIN_ACCESS_RETRY_INTERVAL_MS` and every decision are as
  they were.

**`app/workspaceLayout.ts`** (new — pure, imports nothing from the DOM, React or MobX)

- **`WorkspaceLayout`** — the record: `navCollapsed` (boolean), `wallPinned` (boolean).
- **`LayoutStorage`** — the minimal storage interface the module needs: a `getItem(key)`
  returning a string or null, and a `setItem(key, value)`. `window.localStorage` satisfies it.
- **`WORKSPACE_LAYOUT_KEY`** — the constant `"rphelper.workspace-layout"`.
- **`DEFAULT_WORKSPACE_LAYOUT`** — `navCollapsed: false`, `wallPinned: false`.
- **`readWorkspaceLayout`** — takes a `LayoutStorage` or `null`; returns a complete
  `WorkspaceLayout`. Never throws. Per-field fallback to the default for: null storage, a
  throwing `getItem`, absent key, unparseable JSON, a payload that is not a plain object
  (array, string, number, `null`), a field of the wrong type, a missing field. Unknown keys
  (`asideWidth`, `answerBoxHeight`, anything else) are ignored.
- **`writeWorkspaceLayout`** — takes a `LayoutStorage` or `null` and a partial record (either
  or both fields); returns nothing. Merges the patch over a **fresh** `readWorkspaceLayout`
  of the same storage and stores the JSON of the resulting complete two-field record under
  the key. Any throw (from `getItem`, `setItem` or serialisation) is swallowed. Null storage
  is a no-op.

## Definition of done

1. `[test]` `fetchCurrentUser` issues exactly one `GET` to `/api/me` and resolves to the
   body's `id`, `username` and `role` unchanged, with `id` still a string.
2. `[test]` `fetchCurrentUser` propagates a failure as thrown by the shared client: a stubbed
   well-formed 403 envelope rejects with an `ApiError` carrying that envelope's code; a
   rejected `fetch` rejects with the client's transport-failure `ApiError`.
3. `[test]` The admin gate is unchanged: with `/api/me` stubbed, `enforceAdminAccess`
   requests `/api/me` exactly once and reaches the same decision as before for an admin, a
   roleplayer (navigates to `/`), a 401, a not-ready failure and a well-formed 403. The
   existing `tests/admin/adminAccess.test.ts` clauses pass without being weakened.
4. `[test]` No module under `frontend/src/app/` imports from `frontend/src/admin/`, and
   `frontend/src/shared/currentUser.ts` contains no `/admin` path string (a source scan,
   failing with the offending file).
5. `[test]` `readWorkspaceLayout` returns `{ navCollapsed: false, wallPinned: false }` for a
   `null` storage, a storage with no value under the key, and a storage whose `getItem`
   throws. (UC-070)
6. `[test]` `readWorkspaceLayout` returns the defaults for unparseable JSON and for a stored
   JSON value that is not an object (an array, a string, a number, `null`).
7. `[test]` `readWorkspaceLayout` falls back **per field**: a stored record with a valid
   `navCollapsed: true` and a non-boolean `wallPinned` yields `navCollapsed: true`,
   `wallPinned: false`; a record missing one field keeps the other's stored value.
8. `[test]` `readWorkspaceLayout` tolerates unknown keys: a stored record carrying
   `asideWidth` and `answerBoxHeight` beside `navCollapsed: true` and `wallPinned: true`
   yields exactly `{ navCollapsed: true, wallPinned: true }` — no extra keys on the result.
9. `[test]` `readWorkspaceLayout` reads only the key `rphelper.workspace-layout`.
10. `[test]` `writeWorkspaceLayout` with a `navCollapsed` patch stores, under
    `rphelper.workspace-layout`, a JSON record whose `navCollapsed` is the patched value and
    whose `wallPinned` is the previously stored value (round-trip: a following read returns
    both).
11. `[test]` `writeWorkspaceLayout` over a stored record carrying `asideWidth` writes a record
    containing only `navCollapsed` and `wallPinned`.
12. `[test]` `writeWorkspaceLayout` never throws: a storage whose `setItem` throws, one whose
    `getItem` throws, and a `null` storage all return normally.
13. `[test]` `workspaceLayout.ts` is DOM-free: its source references no `window`,
    `document`, `localStorage` global, React or MobX import (a source scan of the one file).
14. `[manual/live]` `npm run typecheck` passes with the `CurrentUser` type defined only in
    `shared/currentUser.ts`.
