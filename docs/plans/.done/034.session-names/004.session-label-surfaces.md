## Interface intent

- **`Session` type** (`sessionsApi.ts`) — gains `name`, a string or null and a required key. `toSession` copies it. The header comment "no update and no delete call (R6)" becomes "one update call (rename), no delete".
- **`renameSession`** (`sessionsApi.ts`) — takes a session id, a name (string or null) and an optional signal. It issues `PATCH /api/sessions/{id}` with a body of exactly `{ name }` through the shared `apiPatch`, and resolves to the returned `Session`. Errors propagate as the shared client's typed error.
- **`sessionLabel`** (`sessionLabel.ts`, pure) — takes anything carrying `name` and `created_at`, plus an optional time zone. It returns the name when it is non-null; otherwise it returns `created_at` rendered as local `YYYY-MM-DD` (DEC-034-9).
- **Local date-time formatter** (`sessionLabel.ts`) — the existing `formatSessionStart` is renamed `formatLocalDateTime` with an unchanged contract (local `YYYY-MM-DD HH:MM`, 24-hour). A local-date formatter sits beside it for the label's fallback (DEC-034-9).
- **`SessionHit` / `EntryHit`** (`searchApi.ts`) — gain `name` / `session_name` respectively, each a string or null (DEC-034-8).
- **Display call sites switch to `sessionLabel`**:
  - the tree row's label (`CharacterTree.tsx`, line 1 only; the two-line row is step 006);
  - the header `Title` (`SessionScreen.tsx`);
  - the Sessions tab row label and its `Actions for <label>` menu name (`SessionsSection.tsx`);
  - my-search's session row primary text and entry row session text (`SearchScreen.tsx`).

## Definition of done

1. DoD-1 [test] — `sessionLabel` returns a non-null name verbatim, including a name that looks like a date. (US-150.AC-2)
2. DoD-2 [test] — `sessionLabel` with a null name returns the local `YYYY-MM-DD` of `created_at` in the given time zone, including across a date boundary, for example `2026-11-05T23:30:00Z` in `Europe/Berlin` gives `2026-11-06`. It never includes a time. (US-150.AC-1, US-150.AC-3; DEC-arch-session-names-1)
3. DoD-3 [test] — `formatLocalDateTime` renders local `YYYY-MM-DD HH:MM`, zero-padded, 24-hour, at a fixed width of 16 characters. (DEC-arch-session-names-3)
4. DoD-4 [test] — Every sessions-API function returns sessions that carry `name` as received. `toSession` yields exactly the nine `Session` keys.
5. DoD-5 [test] — `renameSession` sends `PATCH /api/sessions/{id}` with a body whose only key is `name`, holding the string or `null` exactly as given, and resolves to the server's session. A server error rejects with the typed error. (DEC-arch-session-names-2)
6. DoD-6 [test] — Search hits expose `name` (session) and `session_name` (entry) as received.
7. DoD-7 [test] — A renamed session shows its name, and a never-renamed session shows its local start date with no time, in each of: the tree row, the session header title, the character page's Sessions row, my-search's session row and my-search's entry row. (US-150.AC-1, US-150.AC-2, US-152.AC-2)
8. DoD-8 [test] — The character page's Sessions tab offers no rename control. (DEC-arch-session-names-4)
