# Step 006 — rename-surfaces

## Goal

Render the two-line tree row and put the rename on its two surfaces: the tree row and the session header. Thread the workspace sessions store to the session screen, and keep the character page's Sessions list in step with a rename made from the tree.

## Interface intent

- **Tree session row** (`CharacterTree.tsx`):
  - Line 1 is the session's label on one line, truncated with an ellipsis.
  - Line 2 is smaller and dimmed. It shows the last-use time (`formatLocalDateTime(last_used_at)`), then ` · ` and the setup name when there is one, or the time alone when there is no setup (DEC-034-9).
  - Next to the link sits an `IconEdit` `IconButton` labelled "Rename session" (DEC-034-10).
  - The tree owns one `SessionRenameState`. While a row is being edited, that row renders `SessionNameEditor` in place of its link.
- **Session header** (`SessionScreen.tsx`):
  - An `IconEdit` `IconButton` labelled "Rename session" sits next to the `Title`. Activating it swaps the title for `SessionNameEditor`. It is offered whether or not the session is archived (DEC-034-10).
  - On success, the returned session is applied to the screen state's session and to the workspace store (DEC-034-11).
  - `SessionScreen` and `SessionRoute` gain a `sessions: SessionsState` prop (DEC-034-14).
- **`App.tsx`** — passes the workspace `SessionsState` it already owns to `SessionRoute` (DEC-034-14).
- **Section sync** (`sessionsSectionState.ts`, pure free function, plus a reaction in `SessionsSection.tsx`) — takes the section state and the workspace sessions. Every section row whose id matches a workspace session with a strictly newer `updated_at` is replaced by that session in place. Rows are never added, removed or reordered (DEC-034-13). `SessionsSection` runs it reactively for as long as it is mounted.

## Definition of done

1. DoD-1 [test] — A tree session row shows its label on the first line. The second line shows `YYYY-MM-DD HH:MM · <setup name>`, or `YYYY-MM-DD HH:MM` alone when the session has no setup. (US-151.AC-1, US-088.AC-1, US-088.AC-2)
2. DoD-2 [test] — For several sessions under one character, the rows are ordered most recent use first, and the second-line times read in the same descending order. (US-151.AC-2, US-089.AC-1)
3. DoD-3 [test] — Each tree session row offers "Rename session". Activating it shows an input pre-filled with the current name, or empty when never renamed. Typing a new name and pressing Enter sends the rename. The row shows the new label only after the server answers, and the row keeps its position. (US-150.AC-2, US-150.AC-4; DEC-arch-session-names-4)
4. DoD-4 [test] — Escape in the tree editor restores the row with its old label and sends nothing.
5. DoD-5 [test] — The session header offers "Rename session". Committing a name updates the header title and the session's tree row from the server's answer. Committing an empty name returns both to the local start date. (US-150.AC-2, US-150.AC-3)
6. DoD-6 [test] — A failed rename from either surface shows "Could not rename the session." inline under the editor. The editor keeps the typed text, and the label shown elsewhere stays the old one. (DEC-034-11)
7. DoD-7 [test] — With the character page mounted next to the tree, a rename from the tree relabels that session's row in the Sessions section. A workspace row with an older or equal `updated_at` does not overwrite the section's row. (US-150.AC-2; DEC-034-13)
8. DoD-8 [test] — The section sync never adds a row the section does not hold, never removes one, and never changes the section's order.
9. DoD-9 [manual/live] — At the 252px tree width, a long name truncates with an ellipsis on line 1 and line 2 does not wrap. Line 2 reads smaller and dimmed. (workspace-shell.md § Geometry)
