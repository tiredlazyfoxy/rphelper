# Step 003 — my-search-names

## Goal

Let my-search find sessions by their stored name. A `LIKE` name arm runs ahead of the vector hits, and session and entry hits are hydrated with the session's name so the client can label them.

## Interface intent

- **Session name arm** (`my_search.py`) — follows the same shape as `search_characters` / `search_setups`. It takes the connection, `user_id`, the query text and the per-kind limit, and returns the ids of the owner's sessions whose `name` contains the query, in `name`, then `id` order. It:
  - folds case the same way the other two matches do;
  - escapes wildcards;
  - excludes NULL names;
  - includes archived sessions;
  - returns nothing for a blank query, without issuing SQL.
- **Session hit merge** (`my_search.py`, pure) — takes the name-arm ids, the vector arm's hits and the limit. It returns the ordered session ids: name hits first, then vector hits whose ids were not already matched, capped at the limit (DEC-arch-session-names-5).
- **`run_my_search`** — runs the name arm alongside the existing vector session search, merges the two, and hydrates the merged order. Fail-whole on a vector-arm error is unchanged.
- **`SessionHit`** — gains `name` (str or None). Session hydration reads `sessions.name`.
- **Entry hit hydration** — also returns the owning session's `name`, next to `session_created_at` (DEC-034-8).
- **Wire models** (`models/search.py`) and router mapping — a session hit gains `name`, and an entry hit gains `session_name`, each a string or null (DEC-034-8).

## Definition of done

1. DoD-1 [test] — A query that is a substring of a stored session name returns that session in the sessions group. This also works with the query in a different case, in Latin and in Cyrillic. (US-152.AC-1; US-147 parity, DEC-arch-session-names-5)
2. DoD-2 [test] — A session with a NULL name is never matched by the name arm. In particular, typing its start date does not return it through the name arm. (accepted limitation, DEC-arch-session-names-5)
3. DoD-3 [test] — Another user's session whose name matches is never returned. (US-076.AC-1)
4. DoD-4 [test] — `%` and `_` in the query match literally. (search-and-retrieval.md: user input never acts as a wildcard)
5. DoD-5 [test] — A blank query still returns five empty groups and runs no name query.
6. DoD-6 [test] — Merge order: name hits come first, ordered by name and then id, followed by the vector hits in port order. A session matched by both appears once, in the name position. The group never exceeds 20.
7. DoD-7 [test] — When the vector session arm raises, the whole search fails with that error, even if the name arm matched. (029 U1 fail-whole)
8. DoD-8 [test] — Session hits carry `name` (null when never renamed) and `created_at`. Entry hits carry `session_name` (null when never renamed) next to `session_created_at`. The wire key sets in the router tests match exactly. (US-152.AC-2)
9. DoD-9 [test] — An archived session found by name is returned and marked archived. (029 U3)
10. DoD-10 [test] — The assistant's `session_search` tool output for a renamed session does not contain its name. (DEC-034-5)
11. DoD-11 [test] — The `sessions.name` sentinel of one user never appears in another user's `/api/search` response. The read-surface map lists `/api/search` as a reader of `sessions.name`. (DEC-034-4)
