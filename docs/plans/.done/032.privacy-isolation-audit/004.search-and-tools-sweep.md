# Step 004 — Search, tools, context assembly and index-write sweep

## Goal

Prove that my-search, the hybrid search port, the three assistant tools,
context assembly and the vector/FTS write paths never return, pass on or touch
another user's material, even when the model or the caller names the other
user's ids. Audit step: no source change planned.

## Source files

None planned. Fix-allowance if a `[test]` item fails against built code — the
user predicate of the failing read or write path, in its module under
`backend/app/services/` (my-search corpora and orchestrator (029), hybrid port
(025), memo search (026), session search (027), web search (028), tool scope
and tool adapters (021), context assembly (020), vector/FTS write paths (024))
or `backend/app/routers/` for the search route. Redesigns are handed back per
`context.md` "Leak-fix policy".

## Test files

- `backend/tests/test_privacy_audit_search_tools.py`

## Interface intent

None (audit). Tests call the services through the names frozen in the owning
features' `## Skeleton` records (025, 026, 027, 028, 020, 021, 024, 029).

## Definition of done

1. DoD-1 [test] — `GET /api/search?q=<B sentinel>` as A returns all five result
   groups empty for every searchable B sentinel, while B's identical request
   returns the sentinel's item (positive control). (US-085.AC-1)
2. DoD-2 [test] — Every hybrid-search variant (025), called with A's user id
   and a query (text and fake embedding) that matches only B's material,
   returns no candidate belonging to B; the same call with B's user id returns
   it. (US-085.AC-1)
3. DoD-3 [test] — The memo-search and session-search services (026, 027),
   called with A's scope and a B-targeting query, return no B memo, session or
   excerpt. (US-085.AC-1)
4. DoD-4 [test] — The memo_search and session_search tool adapters, given the
   tool scope built from A's session and model-supplied arguments that add
   B's user, session, character and setup ids as extra keys plus a
   B-targeting query, return no B material. (US-085.AC-1)
5. DoD-5 [test] — Building a tool scope for B's session on A's behalf fails
   with `session_not_found`; no scope is produced. (US-085.AC-1)
6. DoD-6 [test] — End to end: A composes in A's session while the fake model
   issues memo_search and session_search calls whose arguments name B's ids and
   B's sentinels; the tool rows and the assistant message written to A's zone
   carry no B sentinel and no B id. (US-085.AC-1)
7. DoD-7 [test] — A web_search call made in A's session sends an outbound
   request that contains the model-supplied query and nothing else from the
   instance: no seeded row id (any user) and no sentinel other than one the
   query itself contains. (US-085.AC-1)
8. DoD-8 [test] — Context assembled for A's session contains no B sentinel, and
   context assembled for B's session contains no A sentinel — including a memo
   A created naming B's scope id (`003` DoD-6 case). (US-085.AC-1)
9. DoD-9 [test] — Every foreign-id write attempt by A (message edit, zone
   message, settle, reopen, memo edit, memo delete against B's ids) leaves B's
   rows in `memo_vec`, `session_vec` and their FTS tables identical to before.
   (US-085.AC-1)
10. DoD-10 [test] — A's own successful writes on the same paths (memo
    create/edit/delete, settle, reopen, message edit) change no `memo_vec`,
    `session_vec` or FTS row keyed to a B id. (US-085.AC-1)
