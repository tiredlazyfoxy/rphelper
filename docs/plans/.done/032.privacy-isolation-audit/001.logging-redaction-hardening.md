# Step 001 — Logging and engine redaction hardening

## Goal

Close the three log-leak paths found at plan time (`context.md` "Leaks already
found at plan time"): strip query strings from access-log records, turn
`diagnose`/`backtrace` off on every loguru sink, and build the engine with
bound parameters hidden.

## Source files

- `backend/app/logging.py`
- `backend/app/db/engine.py`

## Test files

- `backend/tests/test_logging_redaction.py`

## Interface intent

- **Access-log query redaction filter** (new, in `app/logging.py`) — a stdlib
  logging filter that rewrites a `uvicorn.access` record so its request target
  keeps the path and loses everything from the first `?` onward. Method, path,
  HTTP version and status survive. It never drops a record; it only rewrites
  the target argument. Input: a log record; output: the record allowed through,
  rewritten.
- **`configure_logging(settings)`** (changed) — installs the redaction filter on
  the `uvicorn.access` logger itself (so it applies whichever handler emits the
  record), and adds every loguru sink (console and file) with
  `diagnose` off and `backtrace` off. Everything else it does today is
  unchanged.
- **Engine factory in `app/db/engine.py`** (changed) — builds the engine with
  bound parameters hidden, so neither a SQLAlchemy log record at any level nor
  the string form of a statement error renders a bound value. No other engine
  option changes.

## Definition of done

1. DoD-1 [test] — After `configure_logging`, a record emitted on the
   `uvicorn.access` stdlib logger in uvicorn's access shape, whose request
   target carries a sentinel in its query string, reaches no sink (console
   output, log file, a level-0 capture sink) with the sentinel present.
   (US-084.AC-1)
2. DoD-2 [test] — The same record, as written by the sinks, still names the
   method, the path (without query) and the status, so access lines stay
   useful. (US-084.AC-1)
3. DoD-3 [test] — A record on `uvicorn.access` whose target has no query string
   is emitted unchanged. (US-084.AC-1)
4. DoD-4 [test] — After `configure_logging`, an exception logged with its
   traceback from a frame whose local variable holds a sentinel leaves no
   sentinel in the console output or the log file, while the traceback's frame
   (function name) is still present. (US-084.AC-1)
5. DoD-5 [test] — With the `sqlalchemy.engine` logger lowered to INFO and a
   level-0 capture sink attached, executing a statement through an engine from
   the engine factory with a sentinel as a bound parameter emits no record
   containing the sentinel. (US-084.AC-1)
6. DoD-6 [test] — A constraint-violation error raised by a statement whose bound
   parameter is a sentinel has a string form that does not contain the
   sentinel. (US-084.AC-1)
7. DoD-7 [test] — An engine from the engine factory reports that it hides
   parameters. (US-084.AC-1)
8. DoD-8 [manual/live] — In a real uvicorn run, `GET /api/search?q=<sentinel>`
   produces an access line in the console/supervisord output that shows
   `/api/search` without the query and no sentinel anywhere.
