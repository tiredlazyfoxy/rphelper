# Step 006 — Admin surfaces, reverse lookup and admin frontend

## Goal

Prove that every administrative response — backend and the `admin` frontend
entry — carries administrative data only: no user content, no count derived
from it, and no answer to "which/how many sessions use this model" (R5),
including fast/002's vector rebuild. Audit step: no source change planned.

## Source files

None planned. Fix-allowance if a `[test]` item fails against built code:

- `backend/app/routers/admin_users.py`
- `backend/app/routers/admin_llm.py`
- `backend/app/routers/admin_db.py`
- the services those routers call, under `backend/app/services/`
- the fast/002 rebuild route/service (`_TBD: resolved from fast/002 plan.md at
  build time_`) — only to drop a count/value field derived from user content
- files under `frontend/src/admin/` — only to remove a forbidden call or
  count rendering

Anything larger is handed back per `context.md` "Leak-fix policy".

- `frontend/tests/adminPrivacyAudit.test.ts`

None (audit).

## Definition of done

1. DoD-1 [test] — Every admin GET (users, llm-servers, available-models,
   database tables, the fast/002 progress/status read if any) as ADM, after A
   and B seeded content, contains no sentinel of any user. (US-084.AC-1)
2. DoD-2 [test] — Every admin GET response is identical before and after A and
   B seed their content (snapshot taken after all logins), so no admin field is
   a count or value derived from user content. (US-084.AC-1)
3. DoD-3 [test] — Every admin mutation response (user create/disable/enable/
   password/role; llm-server create/patch/test/delete; models set; embedding
   model set/unset; database create/sync) contains no sentinel of any user.
   (US-084.AC-1)
4. DoD-4 [test] — R5: removing from the enabled set a model that B's session
   uses succeeds — never refused — and its response equals, field for field
   apart from the model name, the response for removing a model no session
   uses. (US-084.AC-1)
5. DoD-5 [test] — R5: no admin route's declared response model has a field
   whose name matches the forbidden-name list in `006.context.md`.
   (US-084.AC-1)
6. DoD-6 [test] — `GET /api/health` carries no sentinel and is identical before
   and after content is seeded. (US-084.AC-1)
7. DoD-7 [test] — fast/002 vector rebuild: its response and every progress
   payload are equal (apart from ids, timestamps and status fields named in
   `006.context.md`) whether the store holds one content row or many, and carry
   no sentinel. (US-084.AC-1)
8. DoD-8 [test] — Frontend: every `/api/` path literal in any file under
   `frontend/src/admin/` begins with an allowed prefix (`006.context.md`).
   (US-084.AC-1)
9. DoD-9 [test] — Frontend: no file under `frontend/src/admin/` contains an
   identifier or string matching the forbidden-name list or the "N sessions use
   this model" pattern family. (US-084.AC-1)
10. DoD-10 [manual/live] — In a running instance with a second user's content,
    the LLM Servers page's model-disable and connection-delete confirms show no
    number, and the Users and Database pages show no content.
