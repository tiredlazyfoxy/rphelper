# Step 003 — step-specific context

## Built behaviour this sweep re-asserts (harvested)

- Owner predicate is in the SQL `WHERE` everywhere for 001..017 (no
  fetch-then-filter); a foreign id yields the same 404 + code + `detail == {}` as
  an unknown id. So DoD-1..11 are expected to pass for the built rows; 018..031
  rows rely on their declared DoD (018/002 DoD-5/7, 021/006 DoD-9, 022/002
  DoD-4/7, 023/003 DoD-3, 030/003 DoD-7, 031/005 DoD-4).
- `PATCH /api/messages/{}` resolves the message by `messages.user_id` only (no
  session join). Not an attack path via the API — see `context.md` "Known
  risks" — so no inconsistent row is seeded.
- `PUT /api/memos/order` with foreign ids answers 409 `memo_order_mismatch` and
  writes nothing (built, 016).
- `memos.scope_id` has no FK — DoD-5/6 exist because the scope id is not
  structurally tied to its owner.
- Gaps in the owning features' own tests that this step closes: 021/001's tool
  rows on `GET …/zone` and `…/entries` had no cross-user DoD (DoD-11); no
  feature asserted admins against user-content routes (DoD-3).

## Mechanics

- Parametrize DoD-1/3 over the enumeration literal's `owner` rows; map each
  path's leading resource to the right B id (character, setup, session,
  message, memo). For row 30's second case (own character, B's setup) see
  DoD-8. For row 47 take the 404 code from 023/003 DoD-3.
- For write rows, send a body that would be valid for A's own resource (so a
  refusal is the owner predicate, not a 422). Bodies carry an A-side sentinel
  so DoD-2 can also assert B never gains it.
- "Unchanged" in DoD-2 means B's read responses before and after are equal
  (excluding nothing — no timestamps move on a refused write).
- DoD-9 needs the fake model seam from the support module to observe "no call".
