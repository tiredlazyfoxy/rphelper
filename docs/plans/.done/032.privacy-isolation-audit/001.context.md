# Step 001 — step-specific context

This is the one step with a **normal red gate**: the three leaks exist in built
code, so DoD-1, DoD-4, DoD-5..7 must fail against the stubs/current code for the
right reason (sentinel present / attribute false).

## Built facts (harvested)

- `app/logging.py`: `configure_logging(settings)` at ~L50. Console sink on
  stderr at `settings.log_console_level` (default `DEBUG`) using loguru's default
  `diagnose` (True) — the leak. File sink already passes `diagnose=False`.
  `InterceptHandler` bridges stdlib into loguru; root stdlib logger at `NOTSET`;
  `_PROPAGATING_LOGGERS = ("uvicorn", "uvicorn.access", "uvicorn.error",
  "sqlalchemy")` are made to propagate into the bridge, with no levels set on
  them.
- `app/db/engine.py` ~L123-128: the engine is created with no `echo` and no
  `hide_parameters`. The `sqlalchemy` logger stays at its own default (WARNING);
  empirically a level-0 sink catches no SQL today.
- Every existing `logger.*` call in `app/` is clean (ids, codes, counts) — this
  step changes configuration, not call sites.

## uvicorn's access record shape (library fact)

uvicorn logs access lines on the `uvicorn.access` logger with the format
`'%s - "%s %s HTTP/%s" %d'` and args
`(client_addr, method, full_path, http_version, status_code)`; `full_path`
includes `?query` when present. The filter rewrites the `full_path` argument.
Attach it to the **logger**, not to a handler: uvicorn's own dictConfig may
attach its own handler to `uvicorn.access`, and a logger-level filter covers
every handler. Tests must emit through `logging.getLogger("uvicorn.access")`
(a record handed straight to a handler bypasses logger filters).

## Test gotchas

- A traceback with `diagnose=False` still prints the **source line** of each
  frame. Build the sentinel at runtime (e.g. concatenation) and keep it off the
  raising line and out of the exception message, or DoD-4 fails for the wrong
  reason.
- loguru's stderr sink binds `sys.stderr` when added; call `configure_logging`
  inside the test after pytest's capture is active (or point the file sink at
  `tmp_path` and read it). Remove added sinks / restore stdlib logger state
  after each test so the autouse environment isolation in `conftest.py` holds.
- Existing router tests monkeypatch `app.main.configure_logging` to a no-op;
  this test calls the real function directly.
- Log-capture precedent: `tests/test_sync_executor.py:223` `_captured_logs()`
  (level-0 loguru sink collecting message, `repr(extra)` and exception value).
  This step predates the shared support module (step 002) and keeps its own
  capture helper inside its test file.
- With hidden parameters, SQLAlchemy writes a placeholder such as
  "[SQL parameters hidden due to hide_parameters=True]" — its presence is fine.
