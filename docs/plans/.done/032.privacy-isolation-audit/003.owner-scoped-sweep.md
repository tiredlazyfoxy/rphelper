# Step 003 — Owner-scoped CRUD and stream sweep

## Goal

Re-assert, in one place, that every `owner`, `self` and `registry` route in the
enumeration (`context.md`) refuses a foreign id with refusal identity and never
lists another user's characters, sessions, setups, messages or memos. Audit
step: no source change planned.

## Source files

None planned. Fix-allowance if a `[test]` item fails against built code — the
owner predicate of the failing surface only, in its router and service module
under `backend/app/routers/` and `backend/app/services/` (characters, setups,
sessions, stream/messages, memos, configuration, discussion, translation,
export, import). Anything beyond a predicate or a dropped field is handed back
per `context.md` "Leak-fix policy".

## Test files

- `backend/tests/test_privacy_audit_owner_sweep.py`

## Interface intent

None (audit). Tests bind to the support module frozen in step 002's skeleton
record.

## Definition of done

1. DoD-1 [test] — For every `owner` row of the enumeration, A's request with B's
   id for the path's resource gets refusal identity with the row's 404 code:
   the response equals A's response for the unknown id. (US-083.AC-1)
2. DoD-2 [test] — After every write attempt of DoD-1 (PATCH, POST, DELETE,
   archive/restore, settle/reopen, import, zone messages), B's resource reads
   back unchanged through B's own routes — same sentinels, same archive state,
   same zone/entries row set, same memos and order. (US-083.AC-1)
3. DoD-3 [test] — ADM, calling the same `owner` routes with B's ids, gets the
   same refusal identity as A: an admin is not a super-reader of user content.
   (US-083.AC-1)
4. DoD-4 [test] — A's list routes (`GET /api/characters` including the
   archived view, `GET /api/sessions` including the archived view,
   `GET /api/characters/{A}/setups`, `GET /api/characters/{A}/sessions`,
   `GET /api/memos` for each of A's own scopes, A's entries, zone and
   memo-chain) contain no B sentinel and no B id, while containing A's own
   (positive control). (US-083.AC-1)
5. DoD-5 [test] — `GET /api/memos` with each of B's scope ids (character,
   setup, session, and B's user id at user scope) as A returns an empty list
   or a 404, and never a B memo. (US-083.AC-1)
6. DoD-6 [test] — `POST /api/memos` by A naming one of B's scope ids is either
   refused with 404 or creates a row that never appears in any of B's memo
   lists or B's memo-chain. (US-083.AC-1)
7. DoD-7 [test] — `PUT /api/memos/order` by A with an order mixing A's and B's
   memo ids, or B's ids only, gets 409 `memo_order_mismatch`; neither A's nor
   B's memo order changes. (US-083.AC-1)
8. DoD-8 [test] — `POST /api/characters/{A's character}/sessions` with B's
   `setup_id` gets 404 `setup_not_found`; no session is created for A and no
   opening message is written. (US-083.AC-1)
9. DoD-9 [test] — `POST /api/sessions/{B's session}/zone/compose` by A gets a
   404 `session_not_found` JSON response before any stream frame, writes no row
   in B's session, and the fake model receives no call. (US-083.AC-1)
10. DoD-10 [test] — `GET /api/me`, `GET /api/me/settings` and `GET /api/models`
    as A carry no B sentinel and no B id; `PATCH /api/me/settings` by A leaves
    B's settings unchanged. (US-083.AC-1)
11. DoD-11 [test] — B's zone and entries containing tool rows (021) are
    unreachable by A: covered by DoD-1 for rows 34 and 36, asserted
    additionally that A's own zone/entries never contain a B tool row.
    (US-083.AC-1)
