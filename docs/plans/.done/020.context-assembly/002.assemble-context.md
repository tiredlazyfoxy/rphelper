# Step 002 — The assembler: `assemble_context`

## Goal

Add the DB-reading entry point to `services/context.py`. For one caller and one session
it composes existing owner-scoped reads (011's session, 009's character, 017's
configuration, 015's chain filtered to forced, 012's record and zone) through step
`001`'s renderer and mapper. It returns the assembled context, reads live and names no
table. Under 50 lines of source: kept apart from `001` because only this step needs 015
and 017 built (`context.md` D13).

## Source files

backend/app/services/context.py

## Test files

backend/tests/test_context_assembly.py

## Interface intent

**`app/services/context.py`** (changed; adds to step `001`)

- **`AssembledContext`**: frozen value with `system_prompt` (string) and `messages` (an
  ordered, immutable sequence of `ChatMessage`). What `021` sends to the model.
- **`assemble_context`**: takes the Core `Connection`, the caller's `user_id` (required
  positional) and a session id. In this order:
  1. reads the session with `sessions.get_session` (raises `SessionNotFoundError` for a
     missing or another user's session, before anything else is read);
  2. reads the configuration with `configuration.get_session_configuration` and takes the
     resolved values of `system_prompt`, `rp_language`, `preferred_language`;
  3. reads the character with `characters.get_character` for the session's
     `character_id` and takes its `sheet`;
  4. resolves the chain with `memo_chain.resolve_chain` and turns each level into a
     `ForcedNoteLevel` holding, in the chain's order, the bodies of the notes whose
     `memo_reach` is `"forced"` (D6). Every level is passed on, empty ones included; the
     renderer drops empty ones;
  5. reads `messages.list_entries` and `messages.list_zone`;
  6. renders the system prompt and maps the messages with step `001`'s functions.

  Returns an `AssembledContext`. Opens no transaction of its own, leaves none open, writes
  nothing, caches nothing (D11). Selects from no table itself.

## Definition of done

1. `[test]` Happy path. A session with a setup; character system prompt `"P"` and sheet
   `"S"`; one forced note at each of the four levels; settled rows (a partner block, a
   turn, a decision stored with its `(( ))`) then zone rows (role `user`, then role
   `assistant`). The system prompt holds `"P"` under `=== System prompt ===`, `"S"`
   under `=== Character sheet ===`, the four bodies under their level headings in level
   order, and the three instruction sections. `messages` is exactly the expected list:
   stored roles, tagged settled contents, untagged zone contents, id order.
   (UC-045, US-054.AC-1, US-122, UC-081, D1, D7)
2. `[test]` At every level, a note that is **disabled and forced**, a note that is
   disabled and not forced, and a note that is enabled and not forced (searchable) are
   absent: their bodies appear nowhere in the system prompt or any message content, while
   each level's forced note is present. (US-098.AC-1, US-055.AC-1, R3, D6)
3. `[test]` Forced notes appear in level order user → character → setup → session even
   when the user level's `sort_key`s are larger than the session level's; within a level
   they follow `sort_key`, then `id` (raw-inserted out of order, with one `sort_key` tie).
   (US-103.AC-1, D6)
4. `[test]` After a raw update swapping two forced notes' `sort_key`s within a level, a
   second call renders them in the new order. (US-102.AC-1, UC-076, D11)
5. `[test]` A session without a setup assembles with no `--- Setup notes ---` line, and
   the user, character and session forced notes are all present. A forced setup-level
   note of a setup under the same character is absent. (R2, US-057.AC-1)
6. `[test]` Buried rows are absent. With a settled head and rows buried under it
   (`related_to` = the head's id), whether the zone is empty (still re-openable) or holds
   a newer row, the head appears tagged and no buried row's text appears in any message
   or in the system prompt. (UC-038, US-043.AC-1, US-043.AC-2, R7, R11)
7. `[test]` Isolation. Absent from the result: another user's memos raw-inserted at this
   session's exact scopes and scope ids (including a forced user-level note of theirs);
   the settled and zone rows and the forced session-level notes of **another session of
   the same character**; the forced character-level notes of another character of the
   caller. (R5, FEAT-019, UC-054)
8. `[test]` Another user's session id, and an id that exists for nobody, raise
   `SessionNotFoundError`. (R5, D8)
9. `[test]` Read live. Between two calls, raw-update a settled row's text, a zone row's
   text, the character's system prompt, and one forced note's `is_enabled` to false. The
   second call shows the new texts and the new prompt, and that note's body is absent.
   (UC-029, US-110, US-115, UC-044, D11)
10. `[test]` Configuration. A session-level system prompt beats the character's; with
    neither set, `=== System prompt ===` is absent. The user's RP language `"Japanese"`
    and preferred `"Russian"` appear on the `- Candidates:` and `- Out of character:`
    lines; a session override `"French"` for the RP language replaces `"Japanese"` there;
    with no language set anywhere both lines carry `English`. (R1, D4, D5, D8)
11. `[test]` A character whose `sheet` is `""` gives no `=== Character sheet ===` line.
    (D5)
12. `[test]` A session with `archived_at` set, under a character with `archived_at` set,
    assembles normally. (R6, D8)
13. `[test]` A zone row with role `"tool"` is absent from `messages`, and the rows around
    it keep their order. (D3)
14. `[test]` 300 settled rows, one with a 100,000-character text, plus zone rows: every
    row is present as a message in id order and the long text is whole. (D12)
15. `[test]` After a call, and after a call that raised `SessionNotFoundError`, the
    connection is not in a transaction (a following `connection.begin()` succeeds), and
    the `messages` and `memos` rows are unchanged. (D11)
16. `[test]` Source convention on `app/services/context.py`: it imports nothing from
    `app.db` and no `fastapi`; from `sqlalchemy` it imports at most the `Connection`
    type; it contains no `select(`, `insert(`, `update(`, `delete(` or `text(` call and
    no `settled_entries`, `current_zone`, `translation` substring; its `app.services`
    imports are exactly `messages`, `sessions`, `characters`, `configuration`,
    `memo_chain` and `llm.chat`. Every `is_enabled` / `is_forced` attribute access in it
    sits inside the arguments of a `memo_reach` call (no hand-written reach predicate).
    (R11, R8, R3, D6, D9)
17. `[manual/live]` With `021` issuing requests: the assistant answers a zone message in
    that message's language and keeps mirroring when the roleplayer switches language
    (US-036.AC-1..AC-3, UC-033).
18. `[manual/live]` With `021`: an out-of-character exchange is answered in the preferred
    language, while a candidate produced in the same exchange is in the RP language
    (US-131.AC-2, US-131.AC-3, US-037).
19. `[manual/live]` With `021`: a wholly parenthesised message is answered as
    out-of-character talk rather than prose, and a draft with a `(( ))` fragment yields a
    candidate that applies it and does not reproduce it (US-129, US-130, UC-084).
20. `[manual/live]` With `021`: the assistant treats `[partner]` text as the partner's,
    `[my turn]` as the roleplayer's, and honours a `[decision]` as standing context
    (US-122, UC-081).
