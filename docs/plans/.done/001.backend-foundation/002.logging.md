# Step 002 — Logging sinks and the stdlib bridge

## Goal

Configure loguru's two sinks from `Settings` and install the `InterceptHandler` that
makes every stdlib `logging` record — uvicorn's and SQLAlchemy's included — land in
those sinks.

## Source files

```
backend/app/logging.py
```

## Test files

```
backend/tests/test_logging.py
```

## Interface intent

**An intercept handler** — a subclass of the standard library's logging handler. For
each record it receives it forwards the message to loguru, mapping the stdlib level to
loguru's level by name where loguru knows that name and by numeric value otherwise,
carrying the record's exception information through, and setting loguru's caller depth
so the emitted line attributes the record to the module that logged it rather than to
this handler.

**A `configure_logging` entry point**, taking a settings instance and returning nothing.
It does three things and nothing else:

1. Removes loguru's default stderr handler, then adds the two configured sinks — a
   console sink to stderr at `log_console_level`, and a rotating file sink at
   `log_file_path` with `log_file_level`, `log_file_rotation` as its rotation policy,
   `log_file_retention` as its retention count, and **`diagnose=False`**. The last is
   load-bearing: loguru's exception formatting prints local variable values, which
   would defeat the redaction rule at the one moment it matters most.
2. Creates `log_file_path`'s parent directory if it does not exist.
3. Installs the intercept handler as the stdlib root logger's handler, sets the root
   level low enough that nothing is filtered before loguru sees it, and clears the
   handlers of `uvicorn`, `uvicorn.access`, `uvicorn.error` and `sqlalchemy` so their
   records propagate up to the root rather than being written by their own handlers.

It is **idempotent**: calling it twice leaves two sinks and one intercept handler, not
four and two. Tests depend on that, and so does any future re-entry.

No other module in this backend adds, removes or reconfigures a sink. Call sites use
loguru's logger directly.

## Definition of done

1. `[test]` A record emitted through the **stdlib** `logging` API — including through
   the `uvicorn.error` and `sqlalchemy` loggers specifically — reaches loguru's sinks
   after `configure_logging` has run. `deployment.md` states this as a prohibition:
   loguru without a tested `InterceptHandler` bridge is unfinished work.
2. `[test]` After `configure_logging`, loguru has exactly two sinks and loguru's own
   default stderr handler is no longer among them.
3. `[test]` The console sink honours `log_console_level` and the file sink honours
   `log_file_level` independently — at the defaults, a `DEBUG` record appears on the
   console sink and **not** in the file, while a `WARNING` record appears in both.
4. `[test]` The parent directory of `log_file_path` is created when it does not exist,
   and the file then receives records at or above the file sink's level.
5. `[test]` An exception logged with loguru's exception logging writes a traceback to
   the file sink that contains **no local variable values** — the observable
   consequence of `diagnose=False`.
6. `[test]` After `configure_logging`, each of `uvicorn`, `uvicorn.access`,
   `uvicorn.error` and `sqlalchemy` has no handler of its own and propagates to the
   root.
7. `[test]` `configure_logging` is idempotent — two calls leave two sinks and one
   intercept handler on the root.
8. `[test]` The intercept handler preserves the record's level: a stdlib `ERROR` record
   arrives at loguru as `ERROR`, and a record logged at a custom numeric level with no
   loguru name still arrives rather than being dropped.
9. `[manual/live]` Running uvicorn against the application shows uvicorn's startup and
   access lines in loguru's format, not uvicorn's own.
10. `[manual/live]` The redaction rule holds across the whole backend: no call site logs
    message, memo, persona, setup or session text, a translation, an LLM payload, an API
    key or a resolved secret value. Verifier records it as a review criterion.
