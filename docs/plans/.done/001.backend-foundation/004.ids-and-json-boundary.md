# Step 004 — The snowflake generator and the JSON id boundary

## Goal

Mint snowflake ids — the bit layout, the fixed epoch, the lock, the config node id and
the backwards-clock refusal — and declare the two pydantic aliases that are the only
place an id crosses between `int` and decimal string.

```
backend/app/ids.py

backend/app/models/ids.py
```

## Interface intent

**`app/ids.py`** — infrastructure, deliberately beside `config.py` and `secrets.py`, and
**not** in `services/` (it takes no `user_id` and enforces no domain rule) and **not**
in `db/` (it opens no connection and names no table).

- **Public layout constants**: the epoch as milliseconds since the Unix epoch
  corresponding to `2026-01-01T00:00:00Z`, the node-id width (10 bits) and the sequence
  width (12 bits). Public because the layout is the contract, and a test must be able to
  decode an id without re-deriving the shifts. The epoch is a constant that can never
  change — it is the whole 41-bit budget.
- **A generator class.** Constructed with a node id, which it reads **once**; a node id
  outside the range the 10 bits allow is refused at construction. It also takes a clock
  — a callable returning the current time in milliseconds — defaulting to the system
  clock, so drift and exhaustion are testable without touching real time. Its state is
  two values, the last millisecond issued and the sequence within it, held behind a
  lock: uvicorn's thread pool can land two inserts in the same millisecond and an
  unlocked generator hands out the same id twice.
- **A mint operation** returning the next id: 41 bits of milliseconds since the epoch,
  then the node id, then the per-millisecond sequence. When the sequence exhausts within
  one millisecond (more than 4096 ids in that millisecond) it **blocks until the next
  millisecond** rather than raising or wrapping — see `004.context.md`.
- **A distinct backwards-clock exception**, raised when the clock reads earlier than the
  last millisecond issued. It is **deliberately not a domain error**: waiting out the
  drift and carrying on both mint duplicates, so this surfaces as an operational fault —
  a 500 — not as a domain failure the SPA is expected to render.
- **A construction helper** that builds the process's generator from a settings
  instance, reading `node_id`. Step `006`'s app factory calls it once and holds the
  single instance on application state.

**`app/models/ids.py`** — the two annotated aliases, declared verbatim in
`docs/architecture/backend-structure.md` § The JSON id boundary: the outbound alias
serialises an `int` field to a `str`, the inbound alias parses a value to `int` before
validation. Reproduce that declaration exactly.

**`app/models/__init__.py`** — the `models` package marker, re-exporting both aliases so
every later model imports them from one place. Its docstring states the rule: every
id-typed field on a pydantic model uses one of the two aliases, and **a bare `int` id
field is the defect**.

## Definition of done

1. `[test]` Ids minted in succession from one generator strictly increase, and every id
   is positive and fits in 63 bits.
2. `[test]` The layout decodes: for an id minted at a known clock reading with a known
   node id, the high field is milliseconds since `2026-01-01T00:00:00Z`, the middle
   field is the node id, and the low field is the sequence, at the widths the public
   constants declare (10 node bits, 12 sequence bits).
3. `[test]` The node id is read once at construction and is what every subsequently
   minted id carries; a node id outside the representable range is refused at
   construction.
4. `[test]` Concurrent minting from several threads against one generator produces no
   duplicate ids.
5. `[test]` Minting more than 4096 ids within a single millisecond blocks into the next
   millisecond and still yields strictly increasing, unique ids — it neither raises nor
   repeats.
6. `[test]` A clock that reads earlier than the last millisecond issued makes the mint
   operation raise the backwards-clock exception, and that exception is **not** a
   subclass of the domain-error base class from step `003`.
7. `[test]` A pydantic model with an outbound-alias field serialises that field to a
   JSON **decimal string**, and a value above JavaScript's `Number.MAX_SAFE_INTEGER`
   survives the round trip with every digit intact.
8. `[test]` A pydantic model with an inbound-alias field accepts a decimal string and
   yields an `int`, and also accepts an `int` unchanged.
9. `[test]` Both aliases are importable from the `models` package itself, not only from
   the module that declares them.
10. `[manual/live]` The generator is constructed once per process. Verifier confirms the
    construction helper has exactly one call site once step `006` lands.

## Dependencies

Steps `001` (settings supply `node_id`) and `003` (the backwards-clock exception is
defined by contrast with the domain-error base class, and DoD-6 asserts the
non-relationship).
