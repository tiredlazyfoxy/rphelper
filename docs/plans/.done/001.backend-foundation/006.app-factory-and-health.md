# Step 006 — The app factory and `GET /api/health`

## Goal

Assemble everything: the app factory that configures logging once before any router is
registered, holds the process's id generator on application state and installs the error
handler — and the one router in scope, whose readiness probe genuinely reads the
database.

## Source files

```
backend/app/main.py
backend/app/routers/health.py
backend/app/services/health.py
backend/app/models/health.py
```

## Test files

```
backend/tests/test_main.py
backend/tests/test_health.py
```

## Interface intent

**`app/main.py`**

- **An application factory** returning a configured FastAPI application. In order: it
  resolves settings; calls `configure_logging` **exactly once, before any router is
  registered**, so that a failure during registration is already captured by both sinks;
  constructs the process's snowflake generator from those settings and stores that
  single instance on application state; registers the domain-error handler through step
  `003`'s registration entry point; then includes the health router.
- **A lifespan** that runs **no DDL** — no table creation, no upgrade, no schema check.
  Remediation is admin-triggered and belongs to `007`.
- **A module-level application instance** built by the factory, so `app.main:app` is the
  uvicorn target.

**`app/services/health.py`** — a service by construction, not a domain service; see
decision D10 in `context.md`.

- **A probe function** taking a Core `Connection` and a metadata registry and returning
  a plain result carrying the three values the response reports. It never imports
  `fastapi`, never sees a `Request` and never knows a status code.
- It performs the cheap `sqlite_master` read that the architecture insists on — "a
  health check that cannot fail tells an operator nothing".
- **`configured`** is true only once a database with at least one administrator exists:
  a `users` table present **and** holding at least one row whose role is administrator.
  In this feature there is no `users` table, so it is false. Feature `003` sharpens the
  same branch; it must not have to rewrite it.
- **`schema`** is `"missing"` when any table in the supplied registry is absent from
  `sqlite_master`, and `"ok"` when every one is present. The empty registry is
  trivially `"ok"` — correct, not a stub. `"drift"` is a permitted value of the type
  that nothing in this feature produces; feature `007` fills it in.
- **`status`** is the roll-up, in this precedence: a `schema` other than `"ok"` gives
  `"degraded"`; otherwise `configured` being false gives `"unconfigured"`; otherwise
  `"ok"`.
- The registry is a **parameter**, not a module import, so a test can supply one
  containing a table and observe the `"missing"` branch.

**`app/routers/health.py`**

- **`GET /api/health`**, unauthenticated, taking the connection dependency from step
  `005`, calling the probe with that connection and the registry from `db/schema.py`,
  and returning the response model. It issues **no SQL** and holds no rule — it maps the
  probe's plain result onto the model and nothing else.

**`app/models/health.py`**

- **A response model** carrying the three fields and serialising to exactly
  `{"status": ..., "configured": ..., "schema": ...}`. The JSON key is literally
  `schema`; see `006.context.md` for the pydantic naming gotcha. The permitted values
  are the three for `status` and the three for `schema` named above.

## Definition of done

1. `[test]` `GET /api/health` answers 200 with a body carrying exactly the keys
   `status`, `configured` and `schema` — literally those three names, nothing more.
2. `[test]` Against a database created by the test fixture with the empty registry:
   `schema` is `"ok"`, `configured` is `false`, and `status` is `"unconfigured"`.
3. `[test]` The probe reports `schema` as `"missing"` when a table in the registry it is
   given is absent from the database, and `"ok"` when every table in that registry is
   present — which is the proof that it really reads `sqlite_master` rather than
   returning a constant.
4. `[test]` The status roll-up follows its precedence: a non-`"ok"` schema gives
   `"degraded"` regardless of `configured`; an `"ok"` schema with `configured` false
   gives `"unconfigured"`; an `"ok"` schema with `configured` true gives `"ok"`.
5. `[test]` `configured` becomes true only when a `users` table exists **and** holds at
   least one administrator row — a present-but-empty `users` table still reports false.
6. `[test]` The endpoint requires no authentication: it answers with no cookie and no
   credentials at all.
7. `[test]` The probe service is callable with a plain connection and a registry, with
   no FastAPI application, no request and no HTTP status anywhere in its contract.
8. `[test]` The factory invokes `configure_logging` exactly once per call — not zero
   times, not once per router.
9. `[test]` The application exposes the snowflake generator on application state, and it
   is the **same instance** across two requests.
10. `[test]` A domain error raised inside a route of an application built by the factory
    is rendered with the wire shape and that subclass's HTTP status — the proof that the
    handler registration is wired into the factory.
11. `[test]` The lifespan runs no DDL: after the application has started against an
    empty database file, `sqlite_master` holds no application table.
12. `[manual/live]` `configure_logging` is called **before** the first router is
    registered. Verifier confirms by reading `main.py`; call order is not observable
    from outside.
13. `[manual/live]` `uvicorn app.main:app` on port 8184 starts, and `GET
    http://127.0.0.1:8184/api/health` answers with the body from DoD-2.
14. `[manual/live]` The router contains no SQL and the service imports no `fastapi`
    symbol. Verifier confirms by reading the two modules — this is the convention the
    whole backend inherits and it is worth checking at its first instance.

## Dependencies

Steps `001` (settings), `002` (`configure_logging`), `003` (the error handler and its
registration), `004` (the generator and the id aliases) and `005` (the connection
dependency and the registry). This step integrates all five, which is why it is last.
