Feature-wide facts are in `context.md`: D1 (provider), D2 (credentials), D4 (the seam),
D5 (failure shape), D6 (outbound boundary), D7 (no logs, no cache), D9 (timeout), D12

## The Google request

| Part | Value |
|---|---|
| method | `GET` |
| URL | `https://www.googleapis.com/customsearch/v1` (module constant) |
| query parameters | exactly `cx` (engine id), `q` (the query, verbatim), `num` (the limit, as a decimal string) |
| header | `X-goog-api-key: <the key>` |
| body | none |

- **Why the key goes in a header.** Google APIs accept an API key either as the `key`
  query parameter or as the `X-goog-api-key` header. In the query string, the key would be
  part of the request URL, and a URL ends up in httpx exception text, proxy logs and access
  logs. In the header it never appears in a URL. Flip condition: the live check (DoD-13)
  shows the Custom Search JSON API rejecting the header. Then the plan must change. That
  change goes through the user, because the alternative puts the key in the URL; the coder
  does not switch it silently.
- Pass parameters through httpx's `params` mapping, not string formatting, so the query is
  encoded by httpx.
- No other parameter (no `safe`, `lr`, `gl`, `start` or `fields`). DoD-5 asserts the exact
  set.

## The Google response

- A 2xx status with a JSON **object** body is a success. Anything else is a failure (D5).
  That includes 3xx: httpx does not follow redirects by default, and none is expected.
- `items` absent → zero results (success). `items` present but not a list → failure.
- For each element of `items`, in order:
  - not an object, or `link` missing or not a string → skip the element;
  - `title` / `snippet` missing or not a string → `""` for that field;
  - otherwise the web result is (`title`, `link` as `url`, `snippet`).
- Keep at most `limit` results.
- Use the plain-text `title` / `snippet`, never `htmlTitle` / `htmlSnippet`.
- Whitespace is **not** normalised here. The provider returns the strings as Google sent
  them; formatting is the adapter's (`002`).

## Exception mapping (mirrors `LlmClient`)

Catch `httpx.TimeoutException` and `(httpx.HTTPError, httpx.InvalidURL)` around the
request. A non-2xx status, a JSON decode error, and a non-object body or non-list `items`
are handled after the response. Every path raises `ToolFailedError(detail={"tool":
"web_search"})` **from None**. Use the constructor shape frozen in 021 `001`'s
`## Skeleton`. Do not interpolate the status, the URL or the body into the message. The
default message of `ToolFailedError` is fine.

## The settings fields

- Field names are the skeleton's choice. Prose names: the search API key and the search
  engine id. The aliases are exact: `SEARCH_CSE_KEY`, `SEARCH_CSE_ID`.
- An empty string from the environment stays an empty string. "Configured" (both
  non-blank after trimming) is decided in `002`, not here.
- The key's type masks it in `repr` (pydantic's secret string). Step `002`'s router reads
  the plain value from it.

## The conftest amendment

Inside the existing autouse fixture `isolated_settings_environment`, add: before each
test, set `SEARCH_CSE_KEY` and `SEARCH_CSE_ID` to `""` in the process environment, and
restore them afterwards (pytest's `monkeypatch.setenv` does both). Keep the existing
`RPHELPER_*` deletion and both `cache_clear()` calls as they are. Environment values
override `.env`-file values in pydantic-settings, which is why the plan uses `""` rather
than deletion (D12). Tests that need values set them after the fixture has run (their own
`setenv`, init arguments, or a `get_settings` override). DoD-2 deletes both variables
inside the test and disables the env file explicitly (`_env_file=None`).

## Gotchas local to this step

- Pass `transport` to `httpx.AsyncClient` only when it is given. The default `None` means
  the real transport, exactly as `LlmClient` does.
- `request.extensions["timeout"]` on an httpx request is a dict with `connect`, `read`,
  `write` and `pool`. `httpx.Timeout(t)` sets all four to `t`. DoD-9 relies on this.
- An exception raised `from None` still has `__context__` set, but `__cause__` is none and
  `__suppress_context__` is true, so tracebacks omit the httpx exception. DoD-8 asserts
  the last two.
