# Step 002 — The `web_search` Tool adapter and its configuration-gated registration

## Goal

Implement 021's `Tool` protocol for `web_search` in `services/tools/web_search.py`. `run`
passes only the query to a provider and formats the web results into content and a summary
(D5–D9). Make `web_search` reach the model only when the instance is configured: a factory
in the adapter module, a request-time registry builder in `seam.py`, and the registry
dependency in `routers/stream.py` reading the two settings (D3). Amend the one 021 test
assertion that the new import makes false.

## Interface intent

**`app/services/tools/web_search.py`** (new)

- **A result-count constant**: 5 (D9).
- **The adapter class**. It implements 021's `Tool` protocol structurally.
  - `name` is `web_search`.
  - Construction takes a web search provider (step `001`'s protocol). Tests pass a Google
    provider built over a `MockTransport`, or any object that satisfies the protocol.
  - **async `run(scope, connection, arguments)`** returns a `ToolOutcome`:
    1. It reads `query` from `arguments`. If `query` is missing, is not a string, or is
       blank after trimming, it raises `ToolFailedError` with detail `{"tool":
       "web_search"}`, and the provider is never called. It reads no other key, and it
       uses neither the scope nor the connection (D8).
    2. It awaits the provider's search with the query exactly as given and the
       result-count constant.
    3. It returns `ToolOutcome(content, summary)`, built by the formatter.

    Provider errors propagate unchanged (D5). It logs nothing (D7).
- **Formatter** (module-level, pure). It takes the ordered web results and returns the
  content and the summary, per `002.context.md`.
- **Factory** (module-level). It takes an API key and an engine id, each a string or none.
  When both are present and non-blank after trimming, it returns an adapter over step
  `001`'s Google provider, built from the trimmed values with that provider's defaults.
  Otherwise it returns none. This is the one place that decides "configured" (D3).
- **Import shape.** This module uses the same form as 026's and 027's adapters
  (`002.context.md`).

**`app/services/tools/seam.py`** (021-owned, changed)

- **Registry builder** (new). It takes the API key and the engine id, each a string or
  none. It returns a **new** read-only name → `Tool` mapping: every entry of the
  production registry constant (the same instances), plus `web_search` mapped to the
  factory's adapter when the factory returns one. The constant is not mutated. Nothing
  else in the seam changes: not the constant, not `offered_tools`, not `dispatch`.

**`app/routers/stream.py`** (021-owned, changed)

- **The production tool-registry dependency** (021 `006`'s, frozen name) now also takes
  the settings through `Depends(get_settings)`. It returns the registry builder's result
  for the settings' search key (its plain value, or none) and engine id. Its role is
  unchanged: it is still the overridable dependency the compose route passes to the
  source. No route changes.

## Definition of done

1. `[test]` **Content.** For web results ordered A, B, C, the formatter's content is three
   blocks in that order, joined by `\n\n`. Each block is the title line, `\n`, the url
   line, `\n`, the snippet line, per `002.context.md`. A title or snippet containing
   newlines, tabs and runs of spaces is rendered on one line with single spaces and no
   leading or trailing whitespace. (D9, `002.context.md`)
2. `[test]` **Empty fields.** A result with a blank title renders the title line
   `(untitled)`. A result with a blank snippet has no snippet line: the block is the title
   line, `\n`, the url line. (`002.context.md`)
3. `[test]` **Zero results is success.** No results gives content exactly
   `No web results.` and summary exactly `0 results`. (`002.context.md`)
4. `[test]` **Summary.** For three results the summary is exactly `3 results`, and for
   one it is `1 results`. No summary contains the query or any title, url or snippet text.
   (021 D6, D7)
5. `[test]` **What leaves the instance.**
   - Setup: `run` on an adapter whose Google provider uses a recording `MockTransport`
     (200, two items), with arguments `{"query": "Kentish idiom 'to be in the doldrums'",
     "user_id": "<other user id>", "session_id": "<other session id>"}` and a `ToolScope`
     carrying seeded ids.
   - Exactly one request is sent. Its `q` is the query verbatim and its `num` is `5`.
   - No decimal string of any id (the scope's or the arguments') appears anywhere in the
     request URL or headers.
   - The outcome equals the formatter's output for the two items.

   (D6, D8, US-071.AC-1)
6. `[test]` **Bad arguments.** `run` with `{}`, with `{"query": 7}`, and with
   `{"query": "   "}` raises `ToolFailedError` with detail `{"tool": "web_search"}`, and
   the transport receives no request. (D5, `002.context.md`)
7. `[test]` **Factory.** It returns none when the key or the engine id is none, empty, or
   whitespace only, in every combination where at least one is unusable. With `test-key`
   and `test-cx` it returns an object whose `name` is `web_search`. (D3)
8. `[test]` **Registry builder.**
   - With either credential blank or none, its keys are exactly `memo_search` and
     `session_search`, and each value is the same object as in the production registry
     constant.
   - With both credentials set, its keys are exactly those two plus `web_search`.
   - Afterwards the constant still has exactly its two keys, and attempting to assign
     into the returned mapping raises.

   (D3)
9. `[test]` **Offered at the seam.**
   - With the builder's configured registry and all three switches on, `offered_tools`
     returns the three declarations in declaration order. The `web_search` one is
     identical to `definitions.py`'s.
   - With `tool_web_search` off, it returns `memo_search` and `session_search` only.
   - With the builder's unconfigured registry and all switches on, it returns
     `memo_search` and `session_search` only.

   (US-073.AC-1, D3, 021 D5)
10. `[test]` **Offered at the route.**
    - Setup: `POST …/zone/compose` with the **real** registry dependency (not overridden),
      a `get_settings` override pointing at a file-local database, and a fake chat client
      that records its tools and yields only text.
    - With credentials `test-key` / `test-cx` and no tool switch set, the recorded tools
      are the three declarations in order.
    - With the session's `tool_web_search` raw-set to false, `web_search` is absent and
      the other two remain.
    - With the switch on and the key blank, `web_search` is absent. Likewise with the
      switch on and the engine id blank.
    - No test in the file makes a network request.

    (US-073.AC-1, D3)
11. `[test]` **Success through the real seam.**
    - Setup: 021's `dispatch` gets a registry holding an adapter over a `MockTransport`
      Google provider (200, three items), `web_search` among the offered names, a
      `ToolScope` for user A's session, and arguments `{"query": "Valmy 1792 weather"}`.
    - It returns a tool-result frame with tool `web_search` and summary `3 results`.
    - Its tool message content equals the formatter's content for those three items.
    - One ok tool row is written with `tool_name` `web_search`.

    (US-070.AC-1, US-071.AC-1, UC-055 main flow, 021 D6)

      `tool_failed`.
    - Its tool message content is exactly `The tool failed. Continue without its result.`
    - It writes one failed tool row.
    - A loguru sink capturing every level during the dispatch records nothing that

    (UC-055 exception flow, R9, D5, D7)
