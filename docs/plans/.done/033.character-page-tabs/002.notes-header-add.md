# Step 002 — notes: list layout, header '+', inline draft with Save/Cancel

## Goal

Give the shared `MemoLevelGroup` an opt-in "header add" mode — a '+' icon button
beside the group's title that opens the new-note draft inline at the top of the
list with Save and Cancel icon buttons and no blur-save — and switch the
character page's Notes section to it with the list layout (D6). The wall and
Settings keep today's behaviour.

## Interface intent

- **`discardNewNote`** (new free function in `memoLevelState.ts`) — takes the
  level state; closes an open new-note draft (sets it back to "no draft") without
  any request. Does nothing when no draft is open or while the draft's save is in
  flight.
- **`MemoLevelGroup` opt-in prop** (a boolean, e.g. "header add") — when on:
  - a '+' `IconButton` (`IconPlus`, label **"New note"**) renders in the group's
    header next to its Title, in the ready state only, disabled while a draft is
    open;
  - the labelled "New note" button below the list is **not** rendered;
  - the draft renders as the first list item, its editor autofocused, with two
    `IconButton`s: **"Save new note"** (`IconDeviceFloppy`) calling the existing
    `saveNewNote`, and **"Cancel new note"** (`IconX`) calling `discardNewNote`;
    both disabled while saving; the draft's failure text renders inside the draft
    item;
  - focus leaving the draft does **not** save.
  When off (default), the group behaves exactly as today.
- **`CharacterNotesSection`** — passes the opt-in and `layout="list"` (was
  `"grid"`); keeps `reorderable`, its own `DndContext` and the shared `memoDnd`
  sensors.

## Definition of done

1. DoD-1 [test] `discardNewNote` on an open, not-saving draft clears it and makes
   no request; while a save is in flight it leaves the draft unchanged; with no
   draft open it is a no-op. (D6)
2. DoD-2 [test] On the character page's Notes section, a "New note" icon button
   sits in the section header beside the "Notes" heading, and no labelled
   "New note" button renders below the list. (D6)
3. DoD-3 [test] Activating '+' opens an empty draft as the first item of the list,
   with focus in its editor and "Save new note" / "Cancel new note" buttons; '+' is
   disabled while the draft is open. (D6)
4. DoD-4 [test] "Cancel new note" removes the draft and sends no request; '+' is
   enabled again. (D6)
5. DoD-5 [test] "Save new note" with non-blank text sends exactly one create for
   the character level, and on success the new note appears first in the list and
   the draft closes. (D6, UC-042)
6. DoD-6 [test] "Save new note" with blank text sends no request and closes the
   draft. (D6, existing blank rule)
7. DoD-7 [test] In opt-in mode, moving focus out of the draft editor (without
   pressing Save) sends no request and leaves the draft open with its text. (D6)
8. DoD-8 [test] A failed save shows the failure inside the draft item and keeps
   the typed text; Save and Cancel are disabled while the save is in flight. (D6)
9. DoD-9 [test] Without the opt-in, `MemoLevelGroup` renders the labelled
   "New note" button below the list, no header '+', and the draft still saves on
   focus leaving it — i.e. the wall and Settings are unchanged. (D6)
10. DoD-10 [test] Character notes remain reorderable by keyboard in the list
    layout, and a reorder still sends the level's whole order. (US-102)
11. DoD-11 [manual/live] Character notes render as a single-column list, not a
    grid; tooltips show on '+', Save and Cancel.
