# Step 003 — setups: header '+' and inline create form

## Goal

Replace the Setups section's labelled "New setup" button with a '+' icon button in
the section header that opens an inline create form (Name + Description, Save and
Cancel icon buttons, failure inline) at the top of the list; edit stays in
`SetupModal` (D7).

## Interface intent

- **`SetupCreateForm`** (new component, `src/app/SetupCreateForm.tsx`) — inline
  create form for one character's setup. Inputs: the character id, a callback
  invoked with the created setup on success, and a cancel callback. Builds a
  **fresh `SetupDraft` per mount** (it is conditionally mounted), renders a Name
  `TextInput` and a Description `MarkdownEditor` bound to the draft, the draft's
  general/field server errors inline, and two `IconButton`s: **"Save setup"**
  (`IconDeviceFloppy`) running the existing `submitSetup` in create mode, and
  **"Cancel new setup"** (`IconX`) calling the cancel callback with no request.
  Save is enabled exactly when the draft's existing submit guard allows; both
  buttons are disabled while submitting. Name is focused on mount.
- **`SetupsSection`** — header Group: "Setups" Title, a '+' `IconButton`
  (`IconPlus`, label **"New setup"**, disabled while the inline form is open), and
  the unchanged "Show archived setups" switch. The labelled "New setup" button is
  removed. A component-local open flag mounts `SetupCreateForm` **above** the
  list (above the table, the empty line or the load states). On success the
  created setup is applied to the section's list (as the modal's create did), then
  the form unmounts. `SetupModal` is no longer opened for create; Edit from the
  row menu still opens it.

   button and the "Show archived setups" switch; no labelled "New setup" text
   button remains. (D7)
2. DoD-2 [test] Activating '+' shows an inline form above the list with an empty
   Name, an empty Description, and "Save setup" / "Cancel new setup" buttons; no
   modal dialog opens; '+' is disabled while the form is open. (D7)
3. DoD-3 [test] "Cancel new setup" removes the form and sends no request. (D7)
4. DoD-4 [test] Saving with a name (and optional description) sends exactly one
   setup create for this character carrying the entered name and description; on
   success the new setup appears in the list and the form closes. (D7, UC-020,
   US-023)
5. DoD-5 [test] A server failure on save renders inside the form, keeps the
   entered values, and the form stays open; Save and Cancel are disabled while
   the save is in flight. (D7)
6. DoD-6 [test] Save is disabled when the draft's own validation refuses (e.g. a
   blank name), matching the modal's Create guard. (D7)
7. DoD-7 [test] Reopening the form after a cancel or a save starts from empty
   fields (fresh draft per open). (forms-and-lists.md draft lifetime)
8. DoD-8 [test] Edit from a row's menu still opens `SetupModal` prefilled, and
   archive/restore and the archived toggle behave as before; with no setups the
   neutral line "No setups yet." still renders. (D7, US-087)
9. DoD-9 [manual/live] Tooltips show on '+', Save and Cancel; the form sits at the
   top of the Setups tab.
