# Step 003 — step-specific context

Feature-wide facts are in `context.md` (D5 for the URL surface and why the mutations are
named action routes, D9 for path ids, D11 for what is *not* on this router, the
routers-versus-services rule, R5). Only what is narrow to this step is below.

## Borrowed interfaces, by module path and role

- **`backend/app/dependencies.py`** (`004/002`, new top-level leaf; imports `fastapi`;
  nothing under `db/` or `services/` imports it) — holds `require_user`, the
  **`require_role(min_role)` dependency factory**, `CurrentUser`, and a cookie writer and
  clearer. `require_role` resolves the caller from the session cookie exactly as
  `require_user` does, compares through `roles.py`'s pure predicate, raises
  `insufficient_role` (**403**) below the rung, and yields the same `CurrentUser`. **No
  session is 401, not 403** — the ordering is `004/002` DoD-9's and DoD-3 of this step
  re-asserts it here. `CurrentUser` is "a plain immutable value object, not a pydantic
  model, not an ORM row", carrying id, username and role, the role read live.
  **As of the end of `004`, `require_role` has zero consumers — `004/context.md` C4 names
  this feature as its first.**
- **`backend/app/models/ids.py`** (built, `001`) — `SnowflakeOut = Annotated[int,
  PlainSerializer(str, return_type=str)]` and `SnowflakeIn = Annotated[int,
  BeforeValidator(lambda v: int(v))]`, re-exported from `app/models/__init__.py`.
- **`backend/app/services/users.py`** (step `002`) — the six operations and their three
  errors. Their argument order and result shape are that step's Interface intent; do not
  restate them.
- **`backend/app/db/engine.py`**'s connection dependency (`001/005`) — yields a Core
  `Connection`, **opens no transaction**.
- **`backend/app/main.py`** (built, `001/006`) — `create_app()` with a frozen ordering and
  a lifespan that runs no DDL; a router is added with **one appended
  `app.include_router(...)` line**.

## Router conventions this step follows

- A router **declares its own prefix**: the built precedent is
  `APIRouter(prefix="/api", tags=["health"])` in `routers/health.py`; `004/003`'s auth
  router carries `/api` and spells `/auth/...` per route because `GET /api/me` sits at the
  prefix root. This router has no such exception, so the whole prefix
  (`/api/admin/users`) belongs on the `APIRouter`.
- **Guard dependencies attach to the router, never per handler** — `003/003`'s
  `require_unconfigured`, whose DoD-4 tests that a second route on the same router is
  still refused. DoD-4 here is that same test.
- **Routes always return a pydantic model** — never a bare dict, never a bare list, never
  a hand-built `JSONResponse`. Nothing on this router sets a cookie, so no handler takes
  FastAPI's `Response`.
- Direction is strictly `routers → services → db`. `models/` is imported by both and
  imports neither.

## The route table this step implements

`context.md` D5 holds it. Two details that live only here:

- **`{user_id}` is the only path parameter**, on the four id-addressed routes.
- **Create is `POST` at the collection path**, so `POST /api/admin/users` and
  `GET /api/admin/users` share a path and differ by method — the ordinary REST reading,
  and the reason the four mutations sit one segment deeper under a verb rather than
  colliding with it.

## What a cross-route test needs

DoD-8..DoD-12 assert behaviour that is only observable through **other features'** routes
— `GET /api/me` (`004/003`) and `POST /api/auth/login` (`004/003`). That is deliberate:
"disabling ends that user's sessions" has no observable form inside this router. The test
module builds its own `TestClient` over the whole app (there is no shared `app` or
`client` fixture) and drives both routers, which is allowed and is how US-009.AC-1 and
US-010.AC-1/AC-2 get verified at all.

## Gotchas

- **401 before 403.** A request with no cookie at all must answer 401, not 403 — the
  order is `require_role`'s and a test that only checks "refused" would pass on the wrong
  status and break the frontend's 401-navigation rule.
- **Do not add a `GET /api/admin/users/{id}`.** Nothing needs it: the page loads the full
  set and re-loads after every mutation, and every mutation answers with the affected
  row. An unused read route on this router is one more surface R5 has to be argued about.
- **No query parameters at all**, including an innocuous `?enabled=true`: the no
  sorting/filtering/pagination rule is `ui-conventions.md`'s and it is a decision, not an
  omission.
- **The generator comes from application state** (`app.state.id_generator`, `001`'s
  single instance), resolved in the handler and passed down — never imported as a module
  global. `004/003` DoD-13 holds the same line for the login route.
