# Step 003 — The admin users router, behind one router-level `require_role(Role.admin)`

## Goal

Expose account management as six routes that own HTTP and nothing else, guarded once at
the router so a route added later cannot forget the guard, and register it in the app
factory.

## Source files

```
backend/app/models/admin_users.py
backend/app/routers/admin_users.py
backend/app/main.py
```

## Test files

```
backend/tests/test_admin_users_router.py
```

## Interface intent

**`backend/app/models/admin_users.py`** — the pydantic request and response models for
this router and nothing else. There is no `schemas/` directory; models live in
`app/models/` beside `health.py`, `ids.py`, `bootstrap.py` and `auth.py`.

- **An account model** — the response shape every route here answers with: the account's
  **id**, username, role, enabled flag and `last_login_at` (nullable). The id field uses
  `001`'s **outbound** snowflake alias from `app/models/ids.py`, so it serialises as a
  **decimal string**; a bare `int` id field is the defect. It carries **no password, no
  hash, no token, no language default and no count of anything** (R5, UC-066).
- **A list-response model** wrapping the accounts under one field. A route returns a
  pydantic model, never a bare list and never a `JSONResponse`
  (`backend-structure.md`), and a wrapper leaves room for a later field without
  changing the body's type.
- **A create-request model** carrying a username, a plaintext password and a role, with
  the username and the password constrained **non-empty** by a field constraint — the
  same defensive backstop `003`'s D16 and `004/003` chose, answered by FastAPI's own
  **422** rather than the domain-error envelope, adding **no new domain error code**.
  Values are used exactly as received: no trimming, no case folding, no normalization.
- **A set-password request model** carrying one non-empty plaintext password. **No
  current password field** (`context.md` D6).
- **A set-role request model** carrying one role.

**`backend/app/routers/admin_users.py`** — the router, owning HTTP and nothing else: no
business rule, no SQL, no password handling, no transaction.

- It declares its own prefix, following the precedent `routers/health.py` set
  (`APIRouter(prefix=…, tags=…)`), and **carries `require_role(Role.admin)` as a
  router-level dependency** — attached to the router, never per handler, exactly as
  `003/003` attached `require_unconfigured` (`backend-structure.md`, "Authorization as
  router dependencies").
- Six routes, at the paths `context.md` D5 fixes: list, create, disable, enable, set
  password, set role. Every one of them takes the connection dependency from
  `app/db/engine.py`; create additionally takes the process's snowflake generator
  resolved from **application state**, never a module global; set-role additionally takes
  the `CurrentUser` the guard yields and passes **its id** to the service as a plain
  argument.
- Each route calls exactly one `services/users.py` operation and maps its plain result
  onto the account model. **Create answers 201**; the other five answer **200**. No route
  translates a domain error by hand — the base-class handler `001` registered renders
  `username_taken` as 409, `user_not_found` as 404 and `self_role_change_refused` as 409
  on its own.
- The `{user_id}` path parameter is declared with `001`'s **inbound** snowflake alias
  (`context.md` D9): it arrives as a decimal string and reaches the service as an `int`,
  with no `int()` call in the handler and no bare `int` path type.
- **No route is keyed on anything but an account**, and there is no route that returns a
  count, a session, a character or anything a user owns (R5, UC-066). No query parameter
  exists anywhere on this router: no filter, no page, no sort.

**`backend/app/main.py`** — include the router in the app factory with one appended
`app.include_router(...)` line, beside health, bootstrap and auth. Nothing else changes:
the factory's frozen ordering stands and the **lifespan still runs no DDL**.

## Definition of done

1. `[test]` `GET /api/admin/users` with a live **administrator** session answers 200 with
   every account, each carrying id (a **decimal string**, never a JSON number), username,
   role, enabled flag and `last_login_at`. (US-011.AC-1)
2. `[test]` No response on this router carries a password, a hash, a token, a language
   default, or any field or count relating to a character, setup, session, entry or memo
   — and the router declares **no route** that could return one. (US-011.AC-2, UC-066,
   R5)
3. `[test]` **Every** route on this router answers **403** with the `insufficient_role`
   envelope for a live **roleplayer** session, and **401** with the `not_authenticated`
   envelope when there is no session at all — 401 and 403 in that order of precedence.
   (`admin-surfaces.md`, "Backend gating is independent and authoritative" — **no product
   id**)
4. `[test]` The guard is **router-level**: a route registered on this router that declares
   no dependency of its own is still refused for a roleplayer — the property that makes
   forgetting the guard on a future route impossible. (`backend-structure.md`,
   "Authorization as router dependencies"; the pattern `003/003` DoD-4 set — **no product
   id**)
5. `[test]` `POST /api/admin/users` answers **201** with the created account, which is
   **enabled** (US-008.AC-1) and appears in a subsequent `GET` (US-008.AC-2).
6. `[test]` Creating an account with an existing username answers **409** with the wire
   shape `{"error": {"code": "username_taken", …}}` and creates nothing.
7. `[test]` An empty username or an empty password is refused with FastAPI's **422**
   before anything is written, and that response is **not** the domain-error envelope.
8. `[test]` `POST /api/admin/users/{id}/disable` answers 200 with the account now
   disabled, and the target's **existing session cookie answers 401 on `GET /api/me`
   immediately afterwards** — the observable form of "disabling ends that user's active
   sessions". (US-009.AC-1)
9. `[test]` After the disable, `POST /api/auth/login` with that account's **correct**
   credentials is refused. (US-009.AC-2)
10. `[test]` `POST /api/admin/users/{id}/enable` answers 200 with the account enabled
    again, after which that account can log in and receives a **new** session; the
    sessions revoked by the earlier disable stay revoked. (UC-007's alternate flow)
11. `[test]` `POST /api/admin/users/{id}/password` answers 200; afterwards a login with
    the **old** password is refused (US-010.AC-1) and a login with the **new** password
    succeeds (US-010.AC-2). The response body carries no password and no hash.
12. `[test]` `POST /api/admin/users/{id}/role` answers 200 with the new role, and the
    target's **existing** session reports the new role on its next `GET /api/me` with no
    new login — the live-role read `004`'s D7 fixes. (`admin-surfaces.md`'s "Change
    Role"; `data-model.md`'s `users.role` — **no product id**)
13. `[test]` A role change whose target is the **calling** administrator answers **409**
    with `{"error": {"code": "self_role_change_refused", …}}` and changes nothing; the
    same target changed by a **different** administrator succeeds. (`admin-surfaces.md`'s
    "Change Role" — **no product id**)
14. `[test]` Every id-addressed route answers **404** with
    `{"error": {"code": "user_not_found", …}}` for an id no account has.
15. `[test]` A `{user_id}` sent as a decimal string beyond `Number.MAX_SAFE_INTEGER`
    round-trips correctly — it addresses that account and comes back as the same string —
    which is the JSON id boundary holding on a **path parameter** (`context.md` D9).
16. `[test]` The router issues no SQL and holds no rule: its only database contact is
    through the connection dependency, every stored value comes from the service, and the
    generator it passes down comes from application state rather than a module global.
17. `[manual/live]` The router declares exactly the six routes at the paths `context.md`
    D5 fixes, carries `require_role(Role.admin)` **once, on the router**, and no handler
    declares an authorization dependency of its own. Verifier confirms by reading the
    module.
18. `[manual/live]` `main.py`'s lifespan still runs no DDL, and the router registration is
    the only change to the factory. Verifier confirms by reading it.
19. `[manual/live]` `uvicorn app.main:app` on port 8184 starts; against a bootstrapped
    database, an administrator's cookie can create, disable, re-enable, set a password and
    change a role through `curl`, and a roleplayer's cookie is refused on all six routes.
20. `[manual/live]` `mypy app`, `ruff check .` and `pytest` all pass from `backend/`.
