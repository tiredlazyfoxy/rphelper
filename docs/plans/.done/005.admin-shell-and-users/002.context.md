# Step 002 — step-specific context

Feature-wide facts are in `context.md` (D3 for where account management lives, D4 for the
revoke helper's transaction rule, D6 for the password-reset posture, R5, the redaction
rule, the routers-versus-services rule). Only what is narrow to this step is below.

## Borrowed interfaces, by module path and role

- **`backend/app/errors.py`** (built, `001`) — `DomainError` with `code` and
  `http_status` as **class attributes each subclass sets**, per-instance `message` and
  `detail`, and a render method producing `{"error": {code, message, detail}}`. **One
  handler is registered for the base class**, with the decorator form; a subclass adds
  none. Existing subclasses at this point: `secret_ref_missing`/500 (`001`),
  `already_configured`/409 (`003`), `invalid_credentials`/**400**, `not_authenticated`/401,
  `insufficient_role`/403 (`004`). `account_disabled` was **struck** by `004`'s D1 and is
  never added.
- **`backend/app/services/passwords.py`** (`003/001`) — argon2-cffi, Argon2id, the
  **library's own default parameters**, and **no cost literal anywhere in `app/`**. A
  hash operation (plaintext → self-describing encoded string, fresh salt per call) and a
  verification operation (encoded hash + candidate → bool, **false rather than raising**
  on a wrong password or a malformed hash).
- **`backend/app/services/auth.py`** (`004/001` + this feature's step `001`) — the bulk
  revoke-for-one-user helper, which takes a `Connection` and a user id, **opens no
  transaction**, and returns the count of rows it revoked.
- **`backend/app/roles.py`** (`003/001` + `004/002`) — the two-member string enum whose
  **values** are the strings the `role` column stores (`"roleplayer"`, `"admin"`, never
  the member names), plus `ROLE_LADDER` and a pure "at least this rung" predicate. It is
  a leaf module with **no `fastapi` import**, which is what lets `db/schema.py` import it;
  this service imports the enum for the role argument's type and uses no ladder logic —
  authorization is the router's.
- **`backend/app/ids.py`** / `app.state.id_generator` (`001`) — the snowflake generator.
  It is **passed in** as an argument, exactly as `004/001`'s open-session operation takes
  it; the service never reaches a module global.
- **`backend/app/db/engine.py`**'s connection dependency (`001/005`) — yields a Core
  `Connection` and **opens no transaction**, which is why every write here opens its own
  `with conn.begin():`.

## The `users` columns this step writes

Ten after step `001`: `id`, `username` (unique index), `password_hash`, `role` (text +
CHECK via SQLAlchemy Core `Enum` with native types disabled), `is_enabled`, `rp_language`,
`preferred_language`, `created_at`, `updated_at`, `last_login_at`. The full list and its
nullability live in `data-model.md`'s `users` section and in `003/001`'s Interface intent;
do not restate them.

**The service never writes `rp_language` or `preferred_language`.** They are user-level
defaults owned by FEAT-013 / UC-047, this feature offers no field for them, and inventing
a value would be inventing a requirement (`003`'s D15 made the same call).

## The duplicate-username translation, and its flip condition

`users` has exactly **one** unique constraint — `username` — so an integrity violation on
this insert can only be that collision, and translating it to `username_taken` needs no
message parsing. **Flip condition, recorded because the translation silently widens if it
is missed:** if `users` ever gains a second unique constraint or unique index, the
translation must be narrowed to the username one before that column ships.

A check-then-insert was rejected: SQLite has a single writer, but a SELECT that takes a
read lock and then upgrades can fail rather than serialise, and the index settles the
question anyway. A pre-check is allowed as an optimisation only if the integrity
translation stays as the authority.

## The acting administrator reaches the service as a plain id

The router resolves the caller through `require_role` and passes the **id** to the
set-role operation. The service must not import, receive or unpack `CurrentUser` — that
type lives in `app/dependencies.py`, which imports `fastapi`, and nothing under
`services/` may import it (`004`'s D8).

## Gotchas

- **The disable's ordering inside the block does not matter, but the block does.** Both
  writes are in one `with conn.begin():` in this module; the helper must not be called
  outside it, and this module must not open a second, nested one.
- **`user_not_found` is raised before any write**, including in the disable — a disable
  that revoked sessions for a non-existent user would be a silent no-op reported as
  success.
- **The result shape is one shape.** List, create, disable, enable, set-password and
  set-role all return the same plain account result, so the router has one response model
  to map. Do not let set-password return a narrower one "because nothing changed".
- **No delete.** Accounts disable and re-enable and are **never deleted**
  (`data-model.md`, `ui-conventions.md`'s per-entity table). A delete operation here is
  out of scope even as a private helper.
