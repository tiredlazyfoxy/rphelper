# Step 004 — The admin gate: one `/api/me` round-trip before anything mounts

## Goal

Make the `admin` entry decide, before it renders anything at all, whether the caller is
an administrator — mounting for one outcome, navigating for two, and rendering a
not-ready or a failure screen for the other two without ever treating a 502 as a deny.

## Interface intent

**`frontend/src/admin/adminAccess.ts`** — the gate's logic, split pure from impure
(`admin-surfaces.md`, `frontend-structure.md`).

- **A decision type** naming the five outcomes `context.md` D13 fixes: granted, denied
  because there is no session, denied because the role is below administrator, not ready,
  and failed. It is a small union of string literals, not a class and not an enum.
- **A pure, total decision function over the fetched identity** — `admin-surfaces.md`'s
  `resolveAdminAccess(currentUser)`. It takes the identity or nothing and returns one of
  granted / denied-no-session / denied-not-admin. It performs no fetch, touches no
  router, reads no DOM and navigates nothing, so its whole table is unit-testable with
  none of the three. The identity's **id is a `string`** and is not read by this function
  at all; only the role decides.
- **A second pure function classifying a thrown value** into not-ready or failed. The
  not-ready judgement is **delegated to the predicate in
  `frontend/src/shared/notReady.ts`** (`003/004`) and is not re-decided here: this module
  defines no error-code string and no status literal of its own. Everything the predicate
  rejects — including a well-formed 403 or 500 envelope, and a value that is not an
  `ApiError` — is *failed*. A 401 never reaches this function (see the impure half).
- **An impure enforce function**, optionally taking an `AbortSignal`. It requests
  `GET /api/me` through `frontend/src/shared/api.ts`, feeds a success to the pure
  decision function and a throw to the pure classifier, and returns the resulting
  decision. It performs exactly one navigation, and only for **denied-not-admin**: a
  document navigation to `/`, through the **document-navigation seam `shared/api.ts`
  exports** (`context.md` D14). For **denied-no-session** it navigates **nothing** — the
  shared client has already navigated to `/login` on the 401 and then thrown, and a
  second navigation would race it. For not-ready and failed it navigates nothing and
  renders nothing itself. A caller's own `AbortSignal` firing propagates unwrapped, as
  `002`'s D8 requires, and is not classified as a failure.
- **The re-probe interval**, as a module constant: **2000 ms**, fixed, uncapped, no
  backoff (`context.md` D13, following `003`'s D11).

**`frontend/src/admin/AdminNotReady.tsx`** — one **stateless presentational** component
covering the two rendered outcomes. It takes which of the two it is showing, an optional
message to render in the failed case, and a retry callback. It holds no state, no store
and no timer, so the retry loop stays in the boot code that owns the React root. It
renders a short statement worded as a **wait rather than a fault** for not-ready
(`deployment.md`: this is a deployment fact, not a bug) and the carried message for
failed, plus a **visible manual retry control** in both. It calls `notifyFailure` nowhere
and imports no stylesheet.

**`frontend/src/admin/main.tsx`** — the placeholder route table is **replaced
wholesale**, as `002/006` anticipated. The module's boot becomes:

1. find the mount element, exactly as `002/006` built it;
2. **await the gate before creating a root** — nothing at all is rendered while the
   request is in flight, not a spinner and not a frame (`admin-surfaces.md`);
3. **granted** → create the root and render `shared/AppProviders` wrapping
   `BrowserRouter basename="/admin"` — exactly that string, **no trailing slash** —
   wrapping the admin application. At this step that application is still one catch-all
   route rendering an element carrying the entry's stable `data-entry="admin"` marker;
   step `005` replaces it with the shell and the real route table;
4. **denied-not-admin** and **denied-no-session** → render nothing at all; no root is
   created;
5. **not-ready** and **failed** → create the root and render `AppProviders` wrapping
   `AdminNotReady`. In the **not-ready** case only, the boot re-runs the gate on the
   fixed 2000 ms interval until it returns something else, then renders that outcome into
   the **same root**; the **failed** case does not auto-retry. The manual retry control
   re-runs the gate immediately in both.

The module reads no id, imports no stylesheet (`global.css` arrives through
`AppProviders`, and `shell.css` is the `app` entry's alone), creates no store, and holds
no MobX state.

## Definition of done

1. `[test]` The pure decision function is **total** over its input: an identity whose role
   is administrator gives granted, an identity whose role is below it gives
   denied-not-admin, and nothing-fetched gives denied-no-session. It is callable with no
   network, no router and no DOM. (`admin-surfaces.md`, "The pure/impure split is kept" —
   **no product id**)
2. `[test]` The pure classifier answers **not-ready** for exactly what
   `shared/notReady.ts`'s predicate accepts — the transport-failure code at status 0, and
   the malformed-body code at 500, 502, 503 and 504 — and **failed** for a well-formed
   backend envelope at 403, for one at 500, for the malformed-body code at a 4xx status,
   and for a value that is not an `ApiError`. (`deployment.md`'s not-ready gate case —
   **no product id**)
3. `[test]` The enforce function issues exactly **one** `GET /api/me` per call and no
   other request.
4. `[test]` A 401 from `/api/me` yields denied-no-session and the gate itself performs
   **no navigation** — the shared client's own `/login` navigation is the only one, and
   it is not doubled. (`admin-surfaces.md`'s deny table — **no product id**)
5. `[test]` An identity whose role is below administrator yields denied-not-admin and the
   gate performs exactly **one** document navigation, to `/` — not to `/login`, and the
   session is not ended. (`admin-surfaces.md`'s deny table — **no product id**)
6. `[test]` A transport failure and a 502 on `/api/me` yield not-ready and the gate
   performs **no navigation at all** — in particular none to `/login`.
   (`deployment.md`: "a 502 or a network failure on `/api/me` is not a deny" — **no
   product id**)
7. `[test]` An abort of the caller's own signal propagates unwrapped and is classified as
   neither not-ready nor failed. (`002`'s D8 — **no product id**)
8. `[test]` `AdminNotReady` renders a waiting statement in the not-ready variant and the
   carried message in the failed variant, offers a visible retry control in both, and
   invokes its retry callback when that control is used.
9. `[test]` With `/api/me` answering an **administrator** identity, the entry mounts and
   renders its `data-entry="admin"` marker; with it answering **401**, the entry renders
   **nothing** — no marker, no frame, no spinner; with it answering a **non-admin**
   identity, the entry renders nothing and navigates to `/`.
   (`admin-surfaces.md`, "no flash of admin content" — **no product id**)
10. `[test]` With `/api/me` failing as a transport error, the entry renders the not-ready
    screen and **re-probes on a fixed 2000 ms interval** — a second request after one
    interval, a third after two — and once a probe returns an administrator identity the
    interval stops and the admin marker renders in the same document. A **failed**
    classification renders the failure screen and starts **no** interval.
11. `[test]` `002/006`'s entry assertions are repaired at **clause level**, not rewritten:
    the **admin** clauses of DoD-1, DoD-2, DoD-3 and DoD-4 now stub `GET /api/me` with an
    administrator identity before evaluating the entry, after which the entry still
    renders only its own marker, still renders inside `AppProviders`, still declares
    `basename="/admin"` with a location of `/admin/users` resolving against it, and still
    renders no other entry's marker. **The `bootstrap`, `login` and `app` clauses of that
    file are untouched.** (`context.md` D15)
12. `[test]` The `admin` entry issues **no request other than `GET /api/me`** during boot,
    and issues none at all before the mount element is found.
13. `[manual/live]` Nothing is rendered while `/api/me` is in flight — verified by reading
    `main.tsx`: no root is created before the gate resolves, and there is no loading
    element anywhere in the module. (`admin-surfaces.md`)
14. `[manual/live]` With the backend stopped and the dev server running, opening `/admin`
    shows the not-ready screen and **resolves to the admin area on its own** once the
    backend is started — no reload, no bounce to `/login`. (`deployment.md`'s
    not-ready gate case)
15. `[manual/live]` Both colour schemes are correct in both rendered states.
16. `[manual/live]` `npm run typecheck`, `npm test` and `npm run build` all pass from
    `frontend/`, and the build still emits exactly the four entry documents.

## Dependencies

None within this feature — it binds to the `GET /api/me` contract (`004/003`), not to
this feature's backend steps. Steps `001`–`003` are unrelated to it and may land in
either order.
