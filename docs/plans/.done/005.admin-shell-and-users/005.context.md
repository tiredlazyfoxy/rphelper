# Step 005 — step-specific context

Feature-wide facts are in `context.md` (D8 on the colour-scheme toggle, D11 on the absent
user menu, D12 on the nav table and `isNavItemActive`, D16 on the MobX rules, and the
no-third-stylesheet rule). Only what is narrow to this step is below.

## Borrowed interfaces, by module path and role

- **`frontend/src/admin/main.tsx`** (step `004`) — the gate and the five outcomes. The
  only edit here is what the **granted** branch renders.
- **`frontend/src/shared/AppProviders.tsx`** (`002/005`) — already wrapping the router in
  `main.tsx`; a component test that renders the shell or the 404 in isolation wraps in it
  too (`002/context.md`'s test conventions).
- **`frontend/src/shared/IconButton.tsx`** (`002/003`) — props are `icon` (a
  Tabler-shaped component type), a required `label` feeding **both** the tooltip and the
  `aria-label` with no override, a required `onClick`, optional `disabled`, optional
  `color` (applied to the `ActionIcon` only — the icon stays `currentColor`), and an
  optional `sizeVariant: "main" | "inline" | "chevron"` defaulting to `"main"`, mapping
  to 18/16/14 **all at stroke 1.5**. It renders a Mantine `Tooltip` around a `subtle`
  `ActionIcon`. **This step uses it nowhere** — see the `Burger` note below — and step
  `006` is its first consumer here.
- **`@tabler/icons-react`** `^3.40` — `IconUsers`, `IconServer2` and `IconDatabase` are
  the three glyphs `ui-conventions.md`'s icon table assigns to the admin nav.
- **`react-router-dom` 7** — `Routes`, `Route`, `Link` and the current-location hook.
  In-entry navigation is the router's; cross-entry navigation is a plain anchor.

## Mantine specifics this step depends on

- **`AppShell`** with `AppShell.Header`, `AppShell.Navbar` and `AppShell.Main`. The prop
  block is given verbatim in `admin-surfaces.md`'s Shell section; the skeleton agent
  reproduces it. `padding` omitted and no `aside` are both deliberate and are DoD-15.
- **`NavLink`** renders the nav rows; its `active` prop is driven by
  `isNavItemActive(pathname, item)` and **not** by react-router's `NavLink`.
- **`Burger`** is what `admin-surfaces.md` names for the mobile toggle. It is the one
  header control that does **not** go through `IconButton`, and the exception is real
  rather than an oversight: `Burger` is not an `ActionIcon` wrapping a Tabler icon — it
  draws its own glyph and takes its own `aria-label` — so the accessible-name problem
  `IconButton` exists to solve is solved by giving `Burger` an explicit label. Recorded
  here so a reviewer does not read it as a violation of `ui-conventions.md`'s "every
  icon-only action goes through `IconButton`".

## What `isNavItemActive` has to get right

The failure everyone writes first is `pathname.startsWith(item.path)`, which makes
`/database-backups` highlight the Database item and makes `/` highlight everything. The
rule is **whole-segment** matching:

- `exact` items match only when the paths are equal after normalising a trailing slash;
- non-exact items match when the pathname **is** the item's path or continues it at a
  `/` boundary.

No feature in this project has a `/database-backups` route; the case is in the DoD anyway
because `admin-surfaces.md` puts it there as the regression that must not happen, and
because a pure function is exactly where such a case is cheap to pin.

## Placeholders this step deliberately leaves

`/` renders a minimal placeholder naming the Users page. Step `006` replaces that one
route element wholesale — the same "later features replace their entry's route table"
posture `002/006` set for the entries. Nothing else in `AdminApp.tsx` moves at that
point.

## Gotchas

- **The marker moves, it is not duplicated.** Step `004` puts `data-entry="admin"` on the
  element the granted branch renders; here that element becomes `AdminApp` → `AdminShell`,
  and the marker goes on the shell's outermost element. Two markers in one document would
  break `002/006` DoD-1's "renders **only** its own marker" reading.
- **`useState(() => new AdminShellState())`, never `useMemo`** — `frontend-structure.md`
  is explicit that `useMemo` is a cache with no identity guarantee.
- **The navbar's opened flag is domain-shaped shell state, not a modal flag.** It lives
  in the MobX class because `admin-surfaces.md` says so; the *modal* open/target flags
  that arrive in steps `006`–`008` are component-local `useState` and must not join it.
- **No `padding` on `AppShell`.** A shell-level padding plus each page's own `Container`
  gives two nested gutters and a content column nobody intended.
