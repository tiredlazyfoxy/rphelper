# Step 005 — The admin shell: `AppShell`, the MobX shell state, the static nav table and the flat routes

## Goal

Give the admin area its frame — a Mantine `AppShell` with a header and a navbar, a
three-row static nav table highlighted by a pure active-match function, a flat four-route
table and the 404 element two of those routes render until `006` and `007` land.

## Interface intent

**`frontend/src/admin/adminShellState.ts`** — the shell's state and its free functions,
following `002`'s D2 and `003`'s D13 exactly.

- **A data class** holding **one observable field**: whether the navbar is opened. It is
  `makeAutoObservable(this, {}, { autoBind: true })` in the constructor and has **no
  methods and no computed getters**. Mantine's `useDisclosure` is **not** used —
  `admin-surfaces.md` records that custom hooks must not hold reactive state anywhere in
  this codebase.
- **Free functions** taking the data object and toggling, opening and closing the navbar.
  They are synchronous and pure-in-effect: no fetch, no navigation, no timer.

**`frontend/src/admin/navItems.ts`** — the nav declaration and its matcher.

- **A static table** of the three items `admin-surfaces.md` fixes — Users `/` `IconUsers`
  **exact**; LLM Servers `/llm-servers` `IconServer2`; Database `/database` `IconDatabase`
  — each carrying its label, its path, its Tabler icon component and its `exact` flag.
  **All three are declared now** (`context.md` D12); the last two render the 404 until
  their features land.
- **`isNavItemActive(pathname, item)`** — a **pure** function of two plain arguments
  returning a boolean, unit-testable with no router, no DOM and no render. It matches on
  **`/`-delimited path segments**, so a descendant route highlights its parent item, and
  it honours the `exact` flag for the root item (without which `/` matches everything).
  It is deliberately **not** react-router's `end` prop. The case that must not regress is
  **`/database` versus `/database-backups`**: a prefix that is not a whole segment is not
  a match.

**`frontend/src/admin/AdminShell.tsx`** — an `observer` component taking the shell state
**explicitly as a prop** and rendering its children inside the frame. Mantine `AppShell`
with `header={{ height: 56 }}` and `navbar={{ width: 220, breakpoint: "sm", collapsed: {
mobile: <navbar not opened> } }}`; **`padding` is omitted deliberately** (each page
brings its own `Container size="lg" py="md"`) and there is **no `aside`**
(`admin-surfaces.md`).

- **Header**: on mobile a Mantine `Burger` bound to the shell state through the toggle
  free function, then a `Title order={4}`; on the right a **real `<a href="/">`**
  back-to-app link — never a router `Link`, because the app area is a different document
  and because an anchor is what makes middle-click and ctrl-click open a new tab. There
  is **no user menu and no `ColorSchemeToggle`** (`context.md` D11, D8).
- **Navbar**: the static table mapped to Mantine `NavLink`s, each an in-entry router link
  with its icon at `size={18} stroke={1.5}` and its active state from
  `isNavItemActive(pathname, item)` against the current location. Selecting an item
  closes the navbar, so the mobile overlay does not stay over the page it just navigated
  to.
- It carries the entry's stable `data-entry="admin"` marker on its outermost element, so
  the marker sits **above** the `<Routes>` and is present on every admin route including
  the 404 (`004.context.md`, `context.md` D15).
- **No breadcrumbs** (three flat pages, each one click from the navbar), no stylesheet
  import and no `.css` file of any kind (`context.md`).

**`frontend/src/admin/NotFoundPage.tsx`** — the 404 route element: its own `Container
size="lg" py="md"`, a short statement that the page does not exist, and a router `Link`
back to the Users page. No image, no illustration, no automatic redirect.

**`frontend/src/admin/AdminApp.tsx`** — the admin application the gate mounts. It
instantiates the shell state through `useState(() => new AdminShellState())` — **never
`useMemo`** — passes it explicitly to `AdminShell`, and renders inside it a **flat
`<Routes>`** of exactly four elements: `/`, `/llm-servers`, `/database` and the catch-all
`*`. **No nested layout route and no `<Outlet/>`** — the shell renders above the
`<Routes>` (`admin-surfaces.md`). At this step `/` renders a **minimal placeholder**
naming the Users page, which step `006` replaces wholesale; `/llm-servers`, `/database`
and `*` all render the 404 element.

**`frontend/src/admin/main.tsx`** — one change: in the granted outcome the boot renders
`AdminApp` where step `004` rendered a marker element. Everything else about the module —
the gate, the two navigations, the not-ready retry loop, `AppProviders`, the
`basename="/admin"` router — is unchanged, and the marker moves with the shell rather
than being rendered twice.

## Definition of done

1. `[test]` `isNavItemActive` returns true for an item's own path, true for a descendant
   path (`/llm-servers/anything` matches the LLM Servers item), and false for an
   unrelated path. (`admin-surfaces.md`'s nav section — **no product id**)
2. `[test]` `isNavItemActive` does **not** match a non-segment prefix: `/database-backups`
   is **not** active for the `/database` item, in either direction. (`admin-surfaces.md`
   names this case explicitly — **no product id**)
3. `[test]` The root item is matched **exactly**: `/` is active for the Users item, and
   `/llm-servers` and `/database` are **not** — which is what the `exact` flag exists
   for. (`admin-surfaces.md` — **no product id**)
4. `[test]` `isNavItemActive` is callable with two plain arguments and no router, no DOM
   and no render, and the nav table declares exactly the three items
   `admin-surfaces.md` lists, with those paths and that `exact` flag on the root item.
5. `[test]` The shell state is a data class with **one observable field and no methods
   and no computed getters**, and its open, close and toggle free functions take the
   object and change that field. (`002`'s D2, `context.md` D16 — **no product id**)
6. `[test]` The shell renders a header, a navbar with the three nav items by their
   labels, and its children; the `Burger` toggles the navbar through the shell state, and
   selecting a nav item closes it.
7. `[test]` The back-to-app control is a real anchor whose `href` is `/` — not a router
   link — so it is a document navigation. (`admin-surfaces.md`, `frontend-structure.md` —
   **no product id**)
8. `[test]` The header renders **no user menu, no sign-out control and no colour-scheme
   toggle**. (`context.md` D8, D11 — **no product id**)
9. `[test]` The route table is **flat**: four route elements, with the shell rendered
   above them rather than as a parent layout route, and no `<Outlet/>` anywhere in the
   entry. (`admin-surfaces.md` — **no product id**)
10. `[test]` `/llm-servers` and `/database` render the **404** element at this stage, and
    an unknown path such as `/nope` renders it too — the declared-but-unbuilt rows are
    deliberate, not a bug. (`context.md` D12 — **no product id**)
11. `[test]` The 404 element offers a way back to the Users page and performs no
    automatic redirect.
12. `[test]` Navigating between `/` and `/database` inside the entry moves the active
    highlight and does **not** reload the document — in-entry navigation is the router's,
    while the back-to-app link is not.
13. `[test]` The entry's `data-entry="admin"` marker is rendered on **every** admin route,
    including `/llm-servers` and the catch-all, so `002/006`'s basename assertion keeps
    holding after the route table becomes real. (`context.md` D15 — **no product id**)
14. `[test]` The shell is instantiated once per mount through `useState` with an
    initializer: navigating between routes does not construct a second shell state, and
    the navbar's opened flag survives a route change.
15. `[manual/live]` The `AppShell` is configured with `header={{ height: 56 }}` and
    `navbar={{ width: 220, breakpoint: "sm", collapsed: { mobile: … } }}`, carries **no
    `padding`** and **no `aside`**. Verifier confirms by reading the module against
    `admin-surfaces.md`'s block.
16. `[manual/live]` No file under `frontend/src/admin/` imports a stylesheet or declares a
    `.css` of its own, and `src/app/main.tsx` is still the only module importing
    `shell.css`. Verifier confirms by reading the folder.
17. `[manual/live]` Both colour schemes are correct, and the navbar collapses and reopens
    correctly below the `sm` breakpoint.
18. `[manual/live]` `npm run typecheck`, `npm test` and `npm run build` all pass from
    `frontend/`.
