# Step 003 — step-specific context

- **User decision U1 (binding).**
  - A session export is imported into the character the roleplayer chooses (the
    Sessions section of that character's page; the UI is step 007).
  - The imported session takes that character's id. Its `setup_id` is null,
    because the export's persona and setup do not come along (US-082.AC-1/AC-2).
  - A foreign or missing target answers `character_not_found` (the existing
    `CharacterNotFoundError` in `app/errors.py`, 404).
  - An archived target is allowed.
- **Why the lookup does not reuse the character getter.** The existing getters may
  filter out archived rows. This lookup is a direct `select` on `characters` by `id`
  and `user_id` inside the import's transaction, the same choice 030 made for its
  export roots (`030/outcome.md`, "Root lookups for export").
- **Order of checks.** First envelope validation, which is pure. Then, inside the
  transaction, the target lookup. Then the remap and its reference checks. Then
  the writes. That order is what DoD-9 pins.
- **`start_session` is not reused.** It mints and seeds a zone message, but an
  import inserts rows exactly as exported.
- **Memo policy.** The session export carries only `scope='session'` memos of that
  session (US-081.AC-1). Anything else in the file did not come from 030, so it is
  malformed.
- **No step-local fixtures** beyond `context.md` §"Test conventions". Seed a source
  session under character X, export it with 030's `export_session`, and import it
  into character C, distinct from X, of the same caller.
