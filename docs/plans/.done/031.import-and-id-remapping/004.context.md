# Step 004 — step-specific context

## The user decision behind this step (U2, binding)

- **The database import is a REPLACE.** It is allowed only onto an "empty"
  instance: one with no users (the bootstrap path, which `fast/003` will call), or
  one with exactly one user who is an admin (the importing admin).
- **Ids are preserved** "for ID consistency". The target is empty or replaced, so
  nothing can collide.
- **It is one transaction.** After success the importing admin's own login is gone.
  The route clears the cookie (step 005), and the frontend sends them to `/login`
  (step 008).
- **It deviates** from `data-model.md`'s "mint unconditionally" import policy,
  which was written for the ACT-002 granularities (US-136). `outcome.md` records
  the deviation.

## Facts this step reads

- **Wipe order.** Reverse `schema.metadata.sorted_tables` deletes children before
  parents. One `DELETE FROM messages` is safe despite the self-FK, because SQLite
  checks an immediate FK at the end of the statement. `models` has
  `ON DELETE CASCADE` from `llm_servers`, but the reverse order deletes `models`
  first anyway.
- **Do not toggle `PRAGMA foreign_keys`.** The wipe and the insert run with FKs on.
  That is what turns a dangling payload reference into an `IntegrityError`, and so
  into a `malformed_payload` refusal.
- **Vec tables are dropped, not cleared** (orchestrator decision).
  - `memo_vec` / `session_vec` are 024's. They live outside `metadata`, so the
    `metadata` walk never touches them.
  - Drop each one by name, using 024's name constants, and only when
    `vector_table_dimension` reports it present.
  - **Why drop:** a vec0 table's declared dimension is the *previous* designation's.
    024's ensure-on-write (`ensure_vector_tables`, D2) re-creates both tables at the
    then-designated model's `embedding_dim` on the next qualifying write. So a
    restored instance never reports `dimension_mismatch` just because the restored
    designation has a different dimension.
  - Restored rows have no vectors until the rebuild (`fast/002`), whether the
    tables were dropped or cleared, so dropping loses nothing.
  - DDL is transactional (`backend-structure.md` §"Transactional DDL"), so a failed
    import leaves both tables, with their rows, as they were.
  - The drop goes through `text()` and names only 024's constants, never a value
    from the payload. When a vec0 virtual table is dropped, SQLite drops its shadow
    tables with it.
- **FTS** is 024's `ensure_fts_tables`. It runs **before** the wipe, which covers
  both cases:
  - **Tables already existed:** the wipe's delete triggers remove the old entries.
  - **Tables did not exist:** ensure creates them and back-fills them from rows
    that are about to be wiped, then the wipe's triggers remove those entries.

  Either way, the triggers index the inserted rows. The FTS tables are never
  dropped.
- **`IntegrityError`** comes from `sqlalchemy.exc`.
  - Catch it around the insert phase only.
  - Re-raise it as an `ExportInvalidError` built from the `malformed_payload`
    reason, so that the `with connection.begin():` block exits by exception and
    rolls back.
  - Never log or forward the driver text (`backend-structure.md` §"The 500
    posture", the redaction rule).
- **The role check** compares against the admin member of the `Role` enum
  (`app/roles.py`). Read `role` as stored; do not re-derive it.
- **Passwords.** `services/passwords.py` holds the hash-and-verify seam. DoD-2
  verifies a restored hash through it, using a password the test chooses and hashes
  through the same seam at seed time.

## Fixtures guidance

- **Two databases.** Build the source on one `db_settings`/`db_engine` pair and the
  target on a second temp file. Whether that is two settings objects with distinct
  `data_dir`s or a second fixture-built engine is the test-coder's choice.
- **Comparison.** Compare per-table `SELECT *` ordered by primary key.
- **Vec rows and existence.**
  - To seed vec rows, call 024's `ensure_vector_tables(conn, 8)` and insert
    serialized float32 vectors.
  - To check existence afterwards, use `vector_table_dimension` (none means
    absent) or `sqlite_master`.
  - For DoD-12, ensure at a different dimension such as 16.
