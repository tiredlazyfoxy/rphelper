# Step 006 — shared file-import helper and app import effects

## Goal

Add two modules:
- a shared helper that reads a chosen export file, parses it, and posts it as JSON
  to an import route;
- the `app` entry's two import effects. On success they reload the affected lists
  (including `SessionsState`) or navigate, and raise the one coverage warning. On
  failure they call `notifyFailure`.

## Source files

- `frontend/src/shared/importFile.ts`
- `frontend/src/app/importUploads.ts`

## Test files

- `frontend/tests/shared/importFile.test.ts`
- `frontend/tests/app/importUploads.test.ts`

## Interface intent

- **`shared/importFile.ts`** (new):
  - **The unreadable-file code constant.** `client_unreadable_file`.
  - **`readExportFile(file)`.**
    - Takes a chosen file (anything with an async `text()`) and resolves to the
      parsed JSON **object**.
    - Rejects with an `ApiError` carrying the unreadable-file code, status 0 and the
      pinned sentence (`context.md` §"Frontend shared facts") when reading fails,
      the text is not JSON, or the parsed value is not a plain object (null and
      arrays included).
    - Never sends a request.
  - **`postExportFile(path, file, signal?)`.**
    - Reads with `readExportFile`, then calls the existing
      `apiPost(path, parsed, signal)` and resolves to its decoded result.
    - Failures are the `ApiError`s `apiPost` already throws, including its 401 →
      `/login`.
    - An abort propagates unchanged.
- **`app/importUploads.ts`** (new; sibling of 030's `exportDownloads.ts`):
  - **Response types.**
    - The owned-import result: `granularity` is `"user" | "character"`, and
      `character_ids` is `string[]`.
    - The session-import result: `session_id` is a `string`.
  - **Path builders.** The owned-import path is `/api/import`. The session-import
    path takes a character id string and returns `/api/characters/<id>/import`.
  - **`runOwnedImport(file, charactersState, sessionsState, navigate, signal?)`.**
    Posts to the owned path. On success it:
    1. reloads the characters list with the existing `loadCharacters` **and** the
       session tree with the existing `loadSessions` (`context.md` §"Frontend shared
       facts", reload scope);
    2. for a `character` result, navigates to `/characters/<the one id>`;
    3. raises the coverage warning once, through `notifyWarning`.

    On any failure other than an abort, it calls `notifyFailure` once. It never
    rethrows and resolves either way.
  - **`runSessionImport(characterId, file, sessionsState, reloadSection, signal?)`.**
    Posts to the session path for that character. On success it:
    1. awaits the supplied `reloadSection` callback, which re-loads the Sessions
       section's list (step 007 wires it up);
    2. reloads `SessionsState` with `loadSessions`;
    3. raises the coverage warning once.

    Failures are handled as in `runOwnedImport`.
  - **Both effects** pass the optional signal to the post and do nothing further
    once it is aborted.

## Definition of done

1. **DoD-1 [test]:** `readExportFile` resolves to the parsed object for a file
   whose text is a JSON object, and makes no `fetch` call.
2. **DoD-2 [test]:** `readExportFile` rejects with an `ApiError` whose code is
   `client_unreadable_file`, status 0 and message exactly "The chosen file is not a
   readable export.". It does this for each of:
   - text `not json`;
   - text `[1,2]`;
   - text `null`;
   - text `"str"`;
   - a file whose `text()` rejects.

   No case makes a `fetch` call.
3. **DoD-3 [test]:** `postExportFile` calls `fetch` once with the given path,
   method POST, a JSON content type, and a body that is the file's object
   re-serialized. It resolves to the response's decoded JSON.
4. **DoD-4 [test]:** When the server answers 400 with an `export_invalid`
   envelope, `postExportFile` rejects with an `ApiError` carrying that code and
   message.
5. **DoD-5 [test]:** The path builders return `/api/import` and
   `/api/characters/<id>/import`. A 19-digit id is inserted verbatim.
6. **DoD-6 [test]:** `runOwnedImport` with a `character` result: (US-080.AC-2)
   - issues, after the `POST`, one `GET` of the characters list **and** one `GET`
     of the sessions list that `loadSessions` requests;
   - calls `navigate` with `/characters/<returned id>`;
   - raises exactly one warning, with the pinned sentence (`006.context.md`);
   - raises no failure notification.
7. **DoD-7 [test]:** `runOwnedImport` with a `user` result reloads both the
   characters list and the sessions list, does **not** navigate, and raises exactly
   one warning. (US-079.AC-2)
8. **DoD-8 [test]:** `runSessionImport` posts to `/api/characters/<id>/import`. It
   then awaits `reloadSection` exactly once, issues one `GET` of the sessions list
   that `loadSessions` requests, raises one warning, and does not navigate.
   (UC-064)
9. **DoD-9 [test]:** For a server failure (e.g. 400 `export_invalid`, 404
   `character_not_found`) and for an unreadable file, each effect:
   - calls `notifyFailure` exactly once with the thrown `ApiError`;
   - raises no warning;
   - makes no characters-list or sessions-list `GET`, does not call
     `reloadSection`, and does not navigate;
   - does not reject.
10. **DoD-10 [test]:** When the signal is aborted during the post, neither effect
    notifies, warns, reloads or navigates, and neither rejects.
11. **DoD-11 [manual/live]:** `npm run typecheck` passes.
