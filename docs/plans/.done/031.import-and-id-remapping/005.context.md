# Step 005 — step-specific context

## Existing names

- **`require_user`** is in `app/dependencies.py` and yields `CurrentUser(id,
  username, role)`. **`require_role(Role.ADMIN)`** is attached at router level in
  `routers/admin_db.py` as `require_admin`, and the router prefix is
  `/api/admin/database`.
- **`get_connection`** is in `app.db.engine`.
- **`get_id_generator`** is in `app/routers/bootstrap.py` (~L50), injected as
  `Annotated[SnowflakeGenerator, Depends(get_id_generator)]`. Import it the way the
  other routers that mint ids do; the skeleton records which module they import it
  from.
- **The id aliases** `SnowflakeIn` / `SnowflakeOut` are in `app/models/ids.py`.
- **The cookie clear writer** is in `app/dependencies.py`. It is the one used by
  `POST /api/auth/logout` (204, cookie cleared); the skeleton records its real name.
  Applying it is a router concern; the service knows nothing of cookies.
- **030's `routers/transfer.py`** already holds the three `GET` export routes and is
  registered in `main.py`. This step adds handlers only, and `main.py` is not
  touched.

## Why the bodies are raw objects

This is the second deliberate exception to "routes return/accept pydantic models"
(030 set the first for the export response). The envelope is column-agnostic, so
no static model can describe it. The JSON id boundary still holds:
- inbound ids in the payload are parsed by the service's deserializer;
- the responses use `SnowflakeOut`.

`outcome.md` records this for `backend-structure.md`. FastAPI turns a
`dict[str, Any]` body parameter into "must be a JSON object", which is why an
array answers 422 (DoD-6).

## Why 204 + cookie clear on the database import

Success deletes every `auth_sessions` row, including the caller's. Clearing the
cookie stops the browser sending a token the server can no longer resolve. The
frontend navigates to `/login` regardless (step 008).

## Test harness

- Router tests declare local `_insert_user`, `_seed`, `application` and
  `_as(application, settings, user, pw) -> TestClient` helpers. See
  `tests/test_characters_router.py`, `tests/test_sessions_router.py` and 030's
  `tests/test_transfer_router.py`.
- **Envelopes come from 030's `GET` routes** in the same test, so the router tests
  never hand-build a valid envelope.
- **"From another instance"** (DoD-8) means building the database export on a
  second temp database and posting its JSON to the first.
