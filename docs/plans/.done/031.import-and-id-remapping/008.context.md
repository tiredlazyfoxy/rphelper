# Step 008 — step-specific context

## Pinned confirm text (tests bind to these exact strings)

| Prop | Value |
|---|---|
| `title` | `Replace the whole database?` |
| `consequence` | `Everything in this instance, including your own account, is replaced by the contents of the file, and you will be signed out.` |
| `confirmLabel` | `Replace database` |
| `confirmColor` | `red` |

The consequence sentence describes the action only. It names no count, no table,
no user and nothing from the file (R5; `ui-conventions.md` "The confirm text must
not name a blast radius it is not allowed to know"). This is the confirm the user
asked for in U2: the import is destructive because it replaces the admin's own data
and signs them out.

## Existing names

- **`admin/databasePageState.ts`.** `DatabasePageState` holds observable fields
  only:
  - the drift report and its `errorMessage`;
  - 030's export status, size and export error.

  Behaviour lives in free functions such as `loadDriftReport(state, signal)` and
  030's `exportDatabase(state, signal?)`.
- **`admin/DatabasePage.tsx`.** It renders the `Title` "Database" in a page-level
  `Group` with 030's action group (Export), then the inline Alerts, then the drift
  table. **Import joins that same action group.** Do not add a placeholder for
  Rebuild index (`fast/002`).
- **`shared/ConfirmModal.tsx`** props are `{opened, title, consequence,
  confirmLabel, confirmColor?, loading?, onCancel, onConfirm}`. Cancel sits left of
  confirm, fixed in the component.
- **`documentNavigation.assign`** is the same navigation seam `shared/api.ts` uses
  for its 401 → `/login`. Import it from where `api.ts` exposes it; the skeleton
  records the module.
- **`postExportFile`** (step 006, `shared/importFile.ts`) handles the file read and
  parse, and raises the unreadable-file `ApiError` before any request. A 204 resolves
  with no body; the existing client's 204 handling (as used by logout) applies.

## Why the admin page uses no notification

The page already has an in-page error place, so failures render there and never
also as a notification (`ui-conventions.md` §"Async feedback"). On success the page
navigates away, which is the signal. No success text is rendered, and nothing
needs it.
