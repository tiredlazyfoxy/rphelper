| Error / reason | Message |
|---|---|
| `export_invalid` / `not_an_export` | `This file is not an RPHelper export.` |
| `export_invalid` / `unsupported_version` | `This export was made by an incompatible version of RPHelper.` |
| `export_invalid` / `schema_mismatch` | `This export was made with a different database layout and cannot be imported here.` |
| `export_invalid` / `wrong_granularity` | `This kind of export cannot be imported here.` |
| `export_invalid` / `malformed_payload` | `This export is damaged or incomplete and cannot be imported.` |
| `database_not_empty` | `The database can only be replaced while it holds no account other than a single administrator.` |

These set the precedent `already_configured` set for a default message: the message
lives on the subclass, and the base class is untouched (`backend-structure.md`
§"The error model").

## Facts this step reads

- **`app/errors.py`.** `DomainError(message=None, detail=None)`, with class
  attributes `code` and `http_status`. One handler is registered on the base, so a
  new subclass needs no registration. Until now there has been no typed 400/422
  for malformed input; this is the first 400 besides `invalid_credentials`.
- **Registry types** (`db/schema.py`).
  - Ids are `BigInteger().with_variant(Integer(), "sqlite")`.
  - `users.role` is a non-native `Enum` (`users_role`) over the `Role` values.
  - `memos.scope` is a non-native `Enum` over `user`, `character`, `setup` and
    `session`.
  - `messages.role` / `messages.kind` may be enums or text. Read the Table; never
    hard-code a column list.
  - Booleans are `Boolean`, and timestamps are `Text`.

  Detect a column's family from its SQLAlchemy type: `Enum` before `String`,
  because `Enum` subclasses `String`, and `Boolean` before `Integer`.
- **Signed 64-bit range.** An id string must parse to `0 <= n <= 2**63 - 1`.
  Leading `+`, `-`, whitespace or an empty string is not a decimal-digit string.
- **030 names to reuse.** The format literal, the envelope `version` and
  `schema_version` constants, the granularity value set, the database exclusion set
  and the `users` column-exclusion constant are all in `services/transfer.py`.
  030's plan describes them but leaves the exact identifiers to its skeleton, so
  this step's skeleton reads them from the built module and records them.
- **Header-check order is load-bearing for tests.** For example, a body with a
  wrong `format` **and** a wrong `version` must give `not_an_export`.

## Fixtures guidance

Seed through Core inserts against `schema` Tables or the existing services, then
produce envelopes with 030's exporters. Malformed variants are deep copies of a
valid envelope with one mutation each. The import module issues no SQL in this
step, so validation tests need a database only to produce the source envelope.
