# Step 005 — import routes and response models

## Goal

Expose the three imports over HTTP:
- two roleplayer `POST` routes on 030's `routers/transfer.py`;
- the admin `POST` on `routers/admin_db.py`.

The two roleplayer routes answer small response models from a new
`models/transfer.py`. The admin route answers 204 and clears the session cookie.

## Source files

- `backend/app/models/transfer.py`
- `backend/app/routers/transfer.py`
- `backend/app/routers/admin_db.py`

## Test files

- `backend/tests/test_transfer_import_router.py`
- `backend/tests/test_admin_db_import.py`

## Interface intent

- **`models/transfer.py`** (new):
  - **Owned-import response.** Carries `granularity`, which is `"user"` or
    `"character"`, and `character_ids`, a list of outbound snowflake-alias ids,
    serialized as strings.
  - **Session-import response.** Carries `session_id` as an outbound
    snowflake-alias id.
- **`POST /api/import`** (in `routers/transfer.py`).
  - Depends on `require_user`, `get_connection` and `get_id_generator`.
  - Takes the request body as a raw JSON object.
  - Calls `import_owned` with the caller's id and answers 200 with the owned-import
    response.
- **`POST /api/characters/{character_id}/import`** (in `routers/transfer.py`).
  - Depends on the same three.
  - The path id is declared with the inbound snowflake alias from
    `app/models/ids.py`.
  - The body is the raw JSON object.
  - Calls `import_session` and answers 200 with the session-import response.
- **`POST /api/admin/database/import`** (in `routers/admin_db.py`).
  - Inherits the router-level admin guard and depends on `get_connection`.
  - Takes the body as a raw JSON object and calls `import_database`.
  - Answers **204** with no body, and applies the existing session-cookie
    **clear** writer from `app/dependencies.py` to that response.
- **The routers hold no rule.** A typed error raised by a service reaches the
  client through the existing `DomainError` handler.

## Definition of done

1. **DoD-1 [test]:** A roleplayer `POST /api/import` with their own `user` export
   (fetched via 030's `GET /api/export`) answers 200 with `granularity` `"user"`
   and `character_ids` as JSON strings. A follow-up `GET` of each returned
   character id succeeds for the caller. (US-079.AC-2)
2. **DoD-2 [test]:** `POST /api/import` with a `character` export (via 030's `GET
   /api/characters/{id}/export`) answers 200 with `granularity` `"character"` and
   exactly one id, which is not the exported character's id. (US-080.AC-2,
   US-136.AC-2)
3. **DoD-3 [test]:** `POST /api/characters/{C}/import` with a `session` export
   (via 030's `GET /api/sessions/{id}/export`) answers 200 with `session_id` as a
   string. `GET /api/sessions/{session_id}` shows the session under character C
   with no setup. (US-082.AC-1, US-082.AC-2)
4. **DoD-4 [test]:** `POST /api/characters/{C}/import` where C is another user's
   character, or does not exist, answers 404 `character_not_found` with the
   standard envelope. A non-numeric path id answers 422.
5. **DoD-5 [test]:** Each answers 400 `export_invalid` with `detail.reason`
   `wrong_granularity`:
   - a `session` export posted to `/api/import`;
   - a `character` export posted to `/api/characters/{C}/import`;
   - a `database`-granularity envelope posted to either.
6. **DoD-6 [test]:** A body `{"format": "nope"}` posted to each of the three
   routes answers 400 with code `export_invalid` and `detail` exactly `{"reason":
   "not_an_export"}`. On the admin route this holds on an eligible instance. A JSON
   array body answers 422.
7. **DoD-7 [test]:** The two roleplayer routes answer 401 `not_authenticated`
   without a session cookie.
8. **DoD-8 [test]:** An admin who is the instance's only user posts a `database`
   export taken from another instance. The answer is 204 with an empty body and a
   `Set-Cookie` that clears the session cookie. A subsequent request with the old
   cookie answers 401. Logging in as a restored user with their original password
   succeeds. (US-077.AC-2)
9. **DoD-9 [test]:** With a second user present, an admin's `POST
   /api/admin/database/import` answers 409 `database_not_empty`, and the admin's
   next authenticated request still succeeds (nothing was wiped).
10. **DoD-10 [test]:** A roleplayer's `POST /api/admin/database/import` answers
    403 `insufficient_role`, and an unauthenticated request answers 401.
11. **DoD-11 [test]:** Regression smoke: 030's three `GET` export routes and `GET
    /api/admin/database/tables` still answer 200 after this step.
12. **DoD-12 [manual/live]:** Through the dev proxy and nginx (`client_max_body_size
    64m`), a multi-megabyte user export imports successfully.
13. **DoD-13 [manual/live]:** `mypy app` and `ruff check .` pass.
