# Step 004 — whole-database import (replace, ids preserved)

## Goal

Add `import_database`, which replaces the whole database with a `database` export
in one transaction and keeps the export's own ids. It is allowed only on an
instance that has no users, or exactly one user who is an admin.

## Source files

- `backend/app/services/transfer_import.py`

## Test files

- `backend/tests/test_transfer_import_database.py`

## Interface intent

- **`import_database`** (public). Takes a connection and the raw envelope. It takes
  **no request user and no generator**, so that `fast/003` can call it. It returns
  nothing. Inside one `with connection.begin():` block, in this order:
  1. **Eligibility guard.** Count the `users` rows. Allowed when there are 0, or
     exactly 1 whose `role` is admin. Otherwise raise `DatabaseNotEmptyError`.
  2. **Validation.** Run step 001's validation with accepted set {`database`}.
     Because the guard runs first, an ineligible instance answers
     `database_not_empty` whatever the file holds. Validation is pure, so this order
     costs nothing.
  3. **Scope-target check.** Every memo's `(scope, scope_id)` must name a payload
     row. For scope `user` that is a payload `users` id; for the other scopes, a row
     in their table. A miss raises `malformed_payload`.
  4. **Ensure FTS** with 024's `ensure_fts_tables(connection)`.
  5. **Wipe.**
     - Delete every row of every `schema.metadata` table, one DELETE per table, in
       reverse `sorted_tables` order.
     - **Drop** `memo_vec` and `session_vec`, each only when it exists (024's
       `vector_table_dimension` is not none).

     The drop is DDL inside the same transaction, so a failed import restores the
     tables along with everything else.
  6. **Insert with preserved ids.** Use step 002's payload writer with the
     validated rows unchanged (an identity "remap"). The self-reference is still
     inserted in two passes.
  7. **Constraint refusals.** Turn any `IntegrityError` the inserts raise (FK,
     UNIQUE or CHECK) into `ExportInvalidError(malformed_payload)`. The transaction
     rolls back whole, and the driver's message reaches neither the error nor a log
     line.
- **Database identity policy** (module-private). The step-002 seam that hands rows
  to the writer **without** minting new ids, nulling references or substituting the
  caller. Every column is written as exported, including `users.password_hash`,
  `users.role`, `llm_servers.api_key_ref`, `models.is_embedding_designated` and
  `embedding_dim`.

## Definition of done

1. **DoD-1 [test]:** Round trip onto a non-empty instance. (US-077.AC-2, UC-061)
   - **Source:** seed and export with `export_database`:
     - two users, an admin and a roleplayer;
     - characters (one archived), setups and sessions;
     - settled, buried and zone messages;
     - memos at all four scopes;
     - an `llm_servers` row with a `"$NAME"` key ref, and a designated `models` row.
   - **Target:** a fresh database holding exactly one admin user, with a
     character and an `auth_sessions` row.
   - **Expected:** after `import_database`, every `metadata` table except
     `auth_sessions` and `translations` holds exactly the source rows, with the
     same ids and every column equal.
2. **DoD-2 [test]:** After a successful import: (US-077.AC-2)
   - the target's previous admin, their character and their `auth_sessions` rows
     are gone;
   - `auth_sessions` and `translations` hold no rows;
   - an imported user's original password verifies against the restored hash
     through `services/passwords.py`'s verify operation.
3. **DoD-3 [test]:** On a database with **no users** (tables created, all empty),
   the import succeeds and restores the payload. This is the bootstrap path
   `fast/003` will use.
4. **DoD-4 [test]:** Each of these raises `DatabaseNotEmptyError` and leaves every
   row of every table unchanged:
   - two users, both admins;
   - one admin and one roleplayer;
   - exactly one user, who is a roleplayer.
5. **DoD-5 [test]:** On an ineligible instance, an envelope that is also
   malformed (wrong `schema_version`) raises `DatabaseNotEmptyError`, not
   `export_invalid`.
6. **DoD-6 [test]:** On an eligible instance, each of these raises
   `ExportInvalidError` with `malformed_payload`. Afterwards the original admin,
   their rows and their `auth_sessions` row are all still present and unchanged:
   - two `users` rows sharing a username (UNIQUE);
   - a `setups` row whose `character_id` names no payload character (FK);
   - a memo whose `scope='character'` `scope_id` names no payload character.
7. **DoD-7 [test]:** A `user`, `character` or `session` envelope given to
   `import_database` on an eligible instance raises `wrong_granularity`, and
   nothing changes.
8. **DoD-8 [test]:** Vector tables are dropped on success and survive a failure.
   - If `memo_vec` and `session_vec` exist with rows before a successful import,
     neither exists afterwards.
   - If they did not exist before, they still do not exist, and nothing fails.
   - If the import fails (e.g. the UNIQUE case from DoD-6), both still exist with
     their rows and their original dimension.
9. **DoD-9 [test]:** After the import, `memo_fts` / `message_fts` exist.
   - A token from a restored memo body, and one from a restored record row, are
     each found under the preserved id.
   - A token that was only in the wiped target's memo is not found.
   - FTS5 `integrity-check` passes on both tables.
10. **DoD-10 [test]:** Buried messages keep their `related_to` (the preserved head
    id), and the views show the same record and zone as the source.
11. **DoD-11 [test]:** An `ExportInvalidError` raised from a constraint refusal
    carries `detail` exactly `{"reason": "malformed_payload"}`. The duplicated
    row's sentinel username appears in neither the message nor `detail`.
12. **DoD-12 [test]:** After a successful replace that dropped the vector tables,
    024's `ensure_vector_tables(conn, d)` creates them at a dimension `d` that
    differs from the pre-import one, without raising `dimension_mismatch`.
13. **DoD-13 [manual/live]:** `mypy app` and `ruff check .` pass.
