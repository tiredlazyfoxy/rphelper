# Step 004 — The memos router

## Goal

Add `routers/memos.py`, the five routes of the wire contract on one router with
router-level `require_user` (D9): list one level, create, PATCH a subset, DELETE, and the
session's memo chain. Each route converts the service values into `001`'s response
models; validation failures are FastAPI's 422. Register the router in `main.py` after
every router already registered.

## Interface intent

**`routers/memos.py`** (new)

- **`router`**: an `APIRouter` with `require_user` as a router-level dependency, declaring
  full literal paths (D9).
- **List handler**: `GET /api/memos`. Takes the query parameters `scope` (the scope
  literal; required) and `scope_id` (optional inbound snowflake), the current user and the
  connection. A non-user `scope` without `scope_id` answers 422; for `"user"` a supplied
  `scope_id` is ignored. Calls `list_memos`; answers a `MemoListResponse`.
- **Create handler**: `POST /api/memos`, status 201. Takes a `CreateMemoRequest`, the
  current user, the connection and the id generator. Calls `create_memo` with the body's
  scope, its `scope_id` (passed as `None` for `"user"`) and body; answers a
  `MemoResponse`. Nothing in the request sets the flags or `sort_key`.
- **Update handler**: `PATCH /api/memos/{memo_id}`. Takes the path id (inbound snowflake),
  an `UpdateMemoRequest`, the current user and the connection. Forwards to `update_memo`
  only the fields that were set **and** are not null; answers a `MemoResponse`.
- **Delete handler**: `DELETE /api/memos/{memo_id}`, status **204** with an empty body.
  Calls `delete_memo`.
- **Chain handler**: `GET /api/sessions/{session_id}/memo-chain`. Takes the path id, the
  current user and the connection. Calls `resolve_chain`; answers a `MemoChainResponse`
  whose levels are in the order returned.
- Private conversions from `Memo` to `MemoResponse` and from `MemoChainLevel` to
  `MemoChainLevelResponse`.
- `MemoNotFoundError`, `CharacterNotFoundError`, `SetupNotFoundError` and
  `SessionNotFoundError` propagate to the already-registered domain handler. The router
  catches nothing and contains no SQL.

**`main.py`** (extended)

- Includes the memos router **after every router already in the list**.

## Definition of done

1. `[test]` With no login cookie, each of the five routes answers 401 with code
   `not_authenticated`.
2. `[test]` A signed-in roleplayer with character C (`POST /api/characters`), setup S
   under C (`POST /api/characters/<C>/setups`) and session X under C
   (`POST /api/characters/<C>/sessions`) posts a note at each level (`user` with no
   `scope_id`; `character` / `setup` / `session` with C / S / X). Each answers **201** with
   an object of exactly the nine wire keys: `id` a JSON string of decimal digits, `scope`
   as sent, `scope_id` null for the user note and the target's id string otherwise,
   `is_enabled` true, `is_forced` false, `sort_key` 0, `created_at` equal to `updated_at`
   in the fixed-width form, and no `user_id`. `GET /api/memos?scope=<s>` (plus
   `&scope_id=<id>` for the three non-user levels) then lists it.
   (US-049.AC-1, US-050.AC-1, US-051.AC-1, US-052.AC-1, US-053.AC-1)
3. `[test]` A create that also sends `"is_enabled": false, "is_forced": true,
   "sort_key": 9, "user_id": "<B's id>", "title": "t"` answers 201 with `is_enabled`
   true, `is_forced` false, `sort_key` allocated (0 at an empty level) and no `title` key;
   the note is listed for the caller and not for B. (US-053.AC-1, US-119.AC-1, R5)
4. `[test]` A create with body `"  # Heading\n\ntext  "` answers that exact body, and the
   listing returns it unchanged. A `user` create with a `scope_id` of some other id
   answers `scope_id` null and appears in the caller's `?scope=user` listing. (D15, wire
   contract request rules)
5. `[test]` 422, with no `memos` row inserted: a create whose `body` is `""`, `"  \n"` or
   missing; a `character` / `setup` / `session` create without `scope_id`; a create with
   `scope` `"world"` or a non-numeric `scope_id`; `GET /api/memos` with no `scope`, with
   `scope=world`, or with `scope=character` and no `scope_id`; a PATCH whose `body` is
   `""` or `"   "`; a PATCH or DELETE on `/api/memos/abc`; and
   `GET /api/sessions/abc/memo-chain`. (D15, D2)
6. `[test]` Owner scope, user B against user A's objects: list and create at A's
   character, A's setup and A's session answer 404 with codes `character_not_found`,
   `setup_not_found` and `session_not_found`; PATCH and DELETE on A's memo answer 404
   `memo_not_found`; `GET /api/sessions/<A's session>/memo-chain` answers 404
   `session_not_found`. Every such body has an empty `detail` and equals the body for an
   id that exists for nobody. Afterwards, read as A, A's memo is unchanged and still
   listed, and B's `?scope=user` listing holds none of A's user-level notes. (R5, D12)
7. `[test]` `PATCH {"is_enabled": false}` on a forced note answers `is_enabled` false and
   `is_forced` **true**; a following `PATCH {"is_enabled": true}` answers `is_enabled` true
   and `is_forced` true. The same sequence on a not-forced note ends with `is_forced`
   false. (US-101.AC-1, US-101.AC-2, R3)
8. `[test]` `PATCH {"is_forced": true}` on a disabled note answers `is_enabled` false and
   `is_forced` true. `PATCH {"body": "y"}` changes only `body` (flags, `sort_key`,
   `created_at` unchanged; `updated_at` not earlier). `PATCH {"body": null,
   "is_forced": true}` leaves the body as it was. `PATCH {}` answers 200 with the note
   unchanged. (D6, wire contract request rules)
9. `[test]` `DELETE /api/memos/<id>` answers **204** with an empty body. Afterwards the
   level's listing omits the note, the chain omits it, PATCH on it answers 404
   `memo_not_found`, and a second DELETE answers 404 `memo_not_found`. (D2)
10. `[test]` `GET /api/sessions/<X>/memo-chain` for a session **with** setup S answers
    `{"levels": [...]}` with four levels whose `scope`s are `user`, `character`, `setup`,
    `session` in that order and whose `scope_id`s are null, C, S, X as strings; each level
    holds the notes created there, as wire `Memo` objects. (UC-046, R2)
11. `[test]` For a session started under C with **no setup**, the chain answers exactly
    three levels, `user`, `character`, `session`, in that order — no `setup` entry — and
    the user, character and session notes are all present. (US-057.AC-1, R2)
12. `[test]` A disabled note (including disabled and forced) appears in its level's
    listing and in the chain with its flags. (R3: the owner sees disabled notes)
13. `[test]` After `POST /api/characters/<C>/archive`, `POST /api/setups/<S>/archive` and
    `POST /api/sessions/<X>/archive`, listing and creating at each of the three levels and
    `GET /api/sessions/<X>/memo-chain` all succeed (200 / 201). (D8)
14. `[test]` Three notes created at one level list in creation order with `sort_key` 0, 1,
    2; after deleting the middle one, the next create answers `sort_key` 3 and lists last.
    (D4)
15. `[test]` The routers registered before this one still answer with it registered:
    `GET /api/sessions/<X>` answers 200 with the session, and
    `GET /api/characters/<C>/sessions` and `GET /api/characters/<C>/setups` answer 200.
    (D9, registration order)
16. `[manual/live]` Against a running dev backend whose database pre-dates 015: after the
    administrator presses Create for `memos`, `curl`-ing `GET /api/memos?scope=user` with a
    roleplayer's cookie answers `{ "memos": [] }`, and a POST of a user note answers 201.
