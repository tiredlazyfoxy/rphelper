# Step 007 — The shared level group component

## Goal

Add `app/MemoLevelGroup.tsx`: one level's notes as a titled region — each note one list
item with its `MarkdownEditor` (saved on focus loss), the two independent flag
`IconButton`s, its reach line and its inline failure; a "New note" button and the unsaved
new note; the empty, loading and failed states — and the flush on unmount (D1, D5, D6,
D13, D14). The session screen (`008`) and the character page (`009`) both render it.

## Interface intent

**`app/MemoLevelGroup.tsx`** (new)

- **`MemoLevelGroup`**: `observer` component. Props: `state` (a `MemoLevelState`),
  `title` (the group's heading text), `headingOrder` (the heading level the mount needs),
  and `onRetry` (called by the failed state's "Retry"). It does not create, load or own
  its state. It renders:
  - a **region** named by its heading, the heading's text being `title`;
  - by `state.status`: `"idle"` / `"loading"` → a small `Loader`; `"failed"` → the text
    **"Could not load notes"** and a button **"Retry"** calling `onRetry`; `"ready"` → the
    content below;
  - **"No notes yet."** (dimmed) when the level has no saved note and no new note;
  - otherwise a **list** with one **listitem** per saved note, in state order, then the
    new note's listitem last when there is one;
  - per saved note: the shared `MarkdownEditor` labelled **"Note"** showing `noteText` and
    calling `setNoteText` on change, inside a wrapper whose focus-leave runs `saveNote`;
    the enabled toggle (`IconButton` **"Disable note"** with `IconCircleCheck` while
    enabled, **"Enable note"** with `IconCircleOff` while disabled, running
    `toggleEnabled`); the forced toggle (`IconButton` with `IconPin`, **"Force note"**
    while not forced, **"Stop forcing note"** and coloured while forced, running
    `toggleForced`) — both always shown and both disabled while `isFlagWriteInFlight`; the
    reach line, the text `reachStatement(memoReach(note))`; and, when `noteFailure` is
    non-null, that text under the note. A disabled note's editor area renders dimmed and
    struck through via Mantine props;
  - the new note: the `MarkdownEditor` labelled **"Note"** showing its text and calling
    `setNewNoteText`, inside a wrapper whose focus-leave runs `saveNewNote`; **no** flag
    controls and **no** reach line; its failure text under it when non-null;
  - a labelled button **"New note"** (`IconPlus` left section) running `openNewNote`,
    disabled while a new note exists;
  - no title, name or header field for any note, no confirm, no notification.
- On unmount it runs `flushMemoLevel` on its state (D5). Every effect is `void`ed from
  its handler.

## Definition of done

1. `[test]` A ready state with two notes renders a region named by `title` containing a
   heading with that text and a list of exactly two listitems in state order. Each
   listitem holds exactly one textbox, labelled "Note", whose value is that note's body;
   no other textbox is anywhere in the region. (US-119.AC-1, UC-043)
2. `[test]` The editor is the shared `MarkdownEditor`: with the test file's `vi.mock` of
   `src/shared/MarkdownEditor`, each note's mock receives the label "Note" and the note's
   text as its value. (US-056.AC-1 — structural; `frontend-structure.md` "Markdown")
3. `[test]` Reach lines: an enabled forced note shows "Forced: always given to the
   assistant."; an enabled not-forced note "Searchable: found only when the assistant
   searches."; a disabled forced note and a disabled not-forced note each "Disabled: never
   reaches the assistant." (R3 — `is_enabled` gates first; D7)
4. `[test]` Flag controls: an enabled note shows "Disable note", a disabled one "Enable
   note"; a not-forced note shows "Force note", a forced one "Stop forcing note". A
   disabled, forced note shows both "Enable note" and "Stop forcing note" — the forced
   control stays visible on a disabled note. (US-101.AC-1, D6, D14)
5. `[test]` Pressing "Disable note" on an enabled, forced note PATCHes `/api/memos/<id>`
   with exactly `{"is_enabled": false}`; after the response that listitem shows "Enable
   note", "Stop forcing note" and the disabled reach line. Pressing "Enable note" then
   PATCHes exactly `{"is_enabled": true}`, and the listitem shows the forced reach line
   with no other control pressed. The same sequence on a not-forced note ends on the
   searchable reach line. (US-101.AC-1, US-101.AC-2, R3)
6. `[test]` Pressing "Force note" on a disabled note PATCHes exactly
   `{"is_forced": true}`; after the response the listitem shows "Enable note" and "Stop
   forcing note" and still the disabled reach line. (D6)
7. `[test]` While a flag PATCH is pending, both flag buttons of that note are disabled and
   their labels and the reach line are unchanged; after the response they are enabled
   again. (D5 — never optimistic)
8. `[test]` Typing into a note's "Note" textbox and blurring it PATCHes exactly
   `{"body": <typed text>}`; blurring a textbox whose text is unchanged sends nothing.
   (UC-043, D5)
9. `[test]` Clearing a saved note's text and blurring it sends `DELETE /api/memos/<id>`
   (no PATCH, no confirm dialog); after the 204 its listitem is gone. (D2)
10. `[test]` Failures render inside that note's listitem and nowhere as a notification: a
    failed body save shows "Could not save the note." and the textbox keeps the typed
    text; a failed delete shows "Could not delete the note." and the listitem stays; a
    failed toggle shows "Could not change the note.". (D5, context.md strings table)
11. `[test]` Pressing "New note" adds a last listitem holding one empty "Note" textbox, no
    "Disable note" / "Enable note" / "Force note" / "Stop forcing note" button and no
    reach line, and disables "New note". Blurring it while empty (and, in a second case,
    holding only spaces and a newline) removes that listitem, re-enables "New note" and
    sends **no request at all**. (D2 — nothing persisted for a blank new note; D13)
12. `[test]` Typing "Plan" into the new note and blurring it POSTs `/api/memos` with
    exactly the level's `scope` and `scope_id` and `"body": "Plan"` (no flag keys); after
    the 201 the last listitem shows "Disable note", "Force note" and "Searchable: found
    only when the assistant searches.", and "New note" is enabled again.
    (US-053.AC-1, US-049.AC-1, US-050.AC-1, D13)
13. `[test]` A failed create keeps the new listitem with its typed text and "Could not
    save the note." in it, and "New note" stays disabled. (D13, D5)
14. `[test]` A ready level with no notes shows "No notes yet." and an enabled "New note",
    and no listitem. (context.md strings table)
15. `[test]` A loading state shows a loader and no "New note"; a failed state shows "Could
    not load notes" and "Retry", and pressing "Retry" calls `onRetry` once.
16. `[test]` Unmounting the group after typing into a saved note without blurring PATCHes
    that note's new body; unmounting with a new note holding "Later" POSTs it; unmounting
    with nothing changed sends nothing. (D5 — leaving keeps the edit)
17. `[manual/live]` With the real TipTap editor: markdown typed into a note renders as
    formatted text while typing (headings, emphasis, lists) — the live preview; clicking
    the editor's own toolbar does not trigger a save, leaving the note does; a disabled
    note reads dimmed and struck through, and the forced button's colour is distinct
    while forced, in both colour schemes. (US-056.AC-1, D14)
