# Step 006 — One level's notes: the shared level state

## Goal

Add `app/memoLevelState.ts`: the `MemoLevelState` data class for one level (D16) and the
free functions that load it, populate it from a chain, track each note's editor text, and
save on focus loss by D5 / D2 / D13 — PATCH a changed body, DELETE a cleared one, POST a
non-blank new note, send nothing for a blank one — plus the two independent flag toggles
(D6) and the unmount flush. Shared by the session screen's groups and the character page.

## Interface intent

**`app/memoLevelState.ts`** (new)

- **`MemoLevelState`**: data class, observable fields only, constructed from a `scope`
  (`MemoScope`) and a `scopeId` (string, or `null` for the user level):
  - `scope`, `scopeId`: as constructed;
  - `status`: `"idle"`, `"loading"`, `"ready"` or `"failed"`, starts `"idle"`;
  - `memos`: array of `Memo` in server order, starts empty;
  - the editor text of each saved note that differs from its body, keyed by memo id
    (absent means "the body"), starts empty;
  - `newNote`: `null`, or the unsaved new note: its editor text, whether it is saving, and
    its failure text or `null`; starts `null`;
  - per-note failure text keyed by memo id, starts empty;
  - per-note "a flag write is in flight" marks keyed by memo id, starts empty.
- **`noteText`**: pure derivation. Takes the state and a memo id; returns that note's
  editor text (its held edit, else its body).
- **`noteFailure`**: pure derivation. Takes the state and a memo id; returns that note's
  failure text or `null`.
- **`isFlagWriteInFlight`**: pure derivation. Takes the state and a memo id; true while a
  flag toggle on that note awaits its response.
- **`isBlank`**: pure. Takes text; true when it is empty or whitespace only (JavaScript
  `trim`, D15).
- **`loadMemoLevel`**: effect. Takes the state and an optional signal. Sets `"loading"`,
  requests the level's listing, and on success writes the rows in the order received with
  `"ready"`. On failure writes `"failed"` and keeps the rows. Writes nothing once aborted;
  never rejects.
- **`populateMemoLevel`**: action. Takes the state and an array of `Memo`; writes them in
  the given order with `"ready"`, issuing no request (`008` populates levels from the
  chain).
- **`setNoteText`**: action. Takes the state, a memo id and text; records it as that
  note's editor text. Never touches the note's `body`.
- **`saveNote`**: effect, run on focus loss. Takes the state and a memo id. Editor text
  equal to the body → nothing. Blank editor text → `DELETE` the note; on success the note,
  its editor text and its failure are removed; on failure the failure is **"Could not
  delete the note."** and the note and its text stay. Otherwise → `PATCH` with the body
  alone; on success the returned row is applied, and the held editor text is dropped
  unless the user typed something different during the request; on failure the failure
  is **"Could not save the note."** and the text stays. The note's failure is cleared
  before the request. Never rejects.
- **`openNewNote`**: action. Takes the state; creates an empty new note at the end of the
  level when there is none; otherwise does nothing.
- **`setNewNoteText`**: action. Takes the state and text; records it as the new note's
  editor text.
- **`saveNewNote`**: effect, run on focus loss. Takes the state. No new note, or one
  already saving → nothing. Blank text → the new note is dropped with **no request**.
  Otherwise marks it saving, clears its failure and POSTs a create for the level's scope
  and scope id with that text and no flags. On success appends the returned row to the
  end of `memos` and removes the new note; text typed during the request, if different
  from what was sent, becomes that saved note's editor text. On failure the new note
  stays with its text, stops saving, and its failure is **"Could not save the note."**.
  Never rejects.
- **`toggleEnabled`** / **`toggleForced`**: effects. Take the state and a memo id. Clear
  the note's failure, mark its flag write in flight, and PATCH exactly one key —
  `is_enabled` (resp. `is_forced`) set to the opposite of the held value. On success apply
  the returned row; on failure the note's failure is **"Could not change the note."** and
  its flags are unchanged. Either way the in-flight mark is cleared. Never reject.
- **`applyMemoRow`**: action. Takes the state and one server-returned `Memo`; replaces the
  held note with that id **only if** the returned `updated_at` is not older than the held
  one (fixed-width text compare). A row whose id is not held is ignored (never inserted).
- **`flushMemoLevel`**: effect, run on unmount. Takes the state. Runs `saveNote` for every
  note whose editor text differs from its body, and `saveNewNote` when a new note holds
  non-blank text and is not saving. Resolves when they settle; never rejects.

No function passes an abort signal to a mutation (D5); only `loadMemoLevel` takes one.

## Definition of done

1. `[test]` A fresh `MemoLevelState("character", "c1")` has `scope` "character", `scopeId`
   "c1", `status` `"idle"`, no memos and `newNote` null; a `MemoLevelState("user", null)`
   has `scopeId` null. (D16)
2. `[test]` `loadMemoLevel` sets `"loading"` while pending and requests exactly
   `GET /api/memos?scope=character&scope_id=c1` (and exactly `GET /api/memos?scope=user`
   for the user level), then `"ready"` with the server's rows in the server's order,
   disabled ones included. A failed request sets `"failed"`, keeps the rows and resolves
   without throwing; with its signal aborted before the response settles it writes
   nothing. (UC-046, R3)
3. `[test]` `populateMemoLevel` writes the given notes in the given order with `"ready"`
   and issues no request. (D16)
4. `[test]` `noteText` returns the body until `setNoteText` records other text, then that
   text; the note's `body` in `memos` is unchanged by `setNoteText`. (D5 — never
   optimistic)
5. `[test]` `saveNote` with editor text equal to the body sends no request. (D5)
6. `[test]` `saveNote` with changed non-blank text PATCHes `/api/memos/<id>` with exactly
   `{"body": <text>}`. While pending, the note's `body` is the old one. After the response
   the note holds the returned row and `noteText` equals the new body. When the editor
   text was changed again during the request, after the response `noteText` is the newer
   text and the body is the returned one. (UC-043, D5)
7. `[test]` A failed body save makes `noteFailure` "Could not save the note.", keeps the
   editor text and body, and resolves without throwing; the next `saveNote` clears the
   failure before its request and, on success, it stays cleared. (D5)
8. `[test]` `saveNote` on a saved note whose editor text is `""`, and on one whose text is
   `"  \n"`, sends `DELETE /api/memos/<id>` and **no** PATCH; after the 204 the note is
   gone from `memos`. A failed delete makes `noteFailure` "Could not delete the note." and
   keeps the note and its text. (D2 — clearing a saved note deletes it)
9. `[test]` `openNewNote` creates one new note with empty text; a second call leaves it as
   it is. `saveNewNote` with the new note's text `""`, and with `"  \n"`, sends **no
   request at all** and leaves `newNote` null and `memos` unchanged. (D2 — nothing
   persisted for a blank new note; D13)
10. `[test]` `saveNewNote` with text "Plan" on a `("setup", "s1")` level POSTs
    `/api/memos` with exactly `{"scope": "setup", "scope_id": "s1", "body": "Plan"}` — no
    flag keys; the user level sends `"scope_id": null`. While pending, the new note is
    saving and `memos` does not hold the row; a second `saveNewNote` sends nothing. After
    the 201 the returned row is the **last** entry of `memos` with `is_enabled` true and
    `is_forced` false, and `newNote` is null. Text typed during the request becomes that
    note's `noteText`. (US-049.AC-1, US-051.AC-1, US-053.AC-1, D13)
11. `[test]` A failed create keeps the new note with its text, not saving, with failure
    "Could not save the note."; `memos` is unchanged; a later `saveNewNote` retries. (D5,
    D13)
12. `[test]` On an enabled, forced note, `toggleEnabled` PATCHes exactly
    `{"is_enabled": false}`; with the server answering the disabled row (still forced), the
    note is then disabled and still forced. `toggleEnabled` again PATCHes exactly
    `{"is_enabled": true}` and the note is forced again. On a not-forced note the same
    pair of toggles ends not forced. No toggle request body ever holds `is_forced`.
    (US-101.AC-1, US-101.AC-2, R3, D6)
13. `[test]` `toggleForced` PATCHes exactly `{"is_forced": <opposite>}`, including on a
    disabled note, which stays disabled. No such request body holds `is_enabled`. (D6)
14. `[test]` While a toggle is pending, `isFlagWriteInFlight` is true for that note and
    its flags are the held ones (never optimistic); afterwards it is false. A failed toggle
    makes `noteFailure` "Could not change the note.", leaves both flags unchanged, clears
    the in-flight mark and resolves without throwing. (D5, D6)
15. `[test]` `applyMemoRow` replaces a held note when the returned `updated_at` is later
    or equal, and ignores a row whose `updated_at` is older; a row whose id is not held is
    not inserted. Concretely, a body save and a toggle in flight together, whose responses
    arrive newer-first, leave the note equal to the newer row. (D5)
16. `[test]` `flushMemoLevel` on a level with one changed note, one unchanged note, one
    note whose text was cleared and a new note holding "Later" sends exactly one PATCH
    (the changed note), one DELETE (the cleared note) and one POST (the new note), and no
    other request; with the new note's text blank it sends no POST. (D5 — leaving keeps
    the edit; D2)
17. `[test]` `isBlank` is true for `""`, `" "`, `"\n\t "` and false for `"a"`, `" a "`.
    (D15)
18. `[test]` An `autorun` reading `memos` re-runs after `applyMemoRow` and after a
    successful `saveNewNote`; one reading `noteText` for a note re-runs after
    `setNoteText` (writes are MobX actions on observable fields).
