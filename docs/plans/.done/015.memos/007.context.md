## The region and its name

Give the heading an id (`useId`) and the wrapping element `role="region"` (or a
`<section>`) with `aria-labelledby` pointing at it, so
`getByRole("region", { name: title })` finds it. 010's `006.context.md` "The region and
its heading" is the precedent. The list is a plain `<ul>` / `<li>` (or Mantine `List`),
so the roles are `list` / `listitem`; do not put the "New note" button or the empty line
inside the list.

## Focus leave, not every blur

`onBlur` bubbles in React. Put it on a wrapper around each editor and run the save only
when focus leaves the wrapper: `event.relatedTarget` is `null` or not contained in
`event.currentTarget`. Focus moving between the TipTap content and its own toolbar inside
the wrapper must not save (DoD-17). In tests, `fireEvent.blur` on the mocked textarea has
a `null` `relatedTarget`, so it counts as leaving.

## Flag control colour

The forced `IconButton` passes a `color` (a Mantine theme colour) only while the note is
forced, and none otherwise. Do not encode the state any other way; the label carries it
for assistive technology (D14).

## Dimmed and struck through

Wrap a disabled note's editor in a Mantine `Box` with style props (`c="dimmed"`,
`td="line-through"`, or `opacity`), never a class or a stylesheet (`context.md`: no
`.css`). Tests do not assert styling (DoD-17 is manual).

## The flush

A `useEffect` with an empty dependency list whose cleanup calls `flushMemoLevel` on the
`state` prop captured at mount. React's StrictMode double-invoke in development runs the
cleanup once early; with nothing changed the flush sends nothing, so it is harmless. Do
not flush on every re-render.
