## Scope predicates — what each statement carries

| Operation | Statements |
|---|---|
| target check, `character` | `SELECT characters.id FROM characters WHERE id = :scope_id AND user_id = :user_id` — no `archived_at` predicate; no row → `CharacterNotFoundError` |
| target check, `setup` | `SELECT setups.id FROM setups WHERE id = :scope_id AND user_id = :user_id` (a setup id identifies its character; no character predicate); no row → `SetupNotFoundError` |
| target check, `session` | `SELECT sessions.id FROM sessions WHERE id = :scope_id AND user_id = :user_id`; no row → `SessionNotFoundError` |
| target, `user` | no select: the stored `scope_id` is `:user_id` |
| allocation | `SELECT COALESCE(MAX(sort_key), -1) + 1 FROM memos WHERE user_id = :user_id AND scope = :scope AND scope_id = :stored_scope_id`, inside the create's `begin()`, after the target check |
| create | target check, allocation, `next_id()`, then `INSERT … VALUES (id, user_id = :user_id, scope, scope_id, body, is_enabled = true, is_forced = false, sort_key, created_at, updated_at)` — the flags are written explicitly, not left to the column default |
| list | target check, then `SELECT … FROM memos WHERE user_id = :user_id AND scope = :scope AND scope_id = :stored_scope_id ORDER BY sort_key, id`, then rollback (010's pattern) |
| update | locate `WHERE id = :id AND user_id = :user_id` inside `begin()`; no row → `MemoNotFoundError`; if anything supplied, `UPDATE memos SET <supplied columns>, updated_at = :now WHERE id = :id AND user_id = :user_id`; re-read with the locate select and map |
| delete | `DELETE FROM memos WHERE id = :id AND user_id = :user_id` inside `begin()`; a rowcount of 0 → `MemoNotFoundError` (nothing was deleted) |

Each check uses its own parent table's `user_id`; nothing is fetched and filtered in
Python. The "stored scope id" is `user_id` for `"user"` and the argument otherwise.

## Check order and "mints nothing"

D12: target check → allocation → id minting → insert. A refused create raises before
`next_id()` is called, so DoD-5 can pass a generator that records its calls.

## The partial update

The three optional parameters default to "not supplied" (`None`). The router forwards only
keys that were set and non-null (`001`'s `UpdateMemoRequest` note), so the service never
needs to tell "supplied as null" from "not supplied". The `UPDATE`'s `SET` clause is built
from the supplied values only: writing `is_enabled` alone must leave `is_forced` exactly as
stored (DoD-9). Do not add a defensive blank-body check here: blank bodies are refused by
the models (422) before the service is reached, and the frontend deletes rather than
blanking (D2).

## The mapper

One function from a `memos` row (a `Row` from a select of all ten columns) to `Memo`:
drop `user_id`; `scope_id` becomes `None` when `scope == "user"`. `003` imports this
function and `Memo` (D11). Keep it free of any connection use.

## Imports

`memos`, `characters`, `setups`, `sessions` Tables from `app.db.schema`;
`MemoNotFoundError`, `CharacterNotFoundError`, `SetupNotFoundError`,
`SessionNotFoundError` from `app.errors`; the scope literal from `app.models.memos`;
`SnowflakeGenerator` from `app.ids` (annotation). Nothing from any `app.services.` module
(DoD-15).

## Logging

If the module logs at all, it logs ids, the scope and counts — never `body`
(`deployment.md`'s redaction rule).

## Test seeding

Users first, then characters, setups and sessions by raw insert with their committed
columns: characters and setups as 011's `002.context.md` "Test seeding" lists them;
sessions with `id`, `user_id`, `character_id`, `setup_id` (nullable), `archived_at`,
`last_used_at`, `created_at`, `updated_at` (011's `002` value fields plus `user_id`).
Memos through `create_memo`, except where a DoD needs a precise state (another user's row,
chosen `sort_key` values, a raw disabled-and-forced row), which are raw inserts with
fixed-width timestamps. DoD-5 counts `memos` rows directly.
