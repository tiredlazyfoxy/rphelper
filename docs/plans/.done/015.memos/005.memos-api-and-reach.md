# Step 005 — The memos API client and the reach helper

## Goal

Add `app/memosApi.ts`, the `Memo` types and the five calls the frontend makes over the
shared client (list a level, create, update a subset, delete, fetch the chain), and
`app/memoReach.ts`, the pure reach derivation with `is_enabled` checked first and its
one-line statement (D7, R3).

## Interface intent

**`app/memosApi.ts`** (new)

- **`MemoScope`**: the union of the four scope strings.
- **`Memo`**: type mirroring the wire object field for field (`id` string; `scope`;
  `scope_id` string or null; `body` string; `is_enabled`, `is_forced` booleans;
  `sort_key` number; `created_at`, `updated_at` strings). No renaming layer.
- **`MemoChainLevel`**: type for one chain level: `scope`, `scope_id` (string or null),
  `memos` (array of `Memo`).
- **`MemoPatch`**: type for an update: any subset of `body` (string), `is_enabled`,
  `is_forced` (booleans).
- **`fetchMemos`**: takes a scope, a scope id (string, or `null` for the user level) and
  an optional signal. GETs one level's listing; resolves to the unwrapped array.
- **`createMemo`**: takes a scope, a scope id (string or `null`) and a body. POSTs
  `/api/memos` with a JSON object of exactly `scope`, `scope_id` and `body` — never a flag
  or `sort_key`; resolves to the created `Memo`. Takes no signal (D5).
- **`updateMemo`**: takes a memo id and a `MemoPatch`. PATCHes `/api/memos/<id>` with a
  JSON object holding exactly the keys present in the patch; resolves to the `Memo`.
  Takes no signal.
- **`deleteMemo`**: takes a memo id. DELETEs `/api/memos/<id>`; resolves to nothing on
  204. Takes no signal.
- **`fetchMemoChain`**: takes a session id and an optional signal. GETs the session's
  memo chain; resolves to the unwrapped array of levels, in the order received.
- All failures are the shared client's `ApiError`s, rethrown unchanged. Ids are never
  coerced.

**`app/memoReach.ts`** (new)

- **`MemoReach`**: the union `"forced" | "searchable" | "disabled"`.
- **`memoReach`**: pure. Takes anything carrying `is_enabled` and `is_forced` (a `Memo`)
  and returns its reach, testing `is_enabled` first: not enabled → `"disabled"`; enabled
  and forced → `"forced"`; enabled and not forced → `"searchable"`.
- **`reachStatement`**: pure. Takes a `MemoReach` and returns its one-line statement from
  `context.md`'s UI strings table.

## Definition of done

1. `[test]` `fetchMemos("user", null)` requests exactly `GET /api/memos?scope=user` (no
   `scope_id`); `fetchMemos("character", "7250000000000000001")` requests exactly
   `GET /api/memos?scope=character&scope_id=7250000000000000001`, and likewise for
   `"setup"` and `"session"`. Each resolves to the payload's `memos` array with every `id`
   and `scope_id` the identical string (or null) the payload carried. (UC-046, US-049.AC-1,
   US-050.AC-1, US-051.AC-1, US-052.AC-1)
2. `[test]` `createMemo("session", "7250000000000000009", "  # h\n")` POSTs `/api/memos`
   with the JSON body exactly `{"scope": "session", "scope_id": "7250000000000000009",
   "body": "  # h\n"}`; `createMemo("user", null, "x")` with exactly `{"scope": "user",
   "scope_id": null, "body": "x"}`. Neither body holds `is_enabled`, `is_forced` or
   `sort_key`. Each resolves to the response's `Memo`. (US-053.AC-1, US-049.AC-1,
   US-052.AC-1, D15)
3. `[test]` `updateMemo(id, { is_enabled: false })` PATCHes `/api/memos/<id>` with the JSON
   body exactly `{"is_enabled": false}` — no `is_forced` key; `{ is_forced: true }` sends
   exactly `{"is_forced": true}`; `{ body: "y" }` exactly `{"body": "y"}`. Each resolves to
   the response's `Memo`. (US-101.AC-1, US-101.AC-2, D6)
4. `[test]` `deleteMemo(id)` sends `DELETE /api/memos/<id>` and resolves to `undefined` on
   a 204. (D2)
5. `[test]` `fetchMemoChain("7250000000000000005")` requests exactly
   `GET /api/sessions/7250000000000000005/memo-chain` and resolves to the payload's
   `levels` array in the payload's order, each level's `scope_id` the identical string or
   null. (UC-046, US-057.AC-1)
6. `[test]` A 404 envelope with code `memo_not_found` makes `updateMemo` and `deleteMemo`
   reject with an `ApiError` of that code; a 404 `session_not_found` makes
   `fetchMemoChain` reject with that code; a 422 makes `createMemo` reject with an
   `ApiError`.
7. `[test]` `createMemo`, `updateMemo` and `deleteMemo` call `fetch` with no abort signal;
   `fetchMemos` and `fetchMemoChain` pass the signal they were given. (D5)
8. `[test]` `memoReach` over all four combinations: enabled + forced → `"forced"`; enabled
   + not forced → `"searchable"`; not enabled + forced → `"disabled"`; not enabled + not
   forced → `"disabled"`. (R3 — `is_enabled` gates first; D7)
9. `[test]` `reachStatement` returns exactly "Forced: always given to the assistant.",
   "Searchable: found only when the assistant searches." and "Disabled: never reaches the
   assistant." for `"forced"`, `"searchable"` and `"disabled"`. (D7)
