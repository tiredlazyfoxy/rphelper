# Step 003 — The memo chain service

## Goal

Add `services/memo_chain.py`: `resolve_chain`, which resolves a session's notes across the
levels that exist (user, character, setup when present, session) with one owner-scoped
session read and **one** memo query whose setup term is simply absent when the session has
no setup (R2, US-057); and `memo_reach`, the backend twin of R3's three-way derivation with
`is_enabled` checked first (D7), for 020 and 026 to reuse.

## Source files

backend/app/services/memo_chain.py

## Test files

backend/tests/test_memo_chain_service.py

## Interface intent

- **`MemoChainLevel`**: frozen dataclass value for one level of a chain: `scope` (the
  scope literal), `scope_id` (int, or `None` for the user level), `memos` (the level's
  `Memo` values in order). Shaped so `MemoChainLevelResponse` builds from it by attribute.
- **`resolve_chain`**: takes the Core `Connection`, `user_id` (required positional) and a
  session id. Reads the caller's session (archived or not) to learn its character id and
  its setup id, raising `SessionNotFoundError` for a missing or another user's session.
  Then issues **one** select over `memos`, owner-scoped, whose predicate is the OR of one
  term per level that exists: user (stored `scope_id` = the caller), character, setup
  **only when the session has one**, session. Returns the list of levels in the fixed
  order user, character, setup (when present), session — every existing level listed even
  when it holds no notes, each holding its notes ordered by `sort_key`, then `id`,
  disabled ones included. A read: leaves no transaction open on either exit. Writes
  nothing.
- **`memo_reach`**: pure. Takes a note's `is_enabled` and `is_forced` and returns one of
  the three reach names `"forced"`, `"searchable"`, `"disabled"`: not enabled →
  `"disabled"` whatever `is_forced` says; enabled and forced → `"forced"`; enabled and not
  forced → `"searchable"`. A literal type names the three values.

Imports from `services/memos.py` **only** `Memo` and its row mapper (D11).

## Definition of done

1. `[test]` For the caller's session **with** a setup, holding notes at all four levels,
   `resolve_chain` returns exactly four levels with scopes `user`, `character`, `setup`,
   `session` in that order; their `scope_id`s are `None`, the session's character id, its
   setup id and the session id; each level holds exactly that level's notes of the caller,
   ordered by `sort_key`, then `id` (raw-inserted out of order, one `sort_key` tie). A
   disabled note (including a disabled-and-forced one) is included in its level.
   (UC-046, R2, R3, D4)
2. `[test]` For the caller's session **without** a setup, holding notes at the user,
   character and session levels, `resolve_chain` returns exactly **three** levels, scopes
   `user`, `character`, `session` in that order — no setup level and no empty placeholder
   for it — with every one of those notes present in its level. A setup-level note of a
   setup under the same character is absent. (US-057.AC-1, R2)
3. `[test]` A level that exists but holds no notes is still returned, with an empty
   `memos`; a session with no notes at all returns three (no setup) or four (with setup)
   empty levels. (R2: no gap)
4. `[test]` The chain contains none of: another session's session-level notes, another
   character's character-level notes, another setup's notes, and **any** note of another
   user (including that user's user-level notes and a raw-inserted row of theirs whose
   `scope` / `scope_id` equal this session's levels). (R5, R2)
5. `[test]` `resolve_chain` with another user's session id, or an id that exists for
   nobody, raises `SessionNotFoundError`. (R5, D12)
6. `[test]` After raw updates archiving the session, its character and its setup,
   `resolve_chain` still returns all four levels with their notes. (D8)
7. `[test]` One query per resolution: counting the statements executed on the connection
   during `resolve_chain` gives exactly two `SELECT`s (the session read and the memo
   read), both for a session with a setup and for one without. (R2: the no-setup case is
   the same query with one term fewer)
8. `[test]` After `resolve_chain`, including when it raised `SessionNotFoundError`, the
   connection is not in a transaction, so a following `connection.begin()` succeeds; the
   `memos` rows are unchanged.
9. `[test]` `memo_reach` over all four combinations: enabled + forced → `"forced"`;
   enabled + not forced → `"searchable"`; not enabled + forced → `"disabled"`; not
   enabled + not forced → `"disabled"`. (R3 — `is_enabled` gates first; D7)
10. `[test]` The source text of `app/services/memo_chain.py` imports from `app.services`
    only the module `app.services.memos`, and from it only `Memo` and the row mapper; it
    contains no `fastapi` import and no `insert(`, `update(` or `delete(` call. (D11)
