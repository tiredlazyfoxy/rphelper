## Interface intent

**`app/memoChainState.ts`** (new)

- **`MemoChainState`**: data class, observable fields only, constructed from a
  `sessionId` (string): `sessionId`; `status`: `"idle"`, `"loading"`, `"ready"` or
  `"failed"`, starts `"idle"`; `levels`: array of `MemoLevelState`, starts empty.
- **`loadMemoChain`**: effect. Takes the state and an optional signal. Sets `"loading"`,
  requests the session's memo chain, and on success replaces `levels` with one new
  `MemoLevelState` per returned level — constructed from that level's `scope` and
  `scope_id` and populated with its notes (`populateMemoLevel`) — in the order received,
  then `"ready"`. On failure writes `"failed"` and keeps `levels`. Writes nothing once
  aborted; never rejects. Issues no per-level listing request.

**`app/MemoChainSection.tsx`** (new)

- **`MemoChainSection`**: `observer` component. Props: `sessionId` (string). Creates its
  `MemoChainState` once with `useState`; loads on mount with an `AbortController`
  aborted on unmount. Renders a **region** named **"Notes"** headed by a heading
  **"Notes"**, and in it, by status: `"idle"` / `"loading"` → a small `Loader`;
  `"failed"` → the text **"Could not load notes"** and a button **"Retry"** re-running the
  load with a fresh controller; `"ready"` → one `MemoLevelGroup` per level in state order,
  keyed by scope, each titled by a private scope-to-title mapping (**"Your notes"**,
  **"Character notes"**, **"Setup notes"**, **"Session notes"**) with a heading one level
  below "Notes". No notification anywhere.

**`app/SessionScreen.tsx`** (edited; 011-owned file, possibly edited by 013 `007`)

- In the `"ready"` render only, `MemoChainSection` is mounted for the loaded session's id,
  after the screen's existing ready content. Loading, not-found and failed render no
  section. Nothing else in the file changes.

## Definition of done

1. `[test]` A fresh `MemoChainState("s1")` has `sessionId` "s1", `status` `"idle"` and no
   levels. `loadMemoChain` sets `"loading"` while pending, requests exactly
   `GET /api/sessions/s1/memo-chain` and no `/api/memos` listing, then `"ready"` with one
   level state per returned level in the returned order, each with that level's `scope`,
   `scopeId` (null for the user level, the id string otherwise), its notes in order and
   status `"ready"`. A failed request sets `"failed"` and resolves without throwing; an
   aborted signal writes nothing. (UC-046, D16)
2. `[test]` `MemoChainSection` with a four-level chain renders a "Notes" region with a
   "Notes" heading, holding regions "Your notes", "Character notes", "Setup notes" and
   "Session notes" in that document order, each listing its level's notes and only
   those. (UC-046, R2, D1)
3. `[test]` With a **three-level** chain (no setup), the "Notes" region holds exactly the
   regions "Your notes", "Character notes" and "Session notes", in that order; there is no
   "Setup notes" region, heading or text anywhere, and every note of the three levels is
   listed. (US-057.AC-1, R2)
4. `[test]` A level with no notes renders its group with "No notes yet."; a disabled note
   renders in its group with "Enable note". (R2 — no gap; R3 — the owner sees disabled
