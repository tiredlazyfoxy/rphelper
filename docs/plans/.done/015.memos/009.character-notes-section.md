# Step 009 — The character page's Notes section

## Goal

Add `app/CharacterNotesSection.tsx`, the character page's character-level "Notes" region:
it owns one `MemoLevelState` for the character, loads it on mount and renders the shared
`MemoLevelGroup` titled "Notes" (D1). Mount it on `CharacterScreen` after the Sessions
section, keyed by the character id.

## Interface intent

**`app/CharacterNotesSection.tsx`** (new)

- **`CharacterNotesSection`**: `observer` component. Props: `characterId` (string).
  Creates its `MemoLevelState` for scope `"character"` and that id once with `useState`;
  runs `loadMemoLevel` on mount with an `AbortController` aborted on unmount; renders
  `MemoLevelGroup` with that state, the title **"Notes"**, the same heading order as the
  page's "Setups" and "Sessions" headings, and an `onRetry` that re-runs the load with a
  fresh controller (aborting any in-flight one). No other markup of its own.

**`app/CharacterScreen.tsx`** (edited; 009-owned, edited by 010 `006` and 011 `008`)

- In existing mode with status `"ready"`, `CharacterNotesSection` is rendered for the
  loaded character, keyed by the character id, **after** `SessionsSection`. New mode,
  loading, not-found and failed render no Notes section. Nothing else changes.

## Definition of done

1. `[test]` `CharacterNotesSection` for character C requests exactly
   `GET /api/memos?scope=character&scope_id=<C>` and renders a "Notes" region with a
   "Notes" heading listing the payload's notes in order, a disabled note among them with
   "Enable note". (UC-046, R3)
2. `[test]` With an empty listing the region shows "No notes yet."; "New note", typing
   "Voice: dry" and blurring POSTs `/api/memos` with exactly `{"scope": "character",
   "scope_id": "<C>", "body": "Voice: dry"}`; after the 201 the note is listed with
   "Searchable: found only when the assistant searches.", and no listing request follows
   the POST. (US-050.AC-1, US-053.AC-1, D5)
3. `[test]` A failed load shows "Could not load notes" and "Retry" in the region, with no
   notification; "Retry" requests the listing again and, on success, the notes render.
4. `[test]` `CharacterScreen` at `/characters/<id>` (amending 009's, 010's and 011's
   tests): once loaded, the "Notes" region is present and, in document order, follows the
   "Sessions" region. At `/characters/new`, and in the "Character not found" and "Could not
   load the character" states, there is no "Notes" region and no `/api/memos` request.
   (D1)
5. `[test]` For an archived character the "Notes" region still renders and a new note
   there POSTs with that character's id. (D8)
6. `[test]` Navigating in-entry from `/characters/<a>` to `/characters/<b>` requests `b`'s
   notes listing and shows `b`'s notes, with none of `a`'s. (D1)
7. `[test]` 009's, 010's and 011's existing assertions in
   `tests/app/CharacterScreen.test.tsx` and `tests/app/App.test.tsx` keep passing, with
   their `fetch` stubs extended to answer `GET /api/memos?scope=character&scope_id=<id>`
   by exact path and query (`009.context.md`); no other assertion is dropped.
8. `[manual/live]` Against a running backend: on a character's page, add a note, then open
   one of that character's sessions and find it under "Character notes"; edit it there,
   go back to the character page and see the edit after the page reloads its listing.
   (US-050.AC-1, D16)
