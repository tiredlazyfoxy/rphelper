# Step 002 — The memos service

## Goal

Add `services/memos.py`, the one layer that writes `memos` rows: the frozen `Memo` value,
its pure row mapper, and four owner-scoped operations (create at a level, list one level,
update any subset of body and flags, delete). Create checks the target level with its own
scoped select, allocates `sort_key` by D4 and stamps the US-053 defaults in one
transaction. An update of `is_enabled` never writes `is_forced` (R3, US-101). Delete is the
only removal (D2, R6 contrast).

## Interface intent

Every operation takes the Core `Connection` first and the owner's `user_id` (int) as a
**required positional** argument after it (after the id generator, for the create). Each
returns `Memo` values (or nothing, for the delete) or raises a domain error, and never
imports or raises anything HTTP-shaped.

- **`Memo`**: frozen dataclass value: `id` (int), `scope` (the scope literal from
  `models/memos.py`), `scope_id` (int, or `None` exactly when `scope` is `"user"`), `body`
  (string), `is_enabled` (bool), `is_forced` (bool), `sort_key` (int), `created_at`,
  `updated_at` (strings). **No `user_id`.** Shaped so `MemoResponse` builds from it by
  attribute.
- **The row mapper** (public, pure; D11 lets `003` import it): takes one `memos` row and
  returns its `Memo`, replacing the stored `scope_id` of a user-level row with `None`.
- **`create_memo`**: takes the connection, the id generator, `user_id`, a `scope`, a
  `scope_id` (int or `None`) and a `body`. In **one** write transaction: checks the target
  (for `"user"` the target is the caller and the `scope_id` argument is ignored; for the
  other three, the row must be the caller's character / setup / session, archived or not,
  else that level's not-found error); allocates `sort_key` as one more than the largest
  `sort_key` among the caller's notes at the same stored `(scope, scope_id)`, or 0 when
  there are none; mints the id; stamps `created_at` = `updated_at` with one instant;
  inserts with `user_id` from the argument, `is_enabled` true, `is_forced` false and the
  body verbatim. Returns the created value. A refusal inserts nothing and mints nothing.
- **`list_memos`**: takes the connection, `user_id`, a `scope` and a `scope_id` (ignored
  for `"user"`). Checks the target as create does, then returns the caller's notes at that
  level ordered by `sort_key`, then `id`, disabled ones included. A read: leaves no
  transaction open on either exit.
- **`update_memo`**: takes the connection, `user_id`, a memo id, and three optional values
  (`body`, `is_enabled`, `is_forced`) where "not given" means "not supplied". Writes only
  the supplied columns, plus `updated_at` when anything was supplied; with nothing
  supplied, writes nothing. Returns the row as it stands afterwards. Raises
  `MemoNotFoundError` for a missing or another user's memo.
- **`delete_memo`**: takes the connection, `user_id` and a memo id. Deletes that row and
  returns nothing. Raises `MemoNotFoundError` for a missing or another user's memo. Touches
  no other table.

There is **no** archive, restore, move-between-levels or reorder operation.

## Definition of done

1. `[test]` `create_memo` at each of the four levels (the user; the caller's character;
   the caller's setup; the caller's session) returns a `Memo` whose `id` is the value the
   supplied generator minted, with that `scope`, `scope_id` equal to the target's id
   (`None` for `"user"`), the body, `is_enabled` true, `is_forced` false, `sort_key` 0 and
   `created_at == updated_at` in the fixed-width form. The stored row carries `user_id` =
   the caller, and a user-level row stores `scope_id` = the caller's id.
   (US-049.AC-1, US-050.AC-1, US-051.AC-1, US-052.AC-1, US-053.AC-1)
2. `[test]` `create_memo` at `"user"` with a `scope_id` naming some other number stores
   `scope_id` = the caller's id and returns `scope_id` `None`; another user's
   `list_memos` at `"user"` does not contain it. (Wire contract request rules, R5)
3. `[test]` A body with leading and trailing whitespace and markdown
   (`"  # Heading\n\ntext  "`) is returned, stored and listed with exactly those
   characters. (D15)
4. `[test]` `sort_key` allocation: three creates at one level return 0, 1, 2; a create at
   a different level of the same caller returns 0. With raw-inserted rows at a level
   holding `sort_key` 2 and 5, the next create there returns 6. A raw-inserted row of
   **another user** at the same `(scope, scope_id)` with `sort_key` 40 does not affect the
   caller's allocation. After deleting the caller's highest note, the next create returns
   one more than the remaining maximum (gaps are left as they are). (D4, R5)
5. `[test]` `create_memo` and `list_memos` with a character, setup or session id that is
   another user's, or that exists for nobody, raise `CharacterNotFoundError`,
   `SetupNotFoundError` or `SessionNotFoundError` respectively. After a refused create the
   `memos` table holds no new row and the generator was not called. (R5, D12)
6. `[test]` After raw updates archiving the caller's character, setup and session
   (`archived_at` set), `create_memo` and `list_memos` at each of the three levels
   succeed. (D8)
7. `[test]` `list_memos` returns exactly the caller's notes at the addressed level: notes
   of the caller's other levels, of another of the caller's characters, and of another
   user (including another user's user-level notes) are absent. Rows raw-inserted out of
   order come back by `sort_key`, then `id` (two rows sharing a `sort_key` by ascending
   `id`). A disabled note is included. (R5, D4, R3)
8. `[test]` `update_memo` with only `body` returns the new body; `is_enabled`,
   `is_forced`, `sort_key`, `scope`, `scope_id` and `created_at` are unchanged; and
   `updated_at` is in the fixed-width form and not earlier than before. (UC-043, D6)
9. `[test]` A forced note (`is_enabled` true, `is_forced` true) updated with
   `is_enabled` false alone reads back `is_enabled` false and `is_forced` **true**; updated
   again with `is_enabled` true alone, it reads back forced (`is_enabled` true,
   `is_forced` true). The same sequence on a not-forced note returns it to `is_forced`
   false. (US-101.AC-1, US-101.AC-2, R3)
10. `[test]` `update_memo` with `is_forced` alone leaves `is_enabled` unchanged, including
    on a disabled note, which stays disabled with the new `is_forced`. (D6, R3)
11. `[test]` `update_memo` with nothing supplied returns the row unchanged, same
    `updated_at`. (D6)
12. `[test]` `update_memo` and `delete_memo` with another user's memo id, or an id that
    exists for nobody, raise `MemoNotFoundError`; the owner's row is unchanged and still
    present afterwards. (R5, D12)
13. `[test]` `delete_memo` removes the row: a following `list_memos` omits it,
    `update_memo` on its id raises `MemoNotFoundError`, and deleting it again raises
    `MemoNotFoundError`. Other notes at that level are untouched. (D2)
14. `[test]` After `list_memos` (including when it raised a not-found error) the connection
    is not in a transaction, so a following `connection.begin()` succeeds.
15. `[test]` The source text of `app/services/memos.py` contains no `fastapi` import, no
    import from any `app.services.` module, no `archived_at` (target checks carry no
    archived predicate, D8; `memos` has no such column, R6) and no `title`. (D11, R6, D8,
    US-119.AC-1)
