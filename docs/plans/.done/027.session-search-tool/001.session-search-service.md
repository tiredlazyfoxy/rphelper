# Step 001 — `search/session_search.py`: predicate, cap and `search_sessions`

## Goal

Add `services/search/session_search.py` with the result-cap and excerpt-length constants
(D2, D3), the session-search extra predicate (D1), and a sync `search_sessions` that runs
the 025 port's session variant (vector arm only) with that predicate and the fixed limit.

## Source files

backend/app/services/search/session_search.py

## Test files

backend/tests/test_session_search_service.py

## Interface intent

**`app/services/search/session_search.py`** (new)

- **Result-cap constant**: the value `5` (D2). Name frozen by the skeleton.
- **Excerpt-length constant**: the value `1500` (D3). Declared here so the module's
  literals live in one place. Step `002` uses it. Name frozen by the skeleton.
- **Session-search predicate factory**: takes the character id and the current session id.
  It returns an extra-predicate builder of the type 025's session scope accepts. Given the
  base relation, the builder returns the conjunction `character_id = <character id>`,
  `id != <current session id>` and `archived_at IS NULL`, built from that relation's
  columns. It does not add a `user_id` term (the port ANDs it). It reads nothing and
  executes nothing.
- **`search_sessions`**: sync.
  - Inputs: a connection, the user id, the character id, the current session id and the raw
    query text. Keyword-only `client_factory` and `timeout_seconds`, which default to the
    port's own defaults.
  - It builds the 025 session scope from the user id and the predicate above. It calls the
    port's `search` with the result-cap constant as `limit`. It returns the port's hits
    unchanged, order included.
  - Port errors propagate unchanged.
  - On return **and** on raise, the connection has no transaction open (it rolls back any
    transaction left open).
  - It reads only and writes nothing. It never touches `session_fts`.

## Definition of done

1. `[test]` The result-cap constant equals `5`, and the excerpt-length constant equals
   `1500`. (D2, D3)
2. `[test]` The predicate builder, compiled against the `sessions` table with literal binds,
   contains a `character_id` equality naming the given character id, an `id` inequality
   naming the given current session id, and an `archived_at IS NULL` test, all conjoined.
   (D1)
3. `[test]` **Found, three sources.** User A has character C with a distinctive persona, a
   with-setup past session P (setup description and settled entries both distinctive) and a
   current session S. The query is P's composed text. `search_sessions` returns P as the
   first hit. The hit's kind is `session` and its id is P's id. (US-067.AC-1 mechanism,
   US-138.AC-1, UC-053)
4. `[test]` **Another character (absence).** A second character C2 of A has the same persona
   text as C. C2 has a session whose setup and settled entries equal P's, so its composed
   text and vector are identical to P's. That session is absent from the results for A, C
   and S, and P is present. (US-069.AC-1, UC-054, R5)
5. `[test]` **Another user (absence).** User B owns a character with the same persona as C
   and a session whose composed text equals P's. B's session is absent from A's results. B
   cannot hold a session under A's character id, because the character FK forbids it; B's
   own character stands in. (US-069.AC-2, UC-054, R5)
6. `[test]` **Current session (absence).** The current session S has the same composed text
   as P. S is absent from the results and P is present. (D1)
7. `[test]` **Archived (absence, reversible).** An archived past session A1 of C has the
   same composed text as P. It is absent from the results. After `archived_at` is cleared
   on A1, a second call returns A1. (D1)
8. `[test]` **Archived setup still searchable.** A past session whose setup is archived, and
   which is not archived itself, is returned. (D1)
9. `[test]` **No setup, no partner field.** Neither S nor P has a setup. Sessions have no
   partner column (A). `search_sessions` raises nothing and returns P for a query equal to
   P's composed text. (US-068.AC-1, UC-053 postcondition)
10. `[test]` **Persona is part of the representation.** Past session Q of C has no setup and
    no settled entries, so its composed text is the persona alone. Past session R has
    settled entries that do not contain the query's text. With the query equal to the
    persona text, Q is returned, and Q ranks ahead of R. Q has no entry text at all, so
    being found proves that its vector carries the persona. This test does not claim
    paraphrase matching (`context.md` "What the fake embedder can prove").
    (US-138.AC-2 mechanism)
11. `[test]` **Cap.** With seven in-scope past sessions, all with vectors, exactly 5 hits are
    returned. (D2)
12. `[test]` **Errors propagate, no transaction left open.** With no designated embedding
    model, `search_sessions` raises `NoEmbeddingModelError`. With the fake scripted to
    raise, it raises `LlmUnreachableError`. After each raise, and after a successful call,
    the connection reports no transaction in progress. (D5)
13. `[test]` `services/search/session_search.py` imports no `fastapi` and nothing from
    `app.services.tools`. (D6)
