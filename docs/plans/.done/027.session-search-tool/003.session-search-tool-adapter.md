# Step 003 — The `session_search` Tool adapter and its registration

## Goal

Implement 021's `Tool` protocol for `session_search` in `services/tools/session_search.py`.
`run` performs step `001`'s search and step `002`'s excerpt read in one worker-thread call on
the seam's connection, using only `ToolScope` ids, and formats the result into header plus
excerpt blocks and a summary (D3, D5–D7). Register the adapter beside `memo_search` in
`services/tools/seam.py`, and amend the 021 and 026 tests that pinned the registry as holding
`memo_search` alone.

## Interface intent

**`app/services/tools/session_search.py`** (new)

- **The adapter class.** It implements 021's `Tool` protocol structurally.
  - `name` is `session_search`.
  - Construction takes the optional keywords `client_factory` and `timeout_seconds`. When
    they are omitted, `search_sessions`'s own defaults apply. Tests inject the 024 fake
    factory here.
  - **async `run(scope, connection, arguments)`** returns a `ToolOutcome`:
    1. It reads `query` from `arguments`. If `query` is missing or is not a string, it raises
       `ToolFailedError`, with the tool name as the detail. It reads no other key (D7).
    2. It awaits **one** `asyncio.to_thread` call on the given connection. Inside that call
       it runs:
       - `search_sessions`, with the `ToolScope`'s user id and character id, the
         `ToolScope`'s session id as the current session, the query, and the injected
         factory and timeout when they are set;
       - then the excerpt read for those hits' ids (step `002`), with the same user id.

       (D6)
    3. It returns `ToolOutcome(content, summary)`, built by the formatter from the excerpt
       records, which are in hit order.

    Errors propagate unchanged (D5). No transaction is left open, because steps `001` and
    `002` guarantee it and `run` issues nothing else.
- **Formatter** (module-level, pure). It takes the ordered excerpt records and returns the
  content and the summary, as D3 specifies.
  - **Content.** There is one block per record:
    - The header is `### Session <YYYY-MM-DD> · setup: <name>`, or
      `### Session <YYYY-MM-DD> · no setup`.
    - Then comes `\n`.
    - Then the body: the excerpt, or `(no settled entries)` when the excerpt is empty.

    Blocks are joined by `\n\n`, in record order. With no records, the content is exactly
    `No matching sessions.`
  - **Summary.** It is exactly `<N> sessions`, where N is the number of records.
- **Import shape.** This module follows the same form as 026's adapter
  (`003.context.md`):
  - seam names are imported for type-checking only;
  - `ToolOutcome` is imported where it is constructed.

**`app/services/tools/seam.py`** (021-owned, changed)

- **Production registry.** It now maps exactly `memo_search` and `session_search`, each to a
  default-constructed adapter instance. It stays a read-only mapping. Nothing else in the
  seam changes.

## Definition of done

1. `[test]` **Content shape and order.**
   - Setup: a designated model and the fake factory. A's character C has three past
     sessions with vectors: one with a setup named `Harbour Night`, one without a setup,
     and one with no settled entries.
   - `run` for A's current session returns content made of one block per hit, separated by
     `\n\n`.
   - The block order equals `search_sessions`'s hit order for the same inputs.
   - Each block's header line is exactly the D3 header for that session. Use the setup form
     or the `no setup` form, with the seeded `created_at` date.
   - Each block's body is that session's expected excerpt, or `(no settled entries)`.

   (D3, UC-053 main flow)
2. `[test]` **Excerpt bound through the tool.** A matched session whose settled text exceeds
   1500 characters has a body that starts with `…` and is exactly 1501 characters long.
   (D3)
3. `[test]` **Summary.** For the DoD-1 call, the summary is exactly `3 sessions`. For a
   single hit, it is `1 sessions`. No summary contains any seeded entry text or the
   distinctive token. (D3, 021 D6)
4. `[test]` **No persona, no ids.** The content contains neither the persona's nor the setup
   description's unique marker word. It also contains none of the decimal strings of the
   seeded user, character, session or setup ids. (D3)
5. `[test]` **Zero hits is success.** Character C has only the current session, plus
   sessions that are excluded: archived ones, and ones belonging to another character or to
   another user. For these, `run` returns content exactly `No matching sessions.` and summary
   exactly `0 sessions`, and it raises nothing. (D3)
6. `[test]` **Exclusions hold through the tool.**
   - Setup: these sessions all have composed text identical to an included past session P,
     and each has a unique marker in its entries:
     - the current session;
     - an archived session of C;
     - a session of A's other character, which has the same persona;
     - a session of B, under B's character with the same persona.
   - No marker from these sessions appears in the content.
   - P's block does appear.

   (US-069.AC-1, US-069.AC-2, UC-054, D1)
7. `[test]` **Ids only from the scope.**

     `character_id`, a `setup_id` and a `current_session_id`. It returns the same content as
     with `{"query": …}` alone.
   - Nothing of B's appears in the content.
   - The current session is still excluded.

   (D7, R5)
8. `[test]` **Bad arguments.** `run` raises `ToolFailedError` when given `{}`, and when given
   a non-string `query`. (D5)
9. `[test]` **Off the loop.** Setup: a designated model and the fake factory. `run` is
   awaited inside a running event loop, via `asyncio.run` of a coroutine that awaits it. It
   returns blocks, and it raises no "event loop is running" error. (D6)
