# Step 002 — step-specific context

Feature-wide facts are in `context.md`: D3 (shape and literals), D4 (hydration), the (A)
table descriptions, the test conventions. Only what is narrow to this step is below.

## Touch sites (A, built)

- `settled_entries` (`schema.py` ~:384) is a Core select, not a table or view. Use it as a
  subquery, or filter `messages` with the same `settled_at IS NOT NULL` condition. Either
  way, **the settled set is exactly what that select defines**. Do not add a kind filter,
  and do not add a buried or zone condition of your own. If buried or current-zone rows
  were ever to carry `settled_at`, that would be a defect in `settled_entries`, not
  something 027 corrects.
- The message text column and the message `kind` values come from the built `messages`
  table. The test-coder seeds the decision row with the decision kind that table defines.
- `sessions.created_at`: the stored type comes from the built schema. The conversion rule
  is D3's (UTC, naive taken as UTC).
- Owner scope: filter `sessions.user_id = :user_id AND sessions.id IN (:ids)`. Reach messages
  through those sessions. The setup join also matches `setups.user_id` (R5, defence in
  depth). Use one read, or a small fixed number of reads, for the whole id list, never one
  query per entry.
- Rollback: follow the `_reading` pattern of `services/sessions.py`. It is private to that
  module, so reproduce it locally rather than importing it.

## Why the bound lives here, not in the formatter

A long RP's settled text grows without limit. Cutting it in the service keeps the unbounded
text in this read and out of the adapter and the model message. The cut is by characters
(Python string length), taken from the end of the joined text. It may land mid-word, which
is acceptable. The marker shows the reader that the excerpt was cut.

## Test seeding notes

- No vectors are needed in this step. The read is plain SQL over seeded rows, so no
  designated model is required.
- DoD-6's long session: build entries of known lengths, so the expected tail can be
  computed from the seeded strings rather than from the code under test.
- DoD-2's unknown id is any snowflake-sized id that is not seeded.
