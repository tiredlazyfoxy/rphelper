# Step 001 — The chain clause and `search/memo_search.py`

## Goal

Give the memo chain one reusable clause builder in `services/memo_chain.py` (D2), and add
`services/search/memo_search.py`: the result-count constant (D1), the memo-search extra
predicate (searchable flags in R3 order AND the chain clause), and a sync `search_memos` that
runs the 025 port over the session's chain with that predicate and the fixed limit.

## Interface intent

**`app/services/memo_chain.py`** (built module, changed)

- **Chain clause builder** (new, public): takes a relation that exposes `scope` and
  `scope_id` columns, and the four level ids — user id, character id, setup id or none,
  session id. Returns one SQLAlchemy boolean clause: the OR of
  `(scope = 'user' AND scope_id = user id)`, `(scope = 'character' AND scope_id = character
  id)`, `(scope = 'setup' AND scope_id = setup id)` — **present only when the setup id is
  not none** — and `(scope = 'session' AND scope_id = session id)`. Level order in the
  disjunction is user, character, setup, session. It reads nothing and executes nothing.
- **`resolve_chain`**: behaviour unchanged. It may be re-routed through the builder (passing
  the `memos` table) only if its existing tests stay unedited and green; otherwise it is left
  as is.

**`app/services/search/memo_search.py`** (new)

- **Result-count constant** — the value `8` (D1). Name frozen by the skeleton.
- **Memo-search predicate factory** — takes the four level ids (as above). Returns an
  extra-predicate builder of the type 025's memo scope accepts: given the base relation,
  it returns `is_enabled AND NOT is_forced AND <chain clause over that relation>`, with the
  `is_enabled` term first and the `is_forced` term negated (R3). Both flags always present.
- **`search_memos`** — sync. Inputs: a connection, the four level ids, the raw query text;
  keyword-only `client_factory` and `timeout_seconds`, defaulting to the port's own defaults
  (025: `get_llm_client_factory`, `DEFAULT_EMBED_TIMEOUT_SECONDS`). Builds the 025 memo
  scope with the user id and the predicate above, calls the port's `search` with the
  result-count constant as `limit`, and returns the port's hits unchanged (order included).
  Port errors propagate unchanged. On return **and** on raise, the connection has no
  transaction open (rolls back any left open). Reads only; writes nothing.

## Definition of done

1. `[test]` The chain clause builder, compiled against the `memos` table with literal
   binds, for a with-setup chain contains four `(scope, scope_id)` terms naming the four
   given ids; for a no-setup chain it contains exactly three (user, character, session) and
   no `setup` term. (R2, D2)
2. `[test]` The chain clause builder, executed as a filter over seeded memos of one user,
   selects exactly the memos at the four chain levels (three for a no-setup chain) and none
   at another character, another setup or another session of the same user. (R2, D2)
3. `[test]` `resolve_chain` is unchanged: for a with-setup session it still returns the four
   levels (user level `scope_id` none) with their memos, and for a no-setup session three
   levels, as before. The existing memo-chain test file is not edited and stays green. (D2)
4. `[test]` The memo-search predicate, compiled against the `memos` table, names
   `is_enabled` before `is_forced`; the `is_forced` term is negated and conjoined with the
   `is_enabled` term; the chain disjunction is ANDed with both. (R3, D2)
5. `[test]` The result-count constant equals `8`. (D1)
6. `[test]` **All four levels.** A with-setup session of user A with one enabled,
   not-forced note at each of user, character, setup and session level, all carrying the
   query token: `search_memos` returns all four, each hit's memo `scope` / `scope_id` naming
   its level (user level `scope_id` = A's id). (US-063.AC-1, US-099.AC-2)
7. `[test]` **No setup, no gap.** A no-setup session of A with searchable notes at user,
   character and session level: `search_memos` raises nothing and returns all three, one
   per level. (US-065.AC-1, R2)
8. `[test]` **Flags (absences).** In A's chain, beside a searchable note, three notes with
   the same token at the same level — forced and enabled; disabled and not forced; disabled
   and forced — are each absent from the results, while the searchable note is present.
   (UC-052, US-100.AC-2, US-055.AC-2, R3)
9. `[test]` **Another user (absences).** User B's notes carrying the token — B's own
   user-level note, and for each of A's four levels a B note whose `(scope, scope_id)` equals
   that level of A's chain — never appear in A's results. (US-064.AC-1, R5)
10. `[test]` **Outside the chain (absences).** A's notes carrying the token at another
    session, another character and another setup of A are absent. (R2)
11. `[test]` **Cap.** With more than 8 searchable matching notes in the chain, exactly 8
    hits are returned. (D1)
12. `[test]` **Errors propagate, no transaction left open.** With no designated embedding
    model, `search_memos` raises `NoEmbeddingModelError` (even though `memo_fts` holds a
    match); with the fake scripted to raise, it raises `LlmUnreachableError`. After each
    raise, and after a successful call, the connection reports no transaction in progress.
    (D5, R4)
13. `[test]` `services/search/memo_search.py` imports no `fastapi` and nothing from
    `app.services.tools`. (context.md constraints)
