# Step 006 — The shared confirm modal, and the Users page: the list, the table and disable / re-enable

## Goal

Build the one shared confirm dialog the whole product will use, and the Users page that
loads accounts, renders them as a table with a row overflow menu, and disables and
re-enables an account — the disable behind the confirm.

## Interface intent

**`frontend/src/shared/ConfirmModal.tsx`** — the one shared confirm mechanism
(`ui-conventions.md`'s confirm convention, `context.md` D7). A small Mantine `Modal`
taking: whether it is open, the action's **title**, a **one-sentence consequence**, the
**confirm button's label**, an optional confirm **colour** (`red` for a destroy, the
action's own verb otherwise), an optional "in progress" flag, and **cancel** and
**confirm** callbacks. **Cancel sits left of confirm.** It holds no state of its own, owns
no timer, performs no request and knows nothing about accounts — a caller supplies every
word. It lives in `shared/` because `006` and `007` reuse it for deleting an LLM
connection and rebuilding the vector index.

**`frontend/src/admin/usersPageState.ts`** — the page's data and its free functions
(`002`'s D2, `003`'s D13, `context.md` D16).

- **A row type and a role type.** The row carries the account's **id as a `string`**,
  username, role, enabled flag and `last_login_at` (a string or nothing). `id: number`
  anywhere is a defect; nothing is parsed and nothing is sorted numerically. The role
  type is the two-value union matching the backend's ladder values.
- **A data class** holding observable fields only — the rows, an explicit load **status**
  (idle / loading / ready), and the message of a failure to render above the table —
  with `makeAutoObservable(this, {}, { autoBind: true })` in the constructor and **no
  methods and no computed getters**.
- **A load function** taking the store and an optional `AbortSignal`: it requests the
  admin users list through `shared/api.ts`, `runInAction`s the rows and the status, and
  **early-returns on an aborted signal before writing**. A failure clears nothing already
  rendered and puts its message in the error field.
- **A disable function and an enable function**, each taking the store, an account id (a
  **string**) and an optional signal. Each posts to the matching route and then
  **re-loads the list** — mutations are never optimistic, and the re-load is what makes
  the disable's side effects visible. A failure lands in the error field and the list is
  left as it was.

**`frontend/src/admin/UsersPage.tsx`** — an `observer` page component instantiating its
store through `useState(() => new UsersPageState())` — never `useMemo` — and driving the
load from a page-level `useEffect` with an `AbortController` cleanup.

- Its own **`Container size="lg" py="md"`** (the shell supplies no padding), a heading,
  and a header area with room for the Create button step `007` adds.
- **Loading** is a centered Mantine `Loader` gated on the explicit status field, not on
  "rows are still empty". **Errors** are an inline red `Alert` **above** the table and
  are **not also a notification**.
- The table is a plain Mantine **`Table`**, `striped highlightOnHover`, with columns
  **username**, **role** (a `Badge`), **last login** and **active** (a `Badge`), plus a
  trailing **`w={60}`** actions column. **No sorting, no filtering, no pagination** and no
  data-table library. An empty list renders headers with nothing under them — no
  empty-state component (`ui-conventions.md` leaves it optional and none is specified).
  A null `last_login_at` renders as an em dash; a present one is rendered as a readable
  local date-time, never as a relative "3 days ago" (no library, no requirement).
- **Row actions are one overflow `Menu`** behind a single `IconDots` trigger that itself
  goes through `shared/IconButton`, whose `label` names the row's account so twenty rows
  do not share one accessible name. **No other icon-only control appears in a row.** At
  this step the menu holds **Disable** for an enabled account and **Re-enable** for a
  disabled one — the two are mutually exclusive, not one disabled pair; steps `007` and
  `008` add their items to the same menu.
- **Disable opens the shared confirm**, whose consequence sentence says the person is
  signed out immediately and cannot sign in until the account is re-enabled. It
  **names no count and nothing derived from other users' data** (R5,
  `ui-conventions.md`). Confirming calls the disable free function and closes the modal;
  cancelling does nothing at all.
- **Re-enable is not confirmed** — it destroys nothing (`context.md` D7).
- The confirm's open flag and its target row are **component-local `useState`**, never
  page MobX state (`ui-conventions.md`). Handler invocations are `void`-ed with a
  non-rethrowing catch. **No success toast**: the list refreshing is the signal.
- The page renders **nothing about a character, setup, session, entry or memo** and no
  count of any of them (US-011.AC-2, UC-066, R5).

**`frontend/src/admin/AdminApp.tsx`** — one change: the `/` route renders `UsersPage`
instead of step `005`'s placeholder. Nothing else in the route table moves.

## Definition of done

1. `[test]` The confirm modal renders its title, its consequence sentence and its confirm
   label; **cancel is left of confirm**; cancel invokes only the cancel callback and
   confirm only the confirm callback. (`ui-conventions.md`'s confirm convention — **no
   product id**)
2. `[test]` The confirm modal renders nothing when closed, and it owns no state: reopening
   it with different words renders the new words. (**no product id**)
3. `[test]` On mount the page issues exactly **one** request, for the admin users list,
   and renders a `Loader` while it is in flight rather than an empty table.
   (`ui-conventions.md` — **no product id**)
4. `[test]` A loaded list renders one row per account showing its **username**, its
   **role** and its **enabled/disabled status**. (US-011.AC-1)
5. `[test]` The page renders **no** column, badge, tooltip or text carrying a character,
   setup, session, entry or memo, or any count of them — and issues no request but the
   list and the mutations. (US-011.AC-2, UC-066, R5)
6. `[test]` An account with no `last_login_at` renders an em dash rather than an empty
   cell or the word "null". (`admin-surfaces.md`'s "last login" column — **no product
   id**)
7. `[test]` A failed load renders an inline `Alert` **above** the table and raises **no
   notification**; a failed mutation does the same and leaves the previously loaded rows
   rendered. (`ui-conventions.md` — **no product id**)
8. `[test]` Each row has exactly **one** icon-only control — the overflow menu trigger —
   whose accessible name identifies that row's account, and the menu's entries are
   labelled text rather than icons. (`ui-conventions.md`'s IconButton/overflow-menu
   boundary — **no product id**)
9. `[test]` An **enabled** account's menu offers **Disable** and not Re-enable; a
   **disabled** account's menu offers **Re-enable** and not Disable.
10. `[test]` Choosing Disable opens the confirm and issues **no request** until it is
    confirmed; cancelling issues none at all and leaves the row enabled. (US-009.AC-1 —
    the guarded path to it)
11. `[test]` Confirming the disable posts to that account's disable route and then
    **re-loads the list**, after which the row renders as disabled — the state comes from
    the re-load, not from a local write. (US-009.AC-1, `ui-conventions.md`'s
    never-optimistic rule)
12. `[test]` The disable confirm's consequence sentence contains **no number and no count
    of anything** — it describes the action only. (R5, `ui-conventions.md` — **no product
    id**)
13. `[test]` Re-enable posts to that account's enable route **without** a confirm step and
    then re-loads the list, after which the row renders as enabled. (UC-007's alternate
    flow)
14. `[test]` **No success notification** is raised by any path on this page, and
    `notifyFailure` is called nowhere in it. (`ui-conventions.md`: "a notification whose
    message is a success is a defect" — **no product id**)
15. `[test]` Unmounting aborts the in-flight load and no store write happens after it.
    (`002`'s D2 — **no product id**)
16. `[test]` The store is a data class with observable fields only — no method, no
    computed getter — and every load and mutation used by the page is a free function
    taking it; the modal's open flag and target row are **not** fields of it.
    (`002`'s D2, `ui-conventions.md` — **no product id**)
17. `[test]` Every id the page holds and sends is a **`string`**: no `parseInt`, no
    numeric sort, and an account id beyond `Number.MAX_SAFE_INTEGER` round-trips through
    a disable and back into the re-loaded row unchanged. (`frontend-structure.md`, "Ids
    are strings" — **no product id**)
18. `[manual/live]` The table is a plain Mantine `Table` with `striped highlightOnHover`,
    a trailing `w={60}` actions column, and **no sorting, filtering or pagination
    control**. Verifier confirms by reading the module.
19. `[manual/live]` Against a running backend, disabling an account signs that person out
    of their open session on their next request, and re-enabling lets them log in again.
    (US-009.AC-1, UC-007's alternate flow)
20. `[manual/live]` Both colour schemes are correct for the table, the badges, the menu
    and the confirm.
21. `[manual/live]` `npm run typecheck`, `npm test` and `npm run build` all pass from
    `frontend/`.
