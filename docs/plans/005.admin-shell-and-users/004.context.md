# Step 004 — step-specific context

Feature-wide facts are in `context.md` (D13 for the five outcomes and the retry posture,
D14 for the pure/impure split and the navigation seam, D15 for the `entries.test.tsx`
repair, the no-stylesheet rule, the TypeScript-only rule). Only what is narrow to this
step is below.

## Borrowed interfaces, by module path and role

- **`frontend/src/shared/api.ts`** (`002/004`) — one request function taking a path, a
  method, an optional body and an optional signal, plus thin GET/POST/PATCH/DELETE
  helpers. It throws immediately if the path does not start `/api/`; it sends
  credentials and sets no `Authorization` header; 2xx gives the parsed body and an empty
  2xx resolves to nothing; a non-2xx is decoded into a thrown `ApiError`. **A 401
  performs a document navigation to `/login` and still throws, and there is no documented
  opt-out.** A 403 does not navigate. A `fetch` rejection becomes an `ApiError` with code
  `client_transport_failed` and **`status: 0`**. A caller's own `AbortSignal` firing
  propagates **unwrapped**. The module also exports the **document-navigation seam** the
  401 path calls (`002/status.md`, step 004's Skeleton record) — this step's deny
  navigation goes through that same seam so a test can observe it the same way.
- **`frontend/src/shared/apiError.ts`** (`002/004`) — `ApiError extends Error` carrying
  `code: string`, `message`, `detail` (defaults `{}`) and **`status: number`**; the two
  synthetic codes `client_malformed_error` and `client_transport_failed`; and a type
  guard. Branch on **`.code`**, never on `.message`.
- **`frontend/src/shared/notReady.ts`** (`003/004`) — the **pure predicate** taking a
  thrown value and answering whether it is the not-ready-yet condition: the
  transport-failure code, or the malformed-body code **with a status of 500 or above**.
  `003/context.md` D10 states it was put in `shared/` because *"`005`'s admin gate needs
  the same judgement"*. This step imports it and defines no condition of its own.
- **`frontend/src/shared/AppProviders.tsx`** (`002/005`) — `MantineProvider` (theme from
  `theme.ts`, manager and default from `colorScheme.ts`, `defaultColorScheme="dark"`)
  wrapping `<Notifications autoClose={5000} />` above its children; it owns the
  stylesheet import order (Mantine core → notifications → `global.css` last). The admin
  entry already mounts it.
- **`frontend/src/admin/main.tsx`** (`002/006`) — today it does exactly three things:
  find the mount element, `createRoot`, and render `AppProviders` wrapping
  `BrowserRouter basename="/admin"` wrapping a **placeholder** catch-all route rendering
  a marker element. `002/006`'s step file forbids, *at that stage*, "No store, no data
  fetch, no gate, no shell, no `AppShell`, no error boundary", and `006.context.md`
  records that later features **replace their entry's route table wholesale**. So there
  is **no gate stub, no `resolveAdminAccess`, no `enforceAdminAccess` and no `AppShell`
  anywhere**; this step writes the first two.

## The `/api/me` contract this step binds to

`backend-structure.md` and `004/003`: guarded by `require_user`, **200** with `{id (a
decimal string), username, role}` and nothing else; **401** for no cookie, an unissued
token, a revoked session, an expired session, or an account that has since been disabled.
Its response model is the identity model in `backend/app/models/auth.py`. The `id` is a
**string** in the frontend and is never parsed.

## The marker, and why it survives

`002/006`'s Skeleton record fixes the mechanism: the marker is the attribute `data-entry`
with the value `"admin"`, one mount element with id `root`, and a basename mismatch makes
`BrowserRouter` render nothing — which is what makes "the marker is present at
`/admin/users`" a real basename assertion. Keeping the marker is cheaper than replacing
that mechanism, so it survives this step inside the router; step `005` moves it onto the
shell, **above** the `<Routes>`, so it stays present on every admin route including the
404.

## How a test evaluates this entry

`002/status.md`'s step-006 Skeleton record holds the recipe (reset modules, install a
fresh `<div id="root">`, `pushState` the location, `await act(async () => { await
import("../src/admin/main"); })`, assert on `[data-entry=…]`). The two additions this
step needs: `fetch` is stubbed per test (no network-mocking library is a dependency), and
the document-navigation seam is spied on rather than letting jsdom attempt a navigation.

## Gotchas

- **The 401 path is a double event.** The shared client navigates *and* throws. A gate
  that navigated again on denied-no-session would fire two navigations for one condition;
  DoD-4 pins it.
- **A 403 on `/api/me` should not happen** — that route carries `require_user`, not
  `require_role` — but it must not be classified as not-ready if it ever does. It is
  *failed*. Do not add a 403 branch that navigates.
- **The interval belongs to the boot code, not to a component.** A hook holding a timer
  plus a re-render is exactly the reactive-state-in-a-hook shape `admin-surfaces.md`
  forbids, and a MobX store for a two-state screen would be heavier than the screen. The
  boot function owns the `setInterval` handle and clears it on the first non-not-ready
  outcome.
- **`basename` is `"/admin"` with no trailing slash**; nginx serves the document under
  `/admin/` **with** one. Two strings, two mechanisms, neither derived from the other
  (`002/context.md` seam S2).
