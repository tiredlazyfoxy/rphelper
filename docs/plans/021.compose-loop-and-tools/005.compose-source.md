# Step 005 — The compose source: the tool-calling loop

## Goal

Add `services/compose.py` with the async source 019's harness drains: optional `accepted`,
then on its own connections the use-time model check, context assembly, configuration and tool
scope, then rounds of `chat_stream` turning content into `token` frames, reasoning into
`<think>`-wrapped tokens, and tool calls into dispatched tool frames, until a round with no
tool calls — whose text is persisted as one assistant row before `done` (D3, D4, D11).

backend/app/services/compose.py

## Interface intent

**`app/services/compose.py`** (new)

- **`compose_stream`**: an async generator of 019 frame values. Inputs: the engine, the id
  generator, the user id, the session id, the accepted message id (or none, for a textless
  compose), the timeout in seconds, the chat-client factory (003), the tool registry (004).
  Behaviour, in order:
  1. if an accepted id was given, yields `accepted(id)` first;
  2. on one connection it opens from the engine and closes before any provider call:
     `resolve_model_for_use` (017; its domain errors propagate), `assemble_context` (020),
     `get_session_configuration` (017) → `offered_tools` (004), `build_tool_scope` (004),
     `open_chat_client` (003; `secret_ref_missing` propagates);
  3. the conversation starts as a system `ChatMessage` holding the assembled system prompt,
     followed by the assembled messages; the request's tools are the offered declarations;
  4. loops over rounds with no cap (D11): consumes `chat_stream(model name, conversation,
     tools)` under a closing guarantee (the iterator is closed whenever the source is), turning
     reasoning and content into tokens per D4 and accumulating tool-call fragments by index;
     when a round ends with calls, appends the round's assistant message (content without
     reasoning, the calls in index order, fallback ids per D11) and, per call in index order,
     yields `tool_start_frame(call)`, awaits `dispatch`, yields its frame and appends its tool
     message, then starts the next round;
  5. on a round with no calls, writes **one** assistant row through `append_assistant_message`
     on a short-lived connection, its text being every token text yielded in the exchange
     concatenated (think tags included), and yields `done(row id)`.
  - It never catches a provider or domain error to write a row; any failure simply propagates
    (019 D4: the harness persists and emits the `error` frame). It never touches a caller's
    connection.

## Definition of done

1. `[test]` Given an accepted id, the first frame is `accepted` with that id; given none, no
   `accepted` frame is yielded at all. (D2)
2. `[test]` With a session whose user RP language is `"Japanese"`, the fake client's first
   call receives messages whose first item is role `system` with content containing the line
   `=== Languages ===` and a line starting `- Candidates:` that contains `Japanese`, followed
   by the zone's user message with its text; the model name passed is the session's captured
   model. (US-037.AC-1 — the instruction is sent; UC-034; R4)
3. `[test]` Content deltas `"Once "`, `"upon"` then end → frames token `"Once "`, token
   `"upon"`, `done(id)`; afterwards the zone holds an assistant row with text `Once upon`
   whose id equals the `done` id. (UC-034, 019 D4)
4. `[test]` Reasoning deltas `"r1"`, `"r2"` then content `"Hi"` → tokens exactly `<think>`,
   `r1`, `r2`, `</think>`, `Hi`; a round of reasoning only → `<think>`, `r1`, `</think>`;
   content `"<think>x</think>Hi"` with no reasoning field → that one token, no added tags. The
   persisted row text equals the concatenation of the tokens. (D4)
5. `[test]` With a fake `memo_search` registered and switched on: round 1 delivers the call in
   three fragments (id `"call_a"` + name, then `{"query":`, then `"inn"}`) and no content;
   frames are `tool_start` (args `{"query":"inn"}`), `tool_result`; the fake client's second
   call receives the conversation ending with an assistant message carrying the one call with
   arguments `{"query":"inn"}` and then the tool message (`tool_call_id` `"call_a"`, the fake's
   content); round 2's content becomes tokens and `done`. Exactly one assistant row and one
   tool row are written. The first call's tools list is exactly the `memo_search` declaration.
   (D11, D5)
6. `[test]` A registered, enabled fake whose `run` raises: frames `tool_start`, `tool_fail`
   (`tool_failed`), then round 2's tokens and `done`; the second call's last message is the
   tool message with content `The tool failed. Continue without its result.`. The exchange
   ends in `done` with an answer. (R9, UC-051, UC-053)
7. `[test]` 30 consecutive rounds each with one tool call, then a content round → 30
   `tool_start` / `tool_result` pairs, then tokens and `done`; 31 client calls. (FEAT-010 no
   cap, D11)
8. `[test]` One round with two calls (index 0 and 1, fragments interleaved) → dispatched in
   index order (`tool_start` 0, result 0, `tool_start` 1, result 1); the next call's assistant
   message carries both calls in index order. (D11)
9. `[test]` A call whose fragments never carry an id is dispatched with id `call_1`; a second
   id-less call later in the same exchange gets `call_2`. (D11)
10. `[test]` With no enabled model on the instance / a session with no captured model / a
    captured model not enabled, iterating the source yields `accepted` (when given) and then
    raises `NoModelEnabledError` / `ModelNotChosenError` / `ModelNotEnabledError`
    respectively; the factory is never called and no assistant row exists. (R4, D3)
11. `[test]` A fake client that yields content `"Par"` then raises `LlmUnreachableError`: the
    source yields token `"Par"` then raises `LlmUnreachableError`; **no** assistant row was
    written by the source. (019 D4, US-044.AC-1)
12. `[test]` Closing the source (`aclose`) while it is suspended after a token: the fake
    client's iterator records that it was closed, and no assistant row is written by the
    source. (US-132.AC-2, D11)
13. `[test]` With the production (empty) registry and all switches on, the client is called
    with an empty tools list. (D5, U3)
14. `[test]` Source convention: `compose.py` imports no `fastapi`. (D15)
15. `[manual/live]` Against a real llamaswap or OpenAI model, through `006`'s route: a
    discussion in the preferred language yields a candidate in the RP language when one is
    asked for (US-037.AC-1); a reasoning model's thinking arrives wrapped in `<think>` …
    `</think>` and is absent from the settled text.
