# Step 004 — step-specific context

Feature-wide facts (D5, D6, D7, D13, D15, the literals, the payload table) are in
`context.md`. Placement of the seam (`app/services/tools/`) is new to the layout and is
recorded in `outcome.md`.

## Interfaces this step calls

- **`services/sessions.get_session(conn, user_id, session_id)`** (011, built): owner-scoped,
  raises `SessionNotFoundError`; the returned session carries `character_id` and `setup_id`
  (nullable).
- **017 `003` `SessionConfiguration`**: `tool_memo_search`, `tool_session_search`,
  `tool_web_search`, each a resolved setting whose `.value` is a bool (never null — a tool no
  level sets is on, level `default`).
- **019 `001` frame values**: tool-start (tool, call id, args mapping), tool-result (tool, call
  id, summary), tool-fail (tool, call id, code). Use 019's names as frozen by its skeleton.
- **`messages.append_tool_message`** (step `001`) and `ToolFailedError.code` (step `001`).
- **`ChatMessage` / `ToolCall`** (step `002`).
- The id generator type is the one `get_id_generator` returns (routers/bootstrap.py:50); the
  engine is a SQLAlchemy `Engine` (`get_engine(settings)`, db/engine.py:108).

## For the binding features (026 / 027 / 028) — what the seam promises

- A tool receives a `ToolScope` it cannot forge and an open connection it must leave with no
  transaction open; it returns `ToolOutcome(content, summary)` or raises. Raising a domain
  error such as `no_embedding_model` is fine: the seam turns any `Exception` into
  `tool_failed`. Implementations register under their declared name; they do not supply their
  own schema.

## Gotchas local to this step

- Catch `Exception`, never `BaseException`: `CancelledError` and `GeneratorExit` must pass
  through untouched (DoD-9).
- The failure frame and the persisted payload carry the **name as the model gave it**, even
  for an unknown name.
- The connection given to `run` is closed in a `finally`; the row write uses a separate
  short-lived connection opened after `run` finishes, so a stop during `run` never reaches the
  write.
- Tests build the engine file-locally (`schema.metadata.create_all`) and pass it in; the id
  generator is constructed as other service tests do.
