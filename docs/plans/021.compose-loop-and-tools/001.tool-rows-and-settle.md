# Step 001 — Tool rows, their invariants, and `<think>` stripping at settle

## Goal

Give the backend everything a tool row needs before anything writes one: the `tool_failed`
error, a `messages` write for `role='tool'` rows with the two tool columns exposed on
`StreamMessage`, the edit refusal and settle's head rule for tool rows (D8), plus the `<think>`
convention's strip function and its application at settle (D4).

## Interface intent

**`app/errors.py`** (changed)

- **`ToolFailedError`**: a `DomainError` subclass, code `tool_failed`, HTTP status 502, a fixed
  default message, `detail` per instance (the raiser puts the tool name there) (D13).

**`app/services/llm/chat.py`** (changed; 020's module)

- **The two tag literals** `<think>` and `</think>` as module constants (D4).
- **`strip_think`**: pure; takes a text, returns it with every think block removed per D4's
  strip rule (trim only when something was removed; otherwise byte-for-byte unchanged).

**`app/services/messages.py`** (changed)

- **`StreamMessage`** gains `tool_name` and `tool_payload` (each a string or none), appended
  **after** the existing eight fields **with a default of none**, so every existing constructor
  call stays valid. `list_zone` and `list_entries` populate them from the views' rows.
- **`append_tool_message`**: inputs: connection, id generator, user id, session id, the text,
  the tool name and the payload string. Inserts one current-zone row with role `"tool"`, kind
  NULL, `related_to` / `settled_at` NULL, `tool_name` and `tool_payload` set, inside one
  transaction, with the same ownership check (`SessionNotFoundError`) and session bump as
  `append_message` / `append_assistant_message` (019 D8's shared insert, extended to carry the
  two tool columns). Returns the `StreamMessage`. It does not interpret the payload.
- **`edit_message_text`**: additionally refuses a row whose role is `"tool"` with
  `MessageNotEditableError` (`message_not_editable`), writing nothing (D8). Its other
  behaviour is unchanged.

**`app/services/settle.py`** (changed)

- **`settle`**: the head is the **last zone row whose role is not `"tool"`**; when no such row
  exists the zone counts as empty and `zone_empty` is raised with nothing changed. Every other
  zone row (tool rows included) is buried under the head as today. When the head's role is
  `"assistant"`, `strip_think` is applied to its text **before** 012's `(( ))` classification
  and fragment stripping; a head of any other role is not think-stripped. Everything else is
  unchanged.
- **`reopen`**: unchanged.

## Definition of done

1. `[test]` `append_tool_message` on an owned session returns a `StreamMessage` with role
   `"tool"`, kind `None`, `settled_at` `None`, and the given text, tool name and payload
   verbatim; `list_zone` then lists it in id order after an earlier `append_message` row, with
   the same `tool_name` / `tool_payload`. (D7)
2. `[test]` `append_tool_message` against another user's session and against an unknown id
   raises `SessionNotFoundError` and writes no row. (R5, D7)
3. `[test]` `StreamMessage`s read by `list_zone` / `list_entries` for user and assistant rows
   carry `tool_name` and `tool_payload` `None`; a `StreamMessage` constructed with only the
   original eight fields is valid and has both `None`. (D7)
4. `[test]` `GET /api/sessions/{id}/zone` with a tool row in the zone answers 200; the tool
   row appears with `"role":"tool"`, and **no** message object carries a `tool_name` or
   `tool_payload` key (each has exactly the eight wire keys). (D7, 012 wire contract)
5. `[test]` `edit_message_text` on a zone tool row raises `MessageNotEditableError` and the
   row's text is unchanged; a zone user row and a zone assistant row in the same session are
   still edited. `PATCH /api/messages/{tool row id}` answers 409 `message_not_editable`.
   (D8, US-115.AC-1)
6. `[test]` Settle over a zone `[user, assistant, tool]` (by id): the assistant row is the
   settled head; the user row and the tool row both have `related_to` = the head's id.
   (D8, US-126.AC-1)
7. `[test]` Settle over `[user, tool, tool]`: the user row is the head and settles with its
   text as-is (kind `turn`); both tool rows are buried under it. (D8, US-135.AC-1)
8. `[test]` Settle over a zone holding only tool rows raises `zone_empty`; no row changes.
   (D8, R11)
9. `[test]` `strip_think` maps every input of `context.md` D4's worked-examples table to its
   output exactly. (D4)
10. `[test]` Settle of an assistant head with text `<think>x\ny</think>\n((ooc))` files
    `kind='decision'` with text `((ooc))`; an assistant head with text
    `<think>plan</think>\n\nShe nods.` files `kind='turn'` with text `She nods.`.
    (D4, R12, US-129.AC-1)
11. `[test]` Settle of a **user** head whose text is `<think>a</think> b` keeps the think
    block: the settled text is `<think>a</think> b`. (D4)
12. `[test]` Settle of an assistant head with no think block stores its text exactly as
    before this step (012's behaviour; existing settle tests pass untouched). (D4, R12)
13. `[test]` Re-open after settling a group that includes a tool row returns the head and all
    buried rows, the tool row included, to the zone. (R11, D8)
14. `[test]` `ToolFailedError` has code `tool_failed` and status 502; its default message is
    non-empty; given detail `{"tool": "memo_search"}` it keeps that detail. (D13)
