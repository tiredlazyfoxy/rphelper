## The list query and its 422

`scope` is a required query parameter typed by `models/memos.py`'s scope literal, so a
missing or unknown value is FastAPI's own 422. `scope_id` is an optional query parameter
of the inbound-snowflake kind (a non-numeric value → 422). The "non-user scope needs a
`scope_id`" rule cannot be expressed per-parameter, so the handler checks it and answers
422 itself. Any 422 form is acceptable — raising FastAPI's `RequestValidationError` with
one error entry, or an equivalent that the app's handlers render as 422 — provided it adds
**no domain code**; DoD-5 checks the status and that nothing was written. For `"user"`, a
supplied `scope_id` is dropped before calling the service.

If the skeleton finds the optional inbound snowflake awkward as a query parameter (the
`None`-into-`int()` gotcha recorded in `001.context.md`), it may declare `scope_id` as an
optional string and convert it in the handler, answering 422 for a non-numeric value.

## The create

`CreateMemoRequest` already validates the scope / `scope_id` pairing and the body
(`001`). The handler passes `scope_id` through for the three non-user levels and `None`
for `"user"`. Flags, `sort_key`, `user_id` and `title` in the request are ignored keys
(`001`); nothing here reads them.

## The PATCH forwarding

Forward a field only if it is in the request model's set fields **and** its value is not
`None`, exactly as `routers/setups.py` does. `{}` and `{"body": null}` therefore reach the
service with nothing supplied and answer the row unchanged.

## The 204

Declare `status_code=204` and return an empty `Response` (no JSON body, no
`response_model`). The frontend's `apiDelete` resolves 204 to `undefined`.

## Path coexistence and registration

- `/api/memos` and `/api/memos/{memo_id}` have no other owner.
- `/api/sessions/{session_id}/memo-chain` sits beside 011's `/api/sessions/{session_id}`
  (GET) and `…/archive` / `…/restore` (POST), and 012's stream routes under
  `/api/sessions/{id}/…`. The last segment `memo-chain` is a literal no other router
  declares, and the segment count differs from 011's GET, so nothing overlaps.
- Append the include to the **end** of `main.py`'s router list. DoD-15 guards that the
  earlier routers still match first.

## Conversions

`MemoResponse` and `MemoChainLevelResponse` build from the service values by attribute
(`001`). The chain conversion maps each `MemoChainLevel` in order and each of its memos
through the `Memo` conversion; it neither re-orders nor drops a level.

## Test seeding

Users A and B (role `roleplayer`) through the file-local `_insert_user`, each logged in on
its own client. Characters, setups and sessions through their routes as their owner:
`POST /api/characters`, `POST /api/characters/{id}/setups`,
`POST /api/characters/{id}/sessions` with `{"setup_id": "<S>"}` or `{"setup_id": null}`.
Archive through `POST /api/characters/{id}/archive`, `POST /api/setups/{id}/archive`,
`POST /api/sessions/{id}/archive`. Disabled and forced states are reached through
`PATCH /api/memos/{id}`, not raw inserts. "Nobody's" ids are large decimal strings no row
holds.
