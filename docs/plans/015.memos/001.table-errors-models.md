# Step 001 — The `memos` table, `memo_not_found`, and the memo models

## Goal

Declare the `memos` table in the registry (D10), add the `memo_not_found` (404) domain
error (D12), and add the request and response models for the five memo routes. Keep the
backend test landmines that registering `memos` touches passing.

## Interface intent

**`db/schema.py`** (extended)

- **`memos`**: a module-level `Table` literal bound to the one `metadata`, declared after
  `sessions`, with exactly the ten columns of D10: the snowflake `id` primary key (the
  registry's id form); `user_id` (NOT NULL, FK `users.id`, no `ON DELETE`); `scope` (NOT
  NULL, constrained by a database CHECK to `user`, `character`, `setup`, `session`);
  `scope_id` (NOT NULL, the registry's id column type, **no FK**); `body` (Text, NOT NULL);
  `is_enabled` (Boolean, NOT NULL, default true with a matching server default);
  `is_forced` (Boolean, NOT NULL, default false with a matching server default);
  `sort_key` (Integer, NOT NULL, no default); `created_at` and `updated_at` (Text, NOT
  NULL). Plus one non-unique index on `(user_id, scope, scope_id, sort_key)`, in that
  order. A comment block above it cites `data-model.md` "### `memos`" and D2, D4, D10.

**`errors.py`** (extended)

- **`MemoNotFoundError`**: a `DomainError` subclass, code `memo_not_found`, HTTP status
  404, empty `detail`, a fixed non-empty default message. Same shape as
  `SessionNotFoundError`.

**`models/memos.py`** (new)

- **The scope literal**: a type naming exactly the four scope strings, used by every model
  below and importable by the services.
- **`MemoResponse`**: response model with `id` (outbound snowflake → decimal string),
  `scope`, `scope_id` (outbound snowflake or null), `body`, `is_enabled`, `is_forced`,
  `sort_key` (a plain integer, not an id), `created_at`, `updated_at`. No `user_id`.
  Buildable from a service value by attribute.
- **`MemoListResponse`**: wraps a list of `MemoResponse` under the key `memos`.
- **`MemoChainLevelResponse`**: one chain level: `scope`, `scope_id` (outbound snowflake
  or null), `memos` (a list of `MemoResponse`).
- **`MemoChainResponse`**: wraps a list of `MemoChainLevelResponse` under the key
  `levels`.
- **`CreateMemoRequest`**: request model, unknown keys ignored. `scope` (the literal,
  required); `scope_id` (optional, nullable inbound snowflake); `body` (required string,
  non-blank, **not stripped**). A non-user `scope` without a `scope_id` fails validation.
  For `scope` `"user"` a supplied `scope_id` is accepted and has no effect downstream.
  Flags sent in the body are ignored like any unknown key.
- **`UpdateMemoRequest`**: request model, unknown keys ignored. `body` (optional; when a
  string is supplied it must be non-blank, not stripped), `is_enabled` and `is_forced`
  (each optional boolean). A key sent as `null` parses as not supplied in effect (the
  router forwards a field only if it is in the set fields **and** not `None`, as
  `routers/setups.py` does).

## Definition of done

1. `[test]` 015 adds `memos` to the registry, and the 015 delta in `tests/test_db_schema.py`
   uses the same later-table-proof form as the 009 / 010 / 011 deltas (`001.context.md`
   "The delta"). `memos` is in `schema.metadata.tables`, and the assertion still holds
   when a later feature adds a table.
2. `[test]` `memos` has exactly the columns `id`, `user_id`, `scope`, `scope_id`, `body`,
   `is_enabled`, `is_forced`, `sort_key`, `created_at`, `updated_at`; `id` is the primary
   key; every column is NOT NULL. The table has **no** `title`, `name`, `archived_at`,
   `state` or `status` column. (US-119.AC-1, R3, R6, D10)
3. `[test]` `memos.user_id` is a foreign key to `users.id`; `scope_id` has **no** foreign
   key; no foreign key declares an `ON DELETE` clause. The table declares exactly one
   index, non-unique, whose columns are `user_id`, `scope`, `scope_id`, `sort_key` in that
   order. (D10, D4)
4. `[test]` After `metadata.create_all` on a fresh engine: a row inserted with only `id`,
   `user_id`, `scope`, `scope_id`, `body`, `sort_key` and the two timestamps reads back
   with `is_enabled` true and `is_forced` false. (US-053.AC-1, R3, D10)
5. `[test]` On the same engine, a row with `scope` `"world"` fails to insert, each of the
   four valid scopes inserts, and a row whose `user_id` names no `users` row fails (FK
   enforced). Two rows with the same `user_id`, `scope`, `scope_id` and `sort_key` both
   insert (no uniqueness). (D10, D4)
6. `[test]` The set of scope values the `memos` table's CHECK permits equals the set of
   strings in `models/memos.py`'s scope literal, and both equal `{"user", "character",
   "setup", "session"}`. (D10, R2)
7. `[test]` `MemoNotFoundError` is a `DomainError` with code `memo_not_found` and HTTP
   status 404. Raised from a route on an application with the exception handlers
   registered, it answers 404 with `{ "error": { "code": "memo_not_found", "message":
   <non-empty string>, "detail": {} } }`. (D12, R5)
8. `[test]` `MemoResponse` built from int `id` and `scope_id` serialises both as their
   decimal strings; with `scope_id` `None` it serialises JSON `null`; `sort_key` stays a
   JSON number; the object has exactly the nine wire keys (`context.md`) and no `user_id`.
   `MemoListResponse` serialises with the single key `memos`; `MemoChainResponse` with the
   single key `levels`, each level with exactly `scope`, `scope_id`, `memos`, in the order
   given. (D9)
9. `[test]` `CreateMemoRequest`: `{"scope": "character", "scope_id": "7250000000000000001",
   "body": "x"}` parses with `scope_id` the int `7250000000000000001`; `{"scope": "user",
   "body": "x"}` parses; `{"scope": "character", "body": "x"}` fails validation;
   `{"scope": "world", "scope_id": "1", "body": "x"}` fails; `"body": ""` and `"body": "  \n"`
   fail; a missing `body` fails; `"body": "  # h\n"` parses and keeps those exact
   characters. Unknown keys (`user_id`, `is_enabled`, `is_forced`, `sort_key`, `title`)
   are ignored and do not appear on the parsed model. (US-053.AC-1, US-119.AC-1, D2, D15)
10. `[test]` `UpdateMemoRequest`: `{}` parses with no field set; `{"is_enabled": false}`
    sets only `is_enabled`; `{"is_forced": true}` sets only `is_forced`; `{"body": "y"}`
    sets only `body`; `{"body": ""}` and `{"body": "   "}` fail validation; unknown keys
    (`scope`, `scope_id`, `sort_key`, `user_id`) are ignored. (D6, D15, D2)
11. `[test]` 006's, 009's, 010's and 011's existing registry-delta assertions in
    `tests/test_db_schema.py` still pass with `memos` registered; if they subtract a
    "declared by later features" set, `memos` is added to it. No other assertion changes.
12. `[test]` `tests/test_admin_db_router.py`'s undeclared-name expectations (404
    `unknown_table`) still pass with `memos` registered: **only if** its undeclared-names
    list holds `"memos"` is that entry replaced by a name no feature will declare; nothing
    else changes.
13. `[manual/live]` Against an existing database that pre-dates 015, the admin Database
    page lists `memos` as missing, and **Create** brings it to in sync. (D10, FEAT-005)
