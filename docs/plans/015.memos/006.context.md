## Shapes the skeleton chooses

Per-note maps are keyed by the memo id **string** (a plain object or a MobX observable
map — either is observable under `makeAutoObservable`). The new note is one object or
`null`; it needs no id. The component (`007`) gives the new note's list item a fixed React
key of its own. Field names beyond `scope`, `scopeId`, `status`, `memos` and `newNote` are
the skeleton's; tests read per-note bookkeeping only through `noteText`, `noteFailure` and
`isFlagWriteInFlight`, and the new note through `newNote`'s fields as frozen in
`## Skeleton`.

## The draft-retention rule (DoD-6, DoD-10)

A save sends a snapshot of the editor text. When the response arrives:

- saved note: if the current editor text equals the snapshot, drop the held edit (the
  note now reads its new body); otherwise keep the held edit — it was typed during the
  request and will save on the next blur;
- new note: the returned row is appended; if the new note's current text differs from the
  snapshot, record that current text as the saved note's held edit.

A held edit that equals the applied body may be dropped at any time; it is
indistinguishable from none.

## Applying rows (DoD-15)

Fixed-width timestamps compare correctly as strings (`context.md` Wire contract). "Not
older" means `returned.updated_at >= held.updated_at`. This guards two writes on one note
in flight together (a body save and a toggle; `007` disables the flag controls while a
flag write is in flight, but the state does not rely on that). A response for a note that
was deleted meanwhile is ignored.

## Failure slots

One failure text per saved note and one on the new note. Each mutation on a note clears
that note's failure before its request. A failure never touches another note's slot.
There is no level-wide failure besides the load's `"failed"` status.

## The flush

`flushMemoLevel` is called by `007` from an unmount cleanup, where nobody awaits it. It
starts every save it needs at once (no sequencing between notes) and its returned promise
settles when all have. The writes after unmount land on a state no component reads, which
is harmless; nothing may reject.

## Test notes

- Hold a response open with a deferred promise to assert in-flight states (DoD-6, DoD-10,
  DoD-14, DoD-15).
- DoD-12's stub answers each PATCH with a row reflecting the request (as the server would:
  `is_forced` unchanged by an `is_enabled` write), with a later `updated_at` each time.
- Request bodies are asserted by parsing the JSON and comparing whole objects, so a stray
