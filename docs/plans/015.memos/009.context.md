# Step 009 — step-specific context

Feature-wide facts are in `context.md`: **D1** (the character page's one-level section
after Sessions), **D8**, **D16** (its state is separate from the session screen's
character level), the **Build prerequisites** table, the UI strings table, and frontend
**Test conventions**. 011's `008.context.md` "The hook in `CharacterScreen.tsx`" and its
test-amendment notes are the precedent. Only what is narrow to this step is below.

## Borrowed interfaces

- `app/memoLevelState.ts` (`006`): `MemoLevelState`, `loadMemoLevel`.
- `app/MemoLevelGroup.tsx` (`007`): `MemoLevelGroup` (`state`, `title`, `headingOrder`,
  `onRetry`). The group renders the region, the heading, the loading / failed / empty
  states and every note; this component adds none of its own.
- `app/CharacterScreen.tsx`: the existing-mode `"ready"` branch, which renders the persona
  editor, `SetupsSection` and then `SessionsSection` keyed by the character id. Read the
  "Sessions" heading's `order` there and pass the same to the group.

## Two controllers

The mount load and each "Retry" each use their own `AbortController`; a retry aborts the
previous one; unmount aborts whichever is current. Keep the current controller in a ref.

## The hook in `CharacterScreen.tsx`

One element after `SessionsSection`: `CharacterNotesSection` with `characterId` and `key`
set to the loaded character's id. `characterScreenState.ts` is read, not edited.
`017`'s settings mount and `018`'s card grid later rearrange the page; nothing here
anticipates them.

## Test amendments this step owns

- `tests/app/CharacterScreen.test.tsx` (009 `007`, 010 `006`, 011 `008`): every
  existing-mode test whose load succeeds now also triggers
  `GET /api/memos?scope=character&scope_id=<id>`; extend the stub to answer
  `{ "memos": [] }` by exact path **and query** (the pathname `/api/memos` alone is shared
  with the POST and with other levels' listings). Any assertion that counts requests on
  the screen counts only the requests it means. 011 `008` DoD-12's document-order clause
  stays true (Notes comes after Sessions).
- `tests/app/App.test.tsx`: character-screen routes need the same extra stub. Session
  routes are `008`'s concern, not this step's.
- `tests/app/AppBoot.test.tsx` and `tests/entries.test.tsx` render `App` at `/`, where no
  character screen mounts. Unaffected and not in scope.
