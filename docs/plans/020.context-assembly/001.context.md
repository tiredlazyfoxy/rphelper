# Step 001 — step-specific context

Feature-wide facts (the prompt format, the kind tags, `StreamMessage`, the decisions) are
in `context.md`. Only what this step alone needs is here.

## `services/llm/` today

The package holds only `__init__.py` and `client.py` (`LlmClient`: probe, embed; no chat
type; `chat_stream` deliberately absent). `chat.py` is a new sibling. Neither existing
file is touched. 019 will add `frames.py` beside them; it is unrelated.

## Building test inputs

`StreamMessage` is a plain frozen dataclass, so tests construct its values directly with
all eight fields (`id`, `session_id`, `role`, `kind`, `text`, `settled_at`, `created_at`,
`updated_at`). No database is needed in this step. A settled row has a non-null `kind`
and `settled_at`; a zone row has both null. Timestamps can be any fixed-width strings;
the mapper does not read them.

## Gotchas local to this step

- **The renderer does not sort levels.** It renders levels in the order it is given; step
  `002` supplies the chain's order. DoD-4 and DoD-5 test the given order.
- **The mapper decides "tagged" from `kind`, not from which list a row came in.** A
  settled row always has a kind and a zone row never does, so the two agree. The input
  lists are split only because 012 exposes two reads.
- Kinds other than the three never occur (012 writes only these); no behaviour is
  specified for them and no test covers them.
- `ForcedNoteLevel.scope` takes the same four strings as 015's scope literal. This step
  must not import 015 (it is not built); a plain literal of the four values is enough.
