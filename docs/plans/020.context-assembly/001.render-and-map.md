# Step 001 — Chat value type, system-prompt renderer, message mapper

## Goal

Add the neutral chat-message value type (`services/llm/chat.py`) and the pure half of
`services/context.py`: a renderer that builds the system-prompt string in the fixed
format (`context.md` "The prompt format"), and a mapper that turns 012's settled and zone
`StreamMessage`s into one id-ordered chat-message list with kind tags. No I/O.

## Source files

backend/app/services/llm/chat.py
backend/app/services/context.py

## Test files

backend/tests/test_context_render.py

## Interface intent

**`app/services/llm/chat.py`** (new)

- **`ChatRole`**: a literal type of exactly `"user"` and `"assistant"`.
- **`ChatMessage`**: frozen value with `role` (a `ChatRole`) and `content` (string). The
  one chat-message shape the assembler returns and `021`'s client will consume. Imports
  nothing from `app.services` (D9).

**`app/services/context.py`** (new; this step adds the pure part only)

- **`ForcedNoteLevel`**: frozen value for one level's forced notes: `scope` (one of
  `"user"`, `"character"`, `"setup"`, `"session"`) and `bodies` (the forced notes' bodies,
  in order). Plain strings, so this step needs no 015 type.
- **`render_system_prompt`**: pure. Inputs: the resolved system prompt (string or none),
  the character sheet (string), the forced-note levels (a sequence of `ForcedNoteLevel`,
  in chain order), the resolved RP language (string or none) and the resolved preferred
  language (string or none). Output: the system-prompt string laid out exactly as
  `context.md` "The prompt format" specifies: the six sections in fixed order, omitted
  sections per D5, level blocks in the order given with headings only for non-empty
  levels, every user-supplied text verbatim, the fixed English instruction lines with
  their exact lead-ins, `English` in place of a null language (D4). Never raises on any
  combination of nulls and empties.
- **`to_chat_messages`**: pure. Inputs: the settled entries and the zone rows (two
  sequences of `StreamMessage`, each in any order). Output: one list of `ChatMessage`,
  the union of both ordered by the row's `id` ascending. A row whose role is neither
  `"user"` nor `"assistant"` is skipped (D3). A row with a non-null `kind` gets content =
  its kind tag, a line feed, then its text verbatim (D1, Kind tags table). A row with a
  null `kind` gets its text verbatim. The role is the row's stored role. Nothing is
  truncated, stripped or re-parsed (R12, D12).
- The instruction prose, headings, lead-ins and tags are module constants (D10). Their
  names are the coder's; tests bind to the literals in `context.md`, not to the names.

## Definition of done

1. `[test]` `ChatMessage` holds the given role and content; it is immutable (assigning a
   field raises). Constructing one with role `"user"` and with role `"assistant"` works.
   (D9)
2. `[test]` With every input present, the prompt contains the six heading lines
   `=== System prompt ===`, `=== Character sheet ===`, `=== Forced notes ===`,
   `=== Message tags ===`, `=== Languages ===`, `=== Double parentheses ===` as whole
   lines, in that order. The system prompt and the sheet each appear verbatim (test
   values carry markdown, inner newlines and leading / trailing whitespace) after their
   own heading and before the next heading. (`context.md` format table)
3. `[test]` A null system prompt omits the `=== System prompt ===` line and nothing else;
   a sheet of `""` and a sheet of only whitespace each omit the `=== Character sheet ===`
   line and nothing else. (D5)
4. `[test]` Given levels user (two bodies), character (one), setup (one), session (two),
   the `=== Forced notes ===` section holds the level heading lines `--- User notes ---`,
   `--- Character notes ---`, `--- Setup notes ---`, `--- Session notes ---` in that order,
   each followed by its own bodies in the order given, each body verbatim and preceded by
   a `[note]` line. (US-054.AC-1, US-103.AC-1, D6)
5. `[test]` A level given with no bodies has no heading line; a sequence without a setup
   level has no `--- Setup notes ---` line and the session block follows the character
   block directly; an empty sequence, or one whose levels are all empty, omits the
   `=== Forced notes ===` line. (D5, R2)
6. `[test]` With RP language `"Japanese"` and preferred language `"Russian"`: a line
   starting `- Candidates:` contains `Japanese`; a line starting `- Out of character:`
   contains `Russian`; a line starting `- Mirroring:` is present. All three sit after the
   `=== Languages ===` line. (US-036.AC-1, US-036.AC-2, US-036.AC-3, US-131.AC-2,
   US-131.AC-3 — the instruction half; UC-033)
7. `[test]` A null RP language puts `English` on the `- Candidates:` line; a null
   preferred language puts `English` on the `- Out of character:` line; each falls back
   independently (one null, the other set: the set name stays on its own line); both null
   renders without raising. (D4)
8. `[test]` After `=== Message tags ===` the prompt holds lines starting `- [partner]:`,
   `- [my turn]:`, `- [decision]:` and `- Untagged:`. (D1)
9. `[test]` After `=== Double parentheses ===` the prompt holds lines starting
   `- Wholly parenthesised:` and `- Fragment:`. (US-129, US-130, UC-084, R12 — the
   instruction half)
10. `[test]` With a null system prompt, an empty sheet and no forced notes, the prompt is
    non-empty, its first line is `=== Message tags ===`, and it holds exactly the three
    instruction headings. (D5)
11. `[test]` The prompt never contains `memo_search`, `session_search` or `web_search`,
    with any inputs. (D2)
12. `[test]` `to_chat_messages`: a zone row with role `"user"` and one with role
    `"assistant"` map to that role with content equal to their text exactly (no tag).
    Settled rows of kind `partner`, `turn` and `decision` map to content
    `"[partner]\n" + text`, `"[my turn]\n" + text`, `"[decision]\n" + text`, keeping the
    stored role, including a `turn` row whose role is `"assistant"`. (D1, US-122)
13. `[test]` Rows passed out of order, with settled and zone ids interleaved (a settled id
    between two zone ids), come back as one list ordered by id ascending. Either list may
    be empty; both empty gives an empty list. (D7)
14. `[test]` A row with role `"tool"`, in either list, is absent from the output and the
    remaining rows keep their id order. (D3)
15. `[test]` Texts containing `(( ))` (a wholly parenthesised zone message, a zone draft
    with a `(( ))` fragment, a decision stored with its `(( ))`), leading / trailing
    whitespace and blank lines pass through unchanged apart from the tag prefix. (R12)
16. `[test]` 2,000 rows, one of them with a 200,000-character text, map to 2,000 messages
    and that message's content holds the full text. (D12)
17. `[test]` The source of `app/services/llm/chat.py` imports nothing from `app.services`
    (in particular not `app.services.context` and not `app.services.llm.client`). The
    source of `app/services/context.py` imports nothing from `app.services.parens`, no
    `fastapi`, and contains no `translation` substring. (D9, R8, R12)
