# Step 002 — step-specific context

Feature-wide facts (the prompt format, the decisions, `StreamMessage`, test conventions)
are in `context.md`. Only what this step alone needs is here.

## Built reads this step calls

- `sessions.get_session(connection, user_id, session_id)` → `RpSession` with `id`,
  `character_id`, `setup_id` (None when no setup), `setup_name`, `archived_at`, …. Raises
  `SessionNotFoundError` (`app/errors.py`, 404) for a missing or another user's session.
- `characters.get_character(connection, user_id, character_id)` → `Character` with `id`,
  `name`, `sheet` (Text NOT NULL, default `""`), ….
- `messages.list_entries(connection, user_id, session_id)` and
  `messages.list_zone(connection, user_id, session_id)` → `list[StreamMessage]`, id
  ascending, through `settled_entries` / `current_zone` (schema.py's Core `select()`
  objects). Both raise `SessionNotFoundError` via a private `_require_session` and leave
  no transaction open.

**Gotcha.** DoD-12 needs `get_session` and `get_character` to return archived rows. The
harvest shows `RpSession` carries `archived_at`, so archived sessions are read. If
`get_character` turns out to refuse an archived character, **stop and hand back**
(`blocked`). Do not work around it with a raw select: that would break DoD-16.

## Pending interfaces (planned, not built — bind to these plans)

**015 `003`, `services/memo_chain.py`:**

- `resolve_chain(connection, user_id, session_id)` → list of `MemoChainLevel(scope,
  scope_id, memos)`, levels in the fixed order user, character, setup (only when the
  session has one), session. Every existing level is listed even when empty. Notes within
  a level are ordered `sort_key, id`, **disabled ones included**. Raises
  `SessionNotFoundError`; two SELECTs; leaves no transaction open.
- `memo_reach(is_enabled, is_forced)` → `"forced"` | `"searchable"` | `"disabled"`, with
  `is_enabled` checked first.
- `Memo` (015 `002`): `id`, `scope`, `scope_id` (None for user level), `body`,
  `is_enabled`, `is_forced`, `sort_key`, `created_at`, `updated_at`.

**017 `003`, `services/configuration.py`:**

- `get_session_configuration(connection, user_id, session_id)` → `SessionConfiguration`
  whose `system_prompt`, `rp_language` and `preferred_language` are `ResolvedSetting`s.
  Use `.value` only (string or None). `system_prompt`: session, else character, live.
  Languages: session, else user. Raises `SessionNotFoundError`; reads archived rows; no
  open transaction. `model` and the three `tool_*` fields are not used by 020.

Not called: `resolve_model_for_use` (`021`'s).

## Seeding the tests

All raw inserts, file-local helpers (`context.md` "Test conventions"):

- `users` (with `rp_language`, `preferred_language`, nullable), `characters` (`sheet`,
  plus 017's `system_prompt`), `setups`, `sessions` (`character_id`, `setup_id` NULL for
  no setup, `archived_at`, plus 017's `system_prompt`, `rp_language`,
  `preferred_language`). 017's column names are as its step `001` builds them; the
  configuration write services of 017 `004` may be used instead of raw updates.
- `memos` (015 D10): `id`, `user_id`, `scope` (`user` / `character` / `setup` /
  `session`), `scope_id` (the caller's id for a user-level note), `body`, `is_enabled`,
  `is_forced`, `sort_key`, `created_at`, `updated_at`. Raw-insert so `sort_key`s and flag
  combinations are exact.
- `messages` (schema.py): `id`, `user_id`, `session_id`, `role`, `kind`, `text`,
  `related_to`, `settled_at`, `tool_name`, `tool_payload`, `created_at`, `updated_at`.
  CHECK `related_to IS NULL OR settled_at IS NULL`. A settled row: `kind` set,
  `settled_at` set, `related_to` NULL. A buried row: `related_to` = head id, `settled_at`
  NULL. A zone row: both NULL, `kind` NULL. A `role='tool'` row may carry `tool_name`.
  Pick ids so stream order is explicit (a partner block's id between two zone ids in at
  least one test).

## The source-convention test (DoD-16)

`app/services/context.py` legitimately contains the word `messages` (the imported service
module and the result's field) and `memos` may appear in attribute names (`level.memos`).
So the "names no table" check is phrased through the forbidden constructs (no `app.db`
import, no query-builder calls, no view names), not through a bare `messages` substring.
The `memo_reach` check is an AST walk: every `Attribute` node named `is_enabled` or
`is_forced` must have a `Call` to `memo_reach` as an ancestor.
