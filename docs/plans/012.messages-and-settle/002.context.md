# Step 002 — step-specific context

Feature-wide facts are in `context.md`: "The `messages` table", the four states, **D1**,
**D2**, **D3**, **D7**, **D9** (services trust the router's validation), **D11**, **D14**,
**D16**, the cross-cutting constraints, and **Test conventions**. 011's `002.context.md`
("Service conventions", "Timestamps", "Ids", the list read and its rollback) applies
unchanged. Only what is narrow to this step is below.

## Statements each operation issues

| Operation | Statements (all owner-scoped) |
|---|---|
| session check (every operation but the edit) | `SELECT sessions.id FROM sessions WHERE id = :session_id AND user_id = :user_id`. No `archived_at` predicate (R6). No row → `SessionNotFoundError` |
| `list_entries` | session check, then `settled_entries` narrowed by `session_id = :session_id AND user_id = :user_id`, ordered by id ascending — both inside the private read context |
| `list_zone` | the same with `current_zone` |
| `append_message` | inside one `begin()`: session check, `next_id()`, `INSERT INTO messages (id, user_id, session_id, role, text, created_at, updated_at)`, bump |
| `file_partner_entry` | inside one `begin()`: session check, `next_id()`, `INSERT` as above plus `kind = 'partner'`, `settled_at = <instant>`, bump |
| `edit_message_text` | inside one `begin()`: `message_states` narrowed by `id = :message_id AND user_id = :user_id`; classify; `UPDATE messages SET text, updated_at WHERE id = :message_id AND user_id = :user_id`; bump the row's `session_id` (from the state row); read back through `current_zone` by id and `user_id` |
| bump | `UPDATE sessions SET last_used_at = :instant, updated_at = :instant WHERE id = :session_id AND user_id = :user_id` |

**`related_to` is never named in an insert or update in this module** (DoD-13): the zone
and partner inserts omit it (it defaults to NULL). `kind` and `settled_at` are omitted from
the zone insert and set only in the partner insert, which creates a row; they are never
updated on an existing row here (D16).

## Classifying the edit target (D2, D7)

From the `message_states` row: none → `MessageNotFoundError`; `related_to` not NULL →
buried → `MessageNotEditableError`; `settled_at` not NULL → settled →
`MessageNotEditableError` (until `014`); otherwise it is a zone row and the update
proceeds. The edit does **not** check the session separately: the message row's own
`user_id` predicate is the owner check, and a message of another user's session is
`message_not_found` (R5).

## Building the returned value

The two inserts build their `StreamMessage` from the values they inserted; no read-back is
needed. The edit reads the row back through `current_zone` inside the same `begin()` so
the returned value is the stored one.

## Instants

One `_now_text()` call per write operation, used for every timestamp that operation
writes, the bump included (D3). A test asserting "`updated_at` moved forward" compares the
fixed-width strings; on a fast machine two operations may land in the same microsecond, so
tests assert `>=` for "not backward" and use an explicitly older seeded `updated_at` where
they need strictly-later.

## Test seeding

Users A and B, a character and a session each, raw-inserted (011 `001.context.md` "Test
seeding" order). Buried / settled / assistant rows for DoD-6, DoD-8, DoD-9 are raw inserts
into `messages` with chosen ids and states (the buried row's `related_to` points at a
settled row of the same session). DoD-11 sets `sessions.archived_at` with a raw update.
DoD-13 reads the module's source text from disk (AST or text — the test-coder's choice).
