# Step 006 — step-specific context

## Built admin facts (harvested)

- `AdminUserResponse{id, username, role, is_enabled, last_login_at}`.
- `LlmServerResponse{id, name, kind, base_url, has_api_key,
  enabled_model_names, embedding_model_name, embedding_dim, last_test_*,
  created_at, updated_at}`.
- `/api/admin/database/*` returns schema metadata only.
- No `COUNT(` / `func.count` anywhere in `app/`; no admin route touches a
  user-content table. So DoD-1..6 are expected to pass for built rows.
- Admin frontend renders only registry counts (`enabled_model_names.length`,
  `embedding_dim`); no confirm dialog contains a number.

## Snapshot rules for DoD-2 / DoD-7

- Take the "before" snapshot after every login has happened (`last_login_at`
  must not move between snapshots); seed content with already-authenticated
  clients.
- Volatile fields excluded from equality: ids, `created_at`, `updated_at`,
  `last_test_*`, and for fast/002 any job id / started/finished timestamp /
  status enum. Every **numeric** field stays in the comparison — a number that
  moves with content volume is exactly the finding.
- If fast/002's plan declares a vector/row/progress count in its response
  (e.g. "N vectors rebuilt", "k of N"), DoD-7 fails by design: that is a finding
  (`context.md` "Known risks"). Small fix = drop the field (fix-allowance);
  otherwise hand back against fast/002. A bare phase that does not derive from
  content volume is not a finding — the verifier judges.
- fast/002 route(s): `_TBD: resolved from fast/002 plan.md at build time_`
  (frozen in `## Skeleton` by step 002); the harvest reads
  `docs/plans/fast/002.*/plan.md`.

## Forbidden-name list (DoD-5, DoD-9)

Case-insensitive, matched as whole identifiers / words (so `independent` or
token-`usage` reporting from an LLM probe do not match):
`session_count`, `sessions_count`, `sessionCount`, `character_count`,
`characterCount`, `memo_count`, `memoCount`, `message_count`, `messageCount`,
`user_count`, `userCount`, `row_count`, `rowCount`, `vector_count`,
`vectorCount`, `usage_count`, `usageCount`, `in_use`, `inUse`, `used_by`,
`usedBy`, `dependent_sessions`, `dependentSessions`, and the phrase family
`sessions use`, `sessions using`, `in use by`. Registry counts not derived from
user content (`embedding_dim`, the length of `enabled_model_names`) do not
match.

For DoD-5, inspect each admin route's declared response model (and nested
models) where one is declared; a route without one is covered by DoD-1..3.

## Allowed API prefixes for the admin entry (DoD-8)

`/api/admin/`, `/api/me`, `/api/auth/`, `/api/health`. Shared client code the
admin entry imports from outside `frontend/src/admin/` is not scanned; the
assertion is about what the admin entry's own files call.

## Frontend test mechanics

A Vitest test that reads the source files under `frontend/src/admin/` as text
(the project replaces lint rules with grep-style Vitest tests; there is no
ESLint). TypeScript only.
