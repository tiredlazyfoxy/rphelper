# Step 005 — Export, import and bootstrap-from-export sweep

## Goal

Close the route-level gaps in 030/031: a user's own export carries nothing of
another user, an import always lands in the caller's ownership whatever the
payload claims, and the admin import and the pre-auth bootstrap-from-export
refuse a configured instance without wiping or echoing anything. The
whole-database export's opacity rule stays 030's (cited, not re-tested).
Audit step: no source change planned.

## Definition of done

1. DoD-1 [test] — `GET /api/export` as A contains every A sentinel (positive
   control) and no B sentinel and no B id; symmetrically for B. (US-083.AC-1)
2. DoD-2 [test] — `POST /api/import` as A with a payload whose rows claim B's
   user id and reuse B's existing row ids, carrying fresh import sentinels,
   creates rows that appear in A's listings and in no B listing; every B row
   reads back unchanged. (US-083.AC-1)
3. DoD-3 [test] — B importing A's own export (`GET /api/export` as A) gets
   copies owned by B; A's rows and A's listings are unchanged (no row moved to
   or duplicated into A). (US-083.AC-1)
4. DoD-4 [test] — `POST /api/characters/{A's character}/import` with a payload
   naming B's ids attaches the imported rows to A's character only; B's rows
   and listings are unchanged. (US-083.AC-1)
5. DoD-5 [test] — `POST /api/admin/database/import` by ADM while A and B hold
   content gets 409 `database_not_empty`; the response carries no sentinel from
   the payload or the database, and every A and B row reads back unchanged.
   (US-084.AC-1)
6. DoD-6 [test] — The bootstrap-from-export route (enumeration row 5), called
   anonymously on a configured instance with a payload carrying fresh
   sentinels, gets 409 `already_configured`; the response carries no sentinel
   (payload or database); every user and every A and B row is unchanged.
   (US-083.AC-1)
7. DoD-7 [manual/live] — Whole-database export opacity is 030's contract
   (`docs/plans/030.export-granularities/context.md` ~L121, 030/005 DoD-2..4,
   030/008 DoD-7); the verifier confirms those items are `done` rather than
   re-testing them.
