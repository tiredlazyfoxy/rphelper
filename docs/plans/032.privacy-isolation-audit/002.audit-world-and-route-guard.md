# Step 002 — Two-user audit world and route-classification guard

## Goal

Build the shared two-user audit world every later sweep runs in, and a guard
that fails the build whenever `app.routes` and the enumeration table in
`context.md` disagree, plus the auth/role gate for every classified route.
Audit step: no source change is planned (see `context.md` "The audit-step
convention").

## Source files

None planned. Fix-allowance if DoD-2 or DoD-3 finds an unguarded route: the
router module that declares that route, under `backend/app/routers/`
(adding the missing `require_user` / `require_role` dependency only).

## Test files

- `backend/tests/privacy_audit_support.py`
- `backend/tests/test_privacy_audit_routes.py`

## Interface intent

No source interface. The support module is test code written by the
test-coder; its signatures are frozen by the skeleton into `status.md`
`## Skeleton` so steps 003..007 bind to them. It provides, in prose:

- **Audit world builder** — given the per-test settings/engine, creates the
  real application (settings dependency overridden, logging configurable as
  either the real `configure_logging` or a no-op, chosen by the caller),
  bootstraps ADM, creates roleplayers A and B, and seeds — for each of A and B —
  content in every user-content table listed in `002.context.md`, each field
  carrying its own sentinel. Returns the world: per-user ids for every seeded
  row, the sentinel registry, and authenticated clients.
- **Sentinel registry** — maps (user, table, field) to its sentinel; answers
  "every sentinel of user X" and "every sentinel of every user".
- **Clients** — ready clients for A, B, ADM and anon; the same application
  instance.
- **Fake model seam** — installs scripted fakes for the LLM chat client and the
  embedding client through the client-factory seam declared by 019/021 (names
  from those features' `## Skeleton`): scripted completions, scripted tool calls
  with caller-chosen arguments, and failure modes (raise with a caller-chosen
  message). Also exposes what each fake was asked (for "no model call" and
  outbound-payload assertions).
- **Assertions** — refusal identity (a foreign-id response equals the
  unknown-id response: status, `code`, `detail == {}`, body); "no sentinel of
  user X in this text/JSON"; the unknown-id constant.
- **Log capture** — a context manager attaching a level-0 loguru sink that
  collects each record's message, `repr(extra)` and exception text.
- **The enumeration literal** — the table from `context.md` as data: method,
  normalized path, class, expected 404 code where applicable.

The skeleton additionally freezes, from the built application and the fast
plans: the exact method of every `†` row in the enumeration, and the exact
method + path for rows 5 and 74 (`_TBD: resolved from fast/002 and fast/003
plan.md at build time_`).

## Definition of done

1. DoD-1 [test] — The set of (method, path-with-parameters-normalized) over every
   FastAPI API route in the application equals the enumeration literal's set
   exactly; the failure message names every unclassified route and every
   table row with no route. (US-083.AC-1)
2. DoD-2 [test] — Every route not classed `public` answers anon with 401
   `not_authenticated` (unknown ids substituted for path parameters, an empty
   JSON body where a body is taken). (US-083.AC-1)
3. DoD-3 [test] — Every `admin` route answers A with 403 `insufficient_role`.
   (US-084.AC-1)
4. DoD-4 [test] — After the world is built, every table in the coverage list
   (`002.context.md`) holds at least one row owned by A and one owned by B, and
   every registered sentinel is stored somewhere in the database (the sweeps
   cannot pass vacuously). (US-083.AC-1)
5. DoD-5 [test] — Positive control: B, through B's own read routes (character,
   setup, session, entries, zone, memos, memo-chain, configuration, discussion,
   my-search), retrieves every one of B's sentinels that has a read surface.
   (US-083.AC-1)
6. DoD-6 [test] — No two sentinels in the registry are equal, none is a
   substring of another, and none appears in any username, server name or
   model name. (US-083.AC-1)
