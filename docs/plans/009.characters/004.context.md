## Shared client (harvested)

- `apiGet(path, signal?)`, `apiPost(path, body?, signal?)`, `apiPatch(path, body?, signal?)`
  from `src/shared/api.ts`. The path must begin `/api/`, and a query string is part of the
  path. Bodies are JSON-serialised by the client. A non-2xx becomes a thrown `ApiError`
  (`src/shared/apiError.ts`, branch on `.code`). A 401 has already navigated to `/login`
  before the throw. An abort rejects with the original abort error, unwrapped.
- The client never reviver-parses. Ids arrive and stay strings. Nothing here may parse,
  compare numerically or sort by an id.

## MobX precedent

`src/admin/usersPageState.ts`: a class with observable fields and
`makeAutoObservable(this, {}, { autoBind: true })` in the constructor, then free async
functions `(state, …args, signal?)` that `runInAction` every post-await write, return
early on `signal?.aborted`, and catch everything (the error is written into the state, and
the promise never rejects). Follow it.

## The insert position, concretely

`created_at` values are fixed-width UTC text (`YYYY-MM-DDTHH:MM:SS.ffffff+00:00`), so
plain string comparison orders them chronologically. "Insert by `created_at`
descending" means: before the first existing row whose `created_at` is **less than** the
new row's, or at the end if none is. Equal `created_at` (practically impossible) inserts
after the equal rows. This mirrors the server's order closely enough for an interim list
that `011` replaces.
