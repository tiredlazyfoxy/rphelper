# Step 005 — step-specific context

Feature-wide facts are in `context.md`: **D3** (why one wrapper, why `shared/`, which six
packages, no `react-markdown`) and **Test conventions** ("TipTap in jsdom": what this
step's tests cover and what other steps stub). Only what is narrow to this step is below.

## Version constraints — the gotcha

- **TipTap 2, not 3.** `tiptap-markdown` binds to TipTap 2, and `@mantine/tiptap` v7 is
  built against TipTap 2. Pin every `@tiptap/*` package (`react`, `pm`, `starter-kit`,
  `extension-link`) to a `^2.x` range. An unpinned `npm install @tiptap/react` may pull
  3.x and break both peers.
- **`@mantine/tiptap` on the same 7.x line as the installed `@mantine/core`** (read the
  existing `package.json`). Mantine packages are released in lockstep, and mixing minors
  is unsupported.
- `tiptap-markdown` at its current release supporting TipTap 2 (the 0.8 line).
- Use `npm install <pkg>@<range> …` from `frontend/` so `package-lock.json` is regenerated.
  Both files are this step's Source files.
- If an exact pairing proves incompatible at install time, the coder records the versions
  chosen in `## Notes & Issues`. The constraints above (TipTap major 2, Mantine major
  matches core) are the contract DoD-5 checks.

## Wiring notes

- Mantine 7's `RichTextEditor` takes an `editor` from `@tiptap/react`'s `useEditor`;
  toolbar controls are `RichTextEditor.Bold`, `.Italic`, `.H2`, `.H3`, `.BulletList`,
  `.OrderedList`, `.Link`, `.Unlink` inside `RichTextEditor.Toolbar` /
  `RichTextEditor.ControlsGroup`, and the surface is `RichTextEditor.Content`.
- `@mantine/tiptap` requires its stylesheet `@mantine/tiptap/styles.css`. Import it in
  `MarkdownEditor.tsx` so only bundles that use the editor pay for it. This is a package
  stylesheet, not a hand-written one: `tests/stylesheets.test.ts` counts authored `.css`
  files under `src/`, which this does not add.
- Markdown in: pass `value` as the editor's initial `content` with the `Markdown`
  extension from `tiptap-markdown` registered. It parses markdown strings given as content.
  Markdown out: `editor.storage.markdown.getMarkdown()`.
- Accessible name / role: set through the editor's `editorProps.attributes`
  (`role`, `aria-label`, `aria-multiline`). That puts them on the ProseMirror
  contenteditable element itself.
- No echo: emit from the editor's `onUpdate`. When applying an external `value`, set the
  content **without emitting an update** (TipTap's `setContent` takes an `emitUpdate`
  flag), and only when it differs from the current `getMarkdown()`. Otherwise every
  keystroke's re-render would reset the cursor.
- `readOnly` maps to `editor.setEditable(!readOnly)` (and the initial `editable` option),
  plus not rendering the toolbar.

## jsdom specifics for the tests

- TipTap mounts in jsdom. ProseMirror renders the document as real DOM (headings,
  `strong`, `li`), which is what DoD-2 and DoD-3 query.
- `useEditor` may return `null` on the first render before the editor is created. Tests
  should use `findBy…` / `waitFor` for the first assertion.
- Driving real typing (DoD-6) through `user-event` on a ProseMirror surface is unreliable
  in jsdom, which is why it is `[manual/live]`. The test-coder may add a
  DOM-mutation-driven check of `onChange` if it proves stable, but it is not required by
  the coverage contract.
