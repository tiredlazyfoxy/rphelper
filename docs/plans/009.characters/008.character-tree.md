# Step 008 — The tree's header and character level

## Goal

Add `app/CharacterTree.tsx`: the tree header (Search, New character, Show archived) and
one row per character linking to its screen, with archived rows dimmed and badged and
the current route's row marked active. Render it in the body of 008's expanded column,
fed by the workspace characters state that `App` passes down (D4, D11, D13).

## Interface intent

**`app/CharacterTree.tsx`** (new)

- **`CharacterTree`**: `observer` component. Props: `characters` (the workspace
  `CharactersState`). It:
  - loads the list (`loadCharacters`) on mount and again whenever `showArchived` changes,
    each run with an `AbortController` aborted when the next run starts or on unmount;
  - renders a **header**: `IconButton` **"Search"** (`IconSearch`, in-entry navigation to
    `/search`), `IconButton` **"New character"** (`IconPlus`, in-entry navigation to
    `/characters/new`), and a Mantine `Switch` labelled **"Show archived"** reflecting
    `showArchived` and calling `setShowArchived` on change;
  - renders the **character level** below the header, by `status`:
    - `"loading"` (and `"idle"`): a small Mantine `Loader`;
    - `"failed"`: the text **"Could not load characters"** and a button **"Retry"** that
      re-runs `loadCharacters`;
    - `"ready"`: a list with accessible name **"Characters"** holding one row per
      character, in state order. Each row is a router link to `/characters/<id>` whose
      text is the character's name. An archived row is visually dimmed and carries an
      **"Archived"** badge. The row whose id equals the current route's `/characters/:id`
      is marked active and carries `aria-current="page"`; no other row does. An empty list
      renders no rows and no placeholder text;
  - renders **no** expand/collapse chevron and **no** session rows.

**`app/WorkspaceShell.tsx`** (edited; 008-owned file)

- Gains one **required** prop, `characters` (`CharactersState`).
- The expanded column's body (empty in 008) renders `CharacterTree` with it, between the
  "Collapse tree" control and the user menu footer. The rail, the overlay behaviour, the
  collapse persistence and everything else are unchanged.

**`app/App.tsx`** (edited)

- Passes its `CharactersState` (created in `007`) to `WorkspaceShell` as `characters`.

## Definition of done

1. `[test]` `CharacterTree` mounted with `fetch` answering two characters requests exactly
   `GET /api/characters`, then renders a "Characters" list with one link per character,
   in the payload's order. Each link's text is the name and its `href` is
   `/characters/<id>` with the id string verbatim. (US-022.AC-1)
2. `[test]` Clicking a row navigates in-entry to `/characters/<id>`, with no document
   navigation. Rendered at `/characters/<id>`, that row has `aria-current="page"` and the
   other row does not.
3. `[test]` The header's "Search" navigates in-entry to `/search` and "New character" to
   `/characters/new`. (D13)
4. `[test]` The "Show archived" switch is off on a fresh mount. Turning it on requests
   `GET /api/characters?include_archived=true` and renders the archived character with an
   "Archived" badge, and the working one without. Turning it off requests
   `GET /api/characters` again, and the archived row is gone. (D4, R6)
5. `[test]` A failed load renders "Could not load characters" and "Retry" in the tree,
   with no notification. "Retry" requests the list again, and on success the rows render.
   (D12)
6. `[test]` No row carries an expand/collapse control. In the ready state the tree's only
   elements with role `button` are "Search" and "New character", and its only other
   control is the "Show archived" switch. Rows are links. (D13)
7. `[test]` `WorkspaceShell` (amending 008's tests for the new required prop): expanded,
   the nav contains "Collapse tree", the "Show archived" switch, the "Characters" list
   and the "User menu" trigger. After "Collapse tree" the rail shows "Search", "New
   character", "Expand tree" and "User menu", and no "Show archived" switch. 008's other
   shell assertions (persistence, narrow overlay, two grid children) still hold.
8. `[test]` `App` integration: at `/characters/new`, creating "Aria" (POST answered with
   a new id) lands on `/characters/<new id>`, and the tree shows an "Aria" row marked
   `aria-current="page"`, with no second `GET /api/characters` (the list endpoint) issued
   after the create. (US-020.AC-2, D11)
9. `[test]` `App` integration: at `/characters/<id>`, pressing "Archive" removes the row
   from the tree. Turning "Show archived" on shows it with an "Archived" badge. Pressing
   "Restore" removes the badge, and the row remains after "Show archived" is turned off
   again. (US-086.AC-1, US-086.AC-2)
10. `[test]` `App` integration: at `/characters/<id>`, changing the name and pressing
    "Save" makes the tree row show the new name. (US-021.AC-1)
11. `[test]` `tests/app/AppBoot.test.tsx` and `tests/entries.test.tsx` keep passing their
    008 assertions with their `fetch` stubs extended to answer `GET /api/characters`
    (e.g. with `{ "characters": [] }`). No assertion about the boot outcomes changes.
12. `[manual/live]` In a browser below 820px, opening the overlay shows the tree, and
    choosing a character row navigates to it and closes the overlay (008's D11). The
    archived rows' dimming reads as dimmed in both colour schemes.
