# Step 002 — The characters service

## Goal

Add `services/characters.py`, the one layer that issues SQL against `characters`. It
holds a frozen `Character` value and six owner-scoped operations (list, create, get,
update, archive, restore), with archive semantics per D9, interim order per D10, and no
delete operation (R5, R6).

## Source files

backend/app/services/characters.py

## Test files

backend/tests/test_characters_service.py

## Interface intent

Every operation takes the Core `Connection` first and the owner's `user_id` (int) as a
**required positional** argument after it. Each returns `Character` values, or raises
`CharacterNotFoundError` when the addressed row does not exist **for that user**. Each
never imports or raises anything HTTP-shaped.

- **`Character`**: frozen dataclass value: `id` (int), `name`, `sheet`, `archived_at`
  (string or `None`), `created_at`, `updated_at`. No `user_id`.
- **`list_characters`**: takes the connection, `user_id` and an `include_archived` flag.
  Returns the owner's characters, working only unless the flag is true, ordered newest
  created first (D10). A read: leaves no transaction open.
- **`create_character`**: takes the connection, the id generator (`SnowflakeGenerator`),
  `user_id`, `name` and `sheet`. Mints the id before the insert, stamps `created_at` and
  `updated_at` with the same instant, leaves `archived_at` NULL, and returns the created
  value. Stores `name` and `sheet` as given (validation is the request model's, `001`).
- **`get_character`**: takes the connection, `user_id` and a character id. Returns the
  character whether archived or not. A read: leaves no transaction open.
- **`update_character`**: takes the connection, `user_id`, a character id, an optional
  `name` and an optional `sheet` (`None` = not supplied). Writes only supplied fields and
  bumps `updated_at`. With neither supplied it writes nothing and returns the current row.
  Leaves `archived_at` untouched.
- **`archive_character`**: takes the connection, `user_id` and a character id. Sets
  `archived_at` and bumps `updated_at` when the character is working. On an archived one
  it writes nothing and returns it with its original `archived_at`.
- **`restore_character`**: same inputs. Sets `archived_at` to NULL and bumps `updated_at`
  when archived. On a working one it writes nothing.

There is **no** delete operation.

## Definition of done

1. `[test]` `create_character` returns a `Character` whose `id` is the value the supplied
   generator minted, with the given `name` and `sheet`, `archived_at` `None`,
   `created_at == updated_at`, and both timestamps in the fixed-width form
   `YYYY-MM-DDTHH:MM:SS.ffffff+00:00`. (US-020.AC-1)
2. `[test]` After `create_character`, `get_character` for the same user and id returns an
   equal value, and `list_characters` for that user contains it. (US-020.AC-2)
3. `[test]` With two users each owning characters, `list_characters` for one user returns
   only that user's characters, both with and without `include_archived`. (US-022.AC-1, R5)
4. `[test]` `list_characters` without the flag excludes archived characters. With the flag
   it returns working and archived together. In both cases the order is newest created
   first (three characters created in sequence come back newest → oldest). (US-086.AC-1, R6, D10)
5. `[test]` `get_character`, `update_character`, `archive_character` and
   `restore_character` called with **another user's** character id raise
   `CharacterNotFoundError`, and the owner's row is unchanged afterwards (same name, sheet,
   `archived_at`, `updated_at`). The same four called with an id that exists for nobody
   raise the same error. (R5)
6. `[test]` `update_character` with only `name` changes the name and keeps the sheet. With
   only `sheet` it changes the sheet and keeps the name. With both it changes both. Each
   leaves `created_at` unchanged and `updated_at` not earlier than before. With neither
   it returns the current row with `updated_at` unchanged. The change is visible through
   a subsequent `get_character`. (US-021.AC-1, D7)
7. `[test]` `archive_character` on a working character returns it with `archived_at` set
   in the fixed-width form. It is then absent from the default listing, present in the
   include-archived listing, and still returned by `get_character`. Archiving it again
   returns the same `archived_at` and the same `updated_at`. (US-086.AC-1, US-086.AC-3, D9)
8. `[test]` `restore_character` on an archived character returns it with `archived_at`
   `None`, and it is back in the default listing. Restoring a working character returns
   it unchanged (same `updated_at`). (US-086.AC-2, D9)
9. `[test]` `update_character` on an archived character succeeds and leaves `archived_at`
   unchanged. (D9)
10. `[test]` After `list_characters` and after `get_character`, the connection is not in a
    transaction, so a following `connection.begin()` succeeds.
11. `[test]` The source text of `app/services/characters.py` contains no `delete(` call, no
    `DELETE` SQL keyword and no `fastapi` import. (R6, `backend-structure.md` "Routers versus services")
