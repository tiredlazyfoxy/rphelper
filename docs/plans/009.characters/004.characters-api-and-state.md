# Step 004 — The characters API client and the workspace characters state

## Goal

Add `app/charactersApi.ts`, the `Character` type and the six calls of the wire contract
over the shared client. Add `app/charactersState.ts`, the one workspace characters data
class (rows, load status, Show-archived flag) with its load effect and the pure
apply-a-row upsert rule that keeps the tree in step with mutations without a refetch
(D4, D11).

## Interface intent

**`app/charactersApi.ts`** (new)

- **`Character`**: type mirroring the wire object field for field (`id` string, `name`,
  `sheet`, `archived_at` string or null, `created_at`, `updated_at`). No renaming layer.
- **`isArchived`**: pure. Takes a `Character` and returns whether `archived_at` is
  non-null.
- **`fetchCharacters`**: takes `includeArchived` (boolean) and an optional signal.
  GETs the listing (with `?include_archived=true` only when true) and resolves to the
  unwrapped array.
- **`fetchCharacter`**: takes an id (string) and an optional signal. GETs one character.
- **`createCharacter`**: takes `{ name, sheet }` and an optional signal. POSTs and
  resolves to the created character.
- **`updateCharacter`**: takes an id and a patch with optional `name` / `sheet`, plus an
  optional signal. PATCHes with exactly the supplied keys and resolves to the updated
  character.
- **`archiveCharacter`** / **`restoreCharacter`**: take an id and an optional signal.
  POST to the action route and resolve to the character.
- All failures are the shared client's `ApiError`s, rethrown unchanged. Ids are never
  coerced.

**`app/charactersState.ts`** (new)

- **`CharactersState`**: data class, observable fields only: `characters` (array of
  `Character`, starts empty), `status` (`"idle"`, `"loading"`, `"ready"` or `"failed"`,
  starts `"idle"`), `showArchived` (boolean, starts false, never persisted).
- **`loadCharacters`**: effect. Takes the state and an optional signal. Sets `"loading"`,
  requests the listing with `includeArchived` equal to `showArchived`, and on success
  writes the rows **in the order received** with `"ready"`. On failure it writes
  `"failed"` and leaves `characters` as they were. Writes nothing once aborted, and never
  rejects.
- **`setShowArchived`**: effect. Takes the state and a boolean and sets the flag. It does
  not load. The tree reloads in response (`008`).
- **`applyCharacter`**: takes the state and one server-returned `Character` and upserts
  it per D11:
  - present (same id) and still visible → replaced **in place** (position unchanged);
  - archived while `showArchived` is false → removed if present, not inserted if absent;
  - absent and visible → inserted at its `created_at`-descending position among the
    current rows (a newer one goes before every older one).

  "Visible" means working, or archived while `showArchived` is true.

## Definition of done

1. `[test]` `fetchCharacters(false)` requests exactly `GET /api/characters` (no query
   string). `fetchCharacters(true)` requests exactly
   `GET /api/characters?include_archived=true`. Each resolves to the payload's
   `characters` array with every `id` the identical string the payload carried.
2. `[test]` `fetchCharacter("7250000000000000001")` requests
   `GET /api/characters/7250000000000000001`. `createCharacter` POSTs `/api/characters`
   with the JSON body `{ name, sheet }`. `updateCharacter` PATCHes
   `/api/characters/<id>` with a body holding only the keys given. `archiveCharacter` /
   `restoreCharacter` POST `/api/characters/<id>/archive` / `/restore`. Each resolves to
   the response's character.
3. `[test]` A 404 envelope with code `character_not_found` makes `fetchCharacter` reject
   with an `ApiError` whose `code` is `character_not_found`.
4. `[test]` `isArchived` is true for a character whose `archived_at` is a string and false
   when it is null.
5. `[test]` `loadCharacters` sets `status` `"loading"` while the request is pending, then
   `"ready"` with exactly the server's rows in the server's order. It requests
   `include_archived=true` when `showArchived` is true and no flag when false. (US-022.AC-1)
6. `[test]` `loadCharacters` on a failed request sets `"failed"`, keeps the previous rows
   and resolves without throwing. With its signal aborted before the response settles it
   writes nothing.
7. `[test]` `applyCharacter` with a row whose id is present replaces that row in place
   (same index, new values). (US-021.AC-1)
8. `[test]` `applyCharacter` with an archived row while `showArchived` is false removes
   that id from `characters`. While `showArchived` is true it replaces it in place and
   keeps it. (US-086.AC-1)
9. `[test]` `applyCharacter` with an absent working row inserts it by `created_at`
   descending: a row newer than all existing ones lands first, and a row whose
   `created_at` falls between two existing rows lands between them.
   (US-020.AC-2, US-086.AC-2)
10. `[test]` `applyCharacter` with an absent archived row while `showArchived` is false
    leaves `characters` unchanged.
11. `[test]` `setShowArchived` sets the flag and issues no request. An `autorun` reading
    `characters` re-runs after `applyCharacter`, and one reading `showArchived` re-runs
    after `setShowArchived` (the writes are MobX actions on observable fields).
