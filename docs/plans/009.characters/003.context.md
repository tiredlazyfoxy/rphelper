# Step 003 — step-specific context

Feature-wide facts are in `context.md`: the **Wire contract** (routes, shapes, failure
codes), **D6** (router-level auth), **D7**, **D8**, and backend **Test conventions**.
Only what is narrow to this step is below.

## Handler dependencies (harvested)

- Connection: `Annotated[Connection, Depends(get_connection)]` from `app.db.engine`.
- Current user: `Annotated[CurrentUser, Depends(require_user)]` from `app.dependencies`.
  `CurrentUser` is a frozen dataclass `(id: int, username: str, role: Role)`. Pass
  `current_user.id` as the service's `user_id`. FastAPI caches a dependency per request,
  so declaring `require_user` both on the router and on a handler resolves it once.
- Id generator: `Annotated[SnowflakeGenerator, Depends(get_id_generator)]`, where
  `get_id_generator` comes from `app.routers.bootstrap`. Only the create handler needs it.
- Path id: the inbound alias `SnowflakeIn` from `app.models.ids`, **never** a bare `int`
  path type and never a `str` passed through `int()` (`backend-structure.md` "The JSON id
  boundary"). A non-numeric value then fails validation → 422 (DoD-12).
- `include_archived` is a plain `bool` query parameter with default `False`. FastAPI
  parses `true` / `false`.

## Registration

`main.py`'s app factory already calls `register_exception_handlers(app)` and includes the
built routers (health, bootstrap, auth, admin_users, admin_llm, admin_db). Add one
`include_router` for the characters router **after** them. Nothing else in `main.py`
changes. The lifespan still runs no DDL.

## 405 on DELETE

No handler is declared for `DELETE`. Starlette answers **405 Method Not Allowed** when a
path matches a route under another method. `/api/characters` (GET/POST) and
`/api/characters/{character_id}` (GET/PATCH) both match, so DELETE on either answers 405
with no code of ours. DoD-9 asserts the status, not a body.

## Router test pattern

Follow `backend/tests/test_admin_users_router.py` exactly in shape. A file-local
`application` fixture builds the app with the test settings, and a `client` fixture wraps
it. Schema is created with `schema.metadata.create_all`. A file-local `_insert_user` does
a raw insert of a users row with a known password hash, with role `roleplayer` or
`admin`, and a file-local `_login` posts to `POST /api/auth/login` so the client carries
the session cookie. Two users (A, B) plus one administrator cover DoD-4, -5, -11. Use
**separate client instances** (or re-login) per user, so cookies do not leak between them.
