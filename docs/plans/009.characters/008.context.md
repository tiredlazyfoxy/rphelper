## Where the tree sits in 008's shell

008 step `004`'s `WorkspaceShell` renders, in its expanded column: the "Collapse tree"
`IconButton` at the top, **an empty body**, and `UserMenu` (`compact` false) at the foot.
The tree goes in that body. The rail branch (`showsRail` true) is untouched, so a
collapsed or narrow-closed column renders no tree, and the tree's effect does not run.
Expanding mounts the tree and re-runs the load. That is accepted: one small GET per expand,
and the workspace state keeps the rows meanwhile.

The narrow overlay is the same expanded column (008 D3). A row click is an in-entry
navigation, which 008's shell already answers by closing the overlay (008 D11). Nothing to
add here.

## Rows and the active mark

- Rows are router links. Mantine's `NavLink` rendered with `component={Link}` (from
  `react-router-dom`) and `to`, with its `active` prop driven by comparing the row id to
  the current `/characters/:id`. Set `aria-current="page"` on the active row explicitly
  (Mantine's `active` is visual only). Alternatively use `react-router-dom`'s own
  `NavLink`, which sets `aria-current="page"` itself. Either satisfies DoD-2.
- `CharacterTree` sits **outside** `<Routes>` (in the shell), so `useParams` does not see
  `:id`. Read the current id with `useMatch("/characters/:id")` (or from `useLocation`).
  `/characters/new` must not match any row.
- Dimmed archived rows: Mantine `c="dimmed"` (or reduced opacity) on the row label, plus
  a small `Badge` reading exactly "Archived". No `shell.css` change.
- The list's accessible name "Characters": e.g. a `nav` / `ul` with `aria-label`. Tests
  query `getByRole("list", { name: "Characters" })` or the equivalent landmark, so pick an
  element whose role carries the name (`ul` with `aria-label` gives role `list`).

## The reload effect

Depend on the `showArchived` value read during render (the component is an `observer`, so
it re-renders when the flag changes). Abort the previous controller in the effect cleanup.
Do not call `loadCharacters` from the switch's handler as well, or the toggle would issue
two requests.

## 008 test amendments this step owns

- `tests/app/WorkspaceShell.test.tsx`: every render needs the new `characters` prop (a
  fresh `CharactersState`) and a `fetch` stub answering `GET /api/characters`. 008's
  `004.context.md` said the expanded column carries no search / new-character. Any 008
  clause asserting their **absence in the expanded column** is now wrong and is replaced
  by DoD-7. Clauses about the **rail** keep their meaning, but `getByRole` queries for
  "Search" / "New character" may now need scoping to the rail state (collapsed), where
  only one of each exists.
- `tests/app/App.test.tsx`: every route now mounts the tree, so the stub must answer
  `GET /api/characters` in all cases. DoD-8..10 are added here.
- `tests/app/AppBoot.test.tsx`, `tests/entries.test.tsx`: on boot success they render
  `App`, which now issues `GET /api/characters`. A stub that answers every URL with the
  `/api/me` body would make the tree read a payload with no `characters` key. Route the
  stub by URL (DoD-11).
