# Step 002 — step-specific context

Feature-wide facts are in `context.md`: **D7** (PATCH semantics), **D9** (archive /
restore / edit-archived), **D10** (order), the **owner-scope constraint**, the
**no-delete constraint**, and backend **Test conventions**. Only what is narrow to this
step is below.

## Service conventions (harvested from built services)

- **Connection first.** Services take a SQLAlchemy Core `Connection` as their first
  argument and use Core expressions (`select` / `insert` / `update`) against the
  `characters` Table imported from `app.db.schema`. Not the ORM.
- **Reads** run on the connection's autobegun transaction and **roll back the
  transaction they opened** before returning. The engine uses pysqlite transactional DDL,
  so an autobegun read holds a real `BEGIN`, and a later `begin()` on the same
  request-scoped connection would raise (`backend-structure.md` "Transactional DDL").
  DoD-10 checks this.
- **Writes** run inside `with connection.begin():`. A write that must first locate the
  row (update / archive / restore) does the owner-scoped read **inside** that same
  block, so "not found" and "found and written" are decided in one transaction.
- **Value objects**: return a frozen dataclass (`Character`), never a Row or a dict.
- **Errors**: raise `CharacterNotFoundError` from `app.errors`. Never an HTTP exception.

## Timestamps

Each service module defines its own private `_now_text()` returning
`datetime.now(UTC).isoformat(timespec="microseconds")`. That gives the fixed-width
`+00:00` form `data-model.md` requires. **Follow that convention: do not import another
service's helper and do not extract a shared one.** `create_character` calls it once and
uses the value for both `created_at` and `updated_at`.

## Ids

`SnowflakeGenerator` from `app.ids`. Call `next_id()` once per create, before the
insert. The router passes the process's generator in (`003`). Tests may pass a real
generator or any object with a `next_id()` returning a known int.

## Scope predicates — what each statement carries

| Operation | `WHERE` / `VALUES` |
|---|---|
| list | `user_id = :user_id` and, unless `include_archived`, `archived_at IS NULL`; `ORDER BY created_at DESC, id DESC` |
| create | `VALUES (… user_id = :user_id …)` |
| get / locate-for-write | `id = :id AND user_id = :user_id` |
| update / archive / restore | the UPDATE's own `WHERE` is `id = :id AND user_id = :user_id` too, not only the locating read |

A row that exists for another user and a row that exists for nobody follow the same code
path and raise the same error. There is no "exists but not yours" branch (R5, D8).

## Test seeding

The FK is enforced (`foreign_keys = ON`), so tests insert `users` rows first (a raw
insert with the columns `users` requires: id, username, password_hash, role, is_enabled,
created_at, updated_at). The tests create schema with `schema.metadata.create_all` on
the `db_engine` fixture.
