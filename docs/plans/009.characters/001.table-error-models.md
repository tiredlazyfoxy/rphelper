# Step 001 — The `characters` table, its not-found error and its pydantic models

## Goal

Declare 009's half of the `characters` table in the registry (D5), add the
`character_not_found` domain error (404, D8), and add the four request/response models
for `/api/characters`. The models carry the stripped, non-empty name rule. Rescope two
existing backend tests that registering `characters` breaks.

backend/app/db/schema.py

backend/app/models/characters.py

## Test files

backend/tests/test_db_schema.py

## Interface intent

**`db/schema.py`** (extended)

- **`characters`**: a module-level `Table` literal bound to the one `metadata`, with
  exactly the seven columns of D5: the snowflake `id` primary key (the registry's id
  column form), `user_id` (NOT NULL, FK to `users.id`, no `ON DELETE` clause), `name`
  and `sheet` (Text, NOT NULL, no server default), `archived_at` (Text, nullable),
  `created_at` and `updated_at` (Text, NOT NULL). Plus one non-unique index on `user_id`.

**`errors.py`** (extended)

- **`CharacterNotFoundError`**: a `DomainError` subclass, code `character_not_found`,
  HTTP status 404, empty `detail`. Same shape as `UserNotFoundError` in every other
  respect (including whatever that class does about a default message).

**`models/characters.py`** (new)

- **`CharacterResponse`**: response model with `id` (outbound snowflake → decimal
  string), `name`, `sheet`, `archived_at` (string or null), `created_at`, `updated_at`.
  No `user_id`.
- **`CharacterListResponse`**: response model wrapping a list of `CharacterResponse`
  under the key `characters`.
- **`CreateCharacterRequest`**: request model, unknown keys ignored. `name` is required,
  whitespace-stripped, then at least one character. `sheet` is optional, defaults to the
  empty string, and is kept verbatim (not stripped).
- **`UpdateCharacterRequest`**: request model, unknown keys ignored. `name` and `sheet`
  are both optional, and absent or `null` means "not supplied". A supplied `name` follows
  the same strip-then-non-empty rule. A supplied `sheet` is kept verbatim.

## Definition of done

1. `[test]` 009 adds `characters` and nothing else to the registry. The 009 delta in
   `tests/test_db_schema.py` must keep passing when later features add tables, so it is
   written in the form DoD-11 prescribes, not as a bare equality against "everything minus
   a pre-set". It checks two things: `characters` is in `schema.metadata.tables`, and
   the registry minus the tables declared up to and including 009 holds no table this
   feature declared.
2. `[test]` `characters` has exactly the columns `id`, `user_id`, `name`, `sheet`,
   `archived_at`, `created_at`, `updated_at`. `id` is the primary key. `user_id`, `name`,
   `sheet`, `created_at`, `updated_at` are NOT NULL. `archived_at` is nullable. The
   table has **no** `model_ref`, `system_prompt`, `tools`, `rp_language` or
   `preferred_language` column. (D5, `data-model.md` R1 enforcement)
3. `[test]` `characters.user_id` is a foreign key to `users.id`, and the table declares
   an index whose only column is `user_id`.
4. `[test]` `metadata.create_all` on a fresh test engine creates `characters`. Inserting a
   `characters` row whose `user_id` names no `users` row fails (the FK is enforced).
5. `[test]` `CharacterNotFoundError` is a `DomainError` with code `character_not_found`
   and HTTP status 404. Raised from a route on an application with the exception handlers
   registered, it answers 404 with the envelope `{ "error": { "code":
   "character_not_found", … , "detail": {} } }`. (D8, R5)
6. `[test]` `CharacterResponse` built from an int id serialises `id` as the decimal string
   of that int. `archived_at` `None` serialises as JSON `null`. The serialised object has
   exactly the six keys of the wire contract (`context.md`).
7. `[test]` `CharacterListResponse` serialises as an object whose only key is
   `characters`, holding the serialised rows in the order given.
8. `[test]` `CreateCharacterRequest`: `"  Aria  "` parses to `"Aria"`. `""`, `"   "` and a
   missing `name` each fail validation. A missing `sheet` gives `""`. A `sheet` of
   `"  # Notes\n"` is kept exactly. Unknown keys (e.g. `user_id`, `archived_at`) are
   ignored, not rejected. (D8)
9. `[test]` `UpdateCharacterRequest`: `{}` parses with both fields unset. `{"name": null}`
   is the same as absent. `" Bo "` parses to `"Bo"`. A whitespace-only `name` fails
   validation. `sheet` is kept verbatim. Unknown keys are ignored. (D7, D8)
10. `[manual/live]` Against an existing pre-009 database, the admin Database page lists
    `characters` as missing, and its **Create** brings it to in-sync (D5, FEAT-005).
11. `[test]` **Rescope 006's registry-delta assertions** in `tests/test_db_schema.py`: the
    test `test_registry_gains_exactly_the_two_new_tables__S006_001_DoD5` (around lines
    887–889) and its sibling assertion (around lines 897–898). Each asserts
    `set(schema.metadata.tables) - PRE_006_TABLES == NEW_006_TABLES`, which breaks as
    soon as any later table exists. The rescoped form keeps 006's intent: 006 added
    exactly `llm_servers` and `models`, and the pre-006 tables are still present. It must
    not break when later features add tables. Two acceptable shapes:
    - the subset form `NEW_006_TABLES <= set(schema.metadata.tables)`, plus a check that
      no other table between `PRE_006_TABLES` and the later features' known tables
      appeared;
    - or equality after also subtracting a later-features set (009's `{"characters"}` and
      a place for later deltas).

    Keep the existing test names. The two assertions must still fail if 006's two tables
    were removed. The already-safe subset check near line 983 stays as it is.
12. `[test]` **Rescope `tests/test_admin_db_router.py`'s undeclared-name list**: its
    `UNDECLARED_NAMES` (around line 988) uses `"characters"` as an example of an
    unregistered table and expects 404 `unknown_table`. Replace `"characters"` with a
    name that is still undeclared, `"setups"` (feature `010`'s, not yet registered), so
    the 404 `unknown_table` expectation holds again. No other entry or assertion in that
    file changes.
