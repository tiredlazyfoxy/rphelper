## The page spec

`docs/architecture/admin-surfaces.md`, "LLM Servers page — FEAT-004" (~lines 333–453), is
the authority. Two deviations from it are already decided and are **not** this step's to
re-litigate:

- **no "active" badge column and no active switch** (`context.md` D1);
- the **last-test badge** is an addition the doc's own DEVIATION paragraph asks for
  ("surfaced in the UI as a badge or alert **without opening the models list**").

The doc's row overflow menu is Edit · Select Models · Set Embedding · Clear Embedding
(conditional) · Delete · Test connection. This step builds **Test connection** and
**Delete**; `007` adds Edit, `008` adds Select Models, `009` adds Set Embedding and the
conditional Clear Embedding. **No disabled placeholder is left for them** — an unbuilt menu
item is a stub, not room.

## Borrowed interfaces, by module path and role

- **`frontend/src/shared/api.ts`** (`002/004`) — `apiGet`, `apiPost`, `apiDelete`. Every
  path starts with `/api/`; `credentials: "same-origin"`; a **401 navigates to `/login`**
  before throwing, which is correct here — an administrator whose session died mid-page
  belongs on the login screen. `apiDelete` returns `undefined` for the 204 the delete route
  answers.
- **`frontend/src/shared/apiError.ts`** (`002/004`) — branch on **`.code`** or `.status`,
  **never** on `.message`. This page does not branch at all: it renders the error's message
  in the inline `Alert`, which is what an unclassified page-level failure is for.
- **`frontend/src/shared/IconButton.tsx`** (`002/003`) — the only sanctioned icon-only
  control, enforced by `frontend/tests/conventions.test.ts`. The row's overflow trigger is
  its consumer here: `icon` is `IconDots`, `label` names the row's registration,
  `sizeVariant` stays `"main"`.
- **`frontend/src/shared/ConfirmModal.tsx`** (`005/006`) — prop-driven: open flag, title, a
  one-sentence consequence, a confirm label, an optional confirm colour, an optional
  in-progress flag, and cancel/confirm callbacks. It holds no state and makes no request.
  `005`'s step file names this feature's delete-connection confirm as an intended reuse;
  **reuse it, do not hand-roll one**.
- **`frontend/src/admin/usersPageState.ts` / `UsersPage.tsx`** (`005/006`) — the worked
  example of everything above in combination. This page is its sibling and should read like

- **`frontend/src/admin/AdminApp.tsx`** (`005/005`) — the flat four-route table; only the

## Routes this page calls

`GET /api/admin/llm-servers`, `DELETE /api/admin/llm-servers/{id}` and
`POST /api/admin/llm-servers/{id}/test` (`context.md` D17). No other route in this step, and
no query parameter on any of them.

## The list payload this page binds to

Step `005`'s server model: id (a decimal string), name, kind, base URL, the has-API-key
boolean, the enabled model names, the designated model name and dimension (nullable), the
three last-test fields, and the two timestamps. Exact field names are step `005`'s Interface
intent and the skeleton agent resolves them; this page must not invent a field the backend
does not send — and in particular there is **no** `active`, **no** pointer text and **no**
count of anything user-owned to render.

The enabled-model **count** column is the **length of the enabled names array**, not a
separate field. Steps `008` and `009` consume the same array as the "already-enabled" half
of the union, which is why it rides on the list rather than on a route of its own
(`context.md` D17).

## Rendering the last test

`last_test_ok` plus `last_test_error` (which holds the **typed outcome value**, never
prose — `context.md` D6) drive a badge through one pure helper. Four labels, one for each
outcome, plus a "never tested" rendering when the instant is absent. `last_test_at` is a
UTC ISO-8601 **string** rendered as a readable local date-time by constructing a `Date`
from it — a date, not an id, so the ids-are-strings rule does not apply — and an **em
dash** when absent. No relative-time formatting and no date library: `002`'s D14 installs
none and none may be added here.

## The confirm's wording, and the line it must not cross

Title and confirm label name the action. The consequence sentence says the registration and
its enabled-model set are removed and cannot be restored. It carries **no count of
anything**: `domain-rules.md` R5 names *this page's* delete/disable confirm as the exact
site where "Are you sure? N sessions use this model" gets written in good faith, and
forbids it and every variant. DoD-11 asserts the absence.

## Gotchas

- **The status field gates the `Loader`, not "rows are empty".** An empty registration list
  is the first-run state and is legitimate; a `Loader` that never leaves is what the
  implicit version produces.
- **Re-load after the test, not just after the delete.** The badge must show what the
  server **stored**, and the test route is the only thing that writes those three columns.
- **A failed test is not a page error.** The typed outcome comes back on a 200 and belongs
  in the badge; the `Alert` is for a transport failure or a typed error such as
  `secret_ref_missing` (`context.md` D14), which is a 500 and will surprise a reader who
  has not read that decision.
- **Modal open flags and the target row are component-local `useState`.** Putting them in
  the store makes the store's shape depend on the page's visual arrangement.
- **No empty-state component.** `ui-conventions.md` records the sibling project has none and
  flags an improvement as welcome but not mandated; nothing in `docs/product/` requires one,
  so none is specified and none is invented here.
