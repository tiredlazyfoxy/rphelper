# Step 004 — Model enablement, the embedding designation and its measured dimension, and the two use-time validators

## Goal

Complete `services/llm_registry.py` with the model half: replacing a server's enabled set,
designating the one embedding model — measuring its dimension with a real embeddings call
— clearing that designation, and the two use-time predicates R4 requires, which ship here
with no call site by design.

## Interface intent

Same conventions as step `003`: plain functions, a Core `Connection` first, frozen
dataclasses out or a typed error raised, no `fastapi`, no status codes, explicit
transactions, the same injected client factory.

**A set-enabled-models operation** — takes the connection, a server id and the **complete**
set of model names that should be enabled on it, and makes the stored state match, in one
transaction:

- a named model with no row gets one, minted from the generator handed in, with
  `is_enabled` true;
- a named model with a row has `is_enabled` set true;
- a model with a row that is **not** named has `is_enabled` set false;
- **no row is ever deleted** (`context.md` D10), and `is_embedding_designated` and
  `embedding_dim` are **never touched** by this operation (`context.md` D4).

It refuses nothing and consults nothing outside `llm_servers` and `models`. It raises
`llm_server_not_found` for an unknown server, returns the enabled names as stored
afterwards, and is **not** `async` — it makes no outbound call, because the names come
from the caller and not from a probe.

**A designate-embedding-model operation** — takes the connection, a server id, a model name
and `Settings`, and is `async` because it makes one real embeddings call
(`context.md` D2):

1. read the server, raising `llm_server_not_found`;
2. resolve the pointer through `resolve_secret` — `secret_ref_missing` propagates before
   any client exists;
3. build a client through the shared factory and **embed one short fixed string** against
   the named model;
4. measure the length of the returned vector; a failed call, or a response with no usable
   vector, propagates step `002`'s `llm_unreachable` and **writes nothing at all** — the
   previous designation, whatever it was, survives untouched;
5. on success, in **one** transaction: clear `is_embedding_designated` on **every** row of
   the table, then upsert the row for this (server, model) pair with the flag true and the
   measured dimension written to `embedding_dim`.

The designation is **independent of `is_enabled`** — designating does not enable, and a
model that is not enabled may still be designated (`context.md` D4). The fixed probe string
is a constant in this module, is not configurable, and contains no user content. Returns
the server-row value for the designating server.

**A clear-designation operation** — takes the connection and a server id, clears
`is_embedding_designated` on that server's rows in one transaction, and leaves
`is_enabled`, `embedding_dim` and every row's existence alone. Idempotent. Raises
`llm_server_not_found` for an unknown server. Makes no outbound call.

**A use-time chat-model validator** — takes the connection, a **server id**, a **model
name** and the **level** that set the reference (`character` or `session`, **never**
`user`), and returns the enabled model together with its server registration, or raises
`model_not_enabled`. Its `detail` carries the server id as a **decimal string**, the model
name, and the level — and nothing else; never a count, never anything derived from another
user's data (R5). It **substitutes nothing**: there is no "first enabled model" path, no
fallback, no walking up any chain. `context.md` D12 records that the packed form of
`sessions.model_ref` is deliberately not fixed here, which is why this takes a pair rather
than a reference string.

**A use-time embedding-model validator** — takes the connection and returns the designated
model's server registration, model name and recorded dimension, or raises
`no_embedding_model` when there is no designation **or when the designated model is not
enabled** (`context.md` D4). Its `detail` carries nothing user-scoped. It substitutes
nothing: a different embedding model produces vectors that are not comparable with the
stored ones, which is why this fails loudly.

## Definition of done

1. `[test]` Enabling a model that has no row creates one with `is_enabled` true, and it
   then appears in the server's enabled names. (US-014.AC-1, UC-012)
2. `[test]` Submitting a set that omits a previously enabled model sets that row's
   `is_enabled` false and **does not delete it** — it is still present and still
   addressable, which is what makes a stale enablement clearable. (US-014.AC-2;
   `context.md` D10; `admin-surfaces.md`'s union rule)
3. `[test]` Submitting the empty set disables every model on that server and deletes no
   row. (US-014.AC-2)
4. `[test]` Re-submitting the same set is idempotent: no row is created, deleted or
   duplicated, and the unique (server, model) pair holds. (UC-012)
5. `[test]` The same model name may be enabled independently on two different servers, and
   enabling it on one does not change the other. (UC-012; `context.md` D10)
6. `[test]` **Disabling is never refused**: the operation takes no parameter, returns no
   value and raises no error by which a dependency could be reported, and it issues no
   query against any table but `llm_servers` and `models`. (US-016.AC-1, UC-012, R5)
7. `[test]` Disabling a model that is the designated embedding model **succeeds and leaves
   the designation and `embedding_dim` in place** — designation is independent of
   `is_enabled` and there is no cascade. (`context.md` D4 — the brief's first open
   question, **no product id**)
8. `[test]` Designating a model performs exactly **one** embeddings call against that
   server, and writes `is_embedding_designated` true plus an `embedding_dim` equal to the
   **length of the returned vector**. (US-015.AC-1, UC-013; `context.md` D2)
9. `[test]` Designating clears `is_embedding_designated` on **every other row in the whole
   table**, including rows on other servers, so at most one row carries it — and does so in
   the same transaction as the new designation. (UC-013; `data-model.md`'s `models`)
10. `[test]` A designation whose embeddings call fails — transport, timeout, auth, or a 2xx
    with no usable vector — raises and **writes nothing**: no flag moves, no dimension is
    recorded, and a designation that existed before is still exactly as it was.
    (`context.md` D2 — **no product id**)
11. `[test]` Designating does **not** change any row's `is_enabled`, in either direction.
    (`context.md` D4 — **no product id**)
12. `[test]` The fixed probe string is a module constant carrying no user content, and the
    designation call sends exactly that one input. (R5; `deployment.md`'s redaction rule —
    **no product id**)
13. `[test]` Designation resolves the pointer before building a client, so an absent
    environment variable raises `secret_ref_missing` with the client factory never called
    and nothing written. (`backend-structure.md`'s secret-pointer pattern)
14. `[test]` Clearing the designation removes the flag, is idempotent, makes no outbound
    call, and leaves `is_enabled` and every row's existence untouched. (UC-013;
    `admin-surfaces.md`'s Clear-embedding action)
15. `[test]` The chat-model validator returns the model and its server registration when
    the model's row exists and `is_enabled` is true. (US-014.AC-1's registry half)
16. `[test]` The chat-model validator raises `model_not_enabled` when the row exists with
    `is_enabled` false, when no row exists for that pair, and when the server itself is
    gone — and in every case **returns no substitute**: no other model, no "first enabled
    one", no fallback. (US-016.AC-2, UC-012, R4)
17. `[test]` `model_not_enabled`'s `detail` carries the server id as a **decimal string**,
    the model name and the level, with the level constrained to `character` or `session`
    and **never** `user` — and carries **no count and nothing about any session or user**.
    (UC-050 and R1's correction; R5; `backend-structure.md`'s JSON id boundary and its
    three `detail` rules)
18. `[test]` The embedding validator returns the designated server, model name and recorded
    dimension when a designation exists and that model is enabled. (UC-013)
19. `[test]` The embedding validator raises `no_embedding_model` when there is no
    designation at all, and when the designated model exists but is **not enabled** — the
    use-time half of `context.md` D4 — and substitutes no other model in either case.
    (UC-013, R4; `llm-and-streaming.md`'s embedding paragraph)
20. `[test]` `no_embedding_model`'s `detail` carries nothing user-scoped.
    (`backend-structure.md`'s error table; R5)
21. `[test]` Nothing in the module branches on `kind`, and every transaction is an explicit
    `with conn.begin():` in this module. (`context.md` D5;
    `backend-structure.md`, Database access — **no product id**)
22. `[manual/live]` Against a real embeddings-capable server, designating a model records a
    plausible dimension, and designating a **chat-only** model is refused with the typed
    error and leaves the previous designation intact.
23. `[manual/live]` `mypy app`, `ruff check .` and `pytest` all pass from `backend/`.
