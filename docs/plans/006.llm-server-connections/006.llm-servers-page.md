# Step 006 — The LLM Servers page: its store, its table, the row menu, the delete confirm and Test connection

## Goal

Replace the `/llm-servers` route's 404 element with the real page — a plain Mantine table
of registrations, one overflow menu per row, a confirmed delete and UC-011's
test-connection action — driven by a MobX page store with no methods.

## Interface intent

**`frontend/src/admin/llmServersPageState.ts`** — the page store, its row type and its
three effects, in one module (`context.md` D16).

- **A server row type** mirroring step `005`'s server model, with the **id as a
  `string`** — an `id: number` is a defect — the kind as the two-member union, the
  has-API-key boolean, the enabled model names, the nullable designation and dimension, the
  nullable last-test instant, ok flag and typed outcome, and the two timestamps. The probe
  outcome union is the same closed four-value set the backend declares; it is not widened
  to `string`.
- **A page-state class** holding observable fields only: the rows, an explicit
  idle/loading/ready status, a nullable page-level error message, and a nullable
  "which row is currently being tested" id so the row's action can show progress. **No
  methods, no computed getters**, `makeAutoObservable(this, {}, { autoBind: true })` in the
  constructor.
- **A load effect** — `GET`s the list, `runInAction`s its writes, early-returns on an
  aborted signal before writing, sets the status through idle → loading → ready, and puts a
  failure's message into the page error field rather than raising.
- **A delete effect** — takes the state and a row id, `DELETE`s, and on success **re-loads
  the list** (`ui-conventions.md`: mutations are never optimistic). Failure lands in the
  page error field.
- **A test-connection effect** — takes the state and a row id, marks that row in progress,
  `POST`s the test route, and **re-loads the list** afterwards so the badge reflects what
  the server stored. A failure — including the 500 `secret_ref_missing` case
  (`context.md` D14) — lands in the page error field and clears the in-progress marker.
- A **pure** helper deriving the last-test badge's label and colour from a row's ok flag
  and typed outcome, so the four outcomes map to words in one testable place and the
  component maps nothing.

**`frontend/src/admin/LlmServersPage.tsx`** — an `observer` component taking the store as a
prop and rendering it.

- A page-level `useEffect` with an `AbortController` that loads on mount and aborts on
  unmount. The store is created by the component that mounts the page with
  `useState(() => new …)`, **never `useMemo`**.
- A **plain Mantine `Table striped highlightOnHover`**, no data-table library, no card
  list, no sorting, no filtering, no pagination. Columns: name; kind as a **`Badge`**; base
  URL; has API key; enabled-model count (the length of the names array); the last-test
  badge; and a trailing **`w={60}`** action column.
- The action column holds **one** icon-only control — an `IconDots` trigger routed through
  `shared/IconButton` — opening a Mantine `Menu`. Its items in this step are **Test
  connection** and **Delete**. Steps `007`–`009` add the rest to the same menu; no disabled
  placeholder is left for them.
- **Loading** is a centered Mantine `Loader` gated on the status field, never on "rows are
  empty". **Errors** are an inline `Alert` **above** the table and **never** also a
  notification. An empty list renders an empty table body under its headers.
- **Delete goes through `shared/ConfirmModal`** (`005/006`), whose open flag and target row
  are **component-local `useState`**, never store fields. The consequence sentence
  describes the action — the registration and its enabled-model set are removed and cannot
  be restored — and **names no count of anything** (R5).

**`frontend/src/admin/AdminApp.tsx`** — replace the one `<Route path="/llm-servers">`
element that renders the 404 with this page. Nothing else in the file changes: the
`<Routes>` stays flat and four elements long, there is no nested layout route and no
`<Outlet/>`.

## Definition of done

1. `[test]` On mount the page requests the registration list once and renders one row per
   registration, showing name, kind, base URL, whether an API key is recorded and the
   enabled-model count. (US-012.AC-2, UC-010)
2. `[test]` A registration created through the API appears in the table after a load —
   there is no local insertion path. (US-012.AC-2)
3. `[test]` **Every id the page holds is a `string`**: no type, prop, store field or call
   argument declares `number` for an id, and nothing calls `parseInt` or sorts numerically.
   (`data-model.md`'s Identifiers; `frontend-structure.md`, "Ids are strings" — **no
   product id**)
4. `[test]` While the list request is in flight a centered `Loader` renders and no table
   body does; the gate is the explicit status field, so an **empty** ready list renders the
   table's headers with no rows and **no** `Loader`. (`ui-conventions.md`, loading and
   empty states — **no product id**)
5. `[test]` A failed list load renders its message in an inline `Alert` **above** the
   table, and **raises no notification** — `notifyFailure` and Mantine's notification API
   are not reached from this feature at all. (`ui-conventions.md`, errors and async
   feedback — **no product id**)
6. `[test]` Choosing **Test connection** posts to that row's test route and, on a reachable
   result, the row's last-test badge reads as reachable after the list re-loads.
   (US-013.AC-1)
7. `[test]` On a failing result the badge reports the failure and **the row is still
   present in the table** — the registration stays registered. (US-013.AC-2, UC-011)
8. `[test]` The four typed outcomes each map to a distinct rendered badge, derived by the
   pure helper from the row's ok flag and outcome value — the page **parses no message
   text** to decide what to show. (`admin-surfaces.md`'s result taxonomy;
   `context.md` D6 — **no product id**)
9. `[test]` A test that fails at the transport or with a typed error renders the error in
   the page-level `Alert`, clears the in-progress marker, and leaves the table usable.
   (US-013.AC-2; `context.md` D14)
10. `[test]` **Delete is confirmed**: choosing Delete opens the shared confirm and issues
    **no** request; cancelling issues none and leaves the row; confirming issues the
    `DELETE` and then **re-loads the list**, after which the row is gone.
    (`ui-conventions.md`'s confirm convention; `context.md` D18 — **no product id**)
11. `[test]` **The confirm's text names no count and nothing derived from another user's
    data** — the rendered dialog contains no digit-bearing claim about sessions, users or
    anything owned by them, and the page nowhere renders such a count. (R5, UC-012,
    UC-065, UC-066)
12. `[test]` Every mutation is followed by a re-load and nothing is written into the store
    in anticipation: a delete whose request fails leaves the row rendered and puts the
    failure in the `Alert`. (`ui-conventions.md`, mutations are never optimistic — **no
    product id**)
13. `[test]` **No success notification and no success toast is raised anywhere on this
    page**; success is the list refreshing. (`ui-conventions.md`, "A notification whose
    message is a success is a defect" — **no product id**)
14. `[test]` Row actions live in **one** overflow `Menu` behind a single `IconDots` trigger
    routed through `shared/IconButton`, in a trailing `w={60}` column — there is no second
    icon-only control in a row. (`ui-conventions.md`, tables and the icon boundary — **no
    product id**)
15. `[test]` The table has no sort control, no filter input and no pagination control, and
    the page sends no query parameter on any request. (`ui-conventions.md`, "No sorting,
    filtering or pagination" — **no product id**)
16. `[test]` The store class declares **no methods and no computed getters**; every effect
    is a free function taking the state first, `runInAction`s its writes and early-returns
    on an aborted signal before writing, and the store is instantiated with
    `useState(() => …)` rather than `useMemo`. (`context.md` D16 — **no product id**)
17. `[test]` Unmounting mid-request aborts it and writes nothing into the store afterwards.
    (`context.md` D16 — **no product id**)
18. `[test]` `/llm-servers` renders this page and no longer the 404 element, while `/`,
    `/database` and an unmatched path are unchanged; the `<Routes>` is still flat and four
    elements long. (`admin-surfaces.md`, "Flat `<Routes>`"; `005`'s D12 — **no product
    id**)
19. `[test]` No file under `frontend/src/admin/` imports a stylesheet or declares a `.css`
    of its own, and this page renders through Mantine props alone.
    (`frontend-structure.md`; root `CLAUDE.md` — **no product id**)
20. `[manual/live]` Signed in as an administrator against a running backend, the page lists
    real registrations, Test connection updates the badge for a reachable and an
    unreachable server, and Delete removes a registration after the confirm.
21. `[manual/live]` `npm run typecheck`, `npm test` and `npm run build` all pass from
    `frontend/`.
