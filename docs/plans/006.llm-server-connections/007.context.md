# Step 007 — step-specific context

Feature-wide facts are in `context.md` (D1 for the dropped active switch, D5 for the two
kinds, D8 for the server-side 422, **D9 for the three pointer states**, D16 for the MobX
rules, D17 for the routes). Only what is narrow to this step is below.

## The one rule this step exists to get right

`admin-surfaces.md` calls the API-key round-trip **"inherited, and the single easiest thing
to get wrong"**, and the failure mode is specific: a form that sends `""` for an untouched
field **silently deletes the credential on every save**. Nothing about it is visible until
the next call to that provider fails.

The mechanism is the `pointerTouched` boolean. It is not a validation flag and it is not
"is the field non-empty" — an empty field that the administrator deliberately cleared and
an empty field they never visited are the two states that must stay apart, and only an
explicit touch marker tells them apart. Set it in the field's change handler, never derive
it.

DoD-3 through DoD-7 are the five payload cases, written out so none can be tested by
accident.

## Borrowed interfaces, by module path and role

- **`frontend/src/shared/api.ts`** (`002/004`) — `apiPost` for register, **`apiPatch`** for
  edit. Body is sent iff it is not `undefined`; the helpers take a plain object and the
  *absence of a key in that object* is what "omitted" means on the wire.
- **`frontend/src/shared/apiError.ts`** (`002/004`) — `ApiError` with `.code`, `.status`
  and `.detail`. Map by those; `.message` is for rendering only.
- **`frontend/src/admin/createUserDraft.ts` / `CreateUserModal.tsx`** (`005/007`) — the
  worked example of the draft shape, the conditional mount and the by-status mapping. This
  modal is its sibling and should read like it.
- **step `006`'s page store and row type** — the draft is constructed from a row for edit,
  and the submit's success callback is the page's re-load effect.

## The server errors this form can actually draw

Worth stating, because a mapping invented for an error the backend cannot produce is dead
code that looks like coverage:

| Status / code | Where it lands |
|---|---|
| **422** (empty name, empty base URL, bad kind, malformed pointer) | in practice unreachable — the client refuses all four first (DoD-8, DoD-9). If it arrives anyway it lands on the **general key**, because FastAPI's 422 body does not name a field without parsing prose, which the convention forbids. |
| **404** `llm_server_not_found` (edit of a row deleted in another tab) | the **general key** |
| any other typed error, transport failure | the **general key** |

There is **no conflict code on this router** — nothing here is unique, so there is no
`username_taken` analogue and no field-specific mapping to build. Everything that is not a
client-side refusal lands on the general key, and DoD-10 asserts the general key is reached
rather than swallowed.

## The base-URL check the client performs

Non-empty and shaped like an absolute `http`/`https` URL. Nothing stronger: the three
pasteable forms (`http://host:port`, with a trailing slash, with a `/v1` suffix) are all
legal and step `002`'s client normalises them (its DoD-4). A client-side rule that rejected
any of the three would make a correct configuration unenterable.

## Gotchas

- **The pointer field starts empty on edit even when the row records one.** The server never
  returns it, so there is nothing to prefill; showing a fake placeholder of dots in the
  value would make DoD-4 impossible to satisfy honestly. The *description* is where the
  administrator is told what leaving it alone does.
- **`PATCH`, not `POST`, for the edit** (`context.md` D17) — and the payload's shape *is*
  the contract, so a helper that strips empty strings from the body before sending would
  break D9's clear case.
- **A fresh draft per open** via `useState(() => new …)` **inside a conditionally mounted
  modal body**, never a long-lived draft reset on close: a reset function is one more thing
  to keep in step with the field list, and a forgotten field is a stale value shown to the
  next user of the dialog.
- **No confirm on save.** `ui-conventions.md`'s confirm table covers destructive actions;
  a form submit is not one, and `context.md` D18 fixes the set for this feature.
- **The `Select`'s display label may read "OpenAI" while its value is the wire literal.**
  The wire value is what `llm_servers.kind` stores and what the backend's literal accepts;
  do not send the display label.
