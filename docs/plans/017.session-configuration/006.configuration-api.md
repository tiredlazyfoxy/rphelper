# Step 006 — The configuration API module

## Goal

Add `app/configurationApi.ts`: the wire types of the Wire contract, field for field, and
one function each for listing enabled models, reading and updating the user's settings,
and reading and updating a session's configuration. The character routes get no frontend
call until `018` (D20).

frontend/src/app/configurationApi.ts

## Test files

frontend/tests/app/configurationApi.test.ts

## Interface intent

**`app/configurationApi.ts`** (new)

- **Types** mirroring the wire exactly, ids as `string`: `ModelRef`, `EnabledModel`,
  `UserSettings`, `ConfigLevel` (the four level strings), `Setting` (generic over string
  or boolean, with `session`, `inherited`, `inherited_level`, `value`, `level`),
  `SessionConfiguration` (the seven keys).
- **Patch types**: `UserSettingsPatch` (any subset of the two languages, each string or
  null) and `SessionConfigurationPatch` (any subset of `model` as a `ModelRef`,
  `system_prompt` string or null, the three `tool_*` boolean or null, the two languages
  string or null). A patch is sent with **exactly** the keys it holds.
- **`fetchEnabledModels`**: optional signal; `GET /api/models`; resolves to the list
  (unwrapped from `models`), in server order.
- **`fetchUserSettings`**: optional signal; `GET /api/me/settings`; resolves to
  `UserSettings`.
- **`updateUserSettings`**: a `UserSettingsPatch`, optional signal;
  `PATCH /api/me/settings`; resolves to `UserSettings`.
- **`fetchSessionConfiguration`**: a session id string, optional signal;
  `GET /api/sessions/<id>/configuration`; resolves to `SessionConfiguration`.
- **`updateSessionConfiguration`**: a session id, a `SessionConfigurationPatch`,
  optional signal; `PATCH /api/sessions/<id>/configuration`; resolves to
  `SessionConfiguration`.
- Every function rethrows the shared client's `ApiError` unchanged and does no
  normalisation, sorting or id conversion.

## Definition of done

1. `[test]` `fetchEnabledModels` requests exactly `GET /api/models` and resolves to the
   served list in served order, `server_id` the identical strings. (D7, ids are strings)
2. `[test]` `fetchUserSettings` requests `GET /api/me/settings`. `updateUserSettings({
   rp_language: "Japanese" })` sends `PATCH /api/me/settings` with a body of exactly
   `{"rp_language":"Japanese"}`, and `{ preferred_language: null }` sends exactly
   `{"preferred_language":null}`. Each resolves to the served settings. (US-058.AC-1)
3. `[test]` `fetchSessionConfiguration("7250000000000000101")` requests exactly
   `GET /api/sessions/7250000000000000101/configuration` and resolves to the served
   object unchanged (seven keys, settings with five keys). (Wire contract)
4. `[test]` `updateSessionConfiguration(id, { model: { server_id: "7250000000000000301",
   model_name: "llama-3" } })` sends `PATCH /api/sessions/<id>/configuration` with exactly
   that one key. `{ system_prompt: null, tool_web_search: false }` sends exactly those two
   keys with `null` preserved. It resolves to the served configuration. (US-105.AC-1, D18)
5. `[test]` A 409 `model_not_enabled` envelope on the session PATCH rejects with an
   `ApiError` whose `code` is `model_not_enabled` and whose `detail.level` is `"session"`.
   An aborted signal rejects with the abort, not an `ApiError`. (D10,
   `frontend-structure.md` "abort not wrapped")
6. `[test]` The module exports no character-configuration call. (D20)
