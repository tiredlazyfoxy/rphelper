# Step 005 — step-specific context

Feature-wide facts are in `context.md`: the **Wire contract** (routes, shapes, failures),
**D9**, **D10**, **D13**, **D14**, and the backend **Test conventions**. Only what is
narrow to this step is below.

## Router patterns, as harvested

- `routers/sessions.py` (011) is the closest precedent: `APIRouter` with
  `dependencies=[Depends(require_user)]` or a `CurrentUser` parameter, `Depends(get_connection)`,
  path ids typed with the inbound snowflake alias, `Model.model_validate(value,
  from_attributes=True)`.
- 011's `POST /api/characters/{character_id}/sessions` lives in `routers/sessions.py`
  although its path starts `/api/characters/`. The same logic puts
  `/api/characters/{id}/configuration` and `/api/sessions/{id}/configuration` here
  (routers group by feature).
- `main.py` includes routers in a list: health, bootstrap, auth, admin_users, admin_llm,
  admin_db, characters, setups, sessions, then 012's stream, 015's memos and 016's
  additions if they have landed. Append configuration at the end.
- `/api/me` is `routers/auth.py`'s (L86). `/api/me/settings` is a distinct path, and
  `auth.py` is not edited.

## Sent-field mapping

For each request model, a field in `model_fields_set` is passed as its parsed value (which
may be `None`). A field not in it is passed as `UNSET`. `001` already normalised blanks to
`None`. The session `model` field is never `None` here (`001` rejects it). The character
`model` may be `None` (clear).

## The 405 assertion (DoD-9)

011's wire contract says any `PATCH` on `/api/sessions/{id}` answers 405, and 011's
router tests may already assert it. 017 adds no route at that path, so it stays true.
DoD-9 re-asserts it here so a later "convenience" route at that path is caught. Do not
edit `tests/test_sessions_router.py`.

## Test fixtures

- Users through `_insert_user` and login through `POST /api/auth/login`. Characters
  through `POST /api/characters`, sessions through `POST /api/characters/{id}/sessions`.
  `llm_servers` / `models` raw-inserted into the test database (no admin login needed).
  Archive through 009's and 011's archive routes.
- DoD-3 / DoD-4 need sessions created at different registry states. Raw-update
  `models.is_enabled` between creations.
- DoD-1's non-admin case logs in a `roleplayer`-role user.
