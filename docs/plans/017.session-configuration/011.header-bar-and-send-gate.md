# Step 011 — The session header bar and the Send gate

## Goal

Add `app/SessionConfigBar.tsx`: the model picker, the tool indicators and the gear that
opens the configuration modal, loaded when the bar mounts (D16, UC-077). Mount it in
`SessionScreen`'s header, which owns one `SessionConfigState`. Give `Composer` an
optional `sendBlockedReason` prop, passed through `SessionStream`, that disables Send on
*my turn* and shows the reason (D17, US-107).

## Interface intent

**`app/SessionConfigBar.tsx`** (new)

- **`SessionConfigBar`**: `observer` component. Props: `state` (`SessionConfigState`).
  On mount it runs `loadSessionConfig` with an `AbortController` aborted on unmount.
  Renders a group named **"Session configuration"** holding:
  - while either status is idle or loading: a small `Loader`;
  - when either failed: **"Could not load the session configuration"** and **"Retry"**
    (re-runs the load with a fresh controller);
  - when the models are ready: the **model picker**, a Mantine `Select` labelled
    **"Model"**. Its options are the enabled models in served order, labelled
    **"<model_name> (<server_name>)"**, plus, when the captured model is not among them,
    one **disabled** option **"<model_name> (not enabled)"** for it. Its value is the
    captured model (none when null). The placeholder is **"Choose a model"**, or **"No
    model is enabled"** with the picker disabled when the list is empty. It is disabled
    while `modelSaving`. Choosing an option calls `chooseModel`. `modelFailure`, when set,
    renders as text under it;
  - when the configuration is ready: a group **"Tools"** with three `Badge`s, **"Memo
    search: on|off"**, **"Session search: on|off"**, **"Web search: on|off"**, from each
    tool's resolved `value`;
  - the gear: `IconButton` with `IconSettings`, label **"Session configuration"**,
    disabled until the configuration is ready. It opens `SessionConfigModal` (`010`) for
    the state's session with the loaded configuration. The modal's `onSaved` calls
    `applySessionConfiguration`. Its open flag is component-local `useState`.
  - No notification.

**`app/SessionScreen.tsx`** (changed; 011-owned, edited by 013 `007`, 015 `008`, 016
`006`)

- Props unchanged (`sessionId`, `characters`, `storage`). At the top, with the other
  hooks, it creates one `SessionConfigState` for `sessionId` with `useState`. It makes no
  request itself.
- In the `"ready"` render only: `SessionConfigBar` with that state is the **last child of
  the header**, after the header's title row (character link · heading · setup label ·
  Archived badge · "Open notes"), before `SessionStream`. `SessionStream` receives
  `sendBlockedReason` computed from the state. The loading, not-found and failed renders
  are unchanged and render no bar.

**`app/SessionStream.tsx`** (changed; 013-owned)

- Props gain an optional **`sendBlockedReason`** (string or null, default null), passed
  unchanged to `Composer`. Nothing else changes.

**`app/Composer.tsx`** (changed; 013-owned)

- Props gain the same optional **`sendBlockedReason`**. When the effective position is
  *my turn* and the reason is non-null, **Send is disabled** whatever `canSend` says, and
  the reason renders as text in the composer beside the buttons. On *partner*, and when
  the reason is null, Send, Settle, the paste filing, the preview line and Discard behave
  exactly as 013 `006` built them. Settle is never affected.
