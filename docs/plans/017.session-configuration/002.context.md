# Step 002 — step-specific context

Feature-wide facts are in `context.md`: **D1** (the three capture cases and the flagged
refinement), **D7** (the enabled set and its order), **D12** (the import exception and
the transaction posture), and the **Registry fixtures** test convention. Only what is
narrow to this step is below.

## `llm_registry.py` as harvested

- `ModelRefLevel(StrEnum)` CHARACTER / SESSION (~L380). `EnabledChatModel(server:
  LlmServer, model_name)` (~L388).
- `validate_chat_model(connection, server_id: int, model_name: str, level:
  ModelRefLevel) -> EnabledChatModel` (~L541–566). Enabled means the `models` row has
  `is_enabled` and its server exists. It raises `ModelNotEnabledError("The selected model
  is not enabled.", {"server_id": str, "model_name", "level"})`.
- `list_servers` orders by `llm_servers.id`; a server's enabled names come in
  `models.id` order. D7's order is the flattening of that view.
- `UNSET` / `Unset` sentinel (~L32–43).
- Reads go through a private read context (`_reading(connection)`). Its exact
  transaction behaviour is the harvest's open point. DoD-3 is the contract: if
  `_reading` would begin or end a transaction while the caller holds one, the new reads
  and `validate_chat_model` must take a path that does not (for example, detect
  `connection.in_transaction()` and run the select directly). `validate_chat_model`'s
  observable behaviour must not change. Its existing tests in
  `tests/test_llm_registry_models.py` / `_servers.py` keep passing unmodified.

## `start_session` as harvested

`start_session(connection, generator, user_id, character_id, setup_id=None) ->
RpSession` (~L72–125): one `with connection.begin():`, then the character check (owner
scoped), the setup checks, minting the id, the insert. Docstring ~L18–22. The character
check already selects the character row; extend that select with the two model columns
rather than adding a second read. The registry read is case 2 only, so a character with a
model never touches the registry (DoD-7). It happens **after** the checks, so a refused
creation costs no registry read (DoD-10).

`RpSession` (~L50) and `_session_select` / `_to_session` are **not** changed: the
captured model is not part of the `Session` wire shape (D9). Tests read it back with a
raw select on `sessions`.

  It does not import 011's test helpers.

  creations are raw statements in the test.

  does not edit them.

  smaller `models.id` than B's model. The expected first model is B's.
