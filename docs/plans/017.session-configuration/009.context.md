# Step 009 — step-specific context

Feature-wide facts are in `context.md`: **D18** (fresh draft per open, Inherit choices,
only changed keys), **D6** (verbatim prompt, trimmed languages), **D19**, the UI strings

## Pattern

`app/setupDraft.ts` (010) is the in-repo precedent for `ui-conventions.md`'s draft
convention: a class with observable fields only, and `clientErrors` / `errors` /
`canSubmit` / `submitX` as free functions. Field keys for `serverErrors` and
`clientErrors`: use `systemPrompt`, `rpLanguage`, `preferredLanguage` and the general key
the precedent uses. The skeleton freezes the names.

## Comparing against `original`

For each setting, compare the **resulting override** (D18's mapping) with
`original.<setting>.session`:

- system prompt: `"set"` → the text as typed. A text whose `trim()` is empty cannot be
  submitted (client error). `"inherit"` → null.
- languages: `"set"` → `text.trim()`; `"inherit"` → null.
- tools: `"on"` → true, `"off"` → false, `"inherit"` → null.

A setting is in the patch when the resulting override `!==` the original's `session`.
Strings are compared exactly, after the trim that applies.

## `onSaved`

The modal (`010`) passes a callback that hands the configuration to the bar's state
(`applySessionConfiguration`, `008`) and closes the modal. The draft knows neither.
