Feature-wide facts are in `context.md`: the **Wire contract**, **D20** (no character

## Pattern

Mirror `app/setupsApi.ts` / `app/memosApi.ts` (015 `005`): wire types beside the calls,
one `async` function per route, the signal last, `apiGet` / `apiPatch` from
`shared/api.ts`, and unwrapping a list key in the function (`{ models }` → the array).

## The `server_id` name and the ids scan

`tests/ids-are-strings.test.ts` flags an `id`- or `Id`-suffixed binding typed `number`.
`server_id` is a `string`, which passes. Nothing here is typed `number`.

## Generic `Setting`

`Setting<T>` with `T` either `string` or `boolean`. For a boolean setting `value` is never
null on the wire (the tools' default), but the type may stay `T | null` uniformly. The
consumers (`008`, `010`) read `value` for tools as a boolean and treat null as "unknown",
which the backend never sends. The skeleton may narrow it with a separate boolean type if
it prefers. Record the choice in `## Skeleton`.
