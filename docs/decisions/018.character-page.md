# Decisions — 018.character-page

**Stage:** 003.assistant · **Feature:** 018.character-page

This feature covers the character page as a workspace: a page composer that starts a session with an opening message, a draft page with blur-save, the notes grid, the character configuration block and the section order. The layout is in `workspace-shell.md`, and the create-with-message contract is in `session-stream.md` and `frontend-structure.md`. Parts of D1, D2 and D4 were later replaced (033, fast/004, fast/011); the replacements are marked on those entries.

### DEC-018-3 — Create and seed in one transaction
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 018.character-page · **Step:** 001, 002
- **Plan-local:** 018 D3; 001.context helper constraints; 002.context id-minting order
- **Date:** 2026-10-03 · **Decided by:** planner
- **Question:** How is a session created together with its opening message?
- **Decision:**
  - **Request and response.** The start request takes an optional `opening_message` (non-blank text). The response is the eight session keys plus `opening_message` (a message, or null).
  - **Transaction.** The message is inserted in the same transaction, after the session insert and the model capture (DEC-017-1). There is no second session bump.
  - **Zone insert.** It is a public, transaction-neutral helper: it opens no transaction, checks nothing and bumps nothing. It takes no kind or `settled_at`, so it cannot write a settled row (R11). `append_message` uses it too.
  - **Import exception.** `services/sessions.py` may import only that helper and its value type from the messages service.
  - **Operations.** `start_session` keeps its signature. A sibling operation does create-and-seed, and both share one private body.
  - **Id order.** The session id is minted before the message id.
- **Reason:** One transaction means a session never exists without its first message. Without a kind, the helper has no second door into the record.
- **Lands in:** `backend/app/services/messages.py`, `backend/app/services/sessions.py`, `backend/app/models/sessions.py`, `backend/app/routers/sessions.py`.
- **Cites:** `session-stream.md`; `backend-structure.md` service imports.

### DEC-018-4 — ComposerCore split
- **Status:** accepted; geometry superseded by DEC-F011-4, Send placement superseded by DEC-F011-1
- **Stage:** 003.assistant · **Feature:** 018.character-page · **Step:** 003
- **Plan-local:** 018 D4; user decision 3; 003.context concern table, paste order
- **Date:** 2026-10-03 · **Decided by:** user
- **Question:** How do the stream composer and the page composer share one look?
- **Decision:**
  - **Core.** A shared core holds the textarea, Send, the enormous-paste warning, and the send-blocked reason with its Send disable.
  - **Stream host.** Adds partner-paste filing, the settle preview, Settle and Discard.

- **Reason:** The composer's look and conventions are written in one place, and each host adds only what is its own.
- **Lands in:** `frontend/src/app/ComposerCore.tsx`, `frontend/src/app/Composer.tsx`.
- **Cites:** `frontend-structure.md`.

### DEC-018-5 — Page composer send
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 018.character-page · **Step:** 004
- **Plan-local:** 018 D5; 004.context eight-key shaping, unmount guard
- **Date:** 2026-10-03 · **Decided by:** planner
- **Question:** What does Send on the character page do?
- **Decision:**
  - **Send.** One POST. The new session is applied to the workspace tree, and the page push-navigates to the session. A failure keeps the draft and goes to `notifyFailure`. Nothing is pre-seeded.
  - **Shape.** `startSession` resolves to exactly the eight session keys, shaped once in the API module (`toSession`). (Both removed 2026-11-10 as dead code; the page sends through `startSessionWithMessage`, DEC-033-8, DEC-033-9.)
  - **Unmount.** The send is not aborted on unmount; a mounted ref skips only the navigation.
- **Reason:** A ninth key would leak into the workspace store. The session must still be created and listed if the user leaves the page.
- **Lands in:** `frontend/src/app/sessionsApi.ts`, `frontend/src/app/characterComposerState.ts`, `frontend/src/app/CharacterComposer.tsx`.

### DEC-018-6 — Draft page; create on name blur
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 018.character-page · **Step:** 008, 009
- **Plan-local:** 018 D6; user decision 4
- **Date:** 2026-10-03 · **Decided by:** user
- **Question:** How is a new character created?
- **Decision:** The new-character route shows a draft page. The character is created when the name field loses focus with a non-blank name. Fields are read-only while the create is in flight, and success navigates with replace.
- **Reason:** No explicit Create step, and no remount in the middle of typing.
- **Rejected:** creating per keystroke, which remounts the page while the user types.
- **Lands in:** `frontend/src/app/characterScreenState.ts`, `frontend/src/app/CharacterScreen.tsx`.

### DEC-018-7 — Blur-save of name and persona
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 018.character-page · **Step:** 008, 009
- **Plan-local:** 018 D7; user decision 4; 008.context save flags, not-older compare, server trim; 009.context persona focus leave, flush
- **Date:** 2026-10-03 · **Decided by:** user (mechanics: planner)
- **Question:** How are an existing character's name and persona saved?
- **Decision:**
  - **Trigger.** Each saves on blur. There is no Save button.
  - **Merge.** A response replaces the held character only when its `updated_at` is not older, by string compare (DEC-015-5). A field's draft adopts the saved value only if it still equals what was sent. The server trims the name.
  - **Flush.** Runs in the effect cleanup.
  - **In-flight flags.** Separate name and persona saving flags. `submitStatus` keeps covering create, archive and restore.
  - **Persona focus leave.** A wrapper whose `relatedTarget` check ignores focus moving into the editor's toolbar.
  - This retires 009 D2 (DEC-009-1).
- **Reason:** A blur-save must not disable Archive, and a name save must not block a persona save.
- **Supersedes:** DEC-009-1 (009 D2).
- **Lands in:** `frontend/src/app/characterScreenState.ts`, `frontend/src/app/CharacterScreen.tsx`.

### DEC-018-8 — Notes as a reorderable grid
- **Status:** accepted; grid layout superseded by DEC-033-6 (the character page's notes use the list layout; reorder and the page's own `DndContext` stand)
- **Stage:** 003.assistant · **Feature:** 018.character-page · **Step:** 005
- **Plan-local:** 018 D8; 005.context grid without a stylesheet, rect strategy
- **Date:** 2026-10-03 · **Decided by:** planner
- **Question:** How are the character's notes laid out and reordered?
- **Decision:**
  - **Layout.** The level group gains a grid layout prop. The grid is inline (`repeat(auto-fill, minmax(…, 1fr))`) on the same list element, with no stylesheet.
  - **Strategy.** Grid uses dnd-kit's rect sorting strategy; list keeps the vertical one.
  - **Context.** The page has its own `DndContext`. Sensors and announcements are shared with the note wall through `memoDnd.ts`.
- **Reason:** The page has room for a grid, and the wall stays unchanged.
- **Lands in:** `frontend/src/app/MemoLevelGroup.tsx`, `frontend/src/app/memoDnd.ts`, `frontend/src/app/CharacterNotesSection.tsx`, `frontend/src/app/MemoChainSection.tsx`.
- **Cites:** DEC-016-8.

### DEC-018-9 — Character configuration block
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 018.character-page · **Step:** 006, 007
- **Plan-local:** 018 D9; user decision 5; 006.context client-side lines; 007.context select keys, Textarea prompt
- **Date:** 2026-10-03 · **Decided by:** user (mechanics: planner)
- **Question:** How is a character's configuration edited?
- **Decision:**
  - **Shape.** A flat configuration with a per-key save.
  - **Model.** The "First enabled model" choice means null. Select keys are opaque and owned by the component; they are never parsed as ids. A 409 re-reads the models.
  - **Resolved lines.** Computed client-side from null versus non-null. The character level's only inherited source is the default.
  - **Prompt.** A plain `Textarea`, not the markdown editor.
  - This closes DEC-017-20.
- **Reason:** No extra request is needed. The prompt is plain text.
- **Rejected:** reading the session-level `Setting` shape for the character block.
- **Lands in:** `frontend/src/app/configurationApi.ts`, `frontend/src/app/characterConfigState.ts`, `frontend/src/app/CharacterConfigSection.tsx`.
