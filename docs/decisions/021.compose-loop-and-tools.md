### DEC-021-1 — The route commits the text, then streams
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 021.compose-loop-and-tools · **Step:** 004
- **Plan-local:** 021 D1
- **Date:** 2026-10-04 · **Decided by:** planner
- **Question:** When is the roleplayer's text stored relative to the stream?
- **Decision:** A synchronous begin step stores the text in its own transaction and returns the committed row; the stream starts after it, and `accepted` carries that row's id.
- **Reason:** The text survives whatever happens to the stream (R10).
- **Lands in:** `backend/app/services/compose.py`, `backend/app/routers/stream.py`
- **Cites:** `session-stream.md` § The compose route and the streaming harness

### DEC-021-2 — A textless compose is the retry
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 021.compose-loop-and-tools · **Step:** 004
- **Plan-local:** 021 D2, U1
- **Date:** 2026-10-04 · **Decided by:** user
- **Question:** How does the roleplayer re-ask the model without re-sending text?
- **Decision:** A compose with no text stores nothing and sends no `accepted`; it answers 409 `zone_empty` when the zone has no non-tool row. A blank (whitespace-only) text is 422. The model designation is re-read at use, so a retry picks up a newly designated model.
- **Reason:** The server already holds the conversation; a retry needs no text.
- **Lands in:** `backend/app/services/compose.py`
- **Cites:** `session-stream.md` § The compose route and the streaming harness

### DEC-021-3 — Model resolution happens inside the source, after `accepted`
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 021.compose-loop-and-tools · **Step:** 004
- **Plan-local:** 021 D3
- **Date:** 2026-10-04 · **Decided by:** planner
- **Question:** Is a missing or unreachable model an HTTP error or a stream error?
- **Decision:** The model is resolved inside the stream source, after `accepted`, so its failures arrive as `error` frames with the text already stored.
- **Reason:** One failure channel for everything after the commit; the client never has to reconcile an HTTP error with a stored text.
- **Lands in:** `backend/app/services/compose.py`

### DEC-021-4 — The think convention and the strip rule
- **Status:** accepted; superseded in part (the stream-wrapping half) by `llm-and-streaming.md` § Thinking — a text convention, not a frame
- **Stage:** 003.assistant · **Feature:** 021.compose-loop-and-tools · **Step:** 002
- **Plan-local:** 021 D4, U2
- **Date:** 2026-10-04 · **Decided by:** user (convention); planner (rule)
- **Question:** How is model reasoning carried in a stored assistant row, and how is it removed where only the answer may be used?
- **Decision:** Reasoning is stored inline in the assistant row's text between `<think>` and `</think>`. The tags are exactly these, lowercase and case-sensitive, defined once in `services/llm/chat.py`. The strip rule:
  - a block runs from `<think>` to the nearest following `</think>`;
  - an unterminated `<think>` runs to the end of the text;
  - blocks are removed left to right;
  - the result is trimmed only if at least one block was removed; otherwise the text is returned byte-identical;
  - a stray `</think>` with no opener is kept as text.
  Applied at settle (to the assistant head, before the `(( ))` classification) and in context assembly (to zone assistant rows). User rows are never stripped, and settled rows are not stripped in context (they were stripped at settle). DEC-023-10 adds a third site (translation input).

  Worked examples (binding; the strip tests use these rows):

  | # | Input | Output |
  |---|---|---|
  | 1 | `<think>plan</think>\n\nHello` | `Hello` |
  | 2 | `Hello` | `Hello` |
  | 3 | `  Hello  ` | `  Hello  ` (unchanged — no block removed) |
  | 4 | `<think>a</think>One<think>b</think> two` | `One two` |
  | 5 | `Start<think>never closed` | `Start` |
  | 6 | `<think>only</think>` | `` (empty) |
  | 7 | `a </think> b` | `a </think> b` (unchanged) |
  | 8 | `<think>x\ny</think>\n((ooc))` | `((ooc))` |
- **Reason:** One stored text keeps the discussion view able to show reasoning (022) while the record and the model's history see only the answer. Trimming only after a removal keeps an untouched row byte-identical.
- **Superseded in part by:** `llm-and-streaming.md` § Thinking — a text convention, not a frame — the half where RPHelper wrapped the provider's separate reasoning stream in tags; the library now delivers reasoning inline as `<think>` text. The strip rule and the sites hold.
- **Lands in:** `backend/app/services/llm/chat.py`, `backend/app/services/settle.py`, `backend/app/services/context.py`
- **Cites:** `llm-and-streaming.md` § Thinking — a text convention, not a frame

### DEC-021-6 — The tool seam and its failure literals
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 021.compose-loop-and-tools · **Step:** 003
- **Plan-local:** 021 D6
- **Date:** 2026-10-04 · **Decided by:** planner
- **Question:** What is a tool to the loop, and what does a failure look like?
- **Decision:** A tool is a name, a definition and a `run` taking a scope (user, session) and the arguments, returning an outcome. Any `Exception` from `run` is a failure; cancellation propagates. Literals: the model is told "The tool failed. Continue without its result."; the tool row's summary is "The tool failed."; the code is `tool_failed`.
- **Reason:** A failing tool must not end the reply; the model continues without the result.
- **Lands in:** `backend/app/services/tools/`
- **Cites:** `llm-and-streaming.md` § The tool-calling loop

### DEC-021-7 — Tool rows: written when the outcome is known, failure swallowed
- **Status:** accepted; superseded in part by DEC-arch-llm-client-library-5 (arguments) and DEC-022-3 (wire fields)
- **Stage:** 003.assistant · **Feature:** 021.compose-loop-and-tools · **Step:** 003
- **Plan-local:** 021 D7
- **Date:** 2026-10-04 · **Decided by:** planner
- **Question:** When is a tool row written, what does it hold, and what if the write fails?
- **Decision:** The row is written after the outcome is known and before dispatch returns. `tool_name` is stored as given. The payload JSON is `{call_id, arguments, status, content | code}`. A failed write is logged (session id, tool name, exception class) and swallowed.
- **Reason:** A bookkeeping failure must not fail the reply.
- **Superseded in part by:** DEC-arch-llm-client-library-5 — arguments are no longer the provider's raw string; DEC-022-3 — the "tool fields are not on the wire" half (022 exposes derived fields).
- **Lands in:** `backend/app/services/tools/`, `backend/app/services/messages.py`
- **Cites:** `session-stream.md` § The tool seam and dispatch

### DEC-021-9 — Tool rows are replayed one pair per row
- **Status:** accepted; supersedes DEC-020-3
- **Stage:** 003.assistant · **Feature:** 021.compose-loop-and-tools · **Step:** 003
- **Plan-local:** 021 D9
- **Date:** 2026-10-04 · **Decided by:** planner
- **Question:** How are stored tool rows sent back to the model?
- **Decision:** Each tool row replays as one call/result pair, not grouped into rounds (no round is stored). A non-ok row replays the failure literal of DEC-021-6. An ok row without string content, or any row that cannot be replayed, is skipped.
- **Reason:** No stored notion of a round exists, and a per-row pair is always well formed.
- **Supersedes:** DEC-020-3
- **Lands in:** `backend/app/services/llm/chat.py`
- **Cites:** `llm-and-streaming.md` § Tool rows are replayed, not skipped

### DEC-021-15 — Service-import exceptions for compose
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 021.compose-loop-and-tools · **Step:** 004
- **Plan-local:** 021 D15
- **Date:** 2026-10-04 · **Decided by:** planner
- **Question:** May the compose and settle services import other services?
- **Decision:** Compose may import the services it orchestrates (context, messages, tools, registry); settle may import the strip function only from `services/llm/chat.py`. Each exception is named in its import guard, never a prefix.
- **Reason:** Compose is an orchestrator by nature; named exceptions keep every other cross-service import an offender.
- **Lands in:** `backend/app/services/compose.py`, `backend/app/services/settle.py`
- **Cites:** `backend-structure.md` § Layout
