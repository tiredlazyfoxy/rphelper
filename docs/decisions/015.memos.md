# Decisions — 015.memos

**Stage:** 002.record · **Feature:** 015.memos

Notes (memos) at four scopes. This feature covers their storage, the chain read for a session, and the shared editing group used on the session screen and on the character page. The contracts are in `data-model.md`, `backend-structure.md` and `forms-and-lists.md`. These entries record the choices beneath them.

### DEC-015-1 — Where notes are edited
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 015.memos · **Step:** —
- **Plan-local:** 015 D1
- **Date:** 2026-10-02 · **Decided by:** user
- **Question:** Where does the user edit notes?
- **Decision:** On the session screen, notes are edited in the chain. The character page has its own Notes section. Both use one shared level group (`MemoLevelGroup` / `MemoLevelState`).
- **Reason:** Notes are edited where they are read, with a single implementation behind both screens.
- **Lands in:** `frontend/src/app/MemoLevelGroup.tsx`, `frontend/src/app/memoLevelState.ts`.

### DEC-015-2 — Blank is never a stored state; clearing deletes
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 015.memos · **Step:** —
- **Plan-local:** 015 D2
- **Date:** 2026-10-02 · **Decided by:** user
- **Question:** What happens to a blank note?
- **Decision:** A blank new note is dropped and no request is sent. Clearing a saved note DELETEs it, with no confirm step. Blank is never stored. The R6 contrast holds.
- **Reason:** An empty note has no meaning in a prompt.
- **Cites:** `data-model.md` memos.

### DEC-015-5 — Save on focus leave; apply a row only if not older
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 015.memos · **Step:** 006, 007
- **Plan-local:** 015 D5; 006.context draft retention, failure slots, allSettled flush; 007.context flush effect, focus leave
- **Date:** 2026-10-02 · **Decided by:** orchestrator
- **Question:** When is a note saved, and how do overlapping responses merge?
- **Decision:**
  - **Saving.**
    - A note saves on focus leave, if it changed.
    - Focus leave means `relatedTarget` is null or outside `currentTarget` (DEC-F012-1).
    - Mutations take no signal and are never aborted.
  - **Merging.**
    - A returned row is applied only if `returned.updated_at >= held.updated_at`. This is a string compare, valid because the timestamps are fixed-width.
    - Text typed during the request is kept as a held edit.
    - For a new note, the held edit moves onto the saved row.
  - **Failures.** Each note has one failure slot, and the new note has one more. There is no level-wide failure besides the load status.
  - **Flush on unmount.**
    - Unmount saves changed notes and a non-blank new note.
    - The flush starts all saves at once with `Promise.allSettled` and never rejects.
    - It runs from an empty-deps effect cleanup on the state captured at mount, so it is StrictMode-safe.
- **Reason:** Blur alone is unreliable when an element leaves the DOM. The not-older rule stops a late response from overwriting newer typing.
- **Lands in:** `frontend/src/app/memoLevelState.ts`, `frontend/src/app/MemoLevelGroup.tsx`.

### DEC-015-10 — Memos table shape
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 015.memos · **Step:** —
- **Plan-local:** 015 D10
- **Date:** 2026-10-02 · **Decided by:** planner
- **Question:** How is the memos table declared?
- **Decision:**
  - **Columns.** Ten columns. There is no title, `archived_at` or state column.
  - **Scope.** A non-native SQLAlchemy Enum, CHECK name `memos_scope`, length 16. Its four values are written in both `schema.py` and `models/memos.py`, and a test pins that they are equal.
  - **Scope id.** `scope_id` has no FK.
  - **Index.** A composite, non-unique index `ix_memos_user_id_scope_scope_id_sort_key` on (user_id, scope, scope_id, sort_key).
- **Reason:** With a CHECK, a stray scope value is refused at write time.
- **Rejected:** plain Text for scope: a stray value would make a note that no chain query ever finds.
- **Lands in:** `backend/app/db/schema.py`, `backend/app/models/memos.py`.
- **Cites:** `data-model.md` memos.

### DEC-015-12 — Not-found error and check order
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 015.memos · **Step:** —
- **Plan-local:** 015 D12
- **Date:** 2026-10-02 · **Decided by:** planner
- **Question:** What does a missing note answer, and in what order are checks made?
- **Decision:** `MemoNotFoundError` answers `memo_not_found` with 404 and an empty detail. A missing target reuses that level's own not-found code. The order on create is: target check, then sort-key allocation, then id mint.
- **Reason:** No id is minted for a write that will be refused.
- **Lands in:** `backend/app/errors.py`, `backend/app/services/memos.py`.

### DEC-015-15 — Body validation
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 015.memos · **Step:** 001
- **Plan-local:** 015 D15; 001.context after-validator, None→int() gotcha
- **Date:** 2026-10-02 · **Decided by:** planner
- **Question:** How is a note body validated?
- **Decision:** The body is stored verbatim. A blank body answers 422. There is no maximum length. The client's blank test is JS trim. On the server, an after-validator rejects a blank body without stripping it. The optional scope id converts `None` explicitly; it must not reach `int()`.
- **Reason:** A note's whitespace is the user's.
- **Rejected:** the setups' stripped-text alias, which would store the stripped value.
- **Lands in:** `backend/app/models/memos.py`.

### DEC-015-16 — Separate level and chain states per mount
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 015.memos · **Step:** 008, 009
- **Plan-local:** 015 D16; 008.context level states from chain, title map, heading order; 009.context two controllers, retry aborts
- **Date:** 2026-10-03 · **Decided by:** planner
- **Question:** How are chain and level states structured?
- **Decision:**
  - **States.** `MemoLevelState` and `MemoChainState` are separate, one per mount.
  - **Building.** Level states are built verbatim from the chain response. Scope titles come from a private scope→title map.
  - **Headings.** Each level of nesting is one heading order lower.
  - **Loads.** The two loads use two AbortControllers held in a ref. A retry aborts the previous one.
- **Reason:** Each mount owns its data. A stale load must not write after a retry.
- **Lands in:** `frontend/src/app/memoLevelState.ts` and the chain state, `frontend/src/app/MemoChainSection.tsx`, `frontend/src/app/CharacterNotesSection.tsx`.

### DEC-015-17 — Scope id on the wire
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 015.memos · **Step:** 001, 004, 005
- **Plan-local:** 001.context OptionalScopeIdIn; 004.context scope_id rules, PATCH forwarding, DELETE 204; 005.context createMemo body, query-string order
- **Date:** 2026-10-02 · **Decided by:** planner
- **Question:** How are scope ids validated and sent?
- **Decision:**
  - **Validation.** A local `OptionalScopeIdIn` form validates the optional scope id.
  - **Missing scope id.** For a non-user scope it answers a handler 422, with no domain code.
  - **User scope.** A supplied `scope_id` is dropped.
  - **PATCH.** Only fields that are set and non-null are forwarded.
  - **DELETE.** Answers 204 with an empty response.
  - **Client.** `createMemo` always sends `scope_id`, null for the user scope. Query strings use a fixed order: scope, then scope_id.
- **Reason:** These are wire details that follow from the four-scope model.
- **Rejected:** reusing the sessions' optional-id alias, whose error message names a setup.
- **Lands in:** `backend/app/models/memos.py`, `backend/app/routers/memos.py`, the memos API module under `frontend/src/app/`.

### DEC-015-18 — Memo service queries
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 015.memos · **Step:** 002, 003
- **Plan-local:** 002.context operations, explicit flags, rowcount, log redaction; 003.context single chain query, setup OR-term
- **Date:** 2026-10-02 · **Decided by:** planner
- **Question:** How do the memo service and the chain read query?
- **Decision:**
  - **Insert.** Flags are written explicitly.
  - **Delete.** A rowcount of 0 means not found.
  - **Blank bodies.** The service has no defensive blank check, because the request model owns it.
  - **Logs.** Logs carry ids, scope and counts only.
  - **Chain read.** One memo query. The setup OR-term is added only when the session has a setup. Python buckets the rows by scope; owner filtering stays in SQL. The setup row is not ownership-checked.
- **Reason:** One query keeps the chain read cheap. The session's own ownership already scopes it.
- **Rejected:** a NULL sentinel for the setup term; a second query.
- **Lands in:** `backend/app/services/memos.py`, `backend/app/services/memo_chain.py`.
- **Cites:** `domain-rules.md` logging.
