# Decisions — 016.note-wall

**Stage:** 002.record · **Feature:** 016.note-wall

This feature covers the session screen's note wall and the reordering of notes: the pin, open and dismiss behaviour, drag-and-drop, and the reorder route. The layout is described in `workspace-shell.md`, and the route and the sort-key rules in `data-model.md`. Plan-local ids U1–U3 are user decisions and O1–O8 orchestrator decisions; each entry names the ones it records.

### DEC-016-1 — The wall lives in the session screen
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 016.note-wall · **Step:** —
- **Plan-local:** 016 D1; O1
- **Date:** 2026-10-03 · **Decided by:** orchestrator
- **Question:** Which component owns the note wall?
- **Decision:** SessionScreen's ready render, laid out as a grid with the stream column and the wall. The root clips, and the stream scrolls itself.
- **Reason:** Only the session screen knows that a session is open, and it is the one place that applies US-095.
- **Rejected:** hoisting it into the shell, which would need a session-open signal passed up and a second place deciding US-095.
- **Lands in:** `frontend/src/app/SessionScreen.tsx`.
- **Cites:** `workspace-shell.md` note wall.

### DEC-016-2 — Pinned is persisted, open is not
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 016.note-wall · **Step:** —
- **Plan-local:** 016 D2; O2
- **Date:** 2026-10-03 · **Decided by:** orchestrator
- **Question:** Which wall state is stored, and what do pin, unpin and dismiss do?
- **Decision:**
  - **State.** `NoteWallState.pinned` is seeded from the stored `wallPinned`. Open is never persisted, and narrow width is read with `useMediaQuery`, not stored. Opening the wall never writes the record.
  - **Pin and unpin.** The pin toggle writes the record. Unpinning leaves the wall open as a floating flyout.
  - **Dismiss.** Dismiss unpins and writes only when the wall is effectively pinned, meaning pinned and not narrow. At narrow width it only closes.
  - **Storage.** It is a required prop, which re-freezes 011's screen and route props.
- **Reason:** Pinning is a preference, while open is momentary. At narrow width a dismiss must not silently change the wide-screen preference.
- **Lands in:** `frontend/src/app/SessionScreen.tsx` and its wall state.

### DEC-016-5 — New notes are prepended
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 016.note-wall · **Step:** —
- **Plan-local:** 016 D5; U3
- **Date:** 2026-10-03 · **Decided by:** user
- **Question:** Where does a new note go in its level?
- **Decision:** At the top. The sort key is allocated as `COALESCE(MIN(sort_key), 1) - 1`, which is signed, and the client prepends the new note.
- **Reason:** The newest note is the one being worked on.
- **Supersedes:** DEC-015-4 (015 D4).
- **Lands in:** `backend/app/services/memos.py`, `frontend/src/app/memoLevelState.ts`.
- **Cites:** `data-model.md` memos sort key.

### DEC-016-6 — Reorder operation
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 016.note-wall · **Step:** 001
- **Plan-local:** 016 D6; O5; 001.context set check, no unique index
- **Date:** 2026-10-03 · **Decided by:** orchestrator
- **Question:** How does the server apply a new order?
- **Decision:**
  - **Steps.** `reorder_memos` runs in one transaction:
    1. target check;
    2. owner-scoped read of the level's set;
    3. a Python set and duplicate check;
    4. a per-id `UPDATE sort_key = index`, without `updated_at`;
    5. an ordered re-read.
  - **Mismatch.** A set mismatch raises `MemoOrderMismatchError`: `memo_order_mismatch`, 409, with an empty detail that never lists ids.
  - **Route.** `PUT /api/memos/order` is declared before the `{memo_id}` handlers.
  - **Index.** There is no unique index on sort key, because the rewrite passes through duplicate values.
- **Reason:** Order is arrangement, not content. Bumping `updated_at` would make in-flight write responses look older under the not-older apply rule (DEC-015-5). 409 fits a request that is well-formed but conflicts with the current set.
- **Rejected:** 422 for a mismatch; bumping `updated_at`; a unique sort-key index.
- **Lands in:** `backend/app/services/memos.py`, `backend/app/routers/memos.py`, `backend/app/errors.py`.
- **Cites:** `data-model.md` memos.

### DEC-016-7 — Optimistic reorder with revert
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 016.note-wall · **Step:** 002
- **Plan-local:** 016 D7; U1; 002.context merge rules
- **Date:** 2026-10-03 · **Decided by:** user (merge rules: planner)
- **Question:** How does the client apply a drop?
- **Decision:**
  - **Apply.** Optimistically, writing array positions only.
  - **While in flight.** Drags are disabled. A failure reverts and shows "Could not reorder the notes." inline. A 409 is not refetched. There is no refetch and no signal. The reorder failure belongs to the whole level.
  - **On success.** The response gives the order. For each row, the newer by `updated_at` wins. Held ids missing from the response go first, and returned ids that are not held are dropped.
  - **On revert.** The order before the drop is restored, and unknown ids go first.
- **Reason:** A drag must feel immediate. These merge rules keep edits made during the request.
- **Lands in:** `frontend/src/app/memoLevelState.ts`.

### DEC-016-8 — Drag-and-drop with dnd-kit
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 016.note-wall · **Step:** 003, 004
- **Plan-local:** 016 D8; O6; U2; 003.context two shells one body; 004.context level key
- **Date:** 2026-10-03 · **Decided by:** orchestrator (library and selection tension: user)
- **Question:** How is note dragging built and made accessible?
- **Decision:**
  - **Library.** `@dnd-kit/core` ^6.3.1, `@dnd-kit/sortable` ^10.0.0 and `@dnd-kit/utilities` ^3.2.2.
  - **Structure.**
    - One `DndContext` covers the chain, with a `SortableContext` per level using the vertical list strategy.
    - The level key is the scope, and ids are passed through `String()`.
    - Reordering is opt-in through a `reorderable` prop, false by default.
  - **Drop decision.** A pure function (`memoReorder.ts`) refuses a drop with no target, a cross-level drop, a same-id drop and an unknown id.
  - **Sensors.** `PointerSensor` with a distance of 6px, and `KeyboardSensor` with `sortableKeyboardCoordinates`.
  - **Card.**
    - The whole card is the drag surface, with `tabIndex` 0.
    - It keeps role `listitem`, overriding dnd-kit's `role=button`, and is named "Note n of total".
    - Keydown is forwarded only when `target === currentTarget`.
  - **Not draggable.** A card whose editor has focus (a component-local flag), any card in a level with a reorder in flight, and the new note.
  - **Components.** Two thin shells share one card body, so hooks are never conditional.
  - **Accepted limits.**
    - A drag on the card can collide with text selection; the user accepted this as built.
    - jsdom cannot test real drags.
    - Announcements give positions and never ids.
- **Reason:** dnd-kit supports keyboard dragging and screen-reader announcements.
- **Lands in:** `frontend/src/app/MemoLevelGroup.tsx`, `frontend/src/app/MemoChainSection.tsx`, `frontend/src/app/memoReorder.ts`, `frontend/package.json`.
- **Cites:** `ui-conventions.md`; `frontend-structure.md`.

### DEC-016-11 — Wall layout in shell.css; narrow revert in TS
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 016.note-wall · **Step:** —
- **Plan-local:** 016 D11; O1
- **Date:** 2026-10-03 · **Decided by:** orchestrator
- **Question:** How is the wall styled and animated?
- **Decision:**
  - **Selectors.** Six `shell.css` selectors: `.app-session`, `.app-session.wall-pinned`, `.app-stream`, `.app-wall`, `.app-wall.wall-open` and `.app-session.wall-pinned .app-wall`.
  - **Shadow and background.** Mantine `Paper` supplies them. Shadow `md` applies only while the wall is floating and visible.
  - **Narrow width.** The revert is decided in TypeScript.
  - **Motion.** A transform transition of about 150–200 ms.
  - `.app-main` is unchanged.
- **Reason:** CSS cannot express "pinned at narrow width shows only when opened".
- **Rejected:** a CSS media query for the narrow revert.
- **Lands in:** `frontend/src/shell.css`, `frontend/src/app/SessionScreen.tsx`.
- **Cites:** `workspace-shell.md` layout.
