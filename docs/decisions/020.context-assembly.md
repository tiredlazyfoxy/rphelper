# Decisions — 020.context-assembly
**Stage:** 003.assistant · **Feature:** 020.context-assembly

Decisions for the feature that assembles the compose prompt: the context renderer, the
history mapper and the assembly read. Delivered 2026-10-04; landed here at the
finalization of 2026-11-09. The `Plan-local:` line on each entry names the feature's own
id (U-ids are the user's answers, the rest the orchestrator's), so citations such as
"020 D3" resolve here. The prompt layout itself lives in `llm-and-streaming.md`
§ Context assembly; entries that architecture already carries are short anchors.

### DEC-020-1 — Settled history is tagged by kind, the tag followed by a line feed
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 020.context-assembly · **Step:** 001
- **Plan-local:** 020 D1, U1; 020 step 001 context "The mapper decides tagged from kind"
- **Date:** 2026-10-04 · **Decided by:** user
- **Question:** How does the model tell a partner turn from the roleplayer's own turn, when both are stored with role `user`?
- **Decision:** Each settled history message is prefixed with its kind tag — `[partner]`, `[my turn]` or `[decision]` — then a LINE FEED, then the stored text. Zone rows are untagged. The stored role is kept as the message role. The mapper decides "tagged" from the row's kind, not from which input list the row came in (a settled row always has a kind, a zone row never does, so the two agree).
- **Reason:** Partner and own turn are both role `user`, so without a tag the model cannot tell whose words they are. A line feed rather than a space keeps a multi-paragraph first line intact.
- **Lands in:** `backend/app/services/llm/chat.py`
- **Cites:** `llm-and-streaming.md` § Context assembly

### DEC-020-2 — Six system sections; no setup description, character name or tool descriptions
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 020.context-assembly · **Step:** 001
- **Plan-local:** 020 D2, U2
- **Date:** 2026-10-04 · **Decided by:** user (orchestrator for the section literals)
- **Question:** What does the system message contain?
- **Decision:** Six sections in fixed order, headed `=== System prompt ===` through `=== Double parentheses ===`, with level headings of the form `--- User notes ---` and `[note]` bullets, as `llm-and-streaming.md` lays out. The setup description, the character name and the tool descriptions are not included.
- **Reason:** The persona sheet and the forced notes already carry the context; tool descriptions travel with the tool definitions, not the prompt.
- **Lands in:** `backend/app/services/llm/chat.py`
- **Cites:** `llm-and-streaming.md` § Context assembly

### DEC-020-4 — A missing language names English; the two languages fall back independently
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 020.context-assembly · **Step:** 001
- **Plan-local:** 020 D4, U4
- **Date:** 2026-10-04 · **Decided by:** user
- **Question:** What does the language instruction say when the session's roleplay language or the user's preferred language is null?
- **Decision:** A null language names English. The roleplay language and the preferred language fall back independently of each other.
- **Reason:** One default the model always understands; tying the two together would override a language the user did set.
- **Lands in:** `backend/app/services/llm/chat.py`
- **Cites:** `llm-and-streaming.md` § Context assembly; US-142

### DEC-020-5 — Empty parts are omitted; instruction sections are always present
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 020.context-assembly · **Step:** 001
- **Plan-local:** 020 D5
- **Date:** 2026-10-04 · **Decided by:** orchestrator
- **Question:** What happens to a section with nothing in it?
- **Decision:** An empty note level or system prompt is omitted, and a whitespace-only sheet is omitted. The instruction sections (language, double parentheses) are always present.
- **Reason:** Empty headings waste tokens and suggest missing data; the instructions apply whatever the content.
- **Lands in:** `backend/app/services/llm/chat.py`
- **Cites:** `llm-and-streaming.md` § Context assembly

### DEC-020-6 — Forced-note selection reuses the chain; the renderer does not sort
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 020.context-assembly · **Step:** 001, 002
- **Plan-local:** 020 D6; 020 step 001 context "The renderer does not sort levels"
- **Date:** 2026-10-04 · **Decided by:** orchestrator
- **Question:** How are the forced notes and their level order chosen?
- **Decision:** Selection is the memo chain resolver plus `memo_reach == "forced"`; no hand-written conjunction of scopes. The renderer renders levels in the order it is given; the chain supplies that order.
- **Reason:** One definition of which notes reach a session, shared with the note screens; ordering in one place.
- **Lands in:** `backend/app/services/context.py`, `backend/app/services/llm/chat.py`
- **Cites:** `llm-and-streaming.md` § Context assembly; `domain-rules.md` (memo reach)

### DEC-020-7 — History is the settled entries and the zone merged by id
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 020.context-assembly · **Step:** 002
- **Plan-local:** 020 D7
- **Date:** 2026-10-04 · **Decided by:** orchestrator
- **Question:** In what order do settled entries and zone rows reach the model?
- **Decision:** The two reads are merged and ordered by id, not concatenated.
- **Reason:** Settled entries and zone rows can interleave (a partner block filed after zone rows were written).
- **Lands in:** `backend/app/services/context.py`
- **Cites:** `llm-and-streaming.md` § Context assembly

### DEC-020-8 — The session is read first; only three of its fields are used
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 020.context-assembly · **Step:** 002
- **Plan-local:** 020 D8
- **Date:** 2026-10-04 · **Decided by:** orchestrator
- **Question:** In what order does assembly read, and what does it take from the session?
- **Decision:** The session is read first, so an unknown or foreign session raises session-not-found before anything else. Only the system prompt, roleplay language and preferred language are used from it; the sheet is read through the session's character. Archived sessions assemble normally.
- **Reason:** One refusal point; archiving is not a compose barrier (R6).
- **Lands in:** `backend/app/services/context.py`
- **Cites:** `domain-rules.md` R6

### DEC-020-9 — Placement: a neutral renderer and a service with an import exception
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 020.context-assembly · **Step:** 001, 002
- **Plan-local:** 020 D9
- **Date:** 2026-10-04 · **Decided by:** orchestrator
- **Question:** Where do rendering and reading live, given that services do not import each other?
- **Decision:** Rendering and mapping live in `services/llm/chat.py`, which imports no service. The assembly read lives in `services/context.py`, which is allowed to import other services because it opens no transaction of its own.
- **Reason:** The renderer stays pure and testable without a database; the read composes existing service reads rather than duplicating their queries.
- **Lands in:** `backend/app/services/llm/chat.py`, `backend/app/services/context.py`
- **Cites:** `backend-structure.md` § Layout

### DEC-020-10 — Fixed English prompt constants
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 020.context-assembly · **Step:** 001
- **Plan-local:** 020 D10
- **Date:** 2026-10-04 · **Decided by:** orchestrator
- **Question:** Are the prompt's headings and lead-ins configurable or localised?
- **Decision:** No. They are fixed English constants; tests bind to the section markers, not the full prose.
- **Reason:** The model reads them, not the user; English is the most reliable instruction language.

### DEC-020-11 — Assembly reads live with separate sub-reads
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 020.context-assembly · **Step:** 002
- **Plan-local:** 020 D11
- **Date:** 2026-10-04 · **Decided by:** orchestrator
- **Question:** Is the context a consistent snapshot?
- **Decision:** No snapshot: each part is its own read at compose time. A mixed view across a concurrent edit is accepted.
- **Reason:** One user, one session at a time; a snapshot transaction would buy nothing observable.
- **Lands in:** `backend/app/services/context.py`

### DEC-020-12 — No compaction or truncation of the context
- **Status:** accepted
- **Stage:** 003.assistant · **Feature:** 020.context-assembly · **Step:** —
- **Plan-local:** 020 D12
- **Date:** 2026-10-04 · **Decided by:** orchestrator
- **Question:** What happens when the context exceeds the model's window?
- **Decision:** Nothing is compacted or truncated by RPHelper; the whole context is sent.
- **Reason:** Retrieval tools are the deliberate answer to long history; a silent cut would hide context loss.
- **Lands in:** `backend/app/services/context.py`
- **Cites:** `llm-and-streaming.md` § Context assembly
