# Decisions — 014.entry-editing-and-copy-out

**Stage:** 002.record · **Feature:** 014.entry-editing-and-copy-out

Editing settled record entries, the enormous-paste warning, hover reveal of entry actions, and copy-out of a turn as plain text. DEC-014-9 is the authoritative home of the copy-out stripping rules. `workspace-shell.md` points here for them, and no other document restates them.

### DEC-014-1 — PATCH edits settled rows of every kind
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 014.entry-editing-and-copy-out · **Step:** —
- **Plan-local:** 014 D1
- **Date:** 2026-10-02 · **Decided by:** orchestrator
- **Question:** Which rows does the message PATCH accept now that settled entries are editable?
- **Decision:** Settled rows of all kinds, as well as zone rows. Buried rows still answer `message_not_editable`. The edit writes `text` and `updated_at` only, never kind, `settled_at` or `related_to`. The read-back goes through the settled-entries read for a settled row and through the current-zone read for a zone row. This replaces 012 D2 (DEC-012-2).
- **Reason:** The text is the only thing an edit may change. The record's structure is set by settle alone.
- **Supersedes:** DEC-012-2 (012 D2), in part — its buried-row refusal stands.
- **Lands in:** `backend/app/services/messages.py`, `backend/app/routers/stream.py`.
- **Cites:** `session-stream.md`; `domain-rules.md`.

### DEC-014-3 — Paste-cost estimate and threshold
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 014.entry-editing-and-copy-out · **Step:** —
- **Plan-local:** 014 D3
- **Date:** 2026-10-02 · **Decided by:** user
- **Question:** How is an "enormous" paste detected?
- **Decision:**
  - `CHARS_PER_TOKEN = 4` and `PASTE_WARNING_THRESHOLD_TOKENS = 32000`.
  - Estimate = `ceil(length / 4)`, counted in UTF-16 code units, with no trim.
  - The comparison is strictly greater: 128,000 characters gives no warning, 128,001 does.
  - The warning is advisory only.
- **Reason:** No tokenizer reaches the client. A cheap estimate is enough for a warning that never blocks.
- **Flip condition:** a real tokenizer reaches the client, or the threshold proves wrong in use.
- **Lands in:** `frontend/src/app/pasteCost.ts`.

### DEC-014-5 — Warn on composer pastes, synchronously, before any filing
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 014.entry-editing-and-copy-out · **Step:** 003
- **Plan-local:** 014 D5; 003.context paste-handler order
- **Date:** 2026-10-02 · **Decided by:** orchestrator
- **Question:** Which pastes warn, and in what order relative to partner filing?
- **Decision:** Composer pastes warn in both positions. The warning is synchronous and never blocks. Editor pastes don't warn. The handler order is:
  1. Read the text.
  2. If it is non-blank and enormous, warn (synchronously, not awaited).
  3. If the position is *partner*, prevent the default and file the paste.
- **Reason:** The warning must reach the user before the paste is filed, and it must never hold the paste back.
- **Lands in:** `frontend/src/app/ComposerCore.tsx`, `frontend/src/app/Composer.tsx`.

### DEC-014-6 — Entry actions revealed by opacity
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 014.entry-editing-and-copy-out · **Step:** —
- **Plan-local:** 014 D6
- **Date:** 2026-10-02 · **Decided by:** user (hooks: planner)
- **Question:** How are entry actions revealed on hover or focus?
- **Decision:** Reveal uses `useHover`, `useFocusWithin` and `useMergedRef`. `useMediaQuery("(hover: none)")` keeps actions revealed on touch. Hidden actions are styled with `opacity` and marked with `data-revealed`.
- **Reason:** Opacity keeps the controls in the tab order.
- **Rejected:** `display:none`, `visibility`, conditional rendering and `disabled`; each removes the control from keyboard reach.

### DEC-014-8 — A hand-written CommonMark-subset stripper
- **Status:** accepted

- **Plan-local:** 014 D8
- **Date:** 2026-10-02 · **Decided by:** orchestrator
- **Question:** How is a turn turned into plain text for the clipboard?
- **Decision:** A hand-written, pure stripper over a CommonMark subset, with no GFM. It reads the stored text, never the DOM. Bullets become "• ", and single line breaks are kept. ### DEC-014-9 — Copy-out stripping rules (authoritative)
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 014.entry-editing-and-copy-out · **Step:** 002
- **Plan-local:** 014 002.context stripping rules A1–A7, B1–B6, C1–C2, worked examples E1–E11, B1–B10, C1–C8, W1–W5, L1–L6
- **Date:** 2026-10-02 · **Decided by:** orchestrator
- **Question:** Exactly which syntax does copy-out remove, and what does it leave as typed?
- **Decision:** The rules below. The tests take every expected value from the examples, never from calling the module.

  **Notation.** In the examples, inputs and outputs are JSON string literals: `\n` is a line feed, `\r` a carriage return, `\\` one backslash, `\"` a double quote. "Spaces" means U+0020 and tab.

  **Stage A — lines**

  - **A1. Line endings.** Every `\r\n`, then every remaining `\r`, becomes `\n`. The text is split on `\n` into lines.
  - **A2. Fenced code.** A line whose content, after at most three leading spaces, begins with a run of three or more backticks or three or more `~` opens a fence (anything after the run — an info string — is ignored). The opener line is **dropped**. Following lines are **code lines**, kept exactly as they are (no other rule in A, B or C touches them), until a closer: a line that, after at most three leading spaces, is a run of the same character at least as long as the opener's run, followed only by spaces. The closer is dropped. With no closer the code runs to the end of the text.

  Every non-code line then goes through A3–A7 in order:

  - **A3. Blockquote markers.** Repeatedly remove a leading `>` (preceded by at most three spaces) and one space right after it if present.
  - **A4. Dropped lines.** The line is removed entirely (it does not leave a blank line) when it is:
    - a **thematic break** — after at most three spaces, three or more of the same character from `-`, `*`, `_`, optionally separated by spaces, and nothing else;
    - a **setext underline** — after at most three spaces, a run of `=` or a run of `-`, then only spaces — **and** the previous kept line is a non-blank, non-code line;
    - a **link reference definition** — after at most three spaces, `[label]:` followed by optional spaces and at least one non-space character.
  - **A5. ATX headings.** Remove a leading run of one to six `#` (after at most three spaces) that is followed by a space or ends the line, together with the spaces after it; then remove a trailing run of spaces followed by one or more `#` and optional spaces. `#hashtag` (no space) is not a heading.
  - **A6. Unordered list bullets.** A leading `-`, `*` or `+` (after any indentation) followed by at least one space is replaced by `• ` (U+2022 then one space); the indentation before it is kept. Ordered-list markers (`1.`, `2)`) are left as typed.
  - **A7. Line ends.** Remove trailing spaces. Then, if the line ends in a single `\` and the **next** line is a non-blank, non-code line, remove that `\` (a hard break). A backslash ending the last line, or followed by a blank line, stays.

  **Stage B — inline, per paragraph**

  A **paragraph** is a maximal run of consecutive non-blank, non-code lines after stage A, processed joined by `\n` (so inline spans may cross a single line break but never a blank line or a code line). In order:

  - **B1. Code spans.** A run of N backticks opens; the span closes at the next run of **exactly** N backticks. Both runs are removed; the content between is kept verbatim and is **protected** (B2–B6 never touch it). A run with no closing partner stays literal.
  - **B2. Backslash escapes.** `\` followed by an ASCII punctuation character becomes that character alone, **protected** (it never opens or closes anything in B3–B6). Any other backslash stays.
  - **B3. Images.** `![alt](destination)` and `![alt](destination "title")` become `alt`.
  - **B4. Links.** `[text](destination)` (with or without a title), `[text][label]` and `[text][]` become `text`. A bare `[text]` is left as typed.
  - **B5. Autolinks.** `<…>` whose inside has no whitespace, no `<` / `>`, and contains a `:` or an `@` becomes its inside without the angle brackets.
  - **B6. Emphasis.** Three passes, in order, with the delimiter strings `***` / `___`, then `**` / `__`, then `*` / `_`. In a pass, an **opener** is the delimiter string immediately followed by a non-whitespace character; its **closer** is the nearest following occurrence of the same string immediately preceded by a non-whitespace character, with at least one character between them. For `_` strings additionally the opener must not be immediately preceded by a letter or digit, and the closer must not be immediately followed by one. The opener and closer are removed, the content kept; scanning resumes after the closer. A delimiter with no partner stays literal. Protected characters (B1, B2) never count as delimiters.

  **Stage C — whitespace**

  - **C1.** Runs of two or more consecutive blank (empty) non-code lines collapse to one blank line.
  - **C2.** Blank lines at the start and the end of the result are removed. Lines are joined with `\n`; there is no trailing newline.

  **Unchanged guarantee.** A text with no syntax above, no `\r`, no trailing spaces on any line, no run of two or more blank lines and no leading or trailing blank line is returned byte-for-byte.

  **Not syntax — left as typed.** `~~strike~~`, table pipes, task boxes, bare URLs (all GFM, which the renderer does not load); raw HTML tags and entities (`&amp;`); indented code blocks (the indentation is kept as typed); ordered-list numbers; `(( ))` (R12 — not markdown, and a settled turn's fragments were stripped at settle).

  **Worked examples.** One example per line: `Id: input => output`, both as JSON string literals. `=> same` means the output equals the input byte-for-byte.

  Emphasis:

  ```
  E1:  "Some **bold** and *italic* text."         => "Some bold and italic text."
  E2:  "__strong__ and _em_"                      => "strong and em"
  E3:  "***both*** and ___both___"                => "both and both"
  E4:  "**bold *nested* end**"                    => "bold nested end"
  E5:  "*She smiles.*\n*He waits.*"               => "She smiles.\nHe waits."
  E6:  "*one\ntwo*"                               => "one\ntwo"
  E7:  "*one\n\ntwo*"                             => same   (a blank line ends the paragraph)
  E8:  "snake_case_name and 2 * 3 * 4"            => same
  E9:  "\\*not italic\\* and a \\\\ backslash"    => "*not italic* and a \\ backslash"
  E10: "*unclosed emphasis"                       => same
  E11: "un*frigging*believable"                   => "unfriggingbelievable"
  ```

  Blocks:

  ```
  B1:  "# Title\n\nBody text"                     => "Title\n\nBody text"
  B2:  "## Closed heading ##"                     => "Closed heading"
  B3:  "#hashtag stays"                           => same
  B4:  "Title\n=====\nBody"                       => "Title\nBody"
  B5:  "> quoted line\n> > nested"                => "quoted line\nnested"
  B6:  "> - quoted item"                          => "• quoted item"
  B7:  "- one\n- two\n  - nested\n* star\n+ plus" => "• one\n• two\n  • nested\n• star\n• plus"
  B8:  "1. first\n2) second"                      => same
  B9:  "Para one.\n\n***\n\nPara two."            => "Para one.\n\nPara two."
  B10: "# **Big** title\n- *item*"                => "Big title\n• item"
  ```

  Code and links:

  ```
  C1:  "Use `code` here"                            => "Use code here"
  C2:  "Run ``a`b`` now"                            => "Run a`b now"
  C3:  "```js\nconst *a* = 1;\n```\nAfter"          => "const *a* = 1;\nAfter"
  C4:  "~~~\n# not a heading\n~~~"                  => "# not a heading"
  C5:  "[the site](https://example.com \"Title\")"  => "the site"
  C6:  "![a map](map.png) here"                     => "a map here"
  C7:  "See <https://example.com> now"              => "See https://example.com now"
  C8:  "[text][ref]\n\n[ref]: https://example.com"  => "text"
  ```

  Whitespace:

  ```
  W1:  "Line one  \nLine two\\\nLine three"        => "Line one\nLine two\nLine three"
  W2:  "Crlf line\r\nnext\rlast"                    => "Crlf line\nnext\nlast"
  W3:  "\n\n  \nText  \n\n\n\nMore\n\n"             => "Text\n\nMore"
  W4:  ""                                           => ""
  W5:  "Line a\\"                                   => same   (a backslash ending the last line stays)
  ```

  Left as typed:

  ```
  L1:  "~~not strike~~ and | a | b |"               => same
  L2:  "She said ((quietly)) hello. ((ooc))"        => same
  L3:  "<b>raw</b> &amp; text"                      => same
  L4:  "Indented:\n\n    four spaces"               => same
  L5:  "A plain line.\n\nAnother, with (parens) and 3.5 * 2."  => same
  L6:  "First paragraph.\nSecond line.\n\nThird paragraph."    => same
  ```

- **Reason:** No markdown-to-text library is installed, and 014 adds no dependency. The renderer (`react-markdown`) has no plain-text output that would avoid serialising the DOM, which `workspace-shell.md` rules out. The rules are deliberately a subset: the record holds RP prose, not documents. Every case the subset does not cover is listed as left-as-typed rather than guessed.
- **Rejected:** a markdown-to-text library (a new dependency); serialising the rendered DOM.
- **Lands in:** `frontend/src/app/plainText.ts`.
- **Cites:** `workspace-shell.md` copy-out; DEC-014-8.

### DEC-014-10 — Clipboard write with an execCommand fallback
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 014.entry-editing-and-copy-out · **Step:** 004
- **Plan-local:** 014 D9; 004.context fallback mechanics
- **Date:** 2026-10-02 · **Decided by:** planner (flagged to user)
- **Question:** How is text written to the clipboard when the async Clipboard API is unavailable (no TLS)?
- **Decision:** `copyOut.ts` uses `navigator.clipboard.writeText` when it exists. Otherwise it falls back to `execCommand("copy")` through a readOnly, off-screen textarea. The textarea is removed and focus is restored in a `finally`. Failures go to `notifyFailure`; success raises nothing. Copy lives in its own module, because it reads and writes no state and touches `navigator` and `document`.
- **Reason:** `execCommand` is deprecated but universal, and it is used only where the modern API cannot exist (a plain-HTTP self-hosted origin).
- **Flip condition:** TLS lands everywhere, and the fallback becomes dead code.
- **Lands in:** `frontend/src/app/copyOut.ts`.
- **Cites:** `deployment.md`.

### DEC-014-11 — Settled entry editor
- **Status:** accepted; blank-commit case superseded in part by DEC-F014-10
- **Stage:** 002.record · **Feature:** 014.entry-editing-and-copy-out · **Step:** 005
- **Plan-local:** 014 D10; 005.context actions group, blur-ordering race
- **Date:** 2026-10-02 · **Decided by:** orchestrator
- **Question:** How is a settled entry edited, and how does its result merge?
- **Decision:**
  - **Editor.** "Edit entry" opens a plain Textarea "Edit entry text". These labels differ from the zone editor's. Blur commits.
  - **Commit.** An unchanged text sends nothing. A blank text now follows DEC-F014-10.
  - **Success.** The response replaces the one row. The id sequence is unchanged, so the kind override in DEC-013-8 is kept.
  - **Moved row.** If the response is not settled (it was re-opened in another tab), both lists are re-read.
  - **Failure.** `notifyFailure`, an entries re-read, and the editor stays open.
  - **While editing.** The Edit control is absent. Edits don't set `busy`.
  - **Actions group.** The entry header has one actions group: edit | copy (turns) | re-open (last entry).
  - **Accepted race.** Copy reads the stored text. That becomes the committed text only once the PATCH resolves.
- **Reason:** Mirrors the zone editor (DEC-013-10). The race is harmless: copy never shows a text that was not stored.
- **Lands in:** `frontend/src/app/SessionStream.tsx`, `frontend/src/app/streamState.ts`.
