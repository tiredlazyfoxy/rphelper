### DEC-009-3 — "Show archived" switch in the tree header, not persisted
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 009.characters · **Step:** 004, 008
- **Date:** 2026-10-02 · **Decided by:** user
- **Plan-local:** 009 D4
- **Question:** Where does the archived-characters toggle live, and does it persist?
- **Decision:**
  - Switch: a "Show archived" switch in the tree header. It lives in the workspace characters state for the page's lifetime and is never persisted.
  - Toggling: issues exactly one listing request. An effect keyed on `showArchived` loads, and the handler only flips the flag.
  - Archived rows: render dimmed, with an "Archived" badge.
  - The character page: an archived character's page opens by URL and shows Restore in place of Archive. There is no confirm.
- **Reason:** Restoring a filter on load would greet the roleplayer with a list that is not their working list. Loading from both the handler and the effect would send two requests.
- **Lands in:** `frontend/src/app/charactersState.ts`; `frontend/src/app/CharacterTree.tsx`
- **Cites:** `frontend-structure.md` § Routing inside the `app` entry (archive toggle)

### DEC-009-4 — The `characters` table as first declared
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 009.characters · **Step:** 001
- **Date:** 2026-10-02 · **Decided by:** user
- **Plan-local:** 009 D5
- **Question:** Which columns does 009 declare, and with which constraints?
- **Decision:**
  - Columns: seven of the doc's ten — `id`, `user_id` (FK `users.id`, NOT NULL, no `ON DELETE`), `name`, `sheet` (NOT NULL, no server default; the service writes `""`), `archived_at`, `created_at` and `updated_at`.
  - Deferred to 017: `model_ref`, `system_prompt` and `tools`.

- **Cites:** `data-model.md` § `characters`; DEC-007-1

### DEC-009-6 — PATCH semantics: null means absent, an empty PATCH is a no-op
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 009.characters · **Step:** 001, 002, 003
- **Date:** 2026-10-02 · **Decided by:** orchestrator
- **Plan-local:** 009 D7
- **Question:** How do archive, restore and edit appear on the wire, and what does a partial PATCH mean?
- **Decision:**
  - Archive and restore are named action routes. `PATCH` edits `name` and `sheet`.
  - An explicit `null` is treated as "not supplied".
  - A PATCH supplying neither field answers the unchanged character, writes nothing and does not bump `updated_at`.
  - Request models use `extra="ignore"`.
  - `name` uses `StringConstraints(strip_whitespace=True, min_length=1)`, the codebase's first use of it.
- **Reason:** This follows the earlier precedents: each state change hangs off its own route, and a PATCH means "the fields supplied".
- **Lands in:** `backend/app/models/characters.py`; `backend/app/services/characters.py`; `backend/app/routers/characters.py`
- **Cites:** `backend-structure.md` § request validation

### DEC-009-7 — One 404 for missing and foreign; stripped name; native 422
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 009.characters · **Step:** 001, 003
- **Date:** 2026-10-02 · **Decided by:** orchestrator
- **Plan-local:** 009 D8
- **Question:** How do not-found and validation failures look?
- **Decision:**
  - `character_not_found` (404, empty `detail`) answers both "no such id" and "another user's id".
  - `name` is stripped, then required non-empty, with FastAPI's native 422 on failure. `sheet` is never stripped.
  - Unknown body keys are ignored.
- **Reason:** It costs nothing (R5), because the owner predicate is in the same `WHERE` as the id. Markdown whitespace is significant.
- **Lands in:** `backend/app/errors.py`; `backend/app/models/characters.py`
- **Cites:** `backend-structure.md` § The error model; `domain-rules.md` R5

### DEC-009-8 — Archive semantics: idempotent, keeps the original `archived_at`
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 009.characters · **Step:** 002, 006
- **Date:** 2026-10-02 · **Decided by:** orchestrator
- **Plan-local:** 009 D9
- **Question:** What do repeated archive and restore calls do, and can an archived character be edited?
- **Decision:**
  - Archiving an archived character is a no-op that keeps the original `archived_at`. Restoring a working character is a no-op.
  - A no-op writes nothing. A state change bumps `updated_at`.
  - Editing an archived character is allowed and leaves `archived_at` alone.
  - On the screen, archive and restore replace the character state but not the draft.
- **Reason:** "When was this archived" stays true. No requirement forbids editing an archived character.
- **Lands in:** `backend/app/services/characters.py`; `frontend/src/app/characterScreenState.ts`
- **Cites:** `domain-rules.md` R6; `data-model.md` § … and the archive rule

### DEC-009-10 — One workspace characters state; apply the returned row
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 009.characters · **Step:** 004
- **Date:** 2026-10-02 · **Decided by:** orchestrator
- **Plan-local:** 009 D11
- **Question:** How do the tree and the character screen stay consistent after a mutation?
- **Decision:**
  - Ownership: `App` creates one `CharactersState` and passes it as props. No refetch follows a mutation.
  - The upsert rule:
    - A row already in the list is replaced in place.
    - A row archived while the switch is off is dropped.
    - A new row is inserted before the first row with a lower `created_at`, compared as fixed-width text. Equal timestamps insert after. The rule never compares by id.
- **Reason:** This is the never-optimistic rule in its narrowed form, and it avoids a refetch racing the mutation.
- **Lands in:** `frontend/src/app/charactersState.ts`
- **Cites:** `forms-and-lists.md` § narrowed re-load (apply-a-row rule); `frontend-structure.md` § State

### DEC-009-11 — Fixed failure sentences, no `notifyFailure`
- **Status:** accepted
- **Stage:** 002.record · **Feature:** 009.characters · **Step:** 006, 007, 008
- **Date:** 2026-10-02 · **Decided by:** planner
- **Plan-local:** 009 D12; 009 006.context (fixed text per action)
- **Question:** How do 009's failures render?
- **Decision:**
  - Each failure renders in place with a fixed sentence per action:
    - "Could not create the character.", "Could not save the character.", "Could not archive the character." and "Could not restore the character." render in an inline `Alert`.
    - "Could not load the character" and "Could not load characters" render with Retry.
    - A 404 renders "Character not found".
  - There is no `notifyFailure` call site and no success feedback.
- **Reason:** Every failure has a place of its own. A fixed text per action never leaks a server message.
- **Lands in:** `frontend/src/app/characterScreenState.ts`; `frontend/src/app/CharacterScreen.tsx`; `frontend/src/app/CharacterTree.tsx`
- **Cites:** `ui-conventions.md` § Async feedback
