# Decisions — 027.session-search-tool
**Stage:** 004.retrieval · **Feature:** 027.session-search-tool

Decisions for the assistant's `session_search` tool: its scope predicate, its cap,
what represents a session to the model, and the excerpt read. The feature was
delivered on 2026-10-05. The tool's contract is in `search-and-retrieval.md`
§ `session_search`; the port is `DEC-025-1`..`-14`; the adapter pattern mirrors
`DEC-026-3` and `DEC-026-4`.

### DEC-027-1 — The scope predicate: same character, not the current session, not archived
- **Status:** accepted
- **Stage:** 004.retrieval · **Feature:** 027.session-search-tool · **Step:** 001
- **Date:** 2026-10-05 · **Decided by:** user
- **Plan-local:** 027 D1
- **Question:** Which past sessions may the tool return?
- **Decision:** `past_session_predicate(character_id, current_session_id)` builds `character_id = :c AND id != :current AND archived_at IS NULL` over the port's base relation; the port ANDs `user_id`. The archive term is on the session only — a session whose setup is archived stays searchable. Restoring a session makes it findable again with no re-embed, because 024 keeps archived sessions' vectors current.
- **Reason:** The current session is already in context (the architecture's inference); archived sessions are excluded by the user's call.
- **Lands in:** `backend/app/services/search/session_search.py`
- **Cites:** `search-and-retrieval.md` § `session_search`; `domain-rules.md` R5
- **Note:** "By meaning" (a paraphrase finds the session) cannot be proven with the deterministic fake embedder; it is a `[manual/live]` check (step 003 DoD-16), still outstanding.

### DEC-027-2 — At most 5 hits, no paging
- **Status:** accepted
- **Stage:** 004.retrieval · **Feature:** 027.session-search-tool · **Step:** 001
- **Date:** 2026-10-05 · **Decided by:** user
- **Plan-local:** 027 D2
- **Question:** How many sessions does the tool return?
- **Decision:** `SESSION_SEARCH_LIMIT = 5`, passed to the port as `limit`. No paging, no count argument; the declaration stays `query` only.
- **Reason:** Each hit carries a long excerpt, so the cap is lower than `memo_search`'s 8 (`DEC-026-1`).
- **Lands in:** `backend/app/services/search/session_search.py`

### DEC-027-3 — What the model receives: a header line and a tail excerpt per session
- **Status:** accepted
- **Stage:** 004.retrieval · **Feature:** 027.session-search-tool · **Step:** 002, 003
- **Date:** 2026-10-05 · **Decided by:** user (header + tail shape); planner (date source, literals)
- **Plan-local:** 027 D3
- **Question:** The port returns ids only. What text represents a matched session?
- **Decision:**
  - One block per hit, in rank order: `### Session <YYYY-MM-DD> · setup: <setup name>` (or `### Session <YYYY-MM-DD> · no setup`), `\n`, then the body. Blocks joined by `\n\n`.
  - The date is `created_at` as a UTC calendar date (a naive stored value is taken as UTC). The separator is ` · ` (U+00B7). The setup name shows even when the setup is archived.
  - The body is the settled entries' text, ascending id, joined by `\n\n`, entries with empty text skipped. Longer than `SESSION_EXCERPT_CHARS = 1500` → `…` (U+2026, no following space) plus the last 1500 characters. A session with no settled entries has the body `(no settled entries)`.
  - No persona text, no setup description, no ids. Zero hits: `No matching sessions.`. Summary: exactly `<N> sessions`, never pluralised by rule, never content.
- **Reason:** `created_at` is when the roleplay happened; the tail is where the session left off.
- **Rejected:** `last_used_at` / `updated_at` for the date — both move on unrelated writes.
- **Lands in:** `backend/app/services/search/session_search.py`, `backend/app/services/tools/session_search.py`
- **Cites:** `search-and-retrieval.md` § `session_search` — What text represents a session

### DEC-027-4 — The excerpt read is the tool's own owner-scoped hydration
- **Status:** accepted
- **Stage:** 004.retrieval · **Feature:** 027.session-search-tool · **Step:** 002
- **Date:** 2026-10-05 · **Decided by:** planner
- **Plan-local:** 027 D4; step 002 Files Changed
- **Question:** How are the header fields and excerpt read for a list of hit ids?
- **Decision:** `list_session_excerpts(connection, user_id, session_ids)` returns one frozen `SessionExcerpt(session_id, created_date, setup_name, excerpt)` per found id, in the given id order; an id that is not the user's session is dropped silently. Empty input returns before any statement. Otherwise it issues two statements for any list length: the owner-scoped `sessions` ⟕ `setups` header select, then one `settled_entries` read for all found sessions ordered by `session_id, id`. Dates go through `fromisoformat`, naive as UTC. The bound and marker are applied here, so unbounded text never reaches the adapter. A local `_reading` (reproduced, not imported) ends the read.
- **Reason:** Defence in depth on ownership; a fixed statement count instead of one query per id.
- **Lands in:** `backend/app/services/search/session_search.py`
- **Note:** Accepted gap: no `[test]` pins the two-statement count; a regression to one query per id would go unnoticed.

### DEC-027-5 — A whitespace-only settled entry is joined as stored (open divergence from 024)
- **Status:** open
- **Stage:** 004.retrieval · **Feature:** 027.session-search-tool · **Step:** 002
- **Date:** 2026-10-05 · **Decided by:** coder (adjudicated: orchestrator)
- **Plan-local:** 027 step 002 Notes & Issues; 027 orchestrator notes on the verified result (whitespace-only row)
- **Question:** The step said "skip rows whose text is empty", while `DEC-027-3`'s source says "the same joining 024 uses", and 024 also drops whitespace-only parts (`strip()`). Which rule does the excerpt follow?
- **Decision:** As built, only `""` is skipped. A whitespace-only settled row is joined as stored, so a session whose only settled rows are whitespace renders a whitespace body instead of `(no settled entries)`. Accepted as an open divergence, not a 027 re-code; a strip-based rule is the better reading. Tracked as defect D-07.
- **Reason:** No DoD seeded a whitespace-only row, so the literal step rule satisfied the contract as written.
- **Lands in:** `backend/app/services/search/session_search.py`
- **Cites:** `DEC-027-3`

### DEC-027-6 — The tool raises; the seam reports
- **Status:** accepted
- **Stage:** 004.retrieval · **Feature:** 027.session-search-tool · **Step:** 003
- **Date:** 2026-10-05 · **Decided by:** planner
- **Plan-local:** 027 D5
- **Question:** How does a failure reach the assistant?
- **Decision:** As `DEC-026-6`: port errors propagate; a missing or non-string `query` raises `ToolFailedError(detail={"tool": "session_search"})`; no transaction left open on either path.
- **Reason:** One failure path, owned by the seam.
- **Lands in:** `backend/app/services/tools/session_search.py`
- **Cites:** `DEC-026-6`; `domain-rules.md` R9

### DEC-027-7 — Placement: search and excerpt read in one worker-thread call
- **Status:** accepted
- **Stage:** 004.retrieval · **Feature:** 027.session-search-tool · **Step:** 001, 003
- **Date:** 2026-10-05 · **Decided by:** planner
- **Plan-local:** 027 D6
- **Question:** How does the adapter run the sync search and the excerpt read under the async loop?
- **Decision:** `run` makes **one** `asyncio.to_thread` call to a module-private `_search_and_hydrate`, which runs `search_sessions` then `list_session_excerpts` sequentially on the seam's connection. `search_sessions` rolls back in a `finally`, as `search_memos` does. `SessionSearchTool` mirrors `MemoSearchTool` (`DEC-026-3`), including forwarding `client_factory` / `timeout_seconds` only when not `None`. The registry maps `session_search` to a default-constructed adapter beside `memo_search`.
- **Reason:** Same safety argument as `DEC-026-3`; one thread hop instead of two.
- **Lands in:** `backend/app/services/search/session_search.py`, `backend/app/services/tools/session_search.py`, `backend/app/services/tools/seam.py`
- **Cites:** `DEC-026-3`, `DEC-026-4`

### DEC-027-8 — Ids come only from `ToolScope`; `setup_id` is unused

- **Question:** Which inputs does `run` read?
- **Decision:** Only the `query` argument. `ToolScope.session_id` is the current session to exclude; `ToolScope.setup_id` is not used, because the search is per character, not per setup.
- **Reason:** R5; the scope is the seam's.
